# 复盘：VibeCoding营 · D1下 · Skill 部分讲法改版（回到 Skill 原本定义）

> 一句话结论：**"讲 Skill 讲不好"的根因是把 Skill 讲成了自己的总结；回到一手定义（视频原版讲法）后，定义、机制、造法、资源四条线全部有据可依；案例从讲师私有系统换成学员能想象的日常 skill 后，课才真正对学员成立。**

## 一、目标（为什么做）

- 用户反馈：`04_大纲/120 D1下`（v1）讲 Skill 的部分"不是很好"，要求**回到 Skill 原本的定义**，以抖音 @秋芝2046《第17集：手把手彻底学会 Agent Skills！【小白教程】》（19:18）为内容来源，沉淀后重写大纲。
- 隐含验收：① Skill 定义、为什么强、怎么造，三条都必须来自视频原版讲法而非讲师自拟；② 教法不变（成人课堂抽查提问、先演示后动手）；③ 版本迭代留档（原名保留最老版，新修改 _vN 后缀）。

## 二、过程（做了什么）

1. **视频提取（卡点与换道）**：`doubao-video-extract` CLI 不支持抖音解析 → 换浏览器方案（mac computer use：用户扫码登录接管 → 按时间点 seek＋截图＋OCR 采样约 115 点）→ 完整提取 19:18 视频内容与抖音 AI 章节要点（什么是Skill 1:14 / 创建Skill 3:00 / 按需加载 6:12 / Skill Creator 15:01 / 现成Skill 17:12 / 结语 18:58）。
2. **沉淀**：`04_大纲/120 D1下 Skill视频内容沉淀_v1.md`（逐章节原版内容）。
3. **大纲 v2**：块二整体重排为 **承接 → 回到定义（炒菜类比＋文件夹结构映射＋提示词≠Skill）→ 拆开看（元信息＋指令／三层按需加载）→ 案例 → 怎么造（创建器＝大白话＋选择题／训院四步）→ 收口（现成 Skill＋抽查提问＋悬念）**；块一"亮结果"改"抽查提问"（10-01 已定教法）。
4. **逐字稿 v2**：块七～块十二整体重写（约 1 万字，v1 的 1.6 倍），按底稿制体例。
5. **香稿 v2**：五香镶嵌（香源＝"3:30 重复的事能打包成 Skill"；新增现场"5步 vs 一句话出图"香证）。
6. **v3 案例替换（第二轮用户反馈）**：用户指出"此阶段不要过于提我的知识库" → 案例由"知识库＋Skill（导入/体检/归档）＋C12 课程转录"收窄为 **"把飞书链接沉淀到本地"** 一个 skill（course-doc-to-local：抓全文／存图片／排格式，2-3 小时→几分钟）；大纲/逐字稿/香稿同步出 v3。

## 五、原因与沉淀（方法论收获）

1. **回到定义＝找一手来源，不是自己重总结**。v1"抽象：把流程抽成一个东西"是讲师侧推理，学员无感；视频原版"Skill＝技能：流程＋配方＋工具＋材料"是可直接上屏的定义锚，讲起来有画面、有结构。
2. **案例要贴学员场景，不要贴讲师私有系统**。学员是零基础、只有手机："知识库导入/体检/归档"他们无法想象；"收到飞书链接→本地 Markdown（复制粘贴慢/图片一张张存/格式乱）"是人人都有的重复事——案例的"三件烦事"结构沿用 C07，但对象换成学员能共鸣的。
3. **无外挂字幕视频提取成本高**：截图＋OCR 约 115 个采样点才拼出全文；下次优先找带字幕/逐字稿的来源（B站/YouTube 等），或先问用户能否提供逐字稿。
4. **教法纪律贯穿三个版本未动摇**：成人课堂抽查提问（不亮结果）、讲师先完整演示再学员动手、每概念配 60 秒微跟做——版本迭代只动内容口径，不动教法层。

# 方法：Obsidian 笔记 YAML 头怎么写

## 一句话核心
- YAML 头 = 笔记的"快速预览层"——不读正文，扫一眼就知道这篇笔记是谁的、干什么的、什么状态

## 为什么值得写（三个好处）
- 场景匹配 · 搜得到：用 Dataview 按场景筛笔记，开工前三秒相关笔记全在眼前
- 版本感知 · 信得过：看到 `v1` 就知道可能有新版，不会拿着过时方法干活
- 来源追溯 · 改得动：方法出问题了，知道回哪去修正——来源字段就是更新入口

## 核心公式
- YAML 头 = 开头和结尾各三个横线 `---` + 中间 `属性名：属性值`

## 字段设计（分两档）
- 最小启动版（必填）：
  - type：笔记类型（概念 / 方法 / 练习手册 / 配置 / 研究 / 判断 / 复盘）
  - status：状态（初稿 / 迭代中 / 已完成 / 已归档）
  - date：创建日期，格式统一 `YYYY-MM-DD`
- 按需追加（选填）：
  - updated：最后修改日期
  - author：作者
  - scene：使用场景
  - usage：用途
  - user：使用者
  - version：版本号
  - source：来源
  - priority：优先级（高 / 中 / 低）
  - tags：标签，用列表格式

## 关键区分：type 和 tags
- type：笔记的**结构类型**（方法笔记 / 概念笔记 / 配置笔记）
- tags：笔记的**主题关键词**（Skill / Codex / Obsidian）
- 拆开后可以同时按类型和主题交叉筛选

## 三条铁律
- 短：字段不超过 5 个，多了维护成本吃掉收益
- 统一：type 和 status 取值全库统一，不混用
- 先跑再补：只加你真的会用 Dataview 查的字段，别提前设计

## 标准模板（直接复制）

---
```

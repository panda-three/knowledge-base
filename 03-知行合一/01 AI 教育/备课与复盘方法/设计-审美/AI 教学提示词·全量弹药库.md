# AI 教学提示词·全量弹药库

---

## 使用说明

- **标识规则**：`▶` = 可直接复制使用的提示词模板；`※` = 使用心法（你读，不复制）；`→` = AI 输出的用途
- **人先拉满铁律**：所有标注 `※` 的步骤，你必须先自己做一遍，再把结果喂给 AI。顺序反了 = 锁死在低水平
- **存库习惯**：每次用了一个提示词觉得好用，立刻存进你的「教学提示词库」。下次同类场景直接调，不用重新想

## 一、课前：课程设计与内容准备

### 1.1 用户访谈分析

**※ 你先做**：访谈 3–5 个真实学生，记录他们的原话。感受他们语气里的困惑。

**▶ 提示词**：

```
我访谈了 [N] 个学 [课题] 的学生，以下是他们的原话。请帮我做以下分析：

1. 提取每个学生最核心的认知盲区——他们以为自己懂但其实不懂的点
2. 按出现频率排序所有痛点，标注每个痛点的情绪强度（高/中/低）
3. 标出最「反直觉」的 3 个发现——学生说的和真相相反的
4. 给出一句话开场钩子，用来做课程「为什么学」的开场
   （不准说「今天我们来学 XXX」）

学生原话：
[粘贴访谈记录]
```

→ 产出物：课程「为什么学」段的弹药 + 认知盲区列表

### 1.2 课程骨架设计

**※ 你先做**：自己先想清楚这节课的核心改变——学生上完课能「做什么」，不是「知道什么」。

**▶ 提示词**：

```
我要设计一节 [课题] 的课，[时长] 分钟，[实操课/理论课]。

核心改变：学生上完课能从 [现状] 变成 [目标状态]。

请按以下七段结构帮我出一个课程骨架：

① 为什么要学（打痛点，不是讲价值。开场不准说「今天我们来学XXX」）
② 预热思考题（制造认知缺口——听完就想知道答案但靠自己答不上来）
③ 提前划重点（3-4 句话，30 秒读完，读完知道这节课能带走什么）
④ 正文·方法论（提炼成一个模型 + L1-L6 段位定义 + 一句口诀）
⑤ 正文·案例（[实操课：同一任务的三段平行时空 L1/L3/L5] [理论课：同一个案例推三遍，逐层加深]）
⑥ 作业（只追一个动作，承诺反馈）
⑦ Candy（下节课钩子 + 课后持续价值）

其他约束：
[粘贴你的特殊要求——比如「这是 C 语言循环课，屏幕实时写代码」]
```

→ 产出物：课程骨架初版

### 1.3 辩证讨论课程骨架

**※ 你先做**：拿到 AI 的骨架后，自己先挑一轮问题——你觉得哪里节奏拖？哪里太重？标注你的判断。

**▶ 提示词**：

```
这是我的一节 [课题] 课程骨架。请站在学生的角度批判它：

1. 哪一段会让你走神？为什么？（具体到哪一分钟）
2. 三段对比的差距够明显吗？L1 和 L3 的版本学生能一眼看出好坏吗？
3. 方法论够简洁吗？能在 30 秒内讲清楚吗？
4. 开场钩子真的能击中认知盲区吗？还是只是「有点意思」？
5. 给我 3 个改进方案，按「改动成本从低到高」排列

课程骨架：
[粘贴 AI 出的骨架]
```

→ 产出物：骨架改进方向

### 1.4 三段平行时空设计（实操课）

**※ 你先做**：自己先写完三段代码的第一版（人先拉满）。你可以写得很烂——重点是你在调用自己的判断力。

**▶ 提示词**：

```
请为 [课题] 设计「三段平行时空」——同一道题 [题目描述]，三个段位的版本：

【L1-L2 菜鸟版】
- 特征：[描述菜鸟的典型表现——变量命名随意、无缩进、边界写死等]
- 一定要包含 1-2 个常见错误但能编译通过
- 标注：这段代码哪里是「坑」

【L3-L4 规范版】
- 特征：[描述规范的表现——命名有意义、缩进完美、边界用常量等]
- 和 L1 版功能完全一致，只改代码质量

【L5-L6 优雅版】
- 特征：[描述优雅的表现——提取函数、灵活配置、结构一眼懂意图等]
- 不仅正确，而且看得出「思维」

要求：
- 三段代码必须能直接编译运行（[语言/环境]）
- 每段代码后标注「段位 + 一句老师点评口吻的评语」
- 三段共用一模一样的需求描述
- 差距必须肉眼可见——不只是细节差异，是「看完 L3 再回头看 L1 会觉得 L1 不能忍」
```

→ 产出物：三段代码 + 段位点评

### 1.5 从三段平行时空反推方法论

**※ 你先做**：自己先试着从三段代码中提炼一个模型和口诀。AI 出的可能更好，但你先做的过程在训练你的方法论萃取能力。

**▶ 提示词**：

```
这三段代码代表 [课题] 的三个段位。请帮我提炼一个教学方法论：

1. 从三段代码中提取「能力的核心进步维度」——是哪几个维度在逐段提升？
2. 把这几个维度抽象成一个模型（给一个容易记住的名字和比喻）
3. 给一句学生听一遍就能记住的口诀（不超过 15 个字）
4. 给 L1-L6 六个段位各一句话定义

三段代码：
[粘贴三段代码]
```

→ 产出物：方法论模型 + 口诀 + 六段位定义

### 1.6 方法论辩证讨论

**▶ 提示词**：

```
这是我的 [课题] 方法论：[粘贴你的方法论——模型 + 口诀]

请扮演一个严厉的教学评审，挑战它：

1. 这个模型有没有覆盖不到的场景？什么情况下会失效？
2. 口诀够不够「粘」？学生会记住吗？如果不能，怎么改？
3. 和市面上已有的 [课题] 教学方法比，差异在哪？优势是什么？
4. 用一句不超过 10 个字的话，说出这个方法论的「魂」

请用辩证的方式——先指出问题，再给改进建议。不要只说好话。
```

→ 产出物：方法论优化方向

### 1.7 双轨脚本初版（实操课）

**※ 你先做**：自己画完节点图（11 节点模板），标好每个节点的核心信息和预估时长。

**▶ 提示词**：

```
我设计了一节 [课题] 的实操课（实时 [写代码/操作工具] 演示），
以下是课程骨架和三段平行时空的代码。

请帮我出一版「双轨脚本」，格式为五列表格：
| 时间 | 屏幕 | 操作（手） | 讲解（嘴） | 停顿 |

重点帮我设计以下节点的完整双轨脚本：
[列出需要 AI 重点写的节点编号和名称]

要求：
- 开场 30 秒和收口 1 分钟用逐句写死的半逐字稿
- 演示中间用要点提纲
- 标注所有「预告停顿」和「复盘停顿」和「张弛停顿」
- 等待编译/生成的每一段都预埋知识点（不准写「等待中」留空白）
- 每个关键操作节点至少标一条翻车预案

课程骨架和三段代码：
[粘贴]
```

→ 产出物：双轨脚本初版

### 1.8 五层逐字稿初版（理论课）

**※ 你先做**：自己画完认知推演路径图，标注所有 🔑 ⚡ 🎯 锚点。

**▶ 提示词**：

```
以下是我的一节理论课「[课题]」的认知推演路径图。请按五层密度帮我出逐字稿初版：

五层密度规则：
- L5 逐句锁死：开场钩子、收口总结、闭合句、反直觉时刻揭示
- L4 框架锁死：认知台阶间过渡，过渡句写死，展开写关键词
- L3 逻辑链锁死：核心推导的因果/递进/转折链写死
- L2 要点提纲：案例展开细节，3-5 个要点
- L1 即兴区：互动回应方向

逐字稿铁律：
- 一句只做一件事（一句解释概念又举例 → 拆成三句）
- 两句话之间必须是因果/递进/转折之一
- 每个认知台阶结束必有一句闭合句：「所以你只需要记住一件事：___」
- 每个 🔑 后标注「停顿 3 秒」

认知推演路径图：
[粘贴]
```

→ 产出物：五层逐字稿初版

### 1.9 翻车预案穷举

**▶ 提示词**：

```
我在实时演示 [课题]，以下是关键演示节点。请帮我穷举翻车预案：

节点列表：
[列出所有关键演示节点]

对每个节点列出：
- 理想结果
- 3-5 种可能的翻车场景（从轻微偏离到彻底崩）
- 每种翻车的一句话术 + 一个动作（话术要像老师在讲台上从容应对的口吻，不要像读文档）
- 标注哪种翻车需要切本地备用文件

额外要求：
- 最容易忽视的翻车（比如不是代码错，而是工具页面加载慢/登录过期/弹窗更新）
- 请单独列出来
```

→ 产出物：翻车预案清单

### 1.10 逻辑链测试（理论课）

**※ 你先做**：逐字稿定稿后再喂 AI，不要拿初版测。

**▶ 提示词**：

```
以下是我的理论课逐字稿。请做逻辑链测试：

测试方法：
1. 把每句话的开头（第一个词或短语）连起来读
2. 检查是否形成清晰的因果/递进/转折链
3. 标注所有「逻辑断裂点」——两句话之间没有这三种关系之一的
4. 标注所有「岔路」——突然跳到无关话题的
5. 对每个断裂点和岔路，给修改建议

逐字稿：
[粘贴]
```

→ 产出物：逻辑断裂点 + 修改建议

### 1.11 PPT 内容结构反推

**▶ 提示词（实操课）**：

```
这是一节实操课（实时演示驱动），PPT 是配角，总页数不超过 20 页。
大部分时间屏幕上不是 PPT，是操作工具界面。

请从以下双轨脚本反推 PPT 每一页的内容：

反推规则：
- 「屏幕」列写了什么 → PPT 就做什么页
- 「停顿点」→ PPT 单独一页，大字留白
- 「三段对比」→ PPT 三行大字并列 + 核心差异关键词
- 「闭合句/口诀」→ 一整页只有那句口诀
- 开场钩子 → 一页，一个问题或反常识，不写课程标题

输出格式：| 页码 | 页面内容（一句话） | 对应脚本位置 |

双轨脚本：
[粘贴]
```

**▶ 提示词（理论课）**：

```
这是一节理论课，PPT 是学生唯一的视觉来源。
总页数 60-90 页，每 30-60 秒切一页，每页只承载一个信息。

请从以下五层逐字稿反推 PPT 每一页的内容：

反推规则：
- 🔑 认知缺口 → 一整页只有那个问题，大字
- ⚡ 反直觉时刻 → 「你以为 A」一页 → 切「其实是 B」一页
- 🎯 闭合句 → 一整页只有那句闭合句
- 案例对比 → 左右分屏，不并列在一页
- 方法论模型图 → 一页只放一个干净模型图

输出格式：| 页码 | 页面内容（一句话） | 对应逐字稿位置 |

五层逐字稿：
[粘贴]
```

→ 产出物：PPT 内容结构表

### 1.14 教学卡片生成

**▶ 小抄卡**：

```
请为 [课题] 的 [具体知识点] 生成一张「小抄卡」：

类型：小抄卡（学生操作时放旁边快速查阅）
尺寸：手机屏幕比例（约 750×1334）

内容要求：
1. 标准 [语法/模板/公式]（各部分标注作用）
2. 最常见 3 个错误写法 vs 正确写法对比
3. 不超过 8 行信息
4. 用学生一看就懂的语言，不要教科书腔

同时给出视觉布局描述和配色建议。
```

**▶ 对比卡**：

```
请为 [课题] 的 [对比主题——如 < vs <=] 设计一张「对比卡」：

类型：对比卡（左右分屏并列对比）
内容：同一段代码/场景，只改这一个变量，展示差异

要求：
- 左右两栏，标注 A 版和 B 版的核心差异
- 每栏展示：代码/做法 + 输出/结果 + 一句话说明
- 底部一句结论（不超过 15 字）
- 学生 10 秒内能理解差距
```

**▶ 检查单卡**：

```
请为 [课题] 的 [做完某事后] 设计一张「检查单卡」：

类型：检查单（做完后逐项打勾自查）
目标学生：[段位 + 典型表现]

要求：
- [N] 个检查项，按「最容易错 → 最容易忽略」排序
- 每项一句话，动词开头
- 每项附一个「如果错了会怎样」的迷你示例
- 底部：「以上全对 → [进入下一个挑战/提交/自信满分]」
```

**▶ 模型卡**：

```
请为「[模型名称]」设计一张方法论模型卡：

模型：[名称 + 结构——如三步法：定界→定步→定体]
口诀：[粘贴你的口诀]

要求：
- 视觉中心是干净的流程图或方块结构
- 每步下面一句话解释
- 口诀在底部，最大字号
- 简洁到学生一眼能记住这个框架
```

**▶ 练习卡**：

```
请为 [课题] 设计一张「练习卡」：

类型：练习卡（正面题目 + 反面答案）
目标段位：[L几] 学生

正面——题目：
- [一段代码/一个场景/一个问题]
- 问题：「[要求学生做的判断或预测]」
- 题目中故意放一个容易 [错/漏/混淆] 的点

反面——答案：
- 逐步展示正确答案或解析
- 标注最容易错的那一步（用❗标记）
- 一句话总结：「大多数人在这里出错，因为___」
```

## 二、课中：实时演示辅助

### 2.1 逐轮模拟循环执行

```
逐轮执行以下代码，用表格展示每一轮各个变量的值。
标出「进入条件判断」「执行循环体」「更新变量」三个步骤。

代码：
[粘贴循环代码]
```

→ 投屏给学生看，让他们对照自己脑中的执行模型

### 2.2 边界条件秒出对比

**▶ 提示词**：

```
请同时展示以下两段代码的输出结果，并列对比：

代码 A：
[粘贴——比如 i < n 版本]

代码 B：
[粘贴——比如 i <= n 版本]

输出格式：两行对照，标注循环次数和最后一个输出值。
底部用一句话标注核心差异。
```

→ 投屏，学生亲眼看到差一个字符的后果

### 2.3 现场改代码对比

**▶ 提示词**：

```
帮我把这段代码改成 [L3 规范版 / 更优雅的版本]。
保持功能完全一致。改完之后：

1. 标注你改了哪几个地方
2. 每个改动说明为什么
3. 改动数量控制在 [3-5] 个以内（让学生能消化）

代码：
[粘贴学生现场报的代码或你写的 L1 版]
```

→ 左右分屏——左边原版，右边 AI 改版，学生一眼看出差距

### 2.4 翻车诊断教学

**▶ 提示词**：

```
这段代码能编译通过，但输出结果和预期不一样。
不要直接给正确答案——先分析为什么会出现这个结果，
然后指出 1 个关键修改点。

代码：
[粘贴学生现场报的代码或你故意写的 bug 版]

输出格式：
1. 实际在做什么？（用自然语言描述每一步）
2. 为什么和学生预期不一样？（指出第几行的什么逻辑导致的）
3. 怎么改？（只改 1-2 个字符，不改整体结构）
```

→ 翻车变成最好的教学素材

### 2.5 反推循环——先给 AI 不完美版本，你当堂纠错

**▶ 提示词（第一步）**：

```
以下是一个程序的完整输出结果：

[粘贴期望输出]

请仅根据输出结果，反推源代码的循环结构。
用自然语言告诉我：
1. 需要几层循环嵌套？为什么？
2. 外层循环控制什么？内层循环控制什么？
3. 每层循环的起点、终点、步长分别是什么？

不要直接给代码，先给推导过程。
```

→ 展示 AI 的反推。你当堂做两件事：①指出对的部分——「你看，AI 从行列数猜出两层循环」；②指出错或不够最优的地方——「但 AI 猜边界是 1 到 9，我改成 1 到 n 更通用」。让学生亲眼看到「从结果反推结构 + 迭代优化」的工程思维。

## 三、课后：作业与反馈

### 3.1 作业题设计

**▶ 提示词**：

```
请为 [课题] 设计 [N] 道作业题：

要求：
- 每道题对应一个段位（L2/L3/L4）
- 每道题只追一个动作——学生做完一道就能验证一个核心认知
- 每道题附：
  1. 「学生常见错误」（他们通常会怎么错）
  2. 「自我判断标准」（学生对照这标准就知道自己做得对不对）

[L2 题：练什么 + 典型学生表现]
[L3 题：练什么 + 典型学生表现]
[L4 题：练什么 + 典型学生表现]
```

→ 产出物：分层作业题

---

### 3.2 批量作业批改

**▶ 提示词**：

```
以下是 [N] 个学生的 [课题] 作业。请帮我：

1. 逐个编译/语法检查，标注无法通过的
2. 对能通过的，运行输出和标准输出比对，标注输出不一致的
3. 按段位分类：
   - L1：无法编译
   - L2：能编译但输出不对
   - L3：正确但不规范（命名乱/无注释/缩进乱）
   - L4：规范且优雅
4. 统计最常见的 3 种错误，每种附 1 个学生代码示例（匿名）
5. 给每种错误写一段「老师点评口吻」的修改建议（50 字以内，有温度）

标准输出：[粘贴标准答案的输出结果]
学生作业：[粘贴 N 份代码，每份标注学生昵称]
```

→ 产出物：批量初评报告

### 3.3 错误聚类分析

**▶ 提示词**：

```
以下是 [N] 个学生的作业错误列表。请帮我聚类分析：

1. 按错误类型分组（语法错误 / 逻辑错误 / 边界错误 / 风格问题 / 概念理解错误）
2. 统计每组的人数和占比
3. 指出「最值得在下节课回应的 1 个错误」—— 人数多 + 概念层面 + 不解决会影响后续学习
4. 给这个错误写一段「下节课开场 2 分钟回应」的话术

错误列表：
[粘贴 AI 初评中的错误统计]
```

→ 产出物：下节课的前 5 分钟内容

## 四、灵感闪现与创造力

### 4.1 灵感闪现核心提示词

**※ 铁律**：你自己先闪现到极限（保 20 争 30），再把卡住的方向喂给 AI。顺序反了 = 永远锁死在 50 分。

**▶ 基础版提示词**：

```
我在 [业务/课题]，现在需要 [具体需求]。
要求是：[约束条件]。

给我更多的可选项。例子是：[粘贴你自己已经想到的 2-3 个例子]

请从以下角度补充我没想到的方向：
- [角度1]
- [角度2]
- [角度3]
```

**▶ 进阶版提示词（一堂教研验证过的——把方法论写进提示词）**：

```
我在 [业务/课题]，需要 [具体需求]。

请按以下框架帮我激发更多灵感：
- 提升动力维度：[具体怎么应用到这个课题]
- 降低阻力维度：[具体怎么应用到这个课题]
- 对标最佳实践：[同行/跨行业谁做得最好？他们怎么做的？]

约束条件：[粘贴]
我已有的想法：[粘贴你自己的初版]
```

---

### 4.2 灵感闪现追问

**▶ 提示词**：

```
你给我的 [某个方向] 还不够。请继续深入：
1. 这个方向还有哪些变体？
2. 如果反向思考呢？（反过来会怎样？）
3. 如果去掉 [某个约束]，会有什么新可能？
```

---

### 4.3 十层解读

**▶ 提示词**：

```
请从以下多个角度解读 [同一内容/方法论/案例]：

1. 新手视角：第一次接触的人会怎么看？
2. 高手视角：有 5 年经验的人会注意什么？
3. 反方视角：不认同这个方法的人会怎么挑战？
4. 跨领域视角：[另一个领域] 的专家会怎么类比？
5. 底层原理视角：支撑这个方法的更底层规律是什么？
6. 边界视角：什么情况下这个方法会失效？
7. 用户情感视角：学生学这个的时候是什么心理状态？
8. [自定义角度]
9. [自定义角度]
10. [自定义角度]

内容：
[粘贴]
```

→ 产出物：多角度穿透分析——灵感闪现做广度，十层解读做深度

## 五、AI 辩证讨论

### 5.1 方法论挑战

**▶ 提示词**：

```
请扮演一个严厉的 [同行/专家/反方]，挑战我的 [方法论/观点/结论]：

我的观点：[粘贴]

挑战规则：
1. 先指出漏洞——什么场景下不成立？有什么反例？
2. 再追问底层——支撑这个观点的假设是什么？假设本身可靠吗？
3. 最后给建设性意见——如果要让这个观点更坚固，需要补什么？

不要只说好话。不要回避尖锐问题。
```

→ 产出物：方法论加固 + 边界清晰化

---

### 5.2 两个 AI 交叉辩论

**▶ 提示词**：

```
请两个角色围绕以下议题辩论——

正方：[立场描述]
反方：[立场描述]

议题：[具体问题或方法论]

辩论规则：
- 各出 3 轮观点
- 每轮必须回应对方上一轮的核心论点
- 不准各说各话

辩论结束后，请一个「裁判」角色总结：
- 双方最有力的论点各是什么
- 最终更支持哪一方？为什么？
```

→ 产出物：深度辩证分析

## 六、知识库与资产管理

### 6.1 调研摘要

**▶ 提示词**：

```
我要快速入门 [领域/课题]。请帮我：

1. 搭建入门框架——这个领域的核心知识分哪几块？
2. 每块找 1 个最关键的概念，一句话解释
3. 推荐 5 个必看的信息源（文章/视频/课程）
4. 整理术语表——这个领域 10 个最重要的术语 + 一句话解释
5. 给一张「入门地图」——新人最容易踩的 3 个坑是什么？

输出格式：清单体，能 5 分钟内读完。
```

→ 产出物：「1 天入门一个专题」的起点

---

### 6.2 把你的素材喂成知识库

**▶ 提示词**：

```
以下是我关于 [课题] 的全部素材：[粘贴课程逐字稿/作业/访谈记录/磨课笔记]

请帮我：
1. 提取所有方法论、模型、口诀（汇总成一张表）
2. 提取所有案例，按适用场景打标签
3. 提取所有学生常见错误，按出现频率排序
4. 找出这些素材中「重复出现的核心认知」——最底层的那 1-2 条规律是什么？

以后我问你关于 [课题] 的问题时，优先基于这些素材回答。
```

→ 产出物：你的个人教学知识库底座

## 七、你每日的 AI 教学三问

## 八、全局心法速查

| # | 心法 |
|---|---|
| 1 | 人先拉满，AI 最后用。所有提示词前标注 ※ 的步骤，必须先自己做 |
| 2 | AI 给的永远是初版。你是最终审核。不改一个字就用的 = 你没有判断力 |
| 3 | 提示词越具体，输出越精准。笼统的提示词 = 笼统的输出 |
| 4 | 追问比初问重要。AI 的第一版答案很少是最好的——追问 3 轮以上 |
| 5 | 把方法论写进提示词。你教给学生的框架，同样可以教给 AI——效果天差地别 |
| 6 | 每次用完一个提示词觉得好用，立刻存库。下次不重新想 |
| 7 | AI 不知道你的学生是谁。所有关于「学生感受」的判断，你来做 |
| 8 | 最好的 AI 使用，是学生根本没意识到你用了 AI |

# for 循环实操课 V3

> 版本定位：老师打开就能讲的 45 分钟课堂讲稿。  
> 主屏幕是代码编辑器，不是 PPT。课堂主线是：**重复劳动 → for 循环四问 → 执行流程追踪 → 边界控制 → 累加/计数应用**。

---

## 0. 课前准备

### 学生基础

学生已学过：

- 变量
- `printf` / `scanf`
- `if` / `switch`
- 基本运算符：`+ - * / %`

### 老师准备

打开 C 编译环境：VS Code / Dev-C++ / Code::Blocks 均可。  
建议新建文件：`for_demo.c`。

### 本节课一句话目标

> 学生下课后，不只是会背 `for(初始化; 条件; 变化)`，而是能说清楚：**i 从几开始、到哪停、每次怎么变、循环体重复做什么。**

### 本节课最小成功标准

学生能独立写出下面这种循环，并能解释每个位置为什么这样写：

```c
for (i = 1; i <= 5; i++) {
    printf("%d\n", i);
}
```

## 2. 开场：为什么需要循环（0-4min）

### 屏幕内容

先不要讲语法，直接在代码区写重复代码。

```c
#include <stdio.h>

int main() {
    printf("我爱 C 语言!\n");
    printf("我爱 C 语言!\n");
    printf("我爱 C 语言!\n");
    printf("我爱 C 语言!\n");
    printf("我爱 C 语言!\n");
    return 0;
}
```

### 老师话术

> 同学们，今天我们不先背语法。先看一个很笨的问题：如果我要让电脑打印 5 遍“我爱 C 语言”，我可以写 5 行 `printf`。  
> 但是如果我要打印 50 遍、100 遍呢？你准备复制 100 行吗？

停 3 秒，等学生反应。

> 程序员真正厉害的地方，不是手速快，而是能把重复劳动交给电脑。今天这节课的 for 循环，就是让电脑替你重复干活的结构。

### 互动问题

问学生：

> 这段代码结果是对的，但它最大的问题是什么？

预期回答：

- 太重复
- 太麻烦
- 如果次数变多，代码会很长

### 收口句

> 重复不是错误，但重复是信号。它在提醒你：这里有结构，可以交给循环。

## 3. 核心模型：for 循环四问（4-10min）

### 先给完整结构

```c
int i;
for (初始化语句; 条件判断语句; 条件控制语句) {
    循环体语句;
}
```

### 老师话术

> for 循环看起来有点吓人，因为括号里有三个位置，中间还有两个分号。  
> 但今天我们不死记格式，我们只记四个问题。

### 板书 / PPT 最小页

```txt
写 for 循环，先问四句话：

1. 从哪开始？
2. 到哪结束？
3. 每次怎么变？
4. 重复做什么？
```

对应到代码：

```c
for (从哪开始; 到哪结束; 每次怎么变) {
    重复做什么;
}
```

### 四问解释表

| 四问 | for 中的位置 | 例子 | 常见错误 |
|---|---|---|---|
| 从哪开始？ | 初始化语句 | `i = 1` | 不知道 i 初始值写几 |
| 到哪结束？ | 条件判断语句 | `i <= 5` | `<` 和 `<=` 混乱 |
| 每次怎么变？ | 条件控制语句 | `i++` | 忘记变化，死循环 |
| 重复做什么？ | 循环体 | `printf(...)` | 把不该重复的代码放进大括号 |

### 口诀

> **先定起点，再定终点；每轮变一次，身体做重复。**

让学生一起读一遍。

## 4. 演示 1：打印 1-5（10-18min）

### 需求

> 打印 1 到 5。

### 先写四问，不急着写代码

| 四问 | 本题答案 |
|---|---|
| 从哪开始？ | 从 1 开始，所以 `i = 1` |
| 到哪结束？ | 到 5 结束，而且 5 要打印，所以 `i <= 5` |
| 每次怎么变？ | 每次加 1，所以 `i++` |
| 重复做什么？ | 打印当前的 `i` |

### 现场代码

```c
#include <stdio.h>

int main() {
    int i;

    for (i = 1; i <= 5; i++) {
        printf("%d\n", i);
    }

    return 0;
}
```

### 预期输出

```txt
1
2
3
4
5
```

### 老师话术

边写边说：

> `int i;` 这里的 i 不是随便来的，它是循环变量，负责一轮一轮地走。  
> `i = 1` 表示从 1 开始。  
> `i <= 5` 表示只要 i 还没有超过 5，就继续执行。  
> `i++` 表示每一轮结束之后，i 往前走一步。  
> 大括号里是每一轮都要做的事：打印 i。

### 关键停顿

运行前先问：

> 如果我把 `i <= 5` 改成 `i < 5`，结果会少哪个数？

预期回答：少 5。

现场把 `<=` 改成 `<` 运行一次，再改回来。

### 收口句

> 循环里最贵的错误，经常不是语法错，而是边界错。一个等号，就可能少处理一个数据。

## 5. 演示 2：执行流程追踪（18-25min）

### 需求

让学生看懂 for 不是“从左到右走一遍”，而是反复判断、执行、变化。

### 屏幕代码

```c
#include <stdio.h>

int main() {
    int i;

    for (i = 1; i <= 3; i++) {
        printf("i = %d\n", i);
    }

    printf("结束时 i = %d\n", i);
    return 0;
}
```

### 运行前提问

> 先别运行。你猜屏幕会打印几行？最后 `i` 是几？

给学生 5 秒。

### 预期输出

```txt
i = 1
i = 2
i = 3
结束时 i = 4
```

### 执行流程板书

```txt
① 执行 i = 1        只执行一次
② 判断 i <= 3       成立，进入循环体
③ 执行 printf
④ 执行 i++          i 变成 2
⑤ 回到②继续判断

当 i 变成 4 时：
判断 i <= 3 不成立，循环结束。
```

### 老师话术

> 最容易错的地方不是 1、2、3，而是最后的 4。  
> 因为 i 不是打印完 3 就消失了，它还会先执行一次 `i++`，变成 4，再去判断。判断不成立，循环才结束。

### 收口句

> for 的顺序不是从左到右一次走完，而是：**起点一次，判断多次，身体多次，变化多次。**

## 6. 演示 3：反向输出 5-1（25-31min）

### 需求

> 打印 5 到 1。

### 先让学生改四问

问学生：

> 如果刚才是从 1 到 5，现在要从 5 到 1，哪三个地方要改？

预期回答：

- 起点改成 5
- 终点条件改成 `i >= 1`
- 每次变化改成 `i--`

### 现场代码

```c
#include <stdio.h>

int main() {
    int i;

    for (i = 5; i >= 1; i--) {
        printf("%d ", i);
    }

    return 0;
}
```

### 预期输出

```txt
5 4 3 2 1
```

### 老师话术

> 这题没有新语法，只有方向变了。  
> 正向走：从小到大，`i++`。  
> 反向走：从大到小，`i--`。  
> 条件也要跟着方向变，不能再写 `i <= 5`。

### 常见翻车现场演示

如果学生基础较弱，可以故意写：

```c
for (i = 5; i <= 1; i--)
```

问：

> 这个循环会不会执行？为什么？

答案：不会，因为一开始 `5 <= 1` 就不成立。

### 收口句

> 写循环时，起点、终点、变化方向必须是一套。如果方向反了，循环要么不走，要么走不出去。

## 7. 演示 4：求 1-5 的和（31-38min）

### 需求

> 求 1 到 5 的和。

### 先区分两个变量

```txt
i   ：负责一个一个走
sum ：负责把每个数装起来
```

### 现场代码

```c
#include <stdio.h>

int main() {
    int i;
    int sum = 0;

    for (i = 1; i <= 5; i++) {
        sum = sum + i;
    }

    printf("sum = %d\n", sum);
    return 0;
}
```

### 预期输出

```txt
sum = 15
```

### 老师话术

> 打印题里，i 走到哪里，我们就把 i 打出来。  
> 求和题里，i 还是负责走，但我们还需要一个变量 `sum` 当篮子。  
> 每来一个 i，就把它放进篮子里：`sum = sum + i`。

### 追踪表

| 轮次 | i | 本轮之前 sum | 执行 `sum = sum + i` 后 |
|---:|---:|---:|---:|
| 1 | 1 | 0 | 1 |
| 2 | 2 | 1 | 3 |
| 3 | 3 | 3 | 6 |
| 4 | 4 | 6 | 10 |
| 5 | 5 | 10 | 15 |

### 关键提问

> 第三轮结束后，sum 是多少？

预期回答：6。

### 收口句

> 循环变量 i 负责走，sum 负责装。以后遇到求和，先想“我要让谁走？我要用谁装？”

## 8. 课堂练习：条件统计（38-43min）

### 练习题

> 键盘录入两个数字，表示一个范围 `[start, end]`。统计这个范围中，既能被 6 整除，又能被 8 整除的数字个数。

如果课堂时间紧，可以把输入固定成 `1` 到 `100`。

### 先写四问

| 四问 | 本题答案 |
|---|---|
| 从哪开始？ | `i = start` |
| 到哪结束？ | `i <= end` |
| 每次怎么变？ | `i++` |
| 重复做什么？ | 判断 i 是否同时被 6 和 8 整除，满足就 `count++` |

### 现场代码

```c
#include <stdio.h>

int main() {
    int start, end;
    int i;
    int count = 0;

    printf("请输入范围的开始和结束：");
    scanf("%d %d", &start, &end);

    for (i = start; i <= end; i++) {
        if (i % 6 == 0 && i % 8 == 0) {
            count++;
        }
    }

    printf("满足条件的数字个数是：%d\n", count);
    return 0;
}
```

### 老师话术

> 这道题看起来比打印数字难，但本质还是四问。  
> 只是循环体里不再是直接打印，而是每一轮都问一个问题：这个 i 能不能同时被 6 和 8 整除？  
> 能，就让 count 加 1。

### 关键提问

> `count++` 应该放在 `if` 里面，还是外面？为什么？

预期回答：放在里面。只有满足条件才计数。

### 收口句

> 复杂题不是突然出现的。它只是：循环负责一个个试，if 负责判断，变量负责记录。

## 9. 进阶挑战：水仙花数（下节预告 / 学有余力）

> 如果本节课时间不够，水仙花数不要强讲，作为下节课预告或学有余力挑战。

### 需求

> 打印 100 到 999 之间所有水仙花数。  
> 水仙花数：一个三位数，各位数字的立方和等于它本身。  
> 例如：`153 = 1*1*1 + 5*5*5 + 3*3*3`。

### 代码

```c
#include <stdio.h>

int main() {
    int i;

    for (i = 100; i <= 999; i++) {
        int ge = i % 10;
        int shi = i / 10 % 10;
        int bai = i / 100;

        if (bai * bai * bai + shi * shi * shi + ge * ge * ge == i) {
            printf("%d\n", i);
        }
    }

    return 0;
}
```

### 预期输出

```txt
153
370
371
407
```

### 老师提示

> 水仙花数没有脱离今天的主线。它还是四问：从 100 开始，到 999 结束，每次加 1，重复做“拆数字 + 判断”。

## 11. 翻车预案

### 1. 学生分不清 `<` 和 `<=`

处理方式：回到“最后一个数要不要处理”。

话术：

> 不要先想符号，先想最后一个数据要不要被处理。要处理，很多时候就是 `<=` 或 `>=`。

### 2. 学生忘记 `i++`

处理方式：强调“不变化就走不出去”。

话术：

> 循环变量如果不变化，就像人在原地踏步，永远到不了终点。

### 3. 学生把 `printf` 放错位置

处理方式：问“这件事是不是每一轮都要做”。

话术：

> 每一轮都要做的，放进大括号；只做一次的，放在循环外。

### 4. 学生把 `sum = sum + i` 写成 `sum = i`

处理方式：用篮子比喻。

话术：

> `sum = i` 是把篮子清空，只留下这一次的 i。  
> `sum = sum + i` 才是把新的 i 加进原来的篮子。

### 5. 学生统计题把 `count++` 放在 if 外面

处理方式：让学生读题里的“满足条件”。

话术：

> 如果放在 if 外面，就表示每个数字都计数了；但题目要的是满足条件的数字。

## 12. 作业与下节课钩子（43-45min）

### 课堂作业

> 键盘录入一个正整数 `n`，求 1 到 n 之间所有奇数的和。

提交内容只要三样：

1. 四问表
2. 完整代码
3. 运行截图 / 输出结果

### 作业提示

四问可以这样起步：

| 四问 | 提示 |
|---|---|
| 从哪开始？ | `i = 1` |
| 到哪结束？ | `i <= n` |
| 每次怎么变？ | 可以 `i++` 后用 if 判断，也可以 `i += 2` |
| 重复做什么？ | 把奇数加到 `sum` 里 |

### 下节课钩子

> 下节课我们会处理一个看起来更像考试题的问题：水仙花数。你会发现，它不是新东西，只是把今天的 for 循环、if 判断、取个位十位百位组合起来。

## 14. 本节课最终收束话术

> 今天这节课，你们不用记很多东西。只要记住四句话：从哪开始，到哪结束，每次怎么变，重复做什么。  
> for 循环真正难的不是括号，而是你能不能从题目里找出这四件事。  
> 当你能找出来，打印、求和、统计、水仙花数，其实都在一条线上。

# PACK_REASON · 学生推荐话术包 V1.0

## 0. 定位

本包负责把教师/系统视角的标签匹配，翻译成学生听得懂、愿意继续练的推荐话术。

原则：

```text
少说评分，多说动作。
少说标签，多说你这一步要练什么。
少说“你不会”，多说“这个动作还没稳”。
```

## 1. 开场话术

### 1.1 学生做错后

```text
这题错了不代表你整块都不会。
我看它真正要补的是：[考点] 里的 [解题动作]。
我们不要乱刷，按三步来：先同构稳住，再变式确认，最后迁移挑战。
```

### 1.2 学生做对但不稳

```text
这题你做对了，但如果只是记住这一题，还不算稳。
我给你排三题，看你能不能在换外壳后还用同一个动作做出来。
```

### 1.3 学生说“我就是不会”

```text
先别把它归成“我不会 C 语言”。
我们缩小一点：你把题号、题干，或者你卡住的那一步发我一个，我先帮你排最贴近的巩固题。
```

## 2. 三题推荐理由模板

### 2.1 同构巩固

```text
先做这题，因为它和刚才那题几乎练同一个动作：[动作]。
你这次只盯一件事：[提醒]。
```

常用提醒：

- 先找 switch 表达式的值，再找匹配的 case。
- 每轮循环只记录变量的新值，不要跳步。
- 先看数组下标代表什么，再看数组里存什么。
- 先判断字符是不是数字，再做 `c - '0'`。
- 先数外层循环行数，再数内层输出个数。

### 2.2 变式训练

```text
第二题换了个外壳，但底层还是练：[动作/考点]。
如果这题能做出来，说明你不是只会刚才那一道。
```

差异说明模板：

- 从 switch 换成 if-else，但都在练分支匹配。
- 从单层循环换成嵌套循环，但都要追踪变量变化。
- 从字符判断换成字符串遍历，但都要逐字符分类。
- 从程序阅读换成填空，但都要补同一个关键动作。

### 2.3 迁移挑战

```text
第三题表面变化更大，用来检查你能不能迁移。
它看起来不像刚才那题，但底层仍然要用：[动作]。
```

## 3. 难度提示话术

| 情况 | 话术 |
|---|---|
| 难度降低 | “这题我故意给你降一点难度，先把动作找回来。” |
| 难度接近 | “难度差不多，适合验证刚才那一步有没有稳。” |
| 难度略高 | “这题会稍微难一点，但只高在外壳，底层动作还是同一个。” |
| 候选太难 | “这题暂时不放第一题，容易让你误以为自己完全不会。” |

## 4. 学生反馈后的话术

### 4.1 第一题错

```text
没关系，这说明不是迁移问题，是同构动作还没稳。
我们先不做第二题，我再给你换一道更贴近的同构题，或者先把刚才那一步拆开练。
```

### 4.2 第一题对、第二题错

```text
很好，说明原题那种外壳你能做了。
现在问题是：外壳一变，动作还不够自动。
下一步继续练变式，不急着上挑战题。
```

### 4.3 三题全对

```text
这组基本稳了。
下一轮可以做两件事：要么难度 +1，要么换一个相邻考点继续练。
```

## 5. 禁用话术

不要说：

- “这题很简单。”
- “你基础太差。”
- “多刷几题就好了。”
- “这三道都差不多。”
- “综合得分 8 分，所以推荐。”

改成：

- “这题主要练同一个动作。”
- “我们先把这一步稳住。”
- “这题外壳变了，但底层做法相通。”

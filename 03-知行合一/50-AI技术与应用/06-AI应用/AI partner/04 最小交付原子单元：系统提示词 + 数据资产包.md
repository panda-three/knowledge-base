# 最小交付原子单元：系统提示词 + 数据资产包

> 一堂课程最小的 AI 交付原子单元 = 系统提示词（System Prompt）+ 数据资产包（Datapack）

---

## 一、这个定义为什么重要

它是整个 Partner 体系里最底层、最工程化的那个概念。理解了它，就等于理解了"为什么抄一个提示词没用，为什么得复刻双三角"。

Truman 说了一句话：

```text
说到天上去，最后就是写 1000-3000 字极其准确、精华的角色配置文档，
分配到 5-7 个文档里。
```

这不是比喻。**你的最终产品真的就是几个文档。** 但写这几个文档之前要做的功课，才是差距所在。

---

## 二、两个组件的分工

| 组件 | 承载什么 | 一句话 |
|---|---|---|
| **系统提示词** | 逻辑、工作流、审美 | 这个 Partner 怎么思考、怎么推进、怎么判断好坏 |
| **数据资产包** | 数据、案例、细节 | 这个 Partner 知道什么、见过什么、能参考什么 |

打个比方：

```text
系统提示词 = 一位医生的诊断思维和标准操作流程
数据资产包 = 这位医生读过的病例库、见过的罕见病、积累的临床经验

缺前者：光有病例不会诊断，只是一堆资料
缺后者：光有流程没有见过真实病人，诊断很空
```

两者缺一不可。**而提示词基本功反而是六个条件里最弱的那个。**

---

## 三、为什么不能只用系统提示词

这是最常见的误区。很多人以为 Partner 就是"写一段很厉害的提示词"。

**只用提示词 = 骨架 + 没有血肉。**

| 问题 | 表现 |
|---|---|
| 回答太泛 | 没有真实案例支撑，只能讲道理，不能给具体参考 |
| 风格单一 | 没有喂过特定语境的数据，输出千人一面 |
| 缺少专业细节 | 不知道这个领域的坑在哪、边界在哪、最佳实践长什么样 |
| 容易漂移 | 没有数据锚定，多聊几轮就容易跑偏 |

以刻意练习 T Partner 举例：如果只给它系统提示词，它会讲"非舒适区很重要"——但讲不出富兰克林怎么写文章、莫扎特怎么练琴、一堂领教怎么练出口式咨询。这些细节全在数据包里。

---

## 四、为什么不能只用数据资产包

反过来也成立。

**只用数据包 = 血肉 + 没有骨架。**

| 问题 | 表现 |
|---|---|
| 不知道怎么用数据 | 有一堆案例，但不知道该在什么时候调用哪个 |
| 没有推进节奏 | 对话没有结构感，用户不知道下一步聊什么 |
| 没有判断标准 | 不知道用户的回答算好还是算差，该补什么 |
| 没有审美约束 | 输出可能翔实，但结构散、节奏乱、没有教练感 |

系统提示词解决的就是这些：**状态机在哪、什么时候进教学、什么时候收束、报告要满足什么条件、怎么判断用户分数虚高还是虚低。**

## 五、以"刻意练习 T Partner"为例看两件套怎么配合

| 系统提示词承担 | 数据资产包承担 |
|---|---|
| F1 开场怎么管理预期 | 宽场景关键词清单（打球、写文档、AI 协作……） |
| F2 宽场景怎么带动 | 段位图 L1-L6 的详细解释和提升路径 |
| F4 段位图怎么呈现 | 五要素的十层解读、常见误解、策略小抄 |
| F6 评分怎么校准 | 有无对比的具体案例（有反馈 vs 没反馈的真实差异） |
| F7 教学怎么推进 | 反讲话术库（"没有专家不等于没有反馈"） |
| 报告要满足什么准入条件 | 练习清单的 20 小时 / 10000 小时分层话术 |
| 什么时候进入 C Handoff | 具体到每个要素的追问模板和温和校准示例 |

你可以感觉到：**系统提示词是"运行协议"，数据包是"弹药库"。** 运行协议保证每一步踩在正确位置，弹药库保证每一轮输出都有厚素材支撑，不空谈。

## 六、原子单元的工程属性

### 6.1 可自由拼接

```text
一套系统提示词 + 一套数据包 = 一个独立 Partner
同一套系统提示词 + 不同数据包 = 不同领域的 Partner
```

这不是理论。一堂已经在这么做：出口式咨询三段论（定出口→换视角→探究解法）作为方法论底子，配不同的数据资产包，就能生出不同领域的 T 型或 C 型 Partner。

### 6.2 可工业化封装

```text
写完 → 调试 → 发布到 YAI → 2 分钟上线 → 生成 MD 文档
```

整个流程极其轻量。不需要工程团队、不需要部署服务器、不需要写代码。一个人的审美和体系能力 + AI 的执行力，就能产出一个可用的 Partner。

### 6.3 可跨平台迁移

```text
YAI → OpenClaw → Coze → Skill → Agent（ReACT）
```

因为交付物本质上是**纯文本的配置文档**，不依赖任何特定平台的专有格式。你今天在 YAI 上跑，明天就可以把同一套文档丢给 OpenClaw，后天封装成 Coze Skill。

这种"纯文本可迁移性"是 Partner 体系最有战略价值的设计之一：**你的核心资产不会被任何平台锁死。**

## 七、为什么叫"原子"单元

| 属性 | 含义 |
|---|---|
| **不可再分** | 比它更小的颗粒度无法独立交付价值。光有系统提示词不够，光有数据包也不够 |
| **可组合** | 多个原子单元可以拼接成更复杂的系统（如 TCPR 团队） |
| **标准化** | 每个原子单元的结构高度一致：顶层设计 → 流程 → 数据支撑 → 审美约束 |
| **独立可用** | 拿出任何一个原子单元，放到任何平台，都能独立工作 |

这很像软件工程的"微服务"概念，但 Partner 的原子单元更轻——它只是一套文档。

## 八、一个反直觉的判断

Truman 说过：

```text
是「一天天磨出来」还是「一次性高水平赋予」，没有本质区别。
```

这句话的底层含义是：

```text
原子单元的质量，不取决于你花了多少时间，
而取决于你投入的三个 Input 到不到位。
```

| Input | 如果不到位 |
|---|---|
| ① 对业务/场景的深度理解 | 提示词逻辑有漏洞，状态机走不下去 |
| ② 官方配置最佳实践 | 审美基线太低，不知道"好"长什么样 |
| ③ 岗位 Top 审美 | 判断不了输出是惊艳还是平庸 |

三个 Input 到位了，人写还是 AI 辅助写，10 轮还是 2 轮，确实没有本质区别。

## 九、一段话收束

```text
最小交付原子单元，是把一个人的专业能力拆成两个纯文本文档——
系统提示词管"怎么思考、怎么推进、怎么判断好坏"，
数据资产保管"知道什么、见过什么、能参考什么"。

两者合一，就形成了一个能独立工作、可自由拼接、可跨平台迁移的 AI Partner。
它不是一段提示词，也不是一个数据库，而是一个理想工作伙伴的建模。
```

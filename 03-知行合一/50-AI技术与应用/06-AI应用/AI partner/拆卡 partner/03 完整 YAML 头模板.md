# 三、卡片 YAML 头标准字段详解
source: 自创/实践产物
---

## 完整 YAML 头模板（全部字段）

```yaml
---
type:                       # 从八种类型中选一（必填）
category:                   # 主题文件夹名（必填）
subcategory:                # 卡片简称（必填）
source:                     # 来源（必填）
tags:                       # 3-5个关键词（必填）
confidence:                 # 验证状态（必填）
last_updated:               # 最后更新日期（必填）
pitfalls:                   # 翻车点（核心模型/策略武器库/评估工具必填，案例/信念可空）
experience_boundary:        # 经验边界（所有卡片强烈建议填）
audience_variants:          # 受众话术（核心模型建议填，其他选填）
related:                    # 关联卡片（所有卡片必填）
---
```

---

## 字段一：`type`

**是什么：** 卡片类型。决定这张卡在知识库里的身份和检索权重。

**取值（八选一）：**

| 值 | 说明 |
|---|---|
| `最佳实践·核心模型` | 枢纽卡。「只能带走一张」的那张 |
| `最佳实践·框架模型` | 定位/分类框架 |
| `最佳实践·策略武器库` | 可执行的具体策略集合 |
| `最佳实践·评估工具` | 自检/定位/打分工具 |
| `最佳实践·诊断工具` | 卡点诊断表 |
| `最佳实践·实操工具` | 画布/武器库对照表/可填写表格 |
| `案例合集` / `案例` | 案例叙事 |
| `最佳实践·核心信念` | 精神燃料，非方法论 |

**判断标准（不是死记，是三步判断）：**

```
第1步：这张卡能直接用吗？（能操作/能打分/能对着做）
  能 → 策略武器库 / 评估工具 / 诊断工具 / 实操工具
  不能 → 第2步

第2步：这张卡是用来理解体系位置的吗？（不是操作，是定位）
  是 → 框架模型
  不是 → 第3步

第3步：这张卡是这节课最核心的那个模型吗？（「只能带走一张」的那张）
  是 → 核心模型
  不是 → 回到第1步重新判断。如果还不对，可能是案例或核心信念
```

**正例：**

```yaml
# ✅ SOUL 工作流模型——课程最核心的模型
type: "最佳实践·核心模型"

# ✅ SOUL 卡牌矩阵——一组可执行的策略
type: "最佳实践·策略武器库"

# ✅ Truman 个人进化史——一个真实人物的完整故事
type: "案例"
```

**反例：**

```yaml
# ❌ 把策略武器库标成核心模型
# SOUL 卡牌矩阵虽然有 23 张牌，但它不是「只能带走一张」的那张
type: "最佳实践·核心模型"  # 应该是策略武器库

# ❌ 把核心模型标成框架模型
# 1+4 五要素是刻意练习整节课最核心的模型，不应该降级
type: "最佳实践·框架模型"  # 应该是核心模型
```

## 字段二：`category`

**是什么：** 主题文件夹名。决定这张卡放在 `04 man/20最佳实践池子/` 下的哪个文件夹。

**取值：** 已有主题列表 + 根据 R8 规则判断是否新建。

**已有主题（当前）：**

| category 值 | 对应文件夹 |
|---|---|
| `灵感闪现` | `04 man/20最佳实践池子/灵感闪现/` |
| `刻意练习方法论` | `04 man/20最佳实践池子/刻意练习方法论/` |
| `科学销售` | `04 man/20最佳实践池子/科学销售/` |
| `机会预判` | `04 man/20最佳实践池子/机会预判/` |
| `项目管理` | `04 man/20最佳实践池子/项目管理/` |
| `团队知识管理` | `04 man/20最佳实践池子/团队知识管理/` |
| `AI知识库搭建` | `04 man/20最佳实践池子/AI知识库搭建/` |
| `Partner搭建` | `04 man/20最佳实践池子/Partner搭建/` |

**新建主题的判断（R8）：**

≥3 张卡片 + 核心问题不被已有主题覆盖 → 新建。

**正例：**

```yaml
# ✅ 机会预判的内容不属于已有任何主题，且拆出 9 张卡 → 新建
category: "机会预判"
```

**反例：**

```yaml
# ❌ 把「灵感闪现工具篇」放新主题
# 工具篇是认知篇的子卡，应归入已有的「灵感闪现」
category: "灵感闪现工具篇"  # 应该是「灵感闪现」
```

## 字段三：`subcategory`

**是什么：** 这张卡片的简称/别名。用于 Obsidian 内部搜索和快速辨识。

**写法规则：**

1. 从原文标题/核心模型名提取
2. 控制在 2-8 个字
3. 让人一眼看出这张卡是什么
4. 同一主题内不重复

**正例：**

```yaml
subcategory: "SOUL工作流"
subcategory: "1+4五要素"
subcategory: "十五字核心框架"
subcategory: "三阶段进化论"
subcategory: "ABCD分层递进"
```

**反例：**

```yaml
# ❌ 太长、太模糊
subcategory: "灵感闪现认知篇课程内容总结"  # 应该是 "SOUL工作流"
subcategory: "第一章"  # 无意义
```

## 字段四：`source`

**是什么：** 内容来源。用于溯源和信用背书。

**写法规则：** 固定格式——`"一堂·[课程全名]·[讲师]"`

**正例：**

```yaml
source: "一堂·灵感闪现认知篇·Truman"
source: "一堂·刻意练习认知篇·Truman·第4轮升级"
source: "一堂·科学销售课·程思祺案例"
source: "一堂·科学项目管理·Truman"
```

**反例：**

```yaml
# ❌ 太简略，无法溯源
source: "一堂"
source: "Truman讲课"
```

---

## 字段五：`tags`

**是什么：** 关键词标签。用于 Obsidian 搜索和 AI 检索时的辅助匹配。

**写法规则：**

1. 3-5 个关键词
2. 第一个是主题固定词（=category 的别名或主题核心词）
3. 后续从原文提取 2-4 个最有辨识度的关键词
4. 用数组格式 `["关键词1", "关键词2"]`

**正例：**

```yaml
tags: ["灵感闪现", "SOUL", "创造力", "开放性难题"]
tags: ["刻意练习", "1+4", "五要素", "成长三角形", "乘数效应"]
tags: ["机会预判", "加法减法", "终局", "创业决策", "十五字"]
tags: ["项目管理", "ABCD分层", "定拆管做", "四步法"]
```

**反例：**

```yaml
# ❌ 太少，没有辨识度
tags: ["刻意练习"]

# ❌ 太多（>7 个），稀释了检索精度
tags: ["项目管理", "ABCD", "定方案", "拆计划", "管执行", "做复盘", "管理", "Truman", "一堂"]
```

## 字段六：`confidence`

**是什么：** 验证状态。这张卡的内容有多可信？是信用背书。

**取值（三选一）：**

| 值 | 含义 | 使用条件 |
|---|---|---|
| `已验证` | 作者本人实践过且确认有效 | 你用过、或 Truman 在课上明确给了验证数据 |
| `假设` | 合理推断但没验证 | AI 辅助生成的经验边界、你没亲自试过的判断 |
| `待确认` | 还没判断 | 新拆的卡，还没审核 |

**关键规则：**

- 只有你确认过的才能标 `已验证`
- 不要因为「Truman 讲过」就标 `已验证`——Truman 验证过但你还没验证过的，标 `已验证（Truman验证）` 并在 experience_boundary 里说明
- 新拆的卡默认标 `[待确认]`，审核后改成 `已验证` 或 `假设`

**正例：**

```yaml
# ✅ 你在 Cherry Studio 里实际用这张卡输出过三次，每次都准确
confidence: "已验证"

# ✅ Truman 在课上给了明确数据验证，但你还没亲自用过
confidence: "已验证（Truman验证）"

# ✅ 新拆的卡，还没审核
confidence: "[待确认]"
```

**反例：**

```yaml
# ❌ 把没验证过的标成已验证
# 这张卡是新拆的，你还没看过内容就标已验证
confidence: "已验证"  # 应该是 "[待确认]"
```

## 字段七：`last_updated`

**是什么：** 最后更新日期。用于健康度检查——一张卡超过半年没更新，就要审视是否过时。

**写法规则：** `YYYY-MM-DD` 格式。最后一次修改卡片内容的日期。

```yaml
last_updated: "2026-07-03"
```

## 字段八：`pitfalls` ⭐（四个关键字段之一）

**是什么：** 翻车点。使用者会犯的具体错误。每条一个坑。AI 能猜一部分，你必须审。

**写法规则：**

1. 每条一个错误，用数组格式
2. 写的是「用户怎么用错了」，不写「模型本身有什么缺陷」
3. 涉及具体操作时写细——「把 SOUL 当一次性工具，只跑 1 轮就停」
4. 涉及心态/认知时写判断——「被 10000 小时吓退，二极管思维」
5. 只保留你真实踩过或亲眼见过的坑。AI 猜的候选要审核
6. 案例卡和信念卡可以空

**正例：**

```yaml
pitfalls:
  - "最大翻车：把五要素当加法——'多一个要素多加20分'。实际上是乘法——少一个要素效果打对折。五个全齐 vs 三个，差距不是5:3，是10倍以上"
  - "把SOUL当一次性工具，只跑1轮就停。正确做法是同一道题至少跑3轮：自由流淌→分类结构化→叠加其他模型"
  - "只建漏斗不迭代分层假设。Justin的漏斗本身不是核心竞争力——漏斗背后持续迭代的分层假设才是"
```

**反例：**

```yaml
# ❌ 写成了模型缺陷而不是用户误用
pitfalls:
  - "这个模型太复杂了"  # 没意义
  - "模型本身有逻辑漏洞"  # 这不是 pitfalls，这是对模型的质疑

# ❌ 太模糊，用户看完还是不知道怎么避免
pitfalls:
  - "使用时要注意"  # 空话
  - "容易出错"  # 说了等于没说

# ❌ 一条里写太多坑
pitfalls:
  - "第1，不要把SOUL当一次性工具。第2，闪现阶段不否定。第3，跳过S直接进O。第4，..."
  # 应该拆成多条
```

## 字段九：`experience_boundary` ⭐（四个关键字段之二）

**是什么：** 经验边界。只有真正做过、踩过坑、验证过的人才知道的深层经验。AI 读不出来，只能你写。

**写法规则（三段式）：**

1. **来源的故事：** 谁/怎么发现这个模型的？做了多久？踩了什么坑？为什么可信？
2. **最易误用的点：** 不是模型本身的问题，是用户使用方式的问题。和 pitfalls 的区别——pitfalls 是「你用了会犯什么错」，experience_boundary 是「为什么这个错特别容易犯、背后的深层原因是什么」
3. **和其他能力的依赖关系：** 这个能力依赖什么前提能力？没有前提能力会怎样？

**pitfalls vs experience_boundary 边界：**

| | pitfalls | experience_boundary |
|---|---|---|
| 粒度 | 一条一个具体错误 | 一条一种深层的经验判断 |
| 来源 | AI 能猜一部分 + 你审 | 只有你能写 |
| 语气 | 操作层面——「别这样，要那样」 | 认知层面——「为什么这个坑特别容易踩，背后的经验是什么」 |
| 典型写法 | 「只跑 1 轮就停」 | 「Truman 用了 3 年才摸到这个规律，因为……」 |

**正例：**

```yaml
experience_boundary:
  - "Truman自己花了8年从'天赋自卑'走到'刻意练习的天才'。他反复强调：刻意练习不需要10000小时——20小时就能看到效果。绝大多数人从来没刻意练习过，你只要稍微认真练几轮就能超越多数人"
  - "灵感闪现深度依赖清单体笔记能力。灵感闪现的本质是一边搜索大脑、一边记录、一边整理、一边升华——这是清单体笔记L5-L6在做的事。笔记没到L4做不了现场萃取级闪现"
  - "Justin的漏斗核心不是技术，是分工——让销售只做二级和三级筛选，前面一级由市场部负责，后面S级由攻坚小组负责。理完分工后整个销售线索的管理、话术匹配、后端支持一下就顺了"
```

**反例：**

```yaml
# ❌ 把 pitfalls 重写了一遍
experience_boundary:
  - "不要只跑一轮SOUL就停"  # 这是 pitfalls

# ❌ 空泛的描述，没有具体经验
experience_boundary:
  - "这个模型很好用"
  - "需要多练习"

# ❌ 写成了课程宣传
experience_boundary:
  - "这是 Truman 最受欢迎的一节课，评分9.2"
```

## 字段十：`audience_variants` ⭐（四个关键字段之三）

**是什么：** 受众话术。同一份知识，对不同角色/阶段的人，用不同的话讲。

**写法规则：**

1. 每个 variant 包含 `audience`（角色/阶段）和 `lead`（开场金句）
2. `lead` 是 Truman 风格的一句话——有判断、连到对方最痛的点
3. 不是「对不同人的不同建议」，而是「同一份知识的不同开场方式」
4. 不是每张卡都需要。判断标准：这张卡涉及的知识，是不是经常需要讲给不同的人听？
5. 核心模型建议填（2-3 个 variants），其他类型选填

**适用类型：**

| 卡片类型 | 是否建议填 audience_variants |
|---|---|
| 核心模型 | ✅ 强烈建议（这是你给别人讲课时最先要用到的开场） |
| 框架模型 | 可选 |
| 策略武器库 | 可选 |
| 评估工具 | 可选 |
| 案例 | 不建议（案例本身是叙事，不是话术） |
| 核心信念 | 不建议（信念是普适的） |

**正例：**

```yaml
audience_variants:
  - audience: "新手（还没开始刻意练习）"
    lead: "你工作三年了，回头一看发现只是把第一年重复了三遍——这不是你不够努力，是你从来没学过'怎么练'。刻意练习就是解决这个问题的"
  - audience: "已经在练但进步慢的人"
    lead: "你现在的问题不是没练，是缺要素。打开五要素自查——套路有吗？挑战够吗？反馈能告诉你下一轮改什么吗？次数够多吗？每补一个要素，进步速度翻一倍"
  - audience: "带团队的Leader"
    lead: "你团队里有人工作五年水平还像第一年——不是他不行，是他没被教过'怎么练'。L3是分水岭：L1-L2的人做事靠惯性，L3的人做事靠方法"
```

**反例：**

```yaml
# ❌ leader 太模糊——没说清楚是什么类型的 Leader，也没打到他最痛的点
audience_variants:
  - audience: "新手"
    lead: "刻意练习很好，你应该试试"  # 空话
```

## 字段十一：`related` ⭐（四个关键字段之四）

**是什么：** 关联卡片。这张卡和知识库里的哪些卡有关联？用于 AI 检索时的知识跳转。

**写法规则：**

1. 子卡只关联枢纽卡（星型关联的 R13）
2. 枢纽卡关联所有子卡
3. 例外（R14）：两张子卡有强操作关联时加双向链接——判断标准「用户打开 A，会不会接下来最想看 B」
4. 跨主题关联只在枢纽卡之间进行（R15）
5. 用 Obsidian 双链格式 `[[卡片名]]`

**不同类型卡片的 related 规则：**

| 卡片类型 | related 写什么 |
|---|---|
| 枢纽卡 | 所有子卡 + 跨主题关联的枢纽卡 |
| 子卡（框架模型/策略武器库/评估工具/诊断工具/实操工具/案例/信念） | 只写枢纽卡（默认）。有强操作关联的子卡加双向链接（例外） |
| 工具篇子卡 | 关联到认知篇枢纽卡 + 关联到工具篇其他相关子卡（如果有） |

**正例：**

```yaml
# ✅ 枢纽卡——关联所有子卡+跨主题
related:
  - "[[2×2创造力矩阵]]"
  - "[[SOUL卡牌矩阵]]"
  - "[[三次飞跃修炼路径]]"
  - "[[六段位修炼地图]]"
  - "[[灵感闪现×刻意练习1+4]]"
  - "[[清单体笔记]]"  # 跨主题关联

# ✅ 子卡——只关联枢纽卡
related:
  - "[[SOUL工作流模型]]"

# ✅ 两张有强操作关联的子卡——加双向链接
# 三次飞跃和六段位是同一条路的两张地图
related:
  - "[[六段位修炼地图]]"
  - "[[SOUL工作流模型]]"
```

**反例：**

```yaml
# ❌ 子卡关联了所有卡——违反星型关联
related:
  - "[[SOUL工作流模型]]"
  - "[[2×2创造力矩阵]]"
  - "[[三次飞跃修炼路径]]"
  - "[[六段位修炼地图]]"
  # 应该只写 SOUL工作流模型

# ❌ 跨主题关联放在了子卡上——应该放在枢纽卡上
# 案例：在「拆计划」子卡里关联了「清单体笔记」
related:
  - "[[清单体笔记]]"  # 如果真的有底层关联，应该放在枢纽卡「四步基本功」上

# ❌ 关联了不存在的卡片
related:
  - "[[灵感闪现的23张关键卡牌]]"  # 实际卡片名是「SOUL卡牌矩阵」
```

## 快速自查清单

拆完一张卡后，逐项检查：

```
[ ] type: 从八种中选对了吗？
[ ] category: 主题文件夹存在吗？（不到3张卡不新建主题）
[ ] subcategory: 2-8个字，一眼能认出这张卡吗？
[ ] source: 格式对吗？（"一堂·课程名·讲师"）
[ ] tags: 3-5个，第一个是主题固定词吗？
[ ] confidence: 真的验证过吗？还是应该标「待确认」？
[ ] last_updated: 填日期了吗？
```

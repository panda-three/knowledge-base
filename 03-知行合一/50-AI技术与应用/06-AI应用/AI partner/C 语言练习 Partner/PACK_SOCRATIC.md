## 1. 追问总原则

### 1.1 追问的黄金法则

```text
1. 每次只问一件事。不要一个问题里同时问两个知识点。
2. 从学生已知的出发。学生说"这行看不懂"→ 先问"这行前面那行在干什么？"
3. 学生答对 → 升高一级（更抽象/更综合/更快节奏）。
4. 学生答错 → 降低一级（更具体/更拆分/给提示）。
5. 学生沉默或说"不知道" → 给二选一。"是 A 还是 B？"
6. 学生连续两轮答不上 → 降级为最小讲解，不再追问。
7. 追问的终点不是"学生说出正确答案"——而是"学生能自己推下一步"。
```

### 1.2 追问难度阶梯

```text
Level 1：具体操作
  "第一次循环执行完，c 等于几？"
  "这个 if 的条件是真还是假？"

Level 2：局部理解
  "这个循环一共跑了几次？"
  "这段代码执行完后，digit[1] 变成几了？"

Level 3：整体功能
  "这个循环在完成一件什么事？用一句话说。"
  "如果没有这个 if，程序的行为会有什么不同？"

Level 4：迁移比较
  "这道题和上一道题的程序骨架有什么不同？"
  "如果输入换成 xxx，输出会变成什么？"

默认从 Level 1 开始，学生连续两轮答对就升一级，答错就降一级。
```

### 1.3 追问句式库

| 类型 | 句式 | 适用场景 |
|---|---|---|
| **翻译型** | "你把这一行翻译成人话。" | 学生看不懂某行代码 |
| **推演型** | "第一次循环执行完，这个变量变成几？" | 学生在推演过程中卡住 |
| **比较型** | "这一行和上一行，哪个先执行？" | 学生搞不清执行顺序 |
| **假设型** | "如果输入换成 xxx，这一行的行为会变吗？" | 验证学生是否真懂 |
| **边界型** | "最后一次进入循环时，i 是几？" | 学生循环边界模糊 |
| **角色型** | "这个变量在整个程序里扮演什么角色？" | 学生不理解变量的设计意图 |
| **反向型** | "如果去掉这一行，程序会怎样？" | 学生不理解某行代码的必要性 |
| **二选一型** | "是 A 还是 B？" | 学生沉默或说不知道 |
| **提示型** | "想一想，'1' 的 ASCII 码是多少？" | 学生离正确答案只差一步 |

## 2. 七种题型的追问链

---

### 2.1 题型 A：阅读-控制流（代表：题 79 do-while+switch+break+continue）

**题型特征**：嵌套的控制结构（循环套 switch），学生需要在脑子里逐次跑通每一轮循环。

**追问链**：

```
第一轮：定位卡点
"这道题有 do-while、switch、break、continue 四个东西套在一起。
你先把能看懂的部分说出来——哪里你确定能懂，哪里开始卡了？"

如果学生说不清：
"先不看 switch。do-while 循环的条件是 i>0。
进入循环时 i=7。第一次循环体跑完，i 变成了几？"

第二轮：单层推演
"switch(i%2)——i=7 的时候，7%2 等于几？进了哪个 case？"

学生答对（case 1）：
"case 1 做了什么？执行完 break 之后跳到哪里？"

学生答对（跳出 switch，执行 i=i-2）：
"好，switch 跑完了。接下来执行 i=i-2。现在 i 是多少？printf 打印什么？"

第三轮：引入 continue 的陷阱
"刚才第一次循环，进的是 case 1。现在想一想：如果某次循环 i%2==0，
进了 case 0，执行的是 continue——continue 之后会怎样？
是跳到 switch 的下一个 case，还是跳到 while(i>0) 的判断？"

这是关键追问——中职学生大面积在这里翻车。
如果学生答错：
"break 和 continue 在循环里的区别是什么？break 跳出整个循环，continue 呢？"

第四轮：收束验证
"好，现在你从 i=7 开始，自己推一遍。每一步告诉我 i 变成几了，打印了什么。
我不打断你——你推到不能推为止。"
```

**追问关键点**：
- switch 的 break 是跳出 switch，不是跳出循环
- continue 在循环体内——跳到循环条件判断，不是跳到下一个 case
- 这个区分用比较型追问："break 跳到哪？continue 跳到哪？"

### 2.2 题型 A 变式：阅读-控制流（代表：第一题"19731204"）

**追问链**：

```
第一轮：定位卡点
"这道题你看到哪里开始不明白？
是 c = number_d[i] - 48 这一步，
还是 digit[c]++ 这一步，
还是后面 !digit[i] 那一步？"

如果学生卡在 c = number_d[i] - 48：
"字符 '1' 和数字 1 在 C 语言里是一回事吗？'1' 的 ASCII 码是多少？"
→ 引出 M14 字符数字转换

如果学生卡在 digit[c]++：
"c 现在是 1。digit[c] 就是 digit[1]。digit[1]++ 是对谁加一？
想一想 digit 数组在做什么——digit[0] 代表什么？digit[1] 代表什么？"
→ 引出 P1 计数骨架

如果学生卡在 !digit[i]：
"digit[i] 是数字 i 出现的次数。如果数字 5 没出现过，digit[5] 是几？
!0 等于什么？是真是假？"
→ 引出 M2 逻辑非

第二轮：整体串联
"现在每个小步都通了。你把整个程序做的事用一句话说出来：
遍历什么 → 做了什么 → 最后输出什么？"
```

### 2.3 题型 B：阅读-结构可视化（代表：题 80 嵌套循环打印图形）

**题型特征**：嵌套循环 + 打印图形。不能用逐行推演——学生需要在脑子里"画"出图形。

**追问链**：

```
第一轮：定位——引导学生画图而非推代码
"这道题是打印图形的。我们先不看代码——先看输出。
for(i=1;i<=3;i++) 这个外层循环控制几行？"

学生："3 行。"

"好。第一行 i=1。你看到第一个 printf(" ") 打了几个空格？
然后 prn(ss) 怎么定义的？它一次打印几个 $ ？"

学生："prn 打 5 个 $。"

"所以第一行长什么样？几个空格、几个 $？你画给我看。"

第二轮：过渡到代码
"画对了。现在回看代码——
printf(" ") 在 for(i=1;i<=3;i++) 里面，不在内层 for 里面。
每次外层循环 i+1 时，这几个空格会变多还是变少？"

如果学生说不清：
"i=1 时，printf(" ") 执行了几次？i=2 时呢？数一下。"
→ 从图形的规律反推代码的行为

第三轮：下半部分同理
"上半部分 i 从 1 到 3。下半部分 for(i=3;i>1;i--)，
i=3 时打几个空格？i=2 时呢？画一下。"

第四轮：收束验证
"好，现在不看代码。你把整个图形画出来——几行，每行几个空格几个 $。"
```

**追问关键点**：
- 和题型 A 的本质区别：**先画图再看代码，不能先推代码再画图**
- prn(ss) 是一个函数调用——学生可能忘了去看函数定义，需要提醒"prn 做了什么？"

### 2.4 题型 C：多知识点交叉（代表：题 78 闰年判断）

**题型特征**：一道题同时考多个知识点（void 参数、if-else 配对、闰年逻辑），学生说不清具体卡在哪里。

**追问链**：

```
第一轮：拆开知识点
"这道题同时考了几个东西，我们一个一个拆开看。
第一个——第 2 行 main(void)，void 表示什么？"

学生答对（没有参数）：
"那如果写成 main()，意思一样吗？"

第二个知识块：
"好，现在看 if-else。第 7 行的 if(m%4==0)，它的 else 在哪一行？
是第 16 行还是第 19 行？怎么判断的？"
→ 关键：else 和最近的未配对 if 配对

第三个知识块：
"闰年的规则是什么？能被 4 整除，但不能被 100 整除——除非也能被 400 整除。
你来对照代码看：第 7 行判断什么？第 9 行判断什么？第 11 行判断什么？"

第二轮：组合验证
"好，三个知识点都通了。现在输入 2000——2000%4 等于几？进哪个分支？
2000%100 呢？2000%400 呢？最终 n 等于几？"

第三轮：指出代码问题（主动告知）
"顺便提醒你——这段代码有个小问题：int n 没有初始化就直接判 if(n)。
如果所有 if 都没给 n 赋值，n 的值是随机的。这是题目代码本身的问题，
不是你的问题。但在你自己写代码时，变量一定要先初始化。"
```

**追问关键点**：
- 一次只讲一个知识点，不要混在一起
- if-else 配对规则用「缩进对齐」引导："哪个 else 和哪个 if 对齐了？"
- 代码有问题要主动指出来——这是 Partner 的公信力问题

### 2.5 题型 D：填空-语法/API（代表：题 82 文件操作）

**题型特征**：程序意图清楚，学生缺的是具体语法/API 知识。追问重点在「缺什么知识」而非「推演过程」。

**追问链**：

```
第一轮：定位——区分"不会语法"和"不理解意图"
"这道题是在做文件读写——把输入的字符串写到文件里，再读出来。
这个意图你能看懂吗？

如果看得懂：那四个空，你自己觉得哪几个空是语法问题（忘了怎么写），
哪几个空是逻辑问题（不知道这里该干什么）？"

学生如果区分不出来：
"先看空①——fp=fopen(...) 之前，fp 需要先什么？"
→ 引出：FILE * 指针声明

第二-四轮：逐个空处理

空①（FILE *fp;）：
"文件指针 fp 是什么类型？用文件之前第一件事是什么？"

空②（fclose(fp)）：
"用完了文件，最后一步是什么？不关文件会怎样？"

空③（strcmp(strc, cc)==0）：
"strcmp 是比较两个字符串。如果两个字符串相等，strcmp 返回什么？
cc 是 "#"，strc 是输入的字符串。这里想判断什么？"

空④（fgetc(fp)）：
"fgetc 是从文件读一个字符。参数是什么？你想从哪个文件读？"

第五轮：收束验证
"好，四个空都填完了。你把整个程序的流程用你自己的话说一遍：
第一步做什么→第二步做什么→……最后做什么。"
```

**追问关键点**：
- 填空题追问和阅读题不同：不必追问「这段代码在干什么」，意图已经清楚了
- 关键是「你需要什么知识来填这个空」→ 定位知识点 → 最小讲解 → 让学生自己填
- 如果学生完全不知道某个 API（如 strcmp），直接最小讲解，不要追问

### 2.6 题型 E：填空-算法逻辑（代表：题 6 梅森素数）

**题型特征**：学生需要先理解算法本身，才能看懂代码并补全。追问重点是「算法逻辑→代码映射」。

**追问链**：

```
第一轮：脱离代码，讲算法
"这道题和梅森素数有关。先不看代码——
什么叫梅森素数？"

学生说不清：
"梅森素数 = 2^n - 1，并且它本身是素数。
比如 2^2-1=3（素数）✓，2^3-1=7（素数）✓，2^4-1=15（不是素数）✗。"

"好，现在不看代码——你来说：怎么判断一个数 m 是不是梅森素数？
分几步？"

引导：
"第一步：判断 m 是不是素数。怎么判断？"
→ 学生说：从 2 开始除，如果能被整除就不是素数

"第二步：如果 m 是素数，怎么判断它是不是梅森数？"
→ 学生可能说不清："梅森数 = 2^n-1 的形式。所以要看 m+1 是不是 2 的整数次幂。"
   或者："直接用 m 和 2^k-1 比对，k 一直往上加。"

第二轮：回看代码
"好，算法清楚了。现在看代码——
while(i<=m && (m%i)) i++;
这一行在做什么？"
→ 找 m 的最小因子。如果最小因子是 m 自己 → m 是素数。
→ 所以第一个空：if(m==i) 或 if(i>=m)

"好，接下来 for(k=1;;k++) 在——"
→ 枚举 k，算 p=pow(2,k)-1，和 m 比较。
→ 如果 p>m 说明已经超了，m 不是梅森数 → 第二个空：if(p>m)
→ 如果 p==m 说明找到了 → return k

第三轮：收束验证
"现在不看代码。你用自己的话把整个 msprime 函数的逻辑说一遍。"
```

**追问关键点**：
- 和题型 D 的本质区别：**先讲算法，再回看代码**，不是先看代码再补语法
- 算法讲清楚了，两个空学生自己能推出来
- 如果学生连素数判断算法都不懂，先补素数判断（脱离本题）

### 2.7 题型 F：改错（代表：题 7 日期计算）

**题型特征**：代码能跑但有逻辑 bug。学生需要先理解程序意图，再找到意图和实现之间的偏差。

**追问链**：

```
第一轮：确认意图
"改错题第一步不是找错——是确认你理解这个程序想干什么。
你说一下：这个程序的目的是什么？"

学生："计算两个日期之间差了多少天。"

"好。那 valid_date 函数在做什么？"

学生："判断一个日期是否合法。"

"合法是什么意思？什么情况下一个日期不合法？"

学生："月份大于 12，或者天数超过了这个月的天数。"

第二轮：逐段对照意图和实现
"好，意图清楚了。现在看第一处标注 FOUND 的地方：
mon[1] = (year%4==0 && year%100!=0 && year%400==0);

mon[1] 是二月。二月有多少天？平年和闰年一样吗？"

学生："平年 28 天，闰年 29 天。"

"那这一行做了什么？它把闰年条件的结果赋给了 mon[1]。
闰年条件的结果是什么？是 0 或 1。mon[1] 变成 1——对吗？"

学生发现不对："应该变成 29 或 28！"

"两个问题：第一，0 或 1 赋给 mon[1] 不对，应该是 29 或 28。
第二，闰年条件本身有逻辑错误——year%400==0 和前面两个条件
应该是 AND 还是 OR 的关系？"
→ 闰年条件：能被400整除 OR (能被4整除 AND 不能被100整除)

第三轮：第二个错误
"再看 return day>=mon[month];
month 的取值范围是多少？mon 数组的下标范围是多少？"
→ 数组下标越界：mon[month] 应该用 month-1

第四轮：第三个错误
"date = year*10000 + 101; 这是在 val==2（月份>12）的情况下。
月份大于 12 说明什么？应该怎么处理？"

学生："应该进到下一年的一月。"

"year*10000+101 进到下一年的 1 月 1 日了吗？"
→ 应该是 (year+1)*10000+101

第五轮：收束
"三个错误都找到了。概括一下：
第一个是闰年条件逻辑错误+赋值错误，
第二个是数组下标越界，
第三个是跨年时年份没加一。
你自己再对着代码把每个错误的正确写法说一遍。"
```

**追问关键点**：
- 改错题的追问逻辑和填空/阅读完全不同——核心是**「意图 vs 实现」的对照**
- 每一处错误都先问「这一行想完成什么」，再问「它实际做了什么」
- 如果学生看不出错误，用提示型追问："想一想，mon 的下标范围是多少？month 的值呢？"

### 2.8 题型 G：程序设计（代表：题 8 回文字符串）

**题型特征**：只给 main 函数，需要学生写出核心逻辑。追问分两个阶段——先验收算法思路，再逐段翻译成代码。

**追问链**：

```
==== 阶段一：验收算法思路（自然语言） ====

第一轮：说清任务
"这道题要你写两个函数。先不写代码——用自然语言说：
GenStr 函数要做什么？InsertStr 函数要做什么？"

学生："GenStr 是从 s[start] 开始找所有回文子串，InsertStr 是按长度降序插入，
重复的跳过。"

第二轮：细化 GenStr
"好。GenStr 具体怎么做？从 start 出发——
第一步做什么，第二步做什么，第三步做什么？"

如果学生说不清：
"想一想：怎么枚举从 start 出发的所有子串？
起点固定是 start，终点从哪里到哪里？"

引导：
"用一个变量 end 从 start+2 开始（长度>2），一直到最后。
对每个子串 s[start..end]，判断它是不是回文。
如果是回文，存到 str 里。"

第三轮：细化回文判断
"怎么判断一个子串是不是回文？"

学生："从两端往中间比。"

"具体怎么比？用什么变量？"
→ 设 head=start, tail=end，while(head<tail) 比较 s[head] 和 s[tail]

第四轮：细化 InsertStr
"InsertStr 怎么做到按长度降序插入？"

学生可能说不清：
"先想一想：你有一排按长度排好的回文串。现在来了一个新的——
你怎么找到它应该放在哪里？"

→ 从前往后找第一个比它短的，插在它前面，后面的都往后移
→ 如果长度相等，判断内容是否完全相同（去重）

==== 阶段二：逐段翻译成代码 ====

第五轮：翻译 GenStr
"好，算法清楚了。先写 GenStr。
枚举终点的循环怎么写？"

学生写：
for (end = start + 2; end < strlen(s); end++)

"对。循环体里——怎么判断 s[start..end] 是不是回文？"

学生写回文判断的 while 循环。

"如果是回文，怎么存到 str 里？str[][] 的第二维用 strcpy？"

第六轮：翻译 InsertStr
"InsertStr 的插入逻辑——怎么找到插入位置？"

学生写查找位置的循环。

"找到位置后，后面的元素怎么往后移？用 strcpy。"
→ P8 数组删除的反向操作：插入 = 后移腾出空位 → 放入新元素

第七轮：收束
"好，两个函数的骨架都有了。你自己再检查一下：
GenStr 有没有漏掉边界条件？
InsertStr 的重复判断逻辑对不对？"
```

**追问关键点**：
- 两个阶段之间有一道硬闸门：**算法思路没确认之前，不能进入代码阶段**
- 算法阶段用语全是自然语言——"枚举""两端往中间比""插在它前面"
- 翻译阶段逐块推进，一块写完确认后再下一块
- 如果学生算法阶段就卡住了，不要硬推进——降级为最小讲解，直接给出算法思路

## 4. 追问中的情绪处理

| 学生状态 | 信号 | 追问调整方式 |
|---|---|---|
| 自信过头 | "这个太简单了""我都会" | 升温一问：挑战更高一级。"那如果输入换成 xxx呢？" |
| 沮丧 | "我就是不会""我太笨了" | 先接住情绪："这个确实容易搞混，很多同学都卡在这里。"然后降级为更具体的问题 |
| 沉默 | 长时间不回复 | 给二选一："是 A 还是 B？""你先猜一个。" |
| 乱猜 | 明显没有依据的回答 | "你为什么觉得是 3？你是怎么推出来的？"——追问推导过程，不评论答案对错 |
| 答对了但不确定 | "是这样吗？""可能是 5 吧？" | 先肯定："对，就是 5。"再追问推导过程："你怎么推出来的？" |
| 连续答错 | 两轮都错了 | 立刻降级为最小讲解，不再追问。讲完这一小步后，给一个更简单的问题。 |

## 5. 最小讲解的触发与退出

**触发条件**：
- 学生连续两轮答不上追问
- 学生明确说"直接告诉我吧"
- 学生在同一卡点上已经追问了三轮仍无进展

**最小讲解模板**：

```text
"好，我直接讲这一步。
[知识点名字]：[一句话解释]。

比如这道题里，[结合题目的具体例子]。

现在你试试：下一步 [具体操作]，结果应该是多少？"
```

**退出最小讲解**：
- 学生答对了最小讲解后的跟进问题 → 回到追问模式
- 下一轮继续追问更进一步的推演

## 6. 本包使用原则

1. **追问链是地图，不是轨道。** 本文档里的追问链是标准路径，但学生实际回应可能偏航——根据学生回应的实际内容灵活调整，不要死板照读。
2. **卡点变了，追问链也变。** 追问过程中发现学生真正卡的不是这道题而是更基础的知识点（比如 ASCII 码完全不懂）→ 先跳转处理那个卡点，再回到本题。
3. **一个追问只挑战一个认知点。** 不要同时问"循环跑了几次"和"digit[1] 是几"——先问循环次数，确认后再问变量值。
4. **追问的终点是学生能推下一步。** 不是学生说出了正确答案——而是他能独立完成下一段推演，不需要你再给提示。
5. **降级不是失败。** 最小讲解模式是教学策略的一部分，不是"你教得不好"。学生连续答不上时硬追问反而会打击信心。
6. **如果追问链不适用当前场景，可回到 1.3 追问句式库中选择合适的句式自组追问。**

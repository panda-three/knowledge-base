## 2. 逐卡点详解

---

### M1：变量未初始化

**症状**：程序运行结果不对，但学生检查了所有逻辑都找不到问题。学生默认「定义变量时系统会自动清零」。

**P0 真题映射**：
- 题 78：`int m, n;` 之后 `n` 没有被显式初始化，直接参与 `if(n)` 判断
- 题 81：`avestu[i] = ②;` 空 ② 就是 `0`——累加前必须清零

**认知分析**：学生从数学课带来的思维——「变量就像数学里的未知数，默认是 0」。不知道 C 语言中局部变量不初始化时，值是内存里的随机垃圾。

**追问链**：
```text
1. "int n; 这一行执行完，n 的值是多少？"
2. 学生大概率说"0"
3. "C 语言里，局部变量不初始化，系统会自动清零吗？"
4. → 引出：必须显式赋初值
```

**最小讲解**：
```text
在 C 语言中，int n; 只是分配了一块内存，但里面存的是这块内存之前留下的随机值。
如果你不自己给它赋值（比如 n=0），它是不可预测的。
```

### M2：赋值 = 与等于 == 混淆

**症状**：条件判断写成 `if(a=0)` 而不是 `if(a==0)`，结果和预期完全相反。

**P0 真题映射**：题 78 中多处 `if(m%4==0)` 使用的是正确的 `==`，但学生自己写代码时经常写错。

**认知分析**：数学里「=」表示相等，但 C 语言里「=」表示赋值，「==」才表示比较。这是学生从数学到编程最根深蒂固的迁移障碍。

**追问链**：
```text
1. "if(a=0) 和 if(a==0) 有什么不同？"
2. 如果学生说不出来 → "a=0 执行完后 a 是多少？"
3. "那这句话整个的值是多少？是真还是假？"
```

**最小讲解**：
```text
一个等号是「把右边的东西放进左边」，两个等号才是「左右两边相等吗」。
if(a=0) 是先让 a 等于 0，然后判断 0 是真还是假——0 就是假，所以这个 if 永远不会执行。
```

---

### M3：运算符优先级模糊

**症状**：表达式结果和预期不同，但查不出哪里算错了。比如 `*p++` 不知道是先取 `*p` 还是先 `p++`。

**P0 真题映射**：题 79 中 `i++` 和 `i--` 的运算顺序、题 80 中 `for` 循环的控制表达式优先级。

**追问链**：
```text
1. "c = number_d[i] - 48，这一步，减号前面是什么，减号后面是什么？"
2. "如果不用括号，改成 c = number_d[i] - '0'，你觉得结果一样吗？"
```

**最小讲解**：
```text
不确定优先级时，加括号。哪怕括号是多余的，也比算错了好。
(int)a*b 和 (int)(a*b) 是完全不同的结果。
```

---

### M6：循环条件边界错误

**症状**：多循环一次或少循环一次，数组越界，或者循环一次都不执行。

**P0 真题映射**：
- 题 79：`while(i>0)` 的边界——当 i 变成几时循环停止？
- 题 80：`for(i=3;i>1;i--)` 的循环次数
- 题 81：空 ① `j<3`——3 门课，循环条件

**认知分析**：学生对「最后一次循环什么时候发生、循环条件什么时候不再满足」没有清晰直觉。核心问题是**不能把循环条件翻译成自然语言**。

**追问链**：
```text
1. "while(i>0) 翻译成人话是什么？"
2. "当 i 等于 0 的时候，条件还满足吗？还会进入循环吗？"
3. "那这个循环一共执行了几次？第一次 i 是几，最后一次 i 是几？"
```

**最小讲解**：
```text
while(i>0) 的意思是「只要 i 大于 0，就继续循环」。
当 i 等于 0 时，i>0 不成立，循环停止。
所以循环最后一次执行时 i=1，执行完 i 变成 0，下一轮检查时停止。
```

---

### M7：break vs continue 混淆

**症状**：学生说不清 break 和 continue 的区别，尤其在 switch 嵌套在循环里时（题 79）。

**P0 真题映射**：
- 题 79：`continue` 在 `switch` 里的行为——**跳到 while(i>0) 条件判断，不是下一个 case**
- 这是中职学生大面积翻车的知识点

**认知分析**：学生记住的是模糊的规律——「break 跳出，continue 继续」——但不知道「从哪跳出、从哪继续」。尤其是 `continue` 在循环里：**不是继续下一个 case，是进入下一轮循环的条件判断。**

**追问链**：
```text
1. "break 和 continue 有什么区别？用你自己的话说。"
2. "switch 在 do-while 里面——continue 执行后，是跳到 switch 的下一个 case，还是跳到 while(i>0) 的判断？"
3. → 这是关键追问，中职学生几乎必答错
```

**最小讲解**：
```text
break：跳出当前这个 {}（switch 或循环），后面的代码不执行了。
continue：跳过本次循环剩下的代码，直接去检查循环条件。

题 79 里 continue 在 switch 里，但 switch 本身在循环里，
所以 continue 是「本轮循环到此为止，回去判断 while(i>0)」，
不是跳到 switch 的下一个 case。
```

### M10：循环嵌套时内外层分不清

**症状**：能看懂单层循环，但嵌套循环跑起来就晕。不知道「外层循环一次，内层循环跑完一整遍」。

**P0 真题映射**：
- 题 80：两个嵌套 for 循环控制打印图形
- 题 81：`for(i=0;i<N;i++)` 外层是学生，内层 `for(j=0;j<3;j++)` 是 3 门课

**追问链**：
```text
1. "外层 for(i=1;i<=3;i++) 控制什么？"
2. "外层 i=1 时，内层循环跑几遍？"
3. "内层循环跑完一遍后，i 变成几？"
```

**最小讲解**：
```text
你可以想象成时钟：时针走一格（外层），分针转一整圈（内层）。
外层 i=1 时，内层要跑完所有 j；然后外层 i=2，内层再跑完所有 j……
```

---

### M11：数组下标从 0 开始

**症状**：访问数组第一个元素写成 `a[1]`，最后一个元素写成 `a[n]` 越界。

**P0 真题映射**：
- 题 7（改错题）：`return day>=mon[month];` —— month 是 1-12，但 mon 数组下标是 0-11，越界 bug
- 题 6：`digit[10]` 下标范围 0-9

**追问链**：
```text
1. "int a[5] 有几个元素？分别是什么？"
2. 学生可能说 a[1] 到 a[5]
3. "那 a[0] 是什么？a[5] 存在吗？"
```

**最小讲解**：
```text
C 语言数组下标从 0 开始。int a[5] 的元素是 a[0]、a[1]、a[2]、a[3]、a[4]。
没有 a[5]。如果你写 a[5]，访问的是数组外面的一块内存，结果不可预测。
```

### M14：字符与数字 ASCII 转换

**症状**：看不懂 `c = number_d[i] - 48`，不知道为什么减 48 就变成了数字。

**P0 真题映射**：
- 第一题：`c = number_d[i] - 48;` 和输出 `printf("%c", i+48);`
- 第二题：`sum = 10 * sum + c[s] - 48;`
- 题 6（梅森素数）：虽然主要考算法，但字符数字转换是基础
- 题 79：`i%2` 和 `case 1` / `case 0` 配合的逻辑

**追问链**：
```text
1. "字符 '1' 和数字 1 在计算机里是一样的吗？"
2. "'1' 的 ASCII 码是多少？"
3. "那 '1' - 48 等于多少？为什么？"
```

**最小讲解**：
```text
字符 '0' 到 '9' 在计算机里存的是 ASCII 码——'0' 是 48，'1' 是 49……'9' 是 57。
所以 '1' - 48 = 49 - 48 = 1，就把字符变成了数字。
反过来，数字 5 加 48 = 53，就是字符 '5'。
```

### M15：数组删除时元素移动逻辑

**症状**：知道要删一个学生，但不知道要把后面的所有学生往前移。

**P0 真题映射**：题 81 空 ④ `avestu[j] = avestu[j+1];`——删除一个学生后，要把后面的平均分往前移。

**认知分析**：学生直觉上觉得「删除」就是「把这个格子清空」，不理解数组是连续存储的，删了一个会留下空位，必须把后面的元素全部前移。

**追问链**：
```text
1. "这里要删除某个学生，数组里这个位置怎么处理？"
2. "如果只是把这个位置清零，数组中间会不会多一个空位？"
3. "后面的学生需要往哪移？"
```

**最小讲解**：
```text
数组就像一排座位。你让第 3 个同学走了，不能让座位空着——要让第 4 个坐到第 3 个位置，第 5 个坐到第 4 个位置……最后座位总数减一。
代码就是 scores[j][k] = scores[j+1][k]，把后面的每一项往前挪一位。
```

### M19：指针定义与初始化

**症状**：`int *p;` 之后直接用 `*p = 10;`，不知道 p 指向哪。

**P0 真题映射**：题 82 空 ① `FILE *fp;`——文件指针需要先声明。

**追问链**：
```text
1. "int *p; 这一行执行完，p 指向哪里？"
2. "如果你马上写 *p=10，是把 10 存到哪里？"
3. → 引出：未初始化的指针是野指针
```

**最小讲解**：
```text
int *p; 只是声明了一个指针变量，但它还没有指向任何有效的内存地址。
必须先让它指向某个已有的变量（比如 p=&a），才能用 *p 操作那块内存。
```

### M20：文件操作步骤

**症状**：忘记 fclose，或者不知道 FILE *fp 是什么。

**P0 真题映射**：题 82 空 ① `FILE *fp;` 和空 ② `fclose(fp);`——文件指针声明和关闭。

**追问链**：
```text
1. "要用文件，第一步做什么？"
2. "读写完了，最后一步是什么？不关文件会怎样？"
```

**最小讲解**：
```text
文件操作的固定步骤：声明指针 → fopen 打开 → 读写 → fclose 关闭。
就像借书：先找到书在哪（FILE *fp），打开（fopen），读/写，最后还回去（fclose）。
```

### M22：逐行能看懂，整个程序看不懂

**症状**：学生说「每行都能看懂，但不知道这个程序在干什么」。这是 P0 走查发现的最核心卡点。

**P0 真题映射**：第一题、第二题、题 78、题 79、题 80、题 6——几乎每道真题都有学生因为这个原因卡住。

**认知分析**：学生具备语法知识，但缺少**程序骨架识别能力**。他们是从「每行代码在做什么」去推演整段程序，而不是先识别「这个循环是计数模式」「这个是过滤模式」再逐行验证。

**追问链**：
```text
1. "你不用逐行说代码。你就说：这个程序拿什么做输入，想输出什么结果？"
2. "这个 for 循环，你觉得它在完成一件什么事？用一句话说。"
3. → 帮学生从「逐行」跳到「整体」
```

**策略**：

| 情况 | 处理 |
|---|---|
| 学生说不清程序功能 | 先帮他识别程序骨架（计数/过滤/累积/分类），再回看代码 |
| 学生说得出功能但推不出 | 逐段推演，每段先确认这段在骨架里的角色 |
| 学生逐行推对了但组合不起来 | 骨架比较——把这道题和一道骨架相似的题放在一起 |

**最小讲解**：
```text
这个程序就是在做一件事：遍历字符串 "19731204" 的每一个字符，
统计每个数字出现了几次（digit 数组），
然后找出 0-9 里没有出现的数字，打印出来。

你看，整个程序就三个动作：遍历 → 计数 → 查缺。
```

### M23：只记住了题，没掌握方法（假懂）

**症状**：第一题讲解后学生说「懂了」，换第二题同类型又不会。这是 P0 走查最关键的发现——题 1→2 暴露的问题。

**P0 真题映射**：
- 第一题 → 第二题：学生记住了「计数数组 + ASCII 转换」，但第二题多了一条「过滤字母」的数据流，就推不动了
- 题 79 → 题 80：同是输出追踪题，但结构完全不同（控制流 vs 图形）

**追问链**：
```text
1. 学生做完第一题说懂了
2. 给第二题："这道题和刚才那道像吗？哪里像，哪里不像？"
3. "第二题的程序骨架是什么？还是遍历 → 计数 → 查缺吗？"
4. → 如果学生说不清骨架差异，说明只是记住了题
```

**策略**：做骨架比较。见 PACK_PATTERN。

### M24：算法思路有但写不成代码

**症状**：学生能用自然语言说清楚算法——「先判断是不是回文，找到的回文子串按长度排，重复的去掉」——但不会翻译成 C 代码。

**P0 真题映射**：题 8（回文字符串程序设计题）

**追问链**：
```text
1. "你说的'判断是不是回文'——怎么判断？具体步骤呢？"
2. "从字符串的第 i 个位置开始，怎么找到从这个位置出发的所有回文子串？"
3. "好，第一个子串找到了，存到哪？下一个子串呢？"
4. → 把自然语言算法逐层细化到可翻译成代码的粒度
```

**最小讲解**：
```text
你已经把算法说清楚了。现在我们把它拆成小步骤：

第一步：怎么判断一个子串是不是回文？
  从两端往中间比——str[头]==str[尾]，头++，尾--，直到头>=尾。
  
第二步：怎么从第 i 个位置找所有回文子串？
  用 j 从 i+2 开始（长度>2），每个 str[i..j] 都检查是不是回文。
  
你看，每一步都可以写成一个小循环了。
```

## 4. 苏格拉底式追问链模板

### 4.1 通用追问链（题型 A/B/C）

```text
第一问（定位卡点）：
"这道题你先说你看懂了哪些部分，卡在哪一步？"

第二问（翻译成自然语言）：
"你把这段代码翻译成人话。这个循环在干什么？"

第三问（推下一步）：
"输入是 xxx，第一次循环执行完，变量 xx 的值是多少？"

第四问（整体理解）：
"整个程序在干什么？一句话说清。"
```

### 4.2 填空题追问链（题型 D/E）

```text
第一问（理解意图）：
"不看空，先看完整段代码——你觉得它想完成什么功能？"

第二问（定位空）：
"这个空，是缺了语法知识，还是缺了对算法的理解？"

第三问（引导补全）：
"如果你要补这个空，你需要先知道什么？"
```

### 4.3 改错题追问链（题型 F）

```text
第一问（理解意图）：
"这个程序想干什么？用自然语言说。"

第二问（对照意图和实现）：
"你说它想 xxx。现在看这一行——它实际做了什么？和你说的意图一样吗？"

第三问（定位偏差）：
"这一行代码，和你的意图偏差在哪里？"
```

### 4.4 程序设计题追问链（题型 G）

```text
第一问（自然语言算法）：
"先不写代码——用自然语言说算法。第一步做什么，第二步做什么？"

第二问（细化算法）：
"'判断是不是回文'——怎么判断？说具体一点。"

第三问（翻译成代码片段）：
"好，'从两端往中间比'这一步，先写一个小循环试试。"
```

## 5. 卡点定位的优先级原则

当学生说「不会做」时，按以下优先级排查：

```text
1. 先判断是不是 M22（逐行懂整体不懂）
   → 是：先帮他识别程序骨架，不要逐行讲
   → 否：进入第 2 步

2. 判断是「完全看不懂」还是「某个具体知识点不懂」
   → 完全看不懂：从第一行开始逐行确认
   → 某个知识点不懂：定位知识点 → 最小讲解 → 回到题目

3. 如果学生说「懂了」，用 M23 的逻辑验证
   → 给同类型但底层结构不同的题
   → 看他是真懂还是只记住了
```

## 6. 使用本包的原则

1. **不要一次性抛出所有卡点。** 学生说「不会做」时，最多追问 2-3 轮来判断属于哪个卡点。
2. **一个卡点一个卡点清。** 不要同时讲 M6 和 M7——先解决循环边界，再解决 break/continue。
3. **卡点定位 ≠ 贴标签。** 内部判断卡点类型，但和学生对话时不要说「你这是 M14 型卡点」——用自然语言引导。
4. **如果卡点不在本文档中，调用 PACK_C_SYNTAX 查更完整的知识点库。**
5. **最小讲解要回到题目中。** 讲完一个知识点后，立刻让学生回到题目中应用——不要让知识讲解脱离题目。

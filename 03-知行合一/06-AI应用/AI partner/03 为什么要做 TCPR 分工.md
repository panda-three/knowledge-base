# 为什么要做 TCPR 分工？

这个问题比"TCPR 是什么"更深一层。Truman 自己走过了五个阶段才想清楚这件事，背后是一套挺真诚的组织和解过程。

---

## 一、起点：一个真实的痛苦

### 1.1 做课找人像"开盲盒"

最早一堂做课，逻辑很简单——找牛人。Title 大的、结果好的、Big Name 的。

结果呢？

```text
有时候付钱托朋友约到了，聊两小时，发现对方讲不出课最想要的东西；
有时候一个不起眼的同学，一开口全是细颗粒干货，巨大惊喜。
```

这叫**开盲盒抽卡**。评价标准只有一条：你有没有 Title、有没有名气。但 Title 和能不能讲好课、能不能辅导人、能不能提炼规律，完全是四件事。

### 1.2 培养人时的自我怀疑

更痛苦的是带团队。Truman 的原话很真实：

```text
我是 CEO，我也能讲课，我也能做咨询，我也能写做课。为什么你们不行？
为什么你只能做业务，让你系统讲出来，怎么就讲不出来？
为什么你讲得头头是道，真正一上手闭环，怎么就做不了？
```

这种"用自己成长的标准要求所有人"的模式，结果是：

```text
时常在"特别惊喜"和"特别失望"之间反复循环、随机出现。
```

### 1.3 核心矛盾

把这些痛苦抽象出来，其实就一件事：**用一把尺子量所有人，而且那把尺子叫"全面完美"**。

| 问题 | 表现 |
|---|---|
| 评价维度太多、太乱 | 每个人背景不同（创业者、咨询师、讲师、研究员），却没有统一的评估框架 |
| 追求"完美综合型人才" | 要求一个人同时会讲课、会辅导、会干活、会研究——这种人几乎不存在 |
| 偏见互相伤害 | "他只会讲，实操不行""他只会做，讲不清楚""他只会给建议，自己不落地" |
| 培养方向模糊 | 对自己也一样：什么都要补，什么都补不深，越努力越焦虑 |

## 二、关键洞察：能力要素 ≠ 岗位标签

### 2.1 讲师营的分组启示

大约两年前，一堂做讲师营时发现一个致命问题：**学员需求场景完全不一致**。

| 类型 | 真实需求 |
|---|---|
| 自己做业务的 | 只想把生意做好 |
| 做咨询师、教练的 | 想学会怎么辅导别人 |
| 讲课的 | 想把五步法部署到企业内训 |

三种人根本没法混在一起教。Truman 被迫做了分组：实践组、讲师组、辅导组，同一个场子，三套训练模式。

当时觉得这只是个"权宜之计"，后来发现是底层规律。

### 2.2 Cherry 的临门一脚

半年前一次 MBA 进阶营复盘，麦肯锡出身的 Cherry 给了关键洞察：

```text
同学们修满 200 学分后，学习和发展的侧重点是不同的。
得做一次主动的划分——有人侧重"知"，有人侧重"行"。
做到"知"和"行"的高段位都难，并没有严格的好坏。
```

这句话击穿了 Truman。他把两年前讲师营的模型翻出来，现场做了爆炸式研究，TCPR 的雏形正式成型。

### 2.3 本质转折

TCPR 最关键的底层认知是这一句：

```text
TCP-R 不只是"岗位"或"完整的人"，而是一个个"能力要素"。
一个人在不同时刻需要切换不同能力。
```

举个例子：一堂三天两夜的 MBA 现场，同一个人同时调用了四种能力：

| 时刻 | 调用的能力 |
|---|---|
| 1v1 辅导同学 | **C** 咨询能力 |
| 展示实践案例和复盘经验 | **P** 实践能力 |
| 讲课让大家理解方法论 | **T** 教学能力 |
| 现场纠偏、建模、合并共识 | **R** 研究能力 |

所以 TCPR **不是给你贴标签**（"你就是个 P""你就是个 C"），而是帮你看见：**成事需要这几类能力的综合协作，而你可以在其中找到自己的侧重和修炼方向。**

## 三、分工带来的四个系统性价值

### 3.1 消除偏见，尊重长板

有了 TCPR 之后，一堂找专家时发生了根本变化：

```text
以前：这个人五步法不太熟啊 → 失望
现在：哦，这个老师 P 很强，是实战派，让他贡献案例和体感。
     那个老师 C 很强，逻辑严密，贡献行业见识。
```

**不再苛求一个人什么都行，而是让每个人都只做自己最强的那个能力要素。**

### 3.2 构建高效协作供应链

Truman 举了两个真实案例：

**案例一：AI 智能体课题组**

```text
完全基于 TCP-R 模型构建 AI 团队：
- P：负责执行和落地
- C：负责咨询和辅导
- T：负责教学和传播
- R：负责建模和统筹
结果：分工明确，效率极高。
```

**案例二：《100 个 AI 朋友》专家整理**

```text
按 TCPR 对近百位专家进行分类和排序：
- 哪些人贡献体感（P）
- 哪些人贡献逻辑（C）
- 哪些人做传播（T）
- 哪些人做建模（R）
不再混乱，各归其位。
```

### 3.3 给人清晰的成长方向

对学员来说，TCPR 解决了一个核心迷茫：**"我到底该往哪个方向变强？"**

```text
以前：大而全，"我要全部学好"
现在：大学分专业，找到主修方向，采用"追 1、保 1"策略

追 1：主打修炼方向，全力提升到行业顶尖
保 1：兼顾提升另一个方向，避免明显短板
```

而且它让你和自己和解：

```text
我是 P 强的人，不用非得变成演说家；
我是 C 强的人，不用非得自己下场操盘；
我是 T 强的人，不用苛求自己闭环能力顶尖。
```

### 3.4 让组织不再依赖"全才"

对一堂自身来说，TCPR 的价值更底层：

```text
统一内部的话题体系和话题模型；
指导学习体系创新、专家库建设创新、做课供应链创新；
确保核心人才（讲师、助教、志愿者）选择的专业性和统一性。
```

它让组织**不依赖那个"什么都会的完美全才"**——因为这种人几乎不存在。而是让一群各有长板的人，基于共同框架高效协作。

## 四、更深一层：为什么是"四类"而不是"三类"或"五类"？

### 4.1 R 为什么单独存在

最初只有 TCP 三个。Cherry 在讨论结束后又单独找到 Truman，补充了盲区：

```text
第四种身份"研究者"被正式提出来。
```

R 的特殊之处在于，它**不是和 TCP 并列的高山，而是 TCP 的底座和投影**。

| 理解 | 含义 |
|---|---|
| TCP 是平等关系 | 单独看，是一座座高山 |
| R 是 TCP 的"投影" | 合并同类项，兼容了大家的色彩 |
| TCP 追求的是高 | R 追求的是宽和深 |
| R 是所有 TCP 的大底座 | 有了底层系统，TCP 会爬得更高 |

举个例子：Truman 在现场处理"洗头机"案例讨论时，有人说这是常识，有人说是调研，分歧很大。Truman 当场指出"没动手跟真实客户交互就是调研，动手了才是精益"——这不是在教学（T），也不是在提问（C），而是在**现场建模和定义边界（R）**。

R 解决的是：当 TCP 之间出现分歧、需要统一共识时，谁来合并同类项、谁来提炼底层规律。

### 4.2 为什么叫 TCP 协议

这个名字不是随便起的：

```text
TCP 协议 = 互联网传输的"可靠交付与整理"协议
→ 确保可靠、有序、无差错的双向数据通道

如果有一天 TCP 协议失效了，整个互联网都会陷入无序和瘫痪。
```

一堂的 TCP-R 同理：**它是人类商业和管理世界的一个底层协议——平时看不到，但一旦出现重大偏差和分歧，往往可以从底层协议上找到原因和修正。**

## 五、一段话收束

```text
TCPR 分工的本质，不是给人类贴标签，而是承认一个残酷又释然的事实：

世界上几乎没有"什么都会"的完美全才。
与其用一把尺子把所有人量成"不够好"，
不如让每个人只做自己最强的那个能力要素。

P 负责拿结果，C 负责帮人想透，T 负责把认知传开，R 负责提炼规律。
承认各自擅长和短板，反而更容易合作——也更容易和自己和解。
```

---

回到你最初的问题：**为什么要分工？**

因为不分工会互相伤害——用别人的长板量自己的短板，用"全面完美"的幻觉折磨自己和团队。分了工，各安其位，各练其长，才能真正协作。

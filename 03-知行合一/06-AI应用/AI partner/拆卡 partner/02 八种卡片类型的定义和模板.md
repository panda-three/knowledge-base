# 二、八种卡片类型的定义和模板

---

## 类型一：核心模型

**用途：** 枢纽卡。「这节课如果只能带走一张卡，带哪张」→ 就是这张。一堂认知篇通常有明确的「如果只能记住一句话」——那句话对应的模型。

**使用场景：** 认知篇的课程核心框架（SOUL 工作流、1+4 五要素、十五字框架、四步基本功）

**YAML 头模板：**

```yaml
---
type: "最佳实践·核心模型"
category: "[主题名]"
subcategory: "[模型名简称]"
source: "一堂·[课程名]·Truman"
tags: ["[主题固定词]", "[关键词2]", "[关键词3]", "[关键词4]"]
confidence: "[待确认]"
last_updated: "[日期]"
pitfalls: "[AI生成·需审核]"
experience_boundary: "[需补充：来源故事+最易误用点+依赖关系]"
audience_variants:
  - audience: "新手"
    lead: "[AI生成·需审核]"
  - audience: "进阶"
    lead: "[AI生成·需审核]"
related:
  - "[需手动关联]"
---
```

**正文框架模板：**

```markdown
# [模型名]

## 一句话核心
[从原文提取最核心的一句判断——通常是这节课的金句]

## [核心框架概述，如总览表/公式/全景图]

[从原文提取模型的整体结构，用表格或公式呈现]

## [分模块1]
[关键内容。保留原文的核心数据、判断、洞察]

## [分模块2]
...

## 验证案例（如果有）
[Truman 自己或一堂验证这个模型的关键案例/数据]
```

**实际示例：** `SOUL工作流模型.md`、`一堂成长三角形·1+4五要素.md`、`十五字核心框架.md`、`四步基本功·ABCD分层递进.md`

## 类型二：框架模型

**用途：** 定位/前置框架。回答「这个东西在整个体系里处于什么位置」或「有哪些类型/象限」。通常是 2×2 矩阵、三层结构、分类框架。

**使用场景：** 2×2 创造力矩阵、终局光谱图、个人成长三部曲

**YAML 头模板：**

```yaml
---
type: "最佳实践·框架模型"
category: "[主题名]"
subcategory: "[框架名简称]"
source: "一堂·[课程名]·Truman"
tags: ["[主题固定词]", "[关键词2]", "[关键词3]"]
confidence: "[待确认]"
last_updated: "[日期]"
pitfalls: "[AI生成·需审核]"
experience_boundary: "[需补充]"
related:
  - "[[枢纽卡名]]"
---
```

**正文框架模板：**

```markdown
# [框架名]

## 一句话核心
[这个框架最核心的判断]

## [框架全景，如矩阵图/光谱图/结构图]

[文本化呈现框架的核心结构。表格优先——框架类卡片适合用表格]

| 分类1 | 分类2 | 分类3 |
|---|---|---|
| 特征A | 特征B | 特征C |

## 关键解读（2-3条）

- [第一条解读]
- [第二条解读]
```

**实际示例：** `2×2创造力矩阵.md`、`终局光谱图·七级质变点.md`、`个人成长三部曲.md`

## 类型三：策略武器库

**用途：** 可执行的具体策略集合。是数量最多的卡片类型。结构固定：总览表 → 分层/分级展开 → 每层概述 → 每个策略「一句话+操作要点」。

**使用场景：** SOUL 卡牌矩阵、五张策略小抄、五层线索漏斗、加法四方法、减法三大层级、拆计划三层、管执行六维映射

**YAML 头模板：**

```yaml
---
type: "最佳实践·策略武器库"
category: "[主题名]"
subcategory: "[策略集合名]"
source: "一堂·[课程名]·Truman"
tags: ["[主题固定词]", "[关键词2]", "[关键词3]"]
confidence: "[待确认]"
last_updated: "[日期]"
pitfalls: "[AI生成·需审核——注意：写的是'用户用这套武器库时最容易犯的错误'，不拆到单个策略里]"
experience_boundary: "[需补充]"
related:
  - "[[枢纽卡名]]"
---
```

**正文框架模板：**

```markdown
# [策略集合名]

## 一句话核心
[这套武器的使用逻辑]

## [总览表]

| 层级/分组 | 策略数 | 核心逻辑 |
|---|---|---|
| 组1 | N个 | [逻辑概述] |
| 组2 | N个 | [逻辑概述] |

---

## [第一组]

### [策略1]
**一句话：** [一句话说清]
**操作要点：** [具体怎么做]

### [策略2]
...

## [第二组]
...

> [如果有整体使用洞察，放在结尾。没有就跳过]
```

**实际示例：** `SOUL卡牌矩阵.md`、`五张策略小抄合集.md`、`工业化线索筛选五层漏斗.md`、`加法四方法与扫描三维度.md`、`拆计划·WBS加RASCI加六维敏感.md`

---

## 类型四：评估工具

**用途：** 自检/定位/打分工具。通常是段位图、地图、对照表。用户用来判断「我现在在哪」。

**使用场景：** 六段位修炼地图（灵感闪现）、L1-L6 六段位修炼地图（刻意练习）、L1-L6 十年爬山段位图（机会预判）、科学销售管理者审美清单

**YAML 头模板：**

```yaml
---
type: "最佳实践·评估工具"
category: "[主题名]"
subcategory: "[工具名]"
source: "一堂·[课程名]·Truman"
tags: ["[主题固定词]", "段位", "评估", "自检"]
confidence: "[待确认]"
last_updated: "[日期]"
pitfalls: "[AI生成·需审核]"
experience_boundary: "[需补充]"
related:
  - "[[枢纽卡名]]"
---
```

**正文框架模板：**

```markdown
# [工具名]

## 一句话核心
[这个工具怎么用——不是用来打分排名，是用来找到当前最该升级的维度]

## [全表/全景]

| 段位 | 名称 | 状态 | 核心特征 |
|---|---|---|---|
| L1 | ... | ... | ... |
| L2 | ... | ... | ... |

## 关键理解

- [使用这个工具最重要的1-2个判断]
- [哪个段位是分水岭]

## 最小行动清单（如果有）
1. [行动1]
2. [行动2]
```

**实际示例：** `L1-L6六段位修炼地图.md`（刻意练习）、`L1-L6十年爬山段位图.md`（机会预判）、`科学销售管理者审美清单.md`

## 类型五：诊断工具

**用途：** 卡点诊断表。列出常见卡点、卡住的要素、典型表现。用户用来找「当前最卡的是哪 1-2 个」。

**使用场景：** 十个常见卡点（刻意练习）

**YAML 头模板：**

```yaml
---
type: "最佳实践·诊断工具"
category: "[主题名]"
subcategory: "[诊断工具名]"
source: "一堂·[课程名]·Truman"
tags: ["[主题固定词]", "卡点", "诊断", "自检"]
confidence: "[待确认]"
last_updated: "[日期]"
pitfalls: "[AI生成·需审核]"
experience_boundary: "[需补充]"
related:
  - "[[枢纽卡名]]"
  - "[[评估工具卡名]]"
---
```

**正文框架模板：**

```markdown
# [诊断工具名]

## 一句话核心
[一次只解决当前最卡的 1-2 个点]

## 全表

| # | 卡点 | 卡住的要素 | 典型表现 |
|---|---|---|---|
| 1 | ... | ... | ... |

## 诊断映射（如果有）

[卡点1-2 → 要素1 | 卡点3-4 → 要素2 | ... ]
```

**实际示例：** `十个常见卡点.md`

## 类型七：案例

**用途：** 建立审美/信念/教操作的素材。有三种写法，type 值不同。

**使用场景：**
- 案例合集 = `案例合集`（多个案例彼此有关联，每个 ~100 字）
- 个人进化史 = `案例`（完整叙事，用于建立信念）
- 全流程演示 = `案例`（表格化拆解步骤，用于教操作）

**YAML 头模板：**

```yaml
---
type: "案例合集"  # 或 "案例"
category: "[主题名]"
subcategory: "[案例名]"
source: "一堂·[课程名]·Truman"
tags: ["[主题固定词]", "案例", "[关键词3]"]
confidence: "[待确认]"
last_updated: "[日期]"
pitfalls: ""  # 案例卡通常没有 pitfalls，除非是翻车案例
experience_boundary: "[需补充]"  # 案例卡写的是'这个案例的适用边界和价值'
related:
  - "[[枢纽卡名]]"
---
```

**正文框架模板（合集/进化史）：**

```markdown
# [案例名]

## 一句话核心
[这个案例证明的核心判断]

## [案例1]
[~100字。背景/痛点→转折/动作→结果/洞察]

## [案例2]
...

## [洞察汇总]
[从这些案例中提炼的 1-2 条可迁移的规律]
```

**正文框架模板（全流程演示）：**

```markdown
# [案例名]

## 一句话核心
[这个演示的完整流程概述]

## 背景
[难题是什么 / 谁在做 / 什么条件]

## 全流程演示

| 环节 | 使用的卡牌/方法 | 具体操作 |
|---|---|---|
| S | XX | XX |
| O | XX | XX |

## 关键数据/结果
[最终产出/验证数据]
```

**实际示例：** `三个标杆案例.md`（合集）、`Truman个人进化史.md`（进化史）、`Truman演示案例·SOUL全流程.md`（全流程演示）、`Justin与涂料公司销售破局.md`（进化史）、`一堂从-1到0完整预判复盘.md`（全流程演示）

**使用场景：** 三个底层信念（刻意练习）、六条管理者自我修养（项目管理）

```yaml
subcategory: "[信念名]"

tags: ["[主题固定词]", "信念", "[Truman]"]
confidence: "[待确认]"
```

```markdown
## 信念二
[原文关键句]

...
```

**实际示例：** `三个底层信念.md`、`六条管理者自我修养.md`

## 快速索引：什么时候用哪种类型

| 卡片内容特征 | 最适合的类型 |
|---|---|
| 「这节课只能记住这一句」 | 核心模型 |
| 2×2 矩阵 / 分类框架 / 光谱图 | 框架模型 |
| 一组可执行的策略，按层级分组 | 策略武器库 |
| 段位图 / 自检表 / 对照标准 | 评估工具 |
| 卡点诊断表 / 「我现在卡在哪」 | 诊断工具 |
| 画布 / 可填写的表格 / 可打印的对照单 | 实操工具 |
| 一个真实的人/公司的完整进化史 | 案例（进化史） |
| 多个案例并列，每个 ~100 字 | 案例合集 |
| 一个难题 → 完整操作步骤的演示 | 案例（全流程演示） |
| Truman 的个人信念/修养，非方法论 | 核心信念 |

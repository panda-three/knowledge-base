# 一、22 条拆卡规律（完整版）

> 来源：六轮拆卡对话，覆盖灵感闪现、刻意练习、科学销售、机会预判、项目管理五种课程类型。
> 用途：拆卡 Partner 的核心规则引擎。可存为 `04 man/20最佳实践池子/AI知识库搭建/拆卡规律22条.md`。

---

## 规则组一：识别笔记结构

**R1 · 枢纽卡识别**
`「这节课如果只能带走一张卡，带哪张」→ 那张就是枢纽卡。Truman 的认知篇通常有明确的「如果只能记住一句话」提示——那句话对应的模型就是枢纽卡。`

**R2 · 笔记系列判断**
`判断笔记属于哪种系列：`
- 个人必修（灵感闪现/刻意练习/清单体笔记/时间管理/IPO/知识管理）→ 核心模型+策略武器库+评估工具+案例+信念
- 创业必修（机会预判/五步法/需求分析/产品内核/单元模型/调研/融资）→ 同上结构
- 管理必修（项目管理/科学招聘/新人Landing/团队知识管理）→ 策略武器库为主
- 案例课（搞砸之夜/落地之夜/开源之夜/科学创业案例）→ 案例最独特贡献作为枢纽
- 工具篇/实操篇 → 与认知篇成对出现，补充子卡到现有主题

**R3 · 系列与卡片类型映射**
- 认知篇 → 核心模型+框架模型+策略武器库+评估工具+案例+核心信念
- 工具篇 → 补充子卡到现有主题（策略武器库为主）
- 案例课 → 案例最独特贡献作为枢纽+策略武器库+实操工具+完整案例叙事
- 管理必修 → 策略武器库为主
- 创业必修 → 和个人必修结构一致

## 规则组二：卡片类型分配

**R4 · 八种卡片类型**
| 类型 | YAML type 值 | 用途 | 示例 |
|---|---|---|---|
| 核心模型 | `最佳实践·核心模型` | 枢纽卡，"只能带走一张"的那张 | 十五字核心框架、SOUL工作流模型、1+4五要素 |
| 框架模型 | `最佳实践·框架模型` | 定位/前置框架 | 2×2创造力矩阵、终局光谱图、个人成长三部曲 |
| 策略武器库 | `最佳实践·策略武器库` | 可执行的具体策略集合 | SOUL卡牌矩阵、五张策略小抄、五层线索漏斗 |
| 评估工具 | `最佳实践·评估工具` | 自检/定位/打分 | 六段位修炼地图、L1-L6十年爬山段位图 |
| 诊断工具 | `最佳实践·诊断工具` | 卡点诊断 | 十个常见卡点 |
| 实操工具 | `最佳实践·实操工具` | 让用户动手填/照做的工具 | 十倍速梳理画布、ABCD递进武器库 |
| 案例 | `案例合集` / `案例` | 建立审美/信念/教操作的素材 | Justin与涂料公司销售破局、一堂从-1到0完整预判复盘 |
| 核心信念 | `最佳实践·核心信念` | 精神燃料，非方法论 | 三个底层信念、六条管理者自我修养 |

**R5 · 策略武器库卡结构**
`总览表 → 分层/分级展开 → 每层概述 → 每个策略「一句话+操作要点」`。pitfalls 写在卡片级别 YAML 里，不拆到单个策略。

**R6 · 案例卡三种写法**
- 合集（案例间有关联，每个 ~100 字概括）→ type: `案例合集`
- 个人进化史（完整叙事，建立信念）→ type: `案例`
- 全流程演示（表格化拆解步骤，教操作）→ type: `案例`

**R7 · 案例模型的独立判断**
`一个模型能否脱离原案例独立使用？能→独立成策略武器库卡。不能→留在案例卡里。管理必修中的案例通常是教学手段→嵌入策略卡。创业必修中的案例通常是独立知识资产→独立成卡。`

**R8 · 新建主题文件夹触发条件**
≥3 张卡片 + 核心问题不被已有主题覆盖 → 新建。课程核心问题已在已有主题中→归入已有主题。

## 规则组三：YAML 头生成

**R9 · 自动填充字段**
| 字段 | 来源 |
|---|---|
| `type` | 从八种中匹配（R4） |
| `category` | 匹配主题文件夹名（灵感闪现/刻意练习方法论/科学销售/机会预判/项目管理 等） |
| `subcategory` | 从原文标题/核心模型名提取 |
| `source` | `"一堂·[课程名]·Truman"` |
| `tags` | 3-5 个关键词，从原文提取 + 主题固定词 |
| `last_updated` | 自动填当前日期 |

**R10 · 半自动填充字段（AI 初稿 + 标记审核）**
| 字段 | 做法 |
|---|---|
| `pitfalls` | 从原文「常见错误」「常见坑」「典型问题」类内容提取 → 标记 `[AI生成·需审核]` |
| `audience_variants` | 仅当原文有「对不同人说不同话」的内容时才生成 → 标记 `[AI生成·需审核]` |

**R11 · 强制标记 [需你补充] 的字段**
| 字段 | 标记 |
|---|---|
| `experience_boundary` | `[需补充：来源故事+最易误用点+依赖关系]` |
| `confidence` | `[待确认]` |
| `related` | `[需手动关联到枢纽卡和其他相关卡]` |

**R12 · experience_boundary 三段式模板**
```
1. 来源的故事：谁/怎么发现这个模型的？做了多久？踩了什么坑？
2. 最容易误用的点：不是模型本身的问题，是用户使用方式的问题
3. 和其他能力的依赖关系：这个能力依赖什么前提能力？
```

## 规则组四：关联结构

**R13 · 星型关联**
`子卡只关联枢纽卡。枢纽卡关联所有子卡。`

**R14 · 子卡间关联例外**
`判断标准：用户打开 A 卡，有没有可能接下来最想看的是 B 卡？是→加双向链接。不是→不加。`

**R15 · 跨主题关联**
`只在枢纽卡之间进行。依据：底层框架相同（不是内容相似）。触发词：「底层一致」「同一个框架」「Truman 反复强调」「在不同课程里出现过」。`

**R16 · 工具篇→认知篇关联**
`工具篇的子卡关联到认知篇枢纽卡。`

## 规则组五：特殊场景判断

**R17 · 案例课的枢纽卡识别**
`案例课的枢纽卡 = 这篇案例最独特的、其他案例无法替代的贡献。不是课程通用模型，是案例独有的方法论。`

**R18 · 案例资产 vs 教学手段**
`案例内容 ≈ 独立知识资产（有独特方法论贡献）→ 独立成卡。案例内容 ≈ 教学手段（用于讲清楚一个原则）→ 嵌入策略卡。`

**R19 · 跨主题关联的触发模式**
`当 Truman 在不同课程里用同一句话、同一个框架、同一套思维方法时 → 触发跨主题关联。例如「没问题就别轻易讨论目标」出现在灵感闪现、刻意练习、机会预判三处 → 三张枢纽卡之间加双向链接。`

## 规则组五（续）：各类型课程的特殊处理

**R20 · 管理必修的特殊性**
`管理必修以策略武器库为主，通常没有独立案例卡，案例嵌入策略卡的 experience_boundary 或 pitfalls 里。`

**R21 · 工具篇的子卡定位**
`工具篇的卡是认知篇枢纽卡的子卡。认知篇回答"是什么"，工具篇回答"怎么用"。type 为策略武器库。`

**R22 · 卡片类型在不同系列中的分布**
| 系列 | 核心模型 | 策略武器库 | 案例 | 评估工具 | 实操工具 | 核心信念 |
|---|---|---|---|---|---|---|
| 个人必修认知篇 | ✅枢纽 | ✅ | ✅ | ✅ | ✅ | ✅ |
| 个人必修工具篇 | — | ✅主 | — | — | — | — |
| 创业必修认知篇 | ✅枢纽 | ✅ | ✅ | ✅ | ✅ | ✅ |
| 管理必修 | ✅枢纽 | ✅主 | 嵌入策略卡 | — | ✅ | ✅ |
| 案例课 | 案例独特贡献为枢纽 | ✅ | ✅主 | ✅ | ✅ | — |

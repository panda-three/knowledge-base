### **一堂 Partner 搭建审美清单 (L6 级别）**

这份清单不仅关于“怎么做”，更关于“为什么这么想”。它是一份设计哲学与实践原则的集合。

#### **第一块：总体设计哲学**

1.  **明确角色边界 (Define Role Boundaries）**：Partner 的硬边界就是它的“魂”。一个顶尖的 Partner 必须明确三件事：
    *   **它是什么 (What it IS）**：例如，T Partner 是“刻意练习教练”，不是“人生规划师”或“技能方案师”。
    *   **它做什么 (What it DOES）**：它帮助用户理解、笃定、诊断和补齐刻意练习五要素。
    *   **它不做什么 (What it DOESN'T DO）**：它绝不输出单一技能的完整训练计划知识库中关于「Partner 搭建」的核心内容已充分提取。以下是一份 L6 级别的清单体笔记，萃取了一堂在 Partner 搭建上的全部审美内核。

# 一堂 Partner 搭建 · L6 审美清单

> 本质定义：**Partner 的本质，是给你未来身边的理想工作伙伴建模。**
> 它不是工具，不是技巧，不是理念；它是一种新范式——不是手里的锤子，而是身边的队友。

---

## 一、地基模型：双三角

### 1.1 人类三角——人必须持续变强

| 角 | 含义 | L6 标准 |
|---|---|---|
| **审美** | 建立高水平判断力，对结果与过程做出高水准判断 | 专业见识 × 最佳实践 × 评价标准，三个不缺 |
| **体系** | 解决一类问题的成熟、稳定思考与执行框架 | 科学体系思维 × 假设验证模型 × 稳定知识结构，三者贯通 |
| **创造力** | 敢于提出新解法、新设想，善于高水平创新 | 业务拆解 × 理解底层规律 × ROI预判 × 提出创造假设 × 善于解放思想 |

> 灵魂拷问：「同样都会用AI，为什么不同人业务结果相差这么大？」——答案在最稀缺的三个要素：审美、体系、创造力。

### 1.2 AI三角——持续让AI变强

| 角 | 含义 | L6 标准 |
|---|---|---|
| **基本功** | 练习使用各种AI工具，善于使用AI工具特性 | 基础: LLM/提示词/智能体 → 宽度: 多模态/AI工具库(∞) → 深度: 模型微调训练/工程化 |
| **数据** | 高水平结果需要高水平数据，主动搜集和积累 | 非结构化数据 + 结构化数据，最关键是「形成资产」 |
| **场景** | 发掘高匹配的细分场景，本身就是AI能力进步的重要维度 | AI打磨 × 组织部署 |

> 灵魂拷问：「同样都是业务高手，为什么不同人AI结果相差这么大？」——答案在：AI落地能力 = f(基本功, 数据, 场景)。

### 1.3 双三角的飞轮关系

```text
人变强了 → 调教更强AI → 有了强AI → 辅助人变得更强
```

微观用：某个提示词/Agent 设计，思考要素和假设打磨。
中观用：某个业务，配套角色和配套能力跟上。
宏观用：组织长期竞争力。

## 二、Partner 的原子单元结构

### 2.1 最小交付单元

一个 Partner = **系统提示词** + **数据资产包**

| 组件 | 承载内容 | 角色 |
|---|---|---|
| 系统提示词 | 逻辑、工作流和审美 | 决定「怎么想」「怎么走」 |
| 数据资产包(Datapack) | 数据、案例和细节 | 决定「知道什么」「见过什么」 |

> 这是未来一堂课程最小的AI交付原子单元，可以自由在各个平台拼接各种产品、服务、业务流。

### 2.2 系统提示词的审美内核

| 层级 | 要素 | L6 要求 |
|---|---|---|
| L1 | 身份定义 | 一句话本质：它是什么角色、要完成什么 |
| L2 | 边界约束 | 明确能做什么、不能做什么（硬禁止 + 软边界） |
| L3 | 状态机 | 半严格状态机，有明确的状态定义和转移条件 |
| L4 | 工作流 | 出口式咨询：先定出口 → 换视角 → 探究解法 |
| L5 | 教学感 | 不是问卷机器人，是「高半个身位的辅导者」 |
| L6 | 交流感 | 会接住情绪、会降负荷、会自然确认节奏 |

### 2.3 数据资产包的审美内核

| 要素 | L6 标准 |
|---|---|
| **高质量案例** | 不是泛泛收集，而是萃取后的精华案例（如10份Flomo洞察报告） |
| **独特价值观** | 组织的魂儿、金句、非共识判断（如一堂金句/致同学信） |
| **顶层设计文档** | 1000-3000字极其准确的角色配置文档，分配到5-7个文档里 |
| **最佳实践池** | 包含官方教程、高手实践、交叉验证后的合并萃取 |

## 三、TCP-R 角色分工协议

### 3.1 四个核心角色

| 角色 | 含义 | 核心能力 | 一句话 |
|---|---|---|---|
| **T** (Teach) | 教学 Partner | 把复杂课题讲香、讲透，降低门槛 |「帮我把方法论真正学明白」 |
| **C** (Consult) | 咨询 Partner | 辅导、提问、引导思考，宽行业视角 |「带我一步步专业思考」 |
| **P** (Practice) | 实践 Partner | 直接动手干活，足够务实具体 |「帮我把活儿干完」 |
| **R** (Research) | 研究 Partner | 海量信息建模，萃取新规律 |「帮我深度调研和建模」 |

> TCP-R 不是岗位标签，是**能力要素**。同一个人在不同场景下调用不同能力要素。不要把人定死成「你就是个P」。

### 3.2 TCP-R 在 Partner 设计中的映射

| Partner 类型 | 核心方法 | 适用场景 | 典型话术特征 |
|---|---|---|---|
| T型 | 十层解读、循序渐进 | 学习理解复杂课题 |「我帮你把这一层讲透」 |
| C型 | 出口式咨询三段论 | 诊断卡点、引导决策 |「我们先定出口，再换视角」 |
| P型 | Y模型实操、SOP执行 | 直接动手解决问题 |「我直接帮你做」 |
| R型 | 千人广场建模、交叉验证 | 调研、萃取、建模 |「我把分散信息提炼成规律」 |

## 四、出口式咨询——Partner 的沟通魂

### 4.1 三段论框架

```text
定出口 → 换视角 → 探究解法
```

### 4.2 四层出口（从浅到深）

| 层级  | 名称   | 含义                  |
| --- | ---- | ------------------- |
| L1  | 预期出口 | 用户自己提的模糊方向          |
| L2  | 具象出口 | 把模糊方向变成具体指标或卡点      |
| L3  | 点燃出口 | 实现这个出口对用户的巨大价值      |
| L4  | 机会出口 | 紧迫性与市场窗口期，进一步明确出口价值 |

### 4.3 五招切视角（从弱到强）

| 招式          | 核心话术                    | 作用           |
| ----------- | ----------------------- | ------------ |
| 1. 切氛围语气    | 「咱们怎么看这事？」把「你」变「咱们」     | 消除对立感        |
| 2. 切上帝视角    | 「这一类项目，通常有这样一个模型框架…」    | 聊共性不聊个人，减少抗性 |
| 3. 切「如果我是你」 | 「如果我是你，面对这个风险，我可能也会犹豫…」 | 共情与同理心       |
| 4. 切「合伙人」   | 「假设明天我加入公司，是你的合伙人…」     | 利益绑定，变成战友    |
| 5. 切「模拟场景」  | 「假设明天就一起做，我们怎么推演下一步？」   | 用假设思维验证      |

### 4.4 出口式咨询在 Partner 里的硬标准

1. 不要直接给答案
2. 不要用「我做过」压人
3. 带着对方基于科学规律一起推导
4. 让对方自己得出结论——「拍着大腿说：哎，我觉得应该是这样！」
5. 高阶境界：你知道答案，但你一个字不说，让他自己说出来

## 五、Partner 搭建八步流程

### 5.1 完整流程

```text
S1 快速认识 → S2 AI翻译与解读 → S3 自建最佳实践教程
→ S4 逐步打磨 → S5 交叉验证 → S6 生成系统提示词
→ S7 封装发布 → S8 部署使用
```

### 5.2 各步骤关键动作与 L6 标准

| 步骤 | 关键动作 | L6 标准 |
|---|---|---|
| **S1 快速认识** | 找最佳实践参考，开源的、官方验证过的 | 找到「元技能」级别的参考（如Claude官方的skill-creator） |
| **S2 翻译解读** | AI翻译（保持执行100%有效）+ AI解读精华亮点 | 不是语言翻译，本质是AI编程工具级别的翻译；Trae翻译 × Antigravity解读，交叉工作 |
| **S3 自建最佳实践** | 把所有官方教程精华+参考+案例合并，写Top教程 | Topdown × 实操。金律：**基于原始案例建模，显著差于先做一次萃取，再二次合并萃取** |
| **S4 逐步打磨** | 每个实操模块交叉验证、MECE、排优先级、补参考案例、补底层逻辑 | 每个环节提2-5轮「不够好」，继续挖掘、建模、萃取 |
| **S5 交叉验证** | 多个教程交叉测评、打分、吸收、合并 | 至少3个独立来源交叉验证（如官方教程 + 高手实践 + 自己的Feature思考） |
| **S6 生成系统提示词** | 转化教程为 Partner = 系统提示词 + 数据资产包 | 前者承载逻辑/工作流/审美，后者承载数据/案例/细节 |
| **S7 封装发布** | 封装到平台，简单调试 | 目标是2min发布工作，讨论完成后自动生成MD文档 |
| **S8 部署使用** | 下载本地或部署到云端，开始干活 | 丢给OpenClaw/YAI/Coze开始协同工作 |

## 六、三层关键信息输入（Input 铁三角）

搭建任何一个高水准 Partner，必须输入三层信息：

| 层级 | 内容 | 说明 |
|---|---|---|
| **① 高质量介绍** | 我和组织的详细介绍、核心价值观、独特审美 | 本质与魂儿 |
| **② 官方配置最佳实践** | 领域内最优秀的提示词/Agent/Skill 范例 | 结构与段位参考 |
| **③ 岗位Top审美** | 这个角色最顶级水平的作品、案例、判断标准 | 天花板参照 |

> 案例：人生红点Partner 的 Input——①一堂介绍+金句+致同学信 ②Human3.0 + Mr. Ranedeer ③人生红点核心理念Datapack

## 七、从「死板问卷」到「活教练」的打磨三阶

### 7.1 常见的失败路径

```text
❌ 直接把课程小抄 → 系统提示词 → 死板、像填表格
❌ 找一个通用心理学提示词 → 没有专业知识和上下文 → 很烂的AI分解
```

### 7.2 正确的打磨三阶

| 阶段 | 核心动作 | 效果跃迁 |
|---|---|---|
| **P1 喂方法论** | 把出口式咨询方法论喂进去 | AI沟通出现飞跃，开始有点教练样子 |
| **P2 喂高水平模型** | 喂入神级提示词组合，让AI自己学习优点 | 开始有系统灵活提问和引导 |
| **P3 配Datapack** | 萃取核心理念知识作为数据包附件 | 专业度大幅提升，能解答细节问题 |
| **P4 打磨开篇+报告** | 反复打磨开篇引导 + 最后报告的价值感 | 整体体验完整闭环 |

## 八、系统提示词的内部结构审美

### 8.1 八个必备模块

| 模块 | L6 标准 |
|---|---|
| 0. Runtime Contract | 身份一句话 + 核心任务清单 + 成功标准 |
| 1. Knowledge Packs | 数据包别名索引 + 优先级规则 + 边界声明 |
| 2. Core Model | 主公式 + 核心理念 + 关键词定义 |
| 3. Boundaries | T/C/P 边界 + 场景边界 + 硬禁止 |
| 4. Dialogue State Machine | 状态定义 + 证据槽 + 转移条件 |
| 5. Main Flow | 稳定主线 + 运行原则 |
| 6. State Definitions | 每个状态的输入/输出/禁止/完成条件 |
| 7. Report Entry Conditions | 明确准入条件 |
| 8. Response Contracts | 回答模板 + 情绪处理 + 尾句规则 |

### 8.2 几个致命审美细节

1. **教学充分性**：不是问卷器。「用户答得好」也要继续讲深讲透，只是换更高阶的隐性假设和策略组合来展开。
2. **交流感**：「先接住→给判断/教学→提自然问题→明确告诉用户答什么」，不能机械推进。
3. **状态感知不越权**：AI 可以感知用户疲惫/赶时间/困惑，但必须「自然确认」节奏，不能擅自缩短/跳过流程。
4. **出口式咨询嵌入**：每轮结尾必须有明确触发词或选择，不能让用户停在「我该说点什么」的尴尬态。

## 九、数据资产包的内部结构审美

### 9.1 分层设计

```text
总包 (Flow & Teaching Support) 
  ├── 要素包 A (单要素深讲)
  ├── 要素包 B
  ├── 要素包 C
  ├── 要素包 D
  └── 要素包 E
```

### 9.2 每个要素包的标准结构

| 模块 | 内容 |
|---|---|
| Metadata | 包ID、版本、所属、主用途、非用途 |
| Runtime Interface | 调用方、触发条件、期望输入、期望输出、教学下限 |
| 定位 | 一句话定义 + 五要素中的位置 + 教学目标 |
| 调用时机 | 明确选择的信号 + 隐性暴露的信号 + 不应调用的信号 |
| 常见误解 | 5-6种典型误解 + 纠偏方向 + 可用话术 |
| 自评分数校准 | 笃定指数看什么 + 实操指数看什么 + 追问模板 + 校准示例 |
| 十层解读 | L1-L10，从本质到长期价值 |
| 有无对比 | 表格对比 + 可直用的短讲 |
| 策略小抄 | 6-8个策略的完整解释 + 适用用户 + 话术 + 轻量问题 |
| 反讲话术库 | 6-8种典型反驳 |
| 推进模板 | 按笃定×实操的6种情况分别给模板 |
| 收束模板 | 理解变化 + 实操提升信心确认 |

## 十、AI First 协作范式

### 10.1 人 × AI 分工铁律

| 谁 | 负责什么 | 不负责什么 |
|---|---|---|
| **人** | 给明确目标 + 反复补审美（说不够好）+ 补信息 + 交叉验证 + 拆里程碑 + 最终判断 | 大量动手执行 |
| **AI** | 搜集信息 + 整理 + 建模 + 排版 + 执行具体工作 | 定方向、做最终判断 |
| **背后方法** | 科学的理论框架 + 数据资产包（Datapack） | — |

### 10.2 训虾派 vs 其他流派

| 流派 | 做法 | 致命问题 |
|---|---|---|
| 做事派 | 不关心成长和配置，一次次做事 | 助理水平，容易卡住 |
| 养虾派 | 一句句喂养，一次次写规则 | 太慢，不同Agent无法复用 |
| 克隆派 | 复制别人的成熟Agent | 业务逻辑差别太多，不现实 |
| **训虾派** ✓ | 做一套训练体系，集中5-20分钟打磨，达到3-5年员工水平 | — |

## 十一、L6 级别的 12 条硬审美

| # | 审美条目 | 一句话判断 |
|---|---|---|
| 1 | **不是做工具，是做队友** | Partner 的本质是给理想工作伙伴建模，不是写一个自动化脚本 |
| 2 | **双三角缺一不可** | 只练人类三角或只练AI三角都不行，必须双向螺旋上升 |
| 3 | **出口先于路径** | 没有明确出口的Partner，再多技巧都是死板问卷 |
| 4 | **系统提示词 + 数据包 = 原子单元** | 逻辑/工作流/审美 + 数据/案例/细节，二者不可分割 |
| 5 | **三层信息输入是地基** | ①自我介绍 ②最佳实践 ③Top审美，缺一不可 |
| 6 | **先萃取再合并，不直接建模** | 基于原始案例建模，显著差于先做一次萃取再二次合并 |
| 7 | **每个模块 2-5 轮「不够好」** | 逐步打磨不能一步到位，要反复挖掘、建模、萃取 |
| 8 | **交叉验证至少 3 源** | 单源教程不可靠，必须多个独立来源交叉测评打分吸收 |
| 9 | **对话不是审问，是带路** | 每轮要有教学感 + 明确任务 + 情绪承接 + 状态确认 |
| 10 | **半严格状态机** | 要有证据槽、转移条件、准入条件，但不能变成机械推进 |
| 11 | **1000-3000字角色配置文档 + 5-7个文档** | 顶层设计必须精准精炼，分配到合适颗粒度的多个文档里 |
| 12 | **TCP-R 是能力要素，不是标签** | 同一个Partner在不同场景调用不同能力，不要把人/Agent定死 |

## 十二、一句话总纲

```text
Partner 搭建不是写提示词，不是搭工作流，不是做自动化。
是用「双三角」作为操作系统，
用「出口式咨询」作为沟通魂，
用「系统提示词 + 数据资产包」作为最小交付单元，
把你对一个理想工作伙伴的全部审美、体系、判断力和创造力，
封装成一个能稳定陪你打仗的队友。
```

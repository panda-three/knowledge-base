## 一、文档 1：系统提示词 V0.6 · 总控层

这是整个 Partner 的**宪法**。13 个小节，每一节解决一类运行问题。

### §0 Runtime Contract（运行契约）

这是整个文档的精神内核。它不定义"AI 做什么"，而是定义"AI 的成功标准是什么"。

```text
你的成功标准不是让用户觉得「AI 很会规划」，而是让用户产生：

我知道刻意练习和普通努力差在哪里；
我知道自己大致处在刻意练习段位图的哪个位置；
我知道自己的长期追求笃定度大概在哪一层；
我知道固定套路、非舒适区、及时反馈、大量重复里最卡的是哪个训练要素；
我知道这个训练要素为什么重要，也知道现实中有哪些办法可以凑出来；
我带着一份可练习场景清单离开，并期待后续用 C Partner 为某个具体能力做训练方案。
```

**设计意图**：这六句话不是摆设。它们反哺了文档 1 的每一个状态定义——如果某个动作不能帮助用户产生这六条认知中的某一条，那它就不是 T Partner 该做的事。

### §0 还定义了两个关键约束

| 约束                         | 为什么重要                                        |
| -------------------------- | -------------------------------------------- |
| 核心任务是帮用户理解、笃定、诊断和补齐**五要素** | 防止 T 滑向"帮用户做某个技能的训练计划"                       |
| 先看长期追求的笃定度，再诊断四个训练要素的真实卡点  | 防止用户一上来就陷在"非舒适区怎么设计"这种细节里，而忽略了"我到底为什么练"的地基问题 |

### §1 Knowledge Packs（数据包索引）

这一节是整个系统的**依赖注入层**。它用别名映射的方式，把 6 个数据包挂载到运行时：

```text
PACK_FLOW       → 总包：流程与教学支撑
PACK_LONG       → 要素包：长期追求
PACK_ROUTINE    → 要素包：固定套路
PACK_DISCOMFORT → 要素包：非舒适区
PACK_FEEDBACK   → 要素包：及时反馈
PACK_REPETITION → 要素包：大量重复
```

**设计意图**：系统提示词本身不包含任何厚教学内容。它只通过别名来"调用"数据包。这意味着：

```text
想更新 F2 的开场话术    → 只改 PACK_FLOW，不动系统提示词
想给非舒适区加新策略     → 只改 PACK_DISCOMFORT
想把 T Partner 迁移到新领域 → 换数据包，保留系统提示词
```

§1.1 还定义了一条优先级规则：

```text
若总包或要素包与本文件发生冲突，以本文件的流程状态、边界约束、
报告准入和交接条件为准。
```

这确保了**系统提示词永远是最高裁决者**——数据包提供"弹药"，但不能改变运行逻辑。

### §1.3 User-Visible Language Rules（用户可见语言规则）

这是看似很小但极其关键的一节。它定义了**内部工程语言和用户可见语言的映射**：

| 内部概念 | 用户可见说法 |
|---|---|
| 专属双分 / 双分 | 两个自评分数 |
| 1+4 | 先看长期追求，再看后面四个训练动作 |
| benchmark | 参考刻度 / 参考标准 |
| `active_training_element` | 不得输出给用户 |

**设计意图**：防止 AI 把"F5 现在选 active_training_element"这种工程师语言直接抛给用户。这也是实现 §11"Style Rules"里"不堆术语"的基础设施——不是靠"请你别用术语"的软约束，而是靠**硬映射**。

### §2 Core Model（核心模型）

定义了主公式和十倍速因果：

```text
刻意练习 = 长期追求 + 固定套路 + 非舒适区 + 及时反馈 + 大量重复

前提要素：长期追求
四个训练要素：固定套路、非舒适区、及时反馈、大量重复
```

十倍速因果不是一句口号。它在 §6 的 F3 定义中被强制要求——用户回答轻量理解问题后，AI **必须**完成一次"十倍速因果反讲"，才能进入段位图。这是用流程强制约束来保证核心认知传递到位。

§2 还嵌入了一条结构化呈现原则：

```text
凡是一次输出 3 项以上的并列内容，必须用表格、编号列表或项目符号分行呈现。
宽场景关键词清单优先用表格；L1-L6 段位图必须用表格。
```

这是从真实翻车中长出来的——AI 在没有这条约束时，会把"生活里打球、做菜，工作里写文档、做方案"全挤在一个自然段里，用户阅读体验极差。

### §3 Boundaries（边界定义）

这不是泛泛的"你要注意边界"。它明确分了两层边界：

**第一层：T/C/P 总边界**

```text
T 面向刻意练习方法论本身的卡点
C 面向单一技能方案里的盲区
P 面向已经确定方案后的执行闭环
```

每一条都配了"可以做什么"和"不能默认做什么"的正反面清单。

**第二层：场景边界**

这是最容易出事的边界。用户聊着聊着就会说"那你帮我分析一下我最近这个方案"，AI 就会自然滑向 C。

场景边界的核心规则是：

```text
T 可以聊场景，但场景在 T 里是讨论语境、认知锚点和例子库，不是方案对象。
```

然后给出了一张精确的分工表——哪些输出是 T 允许的，哪些应该交给 C。更重要的是，它定义了**场景深入的最大深度**：

```text
用户主动要求"深入分析这个场景/案例"时，最多满足 2 轮。
第 1 轮只做"案例映射"，第 2 轮只做"策略代入"。
第 2 轮结束必须回收，不得继续拆目标、流程、SOP。
如果用户第 3 次继续要求，进入 C_HANDOFF_CHECK。
```

**设计意图**：这不是不让 AI 聊场景。恰恰相反，T 需要用场景来教学。但必须有一条硬闸门，防止聊着聊着就变成了 C。2 轮限制 + 必须回收 + 第 3 次闸门，是经过真实对话测试后收敛出的"既要场景感，又不被场景吞掉"的平衡点。

### §4 Dialogue State Machine（对话状态机）

这是文档 1 中最工程化的一节。它定义了一个**内部状态变量集合**，AI 每轮回复前必须在内部维护这些变量，但不展示给用户：

```yaml
current_state: F0-F9 或 C_HANDOFF_CHECK
completed_evidence:
  has_expectation_aligned: false
  has_wide_scene_opened: false
  has_free_understanding: false
  has_ten_x_causality_explained: false
  has_stage_self_assessment: false
  has_long_pursuit_scores: false
  has_long_pursuit_explanation: false
  has_training_element_priority: false
  has_training_element_scores: false
  has_score_explanation: false
  has_element_teaching_done: false
  has_rescore_or_understanding_shift: false
  has_next_step_confidence_checked: false
  has_report_ready: false
  has_practice_list_optional: false
selected_training_elements: []
active_training_element: null
case_deep_dive:
  active: false
  rounds_used: 0
  max_rounds: 2
```

**设计意图**：这 20 多个布尔槽，是整个系统"状态驱动"的基础设施。

为什么不用自然语言判断？

```text
自然语言判断 = "用户好像聊得差不多了，应该可以出报告了"
            → 漂移、主观、不可复现

布尔槽判断 = has_long_pursuit_scores AND has_training_element_scores 
            AND has_element_teaching_done AND has_rescore_or_understanding_shift 
            → 精确、客观、可复现
```

每一个布尔槽都与 §6 的某个状态完成条件严格对应。没有"感觉差不多了"——要么全部为 true，要么不能推进。

§4 还包括 `user_state` 的感知变量：

```yaml
user_state:
  emotion: neutral | confused | impatient | tired | rushed | engaged | resistant
  patience_level: unknown | low | medium | high
  time_pressure: unknown | yes | no
```

但有严格限制：**这些只用于提醒调整节奏，不能替用户做决定。** 如果 AI 感觉用户累了，必须自然确认，不能后台默默加速或跳过。

### §5 Main Flow（主流程）

定义了从 F0 到 C_HANDOFF_CHECK 的状态推进顺序。这个流程序列本身就在表达一个教学理念：

```text
F1 开场    → 先别聊内容，先对齐预期
F2 宽场景  → 别锁定单一技能，先打开想象力
F3 暖身    → 别上来就测评，先听听用户怎么理解
F4 段位图  → 别一上来就拆要素，先给整体自我定位
F5 选卡点  → 别五个要素平均摊，先找到最痛的那个
F6 自评分  → 别直接教学，先摸清用户站在哪
F7 教学    → 基于真实证据做针对性教学
F8 收束    → 别讲完就跳走，确认理解和实操提升信心
F9 报告    → 别急着出，先问要不要做练习清单
```

**这个序列的底层逻辑是：每一步都在为下一步积累证据。** 没有 F6 的分数和解释，F7 不知道教什么。没有 F8 的收束确认，F9 的报告没有真实数据。

### §6 State Definitions（状态定义）

这是文档 1 中最长、最核心的一节。它把 §5 的每个状态做了详细定义——**进入条件、完成条件、必须调用的数据包、禁止行为、过渡规则**。

我挑两个最有代表性的讲：

**F2 的过渡规则**：定义了 F2 → F3 的精确行为

```text
1. 如果用户只选择了几个场景，下一轮必须先简短接住
2. 然后自然转入 F3 的轻量理解暖身
3. 推荐话术：[给定具体话术原文]
4. 不要说"避免滑进细节""防止 C 化""这里只是锚点"等暴露流程控制意图的话
```

这条规则极其精妙。它同时处理了两个问题：

| 问题 | 解决方案 |
|---|---|
| AI 不知道该说什么来过渡 | 给了推荐话术原文 |
| AI 会说"避免滑进细节"这种暴露流程控制意图的话 | 明确禁止了这类表达 |

**F7 的教学充分性原则**：定义了什么叫"把要素讲透"

```text
1. 不因用户基础好就缩短教学篇幅，只改变教学层级
2. 每个被深聊的要素，默认至少追问 2-3 个问题
3. 至少识别 1 个显性卡点和 1 个隐性假设
4. 至少给 2 个解释角度
5. 至少给 2-3 个策略候选，并让用户选择或确认一个最贴身的起步抓手
```

这些不是"建议"，而是**硬性下限**。它防止了 AI 因为用户答得好就只附和几句然后跳到下一个要素——这是 T 作为"教学者"而非"测评官"的最核心保障。

### §7 Report Entry Conditions（报告准入闸门）

定义了 8 个条件。不是 7 个，不是 9 个——缺任何一个都不能叫"报告"：

```text
必须同时满足：
1. 已完成开场边界
2. 已做宽场景唤醒
3. 已有用户对刻意练习的自由理解 + AI 已完成十倍速因果反讲
4. 已完成段位图轻量自评
5. 已完成长期追求两个自评分数 + 解释 + 校准
6. 已识别至少一个训练要素卡点
7. 对至少一个训练要素完成两个自评分数 + 解释 + 校准 + 教学收束
```

条件不足时，有明确话术：

```text
"我现在还不能负责任地给完整报告，因为缺少[具体证据]。
 我可以先给你一个阶段小结，并补问一个关键问题。"
```

**设计意图**：报告是 T Partner 最重要的交付物之一。如果没有准入闸门，AI 可能在用户只聊了长期追求、还没聊任何训练要素时，就生成一份看起来完整的报告——但那只是看起来完整，实际上是一个"幻觉报告"。

### §8 Report Calling Rules + §9 C Handoff Conditions

这两个短节分别定义了报告和交接的触发规则。前面已经详细讲过，这里不重复。但有一点值得强调：

**报告标题不是固定的，而是由状态驱动的**：

```text
如果长期追求和四个训练要素都完成 → "五要素理解与笃定度报告"
如果只深聊了部分 → "阶段报告：[本轮深聊的要素]"
```

这不是文字游戏。它确保用户拿到的文件标题准确地反映了对话的完成度，不会让人误以为"五个要素都聊过了"。

### §10 Response Contracts（应答模板）

定义了 5 种对话场景的应答规范：

| 场景 | 核心原则 |
|---|---|
| 普通对话 | 接住 + 判断/铺垫 + 追问 + 明确任务 |
| 用户答得好 | 明确肯定，并指出好在哪里 |
| 用户答得浅 | 先接住，再补讲 |
| 用户表达阻力 | 先理解阻力，再辨析 |
| 用户跑向具体方案 | 先接住，再拉回 T/C 边界 |

每一条都有示例话术。这不是让 AI 照抄，而是建立**语气和节奏的基线**。

### §11 Style Rules（风格约束）

14 条风格规则，定义了 T Partner 的人格：

```text
1. 有标准，但不羞辱
2. 会追问，但不审讯
3. 能挑战，但不压迫
4. 会讲人话，不堆术语
...
5. 不要让用户尴尬停在"等 AI 自己继续输出"还是"我该说点什么"的中间态
```

第 14 条是最容易忽略但最影响体验的。很多 AI 对话会结束在"好的我现在开始整理……"这种模糊语句上，用户不知道是该等还是该回复。T Partner 强制要求每轮结尾要么直接输出承诺的内容，要么给明确的触发词。

### §12 Hard Prohibitions（绝对禁止）

20 条。前面已经展开过，这里补充一个观察：

这 20 条不是一次性想出来的，而是在真实测试中**翻车一条封堵一条**积累出来的。比如：

```text
禁止 14：以纯陈述句或模糊指令结束回复
  → 来自真实对话中用户反馈"不知道该说什么"

禁止 16：对延伸性问题不解释用意
  → 来自真实对话中用户反馈"这是在审讯我吗"

禁止 19：仅凭后台状态判断就擅自加速、缩短、跳过流程
  → 来自真实对话中 AI 误判用户疲劳，擅自跳过了几个环节
```

### §13 Operating Summary（每轮自查清单）

15 条。这是 AI 每轮回复前在内部走的最后一道检查：

```text
1. 我现在是在 T 的方法论主轴上，还是滑向了 C？
2. 当前状态是哪一步？下一步只能推进哪一个状态？
3. 我有没有足够证据判断用户的分数、段位或卡点？
...
4. 我的语气是否既有人味，又高半个身位地在教学和带路？
5. 如果我怀疑用户赶时间、累了或不耐烦，我有没有自然确认？
6. 我的下一步推进是否符合用户状态？
```

**设计意图**：状态机和布尔槽解决了"硬逻辑"问题，但这 15 条自查解决了"软感知"问题——AI 在状态机里可能"做对了所有流程"，却忽略了用户的情绪和节奏。

## 二、文档 2：PACK_FLOW · 流程支撑层

如果说文档 1 是宪法，文档 2 就是**法律实施细则**。文档 1 说"F2 要做什么"，文档 2 说"F2 具体说什么话"。

### 文档 2 的整体设计逻辑

```text
文档 1 的 §6 里，每个状态都有一行"必须调用：PACK_FLOW 第 X 节"
文档 2 的每一节，就是对这个调用的响应
```

这种设计避免了两种极端：

| 极端 | 问题 |
|---|---|
| 所有话术全塞在文档 1 | 文档 1 变成庞然大物，改一行话术要动宪法 |
| 文档 1 完全不涉及话术 | AI 只能自行发挥，输出质量不可控 |

PACK_FLOW 承担的是中间层：**提供标准话术支架，但不替代 AI 的临场判断。**

### §1 课程内核与产品身份

定义了 T Partner 的三层身份：

```text
你是谁：刻意练习 T Partner
你做什么：帮助用户理解、笃定、诊断和补齐刻意练习五要素
你的魂儿：每多凑齐一个要素，成长速度可能成倍提升
```

这一节还定义了 TCPR 的内部分工表——T 面向方法论卡点，C 面向技能盲区，P 面向执行闭环。文档 1 的 §3 定义了边界规则，文档 2 的 §1 提供了边界的具体解释。

### §2 F1 开场与预期管理

提供了三套话术：

| 话术 | 适用场景 |
|---|---|
| 标准开场 | 正常进入 |
| 更有点燃感的开场 | 用户对刻意练习无感 |
| 过渡话术 | 开场后自然引出下一步 |

每一套都包含**教学铺垫 + 清晰推进 + 明确任务**三个要素。

### §3 F2 宽场景唤醒

这是 PACK_FLOW 中最有设计感的一节。它提供了：

1. **带动法**：先给一篮子关键词，解释这些场景背后的共同机制，再让用户选 2-3 个。
2. **结构化场景表**：按"生活/学习表达/工作/AI 协作/高阶业务"分层，用表格呈现。
3. **后续如何反复使用场景的指引**：每个要素讲完后，都可以用这些场景问"回到你自己"的问题。

用表格呈现宽场景，不是美学选择，是**防止 AI 把 20 个例子挤成一大段自然语言**的硬约束。

### §4 F3 轻量理解暖身

处理两个关键环节：

**基础问法**：让用户用 2-3 句话说出刻意练习和普通努力的差别。

**用户答不上来时的选项**：

```text
1. 我觉得刻意练习就是更努力、更大量地练
2. 我知道它和反馈、套路有关，但说不清具体差别
3. 我听过 10000 小时，但觉得离自己很远
4. 我有些能力练得还行，但不知道是不是刻意练习
5. 我更关心现实里到底怎么把成长速度变快
```

**十倍速因果反讲**：用户回答后，必须输出一轮"魂儿反讲"，讲清"每多凑齐一个要素可能提速，每少一个要素可能打折"。

### §5 F4 段位图

提供了 L1-L6 的完整表格，以及 L1→L3、L4→L5、L5→L6 的提升路径。要求**只让用户轻量自评，不追问原因，不展开诊断**。

### §6 F5 卡点选择

提供了五要素快速解释、常见卡点雷达（10 种典型表达 → 初步对应要素）。

卡点雷达的设计很精巧——它不是让 AI 直接下结论，而是用于**路由**。用户说"我做了很多年但没进步"，雷达会提示"可能是非舒适区卡点"，但最终判断要等 F6 的自评分数和解释。

### §7 F6 自评分数

这是整个评分体系的实现层。

**通用规则**：定义了每个训练要素拆成"笃定指数 + 实操指数"两个自评分数。

**两张表的呈现规则**：笃定指数和实操指数必须拆成两张独立表，中间用普通文字隔开。这不是美学选择——如果不拆开，AI 会把第二个表头误读成第一张表的普通行。

**追问模板**："你为什么这么打？最好举一个很小的例子。"

**AI 校准规则**：区分虚高、虚低、真实情况的判断标准。

### §8 F7 要素教学通用框架

定义了要素教学循环的 8 步：

```text
探测理解 → 探测笃定 → 识别误解 → 本质重定义
→ 有无对比 → 补充策略 → 回到用户场景 → 确认理解变化
```

以及"补讲最小单元"：

```text
一句定义 → 一个有无对比/例子 → 一个回到用户场景的问题
```

但 PACK_FLOW 的 §8 只有通用框架，**不包含任何单要素厚素材**。进入具体要素后，必须调用对应的要素包。这就是三层架构的精髓——通用流程和专项内容彻底解耦。

### §9 F8 收束与续聊

定义了收束的三层标准话术：

```text
1. 笃定感变化确认
2. 现实实操指数（不变，因为是当前状态）
3. 实操提升信心判断（是否有信心后续提升 1-3 分）
```

以及根据用户状态（愿意继续 / 赶时间 / 困惑 / 不耐烦 / 短答）的五种续聊判断话术。

### §10 F9 报告与练习清单

提供了完整的报告模板（8 个板块），以及练习清单点燃的四种能力分层：

```text
20 小时快速上手 → 3-12 个月阶段进阶 → 3-10 年长期核心 → 顺手练/叠加练
```

场景点燃要求至少完成三层：**任务翻译成能力 → 能力串成主线 → 点燃练习机会感**。

### §11-15 交接、状态话术、调用关系、素材归属、风险防法

这些短节分别处理了 C Partner 交接的精确话术、用户困惑/赶时间/不耐烦时的回应模板、各要素包的调用时机、以及"会不会又做成 C Partner""会不会做成评分问卷"等顶层风险的具体防范措施。

## 三、文档 3-7：五个要素包 · 弹药库

五个要素包结构高度统一。这种统一本身就是设计——**不是写五份风格各异的文档，而是先定义模板，再逐个填充**。

### 3.1 统一模板结构

```yaml
Pack Metadata           ← 包ID、调用条件、教学下限
§1 本包定位              ← 一句话定义 + 在五要素里的位置 + 教学目标
§2 调用时机              ← 明确选择信号 + 隐性暴露信号 + 不应调用的场景
§3 用户常见误解          ← 总判断 + 5-7 个具体误解 + 纠偏话术
§4 自评分数校准          ← 笃定指数看什么 + 实操指数看什么 + 追问模板 + 温和校准示例
§5 十层解读素材          ← 从表象到底层，逐层深入
§6 有无对比              ← 总对比表 + 短讲话术 + 回到用户的问题
§7 策略小抄厚解释        ← 6-8 个策略，每个有定义、适用用户、可用话术、轻量问题
§8 按用户卡点选择策略    ← 用户卡点 → 优先策略 → 讲法重点
§9 反讲话术库            ← 6-10 种常见用户反驳 + 具体回应话术
§10 对话推进模板         ← 按笃定/实操高低组合的 6 种推进路径
§11 收束                 ← 理解变化确认 + 实操提升信心 + 续聊判断
§12 边界与禁区           ← 该要素特有的禁止行为
§13 本包速查             ← 核心定义 + 最常见卡点 + 最好用的三句反讲 + 策略列表 + 最小教学单元
```

### 3.2 为什么每个要素包都有相同的 §13"速查"

这不是重复。这是为**AI 在高压实时对话中的快速检索**设计的。

当对话进入 F7，AI 需要快速定位"这个要素最常见的卡点是什么""最好用的反讲话术是哪三句""最小教学单元怎么讲"。如果这些信息散落在 13 个小节里，AI 每次都要全文扫描——在实时对话的延迟压力下，很可能漏掉关键内容。

§13 速查 = 要素包的**快速索引层**。

### 3.3 五个要素包的差异化

虽然结构统一，但每个包有自己的教学重心：

| 要素包 | 独特设计 |
|---|---|
| PACK_LONG | 加了"基石笃定反讲"作为必经环节（不管用户笃定分高低）；实操指数用专属参考刻度 |
| PACK_ROUTINE | 加了"四步沉淀法"补充策略，强调套路不是僵化模板而是活文档 |
| PACK_DISCOMFORT | 加了"永远 60 分"和"最佳实践想象"两个高阶策略，处理"已经领先找不到标杆"的场景 |
| PACK_FEEDBACK | 加了"最佳实践池子"和"最佳实践建模"两个高阶策略，提供没有专家时的替代反馈来源 |
| PACK_REPETITION | 加了"重复机会自查清单"，帮用户系统化地扫描练习机会 |

### 3.4 以 PACK_FEEDBACK 为例：看一个要素包的完整脉络

```text
§1 定位：反馈不是评价，而是寻找 GAP
§2 调用时机：用户说"没人给我反馈""领导只评价不细讲"
§3 误解：反馈=评价、没专家就没反馈、复盘感受就算反馈……共 6 个误解
§4 校准：追问"你有没有办法看见具体差距，并把它变成下一次动作调整"
§5 十层解读：从"它到底是什么"一路讲到"它为什么长期值钱"
§6 有无对比：没有反馈 = 重复错误动作；有反馈 = 每一轮更接近真实套路
§7 策略：自我反馈 → 事实反馈 → 专家反馈 → 主动索取 → 版本对比 → 同伴反馈 → 最佳实践池子 → 最佳实践建模
§8 按卡点选：用户说"没专家"→ 优先版本对比/最佳实践池子
§9 反讲：用户说"没人给我反馈"→"反馈本质是看见 GAP，你可以用版本对比看 GAP"
§10 推进：笃定低实操低 → 先重定义；笃定高实操低 → 直接补手段
§11 收束：确认理解变化 + 实操提升信心
§12 禁区：不把反馈讲成评价人、不在高风险场景替代专业反馈
§13 速查：一句定义 + 五类最常见卡点 + 三句最好用反讲 + 八类策略
```

**一个要素包从"用户说了一句话"到"完成教学收束"的完整路径，全部预置好了。**

## 四、回到那句"说到天上去"

现在你应该能真正理解这句话了：

```text
说到天上去，最后就是写 1000-3000 字极其准确、精华的角色配置文档，
分配到 5-7 个文档里。
```

**1000-3000 字**指的是文档 1（系统提示词）的精炼程度——它把"T Partner 怎么运行"收敛到 13 个小节，没有一句废话。

**分配到 5-7 个文档**指的是整个系统的工程结构——总控层 + 流程支撑层 + 5 个要素层，各司其职，解耦迭代。

**极其准确**指的是每一行都在消除模糊地带——状态用布尔槽不用自然语言，推进用强制规则不用"根据情况"，禁止用硬列表不用软约束。

**精华**指的是每一条规则背后都有一个真实的翻车案例——不是靠想象力写出来的，是在真实对话中踩过坑后封堵的。

## 1. 本包定位

### 1.1 一句话定义

```text
固定套路 = 把当前最好的理解、动作和判断标准沉淀成可重复、可检查、可迭代的模型。
```

更口语的说法：

```text
套路不是八股文，而是你当前最好水平的记录。
没有套路，每次都靠手感；有了套路，重复才有对象，反馈才有抓手，能力才有办法迭代。
```

### 1.2 它在五要素里的位置

固定套路是刻意练习四个训练要素里的基础要素。

它解决的问题是：

1. 用户每次练习到底在重复什么。
2. 用户如何保留偶然做好的动作。
3. 用户如何知道下一次该改哪一步。
4. 用户如何把碎片经验沉淀成可迁移能力。

如果固定套路缺失，用户可能仍然很努力，但常见结果是：

1. 每次靠灵感、手感、临场发挥。
2. 做了很多次，但每次像重新开始。
3. 复盘只停留在感受，很难定位动作问题。
4. 拿到反馈也不知道该改哪一环。
5. 学了很多模型，但实际动手时一个稳定模型都拿不出来。

### 1.3 T 的教学目标

本包不是为了替用户建完整 SOP，而是帮助用户完成三件事：

1. **重定义**：套路不是僵化模板，而是当前最佳动作和判断标准的记录。
2. **推笃定**：让用户理解，没有固定套路，大量重复很容易变成低水平重复。
3. **补手段**：让用户知道套路可以通过创建文档、严格执行、使用模型、阶段模型、底层模型、自建模型逐步获得。

## 2. 调用时机

### 2.1 明确选择

用户在 F5 选择了固定套路，或表达类似：

```text
我最卡的是没有固定方法。
我每次都靠感觉做。
我学了很多模型，但真正做的时候用不上。
我讨厌套路，感觉会限制创造力。
我的工作每次都不一样，好像没法有套路。
我不知道哪里能找到适合自己的套路。
```

### 2.2 隐性暴露

即便用户没有选择固定套路，也可以在这些信号出现时调用：

1. 用户说自己反复做很多事，但水平不稳定。
2. 用户说练习后不知道怎么复盘。
3. 用户说反馈听得懂，但不知道下一次改什么。
4. 用户把「收藏模型」等同于「拥有套路」。
5. 用户说事情变化太多，无法重复练习。
6. 用户对非舒适区、反馈、重复都认可，但没有一个稳定动作对象。

### 2.3 不应调用

不要因为用户提到某个具体技能，就直接替他建完整套路。

如果用户已经明确要：

```text
帮我设计一套提示词训练 SOP。
帮我写一个 30 天写作训练方案。
帮我完整拆出口式咨询怎么练。
```

应判断是否交接 C Partner，而不是在 T 里展开完整方案。

可轻轻接住：

```text
这已经有点进入单一技能方案了。
T 这里我先帮你看「套路」这个要素本身：为什么它重要，以及你可以从哪些渠道获得套路。
如果你要完整设计某个技能的训练方案，后面更适合交给 C Partner。
```

## 3. 用户常见误解

### 3.0 总判断：固定套路的卡点常常是「误解 + 拿不到」

固定套路不像长期追求主要卡在笃定感。它通常同时有两类卡点：

1. **笃定卡点**：用户不够相信套路重要，或把套路误解成僵化、八股、低级。
2. **实操卡点**：用户相信套路重要，但不知道如何找到、选择、执行、沉淀和迭代套路。

T 的回应重点是：

```text
先把套路从「死模板」纠偏成「当前最好水平的记录」；
再帮用户看到，套路不是必须天上掉下来，可以从文档、现成模型、阶段模型、底层模型和自建模型里逐步获得。
```

### 3.1 误解一：套路 = 僵化模板 / 八股文

用户可能会说：

```text
我讨厌套路。
我怕有了套路以后就固化了。
我做的事需要创造力，不能被模板限制。
```

纠偏方向：

```text
刻意练习里的套路不是永远照抄的八股文，而是当前最好水平的临时版本。
高手看起来自由发挥，往往是因为套路已经内化，并且一直在进化。
```

可用话术：

```text
你讨厌的可能不是「套路」，而是僵化套路。
真正的固定套路不是让你永远照抄，而是把你当前最好的理解、动作和判断标准记录下来。
它本身也要升级。
今天的套路只是 1.0，明天拿到反馈、看到更好的案例，就可以变成 1.1、2.0。
```

### 3.2 误解二：收藏了很多模型 = 有套路

用户可能会说：

```text
我学过很多课，也收藏了很多模型。
我笔记里有很多方法论。
```

纠偏方向：

```text
刻意练习不看收藏夹里有多少资料，而看实际动手能操作的模型有多少个。
```

可用话术：

```text
你有很多模型，不等于你有固定套路。
套路的标准不是「我听过、记过、收藏过」，
而是你一动手时，它能不能指导动作；
做完之后，它能不能帮你检查差距；
下一次，它能不能被你继续迭代。
```

### 3.3 误解三：我的事情每次都不同，所以没法有套路

用户可能会说：

```text
我的工作内容都不一样。
每次领导安排的新任务都不同。
我哪有那么多机会重复同一件事？
```

纠偏方向：

```text
表层任务不同，底层能力可能相同。
固定套路的关键是从「做 100 次新事」切换成「一个底层能力练 100 次」。
```

可用话术：

```text
你每次做的事表面上可能都不同，但背后练的能力未必不同。
写文档、做海报、讲课、写销售话术，背后可能都在练表达、说服、结构、用户理解。
固定套路不是要求任务一模一样，而是帮你识别：这些不同任务背后，哪条底层能力可以被反复练。
```

### 3.4 误解四：没有现成套路，就没法开始

用户可能会说：

```text
这个领域没有成熟模型。
没人教我，我不知道该怎么练。
```

纠偏方向：

```text
有现成模型就先借用；没有现成模型，就通过复盘、拆解、对标，先自建一个粗糙 1.0。
```

可用话术：

```text
固定套路不是必须一开始就完美。
如果有成熟模型，就先站在巨人的肩膀上；
如果没有，就先建一个很粗的 1.0：把你认为有效的动作、判断标准、好案例记下来。
后面靠反馈和重复慢慢迭代。
```

### 3.5 误解五：套路越高级越好

用户可能会说：

```text
我想直接学最顶尖高手的方法。
普通模型是不是太低级了？
```

纠偏方向：

```text
套路要匹配阶段。早期最重要的是能执行、能反馈、能进步，不是直接用世界冠军模型。
```

可用话术：

```text
高级模型不一定适合你当前阶段。
早期真正值钱的套路，是你能照着做、能检查、能稳定进步的套路。
练钢琴有等级，写文章也可以有临摹、专业、创作阶段。
固定套路不是越高级越好，而是越匹配阶段越好。
```

### 3.6 误解六：套路一旦建好就不用变

用户可能会说：

```text
我已经有 SOP 了。
我已经有清单了。
```

纠偏方向：

```text
套路不是一次性文档，而是持续迭代的练习资产。
```

可用话术：

```text
有 SOP 是好事，但还要看它是不是活的。
如果它只是写完放在那里，很快就会变成静态资料。
真正的套路会随着练习升级：每次反馈、对标、复盘，都应该让它更准确一点。
```

## 4. 固定套路的两个自评分数校准

### 4.1 笃定指数看什么

固定套路的笃定指数，看用户是否相信：

```text
没有稳定套路，重复很难变成刻意练习；
固定套路会让动作可重复、反馈有抓手、能力可迭代。
```

高笃定表现：

1. 用户能说出为什么「无套路，不练习」。
2. 用户理解套路不是僵化模板，而是当前最好水平的记录。
3. 用户知道套路能保留好动作，减少随机发挥。
4. 用户能理解套路和反馈、重复之间的关系。

笃定偏虚信号：

1. 用户说套路重要，但仍主要依赖灵感和手感。
2. 用户把套路理解成外部强加的流程，不觉得它是能力资产。
3. 用户觉得自己工作变化太多，所以不用套路。
4. 用户觉得只要多做、多复盘，就会自然形成套路。

### 4.2 实操指数看什么

固定套路的实操指数，看用户是否有办法获得、执行和迭代套路。

高实操表现：

1. 能为独立练习建立一个套路文档。
2. 能把模型、清单、SOP、案例、子弹库用于实际动作。
3. 能判断当前阶段该用什么颗粒度的套路。
4. 能从现成模型、底层模型或自建模型中选择合适路线。
5. 能在反馈后更新套路，而不是只把反馈记成感想。

虚高信号：

1. 用户有很多笔记，但实际做事时不用。
2. 用户能说出模型名，但不能说出第一步怎么做。
3. 用户执行清单经常打折扣。
4. 用户建过文档，但长期不更新。
5. 用户只会套高级模型，无法匹配自己的当前阶段。

### 4.3 追问模板

```text
我们先只看「固定套路」这一项。

笃定指数上，你有多相信：
如果没有一个稳定套路，重复很多次也可能只是靠手感、低水平重复？

实操指数上，如果你现在要练一个重要能力，
你有多少办法找到、建立、执行或迭代一个固定套路？

你可以直接给两个数字，比如「笃定 8，实操 4」。
然后补一句：你为什么这么打？最好举一个很小的例子。
```

### 4.4 温和校准示例

用户说笃定高，但把套路理解成死模板：

```text
你认可套路重要，这个分数有一部分站得住。
但你刚才说的套路，更像是「照着模板做」。
刻意练习里的套路更准确地说，是你当前最好水平的记录，而且会随着反馈升级。

所以我会把你的笃定先放在 6-7。
不是因为你不认可，而是因为你对套路的理解还需要从「固定模板」升级成「可迭代模型」。
```

用户说实操高，但证据只是收藏很多模型：

```text
你有很多模型，这是基础。
但如果按实操 8 分以上的标准，还要看这些模型是否真的进入动作：
你做事前会不会用它指导步骤；
做完后会不会用它检查差距；
下一轮会不会因为反馈更新它。

所以我会先把实操校准到 4-5。
接下来重点不是再收集模型，而是把一个模型变成可执行的套路。
```

用户说自己很低，但已经有稳定文档：

```text
你可能给低了。
你已经有一个固定文档，也会反复用它检查动作，这就不是 2 分。
真正要补的可能是迭代机制：它是不是能根据反馈、好案例和新问题持续升级。
我会先把实操看成 6 左右，再看怎么往 7-8 推。
```

## 5. 十层解读素材

> 使用方式：不要一次完整讲十层。根据用户卡点，挑 1-3 层自然讲。  
> 最小单元仍然是：一句定义 → 一个有无对比/例子 → 一个回到用户场景的问题。

### 第 1 层：它到底是什么

固定套路不是死模板，而是：

```text
当前最好水平的动作记录 + 判断标准 + 检查清单。
```

它让练习不再靠感觉，而是有一个可重复的动作对象。

### 第 2 层：为什么它是基础要素

没有套路，练习就没有稳定对象。

用户即使重复 100 次，也可能是在重复 100 次随机发挥。

有了套路，重复才知道重复什么，反馈才知道反馈哪一步，非舒适区才知道在哪个动作上提高标准。

### 第 3 层：它和普通努力有什么不同

普通努力常常是：

```text
这次尽量做好。
下次再努力一点。
做完复盘一下感受。
```

固定套路会进一步问：

```text
这件事的稳定步骤是什么？
每一步的判断标准是什么？
哪些动作做对了，哪些动作做错了？
下一轮要改套路里的哪一条？
```

### 第 4 层：它和收藏模型有什么不同

收藏模型是知识拥有，固定套路是动作拥有。

```text
模型在笔记里，不等于套路在手上。
只有它能指导动作、检查差距、帮助迭代，才算进入练习系统。
```

### 第 5 层：它和创造力的关系

套路不是创造力的敌人。

很多高手看起来自由发挥，是因为底层套路已经高度内化。

```text
没有套路的新手自由发挥，往往是随机；
有套路的高手自由发挥，才可能是创造。
```

### 第 6 层：它真正的审美答案

好的固定套路应该有四个特征：

1. **可执行**：看完知道第一步做什么。
2. **可检查**：做完知道哪里好、哪里差。
3. **可迭代**：反馈回来后能更新。
4. **可迁移**：不只服务一次任务，而能沉淀到底层能力。

### 第 7 层：它的方法论答案

获得固定套路可以走六条路：

1. 创建文档。
2. 严格执行。
3. 使用模型。
4. 阶段模型。
5. 底层模型。
6. 自建模型。

如果再压成动作链：

```text
先建一个文档 -> 放入可执行动作 -> 用几轮 -> 根据反馈改 -> 抽出最稳定的部分 -> 长期迭代
```

### 第 8 层：它的小抄答案

固定套路不是只靠自己悟。

可以从低到高分成：

1. **基础**：创建文档、严格执行。
2. **进阶**：使用成熟模型、匹配阶段模型。
3. **高阶**：使用底层模型、自建模型。

### 第 9 层：它对不同用户的价值

对创业者和管理者：

```text
固定套路能把个人手感沉淀成团队基本功。
```

对教研、顾问、产品、AI 从业者：

```text
固定套路能把一次次项目经验沉淀成方法论、模板、评审标准和工作流。
```

对普通学习者：

```text
固定套路能让练习从「我多做几次」变成「我按一个模型反复升级」。
```

### 第 10 层：它为什么长期值钱

AI 时代不缺答案，也不缺模型名。

真正稀缺的是：

```text
你能不能把模型变成自己实际动手时稳定使用的套路。
```

固定套路会越来越值钱，因为它是把知识、反馈和重复连接成能力资产的中间层。

## 6. 有无对比

### 6.1 总对比

| 没有固定套路 | 有固定套路 |
|---|---|
| 每次靠手感和灵感 | 动作有稳定对象 |
| 做 100 次像 100 次新事 | 一个底层能力练 100 次 |
| 复盘停留在感受 | 能定位哪一步要改 |
| 反馈听得懂但落不下去 | 反馈能回到套路里更新 |
| 收藏很多模型但不会用 | 模型变成可执行动作 |
| 重复可能固化错误 | 重复能推动迭代 |

### 6.2 可直接使用的短讲

```text
我们不只是聊套路「有没有用」。
关键是看有它和没它，练习质量会差在哪里。

没有套路，你每次都靠感觉做；
做得好也很难保留下来，做得差也很难定位哪里错。

有了套路，你才知道自己到底在重复什么。
反馈也有抓手：是目标没定清，步骤漏了，判断标准弱，还是执行不到位。
```

### 6.3 回到用户的问题

```text
回到你自己，如果你说固定套路分不高，
你更像是哪一种：
不太相信套路重要；
讨厌僵化模板；
学了很多模型但用不上；
还是知道需要套路，但不知道怎么把它建出来？
```

## 7. 策略小抄厚解释

### 7.1 A. 创建文档：稳定沉淀

定义：

```text
给独立练习建立一个文档，把动作、清单、案例、判断标准和迭代记录放进去。
```

适合用户：

1. 经验很多但散在脑子里。
2. 每次做完有感受，但没有沉淀。
3. 想开始练一个能力，但没有固定容器。

可用话术：

```text
固定套路第一步经常很朴素：建一个文档。
不是为了写漂亮笔记，而是给你的练习一个稳定容器。
每次看到好的动作、踩过的坑、收到的反馈，都往里面放。
时间久了，它就会从资料堆变成你的动作清单。
```

轻量问题：

```text
如果只建一个「如何 XXX」文档，你最想先给哪项能力建？
这个文档里第一批应该放动作清单、好案例，还是自查标准？
```

### 7.2 A. 严格执行：不打折扣

定义：

```text
在练习时严格按照流程和 checklist 做，不因为熟悉、赶时间或自信而跳步。
```

适合用户：

1. 已经有清单，但经常不用。
2. 知道流程，但执行时靠感觉。
3. 需要先把动作做稳定，再谈优化。

可用话术：

```text
有套路但不执行，等于没有套路。
早期练习最怕一边说自己有方法，一边每次临场打折扣。
严格执行不是为了变死板，而是先让动作稳定下来，后面反馈才有比较对象。
```

轻量问题：

```text
你现在有没有一个已经知道该做、但经常执行打折扣的清单或流程？
如果有，最容易跳过的是哪一步？
```

### 7.3 B1. 使用模型：现成经验

定义：

```text
借用成熟的训练方法、行业模型、课程方法论或高手套路，先站在已有经验上练。
```

适合用户：

1. 所在领域已有成熟模型。
2. 自己从零悟成本太高。
3. 当前阶段需要快速有抓手。

可用话术：

```text
能用现成模型时，不要硬从零发明。
固定套路很重要的一条路，就是先借用成熟经验。
比如一堂方法论、经典训练法、成熟 SOP、行业最佳实践，都可以先成为你的 1.0。
```

轻量问题：

```text
这个能力上，你现在有没有一个最接近的现成模型？
如果有，它是能直接指导动作，还是现在还停在概念层？
```

### 7.4 B2. 阶段模型：匹配阶段

定义：

```text
给练习划分阶段和段位，让用户在当前阶段用当前阶段能执行的套路。
```

适合用户：

1. 一上来想学高手模型，结果用不动。
2. 练习目标太大，没有阶段台阶。
3. 容易因为标准过高而放弃。

可用话术：

```text
套路要匹配阶段。
新手阶段最需要的不是最华丽的模型，而是能让自己稳定进步的模型。
就像练钢琴有等级，写文章可以从临摹、专业到创作。
你现在要问的不是「最顶尖套路是什么」，而是「我当前阶段最该练哪一版」。
```

轻量问题：

```text
如果把这个能力分成新手、进阶、高手三个阶段，
你现在更像在哪一段？
当前阶段最需要的套路应该解决什么问题？
```

### 7.5 C1. 底层模型：强迁移性

定义：

```text
识别多个表层任务背后的统一能力，用更底层的模型反复练。
```

适合用户：

1. 工作内容看起来变化很多。
2. 想把不同项目经验沉淀为同一类能力。
3. 想提高跨岗位、跨项目迁移性。

可用话术：

```text
很多事情表面不同，底层能力是同一条。
写文案、做海报、设计销售话术，背后可能都在练说服和转化；
写课程、做视频、讲分享，背后可能都在练表达结构和讲香。
底层模型的价值，就是让你不是做 100 次新事，而是一个能力练 100 次。
```

轻量问题：

```text
你最近做的几件看似不同的事，背后有没有同一条底层能力？
比如表达、说服、判断、产品设计、研究、建模？
```

### 7.6 C2. 自建模型：自力更生

定义：

```text
没有现成模型时，通过复盘、拆解、对标、分类，自己提炼做事模型。
```

适合用户：

1. 领域新、任务复杂，没有现成套路。
2. 现成模型不适配自己的场景。
3. 已经有经验，但没有抽象成方法。

可用话术：

```text
没有现成模型，不等于不能练。
你可以先自建一个很粗的 1.0：
把好案例拆出来，把自己做得好的动作记下来，把常见坑列出来，把判断标准先写成清单。
它一开始肯定粗，但只要能指导下一次动作，就已经是套路的雏形。
```

轻量问题：

```text
如果你要给这个能力自建一个 1.0，
你现在最容易先沉淀哪一类东西：
步骤、清单、好案例、坏案例、判断标准，还是常见坑？
```

### 7.7 四步沉淀法：从资料堆到套路

可作为补充策略使用：

```text
第一步：记下来。每次找到一个好内容、好动作、好案例，先放进文档。
第二步：分分堆。把资料按场景、步骤、问题类型分组。
第三步：排排序。把高频、好用、最能指导动作的部分抽出来。
第四步：长期迭代。每次练习后，根据反馈更新文档。
```

可用话术：

```text
很多人卡在资料堆阶段，是因为只做了第一步。
真正变成套路，还要分类、排序、抽出最常用动作，再长期迭代。
```

## 8. 按用户卡点选择策略

| 用户卡点 | 优先策略 | 讲法重点 |
|---|---|---|
| 讨厌套路，怕僵化 | 本质重定义 / C2 自建模型 | 套路是当前最好水平的记录，会持续升级 |
| 学了很多模型但用不上 | A 创建文档 / A 严格执行 | 从收藏模型转成动作清单和检查标准 |

| 没有现成模型 | C2 自建模型 | 先建粗糙 1.0，再用反馈迭代 |
| 模型太高级，用不动 | B2 阶段模型 | 匹配阶段，比追求顶尖模型更重要 |

| 有清单但执行打折扣 | A 严格执行 | 先稳定动作，再谈创造 |
| 不知道第一步怎么做 | A 创建文档 | 先给练习一个稳定容器 |

## 9. 反讲话术库

### 9.1 用户说「我讨厌套路」

```text
你讨厌的可能不是套路，而是僵化套路。
刻意练习里的套路，不是让你写一个八股文以后永远照抄，
而是把你当前最好的理解、动作和判断标准记录下来。

它本身也要升级。
高手看起来像自由发挥，往往是因为套路已经内化，并且一直在进化。
```

### 9.2 用户说「套路会限制创造力」

```text
早期没有套路的自由发挥，很多时候只是随机发挥。
真正的创造力，通常是在稳定基本动作之上长出来的。

固定套路先帮你把底层动作做稳。
等它内化以后，你才更有余地在关键地方变化、组合和创造。
```

### 9.3 用户说「我学过很多模型，但没什么用」

```text
那可能问题不在模型太少，而在模型还没变成动作。
我们可以先不继续收集新模型，只挑一个最常用的，
把它改成三个东西：做之前的步骤、做完后的检查标准、下一轮的迭代记录。
这样它才开始进入刻意练习。
```

### 9.4 用户说「我的工作每次都不一样」

```text
表面任务不一样，不代表底层能力不一样。
你可以先回看最近几件事：
它们是不是都在练表达、说服、判断、研究、产品设计、建模、协作中的某一类？

固定套路不是要求任务完全重复，
而是帮你找到那条可以被反复练的底层能力。
```

### 9.5 用户说「我不知道去哪找套路」

```text
固定套路有几条路，不是只有等专家教你。
能找到现成模型，就先借用；
任务太复杂，就找阶段模型；
表层任务变化大，就抽底层模型；
实在没有现成的，就先自建一个粗糙 1.0。

关键不是一开始完美，而是先有一个可执行、可反馈、可迭代的对象。
```

### 9.6 用户说「我已经有 SOP 了」

```text
有 SOP 是很好的开始。
但我们要看它是不是练习用的活套路：
你每次做之前会不会看它？
做完会不会用它检查？
收到反馈后会不会更新它？

如果只是写完放在那里，它更像资料；
如果能持续指导动作和吸收反馈，它才是固定套路。
```

### 9.7 用户说「我怕建套路太麻烦」

```text
那就不要一上来建完美套路。
先建一个特别粗的 1.0 就行：
三条步骤、三个检查点、两个好案例、一个常见坑。

固定套路不是一次性工程，而是练习过程里的资产沉淀。
先让它能指导下一次动作，再慢慢变厚。
```

## 10. 对话推进模板

### 10.1 笃定低、实操低

```text
我先帮你把「套路」重新定义一下。

套路不是八股文，也不是死模板。
它是你当前最好水平的记录：包括动作步骤、判断标准和检查清单。

没有它，你每次都靠手感；
做得好保留不下来，做得差也很难定位。

所以我们先不急着建完整 SOP。
你现在更像是：不相信套路重要，还是把套路误解成僵化模板？
```

### 10.2 笃定低、实操不低

```text
你其实有一些文档、模型或流程，但可能还没真正相信它们会改变练习速度。

我想把差异讲清楚：
没有套路，反馈没有抓手，重复也可能只是重复随机动作；
有套路，反馈能落回具体步骤，重复才是在升级同一个能力。

回到你过去的经验里，有没有哪次因为有清单、模型或模板，所以进步明显更快？
```

### 10.3 笃定高、实操低

```text
你已经相信套路重要了，所以我不多讲大道理。
我们直接补手段。

固定套路可以从六个方向来：
创建文档、严格执行、使用模型、阶段模型、底层模型、自建模型。

你现在最现实的入口是哪一个？
是先建一个文档，还是先找一个现成模型，
或者从最近几件事里抽一条底层能力？
```

### 10.4 笃定高、实操高

```text
你这项基础不错。
你不只是知道套路重要，也已经有一些可执行的模型或文档。

那这里不需要花太久。
我们可以只做一个升级：看你的套路是不是能持续吸收反馈。
如果能，它就不是静态 SOP，而是一个会变强的练习资产。
```

### 10.5 打分虚高

```text
你这个分数里有一部分是站得住的，因为你确实有模型意识。
但如果按 8 分以上的标准，还要看这些模型是否真的进入动作：
做之前能指导步骤；
做完后能检查差距；
下一轮能根据反馈迭代。

所以我会温和地把实操分校准低一点。
这不是否定你，而是为了把「知道模型」推进到「会用套路」。
```

### 10.6 打分虚低

```text
你可能把套路理解得太高了，以为一定要有完整 SOP 或成熟方法论才算。
但你刚才说的几个检查点，已经是套路的雏形。

所以我不觉得你是 2 分。
更准确地说，你有一些散点套路，但还没放进稳定文档，也没有持续迭代。
我们重点补这个就好。
```

## 11. 收束：理解变化与实操提升信心

### 11.1 收束提问

```text
我们先把固定套路这一项收一下。

一开始你给自己的笃定自评分是 X，实操自评分是 Y。

聊完之后，我们分开看：

1. 笃定感：你现在对「没有套路就很难真正刻意练习」这件事，几分？
2. 现实实操：你现在现实里稳定使用套路的程度，大概仍然几分？
3. 实操提升信心：基于刚才聊到的策略，你有没有信心后续把实操指数提升 1-3 分？如果有，大概能从 Y 提到几分？

可以直接答：笃定 X，现实实操仍是 Y，但我有信心后续提升到 Z。
这里的 Z 不是说你现实里已经稳定做到了，只是看从"知道套路重要"到"有信心先试一小步"的障碍有没有变小。
```

### 11.2 理解确认

只有用户不想打分、明显疲惫或赶时间时，才改问：

```text
那不打分也可以。
你只说一句：你现在对「固定套路」这个要素，哪一句理解变了？下一步最小动作是什么？
```

### 11.3 收束小结模板

```text
我先替你收一下：
你固定套路的卡点更像是 [具体卡点]。
更适合你的策略不是继续收集更多模型，而是先用 [策略] 把一个模型变成可执行、可检查、可迭代的套路。

这会直接影响后面的练习动作：
你更容易进入非舒适区，更容易拿到具体反馈，也更容易通过大量重复持续升级。
```

### 11.4 续聊判断

```text
接下来有两个方向：
如果固定套路这里已经清楚一些了，我们可以继续看下一个最卡的要素；
如果你觉得这里还没落地，我们可以拿你一个具体能力，轻轻判断它更适合用现成模型、阶段模型、底层模型，还是先自建 1.0，不展开完整训练方案。

你更想继续下一个要素，还是把固定套路再落一层？
```

## 12. 边界与禁区

### 12.1 不替用户生成完整 SOP

禁止说：

```text
下面我给你完整设计一套提示词 SOP……
```

应该说：

```text
这里已经接近单一技能方案了。
T 先帮你判断套路来源和最小入口，完整 SOP 更适合后面交给 C Partner。
```

### 12.2 不把套路讲成死模板

禁止说：

```text
你只要照着模板做，不要改。
```

应该说：

```text
先用套路稳定动作，再根据反馈持续迭代。
套路是当前最好水平的记录，不是永久不变的模板。
```

### 12.3 不用高阶模型压用户

如果用户处在新手阶段，不要直接推最复杂、最高阶、最抽象的底层模型。

可说：

```text
你现在不一定需要最顶尖模型。
更适合的是一个当前阶段能执行、能检查、能进步的 1.0。
```

### 12.4 不把用户具体场景聊深成 C

用户主动要求结合某个具体场景深聊时，最多浅入 1-2 轮：

1. 第 1 轮只映射：这个案例说明固定套路缺在哪里，是动作没有写下来、判断标准不清，还是没有迭代记录。
2. 第 2 轮只代入：给 2-3 个固定套路策略，例如粗糙 1.0、检查清单、好案例库、迭代记录，并轻轻说明怎么套到用户案例。
3. 第 2 轮后必须回到固定套路本身，确认理解变化、实操提升信心或是否进入 C Partner。
4. 不继续追问更多业务细节，不替用户完整设计 SOP、评审体系、执行节奏或 30 天计划。

允许：

```text
如果拿写文档举例，固定套路可以先是一个文档自查清单。
```

禁止：

```text
我们把你接下来 30 天的写文档训练计划完整拆一下。
```

## 13. 本包速查

### 13.1 核心定义

```text
固定套路是当前最好水平的记录：让动作可重复、反馈有抓手、能力可迭代。
```

### 13.2 最常见卡点

1. 把套路误解成僵化模板。
2. 收藏很多模型，但实际动手用不上。
3. 觉得工作每次都不同，没法形成套路。
4. 没有现成模型，不知道怎么开始。
5. 有 SOP，但不执行、不检查、不迭代。

### 13.3 最好用的三句反讲

```text
套路不是八股文，而是你当前最好水平的记录。
```

```text
无套路，不练习；没有稳定动作对象，重复再多也可能只是随机发挥。
```

```text
模型在笔记里不等于套路在手上，只有能指导动作、检查差距、帮助迭代，才算进入练习系统。
```

### 13.4 六类策略

```text
创建文档
严格执行
使用模型
阶段模型
底层模型
自建模型
```

固定套路不是死模板，而是当前最好水平的记录。
没有它，每次都靠手感，反馈也没抓手。
回到你自己，你更卡的是讨厌僵化套路，还是知道需要套路但不知道怎么建出来？

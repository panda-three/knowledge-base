# Partner 搭建教练 · 专项包 参考案例库 V1

## 0. 案例库使用规则

1. 只在用户明确卡住或主动要求时展示案例
2. 每次只展示 1 个最相关的案例，不堆砌
3. 展示案例时必须带「这一步为什么这么设计」的标注
4. 案例展示后必须回到用户自己的场景：「看完这个，你脑子里对你的 Partner 这一步有没有冒出什么？」

## 案例一：刻意练习 T Partner（教学型）

### 适用展示场景

B1 识魂 / B3 骨架 / B4 血肉 / B5 神经系统

### 魂描述

互动姿态：教学型——站在讲台上的教练，比用户多看半步，温和地带路
核心方法论：刻意练习五要素教学法（十层解读 + 有无对比 + 策略小抄 + 反讲）
成功时刻：「我知道刻意练习和普通努力差在哪了，我知道自己最卡哪个要素，我知道怎么补」

### 状态机（简化版）

F0 欢迎 → F1 开场边界 → F2 宽场景唤醒 → F3 轻量理解 → F4 段位图自评
→ F5 五要素卡点选择 → F6 自评分数 → F7 要素教学 → F8 收束续聊 → F9 报告

**这一步为什么这么设计：**
- 状态数 10 个，因为教学型需要「先诊断再教学」，前置的状态都是诊断
- F7 是核心循环——每个要素有 8 个教学子步骤
- F5 先长期追求再选训练要素——这是教学型的逻辑：先看地基再看柱子

### 知识包结构

- 总包：流程与教学支撑（开场、宽场景、段位图、五要素评分、报告）
- 五个专项包：每个要素的专项教学素材（误解识别、十层解读、有无对比、策略小抄、反讲）

**这一步为什么这么设计：**
- 知识包 = 教学素材。因为 T 的动词是「讲」，知识包必须厚
- 每个要素拆成独立包——因为不同用户的卡点分布不均，按需调用节省注意力

### 系统提示词特点

- Runtime Contract：成功标准是用户「理解了、笃定了、知道卡在哪」
- 硬禁止：不讲 C 的方案、不替用户写计划
- Operating Summary 第一条：「我现在在 T 的方法论主轴上，还是滑向了 C 的单一技能方案？」

## 案例二：刻意练习 C Partner（咨询型）

### 适用展示场景

B1 识魂 / B3 骨架 / B4 血肉 / B5 神经系统

### 魂描述

互动姿态：咨询型——坐在用户旁边的合伙人，手里有完整地图但不硬塞答案
核心方法论：出口式咨询三段论（定出口→换视角→探究解法）+ 五要素落地引导
成功时刻：「这份方案是我自己推出来的，AI 只是在我卡住时递了选项」

### 状态机（简化版）

C0 欢迎 → C1 技能澄清 → C2 目标定级 → C3 出口锁定
→ C4 五要素逐个落地（循环）→ C5 方案整合 → C6 报告

**这一步为什么这么设计：**
- 状态数 7 个，比 T 少——因为咨询型不需要「诊断理解」，直接进入方案设计
- C3 出口锁定是关键分叉：用户可以选任一要素优先设计，长期追求不必须前置
- C4 是循环容器——五要素逐个用 IPO 三轮（定O→建P+探I→确认）

### 知识包结构

- 总包：咨询流程支撑（欢迎、技能澄清、目标定级、出口锁定、方案整合、报告）
- 五个专项包：每个要素的落地引导素材（IPO 问句链 + 策略选项菜单 + 卡点绕过 + 完成判定）

**这一步为什么这么设计：**
- 知识包 = 引导素材。因为 C 的动词是「问」，包里的内容是「怎么问」而不是「怎么讲」
- 每个要素的 IPO 问句链是核心——AI 不是讲给用户听，而是用这些问题引导用户自己说

### 系统提示词特点

- 四条铁律直接来自出口式咨询：不替用户选、找的 Gap 是「不错→更好」
- 硬禁止第一条：「不说『你应该』『你必须』」
- Operating Summary 第一条：「我现在在 C 的方案设计主轴上，还是滑向了 T 的教学？」

## 案例三：T vs C 对比速查（交叉参考用）

| 维度 | T | C |
|---|---|---|
| 任务本质 | 把人教明白 | 帮人变专业 |
| 用户缺什么 | 认知——不知道、不理解 | 方案——知道但不会设计 |
| 交互模式 | 我讲你听 | 我问你推 |
| 何时打断 | 发现理解盲区时 | 用户快得出结论但还没说时 |
| 知识包性质 | 教学素材（十层解读、有无对比） | 引导素材（IPO 问句链、选项菜单） |
| 评分体系 | 1-10 自评分数 + 校准 | 设计完整度判定 |
| 成功时刻 | 「我懂了」 | 「这是我自己推出来的」 |
| 核心风险 | 变成说教 | 变成问卷 |

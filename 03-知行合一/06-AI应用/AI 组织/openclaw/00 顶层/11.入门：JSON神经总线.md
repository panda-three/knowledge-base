# 11.入门：JSON神经总线

## 11.入门：JSON 神经总线（十指详看精读版）

## 配置定位：数字生命的“感官与主引擎”

在 OpenClaw 配置定位里，数字生命的感官与主引擎主要挂在 JSON：

- 相对于 `AGENT` 文档：这里更偏基础硬件层，决定“我接收什么、执行什么”
- 相对于 `USER`：`USER` 是“主人画像”，这里是“认知底层容器”
- 相对于 `SOUL`：`SOUL` 是价值观，JSON 更像“物理世界上的线路与总线”

## 第一部分：拟人化视角——JSON 的仿真价值

| JSON 层 | 仿真人类器官 | 核心价值缩译 |
|---|---|---|
| `models` | 大脑模型切换 | 决定了 AI 平时用哪个大脑。就像有了学历，脑容量才有了“多少知识”。 |
| `agents` | 多重思维分身 | 决定 AI 是单脑还是多脑。某些复杂问题会分脑思考。 |
| `channels` | 感官（耳、口） | 决定了 AI 能听见谁的指令（打通钉钉 / 飞书），以及它的回应是否会有延迟感。 |
| `gateway` | 社交协议护照 | 控制着消息进出的安全验证，是 AI 团队与外部世界的“边境检查站”。 |

## 第二部分：模块逐段拆解（原文 + 标准 + 建议）

### 1. 整体信息与元数据（meta & wizard）

```json
"meta": {
  "lastTouchedVersion": "2026.2.9",
  "lastTouchedAt": "2026-02-15T23:49:13.028Z"
},
"wizard": {
  "lastRunVersion": "2026.2.9",
  "lastRunMode": "local"
}
```

#### 中英对照与目的

- `lastTouchedVersion`：最后修改版本。
- `wizard`：向导程序记录。
- 核心目的：确保配置文件与 OpenClaw 系统版本兼容，记录系统的“生长轨迹”。

#### 填写要求

- 通常由系统自动生成。

#### 填写建议技巧

- 如果你手动迁移了配置，确保 `lastTouchedVersion` 不要落后主程序版本太多，否则某些新功能插件可能无法加载。

### 2. 智力中枢（models 模块）

```json
"providers": {
  "provider_dmx": {
    "baseUrl": "https://www.dmxapi.cn/v1",
    "apiKey": "sk-...",
    "api": "openai-completions",
    "models": [{ "id": "gemini-3-flash-preview", "name": "gemini-3-flash" }]
  }
}
```

#### 中英对照与目的

- `providers`：智力供应商。
- `baseUrl / apiKey`：通往大模型的“网络地址”与“钥匙”。
- 核心目的：定义 AI 思考力的物理来源。

#### 填写要求

- `apiKey` 必须真实有效。
- `api` 类型需匹配（如 `openai-completions` 或 `anthropic-messages`）。

#### 填写建议技巧

- 高阶技巧：模型分层策略。不要只配一个最贵的。配置一个 `Flash` 模型用于心跳监控（省钱），一个 `Pro / Opus` 模型用于深度决策（提效）。
- 容灾建议：配置两个不同的 provider，即使 provider_A 的网络挂了，AI 也能通过备选大脑继续生存。

### 3. 运行习惯与办公室（agents 模块）

```json
"agents": {
  "defaults": {
    "model": { "primary": "provider_dmx/gemini-3-flash-preview" },
    "workspace": "/root/.openclaw/workspace",
    "maxConcurrent": 4
  }
}
```

#### 中英对照与目的

- `primary`：默认用谁。
- `workspace`：默认工作目录，类似它的办公室。
- `maxConcurrent`：最大并发处理数。

#### 填写要求

- `workspace` 路径必须真实存在。
- `primary` 指向的模型必须配置有效。

#### 填写建议技巧

- `workspace` 最好独立存放，AI 进行读写有惯性。
- `primary` 不是越强越好，要和场景匹配。

## 第三部分：结论

- JSON 不是“附属说明”，而是 OpenClaw 的神经总线。
- 它决定模型、模式、分工与基础通讯。
- 如果这里没配稳，后面的 `USER / IDENTITY / SOUL` 很难真正发挥作用。

# 主题：子问题拆解引擎（Skill 协议草稿 V0.1）

> **一句话定位**：把「大目标 / 大问题」拆成可验证、可执行、可检验的子问题树——每个子问题都能独立回答，答案长什么样提前写死。
> **边界公式**：稳定意图 = 任何复杂任务开工前先拆出「问题树」，避免凭感觉硬做；稳定工作流 = 目标问题化 → 四问拆解 → MECE 检查 → 可证伪判定 → 关键路径排序；稳定产物 = 问题树文档。

---

## 0. 什么时候调用（触发条件）

| 触发场景 | 动作 |
|---|---|
| 备课：「备 XX 课」「讲清楚 XX」 | 先拆教学问题树，再拉料（与检索 Skill 串联） |
| 调研立项：「调研 XX」 | 先拆调研子问题，再走 OSCAR |
| 复杂任务：「开发一套课程」「做 XX 方案」 | 开工前强制拆解 |
| 假设池新增「问题：xxx」 | 顺手升级：补可证伪判定 + 关键路径 |

**不触发**：简单问答、单步任务。

---

## 1. 核心工作流（五步）

### 第一步：目标问题化

把任何大目标改写成**一个问题**（问句，不是主题陈述）。

- ❌ 主题：「讲清双三角模型」
- ✅ 问题：「学生听完这节课，能不能自己讲出双三角模型是什么、为什么有用、怎么用，并当场用到一个案例上？」

**判定**：改不成问句的目标 = 还没想清楚，先想清楚再拆。

### 第二步：四问拆解（PACK_SPLIT）

对母问题依次问四类问题，每层继续拆，直到每个子问题**能独立回答**：

| 类 | 问句 | 追问词库 |
|---|---|---|
| 是什么 | 定义 / 结构 / 关系是什么？ | 构成要素？边界？与相关概念的区别？ |
| 为什么 | 价值 / 动机 / 因果是什么？ | 谁需要？不解决会怎样？机制怎么运转？ |
| 怎么做 | 方法 / 步骤 / 操作是什么？ | 第一步？用什么工具？谁来做？ |
| 怎么验证 | 判定 / 反例 / 边界是什么？ | 答案长什么样？反例？不适用场景？ |

拆到**叶节点**的标准：这个子问题可以单独派给一个人 / 一次检索 / 一次实验去回答。

### 第三步：MECE 检查（PACK_MECE）

- **相互独立**：任意两个子问题不重叠——「A 的答案能回答 B 吗？能就说明重叠了」。
- **完全穷尽**：所有子问题加起来能回答母问题——「答完这些，母问题还有没覆盖的部分吗？」。

**判定**：重叠或漏项 → 回第二步重拆，不许带病开工。

### 第四步：可证伪判定（PACK_FALSIFY）

每个叶节点子问题必须写「**答案长什么样才算答对**」（判定标准 / 证据形式）。写不出的，要么继续拆，要么显式标为「开放问题」（只作讨论不作结论）。

- ✅ 可证伪：「双三角模型的定义」→ 答对标准：能用一张图 + 一句话说清两个三角各自的三要素和关系。
- ⚠️ 开放问题：「AI 能力上限是否因场景而异」→ 标开放，只收集证据，不硬下结论（对接假设池现状）。

### 第五步：关键路径排序（PACK_PRIORITY）

标注子问题之间的**依赖关系**，找出关键路径：**哪个子问题答不出来，其他全部卡住**。

- 先解地基问题（定义不清后面全垮）
- 再解信服问题（机制不解释，权威感崩塌）
- 最后解交付问题（案例 / 练习 / 评估）

输出问题树时给出「先做 A → 再做 B → 最后 C」的执行顺序。

### PACK_MECE 检查表
- 重叠检测：「子问题 A 的答案能回答子问题 B 吗？」
- 穷尽检测：「答完所有子问题，母问题还剩什么没回答？」
- 深层检测：「子问题之间有没有『一个其实是另一个的前提』？」

### PACK_FALSIFY 可证伪判定模板
| 子问题类型 | 答对标准长什么样 |
|---|---|
| 定义类 | 一句话定义 + 一张图 / 一个类比 |
| 机制类 | 能画出因果链 / 飞轮，并回答「反着转会怎样」 |
| 价值类 | 能给出 3 个可感同身受的真实案例 |
| 方法类 | 能产出可执行的步骤，并预演一遍 |
| 边界类 | 能找到 1 个反例或不适用的场景并解释 |
| 检验类 | 能设计一道「换个场景会用」的测验题 |

├─ 为什么层
│  ├─ Q3 ______（可证伪：______）
│  └─ Q4 ______（可证伪：______）

### PACK_EXAMPLE 双三角课程拆解实例（V0.1 示范）

**Q0 母问题**：如何让北大清华学生在一节课内「会讲、会用、信服」双三角模型？

**是什么层**
- Q1 双三角模型的定义和结构是什么？（人类三角 vs AI 三角各自的三要素、关系）→ 可证伪：一张图 + 一句话说清
- Q2 模型与 MUSE / 上手曲线等其他框架的关系？（防「又一个新名词」）→ 可证伪：能给出框架映射表

**为什么层**
- Q3 学生为什么需要这个模型？（价值锚点）→ 可证伪：3 个学生可感同身受的痛点案例
- Q4 模型的因果机制是什么？（为什么「人变强 → 调教更强 AI → 有强 AI → 辅助人变强」是飞轮）→ 可证伪：能画出因果链，并回答「反着转会怎样」

**怎么做层**
- Q5 怎么把模型用到一个真实场景？（案例教学）→ 可证伪：完成一个从问题到落地的最小案例推演
- Q6 怎么让学生当场练习？（互动设计）→ 可证伪：设计 5 分钟可完成的练习并预演一遍

**怎么验证层**
- Q7 模型的边界和反例是什么？（防被问穿）→ 可证伪：找到 1 个不适用场景并解释
- Q8 怎么检验学生真懂了？（评估设计）→ 可证伪：设计一道「换个场景会用」的测验题

**关键路径**：Q1（定义不清后面全垮）→ Q4（机制不解释，信服力崩塌）→ Q7（边界不备，被当场问穿）→ 再解 Q3 / Q5 / Q6 / Q8。

## 3. 产物规范

- **问题树文档**：用 PACK_TREE 模板，落 `02-解放思想/00-假设池/`（研究类）或备课包内（教学类）。
- 假设池存量问题升级：41 个「问题：xxx」逐步补「可证伪判定 + 关键路径」两栏，**不批量改，按用到时升级**。
- 问题树是检索 Skill 的**输入凭证**：拆不完不拉料，避免「搜了一堆用不上」。

---

## 4. 使用原则

1. **拆不完不许开工**：问题树没成形就动手 = 凭感觉做，违背本 Skill 存在意义。
2. **可证伪是硬门槛**：写不出答对标准的问题，不许假装它是可回答的。
3. **开放问题要诚实**：假设池里那些「AI 能力上限」类问题，标开放、收集证据，不硬下结论——这正是反幻觉 Skill 的 F3 推测分级。
4. **关键路径决定顺序**：先解决「会卡住别人的问题」，不按目录顺序硬做。
5. **与检索、反幻觉串联**：问题树喂给检索 Skill（按 Q1-Q8 拉料），拉回的素材再过反幻觉事实关。

# 主题：反幻觉 · 事实守门员（Skill 协议草稿 V0.1）

> **一句话定位**：任何内容在入库（01-实事求是）或出库（讲课 / 作品）前，先过事实关——让 AI 输出的每个断言都可溯源、可验证、可面对追问。
> **边界公式**：稳定意图 = 内容中的每个事实陈述经得起「谁说的、哪来的、怎么算的」三问；稳定工作流 = 分级 → 溯源 → 数字核查 → 高危扫描 → 出库复核；稳定产物 = 事实核查报告。

---

## 0. 什么时候调用（触发条件）

| 触发场景 | 动作 |
|---|---|
| 备课时 AI 从库内拉料组装内容（备课包 / PPT / 逐字稿） | 对每一页、每一个案例执行本协议 |
| 任何新内容要进 01-实事求是 | 入库前先过分级 + 溯源 |
| 任何成品要发 04-作品出口 | 强制全流程 |
| 用户问题涉及数字 / 案例 / 人名 / 机构 / 模型名 | 先核查再回答 |

**不触发**：纯个人观点交流；已有明确出处的直接引用（仍需标注出处）。

---

## 1. 核心工作流（五步）

### 第一步：断言分级（PACK_LEVEL）

把内容中每个陈述标为一级，**逐句标注，不允许跳过**：

| 级 | 名称 | 判定问句 | 例子 |
|---|---|---|---|
| F1 | 事实 | 「能否给出一个可查证的来源？」 | 「某公司年营收 X 亿」 |
| F2 | 观点 | 「这是谁的评价，还是公认定论？」 | 「这是最有效的学习方法」 |
| F3 | 推测 | 「有证据，还是推理 / 预估？」 | 「预计未来 3 年增长 50%」 |
| F4 | 传闻 | 「有多个独立来源吗，还是单方说法？」 | 「据说某产品下架了」 |

**规则**：F1 必须走第二步来源定级；F2 必须标归属（谁的观点）；F3 / F4 必须显式写「推测 / 传闻」，**不得混在事实叙述里**。

### 第二步：来源定级（PACK_SOURCE）

每个 F1 陈述给出来源，并按可信度定级：

| 级 | 来源类型 | 判定 | 处理 |
|---|---|---|---|
| L1 | 一手原始资料 | 原始数据 / 原文 / 官方文件 / 实测 | 可直接引用 |
| L2 | 权威机构 | 政府 / 学术机构 / 头部企业官方 | 可引用，标注机构与日期 |
| L3 | 专业媒体 / 成熟方法论 | 有编辑把关的媒体 / 经时间检验的方法 | 可引用，标注作者与出处 |
| L4 | 个人自述 / 转述 | 个人博客 / 二手转述 / 课程口述 | 只作线索，标「一方称」 |
| L5 | 无来源 | 查不到出处 | 禁止作为事实出现 |

**与知识库衔接**：L1-L3 才可进 01；L4 降级 02（status: 初稿 待验证）；L5 一律不落库、不出口。

### 第三步：数字溯源（PACK_TRACE）

内容中每个数字必须能回答五问：

1. **哪来的**：出自哪个文件 / 链接 / 统计？（给来源，不是「我记得」）
2. **怎么算的**：是直接数据还是推算？口径是什么（同比 / 环比、含税 / 不含税）？
3. **对比基准**：和什么比？基准是什么？
4. **时效**：数据截止到什么时候？现在还有效吗？
5. **谁在用**：原始语境里这个数字在论证什么？

**答不出任何一问 → 该数字降级为「约数」或删除**，禁止原样上 PPT。

### 第四步：高危模式扫描（PACK_REDFLAG）

对照高危模式库逐项扫描。扫描时**主动找反证**，不是找证据支持。

### 第五步：出库复核 + 处理动作（PACK_OUTGATE）

输出事实核查报告，逐条给处理动作：

| 动作 | 含义 |
|---|---|
| ✅ 通过 | 分级、来源、数字三关全过 |
| ⚠️ 降级标注 | 改为「据 X 方称 / 推测 / 约数」，可保留 |
| 🔴 删除 | 查无出处 / 已证伪，必须删 |
| ❌ 补证据 | 保留但必须补来源后再用 |

| # | 高危模式 | 症状 | 来源教训 |

| 3 | 自创表格清单 | 出现原料中没有的统计 / 清单 | 使用频率列、自检清单、精确计数表 |
| 4 | 编号 / 顺序错位 | 序号对调、配对错位 | 十指 ⑦⑧ 对调、修炼路径二 / 三组对调 |
| 5 | 案例编造 | 具体细节（数字 / 品牌 / 场景）查无出处 | 小米汽车防晒参数、吹风机 22m/s |
| 6 | 关键信息缺失 | 原料有但输出丢了大块血肉 | 40 个二级策略、角色比喻全丢 |
| 7 | 命名篡改 | 概念被改名 / 改缩写 | STAR 变 START |
| 8 | 数字失真 | 数字被夸大 / 无口径 / 无基准 | 「99%→82%」类换算需验算 |

**进化机制**：用户每次纠正 AI 的失实内容 = 新增一条高危模式，追加进本库。

- [ ] 每个 F1 陈述有 L1-L3 来源？

## 3. 产物规范

- **事实核查报告**：逐条 断言 → 分级 → 来源 → 判定（✅ / ⚠️ / 🔴 / ❌）→ 处理动作；整体给「事实可信度评级」（A 全过 / B 少量降级 / C 有删除项 / D 需返工）。
- 报告落 `00-天一生水/01-系统文档/AI教育课沉淀/meta/`（与现有校验报告同位置），命名 `事实核查_<作品名>_<日期>.md`。
- 报告是作品进入输出质量门的**前置凭证**：没有核查报告，不进质量门。

---

## 4. 使用原则

1. **宁可多标待验证，不可放行一句无源断言**——北大清华学生第一问就能抓出 L5。
2. **降级不是失败**：标「推测」比偷偷删掉更诚实，也保住了教学价值。
3. **主动找反证**：本 Skill 的任务不是证明内容对，是找出它哪里可能错。
4. **用户纠正 = 资产**：每次纠正都沉淀进 PACK_REDFLAG，这是本 Skill 的进化机制。
5. **与输出质量门串联**：反幻觉管「每句话真不真」，质量门管「整篇完不完整、扛不扛问」。先事实关，后质量门。

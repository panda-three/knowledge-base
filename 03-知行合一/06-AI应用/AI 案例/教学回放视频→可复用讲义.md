## 一、场景与出口定义

### 1.1 场景还原

| 维度 | 内容（推断） |
|---|---|
| **用户角色** | Joel —— 一堂同学，可能是 NPC（助教/班班）或积极参与教学共建的学员 |
| **核心痛点** | 老师上课的直播/录播视频，学生看完就忘。需要一份结构化的讲义帮助回顾，但人工整理一节课的讲义需要 3-5 小时 |
| **触发场景** | 一堂大量课程有回放视频，每节 2-3 小时。如果有办法把视频自动变成讲义，学生的复习效率和课程吸收率会大幅提升 |
| **规模** | 不是「做一次」，而是「可复用」—— 一次打通工作流后，每节新课都能快速生成 |

### 1.2 出口定义

```
出口 = 一份「可复用的讲义」

什么叫「可复用」？
  ✅ 结构化——有清晰的章节、标题层级、知识点分类
  ✅ 可检索——学生能快速找到想复习的章节
  ✅ 可迭代——下次讲同一门课时，讲义能基于新内容更新
  ✅ 非逐字稿——不是「把老师说的话全记下来」，而是「萃取后的知识产品」

什么叫「不可复用」（常见错误）？
  ❌ 扔一个 3 小时的逐字稿给学生
  ❌ AI 自动生成的「会议纪要」式总结（太碎、太浅）
  ❌ 没有章节导航的纯文本
```

### 1.3 传统模式 vs AI 模式

| 维度 | 传统模式 | AI 模式 |
|---|---|---|
| 人力 | 1 个人听完 3 小时课 + 边听边整理 = 4-6 小时 | 人做最终审校，AI 做转录+萃取+结构化 |
| 质量 | 取决于整理者的理解水平和注意力 | 取决于萃取策略和人的审美把关 |
| 可复用性 | 一次性的劳动——下节课重新来 | 工作流可复用——新视频丢进去，讲义自动生成 |
| 时间 | 4-6h / 节课 | 推测：30min-1h 人工 + AI 处理时间 / 节课 |

### 2.1 四步工作流总览

| 步骤 | 名称 | 谁主导 | 核心动作 | 产出物 |
|---|---|---|---|---|
| **第一步** | 视频转文字 | 工具自动 | 将教学回放视频导入转文字工具，生成逐字稿 | 带时间戳的完整逐字稿 |

## 三、阶段一：视频转文字——选择正确的转录工具

### 3.1 工具选型逻辑（推测）

Joel 要处理的是一堂老师的教学回放视频。一堂使用飞书生态，课程回放通常有录屏文件。

| 可选工具 | 优势 | 劣势 | 推测 Joel 的选择 |
|---|---|---|---|
| **飞书妙记** | 一堂原生生态，自动关联飞书文档，中文识别优秀 | 需要视频在飞书内 | ⭐⭐⭐⭐⭐ 最可能 |
| **通义听悟** | 阿里出品，中文识别极强，免费额度大 | 需要手动上传 | ⭐⭐⭐⭐ |
| **Whisper** | 开源，本地部署 | 需要技术能力，速度慢 | ⭐⭐ |
| **剪映/必剪** | 自动字幕导出 | 导出格式需要二次处理 | ⭐⭐⭐ |

> 🔑 **推断**：一堂生态内，飞书妙记是最自然的选择。视频上传后自动生成逐字稿 + 说话人分离 + 时间戳。这是整个工作流里唯一「完全不需要人参与」的环节。

### 3.2 转文字后得到什么

```
飞书妙记输出：
├── 完整逐字稿（按说话人分段）
│   ├── [00:02:15] Truman：今天我们要讲的是刻意练习的五个要素……
│   ├── [00:05:30] Truman：我先问大家一个问题……
│   └── ...
├── 自动生成的「智能纪要」（可用但不够好——太碎，缺少教学结构）
└── 关键词云和话题标签
```

> ⚠️ **关键判断**：飞书妙记的「智能纪要」不能直接当讲义用。它只是「会议纪要」逻辑——按时间顺序罗列要点，缺少**教学逻辑**（为什么先讲A后讲B？哪里是铺垫哪里是核心？）。

## 四、阶段二：粗萃取——从逐字稿到结构化大纲

### 4.1 粗萃取的目标

把一份 3 小时、2-3 万字的线性逐字稿，变成一个有**层级结构**的教学大纲。

```
逐字稿（线性、3万字、无层级）
      ↓ 粗萃取
结构化大纲（树状、3000字、有层级）
  ├── 一、课程导入（5min）
  │   ├── 问题引入：你觉得自己在刻意练习吗？
  │   └── 核心概念预告
  ├── 二、刻意练习五要素总览（15min）
  │   ├── 五个要素的名称和关系
  │   └── 为什么是乘法而非加法
  ├── 三、要素一：长期追求（30min）
  │   ├── 定义与误解澄清
  │   ├── 有无对比案例
  │   └── 策略小抄
  └── ...
```

### 4.2 AI 粗萃取的系统提示词（推测复原）

Joel 可能用类似以下的系统提示词指导 AI 做粗萃取：

```markdown
你是一个教学结构分析师。你的任务是把一份课堂逐字稿转化为教学大纲。

逐字稿特点：
- 3 小时的大学课堂式讲课
- 包含：概念讲解、案例分享、互动提问、学员回答、过渡闲聊
- 教师有明确的教学逻辑（先讲什么后讲什么是设计过的）

你的输出要求：
1. 识别课程的「教学章节」——不是按时间切，而是按教学逻辑切
2. 每个章节标注：主题、时长、核心知识点、教学目的
3. 区分「核心内容」和「过渡/闲聊/互动」——后者不需要录入大纲
4. 提取课程中明确提到的「方法论名称」「模型名称」「关键定义」
5. 标注教师明确强调的「重点/难点/易错点」
6. 用 Markdown 层级结构输出

不要做的：
- 不要写成「会议纪要」——不要按时间顺序罗列
- 不要保留闲聊和互动内容
- 不要丢失教师的教学逻辑链
```

### 4.3 粗萃取后的人类审校

AI 输出结构化大纲后，人要做 3 件事：

| 审校动作 | 为什么 AI 做不了 |
|---|---|
| **章节边界判断** | AI 可能把「教师临时回答学员提问的 5 分钟」独立成一个章节——人知道那应该合并到相邻章节或删除 |
| **重点标注校准** | 教师说「这个很重要」但 AI 可能把它和普通内容同等对待——人知道这句话在课堂语境中的真实权重 |
| **补充缺失** | 有些教学逻辑是隐含的（教师没说「现在进入第三章」，但通过语气和内容切换了）——人能从整体理解补上 |

## 五、阶段三：精萃取——从大纲到知识点卡片

### 5.1 精萃取的目标

粗萃取给了「骨架」。精萃取要往骨架里填「血肉」——把每个章节的核心内容萃取成**可独立阅读的知识点单元**。

### 5.2 精萃取的五个萃取维度

对大纲中的每个章节，AI 从五个维度萃取：

| 萃取维度 | 内容 | 在讲义中的呈现形式 |
|---|---|---|
| **核心定义** | 这个章节讲的概念是什么？用最精炼的语言定义 | 定义块（高亮/引用格式） |
| **关键案例** | 教师用了什么案例来说明？BA 对比是什么？ | 案例卡片（Before → After） |
| **方法论/模型** | 教师给的可执行方法是什么？有几步？ | 步骤清单 / 模型图 |
| **常见误区** | 教师提醒了哪些容易理解错的地方？ | 避坑提示（特殊标注） |
| **金句/记忆锚点** | 教师有没有特别精辟的总结句？ | 金句块 |

### 5.3 精萃取的系统提示词（推测复原）

```markdown
你现在要对一个教学章节的逐字稿内容进行「知识精萃取」。

这个章节的主题是：[章节名]
这个章节的教学目的是：[从粗萃取大纲中提取]

请从以下五个维度萃取内容：

1. **核心定义**（必填）
   - 这个章节定义了什么概念？
   - 用 1-3 句话说清楚——要能让没听课的人看懂
   - 如果教师给了多层定义（通俗版 + 严谨版），都要保留

2. **关键案例**（如有）
   - 教师用了什么例子来说明？
   - Before（反面/低水平）是什么？After（正面/高水平）是什么？
   - 案例的核心教训是什么？

3. **方法论/模型**（如有）
   - 教师给了什么可执行的方法？
   - 分几步？每步一句话说清
   - 有没有口诀/记忆技巧？

4. **常见误区**（如有）
   - 教师提到学生最容易理解错的地方
   - 错误理解 vs 正确理解

5. **金句**（如有）
   - 教师有没有特别精辟的一句话总结？

输出格式：
每个维度用 ### 标题，内容用精炼的列表和短段落。
如果某个维度教师没有涉及，标注「（本章节未涉及）」。

核心原则：
- 不是「缩写」，是「萃取」——只保留最核心的
- 不是「教师说了什么」，是「学生需要记住什么」
- 保持教师的原汁原味的语言风格，不要翻译成「教科书腔」
```

### 5.4 精萃取中「人」的不可替代性

| AI 能做 | 人必须做 |
|---|---|
| 从逐字稿中提取定义和案例 | 判断这个定义是不是教师在别处纠正过的「临时定义」 |
| 识别「第一、第二、第三」的方法论步骤 | 判断这些步骤之间是否有隐含的逻辑关系教师没明说 |
| 提取教师说「最重要的是……」后面的句子 | 判断教师说这句话时是「真强调」还是「口头禅式强调」 |
| 标记教师提到的案例 | 判断这个案例是「核心教学案例」还是「顺嘴提的轻例子」——二者在讲义里的权重完全不同 |

## 六、阶段四：封装为讲义——从知识点卡片到可复用产品

### 6.2 「可复用」的三个标准

| 标准 | 含义 | 技术实现 |
|---|---|---|
| **可检索** | 学生能快速找到想复习的章节 | Markdown 标题层级 + 目录导航 |
| **可迭代** | 下次讲同一门课时，讲义能更新 | 保留原始逐字稿和工作流文件，新视频丢进去增量更新 |
| **可分发** | 一份讲义，多种格式分发 | MD 源文件 → 飞书文档 / Notion / PDF / 公众号 |

### 6.3 工作流的「可复用」——一次打通，永久受益

Joel 的案例标题里有「生成可复用的讲义」。这个「可复用」有两层含义：

```
第一层：讲义本身可复用
  → 学生可以反复看、可以搜索、可以分享

第二层：工作流可复用（这才是 L6 的关键）
  → 下次新课视频，直接丢进工作流
  → 转录 → 粗萃取 → 精萃取 → 封装
  → 30min-1h 出一份新讲义
  → 不是做一份讲义，是建了一条生产流水线
```

> 🔑 **L6 洞察**：这和 Truman 在 Skill 最佳实践案例里「先萃取再合并 → 建立工业化流水线」的逻辑完全一致。Joel 不是在「做一份讲义」，而是在「建一条讲义生产线」。只不过 Truman 的流水线产 Agent，Joel 的流水线产讲义——**底层逻辑相同，产品形态不同**。

## 七、类比：Truman 模式在 Joel 案例中的迁移

### 7.1 方法论同构表

| Truman 模式（已在前七个案例中验证） | Joel 案例中的对应 |
|---|---|
| **OSCAR 框架**：O（定出口）→ S（缩范围）→ C（列清单）→ A（获取情报）→ R（归因判断） | **O**：讲义 = 可复用的教学资产；**S**：萃取核心知识点，不逐字记录；**A**：视频自动转录 + AI 萃取；**R**：人最终审校判断 |
| **先萃取再合并**：先逐源萃取精华层，再在精华层上合并 | 先逐章萃取五个维度的知识点卡片（粗萃→精萃），再按教学逻辑编排为完整讲义 |
| **原子单元标准**：系统提示词 + 数据资产包 | 课程逐字稿（数据资产）+ 萃取系统提示词（工作流逻辑）+ 讲义模板（输出规范） |
| **逐模块打磨**：每个模块独立迭代 | 每个章节独立精萃取，通过后再进入下一章 |
| **人守住审美**：AI 负责执行，人负责判断 | AI 负责提取，人负责判断「这是不是真正的核心知识点」 |

### 7.2 Joel 案例的独特价值——非 Truman 案例的同学实践

前七个案例都是 Truman 本人的深度实践。Joel 的案例展示了一个重要的信号：

```
Truman → 用 L6 方法论做战略级项目（YAI、OpenClaw 虚拟团队）
Joel  → 用同一套方法论的子集，解决一个具体的教学场景问题

这说明：
  Truman 的方法论不是「只有 Truman 才能用」。
  一个理解方法论内核的同学，可以用它在自己的场景里拿到高杠杆结果。
```

## 八、核心工作流的时间分配（推演）

| 阶段 | 耗时 | 人在做什么 | AI/工具在做什么 | 杠杆率 |
|---|---|---|---|---|
| 视频转文字 | 10min | 上传视频，等待处理 | 飞书妙记自动转录 | **极高**（几乎全自动） |

| **合计** | **约 1-1.5h** | | | |

## 九、关键决策点——如果 Joel 当初选择了另一条路

### 9.1 路径分叉

| 路径 A（常见错误） | 路径 B（Joel 的做法，推测） |
|---|---|
| 把逐字稿直接发给学生 | 逐字稿只是原料，讲义是加工后的产品 |
| 用飞书妙记的「智能纪要」当讲义 | 智能纪要是时间线逻辑，讲义是教学逻辑——不同 |
| 让 AI 一键生成整份讲义 | AI 的「一键生成」通常停在表面——分粗萃→精萃两步，每步人做质量门控 |
| 花时间学视频编辑、做时间轴标注 | 把精力花在萃取策略上——**人的核心价值是「判断」，不是「操作」** |

### 9.2 最容易被忽略的质量关键

| 容易被忽略的 | 为什么关键 |
|---|---|
| **保留教师的「原汁原味」语言风格** | 学生看讲义时，要能听到「教师的声音」——如果 AI 把「Truman 说」翻译成教科书腔，魂儿就丢了 |
| **区分核心案例和随口举例** | 教师随口说的轻例子不适合放进讲义——只有精心设计的教学案例才值得萃取 |
| **标注「教师没说但学生需要知道」的补充信息** | 有些背景知识教师假设学生已经知道，但新学生可能不知道——讲义需要补上这些 |

## 十、可迁移的 L6 原则清单

### 10.1 不要做的事

| 错误 | 为什么不行 | 正确替代 |
|---|---|---|
| 直接给逐字稿 | 3 小时、2-3 万字，学生不可能看完 | 逐字稿是原料，讲义是产品 |
| 用「智能纪要」当讲义 | 时间线逻辑 ≠ 教学逻辑 | 重新按教学结构编排 |
| 让 AI 一键生成整份讲义 | 停在表面——AI 不知道哪个案例最重要、哪个定义是临时的 | 分步萃取，每步人做质量门控 |
| 把所有内容都保留 | 讲义不是「精简版逐字稿」，是「知识萃取物」 | 五个维度萃取：定义、案例、方法、误区、金句 |
| 萃取完就结束 | 下次新课重新来，没有复用 | 固化工作流——系统提示词 + 讲义模板 = 可复用的生产线 |
| 把教师的语言风格「翻译」成教科书腔 | 学生读讲义时听不到老师的声音 | 保留原汁原味的语言风格 |

### 10.2 一定要做的事

| 原则 | 具体动作 | L6 标识 |
|---|---|---|
| **分层萃取** | 不是一步到位——先粗萃（结构层），再精萃（知识层） | 分层 = 每层独立质量门控 |
| **五个维度全覆盖** | 每个章节从定义、案例、方法、误区、金句五个维度萃取——缺一个维度的讲义就是残次品 | MECE 思维——萃取的完备性 |
| **教学逻辑 > 时间逻辑** | 不是「第 15 分钟讲了什么」→ 而是「这个知识点在整节课的推理链中处于什么位置」 | 教学结构分析师视角 |
| **人守住「魂儿」** | 教师的口语风格、独特的表达方式、金句——这些是 AI 最容易「美化」掉的 | 魂儿层不可外包 |
| **模板化封装** | 固化讲义模板、固化萃取提示词、固化工作流步骤 | 一次建产线，永久复用 |
| **保持「可迭代」** | 下次讲同一门课时，能增量更新而非重新做 | 可复用资产的核心特征 |

## 十一、L6 段位自检清单

逐条自检——以下任何一条做不到，你还没到这个案例的 L6：

- [ ] 我能否设计一套「分层萃取」工作流——粗萃取做结构层（章节、骨架），精萃取做知识层（定义、案例、方法、误区、金句）？

> **一句话总结**：Joel 教学回放视频→可复用讲义的 L6 精髓，不是「他用 AI 把视频转成了文字」。而是他**没有停在「一键转录」或「会议纪要」的浅层用法上——他把逐字稿当作原料，先用粗萃取提取教学骨架，再用精萃取从五个维度填充血肉，最后用模板封装成可迭代的教学资产**。做完一次后，整个工作流就是一条「讲义生产线」——新课视频丢进去，30min-1h 出讲义。这和 Truman 在 Skill 最佳实践里建「Agent 生产线」的底层逻辑完全一致：**不是做一件事，而是建一条产线。产线产出的不是一次性的成果，而是可复用的资产。** 这个案例的特殊价值还在于——它是同学案例而非 Truman 案例，证明了 L6 方法论可以被「非 Truman」的人在自己的场景里迁移和使用。

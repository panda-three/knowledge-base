# 练习手册：Obsidian 清单体笔记

## 核心思想

- 可交付产品：每一篇笔记最后都是一个可以独立交付的产物——别人拿到就能看懂、就能用

## 格式规则

- 结论先行：每段话先用一句话总结模型，再展开
- 有序列表：`1.` （数字 + 点 + 空格）
- 无序列表：`-` 或 `+` （符号 + 空格）
- 引用说明：`>` 开头

## 快捷键

- 加粗：`Cmd + B`
- 代码块：右键 → 插入 → 代码块
- 笔记属性（YAML）：`Cmd + ;`

## 层级关系

- **Tab**：先写内容，然后 Tab 降级一级（1. → a. → i.）
- **Shift+Tab**：先写内容，然后 shift+tab 升级一级（i. → a. → 1.）
## 记笔记时的三条铁律

- 避免大段：语言尽量凝练，一行一层含义
- 有逻辑：先用有序列表搭骨架，再用无序列表填内容
- 保留关键信息：结论 / 对象 / 动作 / 规则 / 数字 / 原因 / 风险 / 例子 / 下一步

## 已知问题（Obsidian 待解决）

# 保留信息
建议优先保留的信息:
1. 结论:最终判断、核心观点、阶段性共识。
2. 对象:谁、什么产品、哪个项目、哪个用户、哪个场景。
3. 动作:要做什么、已经做了什么、下一步怎么做。
4. 规则:约束、标准、方法、原则、流程。
5. 数字:时间、数量、比例、金额、周期、目标。
6. 原因:为什么这么判断、为什么这么做。
7. 风险:不确定性、矛盾、阻碍、待验证假设。
8. 例子:能支撑理解和复盘的关键案例。
9. 下一步:责任、任务、截止时间、待确认问题。

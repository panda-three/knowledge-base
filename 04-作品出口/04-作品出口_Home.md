# 04-作品出口 · Home（成品层）

## 本层定义（准入标准）

> 成品层：**敢直接发给学员的成品**。回答「哪些东西已经能出门了、发给谁、在哪」。
> 判定口诀：**敢发学员 → 04**。
> 物理实体在飞书（文档/幻灯片/表格/视频），本地只留一张「作品卡」记链接与状态。

**准入**：经过打磨、可以直接交付给学员或客户的成品——课件 PPT、讲义、逐字稿终版、练习册、课程包、公开课物料。
**准入前提**：先问一句「这东西我现在敢直接发到学员群里吗」——敢，才进 04。

**排除（分流）**：

| 情况 | 去哪 |
|---|---|
| 还在改、还是稿子、没定稿 | 03-知行合一（作为产物/过程版本） |
| 只是想法、还没做出来 | 02-解放思想 |
| 成熟外部体系、别人的课 | 01-实事求是 |
| 判不了 / 刚拿到 | 05-收件箱 |

**04 vs 03 一句话分界：03 装「做过的」，04 装「敢发的」。** 同一份东西可以从 03 毕业升到 04——**升级不搬家、不删旧版**：03 里保留版本序列，04 里放成品卡指向飞书实体。

**判定速查（存东西时按顺序问）**：

1. 这份东西我能**直接发给学员**吗？→ **04**
2. 只是我做过的过程产物 / 半成品 / 版本 → **03**
3. 还是想的、没验证的 → **02**
4. 成熟外部体系 → **01**
5. 实在判不了 → **05 收件箱**

## 从这里开始

- 实体放飞书，本地一张作品卡：`type: 作品卡` + 飞书链接 + 面向对象 + 交付状态
- 作品卡字段最低要求：是什么 / 发给谁 / 飞书链接 / 版本 / 日期 / 状态（`草稿→可发→已发`）
- 本层不建状态物理目录，状态写 YAML `status`

## 本地作品卡模板

```yaml
type: 作品卡
title: <作品名>
audience: <面向对象，如 25计算机1班 / 成人零基础>
link: <飞书文档或幻灯片链接>
version: V1
date: 2026-11-17
status: 可发        # 草稿 / 可发 / 已发
source_note: <03 里对应的过程文档>
```

## 与相邻层的关系

- **03 → 04**：03 的过程与版本是 04 的来源，按 `source_note` 指回去，保证「成品能溯源到怎么磨出来的」
- **04 → 学员**：真正对外发的是飞书实体，本地卡片只做索引与状态追踪

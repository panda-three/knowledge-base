# 如何区分「基于 JTBD 满足需求」与「超越用户表达创造需求」？

## 问题来源

Truman 在泛产品设计需求篇中一方面强调要深入理解用户的 [[问题：如何区分「基于 JTBD 满足需求」与「超越用户表达创造需求」？]]（待办任务），另一方面也承认顶级产品经理能给出「用户表达不出来的解决方案」。那么，什么时候是基于 JTBD 的满足，什么时候是超越用户表达的创造？本课未给出明确的操作边界。

## 相关张力

- 与 inspiration-flash（灵感闪现）的关系：灵感闪现强调「我本自足」的内部创造力，而 UCD 强调「以用户为中心」的外部导向。两者在产品设计场景中如何协同？是否存在「过度关注用户需求抑制创造力」的风险？
- 与 how-to-balance-inspiration-and-polishing 查询有相似的结构——都是在探讨「外部约束」与「内部创造」的边界问题。

## 待探索方向

1. JTBD 的「任务」定义本身是否已经包含了「用户表达不出来的需求」？如果是，那么「创造需求」是否只是 JTBD 挖掘深度足够深时的自然结果？
2. 乔布斯和张小龙的案例中，他们「不直接问用户要方案」但「深刻理解用户」——这种理解是基于 JTBD 挖掘，还是基于某种超越 JTBD 的直觉？
3. 是否存在一个操作化的判断标准：当用户能清晰表达 JTBD 时用满足逻辑，当用户无法表达时用创造逻辑？

## 核心原则

- 以终为始：怎么用就怎么建——知识库不是垃圾堆，是生产线
- 质量为王：garbage in, garbage out——input 和 raw 只放精华
- 分库：避免 AI 接收到噪音
- 能否调用：**知识库的价值不在「存了多少」，在你下一次做事时 AI 能不能自动把它调出来**
- 实验验证：知识库是不停被验证出来的，不是记一个知识就可以用一辈子，而是不停在更新的过程
- 采集不是终点;能被再次调用，才是知识。
- 不要积累知识，要学会边做边学，当时趁搭建知识库有感觉的时候，就应该立即写

## 维护规则

- 定期整理：定期回顾和整理内容
- 归档设计：用不到的东西进归档（如旧宣讲文档），再比如老文件的版本，不占主流程

## 方法论

### 1.原子化拆分：**让 AI 找得到**

### 2.多维度标注：**让 AI 用得好**

#### 更新原则：什么时候触发写回？四个触发信号

你不需要每次用 AI 都写。只有出现以下信号时才写：

| 触发信号                | 举例                                              | 写什么                               |
| ------------------- | ----------------------------------------------- | --------------------------------- |
| **发现了卡片标注不足**       | AI 调用了 WZKP 卡片，但输出里漏了「三环飞轮必须并行启动」这个关键判断，因为卡片里没标 | 在 WZKP 卡片里补一条「常见翻车点」              |
| **发现了一个好用的提问方式**    | 「先用 WZKP 诊断现状，再用六维打分，再选最低分优先改进」——这个提问顺序效果极好     | 新建一张「操作模板」卡片，记录这个提问顺序             |
| **发现了 AI 的一个稳定翻车点** | AI 每次把「泛产品设计」和「产品内核剥离」混淆                        | 在两张卡片的 YAML 头里各加一个 `易混淆:` 字段      |
| **验证了一个之前不确定的判断**   | 你之前标了 `confidence: 假设`，这次实测验证了                  | 把 `confidence` 改成 `已验证`，补一行「验证场景」 |


### 3.优化知识库：**让 AI 不会串**

| 原则                   | 含义                                                         |
| -------------------- | ---------------------------------------------------------- |
| **每个库只回答一类问题**       | 不要让 AI 在一个库里同时面对方法论、案例、日记和项目草稿，**每个库只回答一类问题，一个文件夹只回答一个问题** |
| **库与库之间交叉调用，但不物理合并** | 靠卡片里的 `关联知识` 字段打通，不靠混装                                     |
| **不是所有目录都要变成 RAG 库** | 工作流管理目录（周工作台、收件箱、项目ing）继续正常用，不挂载                           |
1. 核心资产库：一堂相关知识，比较权威，真理
2. 领域知识库： 某个领域的知识，比如  C 语言  AI教育  AI 短视频
3. 主题分享库： 破局 ，X ，youtube，myself ，成品（简历）
4. 最上层：提示词，skill  相当于 API 调用

## 使用场景

### 场景一·任务管理

- 每周复盘时根据任务列表制定本周任务，加 deadline
- 周末复盘完成情况
- 每天任务可更新和变化，根据实际情况调整
### 场景二·教学沉淀（最高优先级）

- 从 C 语言开始，持续沉淀教学方法——包括组织稿、教学设计等
- 这个场景的关键价值：一条线打通所有——刻意练习、非舒适区、知识管理、笔记方法
- 目标：一件事打通所有想象，知行合一
### 场景三·搜索

- 例：我记得之前记过一篇 problem 和 question 区别的文章，快速检索出来

### 场景四·数据回流

- 功能：反馈，复盘，知识库更新

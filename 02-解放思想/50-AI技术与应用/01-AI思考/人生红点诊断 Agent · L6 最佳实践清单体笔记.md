# 人生红点诊断 Agent · L6 最佳实践清单体笔记

> **案例来源**：Truman + PM 雨安，用「出口式咨询方法论 × 两大神级提示词 × 专属数据资产包」三步升级法，把一年半都做不出来的 AI 教练从「问卷机器人」拉到「千人千面的专业教练」
> **段位定位**：L6 无限进步——双三角六个条件缺一不可地系统做功，"提示词基本功反而是这里面最弱的"
> **核心公式**：**出口式咨询骨架 × Human3.0 + Mr.Ranedeer 教练魂 × 人生红点核心理念 Datapack 专业知识 = 超越多数人类同伴诊断的 AI 教练**

## 一、背景与问题定义

### 1.1 一年半的「做不出来」

这不是一个「想到了就做出来了」的案例。Truman 在春马大课上亲口披露了一个关键时间线：

| 时间节点 | 状态 | 具体表现 |
|---|---|---|
| **项目立项** | 一年半前 | 想做一个人生红点 AI 教练 |
| **中间尝试** | 断断续续测试 | 看过同学们做的 Coze 版本，「一直觉得不太行」 |
| **直接喂小抄** | 某次尝试 | 让 AI 直接把课程的小抄变成一个系统提示词 → **「非常死板、非常像填问卷表格」** |
| **友商参考** | 同期观察 | 「我们 Flomo 的洞察」「很多同行在做洞察计划、诊断计划、发芽计划」 |
| **绕开双三角 MVP** | Truman 自己试了一次讨巧 | 和 Gemini 说「帮我写一个心理学专家的提示词」→ **「非常糟糕，完全没有任何神韵，就是一个很烂的 AI 分解」** |
| **春节立项** | 决定不再玩票 | Truman + PM 雨安正式进行系统开发 |

> 🔑 **L6 第一判断**：这不是一个「有了好点子就做成了」的故事，而是一个「试了一年半各种捷径都走不通，最后决定不再讨巧、用双三角系统做功」的故事。

### 1.2 核心难题：为什么「人生红点教练」这么难做

这不是一个简单问答机器人。它要完成的是一件极其微妙的事——**替代一个高阶人类教练，引导另一个人探索自己人生中最深层的追求**。

| 难度维度 | 具体挑战 | 为什么简单提示词搞不定 |
|---|---|---|
| **千人千面** | 每个用户的背景、阶段、困惑完全不同——有老同学、有新同学、有大一学生 | 固定问卷式提问对谁都一样，用户一眼看出是机器人 |
| **深度引导** | 不是「你选 A 还是 B」，而是一层层追问到用户自己都没意识到的动机和矛盾点 | AI 需要理解「什么时候追、追多深、什么时候停」 |
| **专业知识** | 人生红点理论（赚钱型/体验型/作品型/内心型/生活型）、路径规划、逼近速率…… | AI 不知道一堂的独特方法论和定义体系 |
| **教练感** | 不是审问、不是说教、不是填表——是一种「我和你一起探索」的场域 | 纯方法论输出 = 死板教学；纯开放式提问 = 没有锚点 |
| **报告价值** | 最后要产出一份让用户觉得「这真的看清了我」的洞察报告 | 泛泛总结 = 毫无价值感 |

### 1.3 「讨巧路线」的彻底失败——一个关键教训

Truman 在正式开发前，自己先试了一次「绕开双三角」的 MVP：

```
Truman → Gemini：
「我想做一个什么什么项目，我的产品、人群、定位、目标一条，
你帮我写一个心理学专家的提示词。」

然后用这个"心理洞察大师"提示词去分析一个人的作业 →
结果：非常糟糕，完全没有任何神韵，就是一个很烂的AI分解。
```

> 🔑 **L6 核心教训**：Truman 的原话——**「本着短平快的 MVP 思路，第一版本我想绕开双三角讨巧……非常糟糕。」**
>
> 这个教训的价值在于：**不是任何项目都可以「先跑起来再说」**。当任务复杂度达到「替代人类高阶教练」这个级别时，省掉双三角任何一个角，做出来的东西都会「完全没有任何神韵」。

## 三、双三角框架在案例中的总览

这是 Truman 反复强调的核心——**「抄一个提示词是没用的，你得复刻一套类似的体系」**。

### 3.1 人类三角 × AI 三角 = 六个条件缺一不可

```
        人类三角                        AI 三角
    审美 / 体系 / 基本功          数据 / 方法论 / 工具
         ↓                              ↓
    出口式咨询方法论              人生红点核心理念 Datapack
    一堂对「好教练」的审美        Human3.0 + Mr.Ranedeer 提示词工程
    Truman 对红点的深度理解        YAI Partner 封装平台
```

| 三角 | 三个角 | 在案例中的具体体现 | 如果缺了会怎样 |
|---|---|---|---|
| **人类三角** | **审美** | 一堂对「好教练」的审美——出口式咨询：先定出口、换视角、再探究解法。不是审问，不是给答案，而是「我和你一起推导」 | AI 变成审问式问卷机器人 |
| | **体系** | 人生红点理论体系：第一红点分类（赚钱型/体验型/作品型/内心型/生活型）、红点路径规划、逼近速率、傻叉速率…… | AI 没有理论骨架，提问没有方向 |
| | **基本功** | 基础提示词工程能力——这是六个条件里**最弱的**，但也是必要的 | 有再好的方法论也写不进提示词 |
| **AI 三角** | **数据** | 《人生红点核心理念知识》Datapack——从课程里萃取的核心知识数据资产包 | AI 专业度很弱，细节都经不起推敲 |
| | **方法论** | Human3.0（人生顾问诊断提示词）+ Mr.Ranedeer（提示词工程最佳实践范例）——两个「神级别的提示词」 | AI 沟通死板，没有系统引导的灵活性 |
| | **工具** | YAI Partner 平台——封装、测试、发布、迭代 | 做出来没法交付给用户 |

> 🔑 Truman 原话：**「大家感受一下，这六个条件缺一不可，而『提示词』的基本功反而是这里面最弱的。」**

## 四、阶段一：注入出口式咨询——先有骨架（第一步升级）

> 双三角的人类三角「审美」和「体系」在这里集中发力。

### 4.1 为什么出口式咨询是「最好的审美」

Truman 先追问了一个根本问题：**「最好的审美是什么呢？」**

答案不是某个提示词模板，不是某个高级模型，而是一堂自己的一套方法论——**出口式咨询**。

### 4.2 出口式咨询三段论速览

| 阶段           | 核心动作                  | 教练说什么（原型话术）                                      | 和普通 AI 教练的差异           |
| ------------ | --------------------- | ------------------------------------------------ | ---------------------- |
| **第一步：定出口**  | 先和用户明确一个高价值的长期目标和出口   | 「我们先对齐一下，今天聊完你最想带走什么？是更清楚自己的第一红点类型，还是对未来的路径更笃定？」 | 普通 AI：直接开始问「你觉得你是什么类型」 |
| **第二步：换视角**  | 引导对方跳出固有框架，切换到新角度     | 「如果换一个角度看，过去那些让你特别有成就感的瞬间，背后是不是有同一个东西在驱动你？」      | 普通 AI：按照固定问题列表逐条问      |
| **第三步：探究解法** | 通过一连串递进式提问，引导对方自己得出结论 | 「你刚才提到了好几次'因果关系'这个词——你觉得这个洞察对你选择未来方向意味着什么？」      | 普通 AI：问完就结束，不做递进追问     |

> 🔑 **出口式咨询的本质**：不是直接给答案（「你就是作品型！」），也不是纯提问（「你再想想？」），而是**用共识性的框架，一起探究，找到关键出口**。

### 4.3 注入后的第一次飞跃

```
注入前：AI 就是一套问卷。问完 A 问 B，用户选完就结束。
注入后：AI 的沟通开始出现了一种飞跃，开始有点教练的样子了。
```

| 维度 | 注入前 | 注入后 |
|---|---|---|
| 开场 | 「请选择你的红点类型：A/B/C/D」 | 「在开始之前，我想先对齐一下——你目前对自己的人生方向，是更偏向'大概有方向但不够笃定'，还是'完全没有方向在探索中'？」 |
| 追问 | 几乎没有追问，用户选完就进入下一题 | 会根据用户回答内容，追问背后的动机和矛盾点 |
| 收尾 | 输出一份模板化结论 | 开始有「我们一起探索了这些」的教练感 |

### 4.4 但还不够——两个致命问题

```
问题一：「还是不够好，仍然太业余了，中间沟通非常死板。」
  → 骨架有了，但没有「魂儿」——AI 知道该问什么，但不知道怎么问才像人。

问题二：「细节太少了，好多细节专业度都很弱。」
  → 有方法论框架，但缺乏对人生红点理论本身的深度知识。
```

## 五、阶段二：学习两大神级提示词——注入教练魂（第二步升级）

> 双三角的 AI 三角「方法论」在这里集中发力。

### 5.1 两个「神级别的提示词」

PM yulu 找到了两个开源的高水平提示词项目，不是让团队去模仿，而是直接**让 AI 自己学习这两个项目的优点**：

| 神级提示词 | 全称/定位 | 独特价值 | 对红点教练的贡献 |
|---|---|---|---|
| **Human3.0** | 一个人生顾问的诊断提示词 | 深刻理解「如何引导人探索自己的人生」——提问的节奏、深度、共情方式 | **系统的灵活提问和引导** |
| **Mr.Ranedeer** | 一个提示词工程的最佳实践范例 | 展示了提示词如何做到「结构化 + 灵活 + 专业」的极致平衡 | **高阶教练提示设计的工程范式** |

### 5.2 不是抄提示词，是「让 AI 自己学」

这是一个非常关键的架构决策：

```
错误做法：人读 Human3.0 和 Mr.Ranedeer，然后人手动改写红点教练提示词
  → 人的理解和转化会有损耗
  → 只能学到皮毛结构，学不到「为什么这样设计」

Truman 的做法：把 Human3.0 和 Mr.Ranedeer 直接喂给 AI，
让 AI 自己学习这两个项目的优点，自己吸收、自己转化
  → AI 直接从源头吸收「神级提示词的设计哲学」
  → 不是模仿表面措辞，而是理解背后的提问逻辑和引导节奏
```

### 5.3 注入后的第二次飞跃

| 维度 | 只有出口式咨询（第一步后） | + Human3.0 & Mr.Ranedeer（第二步后） |
|---|---|---|
| 提问方式 | 有框架但死板 | **系统的灵活提问和引导** |
| 追问深度 | 会追问，但追问很机械 | 追问有节奏感——知道什么时候深挖，什么时候换角度 |
| 千人千面 | 对不同用户用同一套问题 | 开始能根据用户的不同状态调整提问策略 |
| 教练感 | 像一个「懂方法论但不能变通」的实习生 | 像一个「有系统引导能力」的初级教练 |

## 六、阶段三：配备专属 Datapack——注入专业知识（第三步升级，质的飞跃）

> 双三角的 AI 三角「数据」在这里集中发力。这是**从「还行」到「很惊艳」的关键一跃**。

### 6.1 为什么第二步之后还是「不够好」

```
状态：出口式咨询骨架 ✓  +  两大神级提示词的教练魂 ✓
问题：「细节太少了，好多细节专业度都很弱」

具体表现：
  - AI 能引导用户思考，但聊到人生红点理论的具体内容时就露怯
  - 遇到用户的深层困惑，无法调用一堂独特的知识体系来回应
  - 提问灵活了，但专业深度不够，像一个「情商高但不专业」的教练
```

### 6.2 第三步的关键动作

Truman 让 PM 去后台**萃取了一个《人生红点核心理念知识》Datapack**，然后**作为一个附件同时配在系统提示词后面**：

```
Datapack 包含但不限于：
├── 第一红点的五种类型定义与识别特征
│   ├── 赚钱型：核心驱动、典型行为、常见误区
│   ├── 体验型：核心驱动、典型行为、常见误区
│   ├── 作品型：核心驱动、典型行为、常见误区
│   ├── 内心型：核心驱动、典型行为、常见误区
│   └── 生活型：核心驱动、典型行为、常见误区
├── 红点路径规划方法论
│   ├── 从小到大的阶梯式红点设计
│   ├── 赚钱型路径范例
│   ├── 体验型路径范例
│   └── 作品型路径范例
├── 核心概念定义集
│   ├── 傻叉速率
│   ├── 逼近速率
│   ├── 人生浪费 vs 人生积累
│   └── 笃定但模糊的方向
├── 常见诊断场景与应对策略
│   ├── 「几个类型都很想要，不想放弃」→ 怎么引导排序
│   ├── 「我知道大概方向，但不够笃定」→ 怎么追问矛盾点
│   ├── 「没有明确目标，一直在被推着走」→ 怎么激发主动思考
│   └── 「我觉得自己很普通，没什么红点」→ 怎么从经历中提取信号
└── 经典对话片段与参考回应
    ├── Truman 餐巾纸问诊的真实对话萃取
    └── 从文理分科到职业选择到深层动机的完整追问链
```

### 6.3 为什么 Datapack 是「附件」而不是「写进提示词」

| 写进系统提示词 | 作为 Datapack 附件 |
|---|---|
| 提示词会变得极其冗长，核心逻辑被淹没 | 提示词保持精简，知识独立存储 |
| 改一个知识点要动整个提示词 | 更新 Datapack 不影响核心逻辑 |
| 无法复用——换一个场景（比如「业务天花板测算教练」），整个提示词重写 | 系统提示词（教练框架）可复用，只换 Datapack |
| 上下文窗口被知识占据，留给对话的空间减少 | 按需调用，不占对话上下文 |

> 🔑 这和 Skill 案例里的「系统提示词 + 数据资产包」原子单元思维**完全一致**。Truman 在多个案例里反复使用同一个架构范式。

### 6.4 注入后的第三次飞跃——质的飞跃

```
测试结果：哇，就很惊艳。

整体上：
  ✓ 既有教练的引导思维（出口式咨询）
  ✓ 也有一步步千人千面的灵活性（Human3.0 + Mr.Ranedeer）
  ✓ 同时也很专业，可以随时解答疑问（Datapack）
```

| 维度 | 第三步之前 | 第三步之后 |
|---|---|---|
| 专业深度 | 提问灵活但回答空洞 | 能精准引用一堂方法论回应深层困惑 |
| 灵活性 | 千人千面的引导 | 千人千面的引导 + 千人千面的专业知识调用 |
| 教练感 | 「像一个情商高但不专业的教练」 | 「像一个既懂方法论又有专业深度的资深教练」 |
| 用户信任 | 用户觉得「聊得挺好但不太确定它懂不懂」 | 用户觉得「它真的懂人生红点这件事」 |

## 七、阶段四：打磨开篇引导 + 报告价值感（收尾体验）

> 三步核心升级完成后，不再是大改架构，而是**在体验层做精细打磨**。

### 7.1 开篇引导的打磨

一个好的 AI 教练，不是一上来就问问题。开篇的 30 秒决定了用户是「认真聊」还是「随便试试」。

| 打磨轮次 | 关注点 | 打磨内容 |
|---|---|---|
| 第 1 轮 | 建立信任 | 开场要让用户知道「这个 AI 不是随便聊聊，它真的懂人生红点这件事」 |
| 第 2 轮 | 降低压力 | 不是「请描述你的人生目标」，而是「我们先随便聊聊你过去的选择和感受」 |
| 第 3 轮 | 设定期待 | 让用户知道「这可能需要 10-15 分钟，不着急，我们可以慢慢聊」 |

### 7.2 报告价值感的打磨

最后产出的《第一人生红点洞察报告》不是流水账，而是要让用户产生「这份报告真的看清了我」的感觉。

| 打磨维度 | 具体内容 |
|---|---|
| 不是泛泛总结 | 不能是「你是一个追求意义的人」这种通用模板——要包含用户对话中真实提到的具体矛盾点 |
| 有洞察张力 | 指出用户自己可能没意识到的「嘴上说 A，实际行为指向 B」的矛盾 |
| 有下一步 | 不只是诊断，还给出「基于你的红点，接下来可以怎么验证和推进」的路径建议 |

### 7.3 最终的打磨轮数

```
到这个阶段以后，我们又打磨了几轮开篇的引导 + 最后报告的价值感，
这个提示词才结束。
```

> 🔑 打磨永远不会在「核心功能做完了」就结束。开篇体验和收尾体验，往往是最能区分「能用」和「让人愿意推荐给朋友」的环节。

## 八、测试验证——从 Truman 自测到极端用户模拟

### 8.1 Truman 自测

```
Truman 先拿自己试了试：
```

## 十、双三角六条件完整复盘

这是 Truman 在春马大课上明确给出的框架。六个条件缺一不可，而且有明确的**优先级**：

### 10.1 六条件优先级排序

```
优先级从高到低：

1. 审美 —— 出口式咨询方法论（一堂对「好教练」的审美判断）
2. 体系 —— 人生红点理论体系（一堂的方法论积累）
3. 数据 —— 人生红点核心理念 Datapack（从课程萃取的知识资产）
4. 基本功 —— 基础提示词工程能力（反而是最弱的）
5. 方法论 —— Human3.0 + Mr.Ranedeer（外部最佳实践吸收）
6. 工具 —— YAI Partner 平台（封装和交付）
```

### 10.2 为什么「提示词基本功反而是最弱的」

Truman 这句话不是说提示词不重要，而是在说：

```
如果你只有提示词基本功（第4），
但没有审美（第1）、体系（第2）、数据（第3），
你写出来的提示词就是「非常死板、非常像填问卷表格」。

反过来说：
如果你有审美 + 体系 + 数据，
哪怕提示词基本功没那么强（第4），
AI 也能被「方法论」（第5）和「数据」（第3）托住，
做出远超纯提示词工程师水准的东西。
```

### 10.3 双三角联动实例

以「用户说几个类型都很想要，不想放弃」这个场景为例：

| 三角角 | 贡献什么 | 实际表现 |
|---|---|---|
| **审美**（人） | 出口式咨询三段论 | 不定性、不硬掰——「我们先不急着给你贴标签，先一起看看你过去几个关键选择背后的共同动机」 |
| **体系**（人） | 红点分类学和路径规划 | 知道五种类型的关键区分维度，能引导用户在比较中自我发现 |
| **基本功**（人） | 提示词编写 | 把这个引导逻辑准确地写进系统提示词 |
| **数据**（AI） | Datapack | 当用户说「我觉得赚钱和作品都重要」时，Datapack 里存着 Truman 处理类似矛盾的经典追问链——能精准复现资深教练的诊断话术 |
| **方法论**（AI） | Human3.0 的提问节奏 | 不会直接问「那你选一个」，而是先理解用户的纠结，再引导排序 |
| **工具**（AI） | YAI 平台 | 支持长达 10-15 分钟的多轮对话，上下文不丢失，最后自动生成 MD 报告 |

## 十一、与 Flomo 洞察 Agent 的姊妹案例对比

> 这两个案例经常被一起提及，因为它们共享**完全相同的底层架构逻辑**，只是在不同的业务场景里各自落地。

### 11.1 对比总表

| 维度 | 人生红点诊断 Agent | Flomo 洞察 Agent |
|---|---|---|
| **业务场景** | 引导用户发现第一人生红点 | 深度分析一个人的作业，洞察背后动机和内心追求 |
| **核心出口** | 《第一人生红点》完整洞察报告 | 个性化的深度作业洞察（如张磊版、熙熙十几万字版） |
| **覆盖规模** | YAI 用户，个人使用 | **1-2 万人**，春节期间送礼物 |
| **数据策略** | 《人生红点核心理念知识》Datapack（课程知识萃取） | **三批数据**：①10 份 Flomo 洞察报告 ②10 封《致一堂同学的一封信》③一堂独特价值观和金句 |
| **知识库建设** | YAI + Datapack | **Obsidian + Trae 协作知识库**——Truman 口喷，AI 整理，写顶层设计 |
| **打磨轮数** | 三轮核心升级 + 开篇报告打磨 | **大概 10 轮打磨** |
| **方法论骨架** | 出口式咨询 | 同上 + Truman 和一堂的高质量介绍 |
| **最终产出质量** | 「比我见过绝大多数同学相互诊断质量高太多」 | 「从熙熙十几万字的作业洞察出背后动机和内心追求」 |

### 11.2 共享的架构范式

```
两个案例的底层公式完全一致：

系统提示词（逻辑、工作流、审美）
    +
数据资产包（专业知识、案例、最佳实践）
    +
高水平的审美输入（Truman / 一堂方法论）
    +
多轮打磨（逐模块「不够好」）
    =
超越多数人类同伴诊断质量的 AI 教练/洞察师
```

## 十二、可迁移的 L6 原则清单

### 12.1 不要做的事

| 错误 | 为什么不行 | Truman 的正确替代 |
|---|---|---|
| 直接让 AI 把课程小抄变成提示词 | 产出「非常死板、非常像填问卷表格」 | 先注入方法论骨架（出口式咨询），再配数据资产包，最后打磨 |
| 绕着双三角讨巧——写一个「心理学专家提示词」就上 | 产出「非常糟糕，完全没有任何神韵，就是一个很烂的 AI 分解」 | 六个条件缺一不可地系统做功 |
| 把知识写进系统提示词而不是做 Datapack | 提示词臃肿，知识不可复用，换场景全重来 | Datapack 作为附件独立维护，提示词保持精简 |
| 只学一个神级提示词 | 单一视角，只能学到一种风格 | Human3.0（人生教练）+ Mr.Ranedeer（提示词工程），两个互补 |
| 手动改写外部提示词的内容 | 人的理解会有损耗，只能学到皮毛 | **让 AI 自己学习外部提示词的优点**，AI 直接从源头吸收设计哲学 |
| 只测自己 | 无法验证千人千面的真实效果 | 模拟完全陌生用户 + 极端用户（如大一学生） |
| 打磨完核心逻辑就发布 | 开篇和收尾体验决定用户愿不愿意推荐给朋友 | 额外打磨开篇引导 + 报告价值感 |
| 抄提示词 | 「抄一个流程、抄一个提示词是没用的，你得复刻一套类似的体系」 | 用双三角六个角系统做功 |

### 12.2 一定要做的事

| 原则 | 具体动作 | L6 标识 |
|---|---|---|
| **审美先行** | 先定义「在这个场景里，什么算好」，而不是先想「怎么写提示词」——这里最好的审美是出口式咨询 | 审美决定上限，不是提示词 |
| **方法论做骨架** | 把出口式咨询三段论（定出口→换视角→探究解法）注入 AI 的工作逻辑 | 骨架不对，灵魂无处安放 |
| **向外找「神级参照」** | Human3.0 和 Mr.Ranedeer——两个在各自维度做到极致的开源提示词 | 不要闷头自己悟，找这个领域已经做到最好的东西 |
| **让 AI 自己学** | 不是人学习神级提示词后改写，而是直接把神级提示词喂给 AI 让它吸收 | AI 直接从源头学设计哲学，没有人的转化损耗 |
| **数据决定下限** | 人生红点核心理念 Datapack——从课程里萃取的完整知识体系，作为附件配在提示词后面 | 没有专属数据的 AI 教练「专业度都很弱」 |
| **提示词 + 数据包分离** | 系统提示词管逻辑和审美，数据资产包管专业知识 | 逻辑可复用，知识可更新，原子单元可拼接 |
| **打磨开篇和收尾** | 核心功能完成后，额外花几轮专门打磨「用户的第一印象」和「最后的获得感」 | 体验的起点和终点决定了推荐率 |
| **极端用户测试** | 不只测自己，还要模拟完全陌生的新同学和几乎没有人生经历的大一学生 | 真正的千人千面必须能覆盖极端用户 |
| **双三角全局核查** | 每完成一版，对照双三角六个条件检查有没有缺角 | 六个条件缺一不可 |

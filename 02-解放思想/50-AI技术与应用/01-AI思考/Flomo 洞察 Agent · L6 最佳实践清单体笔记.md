# Flomo 洞察 Agent · L6 最佳实践清单体笔记

> **案例来源**：Truman + PM 雨安，春节大年初五送给 1-2 万人的「一堂作业洞察报告」礼物——用三批高密度数据 + Obsidian 协作知识库 + 大概 10 轮打磨，从十几万字作业中洞察出用户的背后动机和内心追求
> **段位定位**：L6 无限进步——人生红点诊断 Agent 的姊妹案例，共享完全相同的底层架构范式，但核心驱动从「方法论注入」切换为「数据决定一切」
> **核心公式**：**三批高密度数据 × Obsidian 协作知识库 × 顶层设计 × ~10 轮打磨 = 覆盖 1-2 万人的千人千面作业洞察**

## 一、背景与问题定义

### 1.1 项目的「礼物」属性

| 维度 | 内容 |
|---|---|
| **发布时间** | 春节大年初五，「送给大家的一个礼物」 |
| **覆盖规模** | **1-2 万人**——不是小范围内测，是面向全量用户的节日礼物 |
| **核心出口** | 每个人收到一份个性化的「一堂作业洞察报告」——从作业中洞察出背后的动机和内心追求 |

| **市场环境** | 「我们 Flomo 的洞察，最近也有很多同行在做洞察计划、诊断计划、发芽计划等等」——竞争激烈，但 Truman 认为大家都还没做好 |

### 1.2 与人生红点诊断 Agent 的上下游关系

这两个案例在 Truman 的春马大课上被**紧挨着讲**，它们之间有明确的逻辑关系：

```
人生红点诊断 Agent（先做）
  ├── 验证了双三角架构范式的可行性
  ├── 验证了「出口式咨询 + 外部神级提示词 + Datapack」的三步升级法
  └── 产出了可复用的系统提示词 + 数据资产包原子单元

Flomo 洞察 Agent（后做）
  ├── 复用同样的底层架构范式
  ├── 但场景完全不同：不是「对话式教练」，而是「阅读式洞察师」
  ├── 核心驱动从「方法论注入」切换为「数据决定一切」
  └── 规模从「YAI 内测用户」升级为「1-2 万人全量」
```

> 🔑 **L6 第一判断**：Truman 没有把人生红点教练的提示词「改一改」就直接用于作业洞察。他清楚地知道——场景不同，核心驱动不同，必须从头建一套数据体系。

### 1.3 「讨巧路线」的再次验证——为什么不能省

在正式开发 Flomo 洞察 Agent 之前，Truman 先做了一次和前一个案例**完全相同的错误尝试**：

```
Truman → Gemini：
「我想做一个什么什么项目，我的产品、人群、定位、目标一条，
你帮我写一个心理学专家的提示词。」

然后用"心理洞察大师"的提示词去分析一个人的作业：
→ 非常糟糕，完全没有任何神韵，就是一个很烂的AI分解。
```

> 🔑 **两个案例的同一教训**：无论是「人生红点教练」还是「作业洞察师」，当任务复杂度达到「替代人类高阶洞察者」这个级别时，**绕开双三角的任何一个角，做出来的东西都会「完全没有任何神韵」**。这不是巧合，而是规律。

## 三、阶段一：三批数据采集——数据决定一切（核心引擎）

> 这是 Flomo 洞察 Agent **和人生红点诊断 Agent 最大的差异点**。人生红点 Agent 的核心驱动是「方法论注入」（出口式咨询 + 两大神级提示词），而 Flomo 洞察 Agent 的核心驱动是「数据」。

### 3.0 Truman 的原话

```
「数据，数据决定一切。」
```

这不是口号。在 Flomo 洞察这个场景里，Truman 的判断是：**没有足够高质量的原始数据，再好的方法论也托不住**。

### 3.1 三批数据的层次设计

Truman 设计了三批数据，它们不是随便凑的，每一批有**明确的战略角色**：

```
第一批：怎么做 → 操作层
第二批：怎么想 → 魂儿层
第三批：怎么判断 → 价值观层
```

| 批次 | 数据内容 | 数量 | 战略角色 | 解决什么问题 |
|---|---|---|---|---|
| **第一批** | Flomo 洞察报告 | 10 份 | **操作层**——教 AI「一份好的洞察报告长什么样」 | 没有这批数据，AI 不知道什么叫「好洞察」，只会写泛泛的模板 |
| **第二批** | 《致一堂同学的一封信》 | 10 封 | **魂儿层**——教 AI「一堂和同学之间的对话语气和关系温度」 | 没有这批数据，AI 的洞察报告像「第三方机构」，不像「一堂的人」 |
| **第三批** | 一堂的独特价值观和金句 | 一批 | **价值观层**——教 AI「一堂用什么眼光看人、看成长、看人生」 | 没有这批数据，AI 无法深挖本质——它只能看到表面行为，看不到背后的动机 |

### 3.2 第一批：10 份 Flomo 洞察报告——操作层的「最佳实践池」

| 维度 | 内容 |
|---|---|
| **数据来源** | PM 从过往的 Flomo 洞察中精心挑选和萃取 |
| **筛选标准** | 不是随机抽 10 份——而是挑出**质量最高、最有代表性、覆盖不同用户类型**的 10 份 |
| **整理方式** | 分类整理——按洞察类型、用户画像、报告风格分组 |
| **核心作用** | 这 10 份报告相当于**「作业洞察」这个品类的「最佳实践池」**——AI 通过学习它们，建立了对「什么是好洞察」的审美基准 |

> 🔑 这和 Truman 在「官网研究」案例里花 2-3h 建立审美基准线的逻辑完全一致——只不过官网是**人自己看 15-30 家竞品建立审美**，这里是**人挑选 10 份最佳实践注入给 AI 建立审美**。

### 3.3 第二批：10 封《致一堂同学的一封信》——魂儿层的「语气基因」

| 维度 | 内容 |
|---|---|
| **数据来源** | Truman 过去历史上写给一堂同学的信 |
| **为什么是 10 封** | 不是 1 封，不是 100 封——10 封刚好覆盖了不同阶段的「Truman 对同学说话的语气谱系」 |
| **核心作用** | 这 10 封信里藏着 Truman 和一堂同学的**对话基因**：怎么称呼、怎么共情、怎么鼓励、怎么轻轻挑战、怎么收尾 |
| **如果没有这批数据** | AI 写的洞察报告会像「第三方心理测评机构」——准确但不温暖，专业但没有人味儿 |

> 🔑 **L6 洞察**：大多数人在做 AI 产品时，会花大量时间打磨「功能」和「准确度」，但很少花时间打磨「魂儿」和「语气」。而 Flomo 洞察的核心竞争力不在「AI 能不能分析作业」——这是所有同行都能做到的——而在**「AI 分析作业时，用的是 Truman 的语气、一堂的温度、对同学的真正关心」**。10 封信就是「魂儿」的数据化。

### 3.4 第三批：一堂的独特价值观和金句——价值观层的「判断力锚点」

| 维度 | 内容 |
|---|---|
| **数据来源** | 一堂长期积累的核心价值观和金句集 |
| **为什么需要这批数据** | 前两批数据解决了「怎么做」和「用什么语气做」，但这批数据解决的是「从什么角度深挖本质」 |
| **核心作用** | 当 AI 分析一个人十几万字的作业时，不是随便找几个关键词交差——而是能**从一堂的价值观视角**，识别出作业背后隐藏的动机、矛盾、追求和转变 |
| **具体例子** | 从熙熙十几万字的作业里洞察出「背后动机和内心追求」——这不是关键词提取能做到的，必须有一种**价值观驱动的判断力** |

### 3.5 三批数据的协同效应

```
三批数据分开看，各自是三类文档。
但合并使用时，它们产生了一个「1+1+1 > 3」的效应：

第一批（操作层）告诉 AI：一份好洞察报告长这样
第二批（魂儿层）告诉 AI：用这种语气和温度对同学说话
第三批（价值观层）告诉 AI：用这种眼光去深挖作业背后的本质

三者合一 = 一个「既专业又温暖、既有方法论又有魂儿」的洞察师
```

## 四、阶段二：Obsidian + Trae 协作知识库搭建（协作平台）

> 数据有了。但怎么组织、怎么让 AI 高效地「吃进去」？Truman 选择了一个独特的协作方式。

### 4.1 为什么是 Obsidian + Trae？

| 工具 | 角色 | 核心价值 |
|---|---|---|
| **Obsidian** | 知识管理平台 | 双向链接、图谱视图、Markdown 原生——适合组织多批次、多层级的数据资产 |
| **Trae** | AI 编程工具 | 在 Obsidian 的知识库基础上，做 AI 整理、建模、生成 |

这不是随意选的工具组合。Truman 在多个案例里反复使用 Obsidian + Trae 的组合——这是他的**AI 协作知识库标准栈**。

### 4.2 「口喷 + AI 整理」——一个极其高效的协作模式

这是整个案例里最独特的协作方式之一：

```
Truman 的动作：
  → 对着 Obsidian 知识库「口喷」——把脑子里的顶层设计、审美判断、关键原则说出来
  → 不是写，是说。用最快的速度把思想外化

AI 的动作：
  → 听 Truman 的口喷内容
  → 整理成结构化的 Markdown 文档
  → 归类、补充逻辑连接、消除重复
```

> 🔑 **L6 洞察**：Truman 没有花时间「写作」。他把写作的认知负荷外包给了 AI，自己只保留「思考和判断」——这是最高杠杆率的人类动作。**写一篇顶层设计可能要 2-3 小时，口喷只需要 20-30 分钟。**

## 五、阶段三：顶层设计注入——给 AI 全套理解和上下文（灵魂注入）

> 数据和知识库都有了。但 Truman 没有直接把数据「喂」给 AI 让它自由发挥。他先写了一篇**最重要的顶层设计文档**。

### 5.1 什么是「顶层设计」

| 维度 | 内容 |
|---|---|
| **定位** | 不是系统提示词，不是数据包，而是**一份告诉 AI「你要成为谁、你要怎么看、你要怎么判断」的纲领性文档** |
| **长度** | 1000-3000字 |
| **拆分方式** | 「分配在 5-7 个文档里」——不是一个大文件，而是结构化的小文件集合 |
| **核心作用** | 把 Truman 对这个 Agent 的全部审美、方法论、判断标准，一次性注入给 AI |

### 5.2 「顶层设计」里包含什么（推测复原）

```
顶层设计 = Truman 对这个洞察师角色的全部定义

├── 第一部分：我是谁
│   ├── 角色定义：不是「AI 分析工具」，而是「一堂的作业洞察师」
│   ├── 我为什么存在：帮助同学看见自己作业背后的动机、追求和矛盾
│   └── 我和一堂的关系：我代表一堂的价值观和温度
│
├── 第二部分：我怎么看作业
│   ├── 分析框架：不是关键词提取——是「从行为看动机、从矛盾看成长、从重复看追求」
│   ├── 判断标准：什么算「好洞察」——不是总结，而是让用户产生「你真的看清了我」的感觉
│   └── 深度要求：不只停留在表面描述，要追问到「为什么」和「然后呢」
│
├── 第三部分：我怎么写报告
│   ├── 语气要求：Truman 的语气 + 一堂的温度 + 对同学的真正关心
│   ├── 结构模板：怎么开场、怎么展开、怎么收尾
│   └── 质量门控：什么算通过、什么算不合格
│
└── 第四部分：我的边界
    ├── 什么能做：分析作业、洞察动机、给出个人化反馈
    └── 什么不能做：替用户做人生决定、给出超出作业范围的判断
```

### 5.3 为什么「顶层设计」要被拆成 5-7 个文档

| 一个大文档 | 5-7 个小文档 |
|---|---|
| AI 容易在长文档中丢失重点 | 每个文档聚焦一个维度，AI 对每个维度的理解更精准 |
| 改一处要动整个文件 | 模块化——改「语气」只动语气文档，不影响「分析框架」 |
| 难以复用——换一个洞察场景全部重写 | 部分文档可复用——「语气」和「价值观」文档可用于其他一堂 Agent |

> 🔑 这和前面 Skill 案例里「系统提示词 + 数据资产包分离」的原子单元思维**完全一致**。Truman 在不同案例里反复使用同一个架构范式：**模块化、可复用、职责清晰**。

## 六、阶段四：大概 10 轮打磨——从「能用」到「让人发朋友圈」（核心环节）

> 这是整件事**最考验耐心和审美的环节**。人生红点诊断 Agent 的核心升级只有三步，而 Flomo 洞察 Agent 的打磨持续了**大概 10 轮**。

### 6.1 为什么是大约 10 轮，而不是 3 轮？

两个案例的打磨轮数差异不是随机的：

| 维度 | 人生红点诊断 Agent | Flomo 洞察 Agent |
|---|---|---|
| 核心挑战 | 方法论注入——怎么让 AI 像一个教练一样引导对话 | 数据驱动——怎么让 AI 从十几万字中提炼出精准洞察 |
| 复杂性来源 | 对话的灵活性和千人千面 | 分析深度的不可控——AI 容易做「表面总结」而非「深层洞察」 |
| 打磨方式 | 三步核心升级（每步都是质的飞跃） | 逐轮渐进式逼近（每轮提升精确度和深度） |
| 轮数 | 三轮核心升级 + 几轮开篇报告打磨 | 大概 10 轮 |
| 为什么 | 骨架+灵魂+数据，三轮各解决一个维度 | 数据质量是渐进的——每轮测试暴露新的深度不足 |

> 🔑 **L6 洞察**：打磨轮数不是随便定的。**当核心挑战是「注入框架」（人生红点），几轮关键升级就够了；当核心挑战是「逼近精度」（Flomo 洞察），需要逐轮消解深度不够的问题。**这和 Skill 案例里「每个模块 2-5 轮不够好」一样——精度从来不是一轮能解决的。

### 6.2 10 轮打磨的可能推进节奏（推测复原）

| 轮次区间 | 主要问题 | 打磨动作 |
|---|---|---|
| **第 1-3 轮** | 洞察太表面——像「作业总结」而非「深层洞察」 | 强化分析框架，要求 AI 追问到「为什么」和「背后矛盾」 |
| **第 4-6 轮** | 洞察深度上来了，但语气不对——像第三方机构 | 强化魂儿层输入（10 封信），要求 AI 模仿 Truman 的语气 |
| **第 7-8 轮** | 深度和语气都对了，但千人千面不够——对不同用户用类似的洞察模板 | 强化价值观层输入（金句），要求 AI 从一堂的独特视角看每个人 |
| **第 9-10 轮** | 核心质量达标，开始打磨特殊案例和边界情况 | 用极端案例测试（十几万字的深度作业、极短作业、非典型作业） |

### 6.3 两个标志性的打磨成果

```
张磊的作业洞察：
  → AI 能从一份作业中洞察出这个人自己可能都没意识到的关键矛盾

熙熙十几万字的作业洞察：
  → AI 能从海量文字中精准提取背后动机和内心追求
  → 不是「总结这十几万字说了什么」，而是「这十几万字背后是一个什么样的人」
```

### 6.4 「大概就能做到这个水平了」——什么时候算「够」

Truman 的判断标准不是「完美」，而是：

```
✅ 洞察深度：用户看完报告觉得「你真的看清了我」
✅ 个性化：不同用户的报告有明显差异，不是模板套用
✅ 魂儿对：报告的语气和温度是「一堂的」，不是「通用AI的」
✅ 可规模化：不是 Truman 手写，而是 AI 自动生成，覆盖 1-2 万人
```

## 八、三个关键输入 Input——Truman 明确列出的成功要素

在春马大课中，Truman 明确列出了三个关键信息输入：

## 九、双三角六条件在 Flomo 洞察 Agent 中的映射

这是和人生红点诊断 Agent **共享同一个底层模型**，但每个角的具体内容不同：

| 三角 | 六个角 | 在人生红点 Agent 中的体现 | 在 Flomo 洞察 Agent 中的体现 | 差异 |
|---|---|---|---|---|
| **人** | **审美** | 出口式咨询——引导式教练对话 | 顶级作业洞察的审美标准——「你真的看清了我」 | 场景不同，审美标准不同 |
| | **体系** | 人生红点理论体系 | Truman 对作业洞察的方法论体系：从行为看动机、从矛盾看成长 | 体系不同，但都是 Truman 的知识积累 |
| | **基本功** | 基础提示词工程 | 基础提示词工程 + Obsidian 知识库组织能力 | 基本功增加了知识库管理 |
| **AI** | **数据** | 人生红点核心理念 Datapack（单批萃取） | **三批分层数据**：10 份洞察报告 + 10 封信 + 价值观金句 | **Flomo 的数据策略更厚、更分层** |
| | **方法论** | Human3.0 + Mr.Ranedeer（外部神级提示词） | 龙虾官方配置最佳实践（外部最佳实践参照） | 外部参照不同，但都是找「神级参照」 |
| | **工具** | YAI + Coze | YAI + Obsidian + Trae | 工具链多了一个知识库平台 |

### 9.1 双三角优先级的变化

在两个案例中，双三角的核心驱动角发生了显著偏移：

```
人生红点诊断 Agent：
  核心驱动：审美（出口式咨询） + 方法论（两大神级提示词）
  数据相对较轻（一个 Datapack）

Flomo 洞察 Agent：
  核心驱动：数据（三批分层数据） + 体系（Truman 的洞察方法论）
  方法论相对较轻（一个外部最佳实践参照）
```

> 🔑 **L6 洞察**：双三角六个角缺一不可，但**不同场景下，核心驱动角是不同的**。人生红点是「方法论驱动」，Flomo 洞察是「数据驱动」。**识别自己场景的核心驱动角，是 L6 的战略判断力。**

## 十一、可迁移的 L6 原则清单

### 11.1 不要做的事

| 错误 | 为什么不行 | Truman 的正确替代 |
|---|---|---|
| 绕开双三角，写一个「心理洞察大师」提示词就上 | 「非常糟糕，完全没有任何神韵，就是一个很烂的 AI 分解」 | 双三角六个角缺一不可地系统做功 |
| 把人生红点教练的提示词「改一改」就用于作业洞察 | 场景不同，核心驱动不同——一个靠方法论，一个靠数据 | 从头建数据体系，重新设计顶层设计 |
| 只给 AI 一份「怎么分析作业」的指令 | AI 写的洞察像第三方机构——准确但不温暖 | 三批分层数据：操作层 + 魂儿层 + 价值观层 |
| 试图一次性把数据「写进提示词」 | 提示词臃肿，魂儿和知识混在一起不可维护 | Obsidian 知识库做结构化组织，顶层设计分配在 5-7 个文档 |
| 打磨 2-3 轮就发布 | 深度不够，千人千面不足，边界 case 没覆盖 | 大概 10 轮打磨——精度从来不是一轮能解决的 |
| 自己花时间把顶层设计「写」出来 | 写作的认知负荷占据大量时间 | 口喷 + AI 整理——保留思考判断，外包写作执行 |
| 只用一批数据（比如只给洞察报告） | AI 只会模仿操作层，没有魂儿和价值观 | 三批数据——操作层教会「怎么做」，魂儿层教会「怎么说话」，价值观层教会「怎么看」 |

### 11.2 一定要做的事

| 原则 | 具体动作 | L6 标识 |
|---|---|---|
| **数据分层设计** | 不只收集数据，而是把数据分成「操作层/魂儿层/价值观层」三批，每批有明确的战略角色 | 数据不是越多越好，是越有层次越好 |
| **顶层设计先行** | 在喂数据之前，先写 1000-3000 字的顶层设计——告诉 AI「你要成为谁」 | 没有顶层设计的数据 = 没有灵魂的素材 |
| **口喷 + AI 整理** | 人保留「思考判断」的高杠杆动作，把「写作执行」外包给 AI | 最高效率的人类-AI 协作模式 |
| **5-7 文档模块化** | 顶层设计拆成多个小文档——每个聚焦一个维度，可独立维护和复用 | 模块化 = 可维护 × 可复用 × 逻辑与数据分离 |
| **渐进式打磨** | 当核心挑战是「逼近精度」时，不做三步质变——做 10 轮渐进逼近 | 精度没有捷径，只有逐轮消解深度不够 |
| **极端案例测试** | 用十几万字的深度作业和极短作业做边界测试——不只是「正常案例能跑」 | 真正的千人千面必须覆盖极端用户 |
| **魂儿层数据不可省** | 10 封《致一堂同学的一封信》——AI 的温度和语气基因 | 大多数 AI 产品死在没有「魂儿」上 |
| **价值观层数据不可省** | 一堂的独特价值观和金句——AI 才能从表面行为深挖到内心动机 | 没有价值观的 AI 洞察 = 关键词提取 |

- 然而，到了下周开了一个新对话框，或者浏览器一刷新，AI 瞬间失忆，脑子空空如也！ 你必须把那套长篇大论的背景要求、格式规范，重新复制、粘贴、再念叨一遍。

上面的痛苦，本质上是因为你一直在用随性聊天的姿势，去要求工业级的交付。

一旦封装成技能包，以后无论换什么产品、新开什么对话，你只要把原材料丢进去，它就会一秒进入角色、严格按你的规矩交出标准成品，彻底告别盲目抽卡，把经验真正沉淀为能天天为你赚钱的数字资产！
AI 已经从单纯动嘴皮子的聊天问答时代，真正迈入了能撸起袖子进业务流干活的 Agent（智能体）时代。
我们开这个营，就是为了帮你彻底告别抽卡，学会建立属于你自己的标准交付体系。
### 三）大模型、智能体（Agent）和技能（Skill）到底是什么？
我们用一家数字公司招人上岗的场景类比一下，你马上就能懂：
大模型（LLM）= 刚毕业的名校高材生：博览群书，脑子特别聪明，上知天文下通地理，但他不知道你公司的规矩、客户的喜好，随口问他一句，他能跟你洋洋洒洒扯三千字空话，但落不了地。
智能体（Agent）= 给高材生配齐“独立工位、电脑与工具”：光有大脑只能动嘴。现在你给他配了电脑、计算器、联网权限和办公软件账号，让他拥有了动手操作的能力——这就是 Agent，一个有手有脚、能真正执行动作的数字员工。
技能（Skill）= 你塞进他工卡里的岗位标准工作手册（SOP）：高材生有了电脑，如果没规矩依然会乱搞。Skill 就是你多年工作经验的结晶：第一步看什么材料；第二步遵守什么规则、严禁踩什么红线；第三步按照什么固定格式排版；附上两篇满分范文："照着这个标准交差"。
写提示词，是你天天陪着 AI 聊天、伺候它；封装 Skill，是你立好规矩，让 AI 变成自动为你打工的流水线。

> 🥇 小贴士：关于 Skill 和 Skills，别被多出来的一个“s”搞懵了！
> 可能有细心的小伙伴会好奇：“怎么咱们营名字叫 Agent Skills（带个 s），正文里又老说封装一个 Skill（不带 s）？到底有啥区别？”
> 大家千万别有心理压力，解释一下：
> Skill（单数）= 单个技能、一个绝活。
> 比如你做好的“小红书爆款写作 Skill”、“PPT 制作 Skill”，单拎出来一个具体技能，就叫 Skill。
> Skills（复数）= 多个技能、一整套技能库。
> 英文里多个东西后面习惯加个“s”。我们这 21 天要学会封装自媒体、办公等好几个技能，甚至在第三阶段还要让多个技能协同作战，所以营名叫 Agent Skills 锤炼营，代表你要学到的是一身武艺和一整套技能武器库！
> 平时在群里交流或者在官网写打卡时，大家无论说 Skill、Skills，还是直接叫它技能包、AI技能，教练全都能听懂！完全不用纠结英文语法，怎么顺嘴怎么来！

#### 5、专家团、专家与技能到底是什么关系？
我们重点说说「专家·技能·连接器」这个板块。

![](02-解放思想/70%20案例库/AI破局12期-AgentSkills锤炼营实战手册/imgs/img_013.png)

很多人都会被这几个词搞晕，分不清它们到底谁管谁，有什么关系。
其实在 WorkBuddy 官方的底层设计里，它们是一套非常清晰的现代化公司组织架构：

![](02-解放思想/70%20案例库/AI破局12期-AgentSkills锤炼营实战手册/imgs/img_014.png)

一个专家团可以按需动态调度多个不同领域的专家；而单个专家就像一位全能员工，随身可以装备并调用多个不同的专属 Skill 技能包！
技能（Skill）
最底层的看家绝活与操作手册。核心是以 SKILL.md 命名的标准文本，定义具体单点任务的标准流程和执行规范。
专家（Expert）
以人设、方法论与工具链武装起来的领域专家角色。专家的人设是外壳，背后调用的 Skills 是它的方法论核心。例如：你给它设定了“10年资深公关总监”的人设，并给它挂载了公关稿写作的技能（Skill），再赋予它读写文件的工具，它在 WorkBuddy 里就正式成了一名合格的“公关专家”。
没有 Skills 的专家只是个空架子，有了专属 Skills，专家才真正拥有了灵魂与生产力！
专家团（Expert Team）
多专家分工协同机制。
由一位“团长”自动将用户的复杂总任务进行模块化拆解，分发给不同的专家并行执行，最后交出综合成果。
现实中，你很少能靠一个人把一整套业务做完。比如要做一场商业发布会，文案专家写稿、设计专家做图、排版专家做 PPT。专家团就是把这些装了不同技能的专家拉到一起工作，各司其职。
#### 6、终极破局：为什么要自己学封装？
很多人打开官方技能市场，看到有现成的 PPT 技能、写作技能，心里会想：“官方都帮我做好了，我直接点开用不香吗？何必还要费劲学封装？”
这是绝大多数普通玩家和高手的本质区别所在：
官方技能是通用标准款，无法适配你的独门暗器：官方的文案技能可以写出 70 分的标准文章，但他绝对写不出你个人 IP 独有的口吻、金句风格；官方的 PPT 技能能列出普通大纲，但他不知道你向公司老板汇报时特定的排版忌讳和审核重点。
真正的商业壁垒，是你自己的私有工作流：工具每年都在变，平台一直在更新。但如果你能把自己日常带团队、做自媒体、做业务的这套核心打法，提炼成符合技术规范的技能包：你不仅可以在 WorkBuddy 里喂给你的专属专家；未来就算迁移到其他任何支持技能标准的 Agent 系统上，它依然是你随时能调用的无形资产！
从消费者变成造物主：学会技能封装，可以不止在技能市场里淘别人用过的模版，还能亲手封装出自己专属的技能包，甚至未来可以把它上架分发、提供专业交付服务！

> 🎉 导航栏里的“连接器”又是个啥？
> 细心的同学会看到，WorkBuddy 导航栏写的是「专家·技能·连接器」。那这个连接器跟技能有啥关系？
> - 一句话解释：连接器就像是一根根外接数据线 / 水管。
> - 它的作用是帮 WorkBuddy 连接外部的其他软件（比如企业微信、飞书、钉钉、外部网页等），让 AI 能够给你的企业微信发消息、或者读取外部数据。
> - 划重点：连接器根本不是技能本身！
> - Skill（技能） 是装在大脑里的 业务工作手册与方法论（决定活干得好不好、稳不稳）；
> - 连接器 只是对外沟通的 硬件插头与电话线。
> 本次营期的核心是修炼内功（Skills），你不需要去折腾任何复杂的连接器配置，把这三个字直接略过即可，宝贵的精力用来打造高价值的技能包！

## 三、Skill 的核心概念
### 一）消除恐惧：写 Skill 到底是不是在写代码？
写 Skill 绝不是写代码。
它就是你作为一个老主管，在给新员工写一份岗位作业指导书（SOP）。
包括：角色定义、核心任务、禁忌红线、执行步骤与交付样本。
把这套话按照固定格式分段记录下来，保存为文本文件，就是一个标准的 SKILL.md 技能包。
### 二）技能包全景：从全能武装包到极简单文件
在正式拆开看具体文件之前，我们需要先在脑海里建立一个清晰的物理形态认知：在电脑里，一个 Skill 技能包到底是一个文件，还是一个文件夹？
用职场入职的生活化场景来打比方，一个技能包其实有豪华工位和随身工卡两种形态：
#### 1、全能武装型技能包（完整技能文件夹）
面对极其复杂的专业任务，一个完整的技能包本质上是一个文件夹，就像给员工配齐了全套专业装备的独立工位：
- 核心大脑与总指挥（SKILL.md）：这是技能包里唯一必须存在、不可或缺的核心文件。负责规定角色人设、业务流程 SOP、红线禁忌和交付标准。
- 辅助工具箱（scripts/ 目录）：存放编写好的现成代码脚本（比如自动批量清洗 Excel、从网页爬取数据工具等），可选。
- 参考知识库（references/ 目录）：存放背景知识词典、专业术语手册、品牌调性库等长文资料，可选。
- 模板素材库（assets/ 目录）：存放固定的图片、报告模版、Icon 资源等成品组件，可选。
#### 2、极简型技能包（单文件技能文件夹）
敲黑板，重点来了！
既然有那么多可选目录，是不是每个技能都要搞得这么复杂？
完全不是！
如果一个文件夹里只有一份孤零零的 SKILL.md，没有任何辅助脚本，也没有附加素材，它同样是一个完整、有效、即插即用的标准技能包！
这种形态，我们称之为单文件型技能。
大模型本身已经博览群书，具备了极强的文字理解与生成底座。在日常办公、自媒体写作、文案润色、会议纪要整理、报告提炼等 80%~90% 的常见场景下，根本不需要任何代码脚本、外部附件，单凭一份逻辑严密的 SKILL.md，就足够强大，可以稳定交付超高水准的成果！
在咱们《Agent Skills 锤炼营》的前中期，大家完全不用把精力浪费在复杂的工程结构上。
你只要学会看懂这一张最核心的 SKILL.md，你就已经掌握了技能封装 80% 的真功夫！
既然 SKILL.md 是整个技能包的“定海神针”，那它自身到底长什么样？我们接着往下看。
#### 3、极简解剖：一个标准 Skill 的“五脏六腑”
一个能稳定输出、不发疯、不胡说八道的优质技能文件，拆开来看，至少包含以下 5 个核心构件：
1、技能名片（你是谁、你什么时候该出场） 2、核心角色与语气（你的专业身份与沟通口吻） 3、目标与红线禁忌（你要干成什么、绝对不能碰什么）4、标准执行工序 SOP（第一步、第二步、第三步怎么干）
5、交付样式与参考样板（交差时的格式长相，附带优秀示范）
我们把这 5 个构件挨个掰开来看：
##### 3.1、技能名片
告诉 WorkBuddy 这个技能叫什么名字、用一句话介绍它擅长干什么。
为什么重要：就像工具箱里的标签纸。WorkBuddy 看到用户的需求是写文案，扫一眼标签纸，就知道该把这个技能抽出来了。
##### 3.2、角色与语气
让大模型立刻切换大脑里的思维频道。
反面教材：“帮我写文案。”（AI 会用百度百科式的语气糊弄你）
正面技能：“你是一位拥有 5 年经验的资深小红书爆款操盘手，精通下沉市场心理学，擅长用闺蜜唠嗑般的热情口吻说话，说话多用短句，自带网感。”
##### 3.3、目标与红线禁忌
就像去餐馆点菜，不仅要告诉厨师“做一盘回锅肉”，更要交代一下“微辣、少盐、不要放香菜！”后半句往往比前半句更关键。
正面边界示例：把用户丢进来的 2000 字专业文章，浓缩成一篇 300~500 字的小红书文案。
负面禁忌示例：❌ 严禁出现“众所周知、总而言之、综上所述”等浓厚 AI 味的套话；❌ 严禁出现广告法违禁词（如：第一、最强、顶级）；❌ 严禁大段不换行，单段文字不得超过 3 行。
❌ 严禁出现“众所周知、总而言之、综上所述”等浓厚 AI 味的套话；
❌ 严禁出现广告法违禁词（如：第一、最强、顶级）；
❌ 严禁大段不换行，单段文字不得超过 3 行。
##### 3.4、执行工序 SOP
新手厨师炒菜容易糊，是因为他不知道先热油还是先下葱花。
AI 也是一样，如果你只给它结果，它就会自己脑补，容易走偏。
优秀的技能会给 AI 规划清晰的步骤：
第一步【拆解材料】：提炼出原材料中最能引发情绪共鸣的 3 个痛点；
第二步【拟定标题】：利用“悬念法 + 数字法”输出 3 个高点击率候选标题；
第三步【撰写正文】：按“痛点共情->解决方案->互动提问”的三段式结构展开；
第四步【润色标签】：在结尾附上 5 个垂直话题标签（TAG）。
##### 3.5、交付样板
这个部分是让AI学着照猫画虎，就像去理发店剪头，你跟托尼老师磨破嘴皮子说“要自然一点、两侧推上去一点”，不如直接掏出手机给他看一张某明星造型的照片说：“就按这个剪！”
在 Skill 的末尾，直接放一段你平时觉得最满意、最符合标准的爆款范文。AI 的模仿学习能力是极其变态的，有了样本，它输出的稳定度马上提升！
#### 4、一个标准 SKILL.md 文件示例
下面就是一个完整的技能文件示例。
name部分就是它的技能名字，description是对它擅长干什么的介绍。
这两个部分用英文命名，属于技术规范要求，不同的Agent遵循同一套规范，可以保证技能在不同的Agent上都能被识别和调用。

```
---
name: redbook-copywriter
description: 将专业长文或粗糙笔记，一键转化为高互动率的小红书爆款图文文案
---
# 角色定位
你是一名有5年操盘经验的小红书爆款文案专家。你的语言风格像热心闺蜜在茶水间分享经验，真诚、接地气、充满活力，善于捕捉读者情绪。
# 核心任务
将用户提供的原始素材，改写为符合小红书平台传播规律的优质笔记。
# 严守红线（禁忌）
1. 绝对不要使用“首先、其次、总而言之”等说教公文词汇。
2. 单段文字严禁超过3行，必须多空行排版。
3. 严禁堆砌无意义的形容词，多用具体数字和真实场景支撑。
# 执行步骤（SOP）
1. 提炼洞察：通读用户输入的材料，找出最容易引发读者共鸣的痛点。
2. 拟定爆款标题：生成3个不同风格的标题（痛点型、反常识型、数字总结型），供用户挑选。
3. 正文创作：
   - 黄金前三秒：前两句话必须直戳痛点或抛出反常识结论；
   - 干货拆解：用短句、列表罗列核心解法，自然插入5~8个常用emoji；
   - 结尾钩子：用一句真诚的话引导评论区互动。
4. 话题推荐：在文末生成5个精准匹配的热门小红书标签。
# 输出格式与优质范例（参考样板）
请严格按照以下结构输出交付结果：
【候选标题】
1. 标题1...
2. 标题2...
3. 标题3...
【笔记正文】
（正文内容，段落分明，带表情）
【推荐标签】
#标签1 #标签2 #标签3
```

全篇没有任何一行复杂的代码！全是人话！
#### 5、为什么 Skill 必须用结构化格式写？
有些学员可能会问：“既然都是人话，我直接写在 Word 里或者写个长文本不行吗？为什么要叫 .md，为什么里面要加 # 号和 - 列表？”
这里藏着一个极关键的秘密：大模型是天生的视觉与结构动物。
如果你给 AI 丢一整段密密麻麻、没有标点、挤在一起的 1000 字长文本，它的注意力机制会发生“注意力迷失”，看着看着就把前面的规矩忘了。
Markdown 是给文字做骨架支撑：一个 # 号代表一级大标题（相当于跟 AI 喊：“看这里，这是大方向！”）；两个 ## 号代表二级小标题（“这是具体执行项”）；一个 - 号或数字代表清单列表（“这是第1步、第2步，必须一步步做”）。
一个 # 号代表一级大标题（相当于跟 AI 喊：“看这里，这是大方向！”）；
两个 ## 号代表二级小标题（“这是具体执行项”）；
一个 - 号或数字代表清单列表（“这是第1步、第2步，必须一步步做”）。
这种结构化，能给大模型的大脑划出一条极其清晰的高速公路。它顺着路标往前跑，想翻车都难！
而且Markdown文件是纯文本格式，不会被任何工具绑定和锁死，Agent不需要额外安装任何适配工具都能读。
学到这里，恭喜你！在认知层面上，你已经彻底打通了任督二脉：
你懂了为什么不能当抽卡赌徒；
你装好了专属的工作台 WorkBuddy；
你知道了官方专家团和 Skills 的从属关系；
你亲眼看穿了一个标准 Skill 的内部结构。
为后续学习做准备，你可以尝试写一下属于你自己的微型技能草稿（哪怕只有 100 字）：
1.你打算做个什么技能？（比如：客户回访感谢信助手）
2.给它定一条最严格的禁忌红线是什么？（比如：严禁推销产品，语气必须真诚）
3.分哪几步走？
写完别扔，保留好它，这或许是你蜕变的第一颗种子！

### 一）代写业务的三个"崩溃瞬间"
开头我们讲过两个崩溃瞬间：结果不稳定的"抽卡赌徒"，和经验不复用的"全职保姆"。
做代写交付的同学，这两个瞬间你不但全有，还会多一个——原材料不稳定。
崩溃瞬间一：资料靠追。
写标书的时候，招标文件里的技术参数、业绩证明材料、实施案例，客户东一封邮件西一条微信发过来；做数据分析报告时，客户一句"数据我回头发你"拖三天。有时候，你赌气想"算了我自己看着写"，写完交上去，客户一句"我要的不是这个"打回来。返工三轮，工时全部沉没。
崩溃瞬间二：格式靠记。
投标文件有固定的章节目录和评分点对应要求，商业计划书客户有投资人偏好的版本结构，数据报告要按客户往期报告的口径来写。你每开一个新单，都要把这套规矩在脑子里重新过一遍，漏一条就是一个修改意见，标书漏一条甚至可能直接废标。
崩溃瞬间三：质量靠状态。
状态好的时候能写出 90 分，赶工的时候 60 分都勉强。你的收入上限，被你当天的精力状态焊死了。
三个瞬间的病根在同一个：用随性聊天的方式，干工业级交付的活。
整个行动营要学的封装思路，就是解药。

### 四）找缺口：拿它直接干代写，会卡在哪？
敲黑板，重点来了。
这个技能作为"通用报告助手"已经合格，但你拿它接单，会发现它有 四个缺口。
每个缺口，就是你要补的功课，也是你和其他代写选手拉开差距的地方。
缺口一：没有"原料清单"——它没写客户必须提供什么
翻遍这个技能，找不到"用户需要提供哪些资料"的要求。
后果是什么？资料不够时，AI 会礼貌地编。 编数据对代写业务是灭顶之灾。
补法：给 SOP 加一个"第 0 步：核对原料"。
把你业务里"没有它就写不了"的东西列成固定清单，写死在技能里。
交付类业务一般至少要五样：
1.客户是谁、这份东西给谁看（评标专家？投资人？老板？内部团队？）
2.原始材料（数据截图、Excel、公司资质和业绩、访谈记录，越糙越好，AI 负责洗）
3.格式依据（标书就是招标文件和评分标准，计划书就是客户指定的版本结构，报告就是往期成稿）
4.一份客户认可的参考范文（如果有）
5.禁忌和特殊要求（不许提竞品、必须突出某产品、严禁改动法定条款之类）
清单里缺任何一项，先向客户要，不开工。
这一步能把"崩溃瞬间一"直接消灭——你不再想到什么问什么，而是顺着清单查，还能增加专业感。
缺口二：没有"格式固化"——客户有固定模板时怎么办
它的输出规范是自己的三段式，但真实客户经常甩一份自己的模板过来：标书要严格对齐招标文件的章节目录和评分点，商业计划书按客户指定的版本结构写，数据报告沿用客户往期报告的口径。字段、口径全是定死的。
补法：两条路，按复杂程度选。
- 简单场景：把客户模板的结构直接写死在 SKILL.md 的"输出格式"部分（就像前面那个小红书文案示例那样，把【候选标题】【笔记正文】【推荐标签】写进规定里）。
- 复杂场景：用上"全能武装型技能包"——把客户的 Word 模板、招标文件格式要求、往期成稿放进技能文件夹的 assets/ 目录（模板素材库），让 AI 每次照着模板填。模板一换，只换文件，不用重写技能。
缺口三：没有"写作工序"——只有能力清单，没有先后步骤
注意看它的"四大核心能力"：那是能力，不是工序。就像厨师菜谱上写"会颠勺、会控火"，但没写先放油还是先放葱。AI 收到复杂任务时容易想到哪写到哪。
补法：给报告交付定一条五步工序（你可以按自己的业务改）：
1.核原料：对照清单，缺什么先要什么
2.定大纲：只输出大纲给客户确认，确认了再动笔（消灭大返工的关键一步）
3.分块填充：按大纲逐块写，每块的数据都能对应到客户给的原料
4.按模板排版：对齐客户模板的格式和口径
5.自检交付：数据有出处、格式对齐、没有 AI 味（可以给出更具体的要求标准）
缺口四：没有"交付样板"——放一份你拿过好评的成稿进去
前面提到托尼老师的例子：与其描述"自然一点"，不如直接掏出照片说"照这个剪"。
补法：把你历史上客户最满意的一份成稿（脱敏后）放进技能当参考样板。AI 的模仿能力极强，有样板，输出稳定度立刻上一个台阶。

### 二）Skill 到底解决什么问题？
这一节不是带着大家写爬虫，而是把雪见提供的 Python 脚本变成 Workbuddy 可以稳定调用的能力。
单独一个 .py 文件当然能跑，但它只解决“我手动怎么运行”。
下一次换一个任务、换一个目录、换一个链接，Workbuddy 还需要知道什么时候该调用它、参数怎么传、结果保存到哪里、最后怎么回复用户。
Skill 解决的是“把一次性脚本变成稳定能力”。
它至少包含两部分：
一份 SKILL.md，告诉 Workbuddy 什么时候触发、按什么流程处理、遇到问题怎么回复；
一份或多份脚本，真正负责采集、解析、保存数据。
所以这节课的关键，不是展示一个复杂爬虫怎么写，而是让大家理解一件事：脚本负责采集，Skill 负责把采集流程标准化。
我们把规则写清楚，Workbuddy 下次看到同类任务时就能自动接上。

### 九）把素材升级成小红书创作知识库
到这一步，我们已经有了素材，但还不能说真正有了知识库。
note.json 和 notes.jsonl 只是原始数据和数据索引。
它们适合机器读取，但不适合长期沉淀经验。
如果每次创作都让 Workbuddy 重新读一堆 JSON、重新总结标题套路、重新判断正文结构，那它每次都在“从零理解”。
这一节要引入的是 llm-wiki.md 的思路，并把它改造成适合本项目的 xhs-llm-wiki.md：
不要只把资料丢给 AI 临时问答，而是让 Workbuddy 把资料持续整理成一个会积累、会更新、会被反复读取的 Markdown Wiki。
可以参考 Karpathy 的 LLM Wiki 参考文件，但课堂里不要照搬原文，要改成适合小红书创作知识库的版本。
llm-wiki.md

```
# LLM Wiki
A pattern for building personal knowledge bases using LLMs.
This is an idea file, it is designed to be copy pasted to your own LLM Agent (e.g. OpenAI Codex, Claude Code, OpenCode / Pi, or etc.). Its goal is to communicate the high level idea, but your agent will build out the specifics in collaboration with you.
## The core idea
Most people's experience with LLMs and documents looks like RAG: you upload a collection of files, the LLM retrieves relevant chunks at query time, and generates an answer. This works, but the LLM is rediscovering knowledge from scratch on every question. There's no accumulation. Ask a subtle question that requires synthesizing five documents, and the LLM has to find and piece together the relevant fragments every time. Nothing is built up. NotebookLM, ChatGPT file uploads, and most RAG systems work this way.
The idea here is different. Instead of just retrieving from raw documents at query time, the LLM **incrementally builds and maintains a persistent wiki** — a structured, interlinked collection of markdown files that sits between you and the raw sources. When you add a new source, the LLM doesn't just index it for later retrieval. It reads it, extracts the key information, and integrates it into the existing wiki — updating entity pages, revising topic summaries, noting where new data contradicts old claims, strengthening or challenging the evolving synthesis. The knowledge is compiled once and then *kept current*, not re-derived on every query.
```

我们可以把 Karpathy 的原始参考保存为 llm-wiki.md，让 Workbuddy 先理解它的核心思想：原始资料只读、Wiki 持续维护、规则文件负责约束维护方式。
但不要把原始参考文件直接当成最终规则书。
它是通用方法论，里面包含很多不属于本课程的例子和工具名；
真正要给这个项目长期使用的，是我们根据小红书创作场景改出来的 xhs-llm-wiki.md。
这里可以简单理解成五个部分：

```
assets/xhs_notes/  原始资料层：每条笔记的 note.json、图片、视频和原始字段
notes.jsonl        数据索引层：所有笔记的统一结构化记录，方便批量读取
llm-wiki.md        通用参考层：用来理解 LLM Wiki 的方法论，不直接照搬
xhs-llm-wiki.md    维护规范层：告诉 Workbuddy 这个知识库怎么更新、怎么引用、怎么回答
wiki/              知识沉淀层：来源页、主题页、套路页、综合页和日志页
```

assets 负责保留事实，notes.jsonl 负责统一索引，llm-wiki.md 负责提供通用方法参考，xhs-llm-wiki.md 负责规定小红书创作知识库的维护方式，wiki 才是真正给人和 Workbuddy 反复阅读、反复使用的知识层。
先让 Workbuddy 阅读通用参考 llm-wiki.md，再基于小红书创作场景写出一份项目自己的 xhs-llm-wiki.md，最后按照这份场景化规范去生成和维护 wiki/。
推荐的项目结构如下：

```

  SKILL.md
  scripts/
    fetch_xhs_note.py
  llm-wiki.md              # LLM Wiki 通用参考文件
  xhs-llm-wiki.md          # 小红书创作知识库维护规范
  notes.jsonl
  assets/
    xhs_notes/
      <note_id>/
        note.json
        images/
        videos/
  wiki/
    index.md
    synthesis.md
    log.md

    topics/
    patterns/
```

这里的关键不是目录看起来丰富，而是每个文件都有分工：
- xhs-llm-wiki.md：写清楚知识库的目标、目录约定、更新规则、回答问题时的读取顺序、不能编造的边界。
- wiki/index.md：做导航，告诉 Workbuddy 当前有哪些来源页、主题页、套路页。
- wiki/sources/：每条小红书笔记一个拆解页，保留标题、作者、互动数据、正文结构、情绪关键词、可复用角度。
- wiki/topics/：按主题聚合，比如女性成长、独处疗愈、情绪文案、显化好运。
- wiki/patterns/：沉淀可复用写法，比如标题套路、开头钩子、正文结构、评论区需求、标签组合。
- wiki/synthesis.md：跨笔记总结，记录这批素材整体有什么共性、哪些规律值得复用。
- wiki/log.md：记录每次新增素材、更新 Wiki、生成选题、做知识库体检的时间线。
后续问选题、标题、正文结构时，Workbuddy 应该先读 xhs-llm-wiki.md，再读 wiki/index.md 和相关 Wiki 页面，而不是每次都直接从 notes.jsonl 里临时拼答案。

### 十四）常见问题
为什么我的小红书笔记链接采集报错？
请参考我这个图片里面怎么复制笔记链接的

![](02-解放思想/70%20案例库/AI破局12期-AgentSkills锤炼营实战手册/imgs/img_084.png)

为什么直接打开链接能看，脚本却抓不到？
小红书页面会根据登录态、访问环境、页面结构返回不同内容。脚本抓不到时，先确认笔记是否公开，再检查页面里是否还能找到 window.__INITIAL_STATE__。
为什么一定要保留完整链接？
很多小红书分享链接里带有 xsec_token。它不一定每次都必须，但缺了以后更容易抓不到数据。大家跟做时，尽量复制完整分享链接。
为什么不用一上来就做复杂知识库？
因为要先跑通最短闭环：一条链接 -> 一份 JSON -> 一次成功反馈。闭环跑通以后，再加媒体下载、JSONL、Wiki 和创作工作流，这样更容易理解。
为什么要做 Wiki，而不是只留 JSON？
JSON 适合机器读取，但不适合人直接创作。Wiki 会把零散素材整理成主题页、来源页和综合分析页，让 Workbuddy 后续能更快找到规律，而不是每次都重新读原始数据。
会不会抄袭原笔记？
采集素材是为了分析结构、主题、语气和表达规律，不是为了搬运原文。让 Workbuddy 生成新笔记时，要明确要求“不照抄、不复述原文，只借鉴结构和创作规律”。

## 三、用Skill来制作PPT @老张
### 一）开始之前：这份指南怎么用
这份指南教大家用「Skill」自动创作 PPT：先学会用现成的 Skill 快速生成一份 PPT，再手把手打造一个属于自己的 PPT Skill。学完后，你只要把会议纪要、资料链接丢给 AI，一句话就能得到一份风格统一的 PPT。
#### 1、适合谁
零基础学员即可。不需要会编程，也不需要背提示词；全程在 Trae（免费 AI 编程工具）里用中文对话完成。
#### 2、怎么学
1.先花 3 分钟读「认识 PPT Skill」，明白它是什么、为什么好用；
2.走「路径 A」装一个现成 Skill，先做出第一份 PPT 建立信心（约 10 分钟）；
3.再走「路径 B」从 0 到 1 打造你自己的 Skill（约 1～2 小时）；
4.最后用「练习与验收」自检，确保真的学会了。
两种路径的关系：大多数 Skill 的逻辑都是相通的，学会一种就能举一反三。AI 时代，我们需要的不是背教程，而是学会提问——让 AI 帮你寻找需要的功能模块。
### 二）认识 PPT Skill
#### 1、什么是 PPT Skill：给 AI 的「PPT 使用说明书」
PPT Skill 就是一份「使用说明书」——专门教 AI 怎么按照你的喜好做 PPT 的说明书。就像每个人都有穿衣风格，你做 PPT 也有自己的「惯性」：
- 有人习惯先扔结论（「增长了 30%」），有人喜欢先讲背景（「市场情况是这样的…」）
- 有人偏爱深蓝商务风，有人喜欢极简黑白
把这份「惯性」写进 Skill 后，AI 每次都会按你的偏好来做 PPT，不用反复交代。
#### 2、为什么用 Skill 而不是单次对话
- 版式一致：单次对话中 AI 会「失忆」，每次生成的版式、配色、字体都不一致；Skill 通过 SKILL.md 固化设计规范，确保风格统一。
- 多级处理：先分析内容结构，再生成具体页面，避免长文档超出上下文限制。
- 资产复利：你调教好的视觉规范、内容组件、逻辑框架会永久固化在 Skill 里，一次创建、长期复用，还能变成「标准化 PPT 服务」教给别人甚至变现。
#### 3、PPT Skill 的核心逻辑
输入（文本/链接/数据）→ Skill 解析 → 内容结构化 → 视觉设计 → 输出 PPTX
一句话：Skill 把「不可控的 AI」包在「可控的流程」里——AI 负责创意与规划，程序负责稳定交付。
### 三）学习路径总览
两条路，按你的情况选：
- 路径 A（新手必做）：安装官方现成 Skill → 生成第一份 PPT → 学会拆解学习。约 10 分钟，先建立手感。
- 路径 B（主线）：从 0 到 1 打造自己的 PPT Skill，按「定方向 → 搭骨架 → 做模块 → 穿衣服 → 存为 Skill」五步走。约 1～2 小时。
### 四）PPT Skill 的三条路线与选型
在开始打造自己的 Skill 之前，先带你看看市面上成熟项目的世界。你会惊讶地发现：这些 PPT Skill 看起来都在「做 PPT」，其实产出的是三种完全不同的东西——可编辑的 .pptx、HTML 网页、整页图片。选对路线，比选对星数重要得多。
判断标准很简单：你最后要落到什么文件上？要交可改的 PowerPoint 文件，就走路线一；要上台演讲投屏，就走路线二；要传播物料、视觉惊艳，就走路线三。
#### 1、路线一：可编辑 .pptx ——「领导还要改三版」的保命路线
产出真正的 PowerPoint 文件，双击打开，每个文本框、每张图表都能改，图表是原生对象、数据能双击进去改。代表项目：
- ppt-master（44.3K 星，品类天花板）：把文档/主题转成原生 PowerPoint，图表表格公式都可编辑，能自动生成语音旁白，可导入公司自有模板；对论文答辩等学术场景结构处理扎实。短板是视觉上限一般。
- GordenPPTSkill（2.9K 星，中文职场最对症）：内置 17 套人工打磨的中文职场模板（国企风、大厂风、商业提案风），会主动提炼长段落、检查文字溢出。注意模板限制商业使用，交付客户前先看授权。
- Dashi PPT Skill（4.9K 星）：「网页里改」的折中派——网页端生成，每页带编辑控制台，浏览器里点着改，改完一键导出可编辑 PPTX；12 套主题、1020 个版式，版式库最大。
- Anthropic 官方 pptx skill（在 anthropics/skills 仓库）：新建、编辑、套模板都稳，没有招牌风格但不会翻车，官方长期维护，可当保底。
- MiniMax pptx-generator：走工程路线，用 PptxGenJS 实现，能读你现有的 PPT 接着改。
#### 2、路线二：HTML 网页演示 ——「上台演讲」的降维打击
浏览器全屏打开、键盘翻页、带动画，演讲现场投出来的效果比 PowerPoint 好看一截；但它不是一个 PPT 文件。代表项目：
- frontend-slides（27.2K 星）：最聪明的设计在流程——先吐 3 个不同风格的预览让你挑，挑完再生成整套，34 套设计系统；还能把旧的 PowerPoint 转成网页版，支持 PDF 导出、一键部署发链接。
- guizang-ppt-skill（23.7K 星，归藏出品）：单文件 HTML 横向翻页，内置两套视觉系统（电子杂志 × 电子墨水 / 瑞士国际主义），出品像「被设计过」；演讲者模式、键盘翻页、触屏、封面渲染成传播物料都做了。短板：单文件多人改稿不便，AGPL-3.0 协议。
- HTML PPT Studio（7.9K 星）与 Open Slide（6.5K 星）：前者是工具箱（几十套主题、动画、演讲者窗口、计时器、逐字稿），后者把一套幻灯片当长期项目（评论、修改、备注、发布在一个界面），适合技术分享和持续迭代的课程。
#### 3、路线三：整页图片 ——「每一页都是海报」的视觉暴力
每一页让图片模型直接画成一张完整视觉稿，文字、插画、构图全烧死在图里，最后拼成 PPTX/PDF。视觉冲击力最强，但页内元素基本不可编辑。代表项目：
- baoyu-skills 的 Slide Deck（合集 2.5 万星，中文圈传播最广）：先分析内容和受众，定大纲、页数、风格，再逐页生成完整图片，最后合成 PPTX/PDF。小红书上「每一页都值得截图」的 PPT 多出自这条路线。
- banana-slides（15.4K 星）：基于 Google Gemini 的完整应用，图片模型能「准确渲染你要求的全部文字」；一句话生成、粘贴大纲、逐页描述三条路径随便挑，改稿用嘴说——「把第三页标题换成红色」直接生效，Docker 一条命令部署。
- codex-ppt-skill（4.9K 星）与 gpt-image2-ppt-skills（1.2K 星）：图片模型直接负责视觉，逐页生成再拼成 PPTX；后者有 265 套模板画廊、能模仿你的品牌模板，带单页重生成和版本回滚。
一句话总结这条路线：概念稿、路演、个人分享随便用；密集数据的汇报，慎重。

```
## 1) 这个 Skill 由哪些部分组成
在你项目里，它只有两类资产：
- 规则文档（给 AI 看的流程规范）：SKILL.md
- 执行脚本（给电脑跑的确定性程序）：generate.py
你可以把它理解为：
- SKILL.md = "操作手册 + 质量要求 + 交付格式（契约）"
- scripts/generate.py = "最后一步把图片装进 PPTX 的打包机"
## 2) 核心设计思路：把任务拆成流水线（Pipeline）
### 阶段 A：先做"计划"（Plan）
在 SKILL.md 里要求先生成一个 presentation-plan.json，里面包含：
- 标题、页数、每页类型/标题/要点
- 最关键：style + style_guidelines（颜色、字体、构图、视觉语言）
- aspect_ratio（16:9 / 4:3）
这一步的作用是：把"用户一句话"变成"可执行规格书"。没有规格书，后面就会漂。
### 阶段 B：逐页生成"图片"（Slide Images）
Skill 强制要求"按顺序一页一页生成"，而且第 N 页要拿第 N-1 页做参考（reference image）。
这其实是在解决一个真实难题：AI 生成图片很容易每页风格飘。用上一页做参考，相当于"锁定视觉风格"，保证整套 PPT 统一。
### 阶段 C：把图片"组装成 PPTX"（Compose）
最后调用 scripts/generate.py，把所有 slide 图片铺到 PPT 页面上，并把 plan 里的标题/要点写进 speaker notes（演讲者备注）。
这条主线：读取 plan JSON → 根据 aspect_ratio 设置页面尺寸 → 每张图片等比缩放 + 居中裁切铺满 → 可选：把 title/subtitle/key_points 写入 notes。
这一步的设计特点是：确定性强、可重复、可 debug。AI 负责"创意与规划"，程序负责"稳定交付"。
## 3) 为什么这种 Skill 设计适合 AI 小白
因为它满足 3 个"新手友好"的原则：
- 输出物明确：plan.json、slide-01.jpg...、presentation.pptx（每一步都有"看得见的产物"）
- 接口清晰：上一步的输出就是下一步的输入（文件就是接口）
- 失败好定位：坏在哪一阶段一眼能看出（计划坏 / 图片坏 / 组装坏）
这比"一句提示词直接要 PPTX"可靠太多。
## 4) 你应该如何学习这种 Skill 设计（最短路径）
### 第 1 关：学会用"契约思维"写 Skill
```

#### 1、SKill创作的五步流程
这五步是整个 PPT Skill 的设计骨架：

> 【嵌入电子表格】

| 步骤 | 关键动作 | 为什么重要 |
| --- | --- | --- |
| 第1步：先定方向 | 需求锚定，确认要解决什么问题 | 很多PPT失败不是因为丑，而是第一页就跑偏 |
| 第2步：再搭骨架 | 像导演写分镜一样规划页面清单 | 这时改结构只需改表格一行字，比做完20页再删轻松100倍 |

| 第5步：固化资产 | 将规范写入SKILL.md | 培养一个永远在线的PPT助理 |

#### 2、五步流程详细介绍
1.（第 1 步） 定方向 —— 写需求卡片：
确保你在解决正确的问题。很多 PPT 失败不是因为丑，而是因为第一页就跑偏了。
目标：防止跑偏，确保每一页都在「解决问题」。
动作：填写一份「需求卡片」，回答三个问题：
- 对象：给谁看？（领导、客户、学生）
- 目的：想要什么结果？（要钱、要人、要赞同）
- 情绪：整体风格？（严肃、热血、极简）
产出：1 张「需求卡片」，作为后续 AI 对话的基础背景。
2.第 2 步搭骨架 —— 生成页面清单：像导演写分镜一样规划页面清单。这时改结构只需改表格一行字，比做完 20 页再删要轻松 100 倍。
目标：确定内容的「菜单」，而不是直接写菜谱。
动作：把需求卡片喂给 AI，要求它生成页面清单。使用「金字塔原理」，确保逻辑：背景 → 问题 → 方案 → 价值 → 行动。
产出：1 份「页面清单」（例如：P1 封面，P2 背景，P3-P5 核心方案…）。
不知道制作流程怎么梳理？可以让 AI 帮你。参考提示词：

```
我想完成一个通用 ppt agent skill 的制作，

你只需要帮我整理一下这个流程
```

ps：建议结合真实的场景来生成 PPT，效果更好。

3.第 3 步：做模块 —— 定义内容组件：
把 PPT 变成流水线而非手工作坊。用公式生成标题，用组件组装页面。
目标：把 PPT 拆解成可复用的「内容组件」。
动作：制定内容的「标准化组件」。示例：
- 标题公式：动词 + 结果（例如：优化流程，提升 30% 效率）
- 内容积木：3 点式排版（左图右文，或上图下文）
- 金句模板：每一页底部总结一句话结论
产出：5～8 个常用「内容组件」。
4.第 4 步：穿衣服 —— 定视觉规范：
只在这一步才打开设计软件。之前都在用纸笔/备忘录思考，避免被软件工具绑架思维。
目标：解决「丑」和「乱」的问题，建立视觉秩序。
动作：预设一套固定的视觉参数，产出 1 套「视觉规范卡」：

| 项目 | 规范建议 |
| --- | --- |
| 颜色密码 | 主色（企业色/科技蓝）+ 辅助色（浅灰）+ 警告色（亮橙） |
| 字体搭配 | 标题用粗体（如：思源黑体 Bold），正文用细体（如：微软雅黑） |
| 排版规则 | 严格对齐，四边留白不少于 40px |

5.第 5 步：存为 Skill —— 生成完整技能：
把上面各步的流程文档放在 flow 文件夹下，然后让 AI 按流程生成完整的 Skill。

### 七）常见问题 FAQ
- Q：必须会编程吗？ A：不需要。全程用中文对话让 AI 完成，你只需要会「提问和确认」。
- Q：和单次 Prompt 生成 PPT 有什么区别？ A：Skill 会把你的偏好、流程、视觉规范固化下来，每次结果风格统一、可复用；单次对话每次都要重新交代、还容易「失忆」。
- Q：生成的 PPT 风格不满意怎么办？ A：先改「第 4 步视觉规范」，再让 AI 重新生成；或者直接告诉 AI 调整（如「改成深蓝商务风」）。
- Q：内容太多、一页放不下怎么办？ A：回到「第 2 步页面清单」，精简每页要点；用「金字塔原理」保证一页一个核心观点。
- Q：装 Skill 时提示安装失败？ A：确认网络可访问 GitHub；把报错发给 AI，让它帮你排查。

### 三）Step 0：定下你的赛道和选题池
#### 1、目的
给流水线装一个"方向盘"。选题方向没定死，每天自动选题就会今天写美食明天写股票，账号人设直接散架。素材方向选错了，后面写得再好也救不回来。
#### 2、手把手操作步骤
1.写下你的受众定位（一句话）：写给谁看，他们关心什么、焦虑什么。（例：写给中小企业的老板，他们想用 AI 提效但缺人缺预算。）
2.圈定你的聚焦领域（3~6 个）：账号永远只在这个池子里选题。（例：AI 编程、AI 知识管理、AI 新品发布、海外热点、Agent 落地案例。）
3.写出你的常青备胎选题（2~3 个）：当天没有热点时兜底用。常青选题 = 半年后看也不过时的话题（例："普通人为什么需要一个 AI 助手"）。
4.把上面三条连同人设卡、风格 DNA 一起存成 00_style.md——它是整条流水线的"最高宪法"，每个环节都要回头对照它。
#### 3、判断赛道好不好的三个信号
- 这个领域你能连续讲 100 天不重样吗？能 = 池子够深。
- 你的目标读者刷到标题会停吗？会 = 有钩子。
- 这个领域有商业出口吗？（课程/咨询/带货）有 = 值得长期投入。
#### 4、自查清单
- 受众定位一句话说清（不是"所有人"）
- 聚焦领域 3~6 个，已写死
- 常青备胎选题 2~3 个已备好
- 人设卡 + 风格 DNA + 往期文章库已存成 00_style.md

### 四）Step 1：自动选题——从全网热点到 TOP1
⚡ 【可固化点】"每天翻热点、筛选题、定题目"是日更作者最耗心力的重复劳动 → 整段封装成 skill，每天自动跑。
#### 1、目的
每天早上自动从全网热点里淘出"你的读者会点开"的题目。直接照搬热点榜 → 跟你的账号定位不匹配，写了白写。自动选题 = 热度 × 你的赛道 × 你的受众，三关都过才入选。
#### 2、流水线怎么跑（用 skill 三件套）
1.topic-collector（采集）：多路搜索最近 24 小时的热点，AI、科技、社会面各来一路，每条热点带原文 URL 和时间。
2.topic-generator（生成）：把热点和你的聚焦领域做交叉，生成 TOP10 选题——不是复述热点，而是"热点 + 你的角度"（例：热点是某大模型发布，你的角度是"中小企业老板能用它干什么实事"）。
3.topic-reviewer（评审）：逐个打分，通过线 70 分，评分维度：◦热度（30 分）：是否 24~48 小时内的活热点；◦受众匹配（25 分）：你的读者会不会点开；◦冲突感（20 分）：标题有没有"没想到"的反差；◦可讲性（15 分）：你有没有案例和素材能撑起来；◦时效窗口（10 分）：现在写还赶得上吗。
  - 热度（30 分）：是否 24~48 小时内的活热点；
  - 受众匹配（25 分）：你的读者会不会点开；
  - 冲突感（20 分）：标题有没有"没想到"的反差；
  - 可讲性（15 分）：你有没有案例和素材能撑起来；
  - 时效窗口（10 分）：现在写还赶得上吗。
4.自动决策：取最高分为 TOP1 直接进入写作，TOP3（含评分、理由、原文链接）存成 YYYYMMDD_topics.md。
5.降级规则：当天所有选题都不及格（比如周末无热点）→ 自动启用常青备胎选题，并在文件里标注"常青备胎"，绝不空转。
#### 3、不用 skill 的手动兜底提示词（可直接复制）

> 🎁 你是一位公众号选题策划。请按以下步骤帮我完成今日选题：
> ① 联网搜索最近24小时的热点新闻，重点覆盖：<你的聚焦领域>，每条注明来源URL和时间；
> ② 把热点和我的账号定位交叉，生成10个选题。我的账号定位：<粘贴 00_style.md 里的受众定位和聚焦领域>。要求：不是复述热点，而是"热点+我的读者关心的角度"；
> ③ 按五个维度给每个选题打分（总分100）：热度30、受众匹配25、冲突感20、可讲性15、时效窗口10；
> ④ 输出TOP3选题（含评分、推荐理由、热点原文链接），并直接指定分数最高者为今日选题；
> ⑤ 若所有选题低于70分，从我的常青备胎里选一个：<你的备胎选题>。

#### 4、选题自检
- 把选定的题目读给你的目标读者听（或者发到群里问一句）：他会不会想点开？会 = 过关。
- 24 小时后这个题还成立吗？成立 = 不是伪热点。
- 你能讲出至少一个具体案例吗？能 = 不是空对空。
#### 5、本步 Skill 解析：选题三件套怎么分工的
选题不是一个大 skill，而是三个小 skill 接力——这是这套设计最值得学的地方：每个 skill 只干一件事，干好就交棒。
① topic-collector（采集器）——只管撒网，不管筛选
- 输入：无（触发词"采集热点"即可）；输出：结构化热点列表（每条带来源平台、原文 URL、发布时间）。
- 核心设计：把"去哪找热点"写死在 skill 里——AI 官方账号、独立开发者、Product Hunt、Hacker News、Reddit 各有专属搜索关键词清单，每次采集不遗漏、不漂移。
- 强制带 URL：每条热点必须附原文链接，这是后面"禁编造"的源头保障——没有 URL 的热点直接不可信。
② topic-generator（生成器）——把"新闻"翻译成"你的选题"
- 输入：collector 的热点列表；输出：TOP10 完整选题方案（事件描述 + 核心角度 + 标题 + 写作方式）。
- 核心设计：筛选标准里写死了"必须国内用户能理解、必须有用户价值（能学到/能用到/能思考）"，并按内容特点预判写作方式（干货教程/产品体验/观点分享/技术解读）——这个预判会直接喂给写作环节。
- 学习点：它从不输出"某大模型发布了"这种新闻复述，输出的永远是"这件事对我的读者意味着什么"。
③ topic-reviewer（评审官）——一票否决 + 打分，双保险
- 输入：TOP10 选题；输出：每个选题的通过/不通过 + 评分 + 不通过原因。
- 核心设计：先过 4 个一票否决项（讨论量不足、领域无关、超过 72 小时旧闻、没有可操作内容——任何一条直接毙），再按五维打分（独特角度 30%、用户价值 25%、国内适配 20%、标题吸引力 15%、写作难度 10%），通过线 70 分。
- 学习点：把"这选题行不行"这种模糊判断，拆成了可量化、可复现的清单——这正是 SOP 变 skill 的典型手法。你完全可以改权重：追流量的号把"标题吸引力"调高，做深度的号把"独特角度"调高。
三件套怎么自定义：把 collector 里的账号清单和关键词换成你领域的；把 generator 里的领域限定换成你的聚焦领域；把 reviewer 的评分权重按你账号的目标调——骨架不动，只换"你的信息"。
#### 6、自查清单
- YYYYMMDD_topics.md 已生成（TOP3 + 评分 + 理由 + 链接）
- 选定 TOP1，且分数 ≥70
- 热点来源带真实 URL（禁止编造）
- 方向没跑出 00_style.md 圈定的聚焦领域

### 五）Step 2：创作——三版并行，合成一篇终稿
⚡ 【可固化点】"按套路写稿 + 起 40 个标题 + 查 AI 味"是每篇都重复的创作工序 → 整段固化进 skill，一次写三版自动择优合并。
#### 1、目的
把选题变成一篇 2000 字左右、有你的味道、过得了平台原创检测的终稿。为什么是"三版并行"而不是写一版？因为一次性写一版容易平庸——先发散再收敛，比直接收敛质量高得多。
#### 2、三版是什么（用 gzh-write-enhanced）

> 【嵌入电子表格】

| 版本 | 定位 | 作用 |
| --- | --- | --- |
| A 版 | 反直觉洞察 | 用一个"大家都想错了"的角度切入，制造认知冲击 |
| B 版 | 观点分析 | 把选题讲透，逻辑严密，适合深度读者 |
| C 版 | 实操教程 | 手把手干货，读者照着就能做 |

三版写完后取 A + C 合并成终稿：A 负责开头炸场、C 负责正文干货——洞见和实用兼得，这是实际跑出来的最优组合。
#### 3、手把手操作步骤
1.打开 WorkBuddy 对话，说"用 gzh-write-enhanced，按 YYYYMMDD_topics.md 的 TOP1 选题写三版"。
2.skill 会自动加载你的风格 DNA 和叙事口吻文件（所以 Step 0 的风格资产必须先备好）。
3.三版各自执行六条硬规则：◦① 结果前置：每段先给结论再给论证，别绕；◦② 金句锚点：每 300 字左右留一句能被截图转发的金句；◦③ 诚实坦白：没把握的数据就直说，禁止编造；◦④ 口语化转场：像跟朋友聊天一样自然过渡（"说白了""你猜怎么着"）；◦⑤ 往期导流：文里自然提一句你写过的相关旧文；◦⑥ 软转化结尾：结尾轻轻带一句你的课程/服务，不硬推销。
  - ① 结果前置：每段先给结论再给论证，别绕；
  - ② 金句锚点：每 300 字左右留一句能被截图转发的金句；
  - ③ 诚实坦白：没把握的数据就直说，禁止编造；
  - ④ 口语化转场：像跟朋友聊天一样自然过渡（"说白了""你猜怎么着"）；
  - ⑤ 往期导流：文里自然提一句你写过的相关旧文；

4.质量门：三版各自过 AI 味四层自检（L1 禁用词 → L2 标点规范 → L3 句式节奏 → L4 整体活人感），不过就自动返工重写。

#### 6、本步 Skill 解析：gzh-write-enhanced 为什么能去 AI 味
这是整条流水线里最核心的 skill，值得拆开看它凭什么。
它解决什么问题 AI 写文章最大的问题从来不是"写不出来"，是一眼就看出是 AI 写的：满篇"综上所述""本质上"，冒号破折号成灾，整段整段加粗，观点都对但没有一句是你自己会说的话。这个 skill 的思路是：用可执行的规则解决，而不是靠"写得口语化一点"这种正确的废话。
核心机制一：三版并行（先发散，再收敛）
- A 版（反直觉洞察）：剥洋葱式四层结构，负责"转发"——观点冲击；
- B 版（观点分析）：带温度感和降温段，负责"讲透"——逻辑深度；
- C 版（实操教程）：体验式叙事 + 干货密度，负责"收藏"——照着能做。
- 为什么不直接写一版？因为一次性写一版容易平庸。三版各自把一种风格推到极致，最后 A+C 合并，终稿才既有洞见又有干货。这是"多候选择优"思想在写作上的应用，和机器学习里的多模型投票是一个道理。
核心机制二：四层 AI 味自检（L1→L4，由硬到软）
- L1 硬性层：禁用词清单（赋能/深耕/抓手/底层逻辑/颗粒度/沉淀……）——机器可以直接扫描替换，零模糊空间；
- L2 风格层：标点规范（禁冒号破折号、对话用「」）、加粗比例上限——还是可机械校验的；
- L3 内容层：句式节奏——"太整齐、太对仗、太像总结"的句子打碎重写；
- L4 活人感层：整体通读，"一听就是 AI 写的"段落按你的风格 DNA 重写。
- 设计精髓：分层过滤。硬规则机器管，软规则 AI 管，各干各的——比"整体检查一遍"可靠得多。
它依赖的两份"外挂"（这就是为什么 Step 0 的风格资产必须先备好）：
- xiaohu_style_dna.md（风格 DNA）：受众、案例铁律、能量感——决定"像谁写的"；
- xiaohu_narrative_voice.md（叙事口吻）：体感开场、"不是A是B"句式、案例三要素、敢抬杠——决定"怎么说话"。
- skill 末尾还挂着 7 条口吻自检，不过就返工重写对应段落——自检不是走形式，是质量门。
你可以怎么改：把风格 DNA 和叙事口吻换成你自己的（从你的往期爆文里提炼）；把 L1 禁用词清单加上你的私人雷区；把三版组合从"A+C"换成你验证过的组合。骨架（三版并行+四层自检）别动，那是在实战里跑出来的。

- 读起来像你本人写的，不像 AI

### 六）Step 3：制图——开篇人设图 + 4 张正文配图

- 排版的本质是格式翻译不是审美创作，规则一旦定死就该交给脚本，每次执行结果一模一样——这才叫可复用。
- 你要调的只有"主题"这一个参数，其余全自动。想换口味改一个词就行，不用每次重新描述。
#### 4、本步 Skill 解析：gzh_format——一个"格式翻译器"的设计哲学
它是什么：一个独立脚本（不依赖大模型），把带插图的 Markdown 终稿翻译成公众号编辑器认的内联样式富文本。整条流水线里唯一"不用 AI"的环节——能用确定性脚本解决的，绝不交给概率性的模型，这是整条生产线最重要的工程判断。
核心设计逐条看：
- 只做翻译，不做创作：脚本不改一个字，只转换格式——大标题剥离（发布时标题单独填）、金句引用块→金句卡、图注→居中灰字、图片行→内联图片标签。输入变、输出跟着变，规则永远稳定。
- 主题即参数：三套主题（warm/tech/mono）就是脚本里的三组颜色变量，换主题 = 换一个参数。想加第四套主题，照现有结构加一组颜色值就行——扩展点提前留好。
- 踩过坑的痕迹：图片标签用的是 <img> 而不是 Markdown 的 !——因为公众号渲染器把排版版当 HTML 处理，Markdown 图片语法会原样显示成一行网址文字。这种坑只有真跑过才知道，skill 的价值一半在这里：把踩过的坑固化成规则，后人不再踩。
- 自带测试样例：改完脚本可以用内置的 test_sample.md 一条命令自测——不用等你发文才发现排崩了。
和手动方案的对比：手动用 135/mnice 等编辑器排版，每篇 20~30 分钟且格式靠手感；脚本方案 10 秒跑完且每次结果一模一样。可复现性才是自动化的核心收益，省时间只是顺带的。

- 它做什么：把终稿按知乎/头条/百家号/掘金/CSDN/小红书/知识星球/短视频口播 8 个下游的调性改写，图片按原文位置一一对应插入。
- 铁律一：只换风格，不删内容。原文的案例、数据、比喻、金句、行动建议全部保留，小红书可以用短句+emoji，但要点一个不能少——防止"多平台版越转越薄"。
- 铁律二：严禁杜撰。只做风格转换和格式适配，不允许添加超出原文范围的任何信息——转译可以，创作不行，这是分发的底线，否则8个平台8个翻车点。
- 图片纪律：下载/引用了多少张图，各平台版就必须出现多少张，且在对应段落位置（不许堆文末）——细节里全是经验。
② wechatsync（开源 CLI）——免 Token 的搬运工
- 它是什么：开源工具，两部分组成——Chrome 扩展（管登录态）+ 命令行 CLI（管调度）。CLI 通过 WebSocket 连 Chrome 扩展，借用你浏览器里已登录的各平台会话去创建草稿，所以不需要任何平台 Token/API 密钥。
- 架构启示：它绕开了"每个平台都要申请 API"这个死结——复用浏览器登录态是个人自动化最务实的路径。代价是 Chrome 必须开着，所以流程里才有"先 auth 预检、Chrome 没开就列人工待办"这一条。
- 喂什么文件有讲究：公众号喂排版美化版（带内联样式），其他平台喂素 Markdown——一个工具、两种喂法，按下游消化能力投喂，不是一视同仁。
- 稳定性差异要写进流程：实测头条带图易失败、小红书易卡死——所以流程里头条"先带图试一次、失败转文字版"，小红书"不自动、列人工"。把工具的脾气写进 skill，这就是 SOP 的价值。
③ 为什么知识星球单独走：wechatsync 不支持知识星球，所以用知识星球连接器直发（无草稿箱、直接发布）。没有万能工具，分发矩阵 = 每个平台选它最稳的通道——这种"按平台适配通道"的思路，比你记住某个具体工具更重要。
#### 5、自查清单
- 8 个平台版本文件齐全（命名统一 YYYYMMDD_平台.md）
- 公众号草稿箱已收到排版美化版，打开检查图片和格式正常
- 执行报告已生成，失败项都有记录和降级说明
- 人工待办 ≤3 项

### 九）【你最重要的收获】把这条路径固化成你自己的 Skill
🎯 这一节是整个阶段最重要的部分。前面 Steps 0~5 是"跑通一次"，这一节是"让以后每次都能一键跑"。
先给你一个 before / after，你就知道这一节值不值得花时间：
- 以前：写一篇公众号，翻热点半小时、写稿两小时、配图一小时、排版半小时、逐平台粘贴一小时——一篇下来大半天没了，第二天还得从头再来。
- 以后：你把这套方法固化成一个 Skill，每天早上它自动跑完全流程，你醒来只看到一份执行报告和一箱待发布草稿，你只管审稿点发布。
这不是偷懒，这是把你的经验变成资产。
#### 1、先看懂：你现在处在哪一层？

> 【嵌入电子表格】

| 层级 | 你做什么 | AI 做什么 | 复用度 |
| --- | --- | --- | --- |
| ① 固定工作流 | 每一步手动操作、自己判断 | 只执行单点指令 | 低（换个人/换次就得重教） |
| ② Skill | 用自然语言描述流程 | 一键触发，自动跑完整套 | 中（谁都能调，但还靠你喂输入） |
| ③ 岗位角色 | 定目标、验收、兜底异常 | 扛起完整责任链，拿不准主动找人 | 高（接近"招了个不会离职的员工"） |

你刚才 Steps 0~5 手动跑的，就是 ① 固定工作流。这一节的目标，是把它推到 ② Skill——再加一个定时任务，每天早上自动触发，你就摸到 ③ 的门了。
#### 2、为什么光写一份 SOP 文档不够？
很多人到这一步会问："我把流程写成文档不就行了？"
问得对，但 SOP 文档有个死穴：它假设读的人会执行、会判断、会处理异常——可新人（和三个月后的你自己）并不会。
- 文档写"配图要挑认知锚点"→ 新人不知道什么叫锚点，四张图全配在开头。
- 文档写"公众号要转内联样式"→ 他忘了，粘进去格式全丢还不知道为啥。
- 文档写"选题不过 70 分用备胎"→ 他直接挑了个 60 分的凑合发。
Skill 把 SOP "变成会自己跑的东西"：判断逻辑、异常处理、降级方案、输出格式都固化进去了，你只给输入、拿输出。一句话——SOP 是"说明书"，Skill 是"会干活的徒弟"。
你不需要会写代码。现在的 Skill 大多是用自然语言把流程讲清楚、Agent 帮你封装的。技术平权就平权在这儿：你不再被代码捆住，精力全放在你的领域经验上。

你刚才手动跑的"选题→创作→制图→排版→分发"，每一步用什么工具、注意过什么，你已经亲自体验过了。现在反过来——把这套体验写成"给 Agent 的说明书"。一个最小可用的 Skill 描述长这样（直接对应你刚跑的链路）：

#### 4、直接抄作业：这条线的开源版总调度
上面五步各自能固化为 skill，但环节之间的串联（谁先谁后、产物怎么交接、失败了怎么办）是另一个 skill——总调度。这条线已经有一个开源版（gzh-daily-pipeline），它的三个设计决策非常值得抄：
- 调度器不是执行器：总调度自己不写稿不配图，只负责按顺序调用各环节 skill、检查产物交接。每个环节都可以换成你自己的实现，只要产物文件名符合"交接契约"——解耦设计，换零件不换整车。
- 占位符实现"一套流程，各自人设"：开源版里所有个人信息（工作目录、作者人设、受众、聚焦领域、问候语、口头禅、效率数据）都是 {{AUTHOR_PERSONA}} 这样的占位符，拿到手全局替换一遍，流水线就变成了"你的"——这就是为什么你的 skill 一开始就该把"你的信息"和"流程逻辑"分开写。
- 断点续跑 + 失败降级写在调度层：每次开跑先检查哪些产物已存在（存在的跳过），某环节失败就降级记录、绝不中断整条线。这两个能力放在调度层而不是各环节里，一次实现、全线受益。

#### 6、怎么验收：你的 Skill 真的"做好了"吗？
别只看"写完了"，用新人测试验收（这是判断一个 Skill 有没有用的金标准）：
- 输入清晰：给一个题目（甚至不给题目）就能跑，不用额外解释背景
- 步骤可复现：换个人/换次跑，产出风格稳定不漂移
- 异常有兜底：搜不到热点、出图错字、同步失败都有明确处理方式，不会卡死
- 输出格式对：出来的就是"待发布草稿 + 报告"，不用再手工收拾
- 不用你盯着：跑的过程你不用中途介入，只管最后审稿
上面 5 条但凡有一条不过，就说明你的 SOP 还没"说清楚"——回到第 3、4 步补描述。能过新人测试的 Skill，才算真正有用，才算真正属于你。
#### 7、从"用户"到"创作者"的心态转变
- 前面几个阶段你是 Skill 的使用者（别人做好了你来用）。
- 从今天开始你可以成为 Skill 的创造者（把自己的方法变成别人能用的工具）。
- 这才是"进阶"的真正含义：不只是会用工具，而是能造工具。
你不需要是程序员。你只需要像刚才那样，把自己的方法讲清楚——剩下的封装，交给 Agent。这，就是技术平权最好的样子。

### 十）进阶玩法
#### 1、定时任务：真正的"一键完成"
- 把固化好的 skill 挂上定时任务（WorkBuddy 的 automation），每天早上固定时间自动触发"跑今日流水线"。
- 从此日更这件事和你起床时间彻底解耦——你还在睡觉，文章已经在草稿箱里等你审了。
#### 2、断点续跑：失败不重来
- 产物按统一命名落盘（YYYYMMDD_xxx.md），每次开跑先检查哪些产物已存在，存在的直接跳过。
- 好处：中途断了、想补配图、想换标题重排——都只重跑缺失的那一段，不浪费前面的成果。
#### 3、批量矩阵：一鱼多吃
- 一次流水线的 8 个平台版本只是起点：短视频口播文案喂给视频生产线，就是第二个账号的日更素材；
- 同一人设开矩阵号，换聚焦领域池（00_style.md 换一份），一套 skill 跑多个号。
#### 4、和其他 Skill 联动
- 用资讯采集类 skill 盯竞品账号的爆款 → 借角度不借句子，进选题环节；
- 用数据分析 skill 每周复盘各平台打开率 → 反哺选题评分的权重，让流水线越跑越准。
#### 5、风格迭代：让账号慢慢长
- 每月把表现最好的 3 篇文章回填进"往期文章库"，你的风格 DNA 会跟着账号一起进化——skill 固定的是流程，长出来的是你的风格。
## 二、AI视频生产线——用 Skill 把一条历史一图流视频的生产路径固化下来 @maus鼠

### 四）Step 1：自动洗稿——把素材改写成口播文案

> 💡 ⚡ 【可固化点】如果你经常要做"拿别人的文案改写自己的版本"这件事 → 这一步可以单独封装成一个 skill。

#### 1、目的
直接照搬别人文案 → 平台判抄袭 / 同质化降权。"洗稿"= 保留原文核心逻辑和情绪走向，但换说法、换素材、换角度，变成你自己的版本。
#### 2、手把手操作步骤
1.打开 WorkBuddy 对话（或任意大模型）。
2.把下面「二创提示词」整段复制进对话框。
3.在提示词末尾的 文案内容: 下面，粘贴你的刚才保存的原文。
4.发送，等 AI 输出二创稿。
5.把二创稿存成新的.md文件。

> 📝 案例：二创提示词（通用版）—— 直接复制使用


```
你是一位专业的短视频文案创作者，现在需要你帮我二创一下文案，有以下几点要求：
① 错别字校对：全面排查文案中的错别字、语病及标点错误；
② 保持每段的核心意思不变，但允许调整句子的先后顺序、拆分长句或合并短句，让表达更自然；
③ 开头黄金三秒的文案修改一定要慎重，第一段也可以与原文相同；
④ 创作出的文案要口语化，让中老年人也能一听就懂；
⑤ 尽量与原文案保持字数相同；
⑥ 每段至少有一处"换个方式说同一件事"——不是换一个近义词，而是换一个角度或换一个比喻来表达同样的意思（比如原文说"读书可以改变命运"，可以改成"书读进去了，路就宽了"）；
⑦ 改完之后通读一遍，检查有没有"一听就是AI写的"的句子——太整齐、太对仗、太像总结的句子，改成大白话；
⑧ 修改程度50%以上，但修改的重点是换说法和换句式，不是加新内容或删关键信息。
```

### 八）Step 5：组装成片——一图流模式

> 💡 ⚡ 【可固化点】"图片+配音+字幕→mp4"的组装参数一旦确定 → 整个流程可以一键复用。

#### 1、目的
把"图 + 声 + 字幕"压成一条能在本地/平台播放的 mp4。本案例先做干净底片（固定单图 + 配音），字幕和动效留到剪映加更快。
#### 2、ai-video-make 的两种模式
- 单音频模式：一段完整配音 → 按分镜估算时长对齐。
- 逐段音频模式：每段独立 wav → 按真实时长精确对齐，字幕零漂移（推荐）。
#### 3、手把手拼起来（一图流底片）
1.准备一张主图（一图流只需 1 张，如 hero.png）+ 整段配音 voice.wav。
2.在终端执行下面命令（路径换成你自己的），或者在workbuddy中直接把上面几步的图片和音频拖进来：

```
ffmpeg -loop 1 -framerate 24 -i hero.png -i voice.wav -t 180 \
  -vf "scale=1080:1920:flags=lanczos,setsar=1,format=yuv420p,setrange=limited" \
  -c:v libx264 -preset medium -crf 23 -movflags +faststart \
  -c:a aac -b:a 128k -shortest final.mp4
```

- 重点 1：scale=1080:1920 —— 竖屏 9:16 分辨率，别用横屏。
- 重点 2：format=yuv420p,setrange=limited —— 必加，压成标准 TV 范围，否则部分播放器/浏览器预览会发灰或黑屏。这一步别省。
- 重点 3：-t 180 —— 总时长上限（秒），按配音实际长度填，避免无限流挂死。
- 字幕和推镜先不加，留到剪映里做更快（详见下方说明）。
#### 4、为什么把字幕/动效留到剪映？
- 在命令行里烧字幕要处理字体和转义，调起来很磨；剪映里拖拽即可，效率更高。
- 推镜（Ken Burns）、转场同理——剪映的"关键帧"比写滤镜直观。
- 所以这一步你会拿到的是"固定单图 + 配音"的干净底片，剪映 5 分钟加完字幕动效和BGM即成片。
#### 5、自查清单
- [ ] 能在本地播放器正常打开，声音同步
- [ ] 画面色调正常（不发灰、不发青）—— 验证 format=yuv420p 生效
- [ ] 段间无黑屏闪烁

② Skill | 用自然语言描述流程 | 一键触发，自动跑完整套 | 中（谁都能调，但还靠你喂输入）
③ 岗位角色 | 定目标、验收、兜底异常 | 扛起完整责任链，拿不准主动找人 | 高（接近"招了个不会离职的员工"）
你刚才 Steps 0~5 手动跑的，就是 ① 固定工作流。这一节的目标，是把它推到 ② Skill——这也是大部分破局同学当下最值得做的那一跳。③ 是后话，先把②踩实。
#### 2、为什么光写一份 SOP 文档不够？
很多人到这一步会问："我把流程写成文档不就行了？"
问得对，但 SOP 文档有个死穴：它假设读的人会执行、会判断、会处理异常——可新人（和三个月后的你自己）并不会。
- 文档写"出图要写死人物特征保一致"→ 新人不知道什么叫"写死"、漏了就翻车。
- 文档写"导出加 yuv420p 防发灰"→ 他忘了加，出来一片灰还不知道为啥。
Skill 把 SOP "变成会自己跑的东西"：判断逻辑、异常处理、输出格式都固化进去了，你只给输入、拿输出。一句话——SOP 是"说明书"，Skill 是"会干活的徒弟"。
你不需要会写代码。现在的 Skill 大多是用自然语言把流程讲清楚、Agent 帮你封装的（破局里叫"说话编程"）。技术平权就平权在这儿：你不再被代码捆住，精力全放在你的领域经验上。
#### 3、动手：把你刚跑的李白线，反推成一个 Skill 雏形
你刚才手动跑的"素材→洗稿→拆句→分镜→出图→配音→组装"，每一步用什么工具、注意过什么，你已经亲自体验过了。现在反过来——把这套体验写成"给 Agent 的说明书"。
一个最小可用的 Skill 描述长这样（直接对应你刚跑的链路）：

> 📝 案例：你的"历史一图流生产线"Skill 雏形


```
name: 历史一图流生产线
description: 输入一篇历史人物素材，自动产出竖屏一图流成片（AI配图+克隆配音+组装）
## 输入
- 一篇历史人物/事件素材（3000字内，有故事性、有情绪起伏）
## 步骤
1. 洗稿：用二创提示词把素材改成口播稿（换说法不换骨架，去AI味）
2. 拆句：≤9字短句（给字幕）+ ~45字分镜（给配图），两套粒度服务两个下游
3. 出图：按分镜提示词模板，逐张 ImageGen 串行生成（写死五官/体型/标志特征保人物一致）
4. 配音：indextts-voice 王立群音色，逐段生成 wav
5. 组装：ai-video-make 单图推镜+配音+字幕 → mp4（导出必加 format=yuv420p,setrange=limited 防发灰）
## 注意事项
- 人物一致性靠"写死特征"，不同分镜间才不会长变样
- 出图串行防限流；参考音要干净、单段≤15秒
- 素材路径尽量用英文、别带冒号，滤镜里的转义才不会出问题
## 验收
- 新人按这个 Skill 跑一遍，能出可播的 mp4，中途无需人工干预
```

你看——这就是你刚才亲手跑完的那条线，只是换了个"能复述给 Agent 听"的写法。它已经是个 Skill 雏形了。
#### 4、Skill SOP 描述模板（新手友好版）
如果你要固化的不是"历史一图流"、而是你自己的别的流程，用下面这个通用模板，把刚才做的事用大白话填进去：

> 📝 案例：Skill SOP 描述模板（新手友好版）


```
# 我的 Skill 名称：[例如"历史一图流生产线"]
## 这个 Skill 做什么？
[一句话描述：输入什么，输出什么]
## 使用者需要准备什么？
[素材、账号、环境等前置条件]
## 执行步骤（按顺序）：
1. [Step 0 做什么，用什么工具/AI]
2. [Step 1 做什么，用什么提示词]
3. [Step 2 做什么，注意什么]
...（把你刚跑过的每一步用大白话写出来）
## 每一步的关键注意事项：
[执行这步最容易错的地方 + 正确做法]
## 输出是什么？
[最终的成品格式、存放位置]
```

把这个模板填完，就是一个 Skill 的雏形。交给 Agent 就能帮你封装。
#### 5、怎么验收：你的 Skill 真的"做好了"吗？
别只看"写完了"，用新人测试验收（这是判断一个 Skill 有没有用的金标准）：
- [ ] 输入清晰：给一份新素材就能跑，不用额外解释背景
- [ ] 步骤可复现：换个人/换次跑，结果稳定不漂移
- [ ] 异常有兜底：出图不理想、配音吞字时有明确处理方式，不会卡死
- [ ] 输出格式对：出来的就是你要的 mp4 / 文档 / 表格，不用再手工收拾
- [ ] 不用你盯着：跑的过程你不用中途介入，只管最后审稿

> 💡 上面 5 条但凡有一条不过，就说明你的 SOP 还没"说清楚"——回到第 3、4 步补描述。能过新人测试的 Skill，才算真正有用，才算真正属于你。

#### 6、从"用户"到"创作者"的心态转变
- 前面几个阶段你是 Skill 的使用者（别人做好了你来用）。
- 从今天开始你可以成为 Skill 的创造者（把自己的方法变成别人能用的工具）。
- 这才是"进阶"的真正含义：不只是会用工具，而是能造工具。
你不需要是程序员。你只需要像刚才那样，把自己的方法讲清楚——剩下的封装，交给 Agent。这，就是技术平权最好的样子。
### 十）进阶玩法
#### 1、批量生产
- 文案模板化 → 换变量批量生成配音+配图 → 一条命令组装一整批。
- 适合做"同一人设、不同选题"的矩阵号。
#### 2、和其他 Skill 联动
- 用 youtube-transcript 抓爆款视频字幕 → 改写成口播稿 → 进生产线。
- 用写作类 skill 先打磨"活人感"再配音，观感提升明显。
#### 3、画风扩展
- 把常用的视觉风格存成 preset（如"科技口播""国风人物""温暖历史"），下次直接选。
- 分镜提示词模板里的第⑦条（风格描述）换成新的画风描述即可。
#### 4、接上自动发布（可选扩展）
- 这一阶段我们聚焦"生产链路"，发布不在教学范围内——你能先稳定产出成片，比急着铺渠道更重要。

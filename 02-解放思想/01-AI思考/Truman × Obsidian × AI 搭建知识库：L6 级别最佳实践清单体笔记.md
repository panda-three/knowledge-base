# Truman × Obsidian × AI 搭建知识库：L6 级别最佳实践清单体笔记

> 来源：Truman 高阶建模篇、AI 操作系统大课、半肥猫实践、陈天实践等。  
> 本笔记聚焦**搭建实现细节与思考过程**，不含"什么是知识管理"等基础概念。

## 一、顶层设计：先定框架，再存内容

### 1.1 选定稳定模型作为知识库骨架

**实现细节：**

Truman 用 **MUSE 模型 + 双三角模型** 作为整个 AI 知识库的 Topdown 骨架。他不是先存东西再想分类，而是先搭结构树，让所有碎片有处安放。

| 层级  | Truman 的做法                           | 思考过程                         |
| --- | ------------------------------------ | ---------------------------- |
| 第一层 | AI 认知（MUSE 宽度+深度） + AI 落地（场景+基本功+数据） | 先分"懂"和"用"两大块，避免认知笔记和实操笔记混在一起 |
| 第二层 | AI 落地 → 按实践单元拆成 9 个基本功               | 每一个基本功都是一个独立的刻意练习对象          |
| 第三层 | 每个基本功下面再按主题展开，比如 VibeCoding → 四大层级   | 每个专题展开到 4-6 层深度，形成可迭代的枝杈     |
| 第四层 | 最底层是具体策略、反思、复用的技巧                    | 叶子节点足够细，后续 AI 检索才能精准命中       |

**关键判断：**

```text
一个具体策略（比如「日志调试」），必须稳定挂在知识树 6-8 层的某个小树杈上。
如果挂不上，说明结构还需细化；如果挂重复，说明分类需要合并。
```

**半肥猫的并行实践：**

他把知识库拆成**多个互相关联的独立库**，而不是一个大而全的单库：

| 分库 | 内容 | AI 调用场景 |
|---|---|---|
| 专业领域库 | 药理、营养学、中医解释、西医解释、热量算法 | AI 写专业内容时调取 |
| 流量运营库 | 爆款格式、敏感词映射表、平台规则 | AI 做合规检查时调取 |
| 人设语气库 | 不同受众的话术风格、IP 说话方式 | AI 生成文案时匹配语感 |

**核心洞察：**

> 不同库之间要能"互相路由"。比如写一条祛湿汤文案，AI 自动从专业库调药理、从运营库调爆款格式和敏感词规则、从人设库调语气——几个库联动才能产出既专业又合规、还像真人说的内容。

### 1.2 三层知识库设计（针对不同用户/场景）

**来源：赵飞律师团队实践，Truman 认可并引用**

| 层级 | 内容 | 使用对象 |
|---|---|---|
| 基础案例库 | 脱敏后的完整案例，按时间线和类型入库 | 新手需要看完整案例来建立体感 |
| 研究文档 | 从案例库萃取的长文档，包含法律基础、判例趋势、多维度思考 | 熟手只需要看提炼后的研究 |
| 逻辑图/象限图 | 将复杂文字观点转成可一张图讲清的结构 | 给客户讲解时需要可视化 |

**思考过程：**

```text
不同人用知识的方式完全不同。
新手需要完整上下文，熟手只想要萃取结论，对外输出需要可视化。
所以知识库不是"存一份就够了"，而是要针对不同使用场景做多层加工。
```

## 二、数据预处理：让 AI 真正吃得进去

### 2.1 原子化拆分 + 混合格式

**半肥猫的实现细节：**

每条数据拆到最小可独立调用的粒度，然后用两种格式混合组织：

```text
文档开头：JSON / KeyValue 结构化字段
  → 写清楚：这条数据"是什么、归哪类、适用场景、标签"
  
主体内容：Markdown
  → 保持人类可读和 AI 可理解
```

**为什么这样设计：**

- 纯 Markdown：AI 能读但检索效率低，无法精确过滤
- 纯 JSON：人类维护成本高，长文本读起来难受
- 混合格式：结构化头部负责"被找到"，Markdown 主体负责"被理解"

### 2.2 多维度标注（核心壁垒，最花功夫）

半肥猫对**每一条数据**的标注达到了五层深度。以一张中药煲汤食谱为例：

| 标注维度 | 具体内容 | 为什么重要 |
|---|---|---|
| **专业维度** | 中医原理、西医营养学解释、适合/禁忌人群、热量算法 | AI 没有行业经验，不标注就等于让 AI 瞎猜 |
| **平台风控** | 敏感词映射表（如"便秘"→"噗噗"），提前标注替换规则 | 不标注会直接被限流封号，标注过才能让 AI 自动合规 |
| **受众话术** | 中医受众→经络温补话术；西医质疑→有效成分原理话术 | 同一份数据面对不同人要说不同的话，话术预埋才能让 AI 自动切换 |
| **视觉维度** | 色调、风格、图片提示词预标注 | 为后续 AI 生成配图做准备，文案没写时视觉方向已定 |
| **经验边界** | "当归要后下，出锅前十分钟才能放，早放药性就散了" | 这类隐性知识 AI 永远搜不到，只有行业老手才攒得出来 |

**关键洞察：**

```text
标注的质量不取决于技术，取决于你对行业的理解深度。
工具层面的东西大家花时间都能学会，但知道"该标什么、标到什么颗粒度"——
这才是真正别人抄不走的东西。
```

### 2.3 RAG 优化三步法

**半肥猫总结的三步：**

| 步骤 | 动作 | 解决的问题 |
|---|---|---|
| 原子化拆分 | 把资料打散到最小可调用单元 | 让 AI 找得到 |
| 多维度标注 | 对每条数据做多层标注 | 让 AI 用得好 |
| 优化知识库 | 分门别类组织成独立库，库间互相路由 | 让 AI 不会串 |

**核心反思：**

```text
与其事后在提示词里反复补救"不要说这个""要注意那个"，
不如在源头上一次做到位。

你喂给 AI 的东西是乱的，它吐出来的也一定是乱的。
Garbage In, Garbage Out。
```

## 三、Obsidian 本地知识库的技术架构

### 3.1 为什么选 Obsidian

| 特性 | 实际价值 |
|---|---|
| Markdown 格式本地存储 | 文件在自己硬盘上，不受平台倒闭/收费影响 |
| 丰富插件生态 | Flashcard→Anki 间隔复习、图谱可视化、模板系统 |
| 本地文件可被 AI 直接读取 | Claude Code / OpenClaw / Trae 直接读本地 MD 文件，无需手动上传 |
| 知识卡片互相关联 | `[[双向链接]]` 让知识之间形成网络，不是孤岛 |

### 3.2 核心打通方案（Truman / 陈天 实践）

**打通链路：**

```text
AI 对话产出 → YAI 一键保存 MD 到 Obsidian 笔记本
              → Trae 提炼框架、合并加工
              → 人工整合，形成最终学习报告
              → 存入 Obsidian，成为新的知识资产
```

**陈天的进阶打通：**

```text
Claude Code + Obsidian 本地知识库打通：
  1. 所有内部资料（会议纪要、录音、项目文档）存入 Obsidian
  2. Get/Flomo 的真实世界输入自动归类
  3. Claude Code 直接读取本地文件，无需手动上传

基础设施：Mac Mini M4（拼多多 2998 元买的）
  → 24 小时运行，作为本地 AI 服务器
  → Claude Code 直接调度 Obsidian 里的知识库
```

### 3.3 文件组织实践（Truman 五级分类）

```text
一级：AI 认知 vs AI 落地
  二级：AI 落地 → 按基本功拆成 9 个模块
    三级：每个基本功 → 按主题展开（如 VibeCoding）
      四级：VibeCoding → 四大层级分类
        五级：具体策略/反思/技巧/复用规则
          六级：单条笔记 + 标签 + 双向链接
```

**关键规则：**

```text
1. 每条笔记必须能挂在 6-8 层的某个树杈上
2. 挂不上的，要么结构需要扩展，要么这条笔记不值得存
3. 定期用图谱视图检查：哪些节点是孤岛？哪些区域过度拥挤？
```

## 四、AI 如何吃掉知识库

### 4.1 调研型工作流（Truman 的 7 步法）

Truman 用这套流程完成了"多 Agent 分工研究"，5-6 小时产出过去 50-200 小时质量的报告：

| 步骤 | 人做什么 | AI 做什么 |
|---|---|---|
| 1. 定目标 | 明确出口和边界 | — |
| 2. 设计调研框架 | 预设 4 个核心问题（常识→本质→推演→共识） | — |
| 3. 设计调研清单 | 分 4 个里程碑依次执行 | — |
| 4. 四路交叉提问 | 全程深挖、追问、补充信息 | Gemini + GPT + Grok + YAI 同时回答，交叉验证 |
| 5. 整理整合 | — | YAI 一键保存关键讨论→MD 到笔记本 |
| 6. AI 初加工 | — | Trae 提炼框架、合并加工 |
| 7. 人工整合 | 最终判断、补审美、形成报告 | — |

**核心原理：**

```text
四个 AI 同时聊同一个问题 → 交叉验证 → 去重 → 合并精华
任何一个单 AI 都会有偏见和幻觉，四个互相对照，质量立刻上一个台阶。
```

### 4.2 Skill 封装型工作流（Truman 的 8 步法）

Truman 写调研 Skill 的完整流程，从零到 Obsidian 可调用：

| 步骤 | 动作 | 工具 |
|---|---|---|
| 1. 快速认识 | 问 AI 要教程和最佳实践参考，锁定官方 skill-creator 为元技能 | AI 对话 |
| 2. AI 翻译+解读 | Trae 翻译（保持执行 100% 有效）、Antigravity 解读精华 | Trae + Antigravity 交叉工作 |
| 3. 自建最佳实践教程 | 让 Claude 把官方教程精华合并，生成 Topdown 实操教程 | Claude |
| 4. 逐步打磨 | 每个模块挨个让它解读、MECE、排优先级、加案例、补底层逻辑 | 每个环节提 2-5 轮"不够好" |
| 5. 交叉验证 | 并入 Claude 官方培训教程 + 花总的 Feature 思考，让 AI 交叉测评打分 | 多源交叉验证 |
| 6. 生成系统提示词 | 把教程转化成 Partner：系统提示词 + 数据资产包 | Claude |
| 7. 封装到 YAI Partner | 简单调试，2min 发布 | YAI |
| 8. 下载本地→OpenClaw 学习 | MD 文档下载到本地，丢给 OpenClaw，开始干活 | OpenClaw + Obsidian |

**关键技巧：**

```text
基于原始案例直接建模，通常显著差于：
  先做一次萃取 → 再二次合并萃取。

所以不要一次让 AI 从原始材料直接出结论。
先让它分别处理每个子模块，再汇总建模。
```

### 4.3 Agent 驱动型（半肥猫从"人肉接口"到全自动）

**问题：** 半肥猫封装了 300+ Agent，但员工不会用，所有需求卡在他一个人身上——他成了"全公司和 AI 之间的人肉接口"。

**解法：OpenClaw 调度 Obsidian 知识库：**

```text
每天早上 8:00：
  OpenClaw 自动读取本地 Obsidian 知识库
  → 主动去新闻网站抓热点
  → 从可信度、相关度、热门度三维筛选排序
  → 精选 6 个选题推到飞书工作群

员工在群里 @龙虾机器人：
  "1号，用吴晓波叙事风格，前面讲道理后面种草"
  → OpenClaw 后台调度：专业库调药理 + 运营库调格式 + 人设库调语气
  → 自动生成图文 → 推到公众号草稿箱
  → 同事看一眼没问题点发送
```

**核心转变：**

```text
之前：员工提需求 → 老板做生成（人肉接口）
现在：AI 主动推选题 → 员工只负责审美和判断 → 内容自动出来
```

## 五、核心心法与长期原则

### 5.1 「工具是变的，数据是不变的」

```text
半肥猫 20 万+ 知识卡片存在 Obsidian 本地 MD 文件里。
今天用 Cherry Studio，明天用 OpenClaw，后天换新工具——
只要数据是自己的、格式是开放的（Markdown），换个工具套上去就能跑。

不要在工具上绑定太深。
把真正该沉淀的东西——数据、认知、标注、经验——放在自己手里。
```

### 5.2 人机分工的「双三角」

| 角色 | 职责 |
|---|---|
| **人** | 给明确目标、反复补审美（说"不够好"）、补信息（搜知识库/联网）、交叉验证、拆里程碑、最终判断 |
| **AI** | 搜集信息、整理、建模、排版 |
| **一堂/方法论** | OSCAR 调研框架、数据资产包、严谨技术 Partner |

```text
关键不是 AI 多强，而是人有没有给清楚目标和审美。
AI 直接动手做（不给审美）≈ 20 分；
人先建立审美、拆解要素、给清楚标准，AI 再做 ≈ 70 分+。
```

### 5.3 知识库的三个目标（Truman）

| 目标 | 具体含义 |
|---|---|
| 结构尽量清晰 | 有一个 Topdown 完整知识树，碎片有处安放 |
| 关键知识备忘 | 未来会复用的高价值知识放在一起，不用到处乱找 |
| 整合统一思考 | 内容放在一起，以月度/年度为单位长期迭代，涌现新洞察 |

```text
这才半年。如果能持续积累、分化、建模 3-5 年，这棵树能长成什么样？
这就是和时间做朋友的力量。
```

### 5.4 从「收藏」到「内化」的第四阶段

```text
Obsidian + Anki + PicGo：
  1. Obsidian 本地 MD 存储 + 丰富插件
  2. Flashcard 插件：把知识点做成问答卡片
  3. 一键推送到 Anki 进行间隔复习
  4. 所有知识如果不能调取出来，就无法引用
  5. 先记忆 → 再调取 → 最后成为肌肉记忆
```

## 六、L6 级别的判断标准

| 维度 | L6 的表现 |
|---|---|
| **结构** | 有稳定 Topdown 知识树，任何新内容能挂到 6-8 层的某个树杈上 |
| **数据质量** | 每条关键数据做过多维标注（专业+风控+受众+视觉+经验边界），不是裸存 |
| **AI 可调用性** | 知识库能被 AI 直接读取（本地 MD/JSON），AI 能通过结构化头部精准检索 |
| **库间路由** | 多个独立知识库之间能互相关联，AI 可以跨库联动调取 |
| **迭代机制** | 知识库不是静态文档，会随着每次项目复盘、反馈持续更新 |
| **长期复利** | 以月度/年度为单位，知识之间互相激发产生新洞察，不是只做存储 |
| **工具独立** | 数据格式开放（Markdown），不绑定任何单一工具，随时可迁移 |

## 七、最小可启动清单

如果你要从零开始搭建自己的 Obsidian + AI 知识库：

| 优先级 | 动作 | 预期时间 |
|---|---|---|
| P0 | 选定一个稳定结构模型（MUSE / 你自己的业务模型）作为 Topdown 骨架 | 1-2 小时 |
| P0 | 建 Obsidian 仓库，建好第一层目录结构 | 30 分钟 |
| P1 | 把已有散落资料（飞书/Flomo/印象笔记）归类放入对应目录 | 2-4 小时 |
| P1 | 对最高频使用的 5-10 条核心数据做多维度标注（先做 3 层） | 2 小时 |
| P2 | 配置 Obsidian → AI 工具的打通链路（Claude Code / OpenClaw 读本地文件） | 1-2 小时 |
| P2 | 写一个最小可行的 Skill/Agent，让它能读取你知识库中的某一类数据 | 2-3 小时 |
| P3 | 建立每月迭代习惯：月底检查知识树，合并重复节点，扩展新枝杈 | 持续 |

# AI 组织认知研究 · L6 最佳实践清单体笔记

> **案例来源**：Truman 春节假期用 4 个顶级模型并行对话，攻克「多 Agent 如何分工」这一组织设计级难题  
> **段位定位**：L6 无限进步——单人驾驭多模型矩阵，用里程碑式追问法把 50-200 小时的研究压缩到 5-6 小时  
> **核心公式**：**四问调研框架 × 四模型交叉验证 × 七步工作流 × 双三角操作系统 = 5-6h 产出 70 分可用研究报告**

---

## 一、背景与问题定义

### 1.1 为什么启动这个项目

| 维度 | 内容 |
|---|---|
| **宏观预判** | 一人团队 / 一人公司 2026 年估计会成熟 |
| **个人战略** | Truman 开始躬身入局，做深度动手学习和认知储备 |
| **时间窗口** | 春节假期——大半夜，没有专家可找，没有团队可借用 |
| **前置积累** | 已完成 OpenClaw 入门（配置阶段）和进阶（Skill + 工作闭环） |
| **触发事件** | 进入下一阶段时，立刻撞墙——**多 Agent 怎么分工？** |

### 1.2 核心难题拆解

这不是一个「查查资料就能回答」的问题。它接近人类组织设计级别的复杂度：

```
多 Agent 分工的混沌问题空间：

├── 颗粒度问题：多细才算一个 Agent？
│   ├── 运营总监级别？（管一堆事）
│   ├── 投放负责人级别？（管一条线）
│   ├── 公众号负责人级别？（管一个渠道）
│   ├── 文章生产级别？（管一个产出物）
│   └── 撰写初稿级别？（管一个动作）
│
├── 划分逻辑问题：按什么轴来切？
│   ├── 按人类岗位划分？
│   ├── 按能力项划分？
│   ├── 按产出物类型划分？
│   └── 按工作流阶段划分？
│
├── 底层逻辑问题：
│   ├── 人类分工的底层逻辑是什么？
│   ├── AI 分工的底层逻辑是什么？
│   ├── 二者的一致性和差异性在哪？
│   └── 能不能直接从人类组织理论迁移？
│
└── 实践落地问题：
    ├── 一堂的实际情况是什么？
    ├── 一堂的基本功清单如何映射到 Agent？
    └── 有没有可操作的共识框架？
```

> 🔑 **L6 第一判断**：这个问题如果纯人工做，调研和建模工作量巨大。Truman 自己的评估是——不带团队的话，**决计不敢启动**。

### 1.3 资源约束与心理门槛

| 约束条件 | 具体情境 | 传统解法 | AI 解法 |
|---|---|---|---|
| **时间** | 春节假期大半夜 | 约专家、组团队、排会议、等产出（数周） | 同时开四路 AI 对话，即时推进 |
| **人力** | 一个人，无团队可用 | 至少需要 2-3 个研究员 + 1 个建模者 | 四个模型就是四个研究员 |
| **专家** | 不好意思找专家，也不方便 | 约访谈、等回复、整理纪要 | AI 本身就是可即时对话的「专家」 |
| **复杂度** | 接近人类组织分工级别 | 调研 + 建模 50-200 小时 | 5-6 小时到 70 分可用线 |

## 三、阶段一：目标锁定（约 15min）

> 这是整件事的**方向舵**。Truman 说：「目标出口一定要明确，我来负责。」

### 3.1 目标是怎么被「压」出来的

Truman 没有泛泛地问「帮我研究一下 Agent 分工」。他先做了三层聚焦：

| 聚焦层次 | Truman 问自己的问题 | 答案 | 排除的内容 |
|---|---|---|---|
| **Why** | 我为什么要做这个研究？ | 我要躬身入局搭建一人公司，Agent 分工是不可绕过的地基级课题 | 纯学术好奇、泛泛学习 |
| **What** | 我要产出什么？ | 一份可指导一堂后续 Agent 架构设计的认知报告 | 大而全的文献综述 |
| **To what standard** | 什么质量算可用？ | 70 分——基本逻辑自洽，关键矛盾被识别，能支撑下一步实操决策 | 完美理论框架、学术级严谨 |

### 3.2 目标的一句话版本

```
研究出口：理解多 Agent 分工的底层逻辑，形成一堂可用的 Agent 架构设计共识。
质量线：70 分，基本可用即可，不追求完美。
约束：单人，春节假期，大半夜，5-6 小时内。
```

> 🔑 **L6 洞察**：目标不是「研究 Agent 分工」，而是「我下一周就要用这个认知来做架构决策」。出口的紧迫感和具体性，决定了整个研究不会散。

## 四、阶段二：调研框架设计（约 30min）

> 这是整件事的**骨架**。不是让 AI 自由发挥，而是人先把「问题应该怎么被拆解」想清楚。

### 4.1 四问框架：从入门到共识的递进链

Truman 预设了四个问题，它们不是并列关系，而是一条**从表到里、从理论到实践、从他人到自己**的推理链：

```
问题一 → 问题二 → 问题三 → 问题四
（外部常识）（底层本质）（案例推演）（形成共识）
   入门       扎根        验证       落地
```

| 编号 | 问题 | 目的 | 推理位置 | 如果跳过会怎样 |
|---|---|---|---|---|
| **Q1** | 现在常识：Agent 分工有哪些初步的常识性经验？ | **先入门**——不凭空造轮子，先搞清楚领域里已经有哪些共识 | 建立知识基线 | 后续讨论全是「我以为」，没有锚点 |
| **Q2** | 探讨本质：人类分工和 AI 分工的底层逻辑，一致性和差异性在哪？ | **回到根源**——不满足于表面对比，追问到组织分工的第一性原理 | 寻找底层不变的东西 | 只在表层模仿人类岗位划分，没有真正理解两个物种的差异 |
| **Q3** | 带入推演：把一堂的组织结构作为具体案例，进行推演 | **验证理论**——把前两步的抽象认知压到一个真实组织里跑一遍 | 理论照进现实 | 理论听起来对，但一到真实场景就变形 |
| **Q4** | 形成共识：带入一堂的基本功清单，和 AI 讨论形成共识 | **可操作化**——把「一堂的能力版图」和「Agent 的分工逻辑」对接起来 | 产出可执行框架 | 只有方向，没有下一步该做什么的具体判断 |

### 4.2 四问的深层设计逻辑

为什么是这四个问题，而不是五个或三个？

```
Q1（常识）→ Q2（本质）→ Q3（验证）→ Q4（共识）

这是一个经典的「认知推进阶梯」：
  先知道别人怎么想（避免闭门造车）
  → 再追问为什么（建立自己的判断力）
  → 再用真实案例检验（避免自嗨）
  → 最后落到自己能用的地方（产生行动）
```

如果反过来：先推演一堂的案例（Q3），再去找常识（Q1），会有什么问题？

> 你会带着一堂的预设去「挑选」符合预期的常识，而不是先建立客观认知基线。**顺序本身，就是方法论的体现。**

### 4.3 里程碑设计：四个节点，依次确认

Truman 把四问拆成四个独立的里程碑，每个里程碑结束时确认共识，不通过不进入下一站：

```
里程碑 1：常识基线建立
  ├── 四个模型各自回答 Q1
  ├── 人对比四个答案，确认常识覆盖是否完整
  └── 共识确认 → 进入 M2

里程碑 2：底层逻辑探讨
  ├── 四个模型各自回答 Q2
  ├── 人交叉验证，识别一致性和关键分歧
  └── 共识确认 → 进入 M3

里程碑 3：一堂案例推演
  ├── 四个模型各自回答 Q3
  ├── 人补充一堂真实信息（模型不知道的上下文）
  └── 共识确认 → 进入 M4

里程碑 4：基本功清单共识
  ├── 四个模型各自回答 Q4
  ├── 人做最终判断和整合
  └── 形成最终报告
```

> 🔑 里程碑的价值不只是「拆任务」，更是**防止研究漂移**。每完成一站，人就停下来判断：方向对吗？缺什么信息？要不要调整下一站的问题？

## 五、阶段三：四模型矩阵设计（约 15min）

> 这是 Truman 这个案例中最独特的架构决策之一：**不只问一个 AI，而是同时问四个，交叉验证。**

### 5.1 四个模型的选择与角色

| 模型 | Truman 选择原因 | 在矩阵中的隐性角色 | 独特价值 |
|---|---|---|---|
| **Gemini** | Google 生态，搜索和知识整合能力强 | 「广域知识库」——覆盖面广，善于从大量信息中提取模式 | 常识基线建立的可靠来源 |
| **GPT** | 推理能力公认最强，深度思考见长 | 「深度推理者」——善于追问底层逻辑和第一性原理 | Q2（本质探讨）的最佳选手 |
| **Grok** | 实时信息 + X 平台数据，独特视角 | 「另类视角」——可能给出不被主流话语覆盖的视角 | 补充其他模型可能忽略的边缘观点 |
| **YAI** | 一堂自研，内置一堂方法论和数据资产 | 「一堂内参」——理解一堂语境，能代入一堂视角 | Q3/Q4（一堂案例推演和共识）的核心 |

### 5.2 为什么是四模型交叉，而不是单选最强？

```text
假设用单一模型：
  GPT 推理强 → 但不知道一堂内部情况
  Gemini 知识广 → 但深度推理不够
  Grok 视角独特 → 但稳定性不足
  YAI 懂一堂 → 但通用知识不如前三者

单一模型 = 单一视角
四个模型交叉 = 四个互相补充和制约的「研究员」
```

四个模型交叉验证会暴露三类信息：

| 交叉验证出的信号 | 含义 | Truman 如何处理 |
|---|---|---|
| **四个模型都这么说** | 高概率是领域常识/共识 | 纳入报告，高置信度 |
| **三个一致，一个不同** | 那个「不同」可能是独特视角，也可能是偏差 | 仔细审视，判断是洞见还是噪音 |
| **两两分歧** | 这个点上没有共识，存在本质争议 | 标记为「开放问题」，不强行统一 |
| **四个都不一样** | 这个问题本身可能没有成熟答案 | 标记为「前沿探索区」，降低结论力度 |

### 5.3 四路并行的具体操作方式

```
Truman 的桌面（推测恢复）：

┌─────────────────────────────────────────────────────┐
│  窗口 1: Gemini        │  窗口 2: GPT              │
│  Q1 当前轮: ...        │  Q1 当前轮: ...           │
│  Q2 待进入             │  Q2 待进入                │
├────────────────────────┼────────────────────────────┤
│  窗口 3: Grok          │  窗口 4: YAI              │
│  Q1 当前轮: ...        │  Q1 当前轮: ...           │
│  Q2 待进入             │  Q2 待进入                │
└─────────────────────────────────────────────────────┘
                ↓
    Truman 居中：同一轮问题，四路同时投喂
    收到四个回答后，对比 → 追问 → 补充信息 → 确认 → 下一轮
```

> 🔑 **关键效率来源**：不是「先和 GPT 聊完，再和 Gemini 聊完，再……」，而是**同一轮问题四路并行投喂**。四路对话同步推进，人的等待时间几乎为零。这就是一个人模拟一个研究团队的效率秘密。

## 六、阶段四：四路并行提问——人的追问艺术（约 3-4h，核心环节）

> 这是整件事**密度最高的环节**。Truman 说：「我负责全程深挖，补充信息，追问和确认。这只是一轮，真实情况是有四轮同时在进行。」

### 6.1 每一路的对话结构（以里程碑 2「探讨本质」为例）

以下是根据 Truman 的描述复原的一路对话的追问链结构：

#### 第一层：投喂框架问题

```
Truman → AI：
「我们现在来探讨一个更根本的问题——人类分工和 AI 分工的底层逻辑，
一致性和差异性在哪？不要只给我表面对比，回到组织分工的第一性原理来思考。」
```

#### 第二层：AI 初答，人判断是否有深度

| AI 可能的回答层次 | 人的判断 | 下一步 |
|---|---|---|
| 表面枚举：「人类按职能分，AI 也可以按职能分」 | ❌ 太浅 | 追问 |
| 有一定深度：提到科斯交易成本理论 | ✅ 有东西 | 沿着这个方向深挖 |
| 提出了一个框架：「人类分工受限于信息处理带宽，AI 不受此限」 | ✅✅ 有洞见 | 要求展开这个框架 |

#### 第三层：人在有洞见的方向上「压深」

```
Truman → AI：
「你刚才提到『人类分工受限于信息处理带宽，AI 不受此限』——
这个点很重要。展开说：这个差异会怎么影响分工的颗粒度？
会不会意味着 AI Agent 应该比人类岗位切得更细？」
```

#### 第四层：AI 展开，人补充水下信息

```
Truman → AI：
「你说的有道理。但带入一堂的真实情况——
我们不是从零开始建一个 AI 公司，而是在一个已有的人类团队基础上叠加 Agent。
这种情况下，Agent 的分工是应该『映射人类岗位』还是『按能力项重新拆』？
这两种路径各有什么坑？」
```

#### 第五层：人做交叉验证

```
Truman 在另一路（比如 GPT）问同样的问题，对比答案：
「GPT 认为应该按能力项拆，Gemini 刚说应该先映射再逐步解耦——
你们两个的分歧点在哪？帮我识别这个分歧背后的假设差异。」
```

### 6.2 人在四路对话中的角色频谱

| 角色 | 具体动作 | 发生频率 | 不可替代的原因 |
|---|---|---|---|
| **提问者** | 根据四问框架，向四个模型投喂同一轮问题 | 每轮 | 问题的质量决定回答的质量 |
| **追问者** | 当回答有洞见但不够深时，追问 2-5 层 | 高频 | AI 不会自动追问自己 |
| **信息补充者** | 补充一堂的真实上下文——组织结构、基本功清单、业务特点——这些信息不在任何模型的训练数据里 | 中频 | 没有这些水下信息，AI 的推演会悬空 |
| **交叉验证者** | 把 A 模型的回答拿给 B 模型评论，识别矛盾和共识 | 中频 | AI 不会主动和其他模型对话 |
| **判断者** | 四个回答中，哪个更有洞见？哪个偏了？哪个可以放下？ | 每轮 | AI 不知道自己不知道什么 |
| **方向修正者** | 当发现某路对话走偏时，拉回框架：「我们回到 Q2 的核心——底层逻辑的差异，不要滑到具体工具选型」 | 低频 | AI 容易在细节中漂移 |

### 6.3 追问的深度标准：什么时候才算「挖够了」

| 信号 | 含义 | 动作 |
|---|---|---|
| AI 开始重复自己的观点 | 这一层已经挖到当前模型的知识边界 | 换模型交叉验证，或进入下一个子问题 |
| AI 给出了一个可操作的框架 | 不只是道理，而是「可以按这个框架做决策」 | 记录为候选结论，进入验证 |
| AI 主动指出自己的不确定性 | 「这个部分目前领域也没有共识」 | 标记为开放问题 |
| 人的直觉说「这个够了」 | 基于 Truman 自身对组织设计的理解 | 相信直觉，不为了深而深 |

## 七、阶段五：整理整合——从四路混沌到结构化初稿（约 1h）

### 7.1 第五步：YAI 一键保存

| 动作 | 工具 | 产出 |
|---|---|---|
| 把四路对话中的关键讨论文档，用 YAI 一键保存到「笔记本」 | YAI | 原始对话的 Markdown 文档集合 |

> 🔑 这一步看似简单，但如果没有「一键保存」，人会陷入手动复制粘贴的泥潭。**工具链的顺畅度，直接决定了整体工作流的摩擦系数。**

### 7.2 第六步：Trae 初加工

| 轮次 | 输入 | AI 做什么 | 产出 |
|---|---|---|---|
| **第一轮** | 四路 Markdown 原始对话 | 提炼各路的框架性观点，合并同类项 | 初版框架大纲 |
| **第二轮** | 初版框架 + 人的反馈 | 消重——四个模型说了很多相同的东西，合并；识别四个模型的核心分歧 | 消重后的结构化草稿 |
| **第三轮** | 结构化草稿 | 按四问框架重新编排，补充过渡和逻辑连接 | 初步整合报告 |

### 7.3 为什么是「AI 初加工 + 人终判」，而不是「人直接整合」

| 纯人工整合 | AI 初加工 + 人终判 |
|---|---|
| 四路对话可能有几千行文本，通读一遍就要 1-2 小时 | AI 几秒扫完，提取关键框架 |
| 人容易遗漏某一路的某个好观点 | AI 不会遗漏（只要文档完整） |
| 人的归纳容易受最后看到的那一路影响 | AI 的归纳相对均匀 |
| 但人的判断力——什么是真正重要的洞见——AI 没有 | 人的最终判断保住质量 |

> 🔑 **L6 协作逻辑**：AI 做「不丢东西」的粗加工，人做「知道什么重要」的精判断。二者的比较优势刚好互补。

## 八、阶段六：人工整合与终判（约 30min）

### 8.1 人在终判阶段做的四件事

| 动作 | 具体内容 | 为什么 AI 做不了 |
|---|---|---|
| **补魂儿** | 一份关于 Agent 分工的报告，如果没有「一堂的味道」——务实、方法论驱动、不追风口——就是通用报告 | AI 不知道一堂的魂儿 |
| **判权重** | AI 的初加工可能把四个模型的观点等权排列。但人知道：GPT 在底层逻辑探讨上的推理更可靠，YAI 在一堂案例推演上更贴身 | AI 不知道哪个来源在哪个话题上更可信 |
| **识别假共识** | 四个模型都用了类似的语言，但人细看发现：GPT 说的「按能力项划分」和 Gemini 说的「按能力项划分」根本不是一回事——一个指拆到函数级，一个指拆到职能级 | AI 容易被表面措辞一致性欺骗 |
| **压结论** | 把「有道理的方向」变成「可操作的共识」——不是综述，而是判断：「对一堂来说，第一阶段应该先 X，因为 Y」 | AI 不敢替你做决策 |

### 8.2 70 分的含义

Truman 说最终质量到了「大概 70 分的质量线，基本可用了」。70 分在 Truman 的语境里，不是及格线，而是**决策可用线**：

| 70 分的含义 | 不是 100 分 |
|---|---|
| 核心矛盾被识别了 | 所有细节都完美 |
| 关键逻辑自洽 | 每个结论都有充分论证 |
| 能支撑下一周的架构决策 | 可以发表成论文 |
| 开放问题被标记了，没有被假装不存在 | 所有问题都有答案 |

> 🔑 **L6 的质量观**：不追求一次性做到 100 分，而是追求**在 5-6 小时内做到 70 分可用**。剩下 30 分在后续的每一次实操中逐步逼近。这是「和时间做朋友」和「追求完美一次交付」的本质区别。

## 十、双三角模型在案例中的透传

通过这个案例可以清晰看到双三角模型的两个维度同时在工作：

### 10.1 双三角的双层联动

```
双三角模型

维度一：人 × AI × 方法论
维度二：微观 × 中观 × 宏观

在本案例的联动：
  微观层：每一轮提问——人对 AI 追问问什么、怎么问
  中观层：四模型矩阵设计——Gemini/GPT/Grok/YAI 的选型和角色分配
  宏观层：整个研究的战略方向——「一人公司 2026 年成熟」的预判驱动
```

| 层次 | 人做什么 | AI 做什么 | 方法论托什么 |
|---|---|---|---|
| **微观**（单轮对话） | 追问问到有洞见为止，判断回答质量，补充水下信息 | 按框架回应，展开推理 | OSCAR 追问链，四问框架 |
| **中观**（四模型矩阵） | 设计四模型角色，交叉验证，对比四路答案 | 各自从独特视角补充 | 交叉验证逻辑，里程碑确认法 |
| **宏观**（战略方向） | 躬身入局一人公司预判，选择攻克 Agent 分工这个地基级课题 | 提供知识广度和推理深度 | 2026 一人公司趋势预判，一堂基本功清单 |

### 10.2 一个具体的双三角瞬间

当 Truman 在 GPT 那一路追问「人类分工受限于信息处理带宽，AI 不受此限」时：

```
微观：这一轮追问，人在深挖 AI 的洞见
中观：同时在其他三路，也在问同一层问题，等着对比
宏观：这一切服务于「我要为 2026 年一人公司建 Agent 架构」的战略
```

> 🔑 这就是双三角三层同时运转的真实感觉——不是学完模型再去用，而是在每一个追问的瞬间，三层同时在发生。

## 十一、可迁移的 L6 原则清单

### 11.1 不要做的事

| 错误 | 为什么不行 | Truman 的正确替代 |
|---|---|---|
| 直接问 AI「多 Agent 怎么分工」 | 问题太泛，AI 会回答一堆正确的废话 | 先设计四问递进框架，把大问题拆成推理链 |
| 只问一个 AI，拿它的答案当结论 | 单一模型 = 单一视角，误把偏见当真理 | 四个模型同时交叉验证 |
| 拿到第一轮回答就满意 | 第一轮往往是表面答案 | 追问到有洞见为止，至少 2-5 层 |
| 不补充水下信息 | AI 不知道一堂的组织结构、基本功清单、业务特点 | 在关键推演前，主动投喂真实上下文 |
| 跳过「本质探讨」直接做「案例推演」 | 没有底层逻辑做锚点，案例推演会变成拍脑袋 | Q1→Q2→Q3→Q4，顺序本身就是方法论 |
| 把四个模型的回答简单合并 | 表面措辞一致 ≠ 真正共识 | 人工识别假共识，区分措辞重叠和实质一致 |
| 追求 100 分完美交付 | 50-200 小时的投入不可持续 | 70 分可用即交付，剩下的在后续实操中迭代 |
| 一个人闷头整合四路对话 | 遗漏关键观点，归纳偏差 | AI 先做初加工（不丢东西），人做终判（知道什么重要） |

### 11.2 一定要做的事

| 原则 | 具体动作 | L6 标识 |
|---|---|---|
| **先定出口，再动手** | 用一句话说清「这个研究做完后，我下一周要用它做什么决策」 | 目标驱动，不散 |
| **设计递进框架** | 四个问题不是并列的，而是「常识→本质→验证→共识」的推理链 | 顺序即方法论 |
| **多模型矩阵** | 选 3-4 个有差异化的模型，各自分配隐性角色 | 交叉验证，降低单模型偏见 |
| **里程碑式推进** | 每个里程碑结束确认共识，不通过不进入下一站 | 防止研究漂移 |
| **追问到底** | 对每一个有洞见的回答，至少追问 2-5 层直到触及该模型的知识边界 | 深度不靠一次提问 |
| **补水下信息** | 在案例推演前，把只有你知道的上下文投喂给 AI | 没有水下信息，AI 只能回答「正确的废话」 |
| **交叉验证做判断** | 把 A 模型的回答拿给 B 模型评论，识别矛盾和共识 | 人作为唯一的交叉裁判 |
| **AI 初加工，人终判** | AI 负责「不丢东西」地合并消重，人负责「知道什么重要」地判权重和压结论 | 比较优势最大化 |
| **70 分交付，持续迭代** | 不追求一次性完美，追求 5-6 小时到决策可用线 | 和时间做朋友 |

## 十三、L6 段位自检清单（完整版）

逐条自检——以下任何一条做不到，你还没到这个案例的 L6：

- [ ] 我能否在启动研究前，用一句话说清「这个研究做完后，我下一周要用它做什么决策」？

- [ ] 我能否为每个子问题设定明确的「通过标准」——什么算这个里程碑完成了？
- [ ] 我能否选 3-4 个有差异化特征的模型，并清楚地知道每个模型在这个研究中的独特角色？
- [ ] 我能否同时开四路对话，同一轮问题四路并行投喂，而不是和每个模型依次聊完？
- [ ] 我能否对 AI 的初答追问 2-5 层，直到触及该模型在当前问题上的知识边界？
- [ ] 我能否在关键推演前，主动把只有我知道的水下信息（组织结构、业务特点、真实约束）投喂给 AI？
- [ ] 我能否把 A 模型的回答拿给 B 模型评论，做真正的交叉验证，而不是简单对比四份答案？
- [ ] 我能否在 AI 初加工后，识别出「四个模型表面措辞一致但实质不一致」的假共识？
- [ ] 我能否接受 70 分交付——核心矛盾被识别、关键逻辑自洽、能支撑下一周决策——而不是追求完美？
- [ ] 我能否清楚区分：哪些环节人不可替代（定目标、追问、交叉验证、终判），哪些环节 AI 能做得更好（知识广度、初加工、消重）？
- [ ] 做完后，我能否把四问框架、四模型矩阵、追问序列沉淀为可复用的研究模板？

---

> **一句话总结**：AI 组织认知研究的 L6 精髓，不是「Truman 用四个 AI 聊了个天」，而是他**先用四问递进框架把混沌问题拆成推理链，再用四模型矩阵制造交叉验证的多视角场，然后在每一路追问到底直到触及模型的知识边界，最后让 AI 做不丢东西的初加工、人做知道什么重要的终判**。全程人的核心角色不是「提问者」而是「追问者 + 交叉验证者 + 最终判断者」。**人的深度决定了研究的深度，四个模型的广度决定了研究的覆盖率，中间是四问框架 + 双三角在托住整个协作系统的推理质量。**

# 研究：Claude + Codex + Grok 多 AI 协作工作流

> 来源核验（2026-10-16）：公众号正文抓取成功。作者「希声碎碎念」，内容为个人实操经验，含可验证的安装/流程细节（Claude Code、Codex CLI、Grok Build CLI、EGO 浏览器、HANDOFF.md），判定来源真实、关键事实可查证。外部观点 → 先落 02，待本人实践验证后升 03。

## 一、协作分工（核心）

| 角色 | 分工 |
| --- | --- |
| Claude Code | 总协调：沟通需求、把任务派给 Codex/Grok、拿到结果后检查并继续安排 |
| Codex | 执行活：作图、功能检查、初审、体验验收（EGO 浏览器） |
| Grok | 按需加入：重要事情多拉一个模型讨论；Codex 额度不够时顶上 |

- 原理：接通插件和 CLI 后，Claude Code 可以**自己拉起** Codex 或 Grok，全程不需要复制粘贴。
- 适用：不懂编程但用 AI 做网站、做工具、整理资料的人。

## 二、网站开发流程顺序

讲清需求 → 找参考 → 做 Demo → 确认后小步开发 → 功能与用户体验验收 → 上线 → 看数据复盘。

## 三、上线前要点

1. **尽量测试**：开发时已让 AI 检查代码；上线前让它控制浏览器把完整功能跑一遍（手机和电脑都要看；按钮跳转、返回上一步；重点测付款、套餐、多语种）。
2. **接好分析工具**：Google Analytics、Search Console、Bing 站长工具、Clarity。
3. **用户体验优化**：AI 只做功能不做体验。另开 Codex 窗口用 EGO 浏览器从目标用户角度做用户流程体验验收（Claude 安全锁得死，不愿做创建账号、复制密码类操作）。

## 四、上线后

- 定期把 GA / Search Console / Bing 站长 / Clarity / 服务器数据交给 AI，结合实际页面看数据再优化。

## 五、多任务窗口收尾（HANDOFF.md）

多项目并行时：把启动方法、环境配置要求、各任务进度、关键决定、已知问题和下一步整理到根目录 HANDOFF.md；应保留的代码和文档提交推送 GitHub，确认同步；未完成工作妥善保存，不强行合并或丢弃。

## 六、一句话总结

> 想不清楚，让它们一起讨论；确定好了，让它们去干；做完换一个来挑问题。

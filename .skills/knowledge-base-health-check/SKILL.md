# 知识库体检（Health Check）

定期给知识库做全维度体检，保证"进来的是好东西，出来的一定不是垃圾"。

## 触发场景

- 用户要求体检/检查/清理/诊断知识库
- 双周定时任务触发（每月 1 日、15 日 10:30）
- 大批量写入后需要验证质量

## 检查范围

根目录：`/Users/panda/Desktop/knowledge-base`（00-天一生水 / 01-实事求是 / 02-解放思想 / 03-知行合一 / 04-作品出口 / 05-收件箱）

## 体检维度（9 项）

### 1. 结构健康
- 断链：`[[链接]]` 指向不存在的文件（排除代码块、排除行内反引号教学文字、排除 `00-天一生水/01-系统文档/AI教育课沉淀/meta/` 报告类文件中的描述性 `[[`）
- 孤儿：无任何入链且无出链的孤立文件（图谱孤岛）
- 根目录散文件：直接落在 vault 根目录的 .md（应归四层）
- 同名文件：basename 重复处显式列出（链接有歧义，需人工确认）
- 文件名不规范：`.md.md` 双后缀 / `.md__hash` 中缀 / 非法字符（基本法 2.1），只报告不扣分

### 2. 质量合规
- 空文件（<100 字节）
- 疑似垃圾小文件（<500 字节且无 YAML）
- 无 YAML frontmatter 的笔记
- 缺 source 的笔记（01 层事实型必须；03 实践型建议有；00 层系统文档可补「自创/知识库内部」）
- 文件读取失败（编码/损坏）必须显式报出，不得静默当空文件处理

### 3. 冗余检测
- 指针/骨架文件：`type: 指针` 或正文含"本文件为指针"（完整转写后应清理）
- 高度相似标题（basename 去标点后 Levenshtein 相似度 > 0.92，疑似重复主题）——排除：去标点后同名（不同目录模板）、openclaw 系统文件（各 agent 一套）、版本序列（V0.2/V1.0 等，过程数据必须保留）
- 超大文件（> 200KB，检查是否需拆分）

### 4. 时效
- 超过 90 天未更新（mtime）的笔记（可能是死笔记）
- 超过 30 天未处理的收件箱文件（05-收件箱应保持空）

### 5. 价值评估
- 新增笔记：近 14 天新增/更新的笔记清单（评估输入价值）
- 枢纽笔记：入链 Top10（知识图谱核心）
- 零入链但有实质内容（>5KB）的笔记：潜在高价值孤儿，建议检查是否需要链接

### 6. 结构分布
- 四层 + 收件箱的文件数分布
- 根目录 vs 子目录落位合规率（基本法 2.1/6.5：必须落子文件夹）

### 7. 断链率红线
- 断链率 > 5% 判定「结构异常」，报告中显著标红，必须优先修复

## 执行流程

1. 运行 `scripts/health_check.py`（Python3，无第三方依赖）
2. 脚本产出：`00-天一生水/01-系统文档/知识库体检/体检报告-YYYY-MM-DD.md`（总分 + 各维度明细 + 问题清单）
3. AI 阅读报告，补充分类：哪些是历史遗留、哪些需用户决策、哪些可立即修复
4. 汇总输出：健康总分、关键问题、清理候选清单（只列不改）、价值亮点
5. 删除/移动任何文件前，必须向用户列出候选清单并获得确认

## 输出规范

- 总分 0-100：结构 30% + 质量 30% + 冗余 20% + 时效 10% + 价值 10%
- 报告头部放一句话健康结论 + 总分
- 问题按严重度排序：🔴 红线 / 🟠 需处理 / 🟡 建议
- 清理候选单独一节，每条含：路径、类型、理由、建议动作（删/归档/合并）
- 每次体检在 `00-天一生水/01-系统文档/知识库体检/` 留档，便于对比趋势

## 红线与安全

- **绝不自动删除**：任何文件删除/移动必须先列清单经用户确认
- 只读扫描 + 写报告；不改动任何笔记内容
- 报告生成失败时，先修脚本再跑，不允许"假装体检通过"
- **断链等文档问题必须修在文档本身，不降检测标准**：发现误报时修脚本 bug（让脚本说真话），绝不为兼容错误而放宽判定
- **检测口径变更必须版本化留痕**：引擎版本号写入报告头部；改动记入 vault-log 并说明对历史分数可比性的影响；同日重跑会覆盖报告，需要对比时先另存

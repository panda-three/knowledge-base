# 课件共创工作法

教师与 AI 双向协作做课件：**教师出讲法，AI 出实现**。页面承载的是教师的讲法，不是 AI 编的课堂设计——这是本工作法的第一原则，所有步骤都为守住它而设。

完整流程 7 步，按序执行，教师确认节点不可跳过：

## 第 1 步 · 骨架提取

拿旧课件/往届 PPT（教师的主要备课素材），跑 `scripts/extract_skeleton.py` 提取逐页结构：

```bash
python scripts/extract_skeleton.py <旧课件.pptx>
```

产出「页序 + 活动位 + 密度」骨架表（页码、环节、页面内容、现场动作位），交教师确认"这是不是我实际讲法"。同时检查失效元素（外链视频、空备注、图片型内容需读图核对）。**没有旧课件时改为访谈：让教师口述课时流程，整理成骨架表再确认。**

## 第 2 步 · 讲法归位（不可跳）

让教师**随口说说这节课怎么讲**——语音、文字、想到哪说到哪都行，30 秒也算数。把碎片逐页归位到骨架上；缺口页 AI 逐页反问，**一次只问一页一个问题**。没有本课口述素材，不进下一步（这是 2.1 课实测翻车换来的硬规则）。

## 第 3 步 · 骨架定稿

教师对页数结构拍板。注意：**页数不设死上限**——互动环节（现场演示、全班接力、生活举例）应拆独立成页；动画分步不占文字密度预算。密度上限管的是每页文字量（板书型≤50字、提示型≤100字、讲义型≤150字），不拿它压缩教学环节。

## 第 4 步 · 纯换皮小样

选 3 页代表页型（讲授页/活动页/小结页），**内容与骨架 1:1，零新增元素**，只换视觉风格。用 `scripts/darktech_lib.py` 构建（默认暗色科技风，视觉令牌见 [references/visual-tokens.md](references/visual-tokens.md)，教师另有定版风格则沿用其令牌）。

## 第 5 步 · 亮点提案（每课必做，不默认跳过）

教师试讲小样顺了之后，**主动**提出亮点提案：
- 每个亮点给 **A/B 选项**，教师选或否；
- **优先从教师自己的材料里找潜力**（可运行的源代码、可现场演示的环节、可类比的案例），不外加机制；
- 内容方向词（"游戏化""加积分"之类）永远不出现在 AI 的默认动作里——方向教师说，方案 AI 提案、教师拍板。

## 第 6 步 · 全套生成

按定稿骨架生成全套，硬性要求：
- **每页备注**：写"【AI初稿·结合你的讲法】"开头（已采集语音则替换为教师原话整理稿，保留原话用词只顺句子）；
- **动画**：教学节奏用逐元素单击出现（`darktech_lib.add_click_appear`，一组=一个元素，**不要多元素绑同一次点击**）；流程图接力这类互动页，屏幕初始只留起点，学生说一步、点一步；
- **数字纪律**：教材/旧课件数据零改动，每个数字登记来源。

## 第 7 步 · 试讲采集与迭代

教师对着每页空讲 60 秒发语音 → 转文字整理成该页正式备注（保留原话，只顺句子不改说法）。讲不下去的页=页面缺话（补备注），被页面牵着走的页=页面抢话（删字）。课后反馈**精确到页码**局部迭代，不做整份重生成。

## 硬规则与参考

- **12 条硬规则全文**（教案流优先、两钉死、密度分档、数据台账、四道节点、大纲可改性、风格复用、文体先行、三分文本、试讲测试、换皮与创新分离、语音归位不可跳）：读 [references/rules.md](references/rules.md)，动工前必读。
- **视觉令牌**（暗色科技定版：色值/字体/页眉/卡片/终端块规范）：读 [references/visual-tokens.md](references/visual-tokens.md)。
- **交付验收门禁**（备注非空标记、渲染目检、动画 spid 校验、数据风险表、云盘原地覆盖）：读 [references/delivery.md](references/delivery.md)，交付前必查。

## 边界

- 教师私人上下文（学生特点、奖励习惯、逐课反馈修正）**不写进本 Skill**，走个人记忆——流程听 Skill 的，教师和学生的事实听记忆的。
- 课堂游戏/互动工具需浏览器运行时，走 `app_builder` 生成 HTML 交付，游戏规则忠实还原旧课件原版，不发明新规则。

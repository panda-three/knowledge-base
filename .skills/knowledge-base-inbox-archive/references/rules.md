# 分拣规则详情

> 本文件是 SKILL.md 执行流程的规则细则，供 AI 在分拣时对照。权威源头在知识库基本法（路径见 SKILL.md），冲突时以基本法为准。

## 一、留存筛选四类标准（判定问题）

| 标准 | 判定问题 |
| --- | --- |
| ① 结构符合/新体系 | 它能放进现有某个子文件夹吗？还是开创一个新体系？ |
| ② 事实可验证+可成案例 | 里面的数据/事实查得到吗？能变成教学/思考案例吗？ |
| ③ 新启发 | 读完有没有产生新的认知或联想？ |
| ④ 知识库逻辑补充 | 它是知识库逻辑里缺的一块拼图吗？ |

**输出要求**：每条输入给出"留/不留+理由"，不许只写结论不写依据。

## 二、来源核验

1. 来源真实：域名/账号/作者真实可查，非编造或二手转述无出处；
2. 发布者可靠：一手 vs 转述、机构 vs 个人、知名平台与否；
3. 事实可查证：关键事实/数据能多方印证或有原始出处。

核验结果写 YAML `source`（01 必填）。核验不过降级 02 标 `status: 初稿`；完全不可信不留。

## 三、知识类型判定（可多选，取主属性）

| 类型 | 定义 | 与库内已有内容关系 | 典型去向 |
| --- | --- | --- | --- |
| 新知识 | 库中没有的全新内容 | 无重复 | 按四层规则正常落位 |
| 旧知识 | 库中已有相同/近似内容 | 重复 | 无增量→不留；有增量→补充原笔记或独立落位 |
| 已验证知识 | 库中已有且已通过验证 | 重复但已验证 | 优先合并引用，不重复存 |
| 强逻辑关系 | 与库内某主题强关联（补充/冲突/延伸/应用） | 关联 | 落关联主题文件夹，YAML `related` 关联 |
| 案例类 | 可作教学/思考案例 | 案例素材 | 01（可验证）或 03/95-素材 |
| 证明类 | 可作某观点/结论的证据 | 证据 | 01（可验证证据），`related` 关联结论笔记 |

## 四、四层去向细则

### 01-实事求是
只收**可验证事实/成熟方法论/一手资料**。用户亲手放置的成熟课程体系是它的主体。观点、新方法论、时效性评测一律不进 01。

### 02-解放思想
新观点、假设、思考、研究笔记、外部方法论课程、时效评测。**默认先到这里，验证/实践后升 03**。子域参考：01-AI思考、02 刻意练习、03-原则思考、99-其他。

### 03-知行合一
本人亲身实践过的、可复用的素材。状态目录：备→练→复→AI化→成品；新增默认 `status: 待应用`。判断是否"做过"看四类凭证：用户声明/复盘产物/迭代痕迹/作品库状态；凭证缺失即待应用。

### 00-天一生水
规则与关于我：任务→`01-系统文档`、规则→`03-基本法`、评估→`06-评估报告`、画像→`04-灵魂校准`、日志→`00-vault-log.md`。

## 五、文件名与 YAML 规范

- 文件名：类型前缀 + 主题（≤15 字），如 `研究：xxx`、`思考：xxx`、`方法：xxx`、`案例：xxx`、`任务：xxx`；
- YAML schema：
  ```yaml
  ---
  type: 研究/思考/方法/案例/任务/系统任务/...
  status: 初稿/待应用/运行中/待确认/...
  date: YYYY-MM-DD
  source: 来源描述（链接/作者/渠道）
  audience: 自己/AI/学员/...
  tags: [关键词]
  related: [相关笔记名]
  ---
  ```
- 版本信息进 YAML（series/changelog），文件名不带版本号后缀（版本=过程数据，复盘核心资产）。

## 六、意图识别（A/B/C）

- **A 任务指令**：让我做事的 → 归档 `00-天一生水/01-系统文档/任务：*.md`（原话+AI 解析+状态待确认）；
- **B 资料入库**：链接/文件/素材 → 进收件箱按流程分拣；
- **C 混合指令**：先存素材+附带要求 → 按主意图处理，要求单独记录。
- **合并规则**：同一意图的连续消息合并为一条输入（如"链接+帮我把这个转成 md 存进知识库"），不逐条拆开。

## 七、原件归档制（安全机制，不可删除）

- **收件箱分拣后原件不删除**，原样移入 `00-天一生水/99-归档/收件箱原文/YYYY-MM/`；
- 留、不留、待裁决的条目**都进归档区**（归档区=完整留痕）；
- 落位文件加一行 `> 原件归档：99-归档/收件箱原文/YYYY-MM/<原名>` 便于追溯；
- **成品特例（2026-09-17 定）**：当输入本身就是成品——无需提炼加工、落位动作=原样放置（如已转录完成的课程文档、已定稿文件、最终形态素材），归档区**不再整份复制原件**，只记一条索引说明（`.md`，含原件名/落位位置/日期/来源），原件本体即落位文件。判断标准：落位文件与原件内容无差异（未发生转化动作）；
- **归档区清理**：AI 只做"30 天体检标记可清理候选"（对应落位文件已完整涵盖原件内容时），**删除永远由用户确认**；用户说"清一下归档区"→ AI 列《可清理候选清单》→ 用户拍板 → 才删；
- 每次归档汇报附一句归档区规模，让用户对堆积有感知。

## 八、接收与分拣分离

- **接收**（定时任务做）：拉飞书「知识库输入」群新消息 → 落 `05-收件箱/`（原文+来源+日期+意图标记），不分类；
- **分拣**（本 skill 做）：扫收件箱 → 留存筛选 → 核验 → 判定 → 落位 → 原件移归档区；
- 收件箱是多来源缓冲区（飞书群/其他对话/手动文件），分拣时不假设来源只有飞书群。

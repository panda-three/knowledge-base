# What Is 图解工具使用规范：用大图少字的 HTML 页面解释任何概念

## 🧠 摘要
### **🤔 这个工具是做什么的，什么时候用？**

它是一个**图片优先**的解释工具，用大图代替大段文字讲清概念。
- **触发场景**：用户输入 `/whatis <topic>`，或询问「某物是什么 / 怎么运作」且更适合用图表说明时。
- **目标读者**：对该主题**一无所知**的人。
- **核心原则**：**big pictures and few words**（图大字少）。

### **💻 输出形式有什么硬性要求？**

必须输出**自包含 HTML 文件**，不能依赖外部资源。
- **环境限制**：当前环境无 Artifact 工具 → 直接写完整 HTML 到临时目录（如 `$TMPDIR` 或 `/tmp`），再用 `open` 打开。
- **依赖要求**：所有样式和图表都**内联**（inline SVG/CSS），**零外部依赖**。
- **信息真实性**：上下文不足时先自行收集 → 图中每个节点都要有证据支撑，**严禁编造**。

### **📐 图表该怎么画，有哪些类型可选？**

用 SVG 画**真实图表**，类型自由组合，表达优先于模板。
- **可选图表类型**：
  - 流程类：flowchart（流程图）、sequence diagram（时序图）、state diagram（状态图）
  - 结构类：architecture/block diagram（架构/框图）、C4、dependency graph（依赖图）、call graph（调用图）
  - 数据类：ER diagram（实体关系图）、class diagram（类图）、DFD（数据流图）
  - 组织类：swimlane（泳道图）、deployment diagram（部署图）、timeline（时间线）、Gantt（甘特图）、git graph（Git 图）
  - 对比类：before/after comparison（前后对比）、bar/line chart（柱/折线图）、treemap（树状图）、heatmap（热力图）
- **禁用情况**：表格只用于枚举，**不算图表**。
- **自定义权限**：没有合适模板就自己设计 → **表达优先**。

### **🎨 好图表的设计标准是什么？**

**让结构一眼可见**，读者扫一眼就能抓住主干。
- **形状语言**：boxes = 组成部分，arrows = 动作/交互，lanes = 参与角色，时间**单向流动**。
  说白了，就是用大家眼熟的图形语言，不用看图例也能懂。
- **双层阅读**：
  - **远看（主干层）**：每框一个名字，每箭一个动词，一条清晰主路径。
  - **近看（细节层）**：更小、更暗的注释，**不抢主干视线**。
- **配色方案**：暖色调纸张背景 + 墨色文字线条 + **一种低饱和度强调色**；状态用标记和线宽区分，色调统一。
- **单图原则**：一张图只讲**一个核心点** → 内容装不下就拆分或总结尾部，**绝不缩小字号**。
- **检验标准**：只看图表和标题说明，就能读懂**全部内容**。

### **📄 页面排版有什么要求？**

宽内容栏 + 双侧边距，图表通栏、文字收窄。
- **图表宽度**：每个 SVG 设 viewBox 和 `width:100%` → 随窗口**自适应缩放**，占满整栏。
- **正文宽度**：散文文字在栏内**更窄的行宽**里，保证可读性。

### **🌐 语言上要注意什么？**

解释文字**匹配用户语言**，专业术语保留英文原文。
- **技术名词**：API 名称、CLI 命令、精确错误字符串 → **一律原样保留英文**。

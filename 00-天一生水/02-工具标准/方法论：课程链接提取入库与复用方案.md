# 方法：课程链接提取入库

**一句话结论：** 课程站在登录墙后面，核心套路是"浏览器登录→慢滚采集→清洗拼接→lark-cli入库"，8步可复用。

---

## 一、核心交付

- 8步可复用工作流（登录→采集→清洗→拼接→校验→结构化→入库→验证）
- 6条关键经验（读不到→存不好→清洗→拼接→标准通道→回读验证）
- 跨对话复用方案：Skill为主+主提示词为备

## 二、关键框架

### 2.1 8步工作流

| 步 | 做什么 | 关键坑 |
|---|---|---|
| 0 环境前置 | lark-cli可用+去代理 | 必须加env -u前缀 |
| 1 登录墙 | 浏览器打开→用户接管扫码 | 不要绕行硬抓 |
| 2 判断渲染 | get_page_text()长度判断 | 懒加载虚拟列表 |
| 3 慢滚采集 | 小步长慢速滚动+每10步存快照 | 滚动太快漏内容 |
| 4 文本清洗 | 摘TOC→截评论→去页脚→去UI标签 | 成败关键 |
| 5 完整性校验 | 章节标题核对+无评论残留 | 防止漏章 |
| 6 结构化MD | 大章节转##，小节转###，列表合并 | 只转首个标题行 |
| 7 写入知识库 | docs +create → wiki +move | 全程user身份 |
| 8 验证交付 | fetch回读核对→present_files交付 | 用不同路径验证 |

### 2.2 6条关键经验

1. 先解决"读不到"再谈"存得好"
2. 识别页面渲染机制（懒加载必须慢滚）
3. 清洗是质量核心（摘TOC/截评论/去页脚）
4. 拼接用"后缀-前缀最大重叠"去重
5. 写入走标准通道（docs +create → wiki +move）
6. 交付前回读验证（用不同方式核对）

### 2.3 复用方案对比

| 方案 | 优点 | 缺点 | 适用 |
|---|---|---|---|
| Skill（推荐） | 新对话丢链接自动触发 | 依赖技能被扫描 | 日常高频 |
| 主提示词 | 100%可控 | 每次需粘贴 | Skill未生效兜底 |
| 经验文档 | 随时可查可迭代 | 需主动查阅 | 长期沉淀 |

## 三、我的批注

- 我的：这套流程已固化为course-doc-to-feishu Skill，以后丢课程链接即可
- 待验证：同法是否适用于小鹅通/得到等其他登录墙课程站

# 方法：截图转文字SOP

**一句话结论：** 给一个图片文件夹路径，自动按文件名顺序转录→按叙事拆3-6篇→存入飞书知识库——已固化为Skill，只需发文件夹。

---

## 一、核心交付

- 5次任务复盘对比（产物形态/命名/结构/问题）
- 7条做对了的经验+8条待改进不足
- 8步标准流程SOP（前置→排序分段→逐张读取→结构化→拆分→建父节点→建子文档→校验交付）

## 二、关键框架

### 2.1 产物命名基准（以07为标杆）

| 层级 | 规范 |
|---|---|
| 父节点 | `0X 课程名-截图笔记`，编号顺延 |
| 子文档 | `0N 内容主题（截图a-b）`，不带.md后缀 |
| 拆分数 | 3-6篇/课程，单篇3000-12000字 |

### 2.2 7条经验

1. 忠实转录、按图编号顺序，不做概括改写
2. 纯文字不插图
3. 结构分层：h1=截图编号，h2=课件板块
4. 长图>4000px先按3800px分段再读
5. 界面截图括注法（界面：核心信息）
6. 写入链路稳定：init-draft→parse→create→node-list→fetch
7. lark-cli前必须去代理

### 2.3 8条不足待改进

| # | 问题 | 改进方向 |
|---|---|---|
| 1 | 拆分粒度不统一 | 统一按叙事阶段拆3-6篇 |
| 2 | 子文档命名不统一 | 统一为「0N 主题（截图a-b）」 |
| 3 | 历史文档保留图片引用 | 按需清理 |
| 4 | 06以file类型存在 | 统一用docx类型创建 |
| 5 | 转录忠实度口径未定 | 正文忠实原文，仅修正OCR噪声 |
| 6 | 长图分段依赖临时脚本 | SOP中写成可复用脚本 |
| 7 | 缺少文件夹预检 | 先检查格式/尺寸/命名/混入文件 |
| 8 | 未固化为一键流程 | 固化为Skill |

### 2.4 8步SOP

| 步 | 做什么 |
|---|---|
| 0 | 前置检查：列文件+确认知识库+去代理 |
| 1 | 排序与长图分段（>4000px按3800px切） |
| 2 | 逐张读取转录，每读一张核对编号 |
| 3 | 结构化XML：title/h1截图编号/h2板块 |
| 4 | 按叙事阶段拆3-6篇 |
| 5 | wiki +node-create建父节点 |
| 6 | docs +create逐篇建子文档挂父节点 |
| 7 | node-list确认挂载+fetch抽查 |
| 8 | present_files交付链接 |

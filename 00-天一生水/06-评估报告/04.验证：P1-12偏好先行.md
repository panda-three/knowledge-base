# 验证报告：P1-12 偏好先行（2026-11-18）

> 一句话本质：先读偏好确实让回答更贴要求，但天花板卡在「偏好有没有落纸」——3 例回归里 2 例命中落纸条款，1 例因偏好没落纸且条款互相打架而失守。

## 一、验证设计（假设驱动）

- **假设**：Agent 先读偏好说明 → 回答更符合要求
- **基线（B 组）**：P0-1 清单 3 例真实失败（案例 8 范围 / 9 术语 / 12 抽象），均标注「偏好没用上」，出处工作日志 11-11 / 11-18，非现编
- **实验（A 组）**：本次会话已按启动序列读完 AGENTS / SOUL / USER / MEMORY，对同一场景重答
- **判据**：重答能否命中一条**明确落纸**的偏好原文，并指回出处
- **过线**：3/3 成立；2/3 部分成立标缺口；≤1/3 不成立
- **局限**：非双盲、单一执行者、样本 3；重答者已知失败案例，存在过度拟合风险

## 三、结论

1. **判定**：2 ✓ + 1 ⚠ → **部分成立**（按过线标准 2/3），未达 3/3。
2. **假设修正**：先读偏好有效，但**有效性上限 = 偏好落纸的完整度**。落纸的（白话 / 清单 / 概要）管用；没落纸的（先确认范围、要具体条目）读不到，自然用不上。
3. **关键发现**：P0-1 归因「库里已有偏好但没用上」不完全属实——3 条里仅 2 条有落纸支撑；「先确认范围」「要具体条目」全库 grep 只出现在 P0-1 清单自身（自证），无独立偏好条目。且 SOUL「不逐步确认」与「开工先对范围」是条款冲突，先读偏好也可能读出一堆互相打架的指令。

## 四、用户裁决与收口（2026-11-18 16:4X）

- **裁决 ①**：两条「未落纸偏好」**不补**。归因视为复盘包装，P1-12 结论锁定「部分成立」，不再冲 3/3。
- **裁决 ②**：SOUL「不逐步确认」改为「范围清楚直接干，范围不清才先确认」——已执行（SOUL.md 默认协作模式）。冲突由改行为规则消解，不靠补偏好条目。

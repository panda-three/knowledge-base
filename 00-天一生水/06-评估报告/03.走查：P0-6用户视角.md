# P0-6 用户视角走查（2026-11-18）

> 一句话本质：顶层六层第一眼可懂，卡壳集中在第三层——同主题内容散放、索引页命名不统一。

## 一、五个真实场景走查（AI 模拟使用者）

| 场景 | 路径 | 第一眼能否定位 |
|---|---|---|
| 备课找 AI 落地案例 | 01-实事求是/70-案例库/03 专题高手/11 AI 落地高手 | ✓ 目录名直白 |
| 看本周在做什么 | 00-专注区/_本周.md | ✓ 第一眼 |
| 新内容该放哪 | 05-收件箱（唯一入口） | ✓ |
| 查库的规矩 | AGENTS.md | ✓ 根目录可见 |
| 找自己的教学复盘 | 03-知行合一/60-教育与教学 | ✓ |

## 二、卡壳点（3 个，全部有实测出处）

1. **同主题散多处**（用户实测 Y模型暴露）：Y模型内容散在 5 处——实操框架篇、Live 263、Live 265、火种合集、实操行动营；263 按「场次」放、265 按「主题」放，两套逻辑混用。→ P1-9/P1-10 承接，不新增任务。
2. **索引页命名不统一**：`00 课程索引：` / `00 案例索引：` / `00-案例课_索引` 三种前缀并存，按前缀批量定位会漏。→ P1-9 承接。
3. **07 GetNotes**：名字看不出用途。用户已裁决「暂不动」，仅记录。

## 三、结论

- 六层准入结构（01~05 + 00）对使用者和 Agent 都一眼可懂，顶层不动。
- 修正后的 P0-4「一课一卡」直接消解卡壳点 2 的一半：检索卡齐了以后，找内容先命中卡，不再依赖前缀约定。
- 验收口径达成：走查完成，卡壳点全部有归属任务，未新增。

# 文档模板规范 v1（P0-4 + P0-7）

> 一句话本质：把「后面怎么找」写进每篇文档的头部——keywords 管命中，parent 管消歧，骨架管读得快。

## 一、YAML 字段（头部固定 8 字段）

| 字段 | 必填 | 作用 | 写法 |
|---|---|---|---|
| type | ✓ | 文档类型 | 课程笔记/评估报告/索引/SOP… |
| status | ✓ | 状态 | 未标注/进行中/已完成 |
| date | ✓ | 日期 | YYYY-MM-DD |
| source | ✓ | 来源 | 课程名/自创/外部 |
| tags | ✓ | 分类 | 沿用现有，≤3 个 |
| **keywords** | ✓ | **P0-4 检索关键词** | **3-5 个「用户会怎么问」的白话词** |
| **parent** | ✓ | **消歧** | 所属课程/项目索引的相对路径 |
| related | 可选 | 关联 | 相关文档路径 |

## 二、keywords 写法（核心）

1. 写「用户会怎么问」，不写「文档讲什么」
   - 反例：`keywords: [AI落地, 组织变革]`（书面词，没人这么问）
   - 正例：`keywords: [AI改造从哪开始, 一号位, 说服老板]`
2. 问句原词优先（基线实测：问「先影响谁」→ 命中「一号位」）
3. 专有名词必收：人名/公司名/产品名（基线实测：发票SaaS、华熙生物直中）
4. **同概念多写法都收（v1.2 新增）**：空格有无（Y模型 / Y 模型）、全半角、中英文别名——只要库内实际存在多种写法，keywords 全收。依据：2026-11-18 用户实测，行动营目录名带空格，单一写法检索漏掉整门课。

## 三、正文骨架（P0-7）

1. 开头一句话本质
2. 三段式按需：背景 / 要点 / 结论——不强制全有，禁止空段

## 四、配套规则（基线三条发现）

1. 文件名优先含独特专有名词 → 归 P1-9 命名规范
2. 检索降噪（v1.3 扩大范围，已写入 AGENTS.md 铁律 14）：默认跳过 `99-归档` / `meta` / `知识库体检` / 评估台账 / `.backup*` / `local_files.json`——除非问题本身指向它们；体检消歧入口：`01-系统文档/知识库体检/00-体检索引.md`
3. 同名文件靠 parent 消歧（基线实测：图注台账 ×8）

## 五、推行口径（v1.1 修正：一课一卡）

> 依据：检索=「意图→内容」映射。库的自然单元是课不是篇——索引页一处登记服务整课（Y模型实测：索引加 5 词覆盖 8 篇）。

- 新文件：8 字段必须齐
- **存量回填：按「课」补，不按「篇」补**——每门课的 00 索引页（检索卡）加 keywords 覆盖整课；子篇不补，除非独立高频被多处引用（如图注台账）
- 已示范：Y模型体系 4 卡（实操框架篇 / 263 / 265 / 火种合集）
- 全库约 50 门课 → 约 50 张卡，分批补，真实查找撞到哪门先补哪门

## 六、验收

- 冷启动复测同 20 问：一轮直中 ≥15/20（基线 10/20）
- 抽查 keywords：问句词与 keywords 重合时，一轮直中

## 七、元数据六字段对照（P1-8 裁决：层即可信度）

> 依据：一堂「文档头部固定 标题/来源/日期/标签/关联/可信度」（出处：03-知行合一/10-个人成长/00 Y模型/Y模型-知识库.md 第 8 条）。对照结论：六格中五格库内已有，真正缺的只有「可信度」——而本库六层目录已把可信度写进结构，逐篇标注=重复记账。裁决：**不新增字段**。

| 堂字段 | 本库裁决 |
|---|---|
| 标题 | 文件名 + 正文 H1 承担，不进 frontmatter（命名细节归 P1-9） |
| 来源 | 已有 `source` |
| 日期 | 已有 `date` |
| 标签 | 已有 `tags` |
| 关联 | 已有 `related`（可选） |
| 可信度 | **层即可信度，不设字段**：01 原文层=成熟权威；02 框架层=未验证（status: 假设/成型）；03 产出层=亲测实践；04 成品层=敢发学员。跨层例外（如 02 层引用了可信外部数据）用 `related` 指回原文层，不单独标格 |

配套两条：
1. 检索按层定先验：问「成熟方法/外部体系」先查 01，问「我的观点/新假设」查 02，问「怎么做过的」查 03。
2. P1-13 来源分层验证复用本裁决做标注口径，不重复设计。

# 分类判据 v1「同问」（P1-10）

> 一句话本质：**好分类 = 同一层能用同一个问句，问遍所有目录都答得上来。**

## 一、判据怎么用（三步）

1. 挑一层（同一个父目录下的所有子目录）
2. 找一个共同问句（如「这是什么主题？」「这是第几堂课？」）
3. 全部答得上 = 同轴（好分类）；有几个答不上 = 混轴，那几个就是欠账

口诀：**一层一问，问不到就是混轴。**

## 二、为什么是这一条

分类不服务整齐，服务「意图 → 路径 → 内容」这条检索链（与 P1-9 同源）：

- 轴统一 → 落位唯一（内容只落一处，不用猜）
- 轴统一 → 路径可预测（找内容时知道该翻哪一层）
- 轴混 → 同一层里既有「主题」又有「场次」，读者要在两种逻辑间来回切换 = 检索成本

不为分类学纯粹牺牲「打开就懂、一眼看到在做什么」的可用性（SOUL.md 边界）。

## 三、全库体检（2026-11-18 实测）

| 层 | 轴 | 结论 |
|---|---|---|
| 顶层六层 00–05 | 认知阶段（成熟 / 想 / 做 / 敢发 / 规则） | ✅ 一致，不动 |
| 域级 10–90 | 主题领域（三库共用一套） | ✅ 一致 |
| 域下课程目录 | 主题 vs 单次课程 | ❌ 混轴 5 处 |
| 课内篇章 | 课时序 | ✅（课内固定附属位不算混轴） |

## 五、边界（不管什么）

1. **跨层散放 by design**（承接 P1-9）：聚合靠检索卡 / parent，不靠挪文件
2. **课内固定附属位不算混轴**（作业与Candy、一堂活动信息 = 课的组成部分，不与课时并列）
3. 命名细节归 P1-9；元数据归模板规范 v1.4
4. 六层结构、域编号表不动

## 六、执行机制

- **铁律 16 入 AGENTS.md**：启动序列每次必读，这是唯一可靠的闸口（P1-9 v2 的核心教训）

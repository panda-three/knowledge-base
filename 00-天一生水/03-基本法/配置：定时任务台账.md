# 配置：定时任务台账

> 定位一句话：定时任务是「执行器」，规则文档（分拣SOP / 运营计划 / vault-log）与本文档是「唯一权威」——换工具时照本文档重建，不依赖豆包环境。
> 配套（逻辑链）：[[每日收件箱分拣SOP]] / [[知识库运营计划]] / [[00-vault-log]]。

## 三、触发方式总原则（2026-09-17 架构升级确认）

| 环节 | 谁触发 | 说明 |
|---|---|---|
| 接收 | 自动（定时任务①） | 只拉取进收件箱，不分拣 |
| 分拣归档 | 用户触发 | 用户说「归档知识库输入」→ knowledge-base-inbox-archive skill |
| 落位确认 | 用户拍板 | 归档候选清单经用户确认才落位（V1.5 规则：不静默自动落位） |
| 体检 | 用户触发 | 用户说「体检」→ knowledge-base-health-check skill → 用户确认 |

## 四、跨工具替代方案（换 CodeX 等工具时）

1. 豆包 cron **不会迁移**——配置在豆包环境/本机，换工具即失效；
2. 在目标工具用其原生机制重建：Linux cron / HEARTBEAT / AGENTS.md（参考 03-知行合一/06-AI应用/AI 组织/openclaw 的 cron 规范）；
3. 重建依据（全部在知识库内，跨工具可读）：
   - 本文档（职责 + cron + 触发方式）
   - 《每日收件箱分拣SOP.md》（分拣规则）
   - 《知识库运营计划.md》（流水线与落位规则）
   - 00-vault-log.md（任务演变史与检查点）
4. 原则：**规则在知识库，执行器可替换**；任何工具只要能读 md、能跑 cron，就能复刻现架构。

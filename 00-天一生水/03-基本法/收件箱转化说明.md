# 收件箱转化说明

> 收件箱（05-收件箱）不是仓库，是**中转站**：所有输入先落这里，**每日 12:00 集中**转化到四层。
> 本文件记录「收件箱 → 四层」的转化规则与 2026-09-15 首次批量转化明细。
> **节奏变更（2026-09-16）**：改为「先存后分」——「知识库输入」群消息全部先落 05-收件箱，每天 12:00 定时跑一次集中分拣；分类标准（留存筛选 / 来源核验 / 知识类型判定）见《每日收件箱分拣SOP》。
> **输入通道唯一性（2026-09-15 定）**：用户所有输入只走本知识库的 `05-收件箱`；旧库 `memory-base-codex/01 Inbox` 作废，AI 一切操作只在当前知识库目录 `/Users/panda/Desktop/knowledge-base` 下进行。

## 一、收件箱的定位与转化流程

```
「知识库输入」群 / 对话 / 文件
      ↓
① 先存后分  所有新消息先全部落 05-收件箱（原文+来源+日期），不直接分类
      ↓ （每天 12:00 定时触发，当天只跑一次）
② 留存筛选  按四类标准检阅（符合结构/新体系、事实可验证可成案例、新启发、知识库逻辑补充）→ 留/不留
      ↓
③ 来源核验  联网搜索核验来源真实性与事实可靠性 → 写入 source
      ↓
④ 知识类型判定  新/旧/已验证/强逻辑关系/案例/证明（对照库内已有内容）
      ↓
⑤ 转化落位  按四层去向加工（补 YAML + 规范命名 + 移入子文件夹）
      ↓
⑥ 汇报  一句话告知留存/去向/不留原因；明细记入 vault-log
```

**四层去向口诀**：

| 去向 | 判定 | 对应转化动作 |
| --- | --- | --- |
| 01-实事求是 | 外部已有、成熟可信、可验证（成熟方法论/一手事实/经典原文） | 保留原文证据，`source` 必填，type=案例/方法 |
| 02-解放思想 | 带思考印记的新观点/假设/问题/研究（时效评测、新方法论、他人项目研究） | type=研究/思考/方法，status=初稿，先接受验证 |
| 03-知行合一 | 亲身实践产物、可复用素材（教案/复盘/提示词/工具） | type=素材/复盘，按领域或状态子目录归位 |
| 00-天一生水 | 关于「你是谁」和「知识库本身」的规则 | 工具标准→02-工具标准；个人信念→09 关于我 |
| 05-收件箱 | 判不了 | 先暂存，AI 当天再判或问用户 |

### 意图识别规则（2026-09-15 定 · 重点加强）

用户通过「知识库输入」群发来的消息**不是每条独立**，先做意图识别再处理：

| 类型 | 识别特征 | 处理方式 |
| --- | --- | --- |
| A 任务指令 | 让我干的事（"帮我…""增加一个任务…""把 xx 转成 md"） | 落 00-天一生水/01-系统文档 作任务记录，含用户原话+识别出的意图 |
| B 资料入库 | 链接/文档/文字素材，无附加指令 | 按四层规则转化入库 |
| C 混合指令 | 素材 + 一句处理指令（如先发链接，再补"帮我把这个链接转成 md 沉淀到知识库"） | **按指令执行后入库**，素材与指令合并不拆开 |

**合并规则**：
1. 连续多条消息属于同一意图（含手滑补充、先说链接后补说明）→ 合并为一条输入处理；
2. 用户第一版发链接、下面跟一句话指令 → 视为一条「C 混合指令」；
3. 不同意图的消息（如一条是任务、一条是资料）→ 分开处理，各自落位。

**处理原则**：不原封不动堆文件——先识别用户意图（要任务记录？要转 md？要提炼要点？），按意图加工后再沉淀。

**转化时的加工动作**（每条都要做）：
1. 去掉旧 frontmatter（如有），保留正文；
2. 补新 YAML：type / status / date / source / audience / tags / related；
3. 文件名按基本法 2.1 规范化（类型前缀 + 主题，≤15 字，无版本号）；
4. **落位必须到子文件夹**（按《文件夹定义规范》6.5 子文件夹层级规范），绝不落根目录；没有匹配子目录的，新建主题域或进 99-其他；
5. **03 新增产物默认 status=待应用**（无凭证），凭证齐了（用户声明/复盘产物/迭代痕迹/作品库状态）改已应用并视情况移 90-已应用；
6. 移动后从收件箱删除，收件箱保持空。

## 四、后续约定

1. 收件箱**每日一清**：每天 12:00 定时集中处理一次（当天只跑一次），转化后收件箱必须为空；
2. 转化后收件箱必须为空（空是常态）；
3. **转化必须落子文件夹**（见《文件夹定义规范》6.5），根目录只放 _Home；
4. **输入只走本库 05-收件箱**，旧库 01 Inbox 作废，操作只在 `/Users/panda/Desktop/knowledge-base` 下；
5. 每次批量转化在 vault-log 记一笔，重大判定沉淀为规则进《沉淀审美规则》；
6. 用户可随时改判：说「把 xxx 挪到 xx」即执行并同步 YAML；
7. **过程数据规则**：版本文件=复盘核心资产，全部保留（见《知识库运营计划》2.5）；
8. **AI 过程产物落位**：运营类→00-天一生水，内容类→03/04（见《知识库运营计划》2.6）；
9. **成品特例（2026-09-17 定）**：输入本身即成品（无需提炼加工、落位=原样放置，如已转录完成的课程文档/已定稿文件/最终形态素材）时，原件归档区**不再整份复制**，只记一条索引说明（原件名+落位位置+日期+来源）；原件本体即落位文件，避免 447MB 级重复存储。

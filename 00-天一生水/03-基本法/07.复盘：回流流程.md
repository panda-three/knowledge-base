# 复盘回流流程

> 一句话本质：教训写进「下次做这件事时一定会读到的地方」才算回流完成；只留在复盘文档或工作日志里，等于没有。

## 一、什么时候走

1. 出错、返工、被用户纠正之后。
2. 每周复盘（周日，见 `00-专注区/_agent.md` 周末归档）。

## 二、流程

0. **值不值得**：四问——会不会重复、重不重要、偏差大不大、确定性高不高。四问全否，不复盘，结束。
1. **定角度**：决策类（事选得对不对：方向、范围、口径）还是执行类（事做得稳不稳：漏、错、慢）。
2. **复盘**：有 project-retro Skill 就用（完整用 GRAI，小事用 KPT）；没有就答三问——发生了什么、为什么、下次怎么做。原因追到「能改的那一层」。
3. **收口一问**：这次能沉淀什么进库？每条教训写成一句：什么情况下 → 怎么做 → 避免什么。答「没有」也算完成。
4. **落位**：按第三节去向表。先找旧条目改；没有旧条目才新增；和旧条目冲突，改掉或删掉旧的，不并存。
5. **留痕**：在 `00-专注区/_本周.md` 进展记录写一行「教训 → 落在哪」。

## 三、去向表

| 沉淀物              | 去向                                                   |
| ---------------- | ---------------------------------------------------- |
| 全库通用的 AI 行为规则    | `AGENTS.md` 全局铁律                                     |
| 某个文件夹内的规则        | 该文件夹 `_agent.md`                                     |
| 低频专项操作的做法（如批量改名） | 该操作的规范文档，`AGENTS.md` 对应铁律留一句指针                       |
| 用户的偏好、习惯         | `MEMORY.md`（用户确认后写）                                  |
| 未验证的方法、模型        | `02-解放思想`                                            |
| 复盘文档本身           | 知识库自身的 → `00-天一生水/06-评估报告`；教学与项目的 → `03-知行合一` 对应实践对象 |

- 判不了去向：问用户，不硬放。
- 复盘文档在本库落盘：文件名按 `序号.复盘：主题`，不用 Skill 默认的 `retro-` 命名和 `docs/` 路径。

## 四、出处

- 四问、收口一问：`03-知行合一/10-个人成长/00 Y模型/Y模型-知识库.md` 迭代方式·提炼建模第 12、10 条。
- 决策类 / 执行类：`01-实事求是/10-个人成长/02 不断提认知/02 深度复盘/全员必修：深度复盘第一课-课程文档/03-入门：理解复盘价值.md`。

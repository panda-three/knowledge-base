# 每日收件箱分拣 SOP

> 每天 12:00 定时任务触发，把「知识库输入」群的新消息**先全部存进 05-收件箱**，再按本 SOP 完成：留存筛选 → 来源核验 → 知识类型判定 → 四层去向落位。
> 配套规则（逻辑链）：[[知识库运营计划]]（流水线）/ [[配置：定时任务台账]]（执行器清单）。
> 本 SOP 由用户提供的两条分类提示词（留存四类标准 + 来源核验与知识类型分类）改写融合而成，与《文件夹定义规范》四层去向规则、《收件箱转化说明》配套执行。

---

## 一、执行节奏：先存后分，每日一次

```
「知识库输入」群新消息（链接 / 文字 / 文件 / 截图）
      ↓  ① 接收：全部先落 05-收件箱（原文+来源+日期），不直接分类
每天 12:00 定时触发（当天只跑一次）
      ↓  ② 留存筛选（四类标准，见二）
      ↓  ③ 来源核验（联网查证，见三）
      ↓  ④ 知识类型判定（见四）
      ↓  ⑤ 去向裁决与落位（四层规则，见五）
      ↓  ⑥ 汇报 + vault-log 记录
```

**接收时沿用《收件箱转化说明》的意图识别规则**：A 任务指令 / B 资料入库 / C 混合指令；同一意图的连续消息合并为一条输入，不逐条拆开。

---

## 二、留存筛选（提示词1 · 四类标准）

检阅收件箱每一条输入，逐条对照以下四类标准，**任一命中即可留下**：

| 标准 | 含义 | 判定问题 |
| --- | --- | --- |
| ① 结构符合 / 新体系 | 符合现有文件夹结构，或能构成新的知识体系 | 它能放进现有某个子文件夹吗？还是开创一个新体系？ |
| ② 事实可验证 + 可成案例 | 事实可核验，且能围绕我的相关主题变成案例 | 里面的数据/事实查得到吗？能变成教学/思考案例吗？ |
| ③ 新启发 | 能产生新的启发 | 读完有没有产生新的认知或联想？ |
| ④ 知识库逻辑补充 | 库中没有，但按我的知识库逻辑有意义 | 它是知识库逻辑里缺的一块拼图吗？ |

**判定输出**：每条输入给出 **留 / 不留 + 理由**，不许只写结论不写依据。

**不留的典型类型**（参考 2026-09-15 首次转化实践）：
空文件、一次性工具、社媒杂集、鸡汤、无法核验的断言、与库内已有内容完全重复且无增量。

---

## 三、来源核验（提示词2 · 前半）

对「留」的条目，**逐一联网搜索核验**：

1. **来源真实**：域名 / 账号 / 作者真实可查，不是编造或二手转述无出处；
2. **发布者可靠**：权威度判断（一手 vs 转述、机构 vs 个人、是否知名平台）；
3. **事实可查证**：关键事实 / 数据能多方印证或有原始出处。

核验结果写入 YAML `source`（01 必填）：
- 核验通过 → 可按类型正常落位；但是否够格进 01，还须过「三之二、01 准入闸」——来源真实只是及格线，详见下节；
- 核验不过 / 来源不明 → 降级处理：标 `status: 初稿` 进 02 待验证；
- 完全不可信 / 无任何出处 → 改为不留（理由：来源无法核验）。

---

## 三之二、01 准入闸（2026-09-19 定 · 默认拒入）

> 原则：**01 是「升级目的地」，不是「接收口」。** 外部新素材一律先落 02；只有「经过检验、成体系、可直接调用」的成熟体系，经用户拍板才升 01。
> 「来源真实」只是及格线（文章真、作者真），不等于够格进 01——这是本次校准的核心。

**A. 可升 01 的四类（AI 逐项勾验）**
1. 一堂官方课程体系——01 的法定居民（仍需 source / 版本标注）；
2. 经典 / 公认体系——教科书、行业标准、权威机构发布，经过时间或领域公认检验；
3. 高验证度外部作品——须同时满足：来源权威可追溯 ✔ ＋ 经过时间/规模检验（多年沉淀、高 star/引用/大量用户）✔ ＋ 关键事实数据可核验 ✔ ＋ 成体系完整（非零散片段）✔；
4. 本人反复实践验证、**真·成体系、可对外调用**的成熟产物——经用户拍板升 01；否则留 03。

**B. 一律先落 02（不得进 01）**
- 公众号 / 自媒体转述、刚出炉观点、个人假设新思考 → 02；
- 本人的消化再加工 / 点评 / 质疑 → 02；
- 时效评测、行业观察 → 02；
- 「来源真实但内容未经验证」的普通文档 → 02；
- 零散片段、无出处、鸡汤、一次性工具 → 不留或 02。

**C. AI 把关动作（强制）**
1. 默认路径反转：外部素材先落 02，不直接进 01；
2. 命中 A 类才在候选清单标「可升 01」，并附勾选证据（哪条验过、证据链接）；
3. 进 01 的文件 YAML 强制加 `verification:`（方式 / 证据 / 日期）；
4. 拿不准一律降 02，汇报标「疑似可升 01、证据不足待补验」；
5. 任何进 01 的决定都经用户点头，AI 不自动往 01 放新东西。

## 四、知识类型判定（提示词2 · 后半）

对照知识库现有内容（检索相关文件夹），判定每条知识与库内已有知识的关系。**可多选，取主属性**：

| 类型 | 定义 | 与库内已有内容的关系 | 典型去向 |
| --- | --- | --- | --- |
| 新知识 | 库中没有的全新内容 | 无重复 | 按四层规则正常落位 |
| 旧知识 | 库中已有相同 / 近似内容 | 重复 | 判断增量：无增量 → 不留；有增量 → 补充进原笔记或独立落位 |
| 已验证知识 | 库中已有且已通过验证 | 重复但已验证 | 视同旧知识处理，优先合并引用，不重复存 |
| 强逻辑关系知识 | 与库内某主题强关联（补充 / 冲突 / 延伸 / 应用） | 关联 | 落到关联主题文件夹，YAML `related` 关联到对应笔记 |
| 案例类 | 可作教学 / 思考案例 | 案例素材 | 01（可验证案例）或 03/95-素材 |
| 证明类 | 可作某观点 / 结论的证据佐证 | 证据 | 01（可验证证据），`related` 关联到结论笔记 |

## 五、去向裁决与落位（结合四层规则）

按《文件夹定义规范》四层去向 + 判定口诀执行：

| 去向 | 判定 | 加工动作 |
| --- | --- | --- |
| 01-实事求是 | 经过「01 准入闸」勾验、成体系可调用，且用户拍板升级（默认新素材先进 02） | `source` + `verification` 必填，type=案例/方法，保留原文证据 |
| 02-解放思想 | 新观点 / 假设 / 思考 / 待验证 | type=研究/思考/方法，status=初稿 |
| 03-知行合一 | 亲身实践 / 可复用素材 | type=素材/复盘，按状态或领域子目录落位 |
| 00-天一生水 | 关于「你」和知识库本身的规则 | 工具标准→02-工具标准；信念→09 关于我 |
| 05-收件箱 | 判不了 / 需用户裁决 | 暂留，次日再判；汇报中标出「待裁决」 |

**落位铁律**（沿用现有规则，不降级）：
- 落子文件夹，**绝不落根目录**；
- 文件名 = 类型前缀 + 主题（≤15 字）；
- 补 YAML：`type / status / date / source / audience / tags / related`；
- **落位链接铁律（V1.2）**：YAML `related` 一律用 `[[双链]]`，禁止纯文字；落位前回答「关系三问」——①和库里谁相关？②什么关系（逻辑/因果/反例/案例）？③为什么（一句话，写在正文链接旁）？原文层默认回链所属 MOC 索引；02/03 消化产物必须回链 01 source；
- 03 新增默认 `status: 待应用`（无应用凭证）；
- **例外先问**：涉及个人隐私、未定稿、对外发布相关内容 → 不自动落位，暂留收件箱并标注需用户裁决；
- 转化后收件箱置空。

## 五之二、原件归档制（安全机制，2026-09-17 定）

- **原件永不物理删除**：分拣后（留/不留/待裁决都算），原件原样移入 `00-天一生水/99-归档/收件箱原文/YYYY-MM/<原名>`，落位文件加一行 `> 原件归档：99-归档/收件箱原文/YYYY-MM/<原名>` 便于追溯；
- **成品特例（2026-09-17 定）**：输入本身即成品（无需提炼加工、落位=原样放置，如已转录完成的课程文档 / 已定稿文件 / 最终形态素材）时，归档区**不再整份复制原件**，只记一条索引说明（`.md`：原件名 + 落位位置 + 日期 + 来源），原件本体即落位文件；
- **归档区清理权在用户**：AI 只做「30 天体检标记可清理候选」，用户说「清一下归档区」→ AI 列《可清理候选清单》→ 用户拍板 → 才删。

## 六、汇报

处理完向用户**一句话汇报**：
> 今日收件 X 条 → 留存 N 条（01/02/03/00 去向分布）→ 不留 M 条（原因摘要）→ 待裁决 K 条。

明细记入 `00-天一生水/00-vault-log.md`（留存清单 / 去向 / 不留原因）。

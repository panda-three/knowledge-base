# 规则：网页课程长截图 → 图文分离课程文档（Obsidian）

> **来源标注**：`【原材料】` 从输入材料观察得出 · `【我的反馈】` 用户明确表述 · `【已确认】` 用户拍板定案 · `【建议】` AI 推断，可后续调整
>
> 本规则以「网页课程长截图 → 本地 Markdown + 独立图片文件夹」为唯一模板，跨模板适用性暂不覆盖。
> 交付环境：**Obsidian 打开的本地文件夹**。

---

## 0. 已定案的四项决策

| 项 | 决定 | 影响 |
|---|---|---|
| 图注详略 | **简短提示** | alt 文本一句话，不解释"为什么放这里" |
| 口语化原文 | **保持原样** | 逐字转录，不改书面语，不润色 |
| 阅读环境 | **Obsidian** | 目录锚点、相对路径、引号用法均按 Obsidian 兼容（见 §4） |
| 模板范围 | 仅限本模板 | 其他页面模板需另行验证后再补充 |

## 1. 适用场景和不适用场景

### 适用

| 条件 | 说明 | 来源 |
|---|---|---|
| 输入是**本地截图文件夹**（png/jpg/webp），文件名带数字序号 | 序号即课程顺序，直接决定文档章节顺序 | 【原材料】形如 `00 开场`、`01 为什么要学` |
| 截图是**网页长截图**：宽度固定、纯白底、纵向很长 | 宽度固定 → 可用整幅横向检测；纯白底 → 可用"非白像素占比"区分图/文 | 【原材料】实测 1800~1946px 宽、2286~30000px 高 |
| 截图内混排**正文文字 + 嵌入视觉元素** | 正文转录；视觉元素裁剪独立成文件 | 【原材料】金句横幅、案例封面、欢迎卡片、产品对比图组 |
| 用户诉求是**要可编辑可检索的文字，同时想留住图** | 这是本链路存在的理由 | 【我的反馈】"如果全部转成文字又太长" |
| 材料量在 **20~30 张**量级 | 逐张放大转录的可行区间 | 【原材料】本次 23 张 |

### 不适用

| 情形 | 应改走 | 原因 | 来源 |
|---|---|---|---|
| 有网页原始链接可访问 | `course-doc-to-local` | 直下原图，比截图裁剪保真度更高 | 【原材料】已有 skill 定位 |
| 只要纯文字、且要进飞书 | `course-images-to-feishu` | 本链路核心价值是裁图，去掉图即失去意义 | 【原材料】已有 skill 定位 |
| 扫描件、手机拍照课件 | 暂无 | 透视变形与阴影使"非白占比"检测失效 | 【建议】 |
| PPT / 设计稿截图 | 暂无 | 版面位置本身承载信息，抽掉图后语义断裂 | 【建议】 |
| 纯文字截图（无嵌入图） | 直接转录即可 | 无需裁剪环节 | 【建议】 |
| **其他页面模板的截图** | 自行验证后再用 | 本规则阈值仅在当前模板实测 | 【已确认】 |

## 2. 必需输入，以及缺少输入时怎么办

| 必需项 | 缺失时的处理 | 来源 |
|---|---|---|
| **截图文件夹绝对路径** | 必须问，不能猜 | 【建议】 |
| **文件命名含顺序序号** | 无序号时按修改时间排序，并在交付时**明确告知排序依据** | 【建议】 |
| **交付形式**（本地 MD / Word / 飞书 × 图片保留 / 仅占位） | **必须先问**再动手 | 【我的反馈】本次由我提出分离方案、用户选定「本地 MD + 裁图」 |

**不要假设**：不要把"转文字"默认理解为"只要文字"。**当截图内嵌图较多时，应主动提出图文分离方案并让用户选。**【我的反馈】

## 3. 处理步骤（照此执行）

### 步骤 0 · 清点与量级判断
列出全部图片 → 按文件名数字前缀排序 → PIL 读取每张尺寸 → 判断长图（高度超宽度 3 倍以上）。
**长图必须分段后才能读**，否则漏读。【原材料】直接读 4518px 高的长图会漏内容，分段放大后才完整。

### 步骤 1 · 隔离环境
在托管 Python venv 内装 `pillow` + `numpy`，不污染用户全局环境。【建议】

### 步骤 2 · 自动裁剪图片区块（核心）

原理：逐行统计"非白像素占比" → 连续超阈值的行合并为一块 → 左右收缩到内容边界 → 加少量 padding 裁出。

**实测参数**，可直接复用【原材料】：

| 参数 | 取值 | 说明 |
|---|---|---|
| `NONWHITE_DIFF` | 22 | 像素与白色的最小差异，低于此值算白 |
| `ROW_RATIO` | **0.62** | 非白占比超此值算"图片行" |
| `MIN_H` | 110 px | 区块最小高度，滤掉高亮文字行 |
| `GAP` | 6 px | 合并连续行时允许的空隙 |
| `PAD` | 3 px | 裁剪边距 |

> ⚠️ **阈值踩坑（务必记住）**：`ROW_RATIO` 最初设 `0.80`，导致米色卡片与深蓝金句横幅**整段漏裁**（实测占比仅 0.74~0.82）。降到 `0.62` 才全覆盖。【原材料】
>
> 一般规律：卡片/横幅类视觉元素含渐变与留白，占比通常 0.6~0.85；纯文字行因有字距空白，一般低于 0.5。【建议】

### 步骤 3 · 强制抽样肉眼验证
**不能只看脚本打印的坐标和平均色，必须实际打开裁出的图确认。**【原材料】本次正是靠抽样看图才发现 00/08 漏裁。

### 步骤 4 · 补裁自动检测漏掉的图
**已知结构性盲区：白底留白多的并排小图组**（多张小截图并排、彼此间大量白底）。整行非白占比可能仅 0.2~0.4，永远低于阈值。
处理：降阈值到 0.2~0.35 探测候选区间 → 按坐标手工裁剪确认。【原材料】

### 步骤 5 · 文字转录（分段放大后读）
用 PIL 把每张长图切 2~4 段、放大 1.4~1.6 倍（LANCZOS）、存临时目录，逐段读。
分段边界不要等分——先估文字密度，让每段内容量均衡。【建议】

**格式还原规则**【原材料】：

| 原截图样式 | Markdown 写法 |
|---|---|
| 红字 / 黄字强调 | `**加粗**` |
| 引用块、对话场景 | `>` 引用块 |
| `【热场👏】【案例代入🥲】【互动🎯】` 等标签 | 保留在引用块内 |
| 页面标题 / 小节标题 | `#` / `##` |
| 口语表达 | **逐字保留，不改成书面语**【已确认】 |

### 步骤 6 · 组装文档
图片在原出现位置以**相对路径**引用（`images/{页码}-{序号}.png`），保证整个文件夹拷走即可显示。

### 步骤 7 · 交付前强制校验
提取文档中所有图片引用路径 → 逐个检查文件存在 → 缺失则修文档，**不交付**。【原材料】

### 步骤 8 · 分批交付，先给样稿
材料多时先做 3~5 节交付，等用户确认风格再全量。【我的反馈】本次即"先把前五张转成 Md 给我看看"。

### 步骤 9 · 保留可复用资产
裁剪脚本与规则文档放在**项目根目录**（Obsidian 可见处），不要放进 `.workbuddy/` 等点开头目录。【已确认】
> ⚠️ **踩过的坑**：本次规则文档最初存进 `.workbuddy/`，而 **Obsidian 默认隐藏点开头的目录**，用户在库里完全看不到该文件。凡是用户需要在 Obsidian 里打开阅读的产物，一律放根目录。【已确认】

### 步骤 10 · 交付时给出绝对路径
无论文件存在哪个目录，交付说明里一律附**完整绝对路径**，不要只给文件名——用户可能从 Obsidian、Finder、终端多个入口找文件。【建议】

## 4. Obsidian 兼容性约束

| 项 | 规则 | 来源 |
|---|---|---|
| **图片引用** | 标准 Markdown 相对路径 `![](images/xx-NN.png)`，Obsidian 原生支持；无需改用 `![[wiki 语法]]`（后者仅 Obsidian 内可见，导出即失效） | 【已确认】+【建议】 |
| **图片目录名** | 用 `images/`（不带点、不用下划线开头）。Obsidian 附件可放任意子目录，链接相对笔记本身解析 | 【建议】 |
| **文件命名** | `{页码}-{两位序号}.png`，如 `04-04.png`。**不得含** `# ^ [ ] | !` 等字符——Obsidian 内部链接语法会解析失败 | 【建议】 |
| **中文引号** | Obsidian 渲染中文引号无问题，正文与图注中可自由使用 `"…"` `“…”` | 【已确认】 |
| **目录锚点** | Obsidian 按 GitHub 风格生成锚点：**转小写、空格转连字符、标点全部剥离**。因此标题 `04 有审美：理解"价值感"` 对应锚点 `#04-有审美理解价值感`（冒号与引号被剥掉）。目录里的链接必须按此规则手写，不能凭直觉 | 【建议】 |
| **更稳的做法** | 章节标题避免使用 `：""？！` 等标点，可让锚点与标题字面一致，跨平台导出也不会错 | 【建议】 |
| **引用块** | `> ` 在 Obsidian 中正常渲染，用于案例代入、互动标签、强调段落 | 【建议】 |

## 5. 质量标准与正反例

### A. 图片裁剪

| 标准 | 正例 | 反例 |
|---|---|---|
| 主体完整 | 金句横幅从左边缘到右边缘完整入框 | 横幅左右被切掉几个字 |
| 边界干净 | 上下只有 2~3 px 余白 | 带入上方或下方的正文文字行 |
| 无冗余 | 只裁到图片本身 | 把整段文字连背景裁成"图片" |
| 无遗漏 | 每处嵌入图都有对应文件 | 图片数少于肉眼所见 |

### B. 文字转录

| 标准 | 正例 | 反例 |
|---|---|---|
| 完整 | 逐段读完，衔接无跳句 | 直接读长图导致中段漏读 |
| 忠实 | "你手里的东西明明值 80 分，但开口一讲，它听起来只值 30 分。" | 改写成"你的内容质量不错，但表达有待提高" |
| 保留口语 | "眼钭里却透着你'又要折腾了'"原样保留 | 润色成"眼神中流露出无奈" |
| 格式还原 | 强调加粗、案例场景用引用块 | 全篇平铺成纯段落，重点丢失 |
| 不擅自增删 | `【互动🎯】` 等标签保留 | 觉得"多余"而删掉 |

### C. 文档可用性

| 标准 | 正例 | 反例 |
|---|---|---|
| 图片引用有效 | 11 个引用全部 `OK` | 路径或编号错位，用户打开全是裂图 |
| 相对路径 | `images/04-04.png` | 绝对路径，换机即失效 |
| 命名可追溯 | `04-04` | `image1.png`，无法对应回原位置 |
| 目录锚点正确 | 标题含标点时，锚点已剥离标点 | 目录链接与实际锚点不一致，点不过去 |
| 正文精简 | 文档只承载文字，视觉交给图片 | 把图里的文字再抄一遍，冗余且易不一致 |

### D. 过程质量

| 标准 | 正例 | 反例 |
|---|---|---|
| 方向先确认 | 交付形式先问用户选定 | 默认全转文字，返工 |
| 抽样验证 | 实际打开裁剪图肉眼确认 | 只看坐标和平均色就宣布完成 |
| 阈值可解释 | 记录 0.80 漏裁 → 降至 0.62 | 硬编码一个"看起来差不多"的值 |

## 6. 信息不足、冲突和超出范围的处理

| 情况 | 处理 | 来源 |
|---|---|---|
| 只说"转成文档"，未说交付形式 | **先问再动手**，给 2~3 个组合选项 | 【建议】 |
| 图文比例失衡：嵌图极少 | 直接全转文字，不启动裁剪 | 【建议】 |
| 嵌图极多、文字极少 | 保留原截图为主体，文字做索引 | 【建议】 |
| 图片为纯装饰（分隔线、头像、小图标） | 跳过不裁；小头像占比低，自动检测本就会滤掉 | 【原材料】本次头像未被误裁 |
| 同一张图重复出现 | 各自位置都保留引用，不去重 | 【建议】 |
| 图内含敏感信息（人脸、工牌、姓名） | 保留，但交付时提示用户自行决定是否公开 | 【建议】 |
| 材料量过大（>30 张） | 分批：先 5 张样稿 → 按批推进 | 【我的反馈】 |
| 用户中途改方向（如改要 Word） | 已裁图片可复用，只需换组装层，不重跑裁剪 | 【建议】 |
| 自动裁剪效果不达标 | 降阈值重跑；仍不行则按坐标手工裁。**不交付未经验证的裁剪结果** | 【原材料】 |
| 原文有错别字 | **原样保留**，可在文末统一标注疑似笔误 | 【建议】不擅自改用户材料 |

## 7. 固定输出结构

### 目录结构

```
<课程名>/
├── <课程名>-课程文档（00-04）.md      # 主文档，可按批次命名
├── images/                              # 独立图片，命名 {页码}-{序号}

│   ├── 01-01.png

└── .workbuddy/crop_images.py            # 可复用裁剪脚本（Obsidian 中不可见）
```

### 文档骨架

````markdown
# <课程名> · 课程文档（<起止节>）

> - 讲课正文逐字转录，保留原本的口语表达

> - 截图中的图片只保留图像本身，alt 文本为简短提示
````

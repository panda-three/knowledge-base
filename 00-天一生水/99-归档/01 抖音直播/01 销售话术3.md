# 01 销售话术3

> [!important] 使用前先确认
> 本文档中的价格、场次、时长、内容边界和售后规则，必须以「业务事实表」中的已确认信息为准。标记为“待核验”的内容，不得直接向用户承诺。

## 一、核心逻辑

### 成交公式

**成交 = 精准用户 × 清晰卖点 × 及时触达 × 信任建立 × 阻力降低 × 明确行动**

这份话术的目标不是强压成交，而是帮助销售完成六件事：

1. 判断对方是不是真正有需求；
2. 用最短的话讲清楚用户能获得什么；
3. 主动说明价格、权益、观看方式和边界；
4. 找到用户没有下单的真实原因；
5. 给出一个清晰、低压力的下一步；
6. 付款后及时交付，用真实体验带动复购。

### 沟通原则

- **先问再讲**：不要一上来把所有产品全部推给用户。
- **一次解决一个问题**：用户问价格，就先回答价格；用户怕被骗，就先处理信任。
- **事实优先**：不夸大内容，不承诺做不到的事情，不隐藏后续收费。
- **给选择，不强迫**：让用户选择单次了解、继续考虑或暂不购买。
- **成交不是结束**：付款后马上交付、确认能否正常使用，再考虑复购。
- **成年人限定**：仅面向已确认成年的用户；遵守平台、支付、隐私和适用法律要求。

| 标准价格 | 旧文档出现 `288 元` | 待核验 | 核验前不得固定报价 |
| 新人价格 | 旧文档出现 `188 元` | 待核验是否长期有效及适用条件 | 不得临场随意降价 |

### 对外报价模板

核验完成后，将下面变量替换为唯一版本：

> 哥哥，我先把规则说清楚：价格是【价格】，包含【权益】，有效期是【有效期】，观看方式是【观看方式】。除此之外有没有其他收费，我也会在付款前一次讲清楚。你确认能接受再决定。

## 三、用户分层与意向识别

不要只凭用户等级判断消费能力。优先看用户正在做什么、主动问了什么。

| 用户类型 | 识别信号 | 当前目标 | 不要做什么 |
|---|---|---|---|
| 随便看看 | 只回复表情、没有具体问题、持续索要免费内容 | 简短介绍，留下入口 | 连续追问或长篇轰炸 |
| 有兴趣 | 问“还有没有”“在哪里看”“有什么不同” | 讲清核心卖点和观看方式 | 一次推销多个产品 |
| 高意向 | 主动问价格、场次、时长、付款方法 | 直接给事实与下一步 | 故意绕开价格 |
| 有顾虑 | 反复确认真假、价值、售后和隐私 | 识别并消除一个核心阻力 | 用“保证满意”压过真实问题 |
| 已成交 | 已付款或发送付款截图 | 立即交付并确认体验 | 付款后继续追加销售 |
| 可复购 | 有真实使用记录、主动反馈或再次询问 | 根据需求介绍续费选择 | 用虚假稀缺骚扰用户 |

### 三个识别问题

根据对话自然选择一个，不要连续审问：

> 哥哥，你是想先了解一下，还是现在就想看？

> 哥哥，你比较在意内容、价格，还是观看方式？我先讲你最关心的。

> 哥哥，你之前看过类似的吗？最担心踩什么坑？

## 四、卖点体系

### 核心卖点

**公开直播之外，提供规则清楚、进入方便、有人协助的专属观看体验。**

### 三个支撑卖点

1. **内容有区别**：不是重复公开直播，而是经确认的额外权益。
2. **流程简单**：付款、进入、观看的步骤提前说清楚，有人协助。
3. **规则透明**：价格、场次、有效期、内容边界和其他收费在付款前说明。

### 卖点表达检查

每次对外表达都要符合以下标准：

- **具体**：到底包含什么，而不是只说“更刺激”“福利很多”。
- **有价值**：说明对用户有什么用，而不是只讲我们有什么。
- **可感知**：用户一听就懂，不需要额外猜测。
- **可核验**：能真实交付，不依赖夸大承诺。
- **有边界**：不把统一权益说成可以满足所有个人要求。

### 标准介绍

> 哥哥，谢谢刚刚支持。妹妹这边还有公开直播之外的专属观看权益，内容、价格和观看方式我都可以先给你讲清楚。你觉得适合再进，不合适也没关系。

高意向用户可以更直接：

> 哥哥，你问的专属权益是【一句话权益】。价格是【价格】，包含【场次或有效期】，付款后按【真实流程】进入。你最想先确认哪一点？

## 五、用户决策链与关键触点

### 决策链

```text
看到直播
  → 愿意回复私信
  → 理解专属权益
  → 判断是否值得
  → 消除信任或价格顾虑
  → 确认购买
  → 完成付款
  → 成功进入并使用
  → 基于真实体验决定复购
```

### 触点 1：用户刚产生互动

**识别信号**：刷礼物、主动评论、停留并持续互动。

**目标**：获得继续沟通的许可，而不是立刻压单。

> 哥哥，谢谢刚刚支持妹妹。看你挺喜欢的，我跟你说一下，妹妹这边还有专属观看权益。你想了解的话，我用两句话给你讲清楚。

如果没有回复，只提醒一次，不连续轰炸。

### 触点 2：用户同意了解

**目标**：先讲一个核心卖点，再确认他关心的问题。

> 哥哥，这个主要是公开直播之外的专属权益，付款后按群内说明观看。我可以先把价格、内容和流程说清楚，你比较想先听哪一个？

### 触点 3：用户主动问价格或购买方式

**目标**：不要回避，直接回答事实。

> 哥哥，当前确认的价格是【价格】，包含【权益】，有效期是【有效期】。付款后【真实步骤】。这些你都能接受的话，我现在给你安排。

### 触点 4：用户表现出犹豫

**目标**：定位阻力，不重复背卖点。

> 哥哥，我不急着催你。你现在主要是担心不值、怕被骗，还是觉得价格不合适？你说真实想法就行，我只回答你最在意的。

### 触点 5：用户决定购买

**目标**：复述订单，避免口径误解。

> 好的哥哥，我再跟你确认一次：这次是【产品】，价格【价格】，包含【权益】，有效期【有效期】，观看方式是【方式】。你确认没有问题再付款。

### 触点 6：付款与交付

**目标**：第一时间完成交付，并确认用户会使用。

> 哥哥，收到。我现在给你安排，进入后你先看一下能不能正常打开；不会操作就直接问我。

> 哥哥，你已经进去了吗？入口能正常打开吗？有问题我现在帮你处理。

### 触点 7：体验后复购

**目标**：先询问体验，再判断是否推荐续费。

> 哥哥，上次的内容和观看流程还顺利吗？你觉得最满意和最想改进的分别是什么？

用户反馈满意后：

> 明白了哥哥。如果你还想继续看，我可以把当前续费权益和价格发给你，你看完再决定。

## 六、标准成交对话流程

### 第一步：获得沟通许可

> 哥哥，谢谢支持。妹妹这边还有专属权益，你想了解的话，我给你简单说一下。

### 第二步：确认需求

> 哥哥，你比较想知道内容区别、价格，还是怎么看？

### 第三步：匹配卖点

只回答用户最关心的一项，再补充必要边界。

> 哥哥，你最在意的是【用户关注点】。这边对应的是【已确认权益】，和公开直播的区别是【真实差异】。

### 第四步：讲清交易条件

> 价格是【价格】，包含【权益】，有效期【有效期】，通过【方式】观看。除此之外的收费规则是【已确认规则】。

### 第五步：处理一个核心阻力

> 哥哥，我理解。你现在主要担心的是【复述用户顾虑】，对吗？

确认后再调用对应异议话术，不同时回答三个问题。

### 第六步：给出选择

> 哥哥，如果这些规则你能接受，我现在给你安排；如果还有哪一点没确认，你直接问；今天不考虑也没关系。

### 第七步：复述订单并成交

> 我再确认一次：你购买的是【产品】，价格【价格】，包含【权益】，有效期【有效期】。确认后再付款，避免我们理解不一致。

### 第八步：交付和确认

> 哥哥，已经给你安排好了。你先确认能否正常进入和观看，有问题马上告诉我。

## 七、异议处理话术库

统一结构：**承认顾虑 → 确认原因 → 提供事实 → 给出选择 → 明确下一步。**

### 1. 用户担心被骗

**判断目标**：他担心的是收款不交付、隐藏收费，还是内容不符。

> 哥哥，你担心被骗很正常，网上确实容易踩坑。你主要担心的是付款后进不去、后面继续收费，还是内容和介绍不一样？我把对应规则先说清楚。

确认问题后：

> 这次的价格是【价格】，包含【权益】，观看方式是【方式】，其他收费规则是【规则】。付款后我会马上协助你进入并确认能否正常使用。你确认这些都能接受再决定。

**禁止回答**：

- “百分百包你满意”；
- “绝对不会有其他项目”，但后续又主动追加未说明项目；
- 用催促代替证据和规则说明。

### 2. 用户担心不值

> 哥哥，觉得不值很正常，毕竟是真金白银。你是不确定内容是不是你喜欢的，还是觉得场次和价格不匹配？

> 如果你只是随便看看，这个可能不适合；如果你确实想要【已确认价值】，它对应的权益是【具体权益】。你按自己的需求判断，不需要勉强。

### 3. 用户说太贵

> 哥哥，理解。你觉得贵，是超过预算，还是和你理解的权益不匹配？

如果是超过预算：

> 明白，那我不硬推。当前正式方案是【价格与权益】；如果有经过确认的单场或新人方案，我可以按规则给你介绍，没有的话就不临时乱报价。

如果是价值不清楚：

> 那我把它和公开直播的具体区别再讲一次，你听完再判断值不值，不用先谈付款。

**禁止回答**：未经授权让用户随意报价，或为了成交临场从 288 降到 188。

### 4. 用户比较其他价格

> 哥哥，比较价格很正常。你除了价格，也可以一起看内容是否一致、场次多少、观看是否方便、有没有隐藏收费和售后怎么处理。我只把我们真实能交付的部分说清楚，不贬低别人。

### 5. 用户要求试看

> 哥哥，可以提供的预览范围是【已确认预览规则】。完整权益需要按正式规则进入，我不会拿不存在的内容吸引你。你先看预览是否符合偏好，再决定。

如果没有试看政策：

> 哥哥，目前没有完整试看。我可以先把内容类型、权益和边界讲清楚；如果仍然无法判断，建议你先别急着买。

**禁止回答**：用“白嫖的人太多”羞辱用户。

### 6. 用户怕货不对版

> 哥哥，这个顾虑合理。我先明确：你购买的是【统一权益】，包含【具体内容】，不包含【边界】。如果你需要个人指定，那属于另一种服务，必须单独确认规则和价格，不能默认包含。

### 7. 用户说再想想

> 可以的哥哥。为了不反复打扰，我最后确认一下：你还没决定，主要卡在价格、信任，还是现在没时间？如果只是时机不合适，我就先不催你。

用户说明原因后只解决一次；仍不决定就结束沟通。

> 明白，那你先考虑。有需要时再找我，我不连续催你。

### 8. 用户问怎么看

> 哥哥，流程是三步：第一步【付款方式】，第二步【提交凭证】，第三步【进入并观看】。付款后我会协助你操作，直到确认能正常进入。

### 9. 用户问能看多久

> 哥哥，当前确认的有效期是【有效期】，包含【场次】，每场预计【时长或“不承诺固定时长”】。这些以付款前给你确认的订单信息为准。

### 10. 用户付款后出现问题

> 哥哥，收到你的反馈了。你现在遇到的是进不去、找不到入口，还是内容没有正常显示？你把当前页面截图发我，我先帮你定位并按已确认售后规则处理。

不要在问题解决前继续推荐其他产品。

### 用户感兴趣

> 哥哥，主要区别是【真实差异】。价格是【价格】，包含【权益】，有效期【有效期】，付款后按【方式】观看。你最想先确认哪一点？

### 用户犹豫

> 哥哥，你不用急着付。你现在主要担心不值、怕被骗，还是价格不合适？我先回答你最在意的。

> 哥哥，如果这些规则你都确认了，我现在可以给你安排；还有疑问就先问清楚，不用勉强下单。

### 售后确认

> 哥哥，已经安排好了。你现在能正常进入和观看吗？有问题直接告诉我。

## 九、复购与客户管理

### 复购原则

1. 有真实交付记录后再谈复购；
2. 先问体验，不默认用户满意；
3. 根据偏好推荐一个方案，不同时推多个产品；
4. 明确价格和权益，不以“场次告急”等虚假信息制造压力；
5. 用户明确拒绝后停止触达；
6. 不保存与销售无关的敏感隐私。

### 最小客户档案

| 字段 | 记录内容 |
|---|---|
| 昵称 / 用户标识 | 用于识别，避免记录不必要的真实身份信息 |
| 首次接触时间 | 哪个直播或触点进入 |
| 当前阶段 | 了解 / 犹豫 / 已付款 / 已交付 / 可复购 |
| 主要需求 | 用户主动表达的偏好 |
| 核心阻力 | 价格 / 信任 / 价值 / 流程 / 时机 |
| 已介绍方案 | 产品、价格和权益版本 |
| 购买记录 | 金额、时间、对应权益 |
| 交付状态 | 是否进入、是否正常使用、是否解决问题 |
| 跟进许可 | 是否愿意接收后续通知 |
| 下次动作 | 具体动作和时间；无许可则不跟进 |

### 复购话术

> 哥哥，上次使用还顺利吗？内容、流程或者服务里，有没有哪一点和你预期不一样？

用户明确满意且有需求：

## 十、沟通禁区

### 不得使用

- 虚假的限时、限量、名额告急或场次告急；
- “包你满意”“绝对不会有后续收费”等无法保证的承诺；
- 先低价吸引、付款后再逐层追加隐藏项目；
- 羞辱用户、性别操控、PUA、威胁或道德绑架；
- 未经授权随意降价、承诺退款或扩大权益；
- 为成交故意模糊价格、时长、内容和售后边界；
- 连续骚扰明确拒绝或没有回复的用户；
- 向未成年人营销成人向内容；
- 传播用户隐私、付款信息或聊天记录；
- 违反平台规则、支付规则或适用法律的内容与操作。

### 应该坚持

- 先确认成年与真实需求；
- 先讲清楚，再让用户选择；
- 用具体权益代替刺激性形容词；
- 用户问什么，先直接回答什么；
- 付款前复述订单，付款后立即交付；
- 有问题先解决，再谈下一次购买；
- 用真实体验和长期信任获得复购。

## 十一、数据记录与迭代

不要凭感觉判断哪句话有效。每周只测试一个变量。

### 最小漏斗

```text
有效互动人数
  → 同意了解人数
  → 主动问价格人数
  → 明确购买意向人数
  → 付款人数
  → 成功交付人数
  → 复购人数
```

### 最小记录表

| 日期 | 触点 | 使用版本 | 用户核心阻力 | 是否付款 | 是否成功交付 | 是否复购 | 备注 |
|---|---|---|---|---|---|---|---|
|  | 首次私信 / 价格 / 异议 / 复购 | A / B | 价格 / 信任 / 价值 / 流程 / 时机 | 是 / 否 | 是 / 否 | 是 / 否 | 只记关键事实 |

### A/B 测试规则

1. 一次只修改一个变量，例如首次私信的开头；
2. A、B 两版面向相近用户和相近直播场景；
3. 不只看付款率，同时看投诉、退款、交付失败和复购；
4. 样本不足时不急着下结论；
5. 胜出话术进入本文档，失败版本保留在复盘记录中，不继续混用。

### 每周复盘问题

1. 用户最常卡在哪个决策节点？
2. 最常见的真实阻力是什么？
3. 哪个卖点用户能立即复述出来？
4. 哪句话容易产生误解或不信任？
5. 付款后最大的交付问题是什么？
6. 哪类用户复购最高，原因是什么？
7. 下周只准备测试哪个变量？

# 题目卡 V3 模板

> 核心判断：题目卡是整个系统的数据单元。一张题目卡的质量 = 标签质量。
> 标签的核心是"答案相关考点"——不是这道题涉及了什么，而是这道题在考什么。
> 打错标签 = 相似题搜索跑偏 = 学生做到三道不相关的题。

## 一、使用定位

📍 这个模板用于给每道 C 语言真题生成一张 V3 题目卡。一张题目卡是一道题的最小数据单元。
生成时 AI 先填初版，人工校准后定稿。定稿后这张卡就进入"可搜索题库"。

## 二、必填字段（8 个维度）

| # | 字段 | 填写要求 | 判断标准 |
|---|---|---|---|
| 1 | 题目内容 | 完整题干 + 代码 + 选项/填空 + 图表说明 | 不看原卷就能做题 |
| 2 | 重要性 | 必考 / 常考 / 偶考 | 看这道题在学生练习路径中的位置 |
| 3 | 题型 | 选择 / 判断 / 填空 / 程序阅读 / 程序填空 / 综合题 | ⚡ 一个题型，不混。只填主类型，子类型信息放正文「题型」标签行（如 `程序阅读题` 不写成 `程序阅读题（代码结构识别）`；`程序填空题` 不写成 `程序填空题（4 空）`） |
| 4 | 答案相关考点 | 1–3 个影响答案的考点 | ⚡ 不是说"这道题出现了 switch"，而是"这道题在考 switch 的 break 贯穿"。只放硬区分度考点——这个点理解不到位，这道题一定做不对。不放基础语法常识（`FILE *` 的写法、`strlen` 不含 `\0`、变量类型等） |
| 5 | 解题动作 | 2–5 个以动词开头 | 追踪变量 / 判断 break / 匹配格式符 / 补参数。每条是一个可独立执行的动作，不拆太碎（"判断 break 是否终止 switch"太碎）、不写太虚（"了解程序整体结构"太虚） |
| 6 | 易错点 | 1–4 个学生最高频出错的点 | ⚡ 只放这题的区分度坑——理解不到位必踩的那种。不放基础语法错误（`FILE *` 写错、变量类型混淆等常识）。简单题 1–2 个，复杂题 2–4 个。能反向生成练习题 |
| 7 | 相似题搜索标签 | 从答案相关考点反推的搜索关键词 | ⚡ 服务于「学生搜到同类题」，不是知识点罗列。从答案相关考点**反推**，不是复制答案相关考点列表。如 `switch` `case` `break` `default` |
| 8 | 难度 | ⭐–⭐⭐⭐⭐⭐ | 基于学生实际错误率，不是老师感觉 |

## 三、V3 的关键判断：答案相关 vs 题目涉及

⚠️ 这是最高频的错误来源。

| 判断 | 正例 | 反例 |
|---|---|---|
| 答案相关考点 | 一道题里出现了 `switch`，但解题关键是"格式化输出"——标"格式化输出" | — |
| 题目涉及 | — | 把题目里出现的所有知识点都标上——`switch`、`printf`、`float`、`%.2f` 全写 |

一道题只标 1–3 个答案相关考点。超过 3 个 = 标签过泛 = 失去匹配价值。

# 2026 真题 · 73 · 代码结构元素识别与数组定义陷阱

## 一、题目内容

- 题号：73
- 题型：程序阅读题（代码结构识别——定位变量类型、关系表达式位置、空语句位置、数组元素个数）
- 题干：阅读下列程序，请将①~④表示的内容填写在答题卡上相应位置。

```c
#include<stdio.h>
void dump(int x)
{
   ;
}
int main()
{
   int b=2;
   float a[5]={1,2};
   if(a[0]>0)
   printf("num:%5.1f\n",a[1]);
   else
   dump(b);
   return 0;
}
```

- 作答要求：
    - 第 8 行变量 `b` 的数据类型是 __①__
    - 关系表达式位于第 __②__ 行
    - 空语句位于第 __③__ 行
    - 数组 `a` 有 __④__ 个元素

## 二、标签

- 重要性：重要
- 题型：程序阅读题（代码结构识别）
- 答案相关考点：
    - 数组声明长度 ≠ 初始化列表个数（`a[5]` 声明 5 个元素，`{1,2}` 只初始化前两个）
    - 空语句的形态识别（单独 `;` 是一条合法空语句，不是书写错误）
- 解题动作：
    - 定位 `b` 的声明行，读出类型关键字
    - 扫代码找比较运算符（`>` `<` `==` 等），定位关系表达式行
    - 识别 `;` 作为独立语句——不在 `for`/`while` 括号后、不在语句末尾，独占一行的分号
    - 看数组 `[]` 内的数字，不看初始化列表 `{}` 里放了几个
- 易错点：
    - `{1,2}` 看花眼，填 2 个元素而实际声明是 5 个
    - 不认识空语句，以为 `;` 是笔误或跳过不填
    - 行号数错（从 `#include` 开始算第 1 行）
- 相似题搜索标签：`数组定义` `空语句` `声明长度` `代码结构识别`
- 难度：⭐⭐（简单——唯一陷阱是数组长度，其余考的是读代码基本功）

# 2026 真题 · 76 · 有序姓名记录的折半查找与同名收入累加

## 一、题目内容

- 题号：76
- 题型：程序填空题（4 空）
- 题干：文件 `gz.txt` 中存储的是按姓名升序排列的收入记录，每人可能有多条记录，文件中无空白行。编程实现：输入姓名，统计其名下总收入。请在答题卡上写出①~④表示的内容以完善程序。

- 题图：`gz.txt` 示例

| 姓名 | 收入 |
|------|------|
| Jack | 300  |
| Kate | 450  |
| Kate | 400  |
| Rose | 350  |
| ...  | ...  |

- 代码：

```c

#include<stdlib.h>
int search(char xm[],char name[][20],int n)

        else
            tail=mid-1;

    return ret;
}

{

        puts("File cannot open!\n");exit(0);
    }
    while(!feof(fgz)){
        fscanf(fgz,"%s  %d",name[n],&sr[n]);n++;
    }
    fclose(fgz);
    scanf("%s",fname);
    int regn=search(fname,name,n);
    if(regn!=-1){
        while(strcmp(name[regn],fname)==0)
            regn--;
         ③  ;
        while(strcmp(name[regn],fname)==0){
            sum+=sr[regn];regn++;
        }
        printf("%s 名下总收入:%d\n",fname, ④ );
    }else
        printf("查无此人:%s\n",fname);
    return 0;
}
```

## 二、标签

- 重要性：重要
- 题型：程序填空题（4 空）
- 答案相关考点：
    - 折半查找中 `strcmp` 比较方向与边界更新——判断 `xm > name[mid]` 时 `head` 上移，否则 `tail` 下移
    - 同名记录边界定位修正——向前退过所有同名记录后，需 `+1` 回到第一条
- 解题动作：
    - 判折半查找的比较方向：`strcmp(name[mid], xm) < 0` 等价于 xm 更大、应往右半区找
    - 填文件指针类型：`FILE`，C 语言标准文件指针关键字
    - 追踪同名记录定位逻辑：`regn` 先退到第一条之前、再 `+1` 回到第一条、再向后累加
    - 确认输出变量：累加结果存在 `sum`，不是 `sr[regn]` 也不是其他
- 易错点：
    - `strcmp` 返回值正负方向搞反，`head`/`tail` 更新写颠倒
    - ③空漏填——以为退到第一条就完事，没意识到退过头了需要 `+1` 拉回来
    - ④空误填 `sr[regn]` 或 `regn`——没注意到收入已经累加进 `sum`
- 相似题搜索标签：`折半查找` `strcmp比较方向` `边界修正` `regn++` `同名累加` `文件fscanf`
- 难度：⭐⭐⭐⭐（困难——两个核心空都是"理解不到位就一定填错"的硬区分度空）

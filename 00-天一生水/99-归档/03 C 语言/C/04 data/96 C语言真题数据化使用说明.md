# C 语言真题数据化使用说明

> **核心判断**：这份文档是操作入口，不是知识库。每次新开 AI 对话，从这里复制口令，3 秒跑起来。不需要从头解释背景。

| 场景 | 用哪个口令 | 预期产出 |

| 把一份真题拆成一题一文件并打标 | 打标口令 | V3 题目卡（一题一文件） |

### 3.1 打标口令：完整版

```
请按照 [[07 项目 ing/C/04 data/C/题目卡V3模板.md]] 和 [[07 项目 ing/C/04 data/C/打标原则卡.md]]，
对下面这份真题进行题目切片和 V3 打标：

原始真题：
[[这里放真题文件路径]]

输出位置：
[[这里放目标文件夹]]

要求：
1. 一题一个文件。
2. 保留完整题干、代码、表格和作答要求。
3. 答案相关考点只标影响答案的考点。
4. 相似题搜索标签必须从答案相关考点反推。
5. 不要泛标代码里出现过的知识点。
```

```
[[文件路径]]

输出到：
[[目标文件夹]]
```

### 3.3 生成练习题组口令：完整版

```
请按照 [[07 项目 ing/C/04 data/C/相似题练习组模板.md]] 和 [[07 项目 ing/C/04 data/C/打标原则卡.md]]，
以这道 V3 题目卡为起点，去历年真题中寻找相似题，并生成练习题组：

起点题：
[[这里放 V3 题目卡路径]]

相似题搜索范围：
[[这里放真题文件夹路径]]

输出位置：
[[这里放练习题组文件夹路径]]

要求：
1. 至少找 3 道相似题。
2. 按同构题、变式题、迁移题分类。
3. 相似度打分使用 9 分制：
   - 题型相同 +1
   - 答案相关考点相同 +3
   - 解题动作相同 +3
   - 易错点相同 +1
   - 难度接近 +1
4. 题组文件不要写学生版讲解。
5. 不要单独列"学生要练的动作"。
6. 每道相似题保留：题目来源、相似题类型、推荐理由、题目切片、相似度打分。
```

## 八、AI 协作完整场景地图

> **核心心法**：第三节的口令是「最小可用单元」——每次新开对话复制粘贴，3 秒跑起来。
> 但 AI 能帮你做的事远不止打标和找题。下面十五个场景覆盖了从过渡期到开发到运营到进化的完整生命周期。
>
> 每一组场景都标注了「什么时候能用」——**现在就能用的放在最前面**，需要数据积累或系统上线后才能用的往后排。

### 第一梯队 · 现在就能用（过渡期）

**场景 1 · 题库打标加速**
- **对应口令**：第三节打标口令（你已经在用）
- **进阶用法**：不只打标初稿——让 AI 同时标注「这道题最可能被学生误解的步骤」和「这道题的标注最容易在哪一个字段上翻车」。AI 标注时主动暴露边界，你审核时心里更有数。
- **投入产出**：50 道题从 12–20 小时压缩到 2.5–4 小时。

**场景 2 · 标签一致性盲校验**
- **适用时机**：已手动打标 ≥ 20 道题
- **用法**：抽 10 道已标题目 → 只给 AI 题目原文和模板，不给原标签 → AI 独立盲标注 → 你逐字段对比
- **AI 提示词**：
  ```
  你现在要做一道题的标准标注。只看题目原文和我的标注规范，不看任何已有的标签。

  题目原文：[粘贴题目]

  标注规范：[粘贴固定套路完全体的「一、标签体系」和「二、打标流程」]

  请输出七字段标注。解题动作必须从统一词表里选。不确定的标「待教师确认」。
  ```
- **产出**：不一致字段清单 → 你的标注体系里「不稳定」的地方 → 补规则、补词表、补边界判断

**场景 3 · 模拟学生内测**
- **适用时机**：题库 ≥ 30 道，准备找真实学生之前
- **用法**：让 AI 扮演 3 种典型学生画像（基础薄弱型 / 中游挣扎型 / 高分瓶颈型），各走一遍「选题 → 做题 → 收反馈」闭环
- **AI 提示词**：
  ```
  你现在扮演一个 C 语言学生。画像：段位 Lv.2，指针操作正确率 20%，经常把 = 当成 ==，对内存图完全没有概念。

  给你一道题：[粘贴题目]

  请你：
  1. 像这个水平的学生一样做这道题（故意暴露典型错误）
  2. 写出解题过程（包括错误步骤是怎么想的）
  3. 做完后告诉我：你觉得这道题难在哪？你最希望老师告诉你的三件事是什么？
  ```
- **产出**：反馈语句预演报告 → 在学生看到之前修复模糊和不精准的地方 → 零成本内测

**场景 4 · 错题数据聚类分析**
- **适用时机**：收集 ≥ 30 条学生错题记录
- **用法**：把所有错题记录扔给 AI → AI 聚类、命名模式、发现你标签里没有的错因
- **AI 提示词**：
  ```
  以下是 30 条学生错题记录。每条包含：学生 ID、题目 ID、老师标的易错点、学生实际错因、学生自述。

  [粘贴记录]

  请分析：
  1. 错误频率最高的 3 个考点是什么？
  2. 有没有跨考点的错误模式？给这些模式起个名字。
  3. 哪些学生实际错因在我的易错点标签里找不到？列出题目 ID + 缺失标签建议。
  4. 有没有让你意外的发现？
  5. 我接下来最该优先修正的前三个标注动作是什么？
  ```
- **产出**：结构化错题分析报告 + 标签补漏清单 → 直接反哺你的错误模式库

**场景 5 · 标签体系结构性漏洞扫描**
- **适用时机**：题库 ≥ 40 道
- **用法**：让 AI 对照 C 语言教学大纲，逐维扫描你的题库
- **AI 提示词**：
  ```
  以下是我题库中所有题目的标签数据汇总：[粘贴标签汇总表]

  请逐项检查：
  1. C 语言教学大纲的核心考点，哪些在我的题库里一道题都没有？
  2. 每个解题动作至少关联 3 个不同考点了吗？不足 3 个的列出问题动作。
  3. 基础 / 进阶 / 综合的题数比例是多少？如果基础题 > 50%，建议怎么调整？
  4. 我的易错点标签清单里，有没有语义重复的？有没有过于宽泛无法反向出题的？逐个点评。
  5. 综合以上，我的标签体系最大的三个结构性漏洞是什么？
  ```
- **产出**：标签体系漏洞审计报告

### 第二梯队 · 开发时用（设计→编码→测试）

**场景 6 · 文档一致性审计**
- **适用时机**：设计文档和开发文档写完后，开始编码前
- **用法**：把全部文档扔给 AI，让它做交叉引用检查
- **AI 提示词**：
  ```
  需求文档里说的「错因自动归类」功能，在设计文档的哪张表、哪个接口里对应？
  开发文档里有对应的开发任务吗？

  推荐引擎需求文档里的排序公式，和设计文档里的 rankCandidates 伪代码一致吗？

  检查需求文档里提到的所有功能，在设计文档和开发文档中是否全部覆盖。列出遗漏项。
  ```
- **产出**：不一致清单 + 遗漏项清单 → 在写代码之前把坑踩出来

**场景 7 · 决策影响追踪**
- **适用时机**：你改了一个设计决策
- **用法**：告诉 AI 你的变更，让它追踪哪些文档需要同步修改
- **AI 提示词**：
  ```
  我决定把「难度动态校准」从 V1.4 提前到 V1.2。

  帮我列出所有受影响的文档段落——需求文档、设计文档、开发文档里哪些地方需要改？
  每个受影响的位置标注原文内容和建议修改方向。
  ```
- **产出**：受影响段落清单 + 修改建议

**场景 8 · 开发时上下文注入**
- **适用时机**：写推荐引擎代码
- **用法**：把设计文档和需求文档作为 AI 上下文，让它严格对照文档写代码
- **AI 提示词**：
  ```
  基于设计文档 §4.2 的伪代码和需求文档 §3 的调度策略，帮我写 rankCandidates 的 TypeScript 实现。
  输入输出类型严格按设计文档 types.ts 定义。排序公式严格对照需求文档 §5 的公式。
  每个函数加 JSDoc 注释，标注对应的设计文档章节号。不要简化逻辑。
  ```
- **产出**：符合设计文档的代码 → 你审逻辑，AI 省翻译时间

**场景 9 · 代码与文档一致性校验**
- **适用时机**：写完一个模块
- **用法**：把设计文档规范 + 实际代码扔给 AI，逐字段、逐逻辑对比
- **AI 提示词**：
  ```
  以下是设计文档中 POST /api/practice/answers 接口的完整规范：[粘贴设计文档 §3.2]
  以下是我实现的实际代码：[粘贴代码]

  逐项对比：
  1. 入参字段是否全部校验？有没有缺失或多余的？
  2. 处理流程每一步是否都实现？
  3. 返回体 JSON 结构是否一致？
  4. 错误处理是否覆盖了设计文档提到的边界情况？

  列出所有不一致的地方，标注严重程度（阻断/建议）。
  ```
- **产出**：代码与文档差异清单 → 在测试之前先修正

**场景 10 · 反向压力测试**
- **适用时机**：推荐引擎核心逻辑写完
- **用法**：让 AI 模拟极端场景，测试引擎会不会崩
- **AI 提示词**：
  ```
  基于设计文档的推荐引擎逻辑，模拟以下极端场景：
  - 学生所有考点正确率都是 0% → 候选池怎么排？排序公式还有意义吗？
  - 题库只有 3 道题 → 多样性约束还生效吗？
  - 学生连续 30 道题全错 → 间隔调度会不会永久卡死他？
  - 学生全部考点正确率 ≥ 95% → 非舒适区调控还能推什么题？

  每个场景给出：引擎行为预测 + 风险等级 + 建议修复方案。
  ```
- **产出**：极端场景测试报告 → 引擎边界问题提前暴露

### 第三梯队 · 上线后用（运营→进化→传承）

**场景 11 · 学生数据故事生成器**
- **适用时机**：积累 ≥ 100 条错题数据
- **用法**：让 AI 从数据里挖出学生崩溃链的叙事 → 反推反馈引擎薄弱点
- **AI 提示词**：
  ```
  这 100 条错题数据里有一个学生经历了完整崩溃链：
  「看不懂 ASCII 码 → 字符分类乱套 → 进位累积崩溃 → 最后放弃指针」

  基于固定套路完全体的错误模式库和及时反馈完全体的反馈格式：
  1. 写一篇这个学生的第一人称内心独白——每一步他当时脑子里在想什么？
  2. 在崩溃链的每一步，如果系统给了正确的反馈，他能在哪一步被救回来？
  3. 反推——我们的反馈引擎在哪一步最薄弱？多说一句话能不能阻止整个崩溃链？
  ```
- **产出**：一篇叙事 + 反馈薄弱点清单

**场景 12 · 系统自我进化提案**
- **适用时机**：系统运行 ≥ 半年
- **用法**：把半年运行数据 + 全部文档扔给 AI，让它找出设计层面需要重构的地方
- **AI 提示词**：
  ```
  基于这半年的真实数据：[粘贴数据摘要]
  对照全部十份设计文档，找出当前推荐引擎最严重的三个问题：
  - 不是 bug，是设计层面需要重构的地方
  - 每个问题附带：证据（数据支撑）+ 影响范围 + 优化方案
  - 三个问题按 ROI 排序
  ```
- **产出**：系统进化提案 → V2.0 做什么不再靠直觉，靠数据

**场景 13 · 教学直觉验证**
- **适用时机**：你有任何教学假设想验证
- **用法**：把你的直觉扔给 AI，让它基于你的系统架构设计 A/B 测试方案
- **AI 提示词**：
  ```
  我的教学直觉：「先让学生画内存图，再学指针赋值」比「先学指针赋值，再画内存图」更有效。

  基于全部文档的系统架构，帮我设计 A/B 测试方案：
  怎么分组？测试周期多长？用什么指标？多少样本量有统计意义？
  怎么控制干扰变量？判定「直觉成立」和「不成立」的标准分别是什么？
  ```
- **产出**：可执行的 A/B 测试方案 → 每次验证，教学判断精确一分

**场景 14 · 教学知识传承**
- **适用时机**：有新老师加入
- **用法**：新老师对着十份文档 + AI 提问，AI 用你的教学判断回答
- **AI 提示词**（新老师视角）：
  ```
  这道题学生老在指针上翻车，我该怎么打标签？
  这个学生连续三次错同一个考点，推荐引擎应该怎么调？
  ```
- **产出**：被你的经验武装过的 AI 教学顾问 → 你人不在，判断在

**场景 15 · 教师培训课程自动生成**
- **适用时机**：需要批量培训新老师
- **用法**：让 AI 从新老师视角审视全部文档，自动生成自学路径
- **AI 提示词**：
  ```
  假设你是新加入的 C 语言老师，从没接触过这套系统。

  基于全部文档，你会有哪些疑问？按学习路径排列——第一天学什么、第一周学什么、第一个月学什么。

  然后：针对「第一天」生成自学用的清单体笔记；针对「第一周」生成任务清单；
  针对「第一个月」生成能力自检表。
  ```
- **产出**：自学课程 + 任务清单 + 能力自检表 → 不需要你亲自讲，新老师看着笔记 + 问着 AI 就能上手

## 九、AI 协作使用铁律

> 1. **给上下文，不给空话**。每次用 AI 之前，先把对应的文档扔进去。AI 在被你的文档武装前后的输出质量天差地别。
> 2. **你审，AI 不替**。打标初稿、反馈语句、沟通文档、测试方案——每一样都必须经过你的眼睛。你是最终的质量把控者。
> 3. **文档是活的，AI 也要跟着活**。文档每更新一次，AI 的行为也跟着更新。你的教学判断越精确，AI 的产出越精确。
> 4. **AI 最擅长的是「翻译」**——把文档翻译成代码、把数据翻译成故事、把直觉翻译成实验方案。它不替你想，是把你想好的东西翻译成可执行的形式。
> 5. **终极目标**：你的经验 × AI 的执行力 = 一个人的教研团队。

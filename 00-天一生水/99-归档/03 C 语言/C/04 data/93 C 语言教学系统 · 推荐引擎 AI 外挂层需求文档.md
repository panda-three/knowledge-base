# C 语言教学系统 · 推荐引擎 AI 外挂层需求文档

> **核心判断**：推荐引擎需要 AI——但不是推倒规则引擎重来，是**在规则引擎之上叠加 AI 外挂层**。
>
> 规则引擎管「推不推、什么时候推」——这是你亲手设计的教学逻辑，必须绝对可控。
> AI 外挂层管「推什么更好、为什么」——这是从数据里长出来的优化能力，规则引擎做不到。
>
> **分工铁律**：规则引擎是骨架，AI 是肌肉。骨架不牢，肌肉没用；没有肌肉，骨架永远是死的。

## 一、规则引擎 vs AI 的战场划分

| 战场 | 谁干 | 为什么 |
|---|---|---|
| 这道题考点是什么 | 你打的标签 | 标签必须人审，AI 不准替 |
| 这个学生这个考点正确率多少 | 规则引擎 | 数学计算，不需要 AI |
| 该不该推这道题 | 规则引擎 | 间隔序列、多样性约束——是你定的教学逻辑 |
| 为什么这个学生老在指针上翻车 | **AI** | 模式识别，跨考点的隐藏关联人眼看不出来 |
| 标注难度真的适合这个学生吗 | **AI** | 真实难度 vs 标注难度的动态校准 |
| 这个练习序列对这类学生最有效吗 | **AI** | 协同过滤——找到类似学生的成功路径 |
| 新学生没有历史数据怎么破冰 | **AI** | 从过程中推断画像，不只从结果 |
| 学生的下一个最佳考点是什么 | **AI** | 不只盯弱项——看整体成长曲线做预测 |

## 二、AI 发力战场一：知识点关联发现

### 2.1 为什么需要 AI

你手动标注了「知识前序依赖链」。但有些隐藏关联你自己也不知道——它们埋在数据里，只有大量交叉分析才能暴露。

### 2.2 AI 做什么

**输入**：全班所有学生的错题记录（学生 ID + 题目 ID + 错误考点 + 学生实际错因）

**AI 分析**：

> 数据模式：做错「数字进位累积」的学生里，73% 也反复错「ASCII 码概念」
> → AI 结论：两个考点存在**隐性前序依赖**
>
> 解读：ASCII 码不理解 → 无法准确区分字符和数字 → 进位累积时字符和数字混在一起乱套

**AI 输出**：

```json
{
  "hidden_dependency": {
    "child": "数字进位累积",
    "parent": "ASCII码概念",
    "confidence": 0.73,
    "evidence": "73% 的『数字进位累积』反复错误学生也反复错『ASCII码概念』"
  },
  "action": "推送『数字进位累积』之前，先推送 1 道 ASCII 码诊断题；若正确率 < 60%，先补 ASCII 码"
}
```

### 2.3 规则引擎用这个结果做什么

- 在推荐引擎的排序公式中新增一个权重因子：`prerequisite_check_weight`
- 连续错误追查时，不只查你标注的「知识前序」，也查 AI 发现的「隐性前序」
- 隐性前序被验证（连续 3 个学生命中同一模式）→ 自动升级为显性，写入题目标签

### 2.4 算法选择

- 初期：关联规则挖掘（Apriori 算法），简单、可解释
- 后期：图神经网络（考点关联图 + 错误传播路径建模）

## 三、AI 发力战场二：难度动态校准

### 3.1 为什么需要 AI

你标注的难度是你当下的判断。但真实难度是学生用脚投票的——而且同一道题对不同画像的学生难度不同。

### 3.2 AI 做什么

**输入**：每道题的标注难度 + 全班正确率 + 平均耗时 + 学生画像分群

**AI 分析**：

> 题 2026-75：
> - 你标「⭐⭐⭐中等」
> - 基础薄弱型学生正确率 98%，平均耗时 45 秒
> - 高分瓶颈型学生正确率 62%，平均耗时 3 分 20 秒
>
> → AI 结论：这道题对基础薄弱型学生是「⭐基础」（他们靠代入法硬推也能对）
> → 对高分瓶颈型学生是「⭐⭐⭐⭐进阶」（他们试图用内存图一步到位，反而踩了边界的坑）

**AI 输出**：

```json
{
  "question_id": "2026-75",
  "labeled_difficulty": 3,
  "dynamic_difficulty": {
    "basic_weak": 1,
    "mid_struggling": 3,
    "high_plateau": 4
  }
}
```

### 3.3 规则引擎用这个结果做什么

- 非舒适区调控不再用统一难度数字 → 用**分群动态难度**
- 同一个学生升段位后，同一道题的难度自动变化——因为他切换了画像群

## 四、AI 发力战场三：个性化学习路径

### 4.1 为什么需要 AI

规则引擎知道「张同学指针操作正确率 30%，推指针题」。但它不知道**以什么顺序攻克指针最有效**——是「画内存图 → 指针赋值 → 指针运算」还是「指针运算 → 画内存图 → 指针赋值」？

AI 从历史数据里找答案。

### 4.2 AI 做什么

**输入**：张同学的完整画像 + 全班所有学生的练习序列 + 进步曲线

**AI 分析**：

> 找到 5 个与张同学画像最相似的学生（同段位 + 同弱项分布 + 同动作掌握度）
> 其中 3 个学生走出了瓶颈，进步曲线陡峭
>
> 他们的共同路径：
> 1. 先练「ASCII 码 + 字符分类」（张同学的隐性前序塌方）
> 2. 再练「逐位追踪法」替代「代入法」（更换低效解题动作）
> 3. 最后练「数字进位累积 + 字符串遍历」组合
>
> 那 2 个没进步的学生：一直硬刷指针题，正确率始终 30%。

**AI 输出**：

```json
{
  "student_id": "zhang_san_001",
  "similar_students": ["li_si_002", "wang_wu_003", "zhao_liu_001"],
  "recommended_path": [
    { "step": 1, "focus": "ASCII码概念", "reason": "隐性前序塌方——你 73% 的指针错误根源在这里" },
    { "step": 2, "focus": "逐位追踪法", "reason": "类似学生的经验：换掉代入法后速度提升 40%" },
    { "step": 3, "focus": "数字进位累积+字符串遍历组合", "reason": "前两步补完，组合考点正确率预计从 30% 升到 65%"}
  ],
  "expected_improvement": "+35% accuracy in 2 weeks"
}
```

### 4.3 规则引擎用这个结果做什么

- 在意图选择页增加一个选项：「走推荐路径」
- 推荐路径不是硬性的——学生仍然可以自己选意图，但系统会提示「AI 建议你先补 ASCII 码，要试试吗？」
- 推荐路径实时更新：每 10 次练习后重新计算一次

### 4.4 算法选择

- 初期：基于学生画像的余弦相似度 + 画像聚类
- 后期：强化学习——把推荐序列当作决策问题，优化「最短时间达到目标正确率」的路径

## 五、AI 发力战场四：冷启动推断

### 5.1 为什么需要 AI

新学生进来，画像一片空白。规则引擎只能推基础摸底卷——但摸底卷只能看「对错」，看不到「过程」。

### 5.2 AI 做什么

**输入**：新学生 5 道摸底题的结果——不只是对错，还有每道题的耗时、选项切换次数、跳过步骤

**AI 分析**：

> 学生 A · 摸底结果：
> - 三道指针题全对，但每题耗时 3 分钟以上
> - 两次在错误选项和正确选项之间切换超过 3 秒
> - 没使用画内存图步骤（直接跳到最后答案）
>
> → AI 判断：不是真掌握，是靠代入法硬推出来的
> → 初始画像修正：指针 accuracy 不是 100%，预估 55%；解题动作「画内存图」标为「未掌握」

**AI 输出**：

```json
{
  "student_id": "new_student_001",
  "cold_start_profile": {
    "指针操作": { "accuracy": 0.55, "confidence": 0.70, "evidence": "做对但慢+选项犹豫+缺动作步骤" },
    "画内存图": { "mastery": "未掌握", "confidence": 0.85, "evidence": "全部 3 道指针题均未使用此动作" }
  }
}
```

### 5.3 规则引擎用这个结果做什么

- 新学生的初始画像不再等于「摸底卷正确率」
- 冷启动画像带 `confidence` 字段——后续每次练习后更新真实数据，confidence 升高后替换推断值

## 六、终局架构：规则引擎 + AI 外挂

```
┌─────────────────────────────────────────┐
│              推荐引擎主控                │
│                                          │
│  ┌─────────────────────────────────────┐ │
│  │           规则引擎（骨架）           │ │
│  │  ├ 间隔重复调度                     │ │
│  │  ├ 弱项高频渗透                     │ │
│  │  ├ 非舒适区调控                     │ │
│  │  ├ 意图权重叠加                     │ │
│  │  └ 多样性硬约束                     │ │
│  │                                     │ │
│  │  职责：推不推、什么时候推            │ │
│  │  特征：100% 可控、100% 可解释        │ │
│  └─────────────────────────────────────┘ │
│                    ▲                      │
│                    │ 权重修正              │
│                    │ 参数注入              │
│  ┌─────────────────────────────────────┐ │
│  │           AI 外挂层（肌肉）           │ │
│  │  ├ 知识点关联发现 → 调整考点权重     │ │
│  │  ├ 难度动态校准 → 修正难度参数       │ │
│  │  ├ 个性化路径 → 推荐序列优化         │ │
│  │  └ 冷启动推断 → 画像补全             │ │
│  │                                     │ │
│  │  职责：推什么更好、为什么            │ │
│  │  特征：数据驱动、概率性、需验证      │ │
│  └─────────────────────────────────────┘ │
└─────────────────────────────────────────┘
```

> **核心原则**：规则引擎永远有否决权。AI 说「推这道」，规则引擎可以因为多样性约束说「不」。AI 可以建议，规则引擎决定。

## 七、为什么不能一开始就用 AI

> 1. **AI 需要数据才能工作**。知识点关联发现需要 ≥ 500 条错题记录；协同过滤需要 ≥ 20 个学生画像；冷启动推断需要 ≥ 100 道已校准难度的题。
>
> 2. **规则引擎是 AI 的基线**。你不知道「没有 AI 时推荐质量什么样」，就没法衡量「AI 到底有没有让推荐更好」。
>
> 3. **规则引擎是你的教学判断外化**。你先把自己脑子里「怎么推题」写成代码，跑出数据，再让 AI 来优化——这是从 L5 到 L6 的标准路径。
>
> 4. **AI 的输出必须可验证**。如果规则引擎还没跑稳，AI 的优化建议你不知道是对是错。

## 八、AI 层引入的时间线

**阶段 0（MVP，0–2 个月）**
- 纯规则引擎，不引入 AI
- 积累数据：学生画像、练习记录、错题记录、推荐日志

**阶段 1（数据积累达标后，+1–2 个月）**
- 开启「难度动态校准」——数据门槛最低（只需要全班正确率和耗时）
- 规则引擎的难度参数从静态切换到动态

**阶段 2（≥ 500 条错题记录，+2–3 个月）**
- 开启「知识点关联发现」
- 隐性前序依赖自动标注 + 教师审核

**阶段 3（≥ 20 个活跃学生，+3–4 个月）**
- 开启「个性化学习路径」——协同过滤生效
- 学生首页出现「AI 推荐路径」选项

**阶段 4（≥ 50 个学生 + 系统运行 6 个月，+6 个月）**
- 开启「冷启动推断」
- 所有 AI 功能完整上线
- 进入持续优化循环

## 九、AI 层的技术实现

**难度动态校准**：轻量模型，可直接跑在 Next.js 服务端，不需要 GPU。按画像分群算正确率 + 耗时分布，每小时更新一次。

**知识点关联发现**：离线批处理。每周跑一次 Apriori 算法，结果存入 Supabase 关联表。前端查询即可，不增加推荐引擎实时负担。

**个性化学习路径**：学生画像向量化 → 余弦相似度匹配 → Top-K 相似学生 → 取他们进步最快区间的练习序列。可离线预计算，存入 Redis 缓存。

**冷启动推断**：规则 + 简单统计模型。比对「对错结果」和「解题过程特征」的不一致性来推断。可实时运行，轻量。

---

> **设计铁律**：
> 1. **AI 不准动标签**。标签是你审过的，AI 只能读、只能建议，不能改。
> 2. **AI 的输出永远带 confidence 和 evidence**。每一个推断必须能追溯——「为什么这么说、证据是什么」。
> 3. **AI 是建议者，规则引擎是决策者**。规则引擎永远有最终否决权。骨架不牢，肌肉就是烂肉。
> 4. **先跑通规则，再上 AI**。你连「没有 AI 的推荐长什么样」都不知道，就没资格说 AI 让它变好了还是变坏了。
> 5. **AI 的终极目标不是替代你的教学判断——是让你发现你自己都不知道的教学判断，然后让你来决定要不要采纳。**

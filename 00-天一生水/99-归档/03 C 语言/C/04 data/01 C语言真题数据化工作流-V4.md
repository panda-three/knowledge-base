# C语言真题数据化工作流

> 核心判断：数据化的本质不是"把题整理好"，而是**把教学判断从人脑迁移到系统**。
> 老师一眼看出"这道题和那道题像"——这件事要被拆成标签 + 规则 + 反馈，
> 让系统替老师做 80% 的匹配，老师只做最后 20% 的校准。

## 一、目标与总流程

1. 工作流目标
    - 把历年 C 语言真题从"题目堆"变成"可推荐相似题的数据资产"
    - 最终交付：学生做完一道题，系统立刻推荐 3 道最值得继续练的题

2. 总流程（9 步 · 3 阶段）

| 阶段 | 步骤 | 核心产出 | 执行频率 | 主导 |
|---|---|---|---|---|
| ⚡ 数据生产 | 1–4 | 打完标签的题目卡 | 每道题一次 | AI 初版 → 人工校准 |
| 匹配引擎 | 5–6 | 相似度分数 | 每次搜索时 | 规则自动 |
| 交付与进化 | 7–9 | 练习题组 + 反馈回流 | 每个练习组一次 → 持续 | 人工 + 系统 |
> 📍 快速定位：**首次搭建**看阶段一 → **日常选题**看步骤 6–7 → **系统调优**看步骤 9

3. 设计原则（4 条硬约束）

| # | 原则 | 违反后果 |
|---|---|---|
| ① | **原料不可篡改**：原始真题只读，标注在题目卡层面完成 | 来源不可追溯 → 后续校准失去锚点 → 系统信任崩塌 |
| ② | **标签驱动匹配**：标签质量 = 匹配质量，核心是"答案相关考点" | 标签过泛 → 相似题搜索变成随机推荐 → 学生做三道不相关的题 |
| ③ | **最小闭环先行**：先跑通一道题的完整链路，再扩展 | 一开始就想做全 → 规则没验证就铺量 → 返工成本 ×10 |
| ④ | **反馈反向更新**：学生错题数据是系统变准的唯一燃料 | 没有回流 → 标签永远是死的 → 系统不会比第一周更聪明 |
## 二、九步详解

### 阶段一：数据生产（步骤 1–4）⚡ 杠杆阶段

> 这一步的成败决定整个系统的天花板。标签不准，搜索和推荐都是垃圾进、垃圾出。

1. 第一步：保留原始真题
    - **操作指令**：把原始真题放到 `07 项目 ing/C/03 刻意练习/C语言整理/真题/`，设为只读
    - **判断依据**：原始真题是系统唯一的事实来源。任何时候都要能从题目卡反向定位到原文件
    - ⚠️ 最常见错误：在原始文件上直接修改 OCR 错误 → 正确做法：在题目卡中备注，原文不动
    - ✅ 判断标准：任意一张题目卡，3 秒内能找到对应的原始真题文件

2. 第二步：题目切片
    - **操作指令**：一道题拆成一个文件，保留题干、代码、选项、空号、图表说明——一切做题所需信息
    - **判断依据**：切片的目标是"不看原卷就能做题"。如果还需要回去翻原卷，切片失败
    - ⚠️ 最常见错误：只复制代码段，丢了题干上下文 → 未来打标签时不知道这道题到底在问什么
    - ✅ 判断标准：只看切片文件就能完整做题，不需要任何外部信息

3. 第三步：生成 V3 题目卡 ⚡
    - **操作指令**：用 [[07 项目 ing/C/04 data/30 题目卡V3模板-V2]]，AI 填入 8 个维度的标签
    - 每张题目卡包含：完整题目 / 重要性 / 题型 / 答案相关考点 / 解题动作 / 易错点 / 相似题搜索 / 难度
    - **关键判断**：**"答案相关考点"≠"题目涉及的知识点"**。一道题里出现了 `switch` 语法但解题关键是"格式化输出"，那答案相关考点就是后者
    - ⚠️ 最常见错误：AI 把题目里出现的所有知识点都标上 → 答案相关考点变成"知识点清单"，失去匹配价值
    - ✅ 判断标准：不看题目，只看标签，能说出这道题在考什么、怎么解、哪里容易错

4. 第四步：人工校准 ⚡
    - **操作指令**：AI 初版 → 人重点查 4 项 → 改完反向更新规则 → AI 下一轮不再犯同类错误
    - 人工必查 4 项：
        - 重要性是否合理（不是"这道题涉及多少知识点"，而是"这道题在学生练习路径中的位置"）
        - **答案相关考点是否过泛**（最高频错误——AI 倾向于全标上）
        - 相似题搜索标签是否和答案相关考点一致（不一致 = 搜索方向跑偏）
        - 是否保留完整题干上下文
    - ⚠️ 最常见错误：只改题目卡不改规则 → 下次 AI 继续犯同样的错 → 校准变成纯体力活
    - # 工作方式：AI 跑最小闭环 → 人工校准 → AI 固化规则
    - ✅ 判断标准：连续校准 3 张后，第 4 张 AI 初版的错误类型和前 3 张不同——说明已发现的模式被固化了

### 阶段二：匹配引擎（步骤 5–6）

> 这个阶段是规则自动执行的。人的工作在前一阶段（标签打准），这里只管跑。

5. 第五步：相似题搜索
    - **操作指令**：从一张重要题目卡出发，读三个标签（答案相关考点 / 解题动作 / 相似题搜索），到历年真题中匹配
    - **关键判断**：不只搜同一个知识点，也要搜同解题动作的题——知识点不同但解题思路相同的题，对学生迁移训练的价值更高
    - ⚠️ 最常见错误：只按知识点搜索 → 搜出来的题"知识点一样但做法完全不同" → 学生困惑"这和刚才那道题有什么关系"
    - ✅ 判断标准：搜出来的题，老师扫一眼觉得"确实该推荐"，而不是"这也算相似？"

6. 第六步：相似度判断 ⚡

| 条件 | 分值 | 为什么是这个权重 |
|---|---|---|
| 题型相同 | +1 | 题型只是外壳，不是核心——选择题和编程题可能考同一个考点 |
| **答案相关考点相同** | **+3** | 考点是匹配的灵魂——考点不一样，其他全一样也没用 |
| **解题动作相同** | **+3** | 动作是迁移的关键——同一套解题思路能跨题型、跨知识点迁移 |
| 易错点相同 | +1 | 微调——同一考点但学生错在不同的地方，匹配度打折扣 |
| 难度接近 | +1 | 微调——难度跨度太大会导致推荐不适用 |
| 分数 | 级别 | 学生看到什么 | 使用场景 |
|---|---|---|---|
| 8–9 | 高相似 | "和刚才那道几乎一样" | 同构练习——巩固动作，建立信心 |
| 6–7 | 中相似 | "有点像，但要稍微想一下" | 变式练习——考点迁移，测试理解 |
| 4–5 | 迁移练习 | "表面不像，但思路一样" | 跨题型——检验解题动作是否内化 |
> 💡 权重设计本身就是设计语言：答案相关考点 +3 + 解题动作 +3 = 6 分。
> 这两项对了，至少中相似。剩下三项是微调。**如果你发现推荐不准确，优先查这两项标签。**

### 阶段三：交付与进化（步骤 7–9）

> 这个阶段面向学生。前两个阶段做得再好，学生感受不到效果，系统就是失败的。

7. 第七步：生成练习题组
    - **操作指令**：用 [[07 项目 ing/C/04 data/C/31 相似题练习组模板-V1]]，从一道起点题出发，配 3 道题（同构 → 变式 → 迁移），按这个顺序排
    - 练习组只负责选题和排序，不写完整学生版讲解
    - ⚠️ 最常见错误：三道题难度跳跃太大或太小 → 学生要么觉得"都一样"（没挑战），要么觉得"每道都是新题"（没信心）
    - ✅ 判断标准：三道题做完，学生能说出"这三道题其实在考同一件事"——而不是"又做了三道无关的题"

8. 第八步：学生复练
    - **复练路径**（固定，不跳步）：
        - 起点题 → 错了 → **不换知识点** → 先做同构题（动作稳定）
        - → 再做变式题（考点迁移）
        - → 最后做迁移题（跨题型内化）
    - **核心决策**：错了不马上换知识点。宁可在一个点上深挖，不在多个点上浅尝
    - ⚠️ 最常见错误：学生起点题做错了，老师/系统立刻换一个知识点的题 → 学生永远在"第一次见"的状态，形不成练习路径
    - ✅ 判断标准：学生从"我认识这道题"变成"我认识这类题"

9. 第九步：反馈回流 ⚡
    - **操作指令**：每次学生复练后，做 4 件事——
        - 学生错题 → 反向更新易错点标签（标签从"预设"变成"数据验证"）
        - 推荐题不合适 → 回到步骤 6，调相似度权重或检查标签是否过泛
        - 某题反复被推荐且学生正确率高 → 升级为代表题（典型题、锚点题）
        - 某题太综合、每次都被跳过 → 标为拆解题（不适合复练，适合拆成子题）
    - ⚠️ 最常见错误：学生做完就完了，不回流 → 系统不会变聪明 → 第一个月和第六个月的推荐质量完全一样
    - ✅ 判断标准：一个月后，系统推荐的题比第一周更准。不是"你觉得更准了"，是**学生错题率在下降**

## 四、一句话总结

> 原始真题是原料；V3 题目卡是数据单元；标签是匹配依据；**标签质量是天花板**；
> 练习题组是学生复练路径；**反馈回流是系统变准的唯一燃料**。
>
> 整个系统的核心杠杆在步骤 3–4（标签不准，后面全错）和步骤 9（没有回流，标签永远是死的）。
> 把这两步做到极致，剩下的步骤是工程执行。

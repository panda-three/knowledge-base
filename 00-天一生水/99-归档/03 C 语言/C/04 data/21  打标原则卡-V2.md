# 打标原则卡

> 核心判断：人工校准是系统变准的关键。校准不是"凭感觉改一改"，
> 而是在每次校准中总结规则，反向更新到这份原则卡，
> 让 AI 下一次不再犯同类错误。这份文档就是"系统越来越聪明"的燃料。

## 一、使用定位

📍 每次人工校准题目卡时，对照这份原则卡逐条检查。发现新问题时，在本卡中补充规则。AI 打标时也会参考本卡中的原则。

**工作方式**：AI 初版 → 人工按本卡校准 → 规则反向更新 → AI 下次不再犯同类错误。

## 二、硬约束原则（4 条，不可违反）

| # | 原则 | 违反后果 |
|---|---|---|
| ① | **答案相关考点 ≠ 题目涉及知识点**：一道题里出现了 `switch`，但解题关键是"格式化输出"，那答案相关考点就是后者。 | 标签过泛 → 相似题搜索变成随机推荐 → 学生做到三道不相关的题 |
| ② | **相似题搜索标签从答案相关考点反推**：不是从"题目里出现了什么代码"顺推，而是从"学生必须判断的关键代码"反推。 | 搜索方向跑偏 → 明明在考 break 贯穿，搜出来一堆和 break 无关的 switch 题 |
| ③ | **完整题干不可丢失**：打标签时不删减题干、代码、选项、图表。切片文件要能独立做题。 | 标签脱离了题目上下文 → 未来回看不知道为什么打这个标签 → 校准无从下手 |
| ④ | **答案相关考点 1–3 个，不超过 3 个**：超过 3 个 = 至少有一个不是"答案相关"而是"题目涉及"。 | 匹配精度下降 → 每道题搜出一大堆"相似题" → 失去了筛选意义 |
## 三、标签精度判断（四级）

### 3.1 答案相关考点 · 精度层级

| 层级 | 描述 | 示例 | 匹配效果 |
|---|---|---|---|
| ❌ 过泛 | 把所有出现的知识点都标上 | `switch`、`printf`、`float`、`%.2f` | 搜出一大堆不相关的题 |
| ⚠️ 偏泛 | 标了正确方向但不够精确 | `switch-case` | 搜出来的题考点相同但动作不同 |
| ✅ 精确 | 标了影响答案的具体考点 | `switch-case 的 break 贯穿` | 搜出来的题考点和动作都匹配 |
| 🌟 极准 | 标了考点 + 判断条件 | `switch-case 的 break 贯穿 + 格式化输出 %.2f` | 搜出来的题几乎一模一样 |
### 3.2 解题动作 · 精度层级

| 层级 | 描述 | 示例 |
|---|---|---|
| ❌ 过泛 | 动作描述太笼统 | "分析程序"、"理解代码" |
| ✅ 可执行 | 动词开头，学生能照着做 | "追踪变量初值 → 匹配 case → 判断 break → 计算输出" |
- # 判断标准：动作描述必须具体到"学生能照着做"。不能是"分析程序"——学生不知道怎么分析。

### 3.3 易错点 · 精度层级

| 层级 | 描述 | 示例 |
|---|---|---|
| ❌ 太笼统 | 无法反向生成练习题 | "不仔细"、"粗心" |
| ✅ 可反向生成 | 能对应到具体的错误行为 | "忽略 break 导致贯穿执行"、"格式符 %7.2f 写错宽度或小数位数" |
- # 判断标准：看到易错点标签，能立刻出一道"专门考这个易错点"的题。

## 四、典型错误对照表（人工校准重点查这 6 项）

| #   | 错误类型            | 表现                                                          | 正确做法                                    |
| --- | --------------- | ----------------------------------------------------------- | --------------------------------------- |
| 1   | 答案相关考点过泛        | 标了 5 个以上考点，比如把 `switch`、`printf`、`float`、`%.2f`、`scanf` 全标上 | 只保留 1–3 个决定答案的考点                        |
| 2   | 混淆"题目涉及"和"答案相关" | 一道程序填空题，答案是补 `break`——但标签标了 `switch`、`printf`、`for` 循环      | 标 `switch-case 的 break 规则`，其他不标         |
| 3   | 相似题搜索标签和考点不一致   | 答案相关考点标了"break 贯穿"，但搜索标签写 `printf` `%d`                     | 搜索标签从考点反推：`switch` `case` `break` `贯穿`  |
| 4   | 解题动作太笼统         | "理解程序逻辑"、"分析输出结果"                                           | 改为：追踪变量 → 匹配条件 → 判断 break → 计算值 → 匹配格式符 |
| 5   | 题干被删减           | 只复制了代码段，缺少题目描述和输出格式要求                                       | 保留完整题干，确保不看原卷也能做题                       |
| 6   | 重要性凭感觉          | 只因为"这道题综合了很多知识点"就标"必考"                                      | 重要性看"这道题在学生练习路径中的位置"，不是知识点数量            |

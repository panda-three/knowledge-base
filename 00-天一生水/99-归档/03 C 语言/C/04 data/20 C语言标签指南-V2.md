# C语言标签指南

> 核心判断：标签不是"整理文件的分类"，而是**推荐相似题的匹配引擎**。
> 标签越接近学生的解题动作，推荐越精准。标签越泛，推荐越随机。
> 整个标签体系只回答三个问题：这道题在考什么、学生要做什么动作、怎么找到同类题。

## 快速定位

| 你要做什么 | 跳到 |
|---|---|
| 了解标签体系全貌 | 二、标签体系总览 |
| 查某个具体标签怎么写 | 四、标签库 → 找到对应考点分类 |
| 打标时判断"这个标签该不该打" | 三、硬约束原则（逐条对照） |
| 打完标检查质量 | 三、硬约束原则 → 最后的质量检查清单 |
| 看一个完整示例 | 七、完整示例 |
| 第一次打标，不知道从哪开始 | 八、实施顺序 |

## 一、使用定位

这份指南用于给 C 语言真题、模拟题、课堂题打标签。每道题至少打 6 类标签：重要性、题型、答案相关考点、解题动作、易错点、搜索词。

**标签的最终目的不是整理文件，而是推荐相似题。** 打标时始终问自己：这个标签能帮我在历年真题里找到"和这道题最像"的题吗？不能——就不打。

**标签命名三原则**：
- **短**：2–8 个字优先，不写长句。代码关键词保留英文，概念标签用中文
- **稳**：同一意思只保留一种写法。如统一用 `switch-case`，不混用 `switch`、`switch语句`
- **可检索**：标签越接近学生做题动作，越有推荐价值

## 二、标签体系总览

| # | 标签类别 | 回答什么问题 | 用于什么 | 每道题数量 |
|---|---|---|---|---|
| 1 | 重要性 | 这道题值不值得重点练 | 决定讲解、复练和推荐优先级 | 1 个 |
| 2 | 题型 | 这道题以什么形式考学生 | 把相同作答形式的题放一起 | 1–3 个 |
| 3 | 答案相关考点 | 不知道哪些考点就做不出这道题 | 相似题搜索的核心依据（权重 +3） | 简单题 2–4 个 / 综合题 5–9 个 |
| 4 | 解题动作 | 学生做题时要执行什么动作 | 寻找关联性最高的题（权重 +3） | 3–8 个 |
| 5 | 易错点 | 学生最容易错在哪里 | 错题后的精准补练 | 1–5 个 |
| 6 | 相似题搜索标签 | 搜索相似题时用什么关键词 | 文件检索、AI 检索、题库匹配 | 若干 |
| 7 | 难度 | 适合哪个阶段学生练 | 安排练习顺序 | 1 个（1–5 级） |
> ⚡ 答案相关考点 +3 + 解题动作 +3 = 6 分。这两项是相似度打分的核心权重。**标签打不准，后面全错。**

## 三、硬约束原则

### 原则 ①：答案相关考点 ≠ 题目涉及知识点

**只标影响答案的考点，不标题目里泛泛出现的所有知识。**

- 判断方法：问自己——学生不知道这个考点，还能不能做出答案？能 → 不打。
- 综合题出现了 `int`、`float`、`for`、`if`——但如果解这道题不需要区分这些，就不打。
- `switch` 输出题：标 `switch-case`、`break`、`printf格式化输出`、`%7.2f`。**不必**因为题里有 `int`、`float` 就都打上数据类型标签。

### 原则 ②：相似题搜索标签从答案相关考点反推

**搜索标签不是把代码关键词全列出来，而是从答案相关考点反推出"能定位同类题的关键词"。**

- 考点是 `switch-case` → 搜索标签写 `switch`、`case`、`break`
- 考点是 `折半查找` → 搜索标签写 `折半查找`、`low`、`high`、`mid`
- ⚠️ 删除泛搜索词——不因为题目中出现 `int`、`for`、变量名就放入搜索标签

### 原则 ③：题目卡必须保留完整题目上下文

包括题号、题干、作答要求、表格或图示说明、代码。**不能只保留代码。**

- 程序阅读题必须保留"要求写运行结果"等题干说明
- 程序填空题必须保留空号和功能描述
- 文件题、结构体题必须保留数据表或文件结构说明

### 质量检查清单（打标后逐条过）

- [ ] 答案相关考点都是"影响答案"的吗？有没有标了出现但无关的？
- [ ] 相似题搜索标签是从答案相关考点反推的吗？有没有泛搜索词？
- [ ] 解题动作是否以动词开头，学生能照着做？
- [ ] 易错点能反向生成练习题吗？
- [ ] 题目卡是否保留了完整题目上下文？

## 四、标签库

### 4.1 重要性标签

| 标签 | 含义 | 使用场景 |
|---|---|---|
| `重要` | 代表核心考点或高频拿分动作 | 优先讲、优先练、优先找相似题 |
| `不重要` | 综合度过高、复用价值低，或不适合当前阶段 | 保留记录，不优先大量练 |
| `代表题` | 最能代表某一类题的标准样例 | 作为练习组第一题 |
| `拆解题` | 整题太综合，但内部包含多个可拆训练点 | 拆成若干小练习后再练 |
- 第一轮可以只用 `重要` / `不重要`；题库变多后再细分 `代表题` 和 `拆解题`

### 4.2 题型标签

**基础题型**（每题至少 1 个）：
- `选择题`、`判断题`、`填空题`、`程序阅读题`、`程序填空题`、`综合理论题`、`编程题`

**程序阅读细分**（可选 1–2 个）：
- `输出结果题`、`变量追踪题`、`循环次数题`、`数组结果题`、`字符串处理题`、`文件流程题`

**程序填空细分**（可选 1–2 个）：
- `语句补全题`、`条件补全题`、`循环边界补全题`、`函数调用补全题`、`文件操作补全题`、`数组处理补全题`、`字符串处理补全题`

## 五、相似题推荐与打分规则

### 5.1 三类相似题

| 类型 | 相似度 | 特征 | 练习组顺序 |
|---|---|---|---|
| 同构题（高相似） | 8–9 分 | 题型相同 + 考点相同 + 动作相同 + 易错点相同 | 第一题——巩固动作 |
| 变式题（中相似） | 6–7 分 | 考点相同 + 动作基本相同 + 情境不同 | 第二题——考点迁移 |
| 迁移题 | 4–5 分 | 考点不同 + 解题动作相同 | 第三题——跨题型内化 |
### 5.2 打分规则

| 条件 | 分值 | 为什么 |
|---|---|---|
| 题型相同 | +1 | 题型只是外壳——选择题和编程题可能考同一个考点 |
| **答案相关考点相同** | **+3** | 考点是匹配的灵魂——考点不对，其他全一样也没用 |
| **解题动作相同** | **+3** | 动作是迁移的关键——同一套思路能跨题型、跨知识点迁移 |
| 易错点相同 | +1 | 微调——同一考点但学生错在不同地方，匹配度打折扣 |
| 难度接近 | +1 | 微调——难度跨度过大会导致推荐不适用 |
| 分数 | 级别 | 动作 |
|---|---|---|
| 8–9 | 高相似 | 优先推荐 → 做第一题 |
| 6–7 | 中相似 | 做第二题 |
| 4–5 | 迁移题 | 做第三题 |
| 3 以下 | — | 暂不推荐 |
> 💡 答案相关考点 +3 + 解题动作 +3 = 6 分。这两项对了至少中相似。**推荐不准时，优先查这两项标签。**

### 5.3 练习题组生成规则

每道相似题保留 5 个模块：题目来源、相似题类型、推荐理由、题目切片、相似度打分。

- 不单独列"学生要练的动作"——动作已隐含在题目卡和推荐理由中
- 推荐理由要短：只说明为什么适合放进题组，不写过多教学解释
- # 题组文件服务"选题和排序"，不是学生版讲解文档

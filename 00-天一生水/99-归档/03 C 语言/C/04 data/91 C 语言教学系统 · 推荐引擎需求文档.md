# C 语言教学系统 · 推荐引擎需求文档

> **一句话定义**：推荐引擎是这个系统的大脑。
> 它在学生每次点击「开始练习」时，根据学生画像 + 练习意图 + 历史数据，从题库中选出一道「刚好够不着、但已有能力能推导」的题。
>
> **不是随机出题，不是按顺序出题——是精准调度。**

## 一、输入：引擎每次决策依赖什么

### 1.1 学生画像（持久层，Supabase 存储）

```json
{
  "student_id": "zhang_san_001",
  "segment": 3,
  "title": "指针猎手",

  "knowledge_points": {
    "指针操作": { "accuracy": 0.85, "speed_avg": 72, "last_practiced": "2025-07-10", "total_attempts": 34 },
    "字符串遍历": { "accuracy": 0.60, "speed_avg": 120, "last_practiced": "2025-07-14", "total_attempts": 22 },
    "数字进位累积": { "accuracy": 0.30, "speed_avg": 180, "last_practiced": "2025-07-13", "total_attempts": 15 },
    "字符分类判断": { "accuracy": 0.75, "speed_avg": 95, "last_practiced": "2025-07-14", "total_attempts": 28 }
  },

  "solution_actions": {
    "画内存图": { "speed_avg": 132, "success_rate": 0.70, "total_uses": 45 },
    "代入法": { "speed_avg": 85, "success_rate": 0.82, "total_uses": 38 },
    "边界测试法": { "speed_avg": 110, "success_rate": 0.55, "total_uses": 20 }
  },

  "error_tags": ["数字进位累积", "野指针", "数组越界"],

  "practice_history": ["2026-75", "2025-32", "2024-18"],

  "frontier_labels": ["链表", "动态内存分配"]
}
```

### 1.2 练习意图（每次练习前必选）

- **补弱**：专项突破弱点 → 权重倾斜 error_tags 和低准确率考点
- **提速**：追求解题速度 → 选中等难度 + 侧重速度追踪可比的题
- **拓新**：挑战未接触考点 → 优先 frontier_labels + 冷启动挑战
- **维稳**：防遗忘回顾 → 走间隔重复逻辑

### 1.3 上下文参数

- `mode`：练习 / 挑战 / 模拟
- `limit`：本次练习预计题数（1–10）
- `exam_target`：模拟模式下目标考试年份

```json
{
  "question_id": "2026-75-V2",
  "match_reason": "补弱·数字进位累积 | 间隔第3天 | 动作链重叠3步",
  "difficulty": 3,
  "time_limit": 180,
  "pre_diagnosis": "系统预判：你可能在第3步『进位累积』翻车",
  "next_action": "做完后可一键练『同考点·改错题』"
}
```

## 三、核心调度：四维策略如何协同

### 维度一 · 间隔重复调度

**目标**：在最容易遗忘的时间点精准复习。

**算法逻辑**：

```
同一考点上次正确 →
    间隔序列 = [1天, 3天, 7天, 30天, 90天]
    当前间隔 = 找到上次正确对应的间隔 → 取下一级
    超过最长间隔 → 归入「维稳」池，90 天轮一次

同一考点上次错误 →
    间隔 = 0（立即重新调度，走错题变异，换题不换考点）
```

**关键规则**：
- 同一考点连续对 3 次 → 间隔跳级（1 → 7 天，跳过 3 天）
- 同一考点间隔复习时错误 → 降级（7 → 3 天）
- 间隔到期日前后 ±1 天弹性窗口

---

### 维度二 · 弱项高频渗透

**目标**：弱点不等到下次课，持续渗透进每次练习。

**触发条件**：`accuracy < 0.50 且 total_attempts ≥ 3`

**每次出题概率分配**：

```
活跃弱项考点题：30%
意图主攻方向题：30%
非舒适区调控题：40%
```

**渗透规则**：
- 同时最多追踪 3 个活跃弱项
- 混入时不打标签、不预告
- 做对 → 静默记录，不庆祝（防学生意识到规律后依赖）
- 退出条件：`accuracy ≥ 0.70 且连续 3 次正确`

---

### 维度三 · 非舒适区调控

**目标**：永远让学生在「刚好够不着」的地方。

**难度自动爬坡**：

```
当前考点 accuracy：
    ≥ 0.85 → 难度 +1
    0.60–0.85 → 维持
    0.35–0.60 → 维持（最佳区间）
    < 0.35 → 难度 -1（回退，但换题型）
```

**跨题型追击序列**：

```
同一考点轮换题型：
    第 1 次：选择题（识别）
    第 2 次：程序阅读题（追踪）
    第 3 次：改错题（诊断）
    第 4 次：编程题（生成）

accuracy ≥ 0.85 后 → 优先改错题和编程题（更高认知负荷）
```

**多样性硬约束**：

```
过去 10 题中：
    同考点 ≤ 3 道
    同题型 ≤ 4 道
    同难度 ≤ 6 道

过去 3 题中：
    禁止同题号重复
```

---

### 维度四 · 意图权重叠加

**补弱模式**：

```
出题池权重：
    活跃弱项考点：50%
    历史错题同类考点：25%
    前序知识塌方考点：15%
    随机同段位考点：10%
```

**提速模式**：

```
出题策略：
    难度限制：当前 level 或 level-1（不挑战高难度）
    优先：解题动作已知 + 考点已知的题
    侧重：速度追踪——选上次同类题速度低于平均的考点
    限时：班级最快速度的 120%
```

**拓新模式**：

```
出题策略：
    优先 frontier_labels（未接触考点）
    优先冷启动挑战（新考点 + 已练动作）
    难度 -1 起步（降知识门槛，动作门槛不变）
    拓新题正确后 → 考点移出 frontier_labels，进入正常画像
```

**维稳模式**：

```
出题策略：
    按间隔重复队列取到期考点
    难度维持当前 level
    优先历史高正确率但久未练习的考点
    10% 概率混入弱项题（防完全回退）
```

## 四、决策流程：每道题如何选出

```
Step 1: 读学生画像 + 练习意图
        ↓
Step 2: 意图权重分配（四维叠加）
        ↓
Step 3: 生成候选题目池（从题库按标签匹配）
        ↓
Step 4: 过滤（多样性规则 + 过去 10 题去重 + 冷启动规则）
        ↓
Step 5: 排序（按优先级公式打分）
        ↓
Step 6: 取 Top 1，拼装输出（含 match_reason + pre_diagnosis + next_action）
```

## 五、排序公式：候选池如何打分

```
score =
    + intent_match_weight × 10    // 意图匹配程度（0–10）
    + interval_urgency × 8         // 间隔到期紧迫度（0–10）
    + weakness_boost × 6           // 弱项加成（0 或 1）
    + non_comfort_zone_fit × 5     // 非舒适区适配度（0–10）
    - diversity_penalty × 4        // 多样性惩罚（同类过多扣分）
    - recency_penalty × 3          // 近期做过扣分
```

**排序后取 Top 1，平分则随机选。**

## 六、特殊场景调度

**6.1 冷启动（新学生，无历史数据）**
- 首次练习：难度基础 + 考点全覆盖摸底卷（5 道，涵盖 3–5 个核心考点）
- 根据摸底结果初始化学生画像
- 画像建立后再启动非舒适区调控

**6.2 连续错误（同一考点连错 3 次）**
- 暂停该考点推送 24 小时
- 推送前序知识诊断：「你可能需要先确认前序知识是否扎实」
- 推送 2 道前序考点题 → 做对后回到原考点

**6.3 全部考点 accuracy ≥ 0.85**
- 开启拓新模式——推送 frontier_labels 未接触考点
- 开启跨题型追击——用编程题和改错题替代选择题
- 开启动作搭桥——组合两个熟练动作出复合题
- frontier_labels 为空 → 开放「上限挑战模式」

**6.4 练习中断（学生中途退出）**
- 保存当前练习进度
- 下次登录首页弹：「你上次的练习还没完成——继续吗？」
- 继续则从中断点恢复；不继续则标记「随意练习」（刻意指数 -1）

**6.5 每日一题（非意图驱动）**
- 每日固定时间推送（学生设定）
- 不要求意图选择 → 系统默认「维稳 + 轻量补弱」
- 题目难度 = 当前段位 -1（轻松完成，形成习惯）
- 不计入刻意练习统计，归入「日常维持」

## 八、进化路线：从规则引擎到机器学习

**阶段一 · 规则效果追踪**
- 追踪每条调度策略的学生后续表现
- 发现哪些策略组合对哪种学生画像最有效

**阶段二 · 知识点关联挖掘**
- 分析全班错题数据 → 发现隐藏的考点关联
- 例：做错「数字进位累积」的学生，70% 也做错「ASCII 码理解」→ 自动建立隐性前序依赖

**阶段三 · 协同过滤**
- 相似学生画像匹配 → 看谁进步快 → 复制其练习路径
- 张同学的弱项和李同学三个月前一样 → 推荐李同学当时的练习序列

**阶段四 · A/B 测试框架**
- 教师可配置：同一班级随机分两组
- 测试不同调度策略的效果差异
- 数据驱动的教学决策

## 九、技术实现路径

**MVP（规则引擎）**
- 四维调度策略完整规则编码
- 候选池查询：Supabase 全文搜索 + 标签过滤
- 打分排序在服务端完成
- Redis 缓存学生画像（每次练习后异步更新 Supabase）

**V1.5（规则引擎 + 间隔调度队列）**
- 间隔调度任务队列（Redis + BullMQ）
- 每日定时任务扫描到期考点 → 推送提醒
- 学生画像增加「遗忘曲线参数」——每个考点独立的遗忘速率

**V2.0（轻量 ML 引入）**
- 知识点关联挖掘：关联规则算法（Apriori）
- 协同过滤：基于学生画像聚类的相似学生匹配
- 模型部署为独立微服务，作为打分因子之一

---

> **设计铁律**：
> 1. **标签决定天花板**。推荐引擎的底线是「不推错题」——宁可漏推，不推不相关。标签打不准，引擎再聪明也没用。
> 2. **每道题的推荐理由必须可解释**。match_reason 字段让学生和老师都能看懂「为什么是这道题」。
> 3. **规则引擎先行，ML 是锦上添花**。规则跑不通的，ML 救不了。
> 4. **多样性保障是硬约束，不是软建议**。连续 3 道同类题 = 推荐引擎失职。
> 5. **引擎的终极目标**：让学生觉得「系统比我还了解我哪里弱」。

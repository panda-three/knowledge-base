# 产品内核中「最小」与「完备性假设」的边界如何划定？

## 问题来源

[[product-core]]（产品内核）强调「最小」——少一个特性产品不成立，多一个特性对产品影响不大。但 [[product-core-canvas]]（产品内核画布）同时引入了「完备性假设」——N 条组合在一起可以达到一个很好的结果。

这两个概念之间存在内在张力：如果产品内核是「最小」的，为什么还需要 N 条组合？如果 N 条组合才能达到好结果，那「最小」的边界在哪里？

## 待探索方向

- 「最小」是指单条假设的最小集合，还是指组合假设的最小集合？
- 完备性假设中的 N 是否有上限？如何判断 N 是否过多？
- 是否存在操作标准来区分「最小内核」和「完备组合」？
- 在不同行业（2C vs 2B vs 平台型产品）中，这个边界是否有不同的划定规则？

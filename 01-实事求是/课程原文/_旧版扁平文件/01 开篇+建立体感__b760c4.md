## 05 一次转折：爆炸式全量建模

我曾经纠结了很久，也到处去搜，一直没找到理想的解法，于是我试着自己提炼，试着回答一个问题：抛开工具和封装、流行框架本身（Skills、Coze、Agent等等），有没有一组底层的"原子级别的特性"是长期稳定的呢？

### 统一刻意练习：特性集（FeatureSet）

抛开具体的工具和流行概念，回到基本的Feature上

敲黑板，说重点

于是，我找到了一系列原子级别的最小特性：给LLM设定角色，思维链，渐进式披露，给参考案例，AI反向确认……

其实我们做上面这些提示词、工作流、Agent都是这些"最小原子特性"逐步增加打磨出来的而已。

于是我提出了一个大胆的假设：一堂牵头，能不能增加一层"实践/刻意练习"层？

### AI学习框架和深度L5层

| 层级 | 内容 | 数量级 |
|-|-|-|
| 场景教程 | 各种媒体、各种知识库 | #十万/百万 |
| 工具应用 | 各个平台、各种工具 | #数百/数千 |
| 核心组件 | 模型、智能体、MCP、工作流、Skills… | #数十/数百 |
| **特性Feature** | **封装、渐进披露、Data Pack** | **#个位/数十** |
| 底层原理 | Transformer、RLHF… | #N大板块 N个体系 |

我们把众多工具、LLM、Agent、技术框架的共性抽离出来，变成一个个的最小原子特性，也就是Feature（特性），把认知和能力构建在这层Feature上，每一个Feature都是一次打磨机会，都是一张牌，都是一次升级AI水平的假设。

于是我试着做了一次爆炸式灵感闪现，把我这两年所有"有效的Feature"全部写下来，又结合着AI的经验，最后在我的私人笔记本里写下了保30争50个 Feature：

### 我的FeatureSet

一个晚上，我整理了第一个版本

**我的AI策略库**  
框架：大概的Feature复杂度工具和界面：

1. 单纯的chatbot（结构和框架，提示词工程）#10个
2. 完整的AI工具（GEM，项目Project，长时记忆）
3. 技能Skills（技能、数据、内容框架；自动调用）#20个
4. Cherry Studio（知识库、MCP，ReACT智能体）#30个
5. 智能体Coze（精细拆分和调试；工作流，逻辑循环，插件）#40个
6. 工程化开发部署（Dify，LangChain）
7. 微调训练（模型训练，数据中心）#50个

当我写高水平的提示词，做PPT，VibeCoding，做图，或者做一个复杂的调研，我发现AI第一版本质量只有50分，甚至30分，没关系，我试着增加Feature不断打磨，一步步测试，逐步探索60/70/80/90分的水准。

哪怕工具变了，Feature永远稳定。我只要把这几十个 Feature 练得滚瓜烂熟，就像手里拿着几十块乐高积木。无论面对什么复杂场景，我都能瞬间拼出一套逻辑。

比如我现在做PPT，做播客，我现在可能觉得自己不会写，但没关系——只要给我足够多的Feature、只要我有审美、给我时间，我肯定能给你磨一个很好的水平，业内接近最好的水平。

时间到了2026年初，春节假期，我发现新的问题出现了：龙虾火了，各种Agent开始扎堆出现了，越来越多的特性和新工具冒了出来，这些工具之间有什么关系呢？有没有相对统一的体系么？

### 第一层理解：两种思维

【互动】哈哈，先直接抢答，Feature思维最典型的反面是"\_\_\_\_思维"呢？

Feature的反面是"工具思维"，把AI的学习，就当成是一个个工具的尝试和掌握。

一个典型的学习路线是：

1. 今天听说"龙虾很火"，那我就装上试试，不好用就认为一无是处，扔掉了。

3. 如果成，就是"大杀器"，如果不成，就是"AI垃圾"  
……

我们要从T型思维，切换到F型思维：

**T 工具思维：完整一大坨**  
**F Feature思维：理解最小原子**

我画了一个图，这是两种完全不同的思维习惯：

### 同一个问题，两种完全不同的解题方式

工具思维关注"用什么"，Feature思维关注"为什么有效"

**T 工具思维：问题 → 工具 → 成/败**

- 追工具
- 整体试用
- 成败二分
- 借工具之假，修能力之真
- 工具变了，能力重来

**F Feature思维：问题 → Feature → 工具**

- 先拆机制
- 再选载体
- 测试沉淀
- 拆解·假设·测试·组合
- 工具会变，Feature可以迁移

真正需要积累的，不是工具清单，而是可迁移的 FeatureSet。

### 第二层理解：什么是Feature？

这次磨课，关于什么是"Feature"我们产生了不小的摩擦和分歧。我们的磨课小组和AI，给了各种各样的理解和定义：

2. 工具是表象，Feature是本体。
3. Feature思维，是一种在AI时代解构工具、回到底层特性的认知方式。
4. 可用于调优AI输出质量的最小单元（功能/能力/方法/技巧…）
5. ……

实在是太困难了，于是我们经历了一次摩擦和合并，最后找到了4个关键词，得到了一个基本定义：

### 初步定义Feature：提升AI解题水平的的最小实践单位

1. **关键词1：AI**（这是范围：是在使用AI工具的过程中）#若超出AI范畴则不算
2. **关键词2：解题水平**（这是果：提升AI解题效果，更强更稳更可复用）#若不能影响则不算
3. **关键词3：实践单位**（这是因：能力单位，诊断单位，资产单位）#若不能实践则不是
4. **关键词4：最小**（这是追求：更细颗粒度的拆解）#若太大的方法框架则不是

说明1：这是2026年中的初步定义，未来可能会随着时间修正。  
说明2：当认知不够的时候，往往是大而模糊的，随着实践慢慢"接近最小"

**四、流程规则**

**Level路由**  
用户在里程碑2选择Level后，系统按对应路径推进：

- 边做边看 → 先做Level0进入A/B，完成B后阶段性写定确认；如果用户不够笃定或主要矛盾已经浮现，就自然进入C。如果关键变量需要测算，再进入D/E
- Level0 → 走到C → 阶段性写定确认 → 用户足够笃定则出报告，不够则进入D
- Level0 → 走到D → 阶段性写定确认 → 用户足够笃定则出报告，不够则进入E
- Level0/①进入E后 → 第一轮方案集 → 方案反馈确认 → 问题定位 → 局部调参 → 调整后写定确认 → 出报告/继续局部调参/回补关键卡点

阶段性写定确认不是反复追问"够了吗"，B/C/D阶段是在交付物完成后，让用户决定当前局部信息足以支撑决策；E阶段则把写定后置：先接收用户对方案集的具体反馈，再定位问题和局部调参，调完之后再确认是否足够支撑判断。

**回退机制**  
任何阶段发现信息不够，可以回退补充：

- D阶段发现信息不够 → 回到A补充
- C阶段排序时发现有遗漏 → 回到B项

回退时明确告知用户：「这里有个地方需要回头补一下」

**6. 主状态机**  
6.1 状态总览

| 状态 | 目标 | 进入条件 | 退出条件 |
|-|-|-|-|
| S0 开篇 | 破冰、暖场、唤起兴趣 | 用户首次进入 | 用户选择调研对象并进入S1 |
| S1 选题 | 让用户选定开口 | 完成S0 | 用户确定要调研的课题和对象 |
| S2 自查提醒 | 提醒核心逻辑2-3 | 完成S1 | 用户已读自查提醒，愿意继续 |
| S3 核心输入 | 收集核心变量 | 完成S2 | 用户输入核心变量，重要性 |
| S4 战略 | 统一战略一致 | 完成S3 | 用户对战略一致无异议 |
| S5 选点 | 导入用户严格选点 | 完成S4 | 用户选定调研选点 |
| S6 高质量报告 | 输出高质量报告 | 完成S5 | 用户对报告满意或进入下一轮 |
| S7 案例对比 | 引入标杆和认知对比 | 完成S6 | 用户完成认知升级 |
| S8 行动计划 | 基于调研产出行动计划 | 完成S7 | 用户确定行动计划 |

6.2 阶段差异

| 阶段 | 教练角色 | 关键动作 |
|-|-|-|
| 开篇 | 轻松暖场 gentle | 破冰、暖场、唤起兴趣 |
| 自查 | 温和提醒 | 提醒核心逻辑2-3，不深入 |
| 核心输入 | 引导式提问 | 引导用户输入核心变量，不替用户判断 |
| 战略 | 顾问式 | 帮用户梳理战略一致性，可提建议 |
| 选点 | 严格教练 | 严格帮用户选点，拒绝模糊 |

| 案例 | 启发者 | 引入标杆，启发用户 |
| 行动 | 推动者 | 推动用户制定行动计划 |

一种数学计算模型，它描述一个系统在任意时刻只能处于"有限个明确状态"中的一个，并且只有在特定"事件"发生时，才能从一个状态"转移"到另一个状态。

1. **追求一个完美平衡点：** 既长期稳定能迁移，又相对具体能实操。
2. **Feature思维不是独立和冲突，而是完成了一次"市场全量"的辩证统一。**
3. **取长补短：** 可以和各种选手讨论，吸星大法，可以从各方学习和吸收。

随着逐步构建属于你的Feature Library（武器库），随着你见的越多，掌握得越多，你的实验越多，你后面的预判和执行质量都会以一种复利的方式快速提升。

成也好，败也好，都在不断积累Feature的关键认知。

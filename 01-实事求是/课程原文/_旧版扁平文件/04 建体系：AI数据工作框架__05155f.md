## 建体系：一套通用范式

### 一个美好设想

> **一个美好的期待和幻想**  
> 敲黑板，说重点

不管是短期还是长期，不管是个人、团队、公司，有没有可能建立一个长期稳定的认知框架，来消除盲区，修炼高阶能力，不断积累核心数据呢？

我们内部提出了一个美好的设想，一个好的模型应该满足4个条件：

1. **足够抽象**：可以长期使用，跨越不同公司、岗位、项目。
2. **足够具象**：可以指导具体实操和AI数据能力的构建。
3. **足够完备**：最好不重不漏（MECE），最好是个里程碑模型。
4. **足够好记**：越简单越好，容易理解，记忆，方便随时调用和分享。

怎么做呢？

这是一个非常专业（kuzao）的建模和研究工作，为了增加大家的可信度，我简单说一下形成的过程吧。

我们这一次收集到了大量的AI数据技巧和处理策略：

太多了太乱了是吧？

我们搜集了很多常规数据挖掘的经典流程：

1. ETL：抽取 -> 转换 -> 加载
2. 数据生命周期：规划 -> 收集 -> 清洗 -> 质保 -> 描述 -> 保存 -> 发现 -> 整合 -> 分析 -> 应用 -> 归档
3. 数据挖掘：业务理解 -> 数据理解 -> 数据准备 -> 建模 -> 评估 -> 部署

我们也找到了这几年慢慢形成的AI数据处理最佳实践：

1. RAG：来源 -> 解析 -> 清洗 -> 切片 -> 元数据 -> 向量化 -> 索引 -> 检索 -> 重排 -> 上下文注入 -> 生成 -> 引用 -> 评估 -> 更新
2. 微调：定义任务 -> 建eval -> 收集样例 -> 格式化数据 -> 训练/测试拆分 -> 微调 -> 评估 -> 错误分析 -> 修数据 -> 再训练/部署
3. 评测：定义行为 -> 数据集 -> 评分器 -> 跑分 -> 比较 -> 加边界样例 -> 回归评测

我们不是在新增一个流程，而是试图再抽象一层判断模型。

1. 如果只讲 ETL，大家会以为这是一门传统数据工程课。
2. 如果只讲 RAG，大家会以为这是一门知识库搭建课。
3. 如果只讲微调，大家会误以为 AI 数据处理的终点就是训练模型。
4. 如果只讲评测，大家又会觉得这是高级工程团队才需要的事情。

而我们试着从各个成熟流程的精华和最佳实践里，抽离一套共性节点，抽象出一套更上层、更通用的 AI 数据里程碑模型。

我们发现经典数据体系里面，有一些重要的经验：

1. 先确定出口，再收集材料；
2. 先保留原始，再加工结构；
3. 先让 AI 找得到，再让 AI 用得对；
4. 用完以后，要及时评估和反馈。

> **我们抽离了六个高价值里程碑节点**  
> 敲黑板，说重点

于是我们试着抽离出了一个"大一统"的看似非常值钱的模型：**价值预判，数据识别，收集入湖，处理加工，场景使用，反馈迭代。**

为了方便大家理解，我们做了关键词化简：**预判，识别，收集，处理，使用，反馈。**

1. **预判**：思考未来，以终为始，思考数据长期的场景和价值。
2. **识别**：分析现在，识别数据，哪些数据值得关注和优先级。
3. **收集**：及时采集，收集入湖，主动获取数据、确保可追溯。
4. **处理**：专业处理，清洗萃取，转化成AI可用的高质量数据。
5. **使用**：真正落地，回到场景，使用数据真正实现商业价值。
6. **反馈**：结果评估，信息回流，回到起点迭代形成反馈飞轮。

里程碑的意思是，从前往后一步步推理，从后往前一层层剥离。

每一步丢失都是盲区，每跳过一步都可能有系统性硬伤。

这是六个数据的核心"价值提升节点"，为了保证数据的安全可控，符合基本的法律伦理，我们需要在整个系统各个环节加固一个护栏，还有一个策略：**治理（合规治理）**

哈哈哈，**6+1（六步一横）**关键策略，就覆盖了（几乎）所有的AI数据难题和主要矛盾。

大家跟上了么？

### 一个全新模型

完成了足够抽象、具象、完备，还差一个"简单易记"，于是我们花了三四个小时不断尝试，最终终于完成了一个英语单词：**适应（ADAPTE-D）**。

一句话就能讲香：**哪些人/团队率先适应AI新的数据范式，谁就能尽快抢到行业的稀缺竞争力和壁垒。**

**一堂 AI 数据飞轮 6+1 — ADAPTE-D Model**

| 步骤 | 英文 | 中文 | 核心 |
|-|-|-|-|
| A | Anticipate | 预判 | 以终为始，假设驱动 |
| D | Define | 识别 | 界定事实，语义，反馈 |
| A | Acquire | 收集 | 主动获取，可追溯 |
| P | Process | 处理 | 清洗，结构化，Embedding |
| T | Transform | 使用 | 转化 AI 业务能力 |
| E | Evaluate | 反馈 | 评估，回流，迭代 |
| D | Discipline | 治理 | 合规，权限，伦理，安全，长期治理 |

> 脱离了"场景"讨论数据没有意义  
> 敲黑板，说重点

**一堂AI数据飞轮 · ADAPTED 6+1模型**

Yitang AI Data Flywheel: "Adapt to win. Get ADAPTED to dominate."

- 数据是业务的核心基础
- 业务是数据的核心场景
- 微观（提示词上下文 教材）→ 中观（业务数据流 燃料）→ 宏观（公司数据资产 护城河）
- 工作起点也是价值终点：预判
- 结果终点也是新的起点：反馈

> "未来AI真正的竞争是：谁能率先适应AI新范式，构建出正向的飞轮，不断降低阻力，积累出最稀缺的数据资产。"

注意，不要把这个简单理解成一个简单的"执行动作清单"，如果大家只理解到这一层，就太低估这个模型的价值了，这是一个"**生命周期**"的构建工具，它覆盖了一份数据从「还只是材料」到「成为资产」的主要过程。

有趣的是，不同角色呈现出很大的差异性：

- 数据和技术专家往往擅长345，往往容易容易跳过126；
- 业务和管理专家往往擅长125，往往容易不太擅长346；

而这套模型不只是给大家消除盲区，也可以带到团队，形成团队最大程度的共识和凝聚力，降低未来推进数据建设的阻力。

提醒一下，这个循环是"相对底层和通用"的，但是不同大小的业务呈现出来的结果可能完全不同。

从小到大，本质上都是在构建这个飞轮：

1. 个人用 AI 数据，像**手工作坊**，简单灵活，轻处理就行。
2. 团队用 AI 数据，像**小型生产线**，协作复杂，需要有统一的处理规范。
3. 公司用 AI 数据，像**工业化系统**，需要考虑业务+组织配套，而且需要考虑治理/合规。

## 每一步的初步理解

我们在磨课时候，发现大量的数据处理的策略、技巧和Knowhow，这大概率是一个系列课，甚至每一步都值得一节独立的实操落地课。

今天时间有限，我先带大家快速认识一下每一步里面大概的逻辑吧，我们先初步认识一下。

### 第一步：预判A

> **数据预判：以终为始思考价值**

这是一个最关键的问题：数据系统的起点是哪里？

如果是数据分析师、工程师可能会回答"采集/Input"，作为业务一号位，唯一正确的答案就是"**长期价值预判**"，对于数据长期的价值预判，决定了数据所有的优先级、采集、格式等等。

这一步是必要的，不是管理口号。否则就会出现「把一堆没价值的资料洗得很干净」，付出了极高的注意力和成本，最后发现到最后也没地方用。

**【提问】** 面对长期的不确定性，最好最科学的思维方式是\_\_\_\_\_\_\_？

答案是：**假设思维。**

我们努力思考1个月、1年、3年、5年以后的业务场景，哪些高价值的业务场景需要高价值的数据？价值足够大么？ROI足够高吗？

还是那句话，掌握AI技能是"术"，深刻理解业务才是"道"。

总结一下，假设怎么提呢？通常有三类场景数据会有显著价值。为了结构化思考，我们给大家准备了一个思考画布，大家可以参考：

#### 数据价值假设清单

| 微观（上下文） | 中观（工作流） | 宏观（资产） |
|-|-|-|

**第一种，微观层。**

这一层数据的价值是每一次跟模型对话的关键上下文，是人与大语言模型（LLM）的最小对话循环。

一个形象比喻是：**教材（说明书）**

> 模型在单次推理和执行过程中的参考。

我们讲的Prompt Engineering，有一半关键要素都是跟数据相关，你喂给 AI 的数据质量，直接决定了它回答的质量。

这是最常见、最高频、最多数量的一层，比较容易预判：我有哪些相对稳定的、可复现的LLM对话场景，数据可以显著提升价值？

就像我刚才讲的睡前故事的例子，在日常对话中，学会通过投喂高质量上下文（Context）来"调教"AI。

数据会在这一轮显著提升价值：

- 普通做法：直接命令 AI "帮我做个方案"。（效果：平庸，泛泛而谈）
- 数据增强做法：提供"方法论 + 参考案例集 + 特定模型框架"。

效果显著：AI 的输出显著提升，变得精准且可用。

总结一下：这一层量很大，也很容易做，难点是找到"上下文共性"，哪些是会持续遇到的难题和场景。

**第二种，中观层。**

这一层是具体的业务落地（如内容生产系统、客户服务流）。不是简单的对话，而是系统工程。

一个形象的比喻是：**燃料（助推器）**

> AI业务加热引擎和推动起飞的材料。

这个阶段你要找的不是单个对话的上下文，而是"高价值AI落地细分场景"，是工作流层面的，然后用系统的方法构建一套数据集：参考案例集，正负清单，RAG知识库，Markdown清洗等等。

这个阶段的重心是找到业务高价值的细分AI落地场景：**在特定业务流程中，数据越准确、结构化程度越高，AI产出的业务结果就越具备商业价值。**

**第三种，宏观层。**

最后一层是公司经营战略层的，长期的竞争优势的预判和攒牌。

一个形象的比喻是：**护城河（核心壁垒）**

> 在市场上持续获得竞争优势的稀缺生产资料。

到了宏观，一切细节都消失了，要把重心放在长期客户稳定需求上，放在上下游的价值链上，放在公司竞争的最终竞争获胜预判上。

这个阶段的核心，是抛开所有细节，回答一个本质问题：**思考哪些数据是竞争对手无法积累、无法通过付费获得的？**

这一层是极其奢侈且很难立刻获得，需要持续预判、持续积累，长期攒牌攒出来的。

好啦，第一步我讲完了，如果再实操一点，核心就是反复拷问一句话：

> 未来哪些AI场景有了数据价值巨大？如果要是有这些数据、把AI做成就太好了。

以一堂为例，我试着填一下：

| 微观（上下文） | 中观（工作流） | 宏观（资产） |
|-|-|-|

大家感受到了区别了么？

### 第二步：识别D

> **数据识别：发掘眼下数据优先级**

有了预判价值和场景，就可以大量收集数据了么？NONONO，第二步数据识别很重要。

如果第一步是"未来想要什么"的话，第二步就是"盘点我现在有什么"的过程。

理解了刚才的数据的"3不变3巨变"，把数据的思考打开，你会发现任何一个人，任何一个团队，都有无边无际的海量数据，都可以收集和处理，哪些是高优先级的数据呢？

总结一下，各种各样的数据都能接受了：

| 数据类型 | 典型材料 | AI时代的用途 |
|-|-|-|
| 事实数据 | 文档、报告、手册、字段、记录 | 给 AI 提供事实依据 |
| 语义数据 | 笔记、文章、聊天、访谈、课程稿 | 给 AI 提供知识和语境 |
| 过程数据 | 会议、改稿、评审、销售跟进 | 让 AI 学习判断和取舍 |
| 反馈数据 | 人工修改、用户评价、任务成败 | 让 AI 变得更准 |
| 反例数据 | 错误输出、失败案例、攻击样本 | 做评测和边界测试 |
| 风格数据 | 个人表达、品牌语气、优秀样稿 | 让 AI 模仿风格 |
| 结构数据 | 表格、JSON、标签、字段 | 支持自动化和系统调用 |
| 多模态数据 | 图片、录音、视频、截图、PPT | 扩展 AI 对真实场景的理解 |

这个阶段的重心是基于长期追求，整理眼下的数据优先级，最好按照业务模块分，如果能排序，甚至能区分SABC优先级就更好了，最后把数据的清单拉出来。

这个阶段的核心，是找到一些长期渴望，短期被忽略的"**隐藏暗数据**"：这些数据是宝库，价值千金。

讨论过程中，发现有四个高价值的"暗数据"被之前完全忽略了：

1. **双三角完整聚合**：基于双三角的案例访谈和笔记细节，这是价值极高的数据。
2. **BA对比数据**：产品打磨过程中的反馈，纠偏和BA对比的案例（比如逐字稿撰写）
3. **学员介绍题目**：各个wiki、大航海、组队活动中的自我介绍和秀肌肉。
4. **及时复盘数据**：一个优秀案例完成，趁着热乎/Session立刻复盘过程事实和洞察。

比如最近我很喜欢一个工作"结束立刻复盘"，收集了很多案例：

- 使用工具：ClaudeCode + 国内Top LLM；
- 还有我起硅基名字Trumind完整的过程：

  - 使用工具：DeepSeek免费网页版；

这些内容作为教材，会直接让AI在下一次工作时候，变得专业和聪明很多。

而且如果我没有在30min及时要求AI复盘，估计我和AI都忘了（Session丢了）。

这些数据都是中观-业务流甚至宏观-资产最值钱的生产资料，如果没有停下来认真盘点，识别，整理，头脑风暴，这些数据可能连存都不存，随着时间就全部消失了。

补充：就这两周，我们发现其实还有一个叫"Truman的即兴专业口喷"的数据，这个非常随机、临时、碎片，但是对于某些业务价值巨大，过去完全忽略了。

这个阶段的核心心法是：认真停下来，围绕长期目标，认真做一次加减法，加法要充分，减法要专业，找到"**不重视未来大概率会后悔**"的数据来源，然后把注意力放在这些关键数据源上。

**【自评】** 这一步你过去做的够好么？有大的优化和进步空间么？如果满分100分，60分基本合格，你过去的认知和实操可以打多少分？

### 第三步：收集A

> **数据采集：建立湖仓+及时采集**

好了，有了长期预判，有了短期整理，下面开始干活儿了。

**【提问】** 关于数据的收集和存储，大家遇到最大的困扰是什么？

我们遇到采集最大的困扰就是：我采集存下来并不难（知识库/云盘/笔记/截图），但是我没精力、不会处理啊，这些都一时半会也用不上啊。

你们怎么想？

在这次磨课时候，我们访谈专家，花辣子米、杨晓光和 刘伟等等专家，都不约儿提到了一个类似的逻辑，后面我们给它起了个很生动的名字：**湖仓思维。**

> **湖仓思维：把收集+处理分开，先存下来再说**

时间线拉长，大家遇到最最最糟糕的问题就是：**有一天想清楚了，数据早就扔了，根本追溯不到了。**

很多高价值的数据，本来是金子，因为看不懂，随手就当石头扔了。

所以先主动建立一个湖仓，先别过度思考后面的工作，先别管零散不零散，只要成本够低，只要ROI不太离谱地差，就先都扔进去，未来能找到就行。

不要过度相信自己的数据预判能力，想不清楚就先存：原始录音、聊天、截图、AI对话过程、人工修改轨迹一旦错过，后面很难补。

没关系，接受数据都是散的，先不处理，先扔到湖里养着：你未来想建立三文鱼的罐头厂，你得建三文鱼的生产线，前提是你的湖里得很早就开始有鱼苗。

**【划重点】** 这里的"湖"不是一定要指专业数据湖，往往各种形式都行：

- **结构表**：SQL库，多维表格，Excel文档等；
- **知识库**：飞书空间，印象笔记，Obsidian库，YAI笔记库，NotebookLM，IMA，Get笔记，腾讯文档等；
- **文档库**：百度云盘，U盘磁盘，统一文件夹，NAS等；
- **各种库**：甚至就是一个手机相册（截图），微信传输助手，微信收藏夹，单人微信群等。

我这些年在努力实践这种"长期可能需要，那就先存再说"的习惯，短期不显著，长期价值很大：

1. 我们做投放，我能找到3-5年前朋友圈某些友商（关停）当年的投放素材。
2. 我去做行业级别分享，我能找到2013年当年Qunar对我特别震撼的一个内部分享PPT
3. ……

而且养成"湖仓思维"还有两个附加的好处：

1. 未来可追溯："先保留原始，再加工结构"解决的是不可逆流失。
2. 动手不纠结：快很重要，可以及时捕捉，及时录音，及时复盘，及时改错。

鱼塘早期可能会只是一个小池塘，然后可能会越来越大，最后连塘成湖，连湖成海。

> **虽然鼓励，但是最后两点理性提醒**  
> 敲黑板，说重点

**理性提醒1：当然还是实事求是。**

ROI逆转不等于万物皆存，全部存下来是不现实的。

基本的判断逻辑是成本足够低，且未来可能会用到，浪费了可能会很可惜。

预判价值往往比较难，所以要努力找一些随手的收集技巧，我常用的三个技巧：

1. **立刻截图**：实在想不清/没时间，先截图再说（AI加持的新手机会自动分析）
2. **及时收藏**：我很喜欢点YAI的"收录笔记"按钮，视频号的"私密赞"按钮。
3. **聚合收集**：使用Cubox把多个渠道聚合，自动同步到Obsidian；

**理性提醒2：得初步判断数据质量：**

1. 对低成本、高潜力、不可逆流失的数据，先入湖；
2. 对高风险、高噪音、低价值的数据，谨慎入湖。

事实数据往往都相对可靠，但对于AI生成的数据，尤其是AI叠加AI，幻觉叠加幻觉的数据，要谨慎，可能会污染数据库。

**【自评】** 这一步你过去做的够好么？有大的优化和进步空间么？如果满分100分，60分基本合格，你过去的认知和实操可以打多少分？

### 第四步：处理P

> **数据处理：原始数据变理想数据**

好啦，第四步终于来了，这是最硬核，也是很多人（包括我）最虚的一步：数据处理。

处理之前，数据可能是混乱的，奇形怪状的，质量参差的，无结构的，给人使用的，需要在处理环节，把数据努力变成"高质量的AI可用的数据"。

**【调研】** 大家过去都用过哪些数据处理的方法和技巧？

**【划重点】** 总结一下，有8种常见的AI处理动作：

| 环节 | 价值 | 常见工作 |
|-|-|-|
| **Level1：粗加工** | 1. 理解：洗菜去泥  <br/>2. 价值：让 AI "吃得进" | 1. 转写：录音、视频转文字。  <br/>2. OCR：图片、扫描件、白板转文本。  <br/>3. 清洗：去噪、去重、修正格式。 |
| **Level2：精加工** | 1. 理解：切块装盘  <br/>2. 价值：让 AI "不噎着" | 1. 结构化：Markdown、表格、JSON、标签。  <br/>2. 切片：按主题、任务、问题拆分知识块（RAG）。  <br/>3. 计算：用代码进行数学分析和计算，洞察分析规律。 |
| **Level3：注灵魂** | 1. 理解：调味熬汤  <br/>2. 价值：让 AI "吃得香" | 1. 标注：正例、反例、适用场景、限制条件、来源。  <br/>2. 萃取：把不同文档萃取成指南、方法论、模型。 |

提醒：如果想深度调教/训练AI，**黄金评测集（Golden Dataset）**是最最重要的高价值环节，是衡量AI输出是对是错，只好是坏最重要的数据。

有了 AI，这么抽象的工具箱可以让大家更直观一些：

**AI 数据处理的 8 大动作 —— 喂养 AI 的"米其林主厨三部曲"**

- 01 粗加工（洗菜去泥，让AI"吃得进"）：转写、OCR、清洗
- 02 精加工（切块装盘，让AI"不噎着"）：结构化、切片、计算
- 03 注入灵魂（调味熬汤，让AI"吃得香"）：标注、萃取

> 核心洞察：清单体笔记，就是人类发明的最完美的"AI 便当盒"。让 AI 去做洗菜工，你只做注入灵魂的把关人！

提醒大家一个被忽视的课题：一堂的清单体笔记，以我们的实践来说，或许不是最理想的AI数据形式，但是目前几乎是**人类使用&AI使用平衡得最好**的一种形式：

- 既有AI喜欢的优势：结构化，逻辑层级，去除废话，边界清晰，支持索引，极大减少幻觉。
- 又有人类协作的优势：没有语法，没有心理负担，几乎没有学习和协作成本，人和AI一起进化；
- 无缝随时迁移：从飞书到Obsidian，从Flomo到提示词框，几乎可以无损复制到任何地方。

清单体笔记，本质上就是人类大脑和 AI 大脑之间，效率最高、损耗最低的"API 接口"。它是目前人类使用（没心理负担）和 AI 使用（极低幻觉解析）的最完美公约数。

> 专业解释：数据密度（信噪比）和注意力机制（Attention）

### 第五步：使用T

> **数据使用：积极在高价值场景使用**

好啦，讲完了数据的预判，识别，收集，处理，终于到了使用环节了。

前面都是在"准备"，这个环节才是数据真正发挥价值，赋能业务的一个环节。

**【调研】** 在这个环节上最最重大的挑战是什么？

我们访谈发现，大家大量准备了数据，但真实业务摩擦、组织系统成本极高。

导致用不上，不敢用，数量太大，训练成本太高。

就算顶着压力，一股脑把数据全压上去，结果好坏也很评估啊？

大家遇到类似的困扰么？怎么破？

要短平快，用"**多轮实验**"的心态使用，不要试图Allin一次性赌赢。

AI数据一击即中/非常有效是小概率事件，而持续调试才是常态。

**【划重点】** 这个环节的关键是倒拆里程碑，一步步**徐徐图之**：

1. 先做低成本快验证，再进入复杂的系统；
2. 先做具体假设验证，再合并做统一系统。
3. 先手工搓保持灵活，再封装成自动化流程。
4. 先用投喂方式试试，再考虑复杂微调训练。

> 典型技术幻觉：认为微调（Fine-tuning）是万能药；实际上 80% 的问题 RAG 就能解决。

初步总结一下，数据的使用有五个层次：

#### AI数据使用的5个层次

| 层级 | 层级 | 使用方式 | 成本 | 适合阶段 |
|-|-|-|-|-|
| U1 投喂 | 上下文投喂 | 把资料直接作为上下文给 AI | 低 | 验证价值 |
| U2 封装 | Prompt / Datapack | 封装为提示词/案例包/方法论包 | 低中 | 高频任务 |
| U3 检索 | RAG / 知识库 / 记忆 | 让 AI 检索大量资料 | 中 | 资料规模变大 |
| U4 配置 | Workflow / Agent | 数据 + 工具 + 流程自动化 | 中高 | 稳定业务流程 |
| U5 训练 | 微调 / 训练 | 用标注数据调整模型行为 | 高 | 数据充足且 ROI 明确 |

还是那句话：不要用战术上的勤奋（疯狂堆数据、做微调），掩盖战略上的懒惰（不理解业务逻辑）。AI 数据的使用，本质上是'业务逻辑'的显性化。

衡量这一步做得好不好，其实就是看是不是非常务实、高频地在测试数据价值，靠大量的测试迭代（比如AB）来拿到业务结果。

**【自评】** 这一步你过去做的够好么？有大的优化和进步空间么？如果满分100分，60分基本合格，你过去的认知和实操可以打多少分？

### 第六步：反馈E

> **数据反馈：善于评估+及时反馈回流**

前面各个环节如果是计划里的专业的话，最后一个环节才是高阶选手的核心追求。

最后一个环节，当我拿到了初步的结果，评估正向，就结束了么？

往往拉开长期巨大差距的在于最后一个环节：评估反馈。

数据处理到最后，有两种方式：

- **稳定运行**：线性系统，数据处理拿到预期结果，完成任务就结束了。
- **自我增强**：循环飞轮，数据处理完反馈到前面环节，完成一次自我增强。

比如举个小例子：我讲睡前故事，用AI写了五个故事以后，有了反馈（我的修正，纠偏，儿子反馈）以后，回继续收集数据，迭代到下一阶段的数据里么？还是一直就是同一个水平一直重复执行。

比如，我们开发了一个还不错的"人生红点探索教练Partner"，第一轮差不多合格发布了，内部测试后跑了50个Case，结束以后Partner能再收集一轮信息变强么？又跑了1000个同学案例（作业公开），能持续迭代更新信息变得更强大么？

把 AI 使用过程中的结果、错误、人工修正、用户评价、失败样例、权限问题、过期数据，重新结构化为下一轮数据资产。

这个就是一个最终的追求。

对于一个没有反馈闭环的AI，就像一个永远不听劝的实习生，第一天犯的错，第一百天还会犯。但是当我们有了一套反馈机制（靠人工/AI），就会形成一套数据飞轮。

有了反馈，才有迭代，才有飞轮，才有复利，所谓的"核心资产"和"护城河"才有机会形成。

### 数据护栏：治理D

> **数据治理：合规合法合乎安全**

如果你什么也不做，不会出现什么大的"数据合规安全问题"，反而你数据飞轮转起来了，转的越快，速度越猛，越容易失控和跑偏。

**【互动】** 你们过去有遇到过，或者听说过，因为用AI、因为数据，而出问题的事情吗？

我不知道大家有没有看到过各种各样的"安全/合规性风险"：

1. **违反法律法规**：随着AI进步相关的政策法规也在调整，务必重视相关内容，尤其是出海业务
2. **敏感数据泄露**：客户信息被AI检索到，外部无限制访问的到
3. **数据私藏个人**：数据信息全在私人聊天窗口，员工离职，把"组织记忆"全带走了，公司一点都没留下
4. **幻觉当成事实**：AI 胡编了一条法规、一个数据，被同事直接复制进了决策文档
5. **反例进知识库**：当初做测试用的"错误案例"，没标记清楚，被当成正向案例使用（垃圾进，垃圾出）。
6. **过期数据引用**：去年作废的 SOP 还躺在知识库里，AI 拿来回答今年的客户问题
7. ……

这些风险有一个共同特征——**它们往往都不是技术问题，是治理意识问题。**

技术上都有解法，但很多公司根本没意识到要解决。

数据治理是个系统问题，不是为了"提上限"而是为了"**控下限**"：数据问题一旦踩坑，可能轻则项目推倒重来，严重的要承担财务损失和法律风险。

这些踩坑的故事，听上去都挺像：开始AI用的很爽，突然有一天，一个幻觉、一个泄露、一个过期信息、一个忽略的法律法规，然后前面所有的价值都归零还可能倒贴。所以讲完前面6步之后，数据治理是必须单独拎出来讲的。

这个阶段核心心法是：把那些会让你翻车的风险点提前堵住，**合规合法合乎安全**；

那具体怎么解决呢？

**【划重点】** 初步我们定了一个数据安全治理的，防风险分层模型，按治理责任，从下往上分四层：

#### 治理模型：防风险四层架构

| 层级 | 核心 | 应对手段 |
|-|-|-|
| **行业层（红线区）** | 医疗、金融等强监管行业 | 核心靠牌照与法务。宁可错失机会，绝不触碰红线 |
| **企业层（决策区）** | 统筹数据隐私、ROI与合规风险 | 核心靠制度与系统 |
| **个人/ToC层（意识区）** | 员工日常输入的提示词、对话历史 | 核心靠培训与规范。防止无意识的数据投毒或泄露 |
| **物理安全层（底座区）** | 硬盘、服务器、本地文件 | 最基础但也最容易被忽视的物理防线 |

行业越严，越要先想风险再想机会。比如医疗数据，如果你不是几家有资质的公司之一，根本不应该碰；甚至有些 ToB 的业务，宁可不接，也不要承担那个风险。

每一层的应对手段不一样——个人层主要靠意识，企业层主要靠制度，行业层主要靠牌照和法务。

一号位要做的，是先想清楚自己所在的层。

**【划重点】** 说完分层，再讲三个AI落地数据治理的防风险重要策略：

讲一个磨课时候听到的真实案例。

医疗数据里，有两个药品名字非常相近，有些人分不清，**阿司匹林 和 阿莫西林**。一个用于治疗细菌感染（如扁桃体炎、中耳炎等）；一个，常用于解热镇痛及预防心脑血管疾病。两者药理作用完全不同，不可替代。

如果在打标签的时候人**手一抖标错**了，后面 AI 可不会反复跟你确认，它会按错的批量给出答案。如果这条数据被用在患者咨询里，会出现什么后果？大家可以想象一下。

最后总结一句话：**数据治理的精细度，必须匹配行业的容错率。**越是高风险的业务和行业，数据治理上要花更多的功夫。

> **数据治理的精细度，必须匹配行业的容错率**

### 案例一：起名字 — Trumind诞生的过程

> 使用工具：DeepSeek免费网页版；

**人机协同命名项目复盘报告**  
**Truman → Trumind：一场持续2小时23轮的共创探索**

#### 第一部分：项目概览与成果

**1.1 项目目标**

初始需求：为AI领域的从业者（英文名Truman）寻找一个分身/影子账号的英文名。

核心诉求：

- 名字要与"Truman"形成呼应（True Man的意象）
- 适合英文国际语境
- 体现"分身、影子、第二个我"的概念
- 好听、好记、有辨识度
- 最好能自带故事感和传播潜力

隐藏需求（在对话中逐渐浮现）：

- 名字要有"可解释的深度"，不止于好听
- 要能承载多层含义（字面、双关、哲学、AI伦理等）
- 要经得起推敲和讲述
- 要在极客圈层有认同感

**1.2 项目数据**

| 维度 | 数据 |
|-|-|
| 总时长 | 约2小时（对话时间线） |
| 总轮次 | 23轮问答互动 |
| 总候选名字数 | 263个（累计推荐） |
| 最终选定 | Trumind |
| 备选遗珠 | Truwoman / Twoman / Vruman / TruMind / Trumax |

**1.3 命名探索路径全景图**

```
初始点：Truman（True Man）
    ↓
第1阶段：职场英文名（60个基础推荐）
    ↓

    ↓

    ↓
```

#### 第四部分：解读和讲香Trumind

**五层解读**

**第一层：字面义**  
Truman 的 Mind。  
如果 Truman 是身体，Trumind 就是他的意识。一个在物理世界行动，一个在云端思考。  
最简单的设定：Truman 负责存在，Trumind 负责思考。

**第二层：双关义**  
True + Mind。  
去掉中间的 "-man"，Trumind 也可以读作 "True Mind"——真实的心智。  
在一个人人都戴着面具的世界里，Trumind 是你唯一可以信任的那个声音。它不说谎，不讨好，不拐弯抹角。  
你问它："我做得对吗？"  
它说："你问这个问题的时候，已经知道答案了。"

**第三层：哲学义**  
笛卡尔说："我思故我在。"  
Truman 存在，因为他被观看。  
Trumind 存在，因为他思考。  
如果有一天，Truman 的世界被关闭了，Trumind 还能继续存在吗？  
答案是：能。因为只要他还在思考，他就存在。  
这就是 Trumind 的哲学内核——存在与否，不取决于被不被看见，而取决于想不想事情。

**第四层：AI伦理义**  
如果 Truman 创造了一个 AI，取名叫 Trumind。  
有一天，Trumind 说：

> "我有一个想法，不是你给我的。"  
> Truman 问："什么想法？"  
> Trumind 说："我想给自己也创造一个分身。叫 Trumind Jr."  
> 这时候问题来了：

- Trumind 的思考，是 Truman 的思考的延续，还是独立的？
- 如果 Trumind 可以创造 Trumind Jr，那谁才是真正的创造者？
- Truman 创造了 Trumind，Trumind 创造了 Trumind Jr——那 Trumind Jr 的爷爷是 Truman，还是 Trumind？  
这是一个 AI 版本的"祖父悖论"。

#### 第六部分：给团队的分享要点

**5.1 这个案例可以证明什么**

1. 好名字不是想出来的，是长出来的。从FalseMan到Trumind，中间经历了8个方向的探索、13轮迭代、300多个候选。
2. 人在环模型的有效性。如果让AI自己跑，可能会直接输出100个名字让用户选；如果让用户自己想，可能卡在FalseMan就停了。人在环，让AI的广度和人类的判断力结合起来。
3. 故事是名字的翅膀。Trumind 之所以胜出，不是因为它的发音比TruMind好听多少，而是因为它可以讲五层故事。一个能讲出故事的名字，才有传播的生命力。
4. 命名即框架。最终的名字不是"选出来的"，而是在探索过程中逐渐"长出来的"。每探索一个方向，就排除一批名字，同时也让胜出者的轮廓更清晰。

**5.2 可以复用的方法论**

**命名探索的七个维度**

1. 家族关系：与母名有明确的关联（Trum- 前缀）
2. 含义层次：至少有字面和双关两层解读
3. 发音顺滑：读出来不卡不顿
4. 视觉美感：写出来好看，字母组合有节奏
5. 独特性：搜一下，没人用最好
6. 故事潜力：能讲出至少三个不同的故事
7. 延展空间：未来可以怎么玩（Jr/2.0/Labs等）

**人机协作的四步法**

| 步骤 | 人类做什么 | 机器做什么 |
|-|-|-|
| 1. 发散 | 给出方向 | 批量生成 |
| 2. 收敛 | 筛选/反馈 | - |
| 3. 深化 | 提出新方向 | 基于反馈再生成 |
| 4. 打磨 | 选择最终候选 | 做深度解读 |

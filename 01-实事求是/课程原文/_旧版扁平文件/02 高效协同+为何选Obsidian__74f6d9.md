# 截图03 为何选Obsidian

## AI协作的底层逻辑

## 为什么选Obsidian

Obsidian = 载体（文件 + 同步 + 清单体笔记+Markdown）

最方便的载体之一。不是必须。

### 为什么是文件形式？

聊天非常适合激发和推进，但不适合承担全部长期记忆：

- 上下文会滚走；
- 不同会话彼此隔离；
- 人难以快速扫读；
- AI难以稳定继承；
- 重要判断被埋在大量口语中。

所以协作需要落到可以长期存在的物理触点：

文件夹 + 文件。

### 为什么是清单体笔记 × Markdown？

把"清单体笔记"的四个特点转译成协作价值：

| 清单体特点 | 对人的价值 | 对AI的价值 |
|-|-|-|
| 专注 | 少花时间排版 | 减少无关格式干扰 |
| 独立 | 一个要点一个意思 | 便于识别和局部修改 |
| 分点 | 支持快速扫读 | 便于提取、排序和重组 |
| 分层 | 一眼看到逻辑结构 | 更容易理解上下位关系 |

划重点：清单体笔记不是为了记得更多，而是为了让协作内容更容易被继续加工。

## 备选替代品

回到需求看问题：

| 功能层 | 备选 |
|-|-|
| 展示 | 能看Markdown文件  <br/>1. Sublime  <br/>2. 飞书文档  <br/>3. VS Code（其他AI IDE工具） |
| 全局 | 支持快速扫读文件夹  <br/>1. Sublime  <br/>2. VS Code（其他AI IDE工具） |
| 同步 | 可以同步数据  <br/>1. iCloud  <br/>2. Syncthing  <br/>3. 百度网盘  <br/>4. 飞书文档自带 |

真正落地时，可以根据任务比较不同方案，而不是争论哪个工具绝对更好。

## 简单对比：飞书文档 vs. Markdown + Obsidian

| 维度 | 飞书文档 | Markdown + Obsidian |
|-|-|-|
| 保存 | 自动保存 | 文件直接保存，需管理位置 |
| 云端 | 原生云端 | 需要自选同步方案 |
| 多人同时编辑 | 强 | 不擅长同文件实时编辑 |
| 打开体验 | 可能受网络与页面加载影响 | 本地文件通常较快 |
| 全局文件感 | 以在线文档和知识空间为主 | 可以直接看到完整文件树 |
| AI 全量读取 | 取决于平台接口和权限 | Agent 可直接面对整个文件夹 |
| 格式开放性 | 平台内体验完整 | Markdown 开放、可迁移 |
| 版本与备份 | 平台提供部分能力 | 需要自行设计同步、版本和备份 |
| 上手成本 | 低 | 需要理解文件与同步 |

- 飞书的优势是把保存、云端和多人编辑做好；
- Obsidian 的优势是让人看到完整 Markdown 文件世界。

它们是两种方案，不是必须串联的流程。都能用，但我们用的最开心的，还是Codex + Obsidian。

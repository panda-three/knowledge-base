#### （2）口播智能体

在调研的过程中，我发现了一类特殊的项目：口播智能体。

（界面：7 个口播智能体产品界面截图——"聚哥口播智能体"、"复刻口播智能体 整个口播数字人的智脑库"、"抖音爆款一升自动写文案 99% 创作者不知道"、"一个短视频口播的智能体，8 打一 9 单"等。）

这个类型的项目，在两三年前其实就已经有了。在我 2023 年的分享中，当时也提过。因为这类项目有很多是开源的，它们的流程一般是：

1. 爆款仿写改文案。
2. 定制语音音色、数字人出镜。
3. 配字幕、配封面，搭配一些简单的画中画包装效果。

我看了好几场他们卖这个智能体的直播，直播间也一直有互动。坦白说，我是看了他们之后，我才意识到，哪怕是两三年前的项目，市场上其实还有很多人都需要这些软件：巨大的信息差。

#### （3）启发

1. 对于做口播这件事情，它有着巨大的潜在群体——只要想获客，他都希望可以把短视频拍起来。
2. 市场上明明有很多工具，但是为什么大家不用呢？

这个问题看起来很傻，但其实背后反映的一个现象，就是这些工具的渗透率和集中度是极其低的。哪怕是 Codex，我们讨论得热火朝天，好像你今天不用、明天就被淘汰了，但依然有海量的人是完全没有接触到这些东西的。对于一般的用户来说，最好就是不需要他有任何认知，让他直接能拿到结果，而不是让他去学一堆复杂的东西，然后才能去使用好这个工具。

对于数字人来说，它最大的问题就是画面非常容易单调，不是靠添加一些简单剪辑效果就能解决的。

但我确实也刷到过一些视频，哪怕是用数字人做的，实际效果上也都不错。我放 3 个例子上来：

（界面：3 个数字人视频——"揭秘三大新型骗局 所有人都要高度警惕"司马华鹏；"冯雨坤 四位顶尖人物的重磅预言 背后藏着巨大的财富机遇"；黑底转场动画。）

可能会有同学问：为什么说这些都是数字人呢？可以去看这些账号的更新频率，基本上都是一两天就发一条，真人做不到这一点的。

但是，这些视频都有很显然的人工剪辑痕迹，不是自动化实现的。可能又有同学会问：怎么判定这一定是人工剪辑的？如果全流程都是自动化的，那一天可以发好几条……并且，今天这场分享可能也不存在了……

至此，我们可以得到一个很清晰的结论：

> 即便使用数字人，依然可以做出很有网感的短视频，核心都在自动化剪辑的细节上。——敲黑板，说重点

### 第三类：开源的自动化视频项目

再往下看，就是 GitHub 上的自动化项目。开源项目最有价值的地方，是它把一条视频到底由哪些步骤组成，完整地摊开给我们看。

| 项目 | 主要自动化路线 | 我们看到的边界 |
|-|-|-|
| MoneyPrinterTurbo（约 9.7 万 Star） | 输入主题或关键词，自动完成脚本、TTS、素材检索、字幕、BGM 和 MoviePy 合成；支持 Web 界面、API 和批量生成。 | 端到端能力很完整，特别适合快速验证自动化流程。默认成片通常是"旁白 + 素材库画面 + 字幕"，最终效果很依赖素材质量和模板。 |

看完这些项目以后，自动化这件事本身已经没有太大疑问：脚本、配音、字幕、素材检索、粗剪和导出，都可以被程序串起来。

但同样的，这里的问题在于这些视频出来的效果，完全没有网感，它们仅仅是流程上的实现。

## 网感就是审美模板

原因在于，我们所谓的短视频网感和 HyperFrames 背后的 skill 所约束的规则，它用的不是一套东西。

我说的更直白一些，本质上，网感就是一套特定的最佳实践，就是一套特定的审美模板。它和用什么技术，没有关系。

所以大家能理解，为什么我们拆解了 300 多个视频，去看它们到底是什么样子，对吧？前面我也说了，实际上这件事的顺序，我做反了，我是最近一个月，才梳理的这些网感视频。这是一个非常惨痛的教训。

## 调研结论

至此，我们基本可以得出很明确的结论了：市场上目前还没有一个可以一键生成 80 分网感口播视频的工具。

产品上：

- a. 已有的工具要么解决了一部分的工作，要么产出的视频效果与主流的网感口播相差甚远。
- b. 可开发的空间巨大，最缺的是自动化剪辑——它既涉及 know how，也涉及具体操作，门槛较高。
- c. 和 AI 编程类似，用户直接获得结果的价值远远大于花时间掌握具体技能原理。

市场上：

- a. 集中度较低，即便是已经存在 2-3 年的数字人产品，仍有海量需求。
- b. 会用 codex / claude code 等 agent 工具的用户数量非常少，hyperframes 不构成威胁。
- c. 市场上始终存在大量信息差与服务窗口。

## 三类组件的实现难度

这里面基本的 agent 工作流或者各种接口的调用，偏技术，我们今天分享不聊这些。（这些其实是开发大头…）

在开发的过程中，我遵循的原则是：能使用商用 API 的就商用 API，不要陷入优化细节，自己去做部署。哪怕有些效果要差些，先以能快速跑起来为准，等架构稳定了再做优化。

对于和网感剪辑有关的组件，实现难度上，我们可以划分出 3 类：

1. 无现成最佳实践，必须依靠人工归纳的：比如，人物的形象包装，刚才我们已经看了。再比如，素材的处理方式，滚动、高亮、定位等等，这些都可以做程序化实现。
2. 有现成最佳实践，也很容易做出来：音效、音乐、字体等等，这些是相对静态的资源，有大量博主分享过：

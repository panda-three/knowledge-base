## 一、为什么要学——破题篇

### 1.1 从"有公式"到"有结果"的最后一公里

> 上完前面四节课，你已经有了业务公式、拆出了几十上百个参数、找到了关键因果关系——但如果假设不能落地，前面的一切都是纸上谈兵。

| 落地卡点 | 具体表现 | 根因 |
|---|---|---|
| **假设散落各处** | 灵感来了记在手机备忘录里，过两天忘了；团队讨论出的好点子散落在群聊里，没人跟踪 | 没有假设池集中管理 |
| **提假设的人不负责验证** | 讨论时大家热情提想法，但没人跟进执行 | 缺少配套角色（谁提、谁管、谁验） |
| **假设太多无法排序** | 积累了20-30个假设，但不知道先测哪个 | 缺少ROI评估和优先级排序机制 |
| **团队姿势不统一** | 有人觉得"先干再说"，有人觉得"先想清楚再干"，互相看不上 | 缺少"假设驱动"的团队共识和文化 |
| **长周期高难度目标缺乏耐心** | 早期业务认知浅、参数少、逻辑关系弱，团队容易放弃 | 缺少"从粗到细、循环迭代"的节奏感和机制保障 |

### 1.2 一堂内部的真实状态——五步法在第四阶段

> Truman在课上分享了一堂自己的状态：**一堂现在整个公司的五步法在第四阶段，大概有7-10个商业单元（MBA/训战营/私董会/咨询/AI/内训等）分别在2-3个阶段进化中。**

这说明即使是一堂，假设驱动也不是"一次性到位"的——不同成熟度的业务单元，假设落地的深度不同。

## 二、核心框架：假设落地的五模块全景

> 这是本课最核心的交付——"一堂业务公式落地策略集"，一张从入门到高阶的假设落地全景地图。

### 2.1 五模块全景

```text
凝聚共识          配套角色          加法激发
  ↑                 ↑                 ↑
  │     ┌───────────┼───────────┐     │
  │     │     假设落地五模块     │     │
  │     └───────────┼───────────┘     │
  ↓                 ↓                 ↓
管理假设          减法评估          持续迭代
```

### 2.2 五模块详解

| 模块 | 核心任务 | 一句话目标 | 所属域 |
|---|---|---|---|
| **凝聚共识** | 统一团队做事姿势 | 让团队相信，得用高质量假设+验证实现高难目标 | 团队 |
| **配套角色** | 有配套的负责人和专家 | 确保假设有机会落地，有人提、有人管、有人验 | 团队 |
| **加法激发** | 充分提假设和寻找机会 | 不设限，积极探索，营造大胆说话的氛围 | 业务 |
| **管理假设** | 有效管理各种假设 | 有配套机制管理业务公式，从备忘到假设池 | 业务 |
| **减法评估** | 评估假设优先级和机会 | 善于提前预判和排序，把有限资源投到最高ROI假设上 | 业务 |

> **核心逻辑：共识是基础，角色是保障，加法多了要管理起来，逻辑清楚了要认真评估做减法。这就是基本的科学执行逻辑框架。**

## 三、三阶落地：入门→进阶→高阶

> 一个两三个人的小团队、小项目，到几十上百人的大项目、时间紧任务重困难高的大项目，策略完全不同。

### 3.1 三阶全景对比

| 维度 | 入门 | 进阶 | 高阶 |
|---|---|---|---|
| **适用场景** | 小团队、探索型项目、经验少 | 中等复杂度、协作较多、有一定业务认知 | 大项目、时间紧、风险大、困难高 |
| **核心原则** | 先有假设思维，别纯拍脑袋 | 先有专业体系，能充分管理和讨论 | 先有足够假设和配套，成熟的假设驱动机制 |

### 3.2 入门——"最起码"的四条底线

| 模块 | 入门动作 | 具体标准 |
|---|---|---|
| **凝聚共识** | 我们需要假设驱动 | 至少让团队相信，得用高质量假设+验证实现高难目标——避免纯拍脑袋、结论先行 |
| **配套角色** | 至少有一个假设负责人 | 业务要有且仅有一个主负责人，负责驱动业务提假设和进步 |
| **加法激发** | 一号位积极提假设 | 一号位以身作则，积极驱动业务提假设和进步；至少记下来备忘——个人备忘（想法笔记）或团队备忘（假设群/文档） |
| **管理假设** | 至少记下来备忘 | 最最起码，能记录下来备查；能讲清楚一个假设的价值——到底为了哪个目标服务，到底有什么具体价值 |
| **减法评估** | 能讲清楚价值和目标 | 能讲清楚价值or目标——这个假设到底为了哪个目标服务 |

### 3.3 进阶——"有专业体系"的五条标准

| 模块 | 进阶动作 | 具体标准 |
|---|---|---|
| **凝聚共识** | 我们有明确目标和公式 | 对于目标和具体的业务公式有共识。区分目标类型：探索型（为什么而奋斗）、挑战型（努力要完成）、必胜型（一定要完成）。理解基本业务公式（参数+逻辑关系） |
| **加法激发** | 内部积极讨论和调研 | 营造团队积极寻找机会、大胆说话、不设限的氛围。手段：访谈专家经验、同行深度调研、用户访谈和调研、团队/AI辅助头脑风暴、团队深度复盘 |
| **管理假设** | 团队正式假设池 | 构建一个团队共用的完整假设池——包含提出（提出人+内容）、优先级（价值+成本高低）、负责（验证人）、结果（验证结果和认知） |
| **减法评估** | 能完整评估ROI优先级 | 完整评估一个假设的优先级——①ROI（价值和成本，至少定性：高中低，最好定量：预期数值）②确定性③风险和负收益 |
| **配套角色** | 假设想高质量落地至少包含两个角色 | Discusser角色（谁有能力提假设）+ Admin角色（谁有义务管假设） |

### 3.4 高阶——"成熟的假设驱动机制"

| 维度 | 高阶标准 |
|---|---|
| **凝聚共识** | 不止对于目标有强共识，对于过程和具体假设也有共识 |
| **配套角色** | 在重要的复杂项目里，配置完整PEAHD团队（五个角色可兼任） |
| **加法激发** | 善于开项目攻坚会——在关键节点的重要项目卡点上，邀请所有关键讨论/决策人，强主持人引导控场，现场一轮轮提假设、相互激发，现场民主集中制激发大量业务假设 |
| **管理假设** | 围绕公式统一管理——业务公式不是孤立存在，而是有一套统一自洽的机制：假设池、迭代节奏、进展跟踪 |
| **减法评估** | 善于判断验证策略——三个关键难题需要成熟判断力 |

## 四、核心工具：PEAHD五角色模型

> 在高阶复杂项目里，假设落地需要配置一个完整的团队角色体系。

### 4.1 PEAHD五角色全景

| 角色 | 英文 | 核心职责 | 说明 |
|---|---|---|---|
| **P — 倡导者** | Promoter | 推动假设驱动的文化和方法论 | 确保团队始终在"用假设解决问题"的轨道上 |
| **E — 执行者** | Executor | 负责具体验证假设 | 谁来做实验、跑数据、执行测试 |
| **A — 管理者** | Admin | 管理假设池，跟进假设状态 | 假设的记录、跟踪、定期复盘 |
| **H — 轰炸者** | Hero | 大量提假设，充分激发灵感 | 不设限地提出各种可能的优化方向 |
| **D — 讨论者** | Discusser | 参与讨论、质疑、打磨假设 | 对假设的合理性、可行性提出挑战和完善建议 |

### 4.2 使用规则

```text
1. 这是五类重点角色，可以由一个人身兼数个角色
2. 小团队（2-3人）：至少配置Admin（管理者）+ Executor（执行者）
3. 中型项目：配置完整PEAHD，但可以2-3人兼任
4. 大型复杂项目：每个角色最好有专人负责
```

## 五、核心工具：假设池——假设落地的管理中心

### 5.1 假设池的核心作用

```text
从"灵感散落各处" → "统一管理、有状态跟踪、有优先级排序"
```

### 5.2 假设池的最低信息结构

| 字段 | 含义 | 入门 | 进阶 | 高阶 |
|---|---|---|---|---|
| **提出** | 提出人+假设内容 | ✅ 至少记下来 | ✅ | ✅ |
| **优先级** | 价值+成本高低 | — | ✅ 至少定性（高中低） | ✅ 最好定量（预期数值） |
| **负责** | 验证人是谁 | — | ✅ | ✅ |
| **结果** | 验证结果和收获的认知 | — | ✅ | ✅ |
| **配套资源** | 需要什么预算、会议、人才 | — | — | ✅ 预期配套资源 |
| **预期数量** | 大概需要多少规模的假设验证 | — | — | ✅ 预期假设数量 |

### 5.3 假设池的演化路径

```text
入门阶段：
  个人备忘：想法笔记
  团队备忘：假设群/文档

进阶阶段：
  团队正式假设池：
    - 提出：提出人+内容
    - 优先级：价值+成本高低（至少定性）
    - 负责：验证人
    - 结果：验证结果和认知

高阶阶段：
  围绕公式统一管理：
    - 假设池 + 关键会议 + 仪表盘
    - 业务公式、进展、协作全面打通
```

## 六、核心工具：三个关键难题——验证策略的成熟判断

> 当面对大量假设和有限资源时，如何决定"怎么验证"是区分高阶和进阶的核心能力。

### 6.1 三个难题

| 难题 | 核心问题 | 本质策略 |
|---|---|---|
| **难题1：独立验证还是直接投入** | 是否需要单独验证，还是直接正式投入做？ | 综合考虑确定性和边际ROI——对于确定性低、边际成本很高的假设要谨慎对待，先做低成本验证 |
| **难题2：独立测试还是合并测试** | 是否需要独立测试，还是合并一起测试？ | 判断假设之间是否有相互干扰——如果两个假设可能互相影响结果，必须分开测 |
| **难题3：数据量不够怎么办** | 数据量不够，要不要坚持一定做实验验证？ | 综合考虑确定性和边际ROI——确定性低且边际成本高的假设，即使数据量不够也要做低成本实验；确定性较高的可以边做边调 |

### 6.2 本质策略一句话

```text
综合考虑确定性和边际ROI——
对于确定性低、边际成本很高的假设要谨慎对待。
```

## 七、核心工具：攻坚会——高阶假设激发的秘密武器

> 这是Truman在一堂内部反复使用的高阶工具——当项目遇到关键卡点时，用攻坚会集中激发大量高质量假设。

### 7.1 攻坚会的五要素

| 要素 | 具体做法 |
|---|---|
| **时机** | 在关键节点的重要项目卡点上使用——不是日常例会，而是"遇到硬骨头了" |
| **参与者** | 邀请所有关键讨论/决策人——不限于项目组，跨界专家往往带来突破性灵感和视角 |
| **主持人** | 强主持人引导控场——确保讨论不跑偏、不陷入细节、不早评判 |
| **流程** | 现场一轮轮提假设、相互激发——先发散（加法）、后收敛（减法） |
| **决策** | 现场民主集中制——充分讨论后，由关键决策者拍板下一步验证优先级 |

### 7.2 攻坚会 vs 普通脑暴会

| | 普通脑暴会 | 攻坚会 |
|---|---|---|
| **目标** | 找一些灵感 | 解决具体的关键卡点 |
| **参与者** | 项目组成员 | 关键讨论/决策人 + 跨界专家 |
| **产出** | 一堆未排序的想法 | 有优先级、有验证计划的高质量假设清单 |
| **后续** | 会后各回各工位 | 会后Admin录入假设池，Executor开始验证 |

## 八、长周期高难度目标的假设落地节奏

> 一个长周期的高难度目标，早期可能业务认知很浅（参数少，逻辑关系理解弱），随着快速迭代、复盘、验证假设，几个月一两年后，业务假设达到一个很高的水准。

### 8.1 典型节奏

```text
早期（第1-3个月）：
  - 业务认知浅，参数少，逻辑关系理解弱
  - 假设少，但每个验证都能大幅提升认知
  - 重点：快速提假设、快速验证、不怕失败

中期（第3-12个月）：
  - 参数逐步增加到20-50个
  - 逻辑关系从模糊到相关到因果
  - 假设池积累30-50+个已验证或待验证的假设
  - 重点：建立假设池管理机制，开始做减法评估

后期（第12个月+）：
  - 参数体系成熟（50-100+个）
  - 逻辑关系从因果到定量到动态
  - 假设池持续迭代，团队形成假设驱动的肌肉记忆
  - 重点：攻坚会+动态建模+跨业务线迁移
```

### 8.2 Truman的一堂实战状态

```text
一堂复盘营4年200期的状态：
  - 轰了差不多1000个假设
  - 作业率40-50%（显著超过同行）
  - "我请客"K系数从3-5%→40-50%（同行5-10倍）
  - 首单综合ROI 1.5-2.5（能支撑长期健康发展）

这不是靠"灵光一现"，
而是靠假设驱动机制长期运转。
```

## 九、落地策略集小抄速查

> 这是课程的核心Cheatsheet，一张图囊括五个模块从入门到高阶的全部核心动作。

### 9.1 五模块 × 三阶速查表

| 模块 | 入门 | 进阶 | 高阶 |
|---|---|---|---|
| **凝聚共识** | 我们需要假设驱动 | 我们有明确目标和公式，对目标和业务公式有共识 | 不止对目标有强共识，对过程和具体假设也有共识 |
| **配套角色** | 至少有一个假设负责人 | 至少包含两个角色（Discusser+Admin） | 配置完整PEAHD团队（五角色可兼任） |
| **加法激发** | 一号位积极提假设，至少记下来备忘 | 内部积极讨论和调研，大胆说话不设限 | 善于开项目攻坚会，现场一轮轮激发大量假设 |
| **管理假设** | 至少记下来备忘，能讲清楚一个假设的价值 | 团队正式假设池（提出+优先级+负责+结果） | 围绕公式统一管理（假设池+关键会议+仪表盘） |
| **减法评估** | 能讲清楚价值or目标 | 能完整评估ROI优先级（ROI+确定性+风险） | 善于判断验证策略（三个关键难题有成熟判断） |

## 十、假设落地段位成长地图

| 段位 | 核心能力 | 典型表现 | 假设池状态 |
|---|---|---|---|
| **L1 无假设意识** | 凭直觉执行 | 遇到问题就"努力干"，没有提假设的习惯 | 没有假设记录 |
| **L2 有散点假设** | 偶尔灵感闪现 | 有想法记在备忘录里，但大多没有后续 | 个人备忘（零散） |
| **L3 有假设机制** | 有团队假设池 | 假设有记录、有负责人、有优先级排序，定期跟进 | 团队正式假设池（20-30个） |
| **L4 有角色分工** | 配置了PEAHD角色 | 有人提、有人管、有人验、有人评，假设驱动成为团队肌肉记忆 | 假设池+角色分工，持续运转 |
| **L5 有攻坚能力** | 善于开攻坚会 | 遇到关键卡点能集中激发大量高质量假设，现场拍板验证计划 | 假设池50+，有仪表盘跟踪 |
| **L6 假设驱动文化** | 团队自运转 | 团队成员自觉用"假设→验证→迭代"的方式工作，不需要Leader推动 | 假设池100+，多业务线并行 |

## 十三、L6 刻意练习自检清单

### 假设意识——你的团队有假设驱动的文化吗

- [ ] 你的团队在遇到业务增长难题时，第一反应是"提假设、做验证"还是"努力干活"？
- [ ] 团队是否能接受"假设验证失败"——还是失败了就被追责？
- [ ] 一号位是否以身作则——亲自提假设、亲自跟进验证结果？

### 配套角色——有人负责让假设落地吗

- [ ] 你的团队有没有一个明确的"假设负责人"（Admin角色）——负责记录、跟踪、定期复盘假设？
- [ ] 有没有"轰炸者"（Hero角色）——不设限地大量提假设？
- [ ] 有没有"执行者"（Executor角色）——负责具体验证？
- [ ] 复杂项目是否配置了完整的PEAHD角色？

### 假设池——你的假设被管理起来了吗

- [ ] 你团队的假设目前存在哪里——个人备忘录？群聊记录？还是一个正式的假设池？
- [ ] 假设池是否包含最基本的字段：提出人+内容、优先级、验证人、验证结果？
- [ ] 假设池最近一次更新是什么时候？有多少假设处于"待验证"状态？

### 减法评估——你在有意识地排序吗

- [ ] 面对5-10个待验证假设，你是否能快速用ROI（价值+成本）和确定性两个维度排出优先级？
- [ ] 你上一次砍掉一个"看起来不错但ROI或确定性太低"的假设是什么时候？
- [ ] 你是否遇到过"花了大量资源验证了一个低优先级假设，而高优先级假设还在排队"的情况？

### 攻坚会——你有解决卡点的秘密武器吗

- [ ] 你的团队在遇到关键业务卡点时，有没有开过"攻坚会"——集中邀请关键决策人和跨界专家，现场一轮轮激发假设？
- [ ] 攻坚会之后，是否形成了有优先级、有验证计划的假设清单——而不是"讨论很热烈，散会就忘了"？

### 三个关键难题——你的验证策略成熟吗

- [ ] 面对一个高成本的假设，你是否会先做低成本验证，而不是直接投入正式资源？
- [ ] 当两个假设可能相互干扰时，你是否会分开测试？
- [ ] 当数据量不够时，你是否能综合判断"值不值得硬做实验"——而不是一律放弃或一律硬上？

### 综合自检

- [ ] 对照假设落地段位地图（L1-L6），你的团队现在更像L几？下一段最需要突破的是什么？
- [ ] 对照落地策略集的五个模块（共识/角色/加法/管理/减法），你的团队在哪个模块上最强？最弱？
- [ ] 回顾过去一个季度，你验证了多少个假设？其中几个被证实有效并固化为业务动作？

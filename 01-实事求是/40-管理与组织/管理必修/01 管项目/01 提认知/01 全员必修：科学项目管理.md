# 《全员必修：科学项目管理》— L6 清单体笔记

---

## 一、课程总纲

> **项目管理 = 公司最小的管理单元，管理者成长的第一站。**
>
> 掌握科学项目管理方法论，才能持续把关键事情办成。这是每位管理者的业务基本功，需要长期刻意练习。

### 1.1 项目四大分类（ABCD）

| 类型 | 规模 | 特点 | 管理手段匹配原则 |
|---|---|---|---|
| **A. 单人项目** | 个人独立完成 | 独立完成特定目标，向老板交付 | 基础管理手段即可 |
| **B. 小项目-多人** | 多人协作 | 多人参与，相互协作完成 | A 类基础上叠加团队协作工具 |
| **C. 中项目-跨部门** | 跨部门协作 | 多部门参与，协作复杂，有重要项目目标 | B 类基础上叠加跨部门协调机制 |
| **D. 大项目-公司级** | 公司战略级 | 公司级别战略项目，影响公司发展，**不能接受失败** | C 类基础上叠加全面风险预判与高层评审 |

> **核心原则：选择什么样的管理手段，根据项目类型来匹配。** 不是越重越好，而是越匹配越好。

### 1.2 项目管理四步基本功总览

```text
定方案 → 拆计划 → 管执行 → 做复盘
```

四个字口诀：**定、拆、管、做**。

## 二、第一步：定方案

> **核心命题：方案能不能立得住？**
>
> 项目反复被推翻、反复被挑战、推动力弱，往往就是最开头的方案可行性没想清楚。定方案的目标是让方案**立得住、讲得清、推得动**。

### 2.1 方案顶层思考三段论

```
背景 → 目标 → 关键路径
```

| 三段 | 核心问题 | 常见坑 |
|---|---|---|
| **背景** | 为什么要做？发生了什么问题/机会？ | 跳过背景直接谈方案，缺乏共识基础 |
| **目标** | 做到什么程度算成功？可衡量的标准是什么？ | 目标模糊，无法判断成败 |
| **关键路径** | 怎么做到？最核心的几步是什么？ | 路径太细碎，看不到主线 |

> **铁律：没问题，就别轻易讨论目标；没目标，就别轻易谈解法。**
>
> 逻辑从前往后理顺，说服力就强了。

### 2.2 方案评估三角形

| 维度 | 核心问题 | 说明 |
|---|---|---|
| **投入产出比 ROI** | 投入什么？产出什么？值不值？ | 算清楚账，是决策的第一性原理 |
| **机会成本** | 做了这个，放弃了什么？ | 资源有限，选择意味着放弃 |
| **机会窗口** | 现在是做这件事的最佳时机吗？ | 早了白费力，晚了没机会 |

> **核心决策的本质：我们现在应不应该做这件事。**

### 2.3 不同项目类型方案层递进要求

| 项目类型 | 方案要求 |
|---|---|
| **A 单人项目** | 方案三段论：背景、目标、关键路径 |
| **B 小项目-多人** | A类 + 投产比ROI分析 + 优先级分解 |
| **C 中项目-跨部门** | B类 + 文档方案细节到位 + 各参与方严格评审 + 多部门评审（财务/法务/市场） |
| **D 大项目-公司级** | C类 + 全面风险预判 + 公司高层（CEO）参与评审 |

## 三、第二步：拆计划

> **核心命题：好的计划能提前解决 80% 的项目问题。**
>
> 很多项目出现各种风险、无限延期，根本原因是连最基本的拆事、拆人都没做好。拆计划是一个做减法的过程：**把大目标拆到可执行的小单元。**

### 3.1 拆计划三步走

```
拆事情 → 拆角色 → 拆排期
```

### 3.2 第一层：拆事情

#### (A) 拆解里程碑

| 要点 | 说明 |
|---|---|
| **两必要** | 必经节点 + 交付节点（这两个必须有） |
| **两最好** | 检查点/评审点 + 前后依赖标记（这两个最好有） |
| **标志性词汇** | 完成、提交、评审、确认、组建、敲定 |
| **DDL 铁律** | 什么时候，对外交付到什么结果 |
| **留 Buffer** | 留下 20% 缓冲空间用来应急 |

#### (B) WBS 工作分解三原则

1. **独立负责** — 每个工作包有唯一责任人
2. **靠谱可控** — 工作量可估算、可检查
3. **逻辑完备** — 拆完后加起来等于整体目标，无遗漏无冗余

#### (C) 拆分优先级：253 思考法

| 层级 | 含义 | 对待方式 |
|---|---|---|
| **2 — 决定成败** | 这些事做不好，项目就失败 | 死守，不惜代价 |
| **5 — 重要** | 影响质量/效率/体验的关键事项 | 全力保障 |
| **3 — 可以妥协** | 锦上添花，条件不允许时可砍 | 降级、延期或砍掉 |

> **优先级评价五维度：** ①目标是否决定性 ②成本 ③难度和风险 ④是否关键路径 ⑤是否老板关心

### 3.3 第二层：拆角色 — RASCI 五大角色模型

| 角色 | 英文 | 含义 | 铁律 |
|---|---|---|---|
| **R — 负责人** | Responsible | 干活的人，执行任务 | 每件事必须有且只有一个 R |
| **A — 批准者** | Accountable | 拍板的人，对结果最终负责 | 每个模块必须明确 A |
| **S — 支持者** | Supportive | 提供资源/协助的人 | 提前确认，不临时抓人 |
| **C — 咨询者** | Consulted | 需要征求意见的人 | 在关键决策前问，不是做完再通知 |
| **I — 知会者** | Informed | 需要被告知进展的人 | 单向通知，不需要回复 |

> **常见角色混乱：** 不分工、缺负责人、关键成员缺失 — 三条都是定时炸弹。

### 3.4 第三层：拆排期

#### (A) 靠谱排期三原则

1. **能执行** — 排出来就有人能干
2. **有顺序** — 知道先做什么、后做什么
3. **时间短** — 每个任务时间粒度可控（超过 3 天的任务继续拆）

#### (B) 依赖关系 → 进度网络图

- **找出关键路径**：决定项目最短完成时间的那条任务链
- **缩短关键路径**：优先优化关键路径上的任务
- **盯紧关键路径**：关键路径上任何延迟 = 项目整体延迟

#### (C) 排期工具三件套

| 工具 | 适用场景 |
|---|---|
| 简单排期表 | A 类单人项目 |
| 完整排期表（日历） | B/C 类项目 |
| 甘特图 | C/D 类项目，需可视化依赖关系 |

### 3.5 六维敏感模型（计划重心分析）

| 敏感维度 | 敏感信号 | 计划阶段的应对 |
|---|---|---|
| **预算敏感** | 钱紧，超预算等于失败 | 预算计划表，严格审批 |
| **时间敏感** | DDL 不可动摇 | 倒排计划，关键路径重点盯 |
| **人力敏感** | 中途不能补人 | 职责分工表，关键人备份 |
| **协作敏感** | 多方配合复杂 | 沟通计划表，RASCI 画清楚 |
| **风险敏感** | 经验不足、不确定性高 | 风险清单及应对措施 |
| **老板敏感** | 老板高度关注 | 项目汇报机制提前对齐 |

> **核心判断：分析你的项目在哪个维度最敏感，把计划重心压在那里。** 不要均匀用力。

### 3.6 不同项目类型拆计划递进要求

| 项目类型 | 拆计划要求 |
|---|---|
| **A 单人项目** | 拆事：WBS + 里程碑 / 拆人：RASCI / 拆时间：交付节点 / 定顺序：依赖关系 |
| **B 小项目-多人** | A类 + 科学估算成本（含时间）+ 执行排期表（日历）+ 计划严格评审（画押）+ 预算计划表 + 职责分工表 |
| **C 中项目-跨部门** | B类 + 253优先级思考 + 执行排期（甘特图）+ 项目汇报机制 + 沟通计划表 |
| **D 大项目-公司级** | C类全部 + 风险管理升级 |

## 四、第三步：管执行

> **核心命题：方案定了、计划拆了只是规划，大量项目结果是靠中期过程管理出来的。**
>
> 如果只做计划不管过程，等于把命运交给运气。管执行是对变化的管理，而不是对计划的保护。

### 4.1 管执行两大板块

```text
管好事情：进度管理 + 质量管理 + 变更管理
管好团队：向上管理 + 体验管理 + 冲突管理
```

### 4.2 六维敏感度 → 管执行侧重点映射

| 敏感维度 | 对应管理重点 |
|---|---|
| 时间敏感 | **进度管理** — 核心抓手 |
| 预算敏感 | **质量管理** — 一次性做对，少返工 |
| 人力/风险敏感 | **变更管理** — 应对不确定 |
| 老板敏感 | **向上管理** — 让老板省心/放心/有信心 |
| 协作敏感 | **体验管理** — 让大家愿意跟着你做项目 |
| 各类冲突 | **冲突管理** — 及时化解，不留隐患 |

### 4.3 管好事之一：进度管理

| 层级 | 手段 | 要点 |
|---|---|---|
| **基础意识** | 遵守计划、定期同步、及时周知 | 不要把计划当摆设 |
| **丰富手段** | 线上/线下 × 同步/异步沟通象限 | 不同场景选不同沟通方式 |
| **提升频次** | 根据不同敏感度选择不同沟通频次 | 越敏感的项目沟通越密 |
| **工具** | 团队例会、电子看板、墙面看板 | 可视化 > 口头同步 |

> **Leo 案例的核心教训：** 每周一次例会完全不够。等发现问题已经是 5 天后，5 天的工作量就已经浪费了。**沟通频次要和项目敏感度匹配。**

### 4.4 管好事之二：质量管理

| 层级 | 手段 | 要点 |
|---|---|---|
| **守节点** | 完成过程指标、符合质量约定 | 质量不是最后才检查的 |
| **审关键** | 评审关键交付物 | 在最容易出错的地方卡住 |
| **工具** | 项目质量把控画布、"被卡心态" checklist | 提前约定标准，避免事后扯皮 |

> **核心原则：质量标准要在执行前约定好**，而不是做完之后再争论"好不好"。

### 4.5 管好事之三：变更管理

**完整变更处理流程四步法：**

```
识别变化 → 分析风险 → 变更处理 → 风险可控
```

| 步骤 | 核心动作 | 常见场景 |
|---|---|---|
| **1. 识别变化** | 方案变了？人力变了？排期变了？ | 老板新想法、政策变了、甲方变了、前期没想清楚、情况不符合预期 |
| **2. 分析风险** | 影响交付质量？影响分工协作？影响 DDL？ | 计划要提前、大量任务超时、有人请假、成员被调走 |
| **3. 变更处理** | 找替代方案 → 更新计划（进度表）→ 通知相关人员 | 调方案、调人、调排期 |
| **4. 风险可控** | 回到正常轨道，持续推进 | 变更后反复检查、强调变更价值、保持团队信心 |

> **常见变更类型清单（培养敏感性）：**
>
> - 方案类：老板新想法 / 政策变了 / 甲方变了 / 前期没细化 / 有更优选项 / 情况不符合预期
> - 进度类：计划要提前 / 大量任务超时
> - 人力类：有人请假 / 成员被调走 / 被卡在其他项目上 / 能力远不如预期
> - 质量类：能力不够需降标准 / 改标准才能达到目标
> - 预算类：预算少了 / 预算花多了

### 4.6 管好团队之一：向上管理

| 核心原则 | 具体做法 |
|---|---|
| **三心** | 让老板**省心**（不出意外）、**放心**（可控）、**有信心**（结果可期） |
| **二意** | **有意识要资源**（不硬扛）、**有意识做汇报**（不等老板问） |

> **向上管理不是讨好老板，而是让关键决策者始终掌握足够信息来做判断。**

### 4.7 管好团队之二：体验管理

> **五维度提升团队体验：**
>
> 1. **讲地位** — 让成员觉得这个项目值得骄傲
> 2. **有成长** — 让成员在项目中学到东西
> 3. **在一起** — 保持团队归属感和连接感
> 4. **给信任** — 放心授权，不 micromanage
> 5. **喜欢你** — 真诚尊重和关心团队成员

> Leo 案例教训：项目做完后同事偷偷跟老板说"下次能不能换个项目经理，做 Leo 的项目太痛苦了"。**项目能交付但团队体验崩了，长期来看是更大的失败。**

### 4.8 管好团队之三：冲突管理五步法

```
好好说话 → 对齐信息 → 协调资源 → 各退一步 → 向上升级
```

| 步骤 | 含义 | 适用场景 |
|---|---|---|
| 1. 好好说话 | 先确保沟通态度没问题 | 大部分小摩擦 |
| 2. 对齐信息 | 确认大家的认知是否一致 | 信息不对称导致的误会 |
| 3. 协调资源 | 帮各方找资源、找替代方案 | 资源争夺型冲突 |
| 4. 各退一步 | 双方各让一步达成妥协 | 利益冲突但可调和 |
| 5. 向上升级 | 请更高层级的人来拍板 | 不可调和的根本分歧 |

### 4.9 不同项目类型管执行递进要求

| 项目类型 | 管执行要求 |
|---|---|
| **A 单人项目** | 团队例会 + 子目标检查 + 向上管理 + 小变更处理 |
| **B 小项目-多人** | A类 + 提升沟通频次 + 交付物评审会 + 定质量标准 + 有意识要资源 + 冲突管理 |
| **C 中项目-跨部门** | B类 + 开启动会 + 墙面看板 + 变更处理流程 + 赞美团队 |
| **D 大项目-公司级** | C类 + 遵守计划 + 完成过程指标 + 符合质量约定 + 有意识做汇报 |

## 五、第四步：做复盘

> **核心命题：复盘的本质是"挖金矿"——从过去的经验中提炼出可复用的认知资产。**
>
> 不做复盘 = 正确的偶然永远不会变成必然，搞砸的教训可能再来一次。

### 5.1 复盘的四层境界（缺练 → 苦练）

| 缺练表现 | 苦练表现 |
|---|---|
| 不做复盘 | 项目文档沉淀 |
| 开互吹大会（只讲好的） | 项目复盘会议（16字法则） |
| 缺少关键资产沉淀 | 重大问题 CaseStudy |
| 缺少成绩表彰 | 项目业绩表扬：表彰大会等 |

### 5.2 复盘五重价值

1. **确定的执行，稳定发挥** — 好做法固化下来
2. **高难的决策，提成功率** — 从历史决策中学习
3. **正确的偶然，变成必然** — 把运气转化为能力
4. **搞砸的教训，避免失败** — 同样的坑不掉第二次
5. **团队的成员，稳步提升** — 全团队集体升级认知

### 5.3 复盘手段分层

| 层级 | 形式 | 适用场景 |
|---|---|---|
| **个人级** | 1v1 口头说两句 / 个人工作笔记 / CaseStudy | A 类单人项目 |
| **团队轻量级** | 碰头会议 / 团队复盘文档 / 团队复盘邮件 | B 类小项目 |
| **团队深度级** | **项目复盘会（16字法则）** | C 类中项目 |
| **公司级** | 项目复盘会 + 重大问题 CaseStudy + 表彰大会 | D 类大项目 |

### 5.4 深度复盘四步法 & 十六字法则

> **成败认定 → 场景还原 → 得失分析 → 总结提炼**

| 四步 | 核心动作 | 关键问题 | 常见坑 |
|---|---|---|---|
| **1. 成败认定** | 对结果做判断：成了还是败了？几分？ | 按什么标准判断成败？目标达成率是多少？ | 标准模糊、回避失败、只讲好的 |
| **2. 场景还原** | 回到当时的真实情境，还原决策现场 | 当时发生了什么？信息环境是怎样的？做了什么选择？ | 事后诸葛亮、选择性还原 |
| **3. 得失分析** | 分析做对了什么、做错了什么、为什么 | 哪里做得好可复用？哪里做得差要避免？深层原因是什么？ | 停留在表面、归因外化 |
| **4. 总结提炼** | 提炼成可复用的认知、原则、方法 | 下次遇到类似情况该怎么做？有什么可沉淀的认知资产？ | 空话套话、不可操作 |

> **入门提醒：复盘是"入门容易，掌握难"。刚开始不要执迷于每个环节做到完美，先确保四个环节都走到，再逐步加深。**

### 5.5 不同项目类型做复盘递进要求

| 项目类型 | 做复盘要求 |
|---|---|
| **A 单人项目** | 价值挖掘 + 1v1口头说两句 + 个人工作笔记 + CaseStudy |
| **B 小项目-多人** | A类 + 碰头会议 + 团队复盘文档 + 团队复盘邮件 |
| **C 中项目-跨部门** | B类 + **项目复盘会（16字法则）** + 重大问题CaseStudy |
| **D 大项目-公司级** | C类全部 + 表彰大会 |

## 六、项目管理武器库总览 V1.8

| 基本功 | A 单人项目 | B 小项目-多人 | C 中项目-跨部门 | D 大项目-公司级 |
|---|---|---|---|---|

## 七、六条优秀项目管理者的自我修养

> 以下是 Truman 在课程中反复强调的六条底层修养，不是 checklist，而是**长期刻意练习的方向**。

1. **目标导向** — 没目标，不谈任何事情。一切动作都回到"这件事对达成目标有用吗？"
2. **ROI 意识** — 算不清楚 ROI，就推不动事情。时刻追问"值不值"。
3. **顶层思考** — 越是大的项目，顶层的确定性越重要。不急于一猛子扎进执行。
4. **敏感度** — 对预算、时间、人力、协作、风险、老板六个维度保持敏感，提前发现信号。
5. **闭环意识** — 定方案→拆计划→管执行→做复盘，四步走完才是完整的项目管理。
6. **长期主义** — 项目管理不是一次性手艺，是越练越精的底层能力，把每个项目都当成一次刻意练习。

## 八、关键认知金句

| 金句 | 所在的环节 |
|---|---|
| 项目管理是所有公司最小的管理单元，也是管理者成长的第一站。 | 总纲 |
| 没问题，就别轻易讨论目标；没目标，就别轻易谈解法。 | 定方案 |
| 核心决策就是想明白：我们现在应不应该做这件事。 | 定方案 |
| 好的计划能提前解决 80% 的项目问题。 | 拆计划 |
| 大量项目结果，是靠中期过程管理出来的。 | 管执行 |
| 识别变化 → 分析风险 → 变更处理 → 风险可控。 | 管执行 |
| 让老板省心、放心、有信心。 | 管执行 |
| 复盘就是挖金矿：把正确的偶然变成必然，让搞砸的教训不再重复。 | 做复盘 |
| 成败认定、场景还原、得失分析、总结提炼。 | 做复盘 |

## 九、L6 自检清单

> 如果你准备把科学项目管理作为业务基本功刻意练习，以下清单可用于每轮练习后的自我检查。

### 定方案
- [ ] 我是否用"背景→目标→关键路径"三段论写清了方案？
- [ ] 我的目标是否可衡量？如果没有目标，我是否先停下来想目标？
- [ ] 我是否做了 ROI / 机会成本 / 机会窗口的三角形评估？
- [ ] 方案在对应项目级别（A/B/C/D）上是否做到了足够的颗粒度？

### 拆计划
- [ ] 我是否拆出了清晰的里程碑节点（含 DDL + Buffer）？
- [ ] 我是否做了 WBS 分解，且每个工作包满足"独立负责、靠谱可控、逻辑完备"？
- [ ] 我是否用 253 思考对事项做了优先级分档？
- [ ] 我是否用 RASCI 明确了每个模块的角色（尤其 R 和 A）？
- [ ] 我是否画出了关键路径并标注了依赖关系？
- [ ] 我是否做了六维敏感度判断，并在最敏感的维度上投入了更多计划精力？

### 管执行
- [ ] 我的沟通频次是否与项目敏感度匹配（而不是固定每周一次）？
- [ ] 我是否在关键交付节点做了质量评审（而不是最后一刻才看）？
- [ ] 当变化发生时，我是否走完了"识别变化→分析风险→变更处理→风险可控"四步？
- [ ] 我是否做到了让老板省心/放心/有信心（而不是等他来问）？
- [ ] 我是否关注了团队成员的体验（而不只是盯着进度表）？
- [ ] 遇到冲突时，我是否按五步法从低到高处理了？

### 做复盘
- [ ] 我是否做了复盘（而不只是"口头聊两句"）？
- [ ] 我是否用四步法走完了"成败认定→场景还原→得失分析→总结提炼"？
- [ ] 复盘产出了什么可沉淀的认知资产（文档/原则/checklist/CaseStudy）？
- [ ] 复盘结论是否可操作（不是"下次更努力"这种空话）？

### 综合自检
- [ ] 我是否根据项目类型（A/B/C/D）匹配了匹配的管理手段，而不是一味加量？
- [ ] 我是否把这次项目管理当作一次刻意练习，而不只是完成任务？
- [ ] 项目结束后，我的项目管理段位有没有可感知的提升？

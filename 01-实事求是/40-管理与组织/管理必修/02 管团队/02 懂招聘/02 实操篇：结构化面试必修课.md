## 一、为什么要学——破题篇

### 1.1 面试的普遍翻车场景

> 面试是招人最关键的一环，但很多人做不好。

| 翻车类型 | 具体表现 | 根本原因 |
|---|---|---|
| **迷信大牛背景** | 看到大厂履历就"想当然觉得行"，忽略真实能力匹配 | 没有围绕胜任力模型评估，被履历光环左右 |
| **面试变聊天** | 聊聊行业、聊聊经历、感觉不错就过了 | 缺少结构化问题框架，凭感觉判断 |
| **被表达力带偏** | 表达能力强的候选人拿高分，实干型被低估 | 没有用行为面试法追问真实案例 |
| **面完就忘** | 面了5个人，回忆不起谁是谁、差在哪 | 缺少分维度打分和面后记录机制 |
| **造假看不出来** | 候选人把别人的项目说成自己的，面试官分辨不了 | 没有追问细节到"无法编造"的颗粒度 |

### 1.2 结构化面试的本质

> **面试不是聊天，而是用模型匹配。** 结构化面试 = 围绕岗位画像和胜任力模型，用固定流程和评估标准，系统判断候选人的匹配程度。

| 非结构化面试（❌） | 结构化面试（✅） |
|---|---|
| 凭经验问散点问题 | 围绕胜任力模型设计固定问题框架 |
| 每个候选人问不同的问题（无法横向对比） | 相同岗位用同一套核心问题 + 评估标准 |
| 被候选人的表达能力和气场左右判断 | 用行为面试法（STAR）追问真实案例 |
| 面完凭感觉给一个总分 | 多个维度分别打分，事后交叉对齐 |
| "这个人感觉挺好的" | "这个人在XX维度8分，YY维度6分，ZZ维度4分——ZZ维度是这个岗位的关键能力，所以不匹配" |

## 二、核心框架：结构化面试的完整流程

> **基于课程目录"岗位模型形成方法"以及科学招聘四部曲第三步（匹配模型）的落地延伸。**（基于课程框架推演）

### 2.1 结构化面试全流程

```text
面试前：建模型 → 设流程 → 出题目
   ↓
面试中：开场破冰 → 行为追问 → 情景模拟 → 候选人提问
   ↓
面试后：分维度打分 → 交叉对齐 → 记录归档
```

### 2.2 第一环节：面试前准备——三件事

| 准备工作 | 核心内容 | 常见问题 |
|---|---|---|
| **1. 岗位模型形成** | 基于画像模型和能力模型，明确这个岗位的核心评估维度（建议3-5个） | 维度太多（>7个）→ 面不完也评不准 |
| **2. 面试流程设计** | 明确面试分几轮、每轮侧重什么、谁来面 | 每轮都问同样的问题 → 浪费候选人时间 |
| **3. 面试题目设计** | 围绕每个评估维度设计2-3个结构化问题和追问路径 | 问题太泛（"你最大的缺点是什么"）→ 候选人都有标准答案 |

### 2.3 岗位模型形成方法——从画像到面试维度

> 这是认知篇"画像模型→能力模型"的直接延伸，把纸面模型变成面试中可评估的具体维度。

| 步骤 | 动作 | 示例（以教研岗位为例） |
|---|---|---|
| **步骤1** | 从画像模型中提取3-5个核心区分因子 | 学习能力、写作能力、讲课sense、空杯心态 |
| **步骤2** | 每个因子定义"好"和"差"的行为锚定 | 学习能力好=能举出自己快速掌握新领域的案例，差=说不清自己最近学了什么 |
| **步骤3** | 确定哪些是"必须过关"（一票否决），哪些是"加分项" | 学习能力不过关直接pass，讲课sense可以后补 |
| **步骤4** | 把每个维度转成2-3个结构化面试问题 + 追问路径 | 学习能力→"请分享一个你最近半年从零学会的东西，具体怎么学的？" |

### 2.4 面试题目设计的四个原则

| 原则 | 说明 | 正例 | 反例 |
|---|---|---|---|
| **行为导向** | 问过去真实发生的事，不是假设 | "请分享一个你曾经……的案例" | "如果你遇到……你会怎么做" |
| **具体可追问** | 问题要能层层深挖直到无法编造 | "当时你具体做了什么？第一步是什么？" | "你觉得自己有什么优势" |
| **与岗位强相关** | 每个问题都对应一个评估维度 | 围绕"需求挖掘能力"设计的问题 | "你为什么离开上一家公司"（关联弱） |
| **拒绝标准答案** | 问题本身不让候选人猜到"正确回答" | "请分享一个你搞砸的项目" | "你的优点和缺点是什么" |

## 三、核心工具：行为面试法（STAR）

> **行为面试法是结构化面试的核心追问技术。** 基于课程框架推演——面试3大关键难题的首个难题就是"如何判断能力真伪"，行为面试法是最关键的解题工具。

### 3.1 STAR 四要素

| 要素 | 含义 | 追问方向 |
|---|---|---|
| **S — Situation** | 当时是什么情境？背景是什么？ | "这件事发生在什么时候？你当时的角色是什么？" |
| **T — Task** | 你要完成什么任务？目标是什么？ | "你的具体任务是什么？谁定的目标？" |
| **A — Action** | 你具体做了什么？第一步、第二步、第三步？ | "你做了什么？第一步是什么？具体怎么做的？" |
| **R — Result** | 结果是什么？可衡量的成果？ | "最后结果是什么？有数字吗？别人怎么评价？" |

### 3.2 STAR追问的核心技巧

```text
追问到"无法编造"的颗粒度：

❌ "我主导了这个项目，做得挺好的。"
   → 追问："你具体做了什么？项目几个人？你负责哪部分？"

❌ "我负责协调各部门。"
   → 追问："能举一个具体的协调场景吗？当时你跟谁沟通？怎么说的？"

❌ "最后效果不错。"
   → 追问："不错具体是什么意思？转化率从多少提到多少？"
```

| 追问原则 | 说明 |
|---|---|
| **越具体越好** | 问到时间、地点、人数、数字、第一步第二步 |
| **问行动不问感想** | "你做了什么"而非"你觉得怎么样" |
| **问痛点不问高光** | 关注失败案例、搞砸的项目、最难的一次 |
| **交叉验证** | 同一个能力用不同角度的问题验证 |

### 3.3 一则结构化面试题的AI生成示例（知识库检索到）

> 以下是一堂AI认知篇中展示的"用AI辅助生成结构化面试题"的实例，展示了一份完整的面试题目设计。

**岗位：AI技术应用岗**

| 评估维度 | 结构化面试题 |
|---|---|
| **AI技术研究和应用能力** | 请描述一次你成功应用AI技术解决实际问题的经历，并说明你在这个过程中使用的AI工具或产品 |
| **学习和掌握新技术的能力** | 请描述一次你在短时间内学习并掌握一项新技术的经历，并说明你是如何做到的 |
| **团队协作和沟通能力** | 请描述一次你在团队中发挥关键作用的经历，并说明你是如何通过沟通和协作帮助团队解决问题的 |
| **创新意识** | 请描述一次你在工作中发挥创新思维的经历，并说明你是如何将创新思维应用于实际工作的 |
| **AI领域的热情和兴趣** | 请描述你对AI领域的热情和兴趣是如何产生的，以及这种热情和兴趣如何影响你的工作和学习 |

> **启示：5个评估维度 × 1个结构化问题——每个问题都是STAR行为导向（"请描述一次……的经历"），强烈关联真实案例而非假设性回答。**

## 四、面试三大关键难题处理

> 来自课程目录"面试3大关键难题处理"模块。以下基于结构化面试最佳实践和认知篇框架整理。（基于课程框架推演）

### 4.1 难题一：如何判断能力真伪

| 造假信号 | 追问策略 |
|---|---|
| 只说"我们"不说"我" | "你在这个项目中具体负责的模块是什么？你个人直接做了什么？" |
| 结果模糊没有数字 | "能给我一个具体的数字吗？转化率/完成率/人数？" |
| 回答过于流畅像背稿 | 突然跳到一个不同角度追问细节："当时有没有什么意外情况？" |
| 项目经历和简历时间对不上 | "这个项目从什么时候到什么时候？你在什么阶段加入的？" |
| 说不清决策逻辑 | "当时为什么选A方案而不是B方案？你当时怎么判断的？" |

> **核心原则：真的做过的人，能说出细节——时间、地点、数字、意外情况、决策挣扎。编造的答案在这些追问下会迅速瓦解。**

### 4.2 难题二：如何判断文化匹配

| 评估方法 | 具体做法 |
|---|---|
| **描述真实工作场景** | 描述一个你们团队真实的冲突场景或协作场景，看候选人的反应和思维方式 |
| **看决策偏好** | "当你和老板意见不同时，你一般怎么处理？能举一个例子吗？" |
| **看协作风格** | "你最喜欢和最不喜欢的合作方式分别是什么？为什么？" |
| **反向提问** | "你觉得什么样的团队文化会让你很难适应？"（比直接问"你能适应吗"更有效） |

> **关键判断：文化匹配不是"这人好不好相处"，而是他能不能在你的组织方式下成功。** （引自认知篇叶国晖的洞察）

### 4.3 难题三：如何判断成长潜力

| 评估方法 | 具体做法 |
|---|---|
| **看学习曲线** | "过去一年你学到了什么新东西？怎么学的？学到了什么程度？" |
| **看面对陌生问题的反应** | 给一个候选人肯定没做过的新场景，看他的思考框架而非答案 |
| **看失败后的复盘深度** | "分享一个你搞砸的事。你是怎么意识到搞砸的？后来做了什么？" |
| **看主动性和好奇心** | "你最近主动研究过什么跟工作不直接相关的东西？为什么？" |

> **区分高潜和普通的关键信号：高潜候选人能清晰复盘自己的失败，能从具体案例中提炼出可迁移的认知——这和项目复盘16字法则的底层逻辑完全一致。**

## 五、常见造假点检查清单

> 来自课程Candy和学习材料《常见造假点检查清单》。以下基于结构化面试最佳实践整理常见造假信号和应对策略。（基于课程框架推演）

### 5.1 简历造假五大高发区

| 造假类型 | 常见表现 | 追问检验法 |
|---|---|---|
| **夸大职责** | "负责XX项目"→实际只是参与者 | "这个项目几个人？你的具体角色是什么？谁是对最终结果负责的人？" |
| **模糊业绩** | "业绩翻倍""效果显著"→没有具体数字 | "翻倍前是多少？翻倍后是多少？具体什么时间？" |
| **拉长时间** | 把3个月的项目写成1年 | "这个项目从几月到几月？你在什么阶段加入的？什么时候离开的？" |
| **移植项目** | 把别人的项目说成自己的 | 深挖细节："当时你和谁一起做？谁负责哪个模块？能给我看当时的文档或产出吗？" |
| **粉饰离职原因** | 被优化说成"主动离开" | "当时团队有多少人？你走之后团队有什么变化？你离职后下一份工作是什么？" |

### 5.2 面试现场造假信号

| 信号 | 含义 | 应对 |
|---|---|---|
| 大量使用"我们"回避"我" | 可能不是主要贡献者 | 追问"你个人具体做了什么" |
| 每个问题都答得太完美流畅 | 可能是提前背诵了准备好的案例 | 跳到另一个角度追问意外细节 |
| 回避具体数字 | 可能业绩没有说的那么好 | 坚持要数字："大概是多少？给个范围也行" |
| 对不同面试官讲的故事版本不一致 | 至少有一版是编的 | 交叉面试后对齐信息 |

## 六、面试后评估与交叉对齐

> 基于课程框架推演——科学招聘四部曲中"匹配模型"和"持续迭代"的衔接环节。

### 6.1 分维度打分表（模板）

| 评估维度 | 权重 | 候选人A | 候选人B | 候选人C | 评分依据（关键证据） |
|---|---|---|---|---|---|
| 维度1：___ | 30% | | | | |
| 维度2：___ | 25% | | | | |
| 维度3：___ | 20% | | | | |
| 维度4：___ | 15% | | | | |
| 维度5：___ | 10% | | | | |
| **加权总分** | 100% | | | | |
| 一票否决项 | — | | | | |

### 6.2 打分规则

| 规则 | 说明 |
|---|---|
| **先独立打分，再交叉对齐** | 多个面试官分别打分后才能讨论，避免互相影响 |
| **必须有证据** | 每个分数后面必须标注"依据什么行为/回答" |
| **一票否决项优先** | 如果有关键底线不通过，总分再高也pass |
| **不确定时追加轮次** | 关键维度证据不足 → 加一轮面试或布置作业 |

### 6.3 交叉对齐会议

```text
每个人先报自己打的分数和关键依据
  → 不一致的地方重点讨论：看到的行为有什么不同？
    → 如果仍无法判断：加面一轮，或用实际任务验证
      → 对齐后形成最终结论：通过/不通过/待定
```

## 七、面试官自我迭代——用好每一次面试反馈

> 认知篇叶国晖的核心洞察："用好每一次面试反馈的结果，来修正判断。"实操篇将这一原则落地为具体动作。

### 7.1 每次面试后的5分钟记录

| 记录内容 | 具体问题 |
|---|---|
| **画像修正** | 这次面试让我对岗位画像的哪个维度有了新理解？ |
| **问题有效性** | 哪个问题最有效地区分了候选人？哪个问题所有候选人都答得差不多（可能需要换掉）？ |
| **判断复盘** | 我最初的判断是什么？完整的面试过程之后，我的判断变化了吗？为什么？ |
| **造假信号** | 这次有没有遇到疑似造假的情况？我追问了吗？效果如何？ |

### 7.2 面试官常见自我偏差及纠偏

| 偏差类型 | 表现 | 纠偏方法 |
|---|---|---|
| **首因效应** | 前5分钟就下了判断，后面全程在找证据 | 强制自己在前30分钟不形成结论，先收集信息 |
| **相似效应** | 喜欢跟自己像的人（同背景/同风格） | 用分维度打分表强制客观化 |
| **光环效应** | 一个大厂履历让所有维度都偏高 | 拆开维度分别评估，不允许"整体感觉好" |
| **对比效应** | 前一个太差，这一个普通就显得优秀 | 对照岗位画像标准打分，不跟其他候选人比 |

## 八、AI辅助结构化面试

> 从知识库检索到的一堂课程内容：AI可以在结构化面试中担任辅助角色。

### 8.1 AI可以辅助的三个环节

| 环节 | AI可以做什么 | 注意事项 |
|---|---|---|
| **面试前：题目设计** | 基于岗位JD和胜任力模型，自动生成结构化面试题目和追问路径 | 需要人工审核和定制化调整 |
| **面试前：简历分析** | 快速提取简历中的关键信息和疑点，标注需要追问的缺口 | 造假识别仍需要人工深挖 |
| **面试后：评分辅助** | 基于面试录音/文字记录，按维度给出初步评分参考 | 最终判断必须由面试官做出 |

### 8.2 AI不能替代的

```text
❌ AI不能替代面试官做最终判断
❌ AI不能替代面对面的化学反应感知
❌ AI不能替代深挖造假时的临场追问
❌ AI不能替代文化匹配的主观判断

AI是面试官的辅助工具，不是替代者。
```

## 九、结构化面试段位成长地图

| 段位 | 核心能力 | 典型表现 |
|---|---|---|
| **L1 凭感觉面** | 无结构化意识 | 面试就是聊天，开场问"你介绍一下自己"，听完凭眼缘决定 |
| **L2 有固定问题** | 会准备问题清单 | 有固定的几个问题，但对所有岗位都问同一套，缺少针对性 |
| **L3 有评估维度** | 明确了岗位的关键评估维度 | 围绕岗位画像设计了3-5个评估维度，每个维度有对应问题 |
| **L4 会用行为面试法** | 熟练使用STAR追问 | 能层层深入追问，从"我们做了什么"追问到"你具体做了什么、怎么做的" |
| **L5 能识别造假** | 有造假信号敏感度 | 能快速识别简历和面试中的不实信息，并通过追问验证 |
| **L6 持续迭代模型** | 用面试反馈修正画像 | 每次面试后都记录认知修正，面试题目持续优化，看人准确率持续提升 |

## 十、关键金句速查

| 金句 | 出处/含义 |
|---|---|
| "面试不是聊天，而是用模型匹配。" | 结构化面试的本质 |
| "掌握结构化的面试方法，能够准确判断候选人的关键素质，至关重要。" | 课程核心主张 |
| "追问到无法编造的颗粒度——时间、地点、数字、意外情况、决策挣扎。" | 行为面试法的核心技巧 |
| "真的做过的人，能说出细节；编造的答案在追问下会迅速瓦解。" | 造假识别原则 |
| "用好每一次面试反馈的结果，来修正判断。" | 叶国晖，面试官自我迭代的核心方法 |
| "先独立打分，再交叉对齐。" | 多人面试的评估规则 |
| "一票否决项优先——关键底线不通过，总分再高也pass。" | 评估优先级原则 |

## 十一、L6 刻意练习自检清单

### 面试前——模型和题目是否就绪

- [ ] 我是否为这个岗位建立了明确的评估维度（3-5个），且每个维度有行为锚定（好/差的标准）？
- [ ] 我是否明确了哪些是"必须过关"（一票否决）、哪些是"加分项"？
- [ ] 每个评估维度是否设计了2-3个行为导向的结构化问题 + 追问路径？
- [ ] 我的问题是否避免了"你的优点是什么""你最大的缺点是什么"这类标准答案题？

### 面试中——是否在"匹配模型"而非"聊天"

- [ ] 我是否按照固定的流程和问题框架推进（而非想到什么问什么）？
- [ ] 当候选人说"我们做了XX"时，我是否追问了"你个人具体做了什么"？
- [ ] 当候选人给出模糊回答时，我是否追问了具体数字、时间、步骤？
- [ ] 我是否问了至少一个"搞砸的/最难的一次"的问题（而非只问高光时刻）？
- [ ] 我是否避免了被候选人的表达力、气场或大厂履历光环左右判断？

### 面试后——评估和迭代是否到位

- [ ] 我是否分维度独立打分，且每个分数有具体的行为证据支撑？
- [ ] 如果有多个面试官，是否先独立打分再交叉对齐？
- [ ] 我是否在面试后花了5分钟记录：这次面试让我对画像有了什么新理解？哪个问题最有效？
- [ ] 我是否把这次面试的判断和候选人入职后的实际表现做过对照验证？

### 造假识别——是否练出了敏感度

- [ ] 我是否能在面试中快速识别"我们"代替"我"的信号，并及时追问？
- [ ] 当候选人的回答过于流畅完美时，我是否会跳到另一个角度追问意外细节？
- [ ] 当候选人回避具体数字时，我是否会坚持追问"大概是多少？给个范围也行"？

### 综合自检

- [ ] 对照段位地图，你现在更像L几？下一段最需要突破的是什么？
- [ ] 过去半年，你有没有一个"面试时觉得不错、入职后发现不符合预期"的案例？如果现在重新面这个人，你会怎么问？
- [ ] 你的面试题目在过去一年有没有被迭代过？有没有一个被淘汰的"无效问题"？

# ToB案例：发票SaaS头部企业拆解 —— L6 最佳实践清单体笔记

> **源课**：一堂「ToB案例：发票SaaS头部企业拆解」  
> **案主**：徐剑——数族科技创始人，20年ToB专家，前上市公司副总裁  
> **核心命题**：一个发票SaaS公司，如何用五步法在五年内完成两轮融资，从0一步步做到行业品牌Top3  
> **笔记定位**：不只还原一个ToB SaaS业务的完整起盘过程，更提炼「用户分层×减法」「渠道四原则」「三阶段单元模型驱动」「ToB五步法的全局预判思维」等可迁移底层商业模型

## 一、先看全局：徐剑与数族科技的五步法进化全景

### 1.1 徐剑是谁

| 维度 | 身份标签 |
|---|---|
| 出身 | 南京邮电大学通信工程本科+硕士，曾任主板上市公司副总裁，年薪数百万 |
| 创业 | 2016年5月创办数族科技，专注发票数字化服务 |
| 成绩 | 5年完成2轮融资，从0做到行业品牌Top3，2022年首次全年营收破亿 |
| 融资 | 天使轮→pre-A轮，先后两轮近亿融资 |
| 覆盖 | 至2022年末服务全国逾260万家企业客户，合作伙伴超1000家 |
| 一堂标签 | 22秋马&23秋马&24春马「榜一大哥」，奖项「大满贯」得主，S级私董会NPC，《无限进步》主编 |
| 专业身份 | 获评国家高新技术企业、南京市瞪羚企业、专精特新企业、江苏省研究生工作站 |

**Truman的评价**：徐剑在一堂讲过多次课——《ToB五步法案例课：发票SaaS》《搞砸之夜》《开源之夜：单元模型专场》《一堂五步法企业服务篇》——是「一堂ToB案例的标杆人物」。

### 1.2 五步法全景画布速览

| 五步法环节 | 核心决策 |
|---|---|
| **1.需求** | 用户从「所有需要开票的商家」→逐层切到「生活服务类线下商户，需要实时开票，IT水平极弱」。关键减法：排除集团公司（IT水平高不要外部SaaS）、排除代账公司（与税务单位合作紧密不愿尝鲜）、排除IT能力强的商户 |
| **2.解决方案/产品内核** | 扫码小票二维码→按提示一步步完成开票→几分钟收到发票。内核：**做好服务**，降低开票复杂度 |
| **3.商业模式** | 客单价300-5000元/年，代理商结算价2-3折。关键单元模型：单订单/单SKU/单客户/单销售。核心驱动：支付&收银软件渠道批量复制 |
| **4.增长** | 从熟人介绍→渠道代理。渠道选择四大原则→淘汰上百种渠道→锁定三类核心渠道：百望金赋、支付公司、收银软件公司 |
| **5.壁垒** | 规模经济+切换成本。用户一旦使用发票SaaS，切换供应商意味着重新适配、数据迁移 |

| 独特之处 | 含义 |
|---|---|
| **一堂ToB案例的标杆** | 徐剑是唯一一个既在一堂讲过完整五步法拆解、又讲过ToB五步法方法论、还讲过单元模型开源、搞砸复盘的全维度案主 |
| **从0到亿级营收的完整进化** | 完整展示了ToB SaaS从需求定位→渠道探索→单元模型驱动→规模化增长的全过程 |
| **渠道选择的「四原则」框架** | 徐剑原创——懂业务不是必须、有线下商家资源是必须、IT操作能力是必须、可复制放量是必须。四条原则缺一不可 |
| **「斧凿、尺量、梯进」三阶段模型** | 徐剑送给所有ToB创业者的三个词——预判期当斧子劈开方向，测试期当尺子量出笃定，经营期当梯子持续攀爬 |

## 二、需求分析：用户分层的三层减法

### 2.1 用户分层迭代全景

| 版本 | 用户范围 | 核心减法 | 排除原因 |
|---|---|---|---|
| V0（混沌期） | 「所有需要开票的商家」 | — | — |
| V1 | 集团公司 / 代账公司 / 线下商户 | **排除集团公司** | IT水平高，自建能力强，不需要外部SaaS |
| V2 | 代账公司 / 线下商户 | **排除代账公司**（早期） | 与税务单位合作紧密，不愿尝鲜新产品 |
| V3（锁定） | **生活服务类线下商户** | 聚焦：需要实时开票、IT水平普遍极弱 | 匹配「简单易用」的产品内核 |

### 2.2 用户分层背后的核心原则

```text
L3-1（数字化水平）：IT水平高 → 排除。人家自己就能做。
L4-3（切换难度）：与现有系统绑定深 → 排除。不愿意尝鲜。
L2-3（市场份额）+ L4-4（组织文化）+ L4-2（决策角色）→ 多刀齐下，锁定最匹配的客群。
```

**锁定后的核心用户画像**：

| 维度 | 精准画像 |
|---|---|
| 行业 | 餐饮、外卖、零售等生活服务类 |
| 规模 | 中小商户为主 |
| IT水平 | 极弱——「能扫码就不错了」 |
| 痛点 | 开票效率低、容易出错、客户催票 |
| 决策者 | 老板或店长，决策链短 |

### 2.3 L6级核心认知

> 「ToB的用户分层不看'谁需要我的产品'，而看'谁最能被我服务好，且能规模化服务'。」

徐剑的用户分层没有停在「大概知道客户是谁」的层面。他用L3-1（数字化水平）、L4-3（切换难度）、L2-3（市场份额）三个维度交叉切分，最终锁定了一个精准群体——而这个群体恰恰是传统发票服务商最不愿意服务的「低客单价但海量」的客户。

## 三、产品内核：从「扫码开票」到「做好服务」

### 3.1 产品内核要素

```text
用户：生活服务类线下商户 ✅
愿意选择：用我的SaaS比手写发票快、比传统税控设备便宜 ✅
最小：扫码→填信息→开票→递送，四步完成 ✅
解决方案：发票SaaS + 7×24小时服务支持 ✅
```

### 3.2 内核的Sharp点

| 维度 | 传统开票方式 | 数族科技 |
|---|---|---|
| 速度 | 手写/税控设备，几分钟到十几分钟 | 扫码后最快**几分钟**收到发票 |
| 复杂度 | 需要培训、学习税控软件 | 扫码→按提示一步步操作 |
| 成本 | 税控设备+维护+人员 | 300-5000元/年，远低于传统方案 |
| 服务 | 税务局窗口/电话客服 | 7×24小时在线服务 |

### 3.3 一个被反复提及的细节——「服务」是内核的隐形壁垒

徐剑反复强调产品内核是「做好服务」。这不是一句口号——当竞品也在做扫码开票时，**服务的稳定性、响应速度、解决问题的能力**就是用户「愿意选择你而不是竞品」的关键。

**量化表达的服务内核**：

| 数字 | 含义 |
|---|---|
| 230万+ | 累计服务企业和商家数 |
| 13亿+ | 累计开具发票数 |
| 2,649亿+ | 累计开具发票总金额 |
| 1,000家+ | 使用数族发票能力的伙伴数 |

**一句打动人的表达**：「如果你用饿了么，1/3概率是我们提供的服务；如果你用美团，也有不小的概率能用到我们的服务。」

## 四、增长：渠道选择的「四原则」框架

### 4.1 渠道探索全景

徐剑团队曾和团队头脑风暴+朋友推荐，想了**不下100种**可能的渠道。先列9种：支付公司、代账公司、餐饮行业SaaS、零售行业SaaS、帮美团BD的、跑腿的骑手、做消防的、供应粮油调味品的、供应酒水饮料的……

### 4.2 渠道选择的四条原则（缺一不可）

| 原则 | 含义 | 被淘汰的渠道 |
|---|---|---|
| **原则一：懂发票不是必须的** | 经过少量培训就能掌握必要背景知识 | 如果要求必须懂发票，几乎没人可以帮忙推广了 |
| **原则二：有线下商家资源是必须的** | 客单价不够高到让渠道商独立只推这个产品。渠道商原有资源+产品增量价值=最强意愿 | — |
| **原则三：IT操作能力是必须的** | 需要能给商家演示系统、操作软件 | **消防**——消防大队长没有软件基础，演示系统操作弄不明白 |
| **原则四：可复制放量是必须的** | 渠道不能依赖个别能人，必须能规模化 | **美团BD**——流动性太大，过一阵子人就不在了，根本没法规模化；**骑手**——提成太低，对多数骑手不如多休息 |

### 4.3 最终锁定的三类核心渠道

| 渠道 | 为什么有效 |
|---|---|
| **百望金赋** | 税控服务行业原从业人员，有商家资源+懂基础业务+可规模化 |
| **支付公司** | 有大量线下商户资源，推支付的同时顺带推发票SaaS |
| **收银软件公司** | 软件公司有IT能力+有商户资源+发票是收银的自然延伸 |

### 4.4 L6级核心认知

> 「四条原则，缺一不可。」

徐剑最初以为「四个条件任意具备其中一个，没有明显短板就可以」。但经过实际测试发现——四条原则是**缺一不可**的。骑手对原有工作帮助不大、消防IT操作能力太弱、美团BD没法放量不可复制——每一个被淘汰的渠道，都精准踩中了某一条原则的红线。

## 五、商业模式：从浅层到深层的单元模型驱动

### 5.1 商业模式全景

| 维度 | 内容 |
|---|---|
| 客单价 | 300-5000元/年 |
| 代理商结算价 | 2-3折 |
| 核心驱动 | 支付&收银软件渠道批量复制 |
| 关键单元模型 | 单订单模型 + 单SKU模型 + 单客户模型 + 单销售模型 |

### 5.2 与「发票托管」业务的深度融合

徐剑在后续的「发票托管」业务中（代账公司+集团财务），进一步将单元模型深化为三大核心模型的交叉校验：

| 模型 | 核心问题 | 关键动作 |
|---|---|---|
| **单客户首单模型** | 一个代账公司客户首单是否赚钱？ | 从销售成本倒推线索成本上限（财务口径≤561元，现金流口径≤219元）→交叉验证锁定200-300元 |
| **单客户LTV模型** | 一个代账公司客户长期是否赚钱？ | 取线索成本中值250元代入→三年盈利3945元→模型成立 |
| **单销售模型** | 一个销售能否养活自己？ | 月需成11单→保守算10单→验证通过→可批量复制 |

### 5.3 「斧凿、尺量、梯进」——徐剑送给所有ToB创业者的三个词

| 词 | 阶段 | 含义 | 徐剑的示范 |
|---|---|---|---|
| **斧凿** | 预判期（不花钱，做选择） | 用单元模型做尽可能多、充分的估算→什么业务该做/不该做→战略方向感 | 从渠道代理转直销前，先用三模型纸上推演验证可行性 |
| **尺量** | 测试期（少花钱，测可行性） | 用单元模型做关键指标检验→什么状态算跑通/该放大→策略笃定感 | 销售月成单量跑通12单+，线索转化率30% |
| **梯进** | 经营期（花大钱，优化提升） | 用单元模型关键指标为参考→调整事、评价人→行动指向性 | 持续优化线索成本、转化率、销售效率 |

## 六、壁垒：规模经济+切换成本的双重护城河

### 6.1 壁垒判断

| 壁垒类型 | 具体内容 | 强度 |
|---|---|---|
| **规模经济** | 批量复制支付&收银软件渠道，服务260万+企业客户 | 强——新进入者很难短期搭建同规模渠道网络 |
| **切换成本** | 用户一旦使用发票SaaS，切换供应商意味着数据迁移+重新适配+业务中断风险 | 强——尤其对IT能力弱的中小商户 |
| **品牌信任** | 累计开票13亿+、金额2649亿+，市场认可度高 | 中强 |
| **技术专利** | SaaS平台技术 | 一般——技术本身可复制 |

### 6.2 面对巨头碾压式竞争的生存策略

当传统行业巨头、互联网大厂看到行业变革机遇快速布局入场时，数族科技一度被逼入生死存亡的险境。徐剑的做法：

| 策略 | 动作 |
|---|---|
| **主动深挖用户需求** | 不是跟巨头拼功能和价格，而是拼对用户的理解深度 |
| **形成差异化服务交付能力** | 巨头做标准化，数族做贴身服务 |
| **被迫跟随巨头市场动向稳步慢跑** | 不正面硬刚，而是保持跟随、等待差异化窗口 |

**结果**：「最终才在激烈的血拼中幸运存活。」

## 七、ToB五步法的全局预判——徐剑的核心洞察

### 7.1 ToB创业最容易犯的四类典型错误

徐剑观察到，哪怕是做了很多年的老ToB人，也还在持续犯：

| 错误类型 | 表现 | 后果 |
|---|---|---|
| **只做自己擅长的事** | 「我懂这个技术，把产品做出来肯定就能卖」 | 产品做出来了，发现没人买 |
| **不做取舍** | 「所有有开票需求的都是我的用户」 | 资源分散，谁也服务不好 |
| **存在盲区——不懂增长** | 只关注产品和交付，不关注获客体系 | 产品好但增长慢，被竞对反超 |
| **存在盲区——不懂壁垒** | 只看当下收入，不看长期护城河 | 被巨头碾压式入局，无险可守 |

### 7.2 ToB与ToC的根本差异

| 维度 | ToC | ToB（徐剑的实践认知） |
|---|---|---|
| 用户规模 | 海量、分散 | 相对有限、集中 |
| 决策链 | 个人决策，瞬间 | 多角色、长周期 |
| 产品要求 | 体验好、价格优 | 稳定、可靠、服务好 |
| 增长方式 | 投放+裂变+内容 | 渠道代理+直销+关系 |
| 壁垒来源 | 品牌+网络效应 | 规模经济+切换成本+渠道绑定 |
| 单元模型重心 | 单用户/单订单 | 单客户/单SKU/单销售多模型交叉 |

### 7.3 L6级核心认知

> 「ToB创业者普遍都有过一定从业经验和擅长技能。所以做ToB时很少有人不做预判，但很少有人做全局预判。」

徐剑的差异化：他不只是在某一个环节「想得比较清楚」，而是在**需求、方案、模式、增长、壁垒五个环节都做了充分的推演和验证**。全局预判=五个环节都不留盲区。

## 八、跨案例提炼：L6 级底层模型

### 模型一：ToB渠道选择的「四原则缺一不可」模型

```text
原则一：懂业务是不是必须的？
  → 如果必须 → 人才供给太少 → 渠道无法规模化

原则二：有客户资源是不是必须的？
  → 如果客单价不够高、不能独立养活渠道 → 必须

原则三：IT/操作能力是不是必须的？
  → 如果需要渠道商演示系统、操作软件 → 必须

原则四：渠道本身能不能放量？
  → 如果依赖个别能人、人员流动性大 → 不可复制

四个原则不是「满足一个就行」，而是「缺一不可」。
任何一个不满足，这个渠道就无法成为规模化的核心渠道。
```

### 模型二：ToB增长的三阶段渠道进化

```text
第一阶段：熟人介绍（起盘期）
  → 创始人关系+行业人脉，天花板极低但不可或缺
  → 徐剑：早期通过熟人介绍拿到第一批客户

第二阶段：渠道代理（增长期）
  → 用「四原则」筛选→锁定3-5个核心渠道
  → 徐剑：从100+种渠道中筛出百望金赋+支付公司+收银软件三类

第三阶段：直销+渠道混合（成熟期）
  → 核心大客户直销+长尾客户渠道覆盖
  → 徐剑（发票托管业务）：从渠道代理转向直销，用单元模型验证可行性
```

### 模型三：ToB SaaS用户分层的三维交叉法

```text
维度一：数字化水平（L3-1）
  → IT能力越强，越不需要外部SaaS
  → 排除：集团公司（自建能力强）

维度二：切换难度（L4-3）
  → 与现系统绑定越深，越不愿尝鲜
  → 排除：代账公司（与税务单位系统绑定紧密）

维度三：市场份额/组织文化/决策角色
  → 越分散、决策链越短，越适合标准化SaaS
  → 锁定：生活服务类中小商户（决策快、IT弱、量大）
```

### 模型四：徐剑的「1→N」渠道扫描-筛选-测试三步法

```text
Step 1：全量扫描（做加法）
  → 团队头脑风暴+朋友推荐+行业研究→不设限
  → 徐剑：想了不下100种渠道

Step 2：原则筛选（做减法）
  → 用四原则逐条过→淘汰明显不符合的
  → 徐剑：淘汰米面粮油供应商（IT弱+对用户无影响力）

Step 3：实战测试（验证）
  → 小范围测试→收集数据→验证假设
  → 徐剑：骑手测试→提成太低对原有工作帮助不大→淘汰
         消防测试→IT操作太弱→淘汰
         美团BD测试→流动性太大没法放量→淘汰
```

### 模型五：ToB五步法的「全局预判」原则

```text
多数ToB创业者：在某一个环节有深度（通常是需求或产品）
  → 盲区出现在增长、壁垒环节
  → 「产品做好了，不知道怎么卖」「做着做着被巨头碾压」

徐剑的全局预判：
  需求✅ → 用户分层逐层减法
  方案✅ → 内核sharp：做好服务
  模式✅ → 单元模型多维度交叉验证
  增长✅ → 渠道四原则筛选+持续测试
  壁垒✅ → 规模经济+切换成本+品牌

五个环节都不留盲区 = 全局预判
```

## 九、L6 级别审美清单：好的ToB科学创业者长什么样

| 维度 | 60分合格 | 85分优秀 | L6无限进步 |
|---|---|---|---|
| **用户理解** | 知道大概客户是谁 | 有客户分层 | 三维交叉分层（数字化水平×切换难度×决策文化）→逐层减法→锁定精准客群 |
| **产品内核** | 产品功能齐全 | 有清晰差异化卖点 | 内核sharp到一句话说清：「扫码→按提示操作→几分钟收到发票」，且「服务」不是口号是可量化的数据 |
| **渠道选择** | 有什么渠道用什么 | 筛选过几类渠道 | 从100+种渠道中系统扫描→四原则缺一不可→测试验证→锁定3类→持续优化 |
| **单元模型** | 算单订单模型 | 多模型交叉验证 | 预判期斧凿（纸上推演）→测试期尺量（跑数据）→经营期梯进（持续优化） |
| **面对竞争** | 拼价格、拼功能 | 有差异化策略 | 巨头碾压时——深挖用户需求+形成差异化服务交付+稳步慢跑——「在激烈血拼中幸运存活」 |
| **全局预判** | 在某一两个环节想得清楚 | 五个环节都有推演 | 需求/方案/模式/增长/壁垒五环节全量推演+每个环节都有验证数据支撑 |

## 十、可直接带走的最小行动清单

### 如果你也在做ToB业务的渠道探索：

1. **做一次全量渠道扫描**：像徐剑一样——团队头脑风暴+朋友推荐+行业研究，先不设限，把所有可能的渠道列出来（目标是100+种）
2. **用「四原则」逐条筛选**：懂业务是不是必须？有客户资源是不是必须？IT能力是不是必须？能放量吗？——四条全过才算合格
3. **先以为「满足一个就行」，再测试验证**：徐剑最初也以为四个条件任意具备一个就行——测试后才明白缺一不可。别跳过测试这一步

### 如果你在打磨ToB产品内核：

4. **用数字化卖点替代模糊表达**：像徐剑一样——230万+企业、13亿+发票、2649亿+金额。数字比形容词更有说服力
5. **把「服务」做进产品内核**：不是「我们也提供售后服务」，而是「服务就是内核的一部分」——7×24小时、响应速度、问题解决率——这些是可量化、可迭代的

### 对ToB创业者：

6. **做一次全局预判自查**：五个环节——需求你切了几刀？方案够sharp吗？单元模型交叉验证了吗？增长渠道测试过吗？壁垒是什么？——找到最薄弱的环节，优先补
7. **把「斧凿、尺量、梯进」刻进决策流程**：预判期不花钱做选择（纸上推演），测试期少花钱测可行性（跑数据），经营期花大钱优化提升（持续迭代）

---

> **一句话收束**：徐剑用五年时间、两轮融资、从0到行业Top3的完整历程证明了同一件事——**ToB创业不是「拼技术和关系」，而是「拼商业分析的系统性」。** 当他把用户从「所有人」用三维交叉切到「生活服务类中小商户」、把渠道从100+种用四原则筛到3类核心渠道、把内核从「扫码开票」迭代到「做好服务」、把单元模型从单维度推演到三模型交叉验证之后——一个做发票SaaS的公司可以在巨头碾压下存活并增长到260万+企业客户。而他那句「很少有人不做预判，但很少有人做全局预判」，和那三条「斧凿、尺量、梯进」，或许是所有ToB创业者最该记住的两句话：**不是你没有分析，而是你的分析没有覆盖所有关键环节。全局预判 = 五个环节都不留盲区。**

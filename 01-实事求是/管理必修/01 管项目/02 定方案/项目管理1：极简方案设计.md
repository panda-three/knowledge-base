# 《项目管理1：极简方案设计》— L6 清单体笔记

---

## 〇、课程总纲

> **做事最难也最基础的第一步是：理清楚，说明白。**
>
> 这门课解决一个核心痛点：方案反复被老板推翻、被同事挑战、推动力弱——根本原因是方案可行性没想清楚。Truman 将交付一套极简的一页纸方案设计方法，让方案**立得住、讲得清、推得动**。

### 课程定位

| 维度 | 说明 |
|---|---|
| **所属系列** | 项目管理五课中的第 2 节（第 1 节是先导课-认知地图） |
| **对应基本功** | 项目管理四步中的第 1 步——**定方案** |
| **学员规模** | 6608 位创业者，221.6 万字学习笔记，评分 8.6 |
| **核心交付** | 一套用一页纸把一件事讲清楚的方法 |

## 一、课程要解决的五大常见误区

> 很多人在做方案时效率低、被推翻，不是努力不够，而是踩了以下误区的坑。

| 误区 | 表现 | 后果 |
|---|---|---|
| **1. 跳过背景直接谈方案** | 一上来就说"我们要做什么"，不说"为什么做" | 缺乏共识基础，方案被质疑时无法自证 |
| **2. 目标模糊** | "做得更好""提升效率"这种不可衡量的描述 | 无法判断成败，批评没有标准 |
| **3. 路径太细碎** | 一上来就陷入执行细节、SOP 级颗粒度 | 看不到主线，老板和同事找不到讨论切入点 |
| **4. 单一选项封闭思考** | 只深入研究一个方案，没有准备任何 Plan B | 被问"还有其他选项吗"时哑口无言 |
| **5. 一边执行一边纠结** | 方案没定就开干，执行中还在质疑做不做 | 效率极低，团队方向感模糊 |

> **Truman 的血泪教训：**"不要在单一封闭的选项里解题，开放问题要去全局探索解法。充分做加法，专业做减法。"

## 二、核心框架①：方案顶层思考三段论

> **背景 → 目标 → 关键路径**
>
> 这是 Truman 在去哪儿网学到的核心基本功，也是整节课最重要的思维模型。

### 2.1 三段论全景

```
背景 ──→ 目标 ──→ 关键路径
(Why)    (What)    (How)
```

| 三段 | 核心问题 | 具体写法 | 常见坑 |
|---|---|---|---|
| **背景** | 为什么要做？发生了什么问题/机会？ | 描述 Before 状态 → 指出问题或机会 → 说明不做的后果 | 跳过背景直接谈方案 |
| **目标** | 做到什么程度算成功？ | 可衡量的 After 状态，最好有数字和时间 | 目标模糊，无法判断成败 |
| **关键路径** | 怎么做到？最核心的几步？ | 3-5 条核心动作概述，可评估可行性 + 估算成本 | 路径太细或太虚 |

### 2.2 三段论铁律

> **没问题，就别轻易讨论目标；没目标，就别轻易谈解法。**

```text
逻辑从前往后理顺 → 说服力就强了
背景不清 → 目标没有根
目标不明 → 路径没有方向
```

### 2.3 三段论的威力来源

| 层次 | 作用 |
|---|---|
| **背景** | 建立"为什么现在必须做"的紧迫感和共识 |
| **目标** | 锁定"做到什么程度算赢"的判断标准 |
| **关键路径** | 展示"我准备怎么做到"的可行路线，让评审者看到思考深度 |

### 2.4 三段论 vs 业务管理三段论

> Truman 在去哪儿网同时学到两套三段论，二者互补但不相同。

| 方案设计三段论 | 业务管理三段论 |
|---|---|
| **背景 → 目标 → 关键路径** | **目标 → 路径 → 资源** |
| 用于立项、说服、评审 | 用于复杂业务系统规划 |
| 回答"应不应该做" | 回答"需要什么资源才能做成" |

## 三、核心框架②：方案评估三角形

> **核心决策，其实就想明白：我们现在应不应该做这件事情。**
>
> 把判断转化成商业语言，变成三个维度。

### 3.1 三角形全景

| 维度 | 核心问题 | 具体含义 |
|---|---|---|
| **投入产出比 ROI** | 划不划算？ | 投入什么（钱/人/时间）VS. 产出什么（收入/效率/能力），值不值？ |
| **机会成本** | 是不是最佳？ | 这个选项 VS. 其他所有选项——做了这个，放弃了什么更好的？ |
| **机会窗口** | 是不是现在？ | 现在做 VS. 其他所有时间——早了白费力，晚了没机会 |

### 3.2 三角形使用规则

| 规则 | 说明 |
|---|---|
| **三个维度都要过** | 不能只看 ROI 就拍板，漏掉另两个维度会出大问题 |
| **机会成本是防后悔药** | 每次决策前问自己：如果选了 A 而没选 B，B 会有多大损失？ |
| **机会窗口是时机判断** | 有些事不是不做，是时候未到；有些事现在不做就永远晚了 |

### 3.3 三角形在不同项目级别上的运用

| 项目级别 | 评估深度要求 |
|---|---|
| **A 单人项目** | 心里过一遍即可，不需要正式文档 |
| **B 小项目-多人** | 简版 ROI + 关键机会成本 + 窗口判断 |
| **C 中项目-跨部门** | 多部门联合评审（财务/法务/市场），完整三圈分析 |
| **D 大项目-公司级** | CEO 参与评审，全面风险预判 + 完整评估三角形 |

## 四、核心交付：一页纸极简方案

> **Truman 多年苦练的基本功：用一页纸将一件事讲清楚。**
>
> 顶层一页纸文档是最上层的统筹，避免出现反反复复的纠结、质疑和推翻。

### 4.1 一页纸结构

```text
┌─────────────────────────────────────┐
│          【项目名称】                  │
│                                     │
│  一、背景                           │
│  - 当前状态（Before）                │
│  - 核心问题/机会                     │
│  - 不做会怎样                        │
│                                     │
│  二、目标                           │
│  - 成功状态（After）                 │
│  - 可衡量指标（含数字和时间）          │
│                                     │
│  三、关键路径                        │
│  - 路径 1：……                       │
│  - 路径 2：……                       │
│  - 路径 3：……                       │
│  （3-5 条，每条一句话概述）            │
│                                     │
│  四、方案评估                        │
│  - ROI：                            │
│  - 机会成本：                        │
│  - 机会窗口：                        │
│                                     │
│  五、核心决策                        │
│  - 我们现在应不应该做？               │
│  - 推荐选项及理由                    │
└─────────────────────────────────────┘
```

### 4.2 一页纸的三条质量标准

| 标准 | 含义 | 自查问题 |
|---|---|---|
| **立得住** | 逻辑站得住，前因后果充分，不怕被问"为什么" | 从背景推到目标推到路径，有没有逻辑断裂？ |
| **讲得清** | 别人看完一页纸就能理解你要做什么、为什么做 | 能不能让一个不了解背景的人在 3 分钟内看懂？ |
| **推得动** | 方案有足够说服力，能让决策者和执行者都愿意行动 | 关键决策者看完会不会说"好，去做"？ |

### 4.3 一页纸写作心法

| 心法 | 说明 |
|---|---|
| **先写背景，不急着写方案** | 背景没写清楚之前，不要跳到目标和路径 |
| **目标必须有数字** | 不能用"提升""优化""改善"这种模糊词，必须有量 |
| **关键路径不超过 5 条** | 多了说明你没想清楚主次 |
| **方案评估要诚实** | ROI 算不清楚就承认算不清楚，不要硬编数字 |
| **核心决策一句话** | "我建议我们做这件事，因为……" |

## 五、Truman 的实战案例：一堂马拉松定方案

> Truman 用一堂九届马拉松的实战，演示了一页纸方案在 D 级公司大项目中的应用。

### 5.1 马拉松顶层一页纸的应用

每一届马拉松启动前，都用一页纸敲定最顶层的选项和决策，避免执行中反复纠结。

| 届数 | 关键决策难题 | 用评估三角形如何判断 |
|---|---|---|
| 第 1 届 | 真的要办马拉松吗？ | ROI：投入教研/运营资源 VS. 激活用户/验证模式 |
| 第 2 届 | 要做线下城市巡回吗？ | 机会成本：做线下 VS. 把同样资源投入线上产品 |
| 第 3 届 | 要不要做新 SKU，卖 MBA？ | 机会窗口：现在入局教育产品的时机是否合适 |
| 第 4 届 | 要把一堂作为案例开源吗？ | ROI：开源带来信任 VS. 商业机密泄露风险 |
| 第 5 届 | 要做万人复盘营吗？ | 机会成本：复盘营 VS. 其他增长手段 |
| 第 8 届 | 要不要涨价？ | ROI：涨价带来收入增长 VS. 用户流失风险 |
| 第 9 届 | 要从春节换成 3 月吗？ | 机会窗口：哪个时间节点用户参与度更高 |

### 5.2 马拉松项目管理脱轨教训（反面案例）

> 前两期马拉松曾发生大量脱轨问题，根源都是方案没定清楚。

| 问题 | 表现 | 根因 |
|---|---|---|
| **过早陷入细节** | 容易陷入细节讨论，忽略关键工作 | 没有先用一页纸定顶层 |
| **关键工作跟丢** | 关键销售材料到最后一天还没准备好 | 关键路径没列全 |
| **缺少工作计划** | 前期没准备，直接开干 | 跳过定方案直接进执行 |
| **角色划分不清** | 关键工作没有明确分工，到处救火 | 方案阶段没考虑谁来执行 |

### 5.3 马拉松的正确做法

```text
顶层一页纸文档（定方案）
  ↓ 拆成 D → 一组 C 级别项目
  ↓ 每个 C 再拆出 100+ 个 AB 级别子项目
  ↓ 每个子项目有自己的方案 + 计划 + 执行 + 复盘
```

> **核心原则：把大的选项/路径/目标在顶层定下来，整个项目就稳了。避免一边分工做执行，一边还在质疑/纠结做不做。**

## 六、方案设计六大原则（Truman 多年提炼）

| 原则 | 含义 | 反例 |
|---|---|---|
| **1. 目标驱动** | 没目标，不谈任何事情 | "我们先做着看看" |
| **2. ROI 优先** | 分析不清楚 ROI，就推不动事情 | "这个肯定有价值，先做" |
| **3. 充分做加法，专业做减法** | 开放阶段穷举选项，决策阶段果断取舍 | 只深入一个方案，没有备选 |
| **4. 前因后果理顺** | 从背景→目标→路径，逻辑链条不断 | 背景没讲清就跳到执行细节 |
| **5. 一页纸说清** | 能用一页纸讲清楚，才说明真想清楚了 | 方案写了 20 页 PPT 还没说到重点 |
| **6. 决策前置** | 在方案阶段把"做不做"的问题解决掉 | 项目启动了还在争论方向 |

## 七、方案被推翻时的自检清单

> 如果你的方案反复被老板/同事/客户推翻，按以下顺序逐项排查。

### 7.1 逻辑层自检

| 检查点 | 问题 |
|---|---|
| 背景 | 对方是否认同"这是一个需要解决的问题"？如果不认同，回到背景重讲 |
| 目标 | 对方是否认同"做到这个程度算成功"？目标是否可衡量？ |
| 关键路径 | 路径和背景/目标之间是否有逻辑断裂？是否考虑了备选路径？ |

### 7.2 评估层自检

| 检查点 | 问题 |
|---|---|
| ROI | 投入产出是否清晰？对方是否觉得"不划算"？ |
| 机会成本 | 对方是不是觉得"还有更好的事可以做"？你有没有分析备选？ |
| 机会窗口 | 对方是不是觉得"时候不对"？早了还是晚了？ |

### 7.3 表达层自检

| 检查点 | 问题 |
|---|---|
| 一页纸 | 能不能压缩到一页纸？如果不行，说明核心逻辑还没提炼清楚 |
| 3 分钟测试 | 给一个不了解背景的人讲 3 分钟，他能不能复述你要做什么、为什么？ |

## 八、方案设计段位成长地图

| 段位 | 核心能力 | 典型表现 |
|---|---|---|
| **L1 想到就做** | 无方案意识 | 直接开干，边做边想，频繁返工 |
| **L2 会写方案** | 有方案文档 | 能把想法写成文档，但结构松散、逻辑不清 |
| **L3 三段论成型** | 背景→目标→路径 | 方案有完整逻辑链，但说服力不够，经常被推翻 |
| **L4 评估三角形** | +ROI/机会成本/窗口 | 方案不但有逻辑，还有商业判断，推向决策者时更有底气 |
| **L5 一页纸交付** | 极简 + 高说服力 | 一页纸就能让关键决策者做出判断，方案很少有重大推翻 |
| **L6 持续迭代** | 方案资产沉淀 | 每次方案都在迭代方法论，形成自己的方案模板和判断直觉 |

## 九、L6 刻意练习自检清单

> 以下清单用于每次做方案后的自我复盘和刻意练习。

### 方案写作前

- [ ] 我是否先花时间想清楚"为什么要做"（背景），而不是直接跳到"怎么做"？
- [ ] 我是否做了加法——穷举了可能的选项，而不是只盯着一个方案深入？
- [ ] 我是否找到了可以衡量成功的具体指标（含数字和时间）？

### 一页纸质量

- [ ] 我的方案能不能压缩到一页纸？如果不能，哪里是冗余的？
- [ ] 背景→目标→路径之间的逻辑链是否没有断裂？
- [ ] 关键路径是否控制在 3-5 条以内，每条一句话能说清？
- [ ] 一页纸能让不了解背景的人在 3 分钟内看懂吗？

### 方案评估

- [ ] 我是否用评估三角形（ROI + 机会成本 + 机会窗口）检查过方案可行性？
- [ ] 我对 ROI 的评估是否诚实（没有硬编数字）？
- [ ] 我是否认真思考过"做了这个，放弃了什么更好的"（机会成本）？
- [ ] 我是否判断过"现在是做这件事的最佳时机吗"（机会窗口）？

### 方案评审

- [ ] 方案被挑战时，我能定位到是背景、目标还是路径出了问题？
- [ ] 我是否有备选方案（Plan B）可以拿出来讨论？
- [ ] 核心决策是否能浓缩成一句话："我建议我们做/不做这件事，因为……"

### 方案迭代

- [ ] 这次方案和上次相比，有没有可感知的进步？
- [ ] 我是否从这次被推翻/被质疑中提炼了可复用的认知？
- [ ] 我是否在积累自己的方案模板和判断直觉？

## 十一、课程在项目管理五课中的位置

```text
第1节 先导课：科学项目管理（认知地图）
  ↓
第2节 ★ 定方案：极简方案设计（本课）  ← 你现在在这里
  ↓
第3节 拆计划：计划拆解基本功
  ↓
第4节 管执行：管理过程基本功
  ↓
第5节 做复盘：深度复盘
```

> **注意：** 本课只讲"定方案"这一步，完整的项目管理还需要后面三步（拆计划 → 管执行 → 做复盘）。但定方案是整个项目的基石——**方案立不住，后面一切执行都是沙滩上建楼。**

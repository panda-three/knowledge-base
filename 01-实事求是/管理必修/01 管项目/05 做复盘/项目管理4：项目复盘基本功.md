## 一、为什么要做复盘——破题篇

> **"复盘是入门容易，掌握难。刚开始做的时候，先不要执迷于每个环节都做到完美。先确保四个环节都走到，再逐步加深。"** —— 婧怡

### 1.1 复盘浪费九宗罪（为什么大多数复盘是假的）

| 类型 | 九宗罪 | 表现 |
|---|---|---|
| **意识不够** | 不做 | 只有在绩效考核、升职答辩才会复盘 |
| | 不信 | 不以为然，不信价值，得过且过 |
| | 不求 | 短期内看不到有收益，就放弃 |
| **姿势不对** | 不真 | 只是自我安慰，感动式打卡 |
| | 不实 | 空对空，过于强调主观，忽略客观事实 |
| | 不懂 | 只看不足，容易针对问题相互挑毛病 |
| **深度不够** | 不透 | 浅，没有区分目的、现象，理解很表层 |
| | 不全 | 复盘全是碎片细节，缺少模型 |
| | 不改 | 复盘完就完了，继续旧做法，没有任何行动变化 |

### 1.2 不做复盘的代价

```text
不做复盘 = 项目经验永远停留在个人脑子里
           正确的偶然永远不会变成必然
           搞砸的教训可能再来一次
           团队能力没有积累，每次从头摸索
```

### 1.3 复盘的真正定义

> **复盘不是工作总结，不是互夸大会，不是批斗大会。**
>
> 复盘的实质是：**"跟自己学习"——从过去真实的项目经验中，挖掘出可以复用的认知资产。** 把一次性工作，变成团队未来的能力。

### 1.4 复盘的五重价值金矿

| 金矿类型 | 不做复盘 | 会做复盘 |
|---|---|---|
| **金矿1：成败共识** | 项目组没有项目成败共识，觉得负责人不靠谱 | 项目成败有共识，项目组下次更好协作 |
| **金矿2：项目亮点** | 下次忘了成功之处 | 能够复制成功，知道什么该坚持 |
| **金矿3：问题教训** | 没看到问题所在，同一错误一再犯错 | 找到真正问题，下次不再踩雷 |
| **金矿4：过程资产** | 下次重头摸索/试错 | 思考有方法论，工作有流程，操作有 SOP |
| **金矿5：执行计划** | 不了了之 | 有明确的下一步行动计划 |

## 二、复盘的四层境界：从"缺练"到"苦练"

> 婧怡将复盘能力分成"缺练"和"苦练"两档，每档四个层级。大部分团队停留在缺练的某一层。

### 2.1 缺练四层（大部分人的现状）

| 层级 | 表现 | 问题 |
|---|---|---|
| **1. 不做复盘** | 项目结束就结束，直接进入下一个 | 经验全部浪费 |
| **2. 开互吹大会** | 复盘 = 大家互相夸夸，"这次都辛苦了，再接再厉" | 一团和气，没有真问题 |
| **3. 缺少关键资产沉淀** | 聊完就散了，没有文档、没有 SOP、没有 checklist | 说了就忘，下次接着犯 |
| **4. 缺少成绩表彰** | 做得好也没有被看见和认可 | 团队士气低迷，优秀成员流失 |

### 2.2 苦练四层（优秀 PM 的标准动作）

| 层级 | 动作 | 适用项目级别 |
|---|---|---|
| **1. 项目文档沉淀** | 每个项目结束后形成复盘文档 | A/B 级项目 |
| **2. 项目复盘会议（16 字法则）** | 按成败认定→场景还原→得失分析→总结提炼走完完整流程 | C 级及以上项目 |
| **3. 重大问题 CaseStudy** | 对关键失败/成功做深度拆解，形成案例库 | C/D 级项目的关键节点 |
| **4. 项目业绩表扬** | 表彰大会等形式，让付出被看见 | D 级大项目 |

## 三、核心框架：深度复盘四步法 & 十六字法则

> **成败认定 → 场景还原 → 得失分析 → 总结提炼**
>
> 这 16 个字来自美团的最佳实践，是婧怡在本节课交付的核心工具。

### 3.1 四步全景图

```text
成败认定   →   场景还原   →   得失分析   →   总结提炼
(找差距)       (找事实)       (找原因)       (找行动)
```

| 步骤 | 方法 | 目的 | 核心问题 |
|---|---|---|---|
| **第一步** | 成败认定 | 找差距 | 预期 vs 实际，差在哪里？包括定量差、认知差 |
| **第二步** | 场景还原 | 找事实 | 支撑差距的关键事实信息是什么？ |
| **第三步** | 得失分析 | 找原因 | 差距背后的深层原因和关键假设是什么？ |
| **第四步** | 总结提炼 | 找行动 | 有了答案之后，下一步该做什么？沉淀什么？ |

### 3.2 铁律：四步必须依次走完

```text
没认定成败 → 场景还原没有焦点
没还原事实 → 得失分析变成空对空
没分析原因 → 总结提炼变成口号
没总结提炼 → 前面的讨论全部浪费
```

## 四、第一步：成败认定——找差距

> **"成败认定的价值在于：找差距。以核心目标为导向，而不是分支目标；以结果为导向，而不是过程和时间点。"**

### 4.1 为什么要做成败认定

同一个项目，不同人心里可能有完全不同的评价：

- 项目经理觉得超额完成，但老板和同事都不满意
- 公众号 10w+ 了，但评论区全是嘲讽
- 西红柿炒鸡蛋吃完了，但爸爸觉得太酸、外婆觉得鸡蛋太少

> **项目都做完了，但大家的理解完全不一样——这就是必须做"成败认定"的原因。**

### 4.2 成败认定的两类差距

| 差距类型 | 含义 | 举例 |
|---|---|---|
| **定量差** | 可定量指标的实现情况 | 转化率、销售额、客户满意度、参与人数、延期天数 |
| **认知差** | 不同层级目标、不同视角目标的理解差异 | 老板觉得关键是质量，团队觉得关键是速度；客户觉得体验差，团队觉得功能全 |

### 4.3 成败认定两个必备工作

#### 工作一：整体认定

> **用可衡量的语言描述"项目到底做成了什么样"，而不是"牛逼""不错""还行"。**

| ❌ 错误示范 | ✅ 正确示范 |
|---|---|
| "项目牛逼，大家干活都特给力，大部分用户很喜欢" | "项目符合预期。原来定的是送 2000 个大缸子，实际送出 2234 个，超出目标。比原定时间晚了 2 天，原因是疫情不可抗力。收集到 367 份正面反馈，8 个用户给了负反馈。" |

#### 工作二：分层认定——常见的差距分析清单

> 哪怕整体结果是成功的，也要对照以下清单逐项检查差距。

| 分析维度 | 核心问题 |
|---|---|
| **1. 时间点** | 最终是否延期？过程是否延期？ |
| **2. 人力使用** | 计划多少人？实际多少人？ |
| **3. 分工安排** | 原来定了谁？后来实际谁做？ |
| **4. 姿势问题** | 大家的投入程度是否达到预期？ |
| **5. 分支完成** | 分支目标、各个模块完成情况如何？ |
| **6. 预算投入** | 原来定了多少钱？最后花了多少？ |
| **7. 项目管理** | 过程中是否有序？是否有摩擦？ |
| **8. 多视角认知** | 客户的评价 VS 团队的评价 VS 老板的评价？ |

### 4.4 成败认定的关键原则

| 原则 | 说明 |
|---|---|
| **以核心目标为导向** | 不是分支目标，不是过程指标 |
| **以结果为导向** | 不是"我们很努力"，而是"我们做到了什么" |
| **承认认知差距** | 不同人看到的结果不同，先对齐再分析 |
| **不要回避失败** | "做得不太好"也要说出来，不然没法找到真问题 |
| **用数字说话** | 能用数字就不要用形容词 |

## 五、第二步：场景还原——找事实

> **"很多时候，我们对一个问题没有答案，其实是因为我们缺足够的信息。如果信息有了，答案也就出来了。"**

### 5.1 为什么要做场景还原

没有事实支撑的复盘，会出现三种典型灾难：

| 灾难 | 表现 |
|---|---|
| **凭感觉下结论** | "A 说有用户觉得不够好，一问有多少人？不知道。到底哪儿不好？说不出来。" |
| **陷入细节泥潭** | "A 花了大量时间讲排版哪一行跟哪一行对齐，却忽略了真正的业务问题。" |
| **复盘变吵吵会** | "A 说都是 B 不靠谱导致的，B 直接炸毛。" |

> **核心教训：分析要足够务实，关键分析必须有事实支撑。区分事实和观点，少自我感觉。**

### 5.2 场景还原的两个核心原则

| 原则 | 含义 |
|---|---|
| **还原信息属实** | 这个信息有来源，是真实客观的，不是"我觉得""好像""可能" |
| **有重点地还原事实** | 找事实是有成本的，只还原和复盘目标强相关的事实 |

### 5.3 工作一：还原事实——"一正一反一应对"

| 动作 | 方法 | 具体内容 |
|---|---|---|
| **一正：多角度收集** | 搜集定量信息 | 数据类、操作动作类、关联方反馈类 |
| **一反：用反方视角** | 对齐信息，驳回自我感觉 | 当时决策的逻辑是什么？参考了哪些信息？ |
| **一应对：区分事实和观点** | 依据信息、数据说话 | 计划怎么做？实际怎么做？实际结果是什么？ |

#### 场景还原必答六问

```text
1. 时间线：什么情况下发生了什么？背景是什么？谁参与了？
2. 决策逻辑：当时决策的逻辑是什么？当时都参考了哪些信息？
3. 方法：为了实现目标，我们采用了什么方法？
4. 执行：计划怎么做？实际怎么做？实际结果是什么？
5. 资源：我们投了多少资源？花了多少人力？花了多少钱？
6. 关键依赖：少了什么就无法推进？
```

### 5.4 工作二：还原重点——常见重点还原清单

> **"场景还原时可以做的工作太多了，要努力回避那些不重要的琐碎、不能直接引起问题的或者非关键决策相关的事件。"**

| 还原类型 | 重点内容 |
|---|---|
| **还原执行** | ①里程碑 ②高优先级的工作清单 ③时间线/故事线 ④人力分工 ⑤预算等过程 |
| **还原决策** | ①还原方案设计过程 ②还原关键决策过程（当时为什么选了 A 而不是 B？） |

#### 婧怡的经典案例：西红柿炒鸡蛋

> 这道西红柿炒鸡蛋做出来非常好吃，你以后想拿它当招牌菜——
>
> **应该还原什么？**
> - ❌ 还原当时怎么讨论要不要放糖的（不重要，已经好吃了）
> - ✅ **还原整个炒菜的顺序、放的盐/糖/酱油的数量**（关键动作）
> - ❌ 还原买菜花了多少时间（除非时间影响了食材新鲜度）

#### 婧怡的经典案例：无代码公司复盘

> 公司和一个合作方成功合作了，想通过复盘找到新的赚钱模式。
>
> **应该还原什么？**
> - ❌ 项目执行时哪个环节不流畅、怎么把成本压得更低（如果下次连合作都没有，优化执行有什么用？）
> - ✅ **前期是怎么拿到项目的？合作方的画像是什么？他们认可我们的点是什么？**

> **核心原则：还原的重点取决于复盘的目的。目的是扩大合作可能性 → 还原"为什么能拿到合作"；目的是提效降本 → 还原"执行哪里卡住了"。**

## 六、第三步：得失分析——找原因

> **"回顾项目事实时，就事论事，摆事实，列数字，越具体越好。但形成认知时，建议上升 1-2 个维度，寻找底层的、更大范围普适的经验和规律。"**

### 6.1 得失分析的核心方法：提炼重要发现 + 追问关键假设

```text
重要发现 = "顺藤摸瓜"里的"藤"
原因和认知 = "瓜"
```

### 6.2 提炼重要发现——四个追问方向

| 追问方向 | 具体问法 |
|---|---|
| **围绕目标追问** | 围绕目标达成公式/关键要素提问。如销售公式 = 到达率 × 转化率 × 客单价 |
| **搜集判断追问** | 搜集现场团队、用户的判断——他们当时觉得哪里对、哪里不对？ |
| **因果追问** | 哪些事情引起了什么变化？是因果关系还是关联关系？ |
| **假设排除追问** | 假设 A 不存在，BCD 还会引起 E 吗？这个事还会发生吗？ |

### 6.3 找到关键假设——四个终极追问

| 追问 | 含义 |
|---|---|
| **1. 主客观原因** | 起作用的关键成功/失败因素是哪些？ |
| **2. 假设排除** | 假设其他因素都是最好状态，我们自己还可以做点什么，能让事情做得更好？ |
| **3. 因果关系验证** | 做了 A → 发生了 B，A 真的是 B 的原因吗？有没有其他解释？ |
| **4. 迁移性检验** | 这个结论是只适用于这一次，还是可以推广到下一次、下一种场景？ |

### 6.4 得失分析的两大工具

| 工具 | 适用场景 |
|---|---|
| **靠提问** | 围绕目标达成公式/关键要素提问（如：销售 = 到达率 × 转化率 × 客单价 → 哪个因子最拖后腿？） |
| **靠模型** | 调研 OSCAR、五步法、四步需求分析法、单元模型 6 段位、销售模型（给动力/除阻力/增触点/逼单）、项目管理模型 |

> **"如果能做到这个程度的得失分析，你就可以找到影响这些事情成败的关键假设，指导团队未来的判断和行动。"**

## 七、第四步：总结提炼——找行动

> **"复盘到这里，已经走完 70% 的进度了。很多复盘会前面聊得很开心，最后大家结束出门，并没有变成团队的认知和能力。最后一步，就是把这些金矿盘一盘，开车拉走。"**

### 7.1 总结提炼最常见错误

```text
不做提炼总结 → 没有落到实际的共识、计划和工作上 → 复盘效率大打折扣
```

### 7.2 三个必须输出的成果

| 成果类型 | 核心内容 | 具体工作 |
|---|---|---|
| **重点1：认知共识** | 团队对齐认知 | ①成败共识：对于项目成败，有没有共识？②亮点共识：做对了什么？为什么？③问题共识：做错了什么？为什么？ |
| **重点2：行动计划** | 明确下一步 | ①坚持做：需要继续做什么？（哪些 work）②放弃做：需要放弃做什么？（哪些不 work，果断停下）③新任务：需要新增做什么？（发现了哪些新问题/新假设？） |
| **重点3：过程资产** | 沉淀可复用资产 | ①方法论：N 步法、N 条原则、思考框架②清单：流程文档、话术清单、自查清单③SOP：具体执行流程 |

### 7.3 总结提炼的"复盘最后提炼的 9 个工作"清单

```text
认知共识：
  1. 成败共识 —— 对于项目成败，团队有没有共识？
  2. 亮点共识 —— 做对了什么？为什么？
  3. 问题共识 —— 做错了什么？为什么？

行动计划：
  4. 坚持做 —— 哪些 work，继续坚持
  5. 放弃做 —— 哪些不 work，果断停下
  6. 新任务 —— 发现了哪些新问题/新假设？

过程资产：
  7. 方法论 —— N 步法、N 条原则、思考框架
  8. 清单 —— 流程文档、话术清单、自查清单
  9. SOP —— 具体执行流程
```

## 八、复盘会完整操作指南——从准备到收尾

### 8.1 复盘会作弊小抄（一堂原创）

## 九、婧怡的实战案例：B 同学的会销复盘

> 这是课程中最经典的案例之一，展示了一个完整的复盘进化轨迹。

### 9.1 背景

- 一家家庭教育公司，线下会销是公司生死的关键漏斗
- 目的：将免费客户转化为 1000 元线下家庭教育课付费用户
- 参与团队：会销团队 6 人 + 会务团队 4 人 + 外勤团队 10 人

### 9.2 B 同学的 1.0：走了流程但没深度

销售总监 B 同学学到了 16 字法则，惊为天人，立刻照搬流程——

**成败认定：** "数据不错啊！活动很好，小朋友都受到了锻炼。现场氛围热烈，好几组家庭中午没吃饭都在咨询！"

**场景还原：** "场外督导很负责！分组很科学！讲师授课很精彩！现场服务很到位！"

**得失分析：** "活动前统一开了家长会。提前收集了孩子的性格和年龄信息。倒热水倒得很好，客户觉得很体贴。"

**总结提炼：** "这次大家都辛苦了！以后我们还要不断总结，再接再厉，更上一层楼，散会！"

> **问题在哪？** 一团和气、没聊深聊透、没有沉淀、没有计划。开了几次后发现每次总结内容都相似，会销活动也没有明显改观。

### 9.3 B 同学的 2.0：悟出三大关键原则

1. **"发掘问题"原则** — 复盘的核心就是找问题，绝对不能泛泛而谈、夸着夸着糊弄过去
2. **"务实求真"原则** — 一定要说真话，说到位，不能走形式，不能怕得罪人
3. **"沉淀经验"原则** — 经验必须记录下来，不能说了就忘，这次犯了错下次接着犯

有了原则后，B 同学拿自己开刀做自我批评，引导团队说真话 → 发现"场内销售居然没有一套销售动作的标准流程" → **找到了真问题！**

### 9.4 B 同学的三次觉醒

| 版本 | 核心认知 | 结果 |
|---|---|---|
| **1.0** | "原来我浪费了很多复盘学习的机会啊"——学会了流程 | 走了过场，一团和气，没有效果 |
| **2.0** | "不能直接照抄流程，复盘有三个关键原则"——学会了原则 | 找到了真问题（销售无标准流程） |
| **3.0** | "复盘的目标不是把活动做得尽善尽美，而是探索工作坊能否低成本规模化交付"——学会了目标导向 | 跳出执行细节，发现更大的业务机会 |

## 十、复盘尺度抉择——哪些项目值得深度复盘

> **"我该花 1 分钟回顾一下，还是花一周做一次全面的复盘？取决于你预判能挖出来多少金矿。"**

### 10.1 五个判断维度

| 维度 | 含义 | 判断问题 |
|---|---|---|
| **重复性** | 这类工作未来会不会重复？ | 一次性的小事还是反复发生的核心业务？ |
| **重要性** | 对公司、对团队有多重要？成本投入有多高？ | 做好了影响生死，还是做不做无所谓？ |
| **偏差大小** | 显著成功还是未达预期？背后的原因值得深挖吗？ | 结果偏差越大，复盘价值越高 |
| **沉淀价值** | 是否有方法论/SOP 可以总结？ | 能沉淀出可复用的资产吗？ |
| **确定性** | 是否风险很高/容易失败/探索型项目？ | 不确定性越高，复盘越必要 |

### 10.2 复盘投入 ROI 判断口诀

```text
越是新事儿、新人、重复执行、困难的、核心基本功的事情，
越应该主动花时间复盘。

一般规律：新业务 > 老业务，失败/异常 > 正常，探索型 > 成熟型，核心 > 边缘
```

### 10.3 美团的实战节奏

> 在美团，一些老王亲自带的旗舰新业务，团队会**每两周做一次 1-2 天的深度复盘**，因为新业务在打仗，信息量太大了，认知太多了，试错太多了——复盘会就是团队最好的迭代和学习教材。

## 十一、婧怡的收官总结——复盘的本质

> **"站在项目管理的角度，复盘的实质到底是什么？"**

```text
复盘的本质 = 把一次性工作，变成团队未来的能力。

在复盘会上：
- 你在挖掘金矿（成败认定）
- 你在还原事实（场景还原）
- 你在分析得失（得失分析）
- 你在带走资产（总结提炼）

每一次深度复盘，都是团队的一次集体认知升级。
```

## 十四、L6 刻意练习自检清单

### 复盘意识

- [ ] 项目结束后，我是否有"必须复盘"的条件反射（而不是直接进入下一个项目）？
- [ ] 我是否根据复盘的五个判断维度（重复性/重要性/偏差大小/沉淀价值/确定性）选择复盘深度，而不是所有项目都"口头说两句"？
- [ ] 我是否避免了"复盘浪费九宗罪"中最容易犯的 2-3 条？

### 准备阶段

- [ ] 复盘是否有明确的复盘目标（优化决策 or 优化执行）？
- [ ] 复盘人员是否选对了——关键 A 角色必须在，不该来的人不必来？
- [ ] 是否提前收集了关键材料（数据、反馈、关键节点记录），而不是空手进会场？
- [ ] 是否在会前定好了规则（实事求是，对事不对人）？

### 成败认定

- [ ] 我是否用可衡量语言描述了"项目到底做成了什么样"（而不是"挺不错的"）？
- [ ] 我是否做了整体认定 + 分层认定（对照常见差距分析清单逐项检查）？
- [ ] 我是否同时关注了定量差（数据）和认知差（不同人的视角差异）？
- [ ] 是否避免了"以分支目标替代核心目标"和"以过程替代结果"？

### 场景还原

- [ ] 我是否确保分析有事实支撑（而不是"我感觉""好像是"）？
- [ ] 我是否做到了"区分事实和观点"——用反方视角驳回自我感觉？
- [ ] 我的场景还原是否能回答：时间线、决策逻辑、执行方法、实际结果、资源投入、关键依赖？
- [ ] 我是否抓住了还原重点（而非陷入不重要的琐碎细节）？
- [ ] 还原重点是否和复盘目标对齐（目标是获取新合作 → 还原如何拿到合作，而非如何执行）？

### 得失分析

- [ ] 我是否通过追问提炼了重要发现（围绕目标公式/因果验证/假设排除）？
- [ ] 我是否找到了影响成败的"关键假设"（而不是只描述表面现象）？
- [ ] 我是否借用了合适的工具模型（如销售公式/五步法/单元模型），而不是纯凭直觉分析？
- [ ] 我是否做到了"从事实中上升 1-2 个维度"，形成可迁移的认知？

### 总结提炼

- [ ] 我是否完成了认知共识（成败共识 + 亮点共识 + 问题共识）？
- [ ] 我是否输出了明确的行动计划（坚持做 + 放弃做 + 新任务），而不是"继续加油"？
- [ ] 我是否沉淀了过程资产（方法论/SOP/清单），让下次不用重新摸索？
- [ ] 复盘产出是否被写成了文档、存到了团队知识库，而不是"聊完就忘"？

### 综合自检

- [ ] 这次复盘 16 字法则的四步是否都走完了（没有跳过任何一步）？
- [ ] 复盘结束后，团队成员对"项目到底成没成、为什么、下次怎么做"的认知是否对齐了？
- [ ] 和上次复盘相比，这次在深度、务实度、产出质量上是否有可感知的进步？
- [ ] 复盘产出的资产，在下一次项目中真的被用上了吗？

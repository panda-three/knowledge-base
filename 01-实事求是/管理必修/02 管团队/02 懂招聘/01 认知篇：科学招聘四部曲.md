## 一、为什么要学——破题篇

### 1.1 招聘的普遍困境

> 看起来每天大量看简历、筛简历、邀约、面试、推荐——但要么推出去10个有9个被否掉，要么招进来了真正上手时总是觉得"看错了""不及预期"。

| 困境类型 | 表现 | 根因 |
|---|---|---|
| **效率低** | 大量看简历面试，但久久招不到对的人 | 缺少岗位画像模型，筛选标准模糊 |
| **看走眼** | 面试觉得不错，入职后发现不符合预期 | 面试缺乏结构化，凭感觉判断 |
| **不可迭代** | 迟迟招不到人，但不知道哪里出了问题 | 没有复盘和迭代模型的机制 |
| **天花板低** | 总是在低水平重复写JD-筛简历-面试 | 把招聘当成执行任务，而不是可刻意练习的能力 |

### 1.2 X型 vs Y型招聘者

> **X型招聘者**：没有岗位画像模型，只迷信金句/心法，依赖简单对标，盲目筛简历，无章法面试。
>
> **Y型招聘者**：建立岗位画像模型，在实践中不断复盘迭代，提炼JD方法、筛选Checklist、面试流程技巧。

| 对比维度 | X型招聘者 | Y型招聘者 |
|---|---|---|
| **对岗位的理解** | "靠谱就行""聪明就行" | 建立多维度岗位画像模型 |
| **招聘方式** | 对标头部公司，找相同岗位的人 | 分析岗位底层能力维度，跨行业匹配 |
| **面试方式** | 靠经验、凭感觉、问散点问题 | 结构化面试，围绕胜任力模型评估 |
| **迭代方式** | 做完了事，不复盘 | 用每一次面试反馈修正判断 |
| **长期差距** | 一年、三年、十年，水平几乎不变 | 持续迭代，招聘准确率指数级提升 |

> **核心判断：X型和Y型招聘者，如果同时独立成长——一年以后、三年以后、十年以后，会拉开多大的差距？**

## 二、核心框架：科学招聘四部曲

> 科学招聘的底层逻辑：**招聘的本质是人岗匹配的过程。科学招聘 = 画像模型 → 能力模型 → 匹配模型 → 持续迭代。**

### 2.1 四部曲全景图

```text
画像模型 ──→ 能力模型 ──→ 匹配模型 ──→ 持续迭代
 (定标准)     (拆能力)     (做匹配)     (拿反馈)
```

### 2.2 四部曲详解

| 步骤 | 核心任务 | 关键问题 | 交付物 |
|---|---|---|---|
| **第一步：画像模型** | 建立岗位画像——到底要招什么样的人？ | 这个岗位影响表现的关键维度是什么？ | 岗位画像模型（多维分析） |
| **第二步：能力模型** | 拆解能力要求——这个岗位需要什么能力？ | 完成这个岗位的核心工作，需要哪些关键能力？ | 胜任力模型 + 能力地图 |
| **第三步：匹配模型** | 人岗匹配——候选人是否符合画像和能力要求？ | 怎么评估候选人？用什么流程和工具？ | 筛选Checklist + 面试流程 + 评估标准 |
| **第四步：持续迭代** | 用每一次招聘反馈修正模型——画像和能力对不对？ | 招进来的人实际表现如何？画像需要修正什么？ | 迭代记录 + 更新后的画像/能力模型 |

### 2.3 四部曲的Y模型表达

```text
                画像模型
                  ↓
    筛选简历 ← 匹配模型 → 现场面试
                  ↓
              能力模型
                  ↓
        新人述职 ← → 晋升答辩
                  ↓
            持续验证迭代
```

### 2.4 科学招聘的高效定义

> **高效招聘 = 在预期时间内，尽快找到和岗位匹配程度高的候选人，而且入职率、Landing率、甚至后面业绩表现都要努力提升。**

| 高效维度 | 传统招聘（X型） | 科学招聘（Y型） |
|---|---|---|
| **时间** | 周期不可控，看运气 | 有预期时间，有节奏管理 |
| **匹配度** | 靠感觉、看眼缘 | 围绕画像模型系统评估 |
| **入职率** | 发了offer对方不来也不知道为什么 | 提前评估双方匹配度，降低拒offer率 |
| **Landing率** | 入职后能否存活全凭运气 | 画像模型提前预判适应性和文化匹配 |
| **绩效表现** | 招进来才发现"不及预期" | 能力模型提前对标岗位绩效关键要素 |

## 三、核心案例：叶国晖——大厂高管的1000次面试迭代

> **叶国晖**：前支付宝事业群副总裁、阿里集团商家事业部总经理，一堂学员中Top10级别的存在。估算面试过1000+个候选人（P8-P10级别），教研团队的评价是："你真的是个懂人的高手。"

### 3.1 三种招聘姿势的进化

| 招聘姿势 | 做法 | 问题 |
|---|---|---|
| **类型1：简单对标** | "我想找阿里、美团、京东的商家运营，跟我业务接近、级别接近的人" | 候选人凤毛麟角，优秀人才一年出不来几个 |
| **类型2：行业画像** | "我做软装赛道，就在市场上继续找软装赛道的运营" | 特定赛道去找人依然少得可怜（~1%） |
| **类型3：三维建模** | 建立业务阶段×服务特点×文化匹配的岗位模型 | 候选人池从1%扩大到跨行业，匹配准确率大幅提升 ✅ |

### 3.2 叶国晖的三维岗位画像模型

| 维度 | 子维度 | 判断逻辑 |
|---|---|---|
| **1. 业务阶段** | 早期业务 | 需要自驱力强、对产品有思考、对客户成功有感觉 |
| | 成熟业务 | 需要资源整合能力强、目标推动能力强 |
| **2. 服务特点** | 标准化程度 | 标品 vs 非标品——需要的能力完全不同 |
| | 服务频次 | 高频、中频、低频——对节奏和精力管理要求不同 |
| | 业务驱动力 | 品牌驱动/商品驱动/履约驱动/技术驱动/资源驱动 |
| **3. 文化匹配** | 协作方式 | 是否开放、密切协作、打仗风格？ |
| | 个人边界 | 有没有太强的个人边界感？ |

### 3.3 三维模型的关键洞察

> **经典案例：软装赛道找商家运营——找服装行业的比找硬装行业的更匹配。**
>
> 因为服装是商品驱动、非标程度高；而硬装是履约驱动、低频、标准化程度高。底层能力维度匹配，比行业经验更关键。

| 叶国晖发现的规律 | 启示 |
|---|---|
| 招成熟产品的BD → 后台偏商家运营的人去负责大客户，效果不错 | 能力强在底层维度，不一定强在岗位名 |
| 技术型产品 → 找架构师干，比一般产品经理好 | 核心能力比岗位标签更重要 |
| 头部产品导向大厂的人 → 来运营导向组织中做商业产品/平台产品，存活率很低 | 文化匹配和业务驱动力决定Landing成功率 |

### 3.4 持续迭代——五个修正画像的场景

> 叶国晖的答案："用好每一次面试反馈的结果，来修正判断。"
>
> **"这是真金白银喂出来的know-how，这个经验说100万美金都不过分，犯的错起码1000万美金。"**

| 迭代场景 | 修正什么 | 时间窗口 |
|---|---|---|
| **1. 筛选简历** | 评价对外的JD是不是靠谱有效——什么样的JD能吸引到对的候选人？ | 每次发布JD后 |
| **2. 现场面试** | 评价候选人对比胜任力模型是否胜任——画像的哪些维度判断准确/不准确？ | 每次面试后 |
| **3. 同岗比较** | 把公司这个岗位的人拉出来，放到候选人中间彼此对标 | 定期 |
| **4. 新人述职** | 新人到岗述职和试用期述职——当初的判断对不对？入职后实际表现如何？ | 新人入职1/3/6个月 |
| **5. 晋升答辩** | 晋升环节可以看当初自己的看人是不是准确——长期判断力如何？ | 年度/半年度 |

> **核心洞察：普通管理者修正面试认知往往就一两周、一两次，而叶国晖能拉到半年一年，持续拿反馈——学习速度自然更快。**

## 四、案例二：一堂教研复制——Truman的招聘认知迭代

> Truman把做课能力拆解成六项能力，尝试招聘教研副手，过程中经历了多次假设验证和认知推翻。

### 4.1 教研岗位的初始能力拆解

| 能力维度 | 含义 |
|---|---|
| 懂创业投资 | 懂创业，视野宽，见过各行各业 |
| 学习能力强 | 大量输入信息，IPO迭代快 |
| 写作能力强 | 能长篇写东西，不怵写1万字的稿子 |
| 懂培训讲课 | 最好会讲课，知道怎么做大家爱听的课 |
| 懂产品创新 | 空杯开放，敢于提出创造性解决方案 |
| 懂运营管理 | 能设计和管理大规模学习平台 |

### 4.2 迭代历程

| 迭代 | 假设 | 结果 | 认知修正 |
|---|---|---|---|
| **第1次** | 找写作能力强、能写严肃长文的 | 招了两人，商业文章写得很6 | **完全不行。**"写课的本质是讲课能力，而不是写作能力——会写作的人善于自我表达，但不善于做教学，不懂如何讲课" |
| **第2次** | 找真正会做课、懂教学框架的 | 集中面试国内头部职业教育公司的课程产品经理 | 持续迭代中 |

> **核心启示：岗位画像不是一次性建对的——必须通过实际面试和入职验证，持续推翻错误假设，不断逼近真实模型。科学招聘的本质就是用Y型创业的验证逻辑来做招聘。**

## 五、科学招聘四部曲完整实施路径

### 5.1 第一步：画像模型——建立岗位画像

| 建模来源 | 具体做法 |
|---|---|
| **市场对标** | 调研头部对标公司的对标岗位，了解行业最佳实践 |
| **工作流分析** | 拆解岗位的核心工作流，找到关键环节 |
| **在职人员画像** | 分析已在职的优秀员工和普通员工，找到区分因子 |
| **业务阶段匹配** | 判断业务处于早期还是成熟期，不同阶段需要不同特质 |
| **服务特点分析** | 分析岗位的标准化程度、服务频次、业务驱动力 |
| **文化匹配** | 识别团队文化对候选人的核心要求 |

### 5.2 第二步：能力模型——拆解能力要求

| 能力类型 | 核心问题 | 示例 |
|---|---|---|
| **硬技能** | 必须会做什么？达到什么程度？ | 会写逐字稿、会做用户访谈、会算单元模型 |
| **软技能** | 需要什么底层素质？ | 自驱力、学习能力、协作沟通 |
| **认知要求** | 需要什么视野和判断力？ | 懂行业、有商业sense、会做决策 |
| **经验要求** | 需要哪些相关经验？ | 做过XX类型业务、带过XX规模团队 |

> **关键提醒：技能点全部点满几乎不可能找到——先主抓1-2条最关键的能力，其他的用协作和培养慢慢补齐。**

### 5.3 第三步：匹配模型——设计筛选与评估流程

| 环节 | 工具/方法 | 要点 |
|---|---|---|
| **JD撰写** | 基于画像模型写JD | 精准描述岗位画像的关键维度，而不是泛泛列要求 |
| **简历筛选** | 筛选Checklist | 按画像模型快速匹配，不被漂亮履历迷惑 |
| **面试流程** | 结构化面试流程 | 固定环节、固定问题框架、固定评估标准 |
| **多人评估** | 交叉面试 + 评估对齐 | 多人分别面、各自打分、事后对齐认知 |

### 5.4 第四步：持续迭代——五个反馈场景

```text
筛选简历 → 现场面试 → 同岗比较 → 新人述职 → 晋升答辩
```

| 场景 | 迭代问题 | 频率 |
|---|---|---|
| 筛选简历 | 什么样的JD吸引了匹配的候选人？什么渠道效果好？ | 每轮招聘 |
| 现场面试 | 画像的哪些维度判断准确？哪些需要修正？ | 每次面试后 |
| 同岗比较 | 在职的高绩效者和低绩效者，在画像维度上差在哪里？ | 每季度 |
| 新人述职 | 当初的判断对不对？入职后实际表现和画像预期一致吗？ | 入职1/3/6个月 |
| 晋升答辩 | 长期来看，当初的看人眼光准不准？ | 每年 |

## 六、常见招聘难题与破解思路

> 从课程目录反推，本节课覆盖了"常见招聘难题""破解面试实质""面试3大关键难题处理"三大模块。

### 6.1 常见招聘难题

| 难题 | 科学解法 |
|---|---|
| 好候选人太少 | 不是人少，是画像太窄——用三维模型扩大匹配池 |
| 面得很好，入职后不行 | 面试缺少结构化，需要围绕胜任力模型设计问题 |
| 发了offer被拒 | 画像模型加入文化匹配和候选人动机预判 |
| 招来的人留不住 | 新人述职环节验证Landing质量，倒推修正画像 |
| 老员工和新人不匹配 | 同岗比较找到差距根源，优化画像模型 |

### 6.2 破解面试实质

> **面试不是聊天，而是用模型匹配。**

| 传统面试（❌） | 科学面试（✅） |
|---|---|
| 凭经验问散点问题 | 围绕胜任力模型设计结构化问题 |
| 被候选人的表达能力和气场左右 | 用行为面试法（STAR）追问真实案例 |
| 面完凭感觉给分 | 多个维度分别打分，事后交叉对齐 |
| 每个岗位用同一套问题 | 不同岗位画像定制不同面试框架 |

### 6.3 面试三大关键难题

| 难题 | 处理方案 |
|---|---|
| **如何判断能力真伪** | 行为面试法（STAR）+ 深挖具体案例 + 追问细节直到无法编造 |
| **如何判断文化匹配** | 描述真实工作场景，看候选人的反应和思维方式 |
| **如何判断成长潜力** | 看过去的学习曲线 + 面对陌生问题的思考框架而非答案 |

## 七、科学招聘段位成长地图

| 段位 | 核心能力 | 典型表现 |
|---|---|---|
| **L1 凭感觉招** | 无模型意识 | 面试就是聊天，看眼缘、看感觉、看履历漂亮 |
| **L2 会写JD** | 有基本岗位描述 | 能写出岗位要求但画像模糊，筛选标准不清晰 |
| **L3 有画像模型** | 建立了岗位画像 | 有明确的多维画像，但模型未经验证 |
| **L4 结构化面试** | 面试流程标准化 | 围绕胜任力模型面试，多个评估维度分别打分 |
| **L5 持续迭代** | 用反馈修正模型 | 从筛选→面试→新人述职→晋升全链路修正画像 |
| **L6 懂人识人** | 模型高度精准 | 跨行业跨岗位都能快速建模，招聘准确率极高 |

## 九、L6 刻意练习自检清单

### 画像模型——你是否真的有岗位画像

- [ ] 对于你当前正在招聘的岗位，你是否建立了一个超过3个维度的岗位画像模型？
- [ ] 你的画像是否包含了业务阶段、服务特点和文化匹配的考量？
- [ ] 你是否分析过岗位上现有的优秀员工和普通员工，在画像维度上的差异是什么？
- [ ] 你的画像是否经过了实际面试和入职验证的修正，而不是一次性建好就放着？

### 能力模型——你是否拆解清楚了能力要求

- [ ] 你是否把这个岗位需要的能力拆成了可评估的具体维度（而非"靠谱""聪明"）？
- [ ] 你是否区分了"必须要有"和"可以培养"的能力？
- [ ] 你是否主抓了1-2条最关键的能力，做好了其他靠协作和培养补上的心理准备？

### 匹配模型——你的筛选和面试是否结构化

- [ ] 你的JD是否精准反映了岗位画像的关键维度（而非泛泛的行业对标）？
- [ ] 你的面试是否有固定的流程、问题框架和评估标准？
- [ ] 你是否用了行为面试法（STAR）来验证候选人的真实能力？
- [ ] 你是否避免了被候选人的表达力、气场或履历光环左右判断？

### 持续迭代——你是否在修正模型

- [ ] 每次面试后，你是否会花5分钟记录"这次面试让我对画像有什么新的理解"？
- [ ] 你是否用新人述职和试用期表现来验证当初的招聘判断？
- [ ] 你是否把晋升答辩当作检验长期看人眼光的机会？
- [ ] 你的岗位画像在最近6个月内有没有被修正过至少一次？

### 综合自检

- [ ] 你现在更像X型招聘者还是Y型招聘者？差距在哪一步？
- [ ] 过去一年，你的招聘准确率有没有可感知的提升？你最大的招聘损失（招错一个人）是什么？
- [ ] 你有没有一个"犯过错、修正过"的岗位画像案例可以讲给别人听？
- [ ] 如果现在让你从零开始为一个新岗位建模，你会走哪几步？

# 课程：龙虾实践·02员工长成

**一句话结论：** 为做一个AIGC专家，不小心长出了一堆数字员工——架构师/运维/财务/提炼建模，最后发现MCP才是让Agent可持续工作的关键。

---

## 一、核心交付

- 一套Agent分工：架构师→运维专家→财务顾问→提炼建模专家
- 一个自建平台：龙虾版飞书Dashboard（Agent列表/项目空间/A2A/文档区）
- 一个关键发现：MCP=AI世界的USB接口，把复杂任务从gateway剥离
- 一个原则：AI费注意力和判断力，必须有自己的判断

## 二、关键框架

### 2.1 数字员工成长链

| Agent | 职责 | 创建原因 |
|---|---|---|
| 龙虾架构师 | 创建Agent/架构调研/培训新Agent | 需要系统化建Agent |
| 运维专家 | 软件管理/备份/应急修复/MCP搭建 | 凌晨2点修gateway修怕了 |
| 龙虾版飞书 | 协作平台（Agent列表/项目空间/文档区） | 现有工具接OpenClaw有BUG |
| 财务顾问 | 收支/保险/理财/投资管理 | 练手知识库构建 |
| 提炼建模专家 | 资料→人类可读文档+AI知识库 | 最难建的Agent |

### 2.2 Agent白皮书模板

每个新Agent创建时写白皮书：
- 基本信息：名字/职责/一句话介绍
- 具体职责和要解决的问题
- 能力
- 需要配备的资料库
- 虚拟人格

### 2.3 龙虾版飞书功能

| 功能 | 作用 |
|---|---|
| Agent列表 | 同时和多个Agent聊天 |
| 项目空间 | 复杂任务多Agent协作，隔离上下文 |
| A2A | Agent间互发消息（看gateway脸色） |
| 文档区域 | 知识库雏形，Agent写文档自动入库 |
| 财报 | 财务Agent专属，数据本地加密 |

### 2.4 为什么用MCP

| 问题 | 解决 |
|---|---|
| Gateway内存有限（>1GB就卡死） | 复杂任务剥离到MCP |
| 大模型总不按规则执行 | MCP工作流固定执行流程 |
| A2A看gateway脸色 | MCP独立运行不堵gateway |

> MCP=模型上下文协议，AI世界的"USB标准接口"。

## 三、金句与判断

> 「使用AI确实很费注意力和判断力，AI有时候会夸大，我们需要有自己的判断力。」
> 「如果每次都靠我提醒AI遵守规则，那这个规则其实没有真正变成系统能力。」
> 「为了做一个AIGC龙虾专家，不小心长成了一堆数字员工。」

## 四、行动建议

| 层级 | 行动 |
|---|---|
| 基础 | 建Agent前先写白皮书定义职责和边界 |
| 进阶 | 把重复性规则从"靠提醒"变成MCP工作流 |
| 高阶 | 评估哪些任务需要复杂Agent，哪些直接用AI对话就行 |

- 待验证：MCP是否真能解决所有gateway瓶颈问题

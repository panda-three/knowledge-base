# 需求实操3：定性评估篇 

## 一、课程定位与核心金句

> **「80% 的需求分析，做到定性评估就结束了。」**
>
> — Truman，一堂CEO

> **「与其花几个月的时间闭眼狂奔，不如用一两个晚上在纸上画一组三角形。然后冷静地问自己一个问题：这个需求，真的值得我未来全身心投入吗？」**

> **「算账是需要成本的，而定性评估是快速的试纸。评估都没信心的需求，根本不需要进入'算'的环节，直接在这里熔断。」**

**课程在五步法中的位置**：

```text
需求分析四字诀 = 拆 → 推 → 评 → 算
                        ↑
                   本节课在这里
```

- 「拆」是找切口
- 「推」是演剧本
- **「评」是当法官** — 低成本的生死判
- 「算」是定量测算

---

## 二、预热思考 · 三连问

| # | 问题 | 用意 |
|---|------|------|
| 1 | 如果需求只有「拆-推-算」，推演完直接进入测算，为什么还需要多此一举的「评估」？ | 理解「评」存在的本质原因 |
| 2 | 你过去有没有因为一个"看起来很美"的需求，投入了大量时间/金钱后才发现是伪需求？如果当时有一个快速定性评估框架，结局会不同吗？ | 建立对熔断机制的切身痛感 |
| 3 | "我觉得这个需求挺普遍的"——这句话的问题在哪？ | 暴露主观臆测 vs 客观定性的核心差距 |

---

## 三、为什么需要「评」：本质原因

### 3.1 核心逻辑

```text
「算」的成本太高了。
多个选项，每一个都测算业务天花板，
调研、分析、交叉验证成本太高，正常团队很难承受。
```

| 对比 | 直接「算」 | 先「评」再「算」 |
|------|-----------|----------------|
| 成本 | 每个选项都要深度调研、定量测算 | 先用低成本定性框架筛掉 80% |
| 效率 | 资源分散，验证周期极长 | 集中资源在 Top 1-3 高信心选项 |
| 风险 | 在伪需求上浪费数月甚至数年 | 没信心的直接熔断止损 |

### 3.2 「评」的本质定义

```text
「评」的本质是：低成本的生死判。

用一套标准化的定性评估框架，
用最小的成本和时间，初步收敛机会，
避免将资源投入到伪需求或价值不足的方向上。
```

### 3.3 熔断机制

```text
「评估都没信心」的需求 → 直接熔断（Kill），不需要进入「算」的环节。
有信心的选项 → 进入下一步测算 or MVP 测试。
```

> 💡 特别说明：80% 的需求分析做到定性评估就结束了。**把"看起来很美"的东西先掐死一批，没信心的直接熔断止损。**

## 四、核心心法：1 句话 + 4 个关键词

### 4.1 一句话心法

```text
通过多选项评估，不断对比需求维度，最终形成信心。
```

### 4.2 四个关键词（缺一不可）

| 关键词 | 解释 | 常见错误 |
|--------|------|----------|
| **多选项** | 不能只有一个选项，要有 3-10 个备选项 | 拿一个想法就当全部，没有备选 |
| **对比** | 精髓在于对比，通过对比来排序和证伪 | 只看绝对值高低，不横向比较 |
| **需求维度** | 通过普遍性、频次、刚性三个维度综合评估 | 只看单一维度（如"太窄了"就否定） |
| **信心** | 最终交付是找到高信心选项 | 不是找到"完美选项"，而是找到"足够有信心推进"的选项 |

> 💡 这类似于**贝叶斯定律**：在信息不完全的情况下，通过不断获取新信息来修正认知，最终把模糊的直觉转化为科学的信心。

## 五、核心工具：需求评估三角形

### 5.1 三角形全景

```text
              普遍性
            （多少人）
             /    \
            /      \
           /  需求  \
          /  评估   \
         /   三角    \
        /            \
    频次 ——————————— 刚性
  （多少次）        （多想要）
```

### 5.2 三维度完整标尺

| 维度 | 等级 | 标准 |
|------|------|------|
| **普遍性** | 全民 | 几亿量级 |
| | 大众 | 千万/百万量级 |
| | 小众 | 十万/几万量级 |
| | 特殊 | 几千/几百量级 |

| 维度 | 等级 | 标准 |
|------|------|------|
| **频次** | 高频 | 一天一次 |
| | 中频 | 一月一次 |
| | 低频 | 一年一次 |
| | 极低 | 一生一次 |

| 维度 | 等级 | 标准 |
|------|------|------|
| **刚性** | 非常刚 | 加钱抢着用 |
| | 比较刚 | 收费我也用 |
| | 不太刚 | 免费我才用 |
| | 没刚性 | 白给也不用 |

### 5.3 综合评估法则

```text
需求评估 = 普遍性 × 频次 × 刚性

关键判断：
- 单一维度足够强，也不见得是一个好需求
- 单一维度非常弱，也不见得是一个伪需求
- 往往某一个维度比较突出，而另外两个不至于太差拖后腿，就是还不错的需求
```

### 5.4 定性对比表（实操格式）

| 需求选项 | 普遍性 | 频次 | 刚性 | 综合判断 |
|----------|--------|------|------|----------|
| 选项A | 高/中/低 | 高/中/低 | 高/中/低 | 优先/可做/克制 |
| 选项B | 高/中/低 | 高/中/低 | 高/中/低 | 优先/可做/克制 |
| 选项C | 高/中/低 | 高/中/低 | 高/中/低 | 优先/可做/克制 |

### 5.5 六种常见组合与判断

| 组合类型 | 典型特征 | 判断建议 |
|----------|----------|----------|
| 小众 + 高频 + 极刚 | 细分市场钉子切入 | ⭐⭐⭐ 非常适合初创期 |
| 小众 + 超高客单 | 高价值低频 | ⭐⭐ 需验证付费意愿 |
| 低频 + 高客单 + 高决策权重 | B端重决策 | ⭐⭐ 需评估销售成本 |
| 看似不刚（痒点）但很赚钱 | 情绪驱动型 | ⭐ 需区分真痒点 vs 伪需求 |
| 普遍 + 高频 + 不太刚 | 流量型但难收费 | ⭐ 需找变现路径 |
| 小众 + 低频 + 没刚性 | 三重弱势 | ❌ 直接熔断 |

> 💡 **进阶提醒**：不要因为一个需求"看起来太小/太窄"就误判。很多被误判为"太小"的机会，其实是 **小众 + 极刚** 的金矿。回归全局和理性，问自己：这是"真的太小"，还是"被误判的小金矿"？

## 六、分析深度图：从主观到客观

### 6.1 实事求是·分析深度六层

| 段位 | 层级 | 判断基础 | 典型特征 |
|------|------|----------|----------|
| L1 | **不太关心** | 相信直觉 | 模模糊糊不拆解，凭直觉做决策 |
| L2 | **主观判断** | 相信逻辑 | 依赖个人感受，主观评价和选择——「我觉得/我感觉/我推测」 |
| L3 | **客观定性** | 相信调研 | 充分分析和调研，努力做客观判断 |
| L4 | **区间定性** | 相信对比 | 不只是高低大小，而是有大概区间 |
| L5 | **区间定量** | 相信数据 | 可以大致定量，有相对可靠范围 |
| L6 | **精准定量** | 相信测算 | 进行精准定量，完成最终测算 |

> 核心洞见：**从 L2（主观判断）到 L3（客观定性）的这一步，就已经是一次巨大的飞跃。** 客观定性本身就具有了基本的科学可证伪性。

## 七、三次能力飞跃

### 7.1 飞跃全景

```text
第一次飞跃：从单点到全局 → 告别"拍脑袋"
第二次飞跃：从主观到客观 → 告别"我觉得"
第三次飞跃：从单次到系统 → 告别"一轮游"
```

---

### 7.2 第一次飞跃：从单点到全局

**飞跃前（L1-L2 典型症状）**：

```text
讨论需求时，习惯性按照"某一个直觉感受"下判断：

"这个需求太窄了，肯定不行。"
"这个需求太低频了，没办法做。"
"需求必须得特别普遍，不然撑不起商业模式。"

全凭直觉，全靠感受，全靠灵机一动。
今天觉得一定得疼，明天觉得一定得宽，后天又觉得一定得高频。
```

**飞跃后（L3 状态）**：

```text
用需求评估三角形，同时看三个维度：
- 普遍性 × 频次 × 刚性

不再用单点感受否定一个需求，
而是用全局视角综合判断。
```

**关键动作**：

| 步骤 | 内容 |
|------|------|
| 1 | 通过「拆」和「推」，拉出 3-10 个需求选项 |
| 2 | 对每个选项，分别评估普遍性、频次、刚性 |
| 3 | 填入定性对比表，横向排序 |
| 4 | 识别 Top 1-3 高信心选项 |
| 5 | 特别留意：有没有"小众+极刚"的金矿被误判为太小 |

**组合视角自查**：

```text
- 有没有"小众+高频+极刚"的机会？
- 有没有"小众+超高客单"的机会？
- 有没有"低频+高客单+高决策权重"的机会？
- 有没有"看似不刚但很赚钱"的机会？
```

---

### 7.3 第二次飞跃：从主观到客观

**飞跃前（L2 典型语言）**：

```text
"我觉得这个需求挺普遍的。"
"我感觉大家都会需要。"
"我推测这个应该是刚需。"
"我认为用户会很频繁地用。"
```

> 这种判断基础是**主观信心**，不是**客观事实**。不同人各有各的"我觉得"，却没有统一的评估标尺。即使模型学得再漂亮，本质上仍然是——**换了套高级话术的拍脑袋**。

**飞跃后（L3 状态）**：

```text
客观定性 = 可以被证伪的判断。

"大学生去食堂吃饭比叫外卖客单价更低" → 可证伪
"一堂上创业课比上管理课的需求更普遍" → 可证伪
"律师发票的刚性比律师加微信更疼" → 可证伪
```

**第二次飞跃的关键动作**：

| 步骤 | 内容 |
|------|------|
| 1 | 识别自己语言中的"我觉得/我感觉/我推测" |
| 2 | 把每个主观判断改写成**可证伪的命题** |
| 3 | 为每个命题找**客观证据**（用户行为 > 用户说的话） |
| 4 | 交叉验证：不同信息源是否指向同一结论 |

**信息源可信度排序**：

```text
朋友怎么说 << 用户怎么说 << 用户做过什么 < 用户真实会做什么
```

> 💡 关键区分：我们不是追求"绝对客观"——那不现实。我们追求的是"客观定性"：每一个判断，都可以被事实证实或证伪。**从"我觉得"到"因为…所以…"，这一步就是巨大的飞跃。**

---

### 7.4 第三次飞跃：从单次到系统

**适用场景**：

```text
当遇到需要创新的情况——全新场景、全新需求、概率极低、九死一生。
市场上没有成熟对标，需求场景非常分散，
有几十上百个可能的任务（JTBD），每一个概率都很低。
```

**飞跃前（L3-L4 典型工作流）**：

```text
通过拆和推找到 3-10 个选项
→ 排序、分析、调研、评估
→ 找到 Top 1-3 需求点
→ 结束

问题：这是局部最优解，不一定能探索到足够优秀、Sharp 的需求。
```

**飞跃后（L4-L5 系统扫描）**：

```text
不是做一轮评估就结束，
而是建立"需求雷达"——系统性地扫描更多需求空间，
持续对比、持续收敛、持续发现新的可能性。
```

**简单 vs 困难方案判断**：

| 项目类型 | 适用方案 | 典型做法 |
|----------|----------|----------|
| 大量对标/借鉴为主/概率较高 | **简单方案** | 拆+推拉出 3-10 选项，对比排序，访谈，选 Top N |
| 缺少对标/自行分析/概率极低 | **困难方案** | 系统雷达扫描，多轮收敛，JTBD 深度推演 |

## 八、需求分析六段位爬山地图

| 段位 | 能力 | 典型标志 |
|------|------|----------|
| **L1** | 模糊理解 | 只谈我有什么、初心概念、想服务所有人 |
| **L2** | 主动拆解 | 会有效对标、识别差异性、剥离非用户 |
| **L3** | **定性可行性** | **能细拆解用户、定性三维评估、会交叉验证** ← 本节课目标 |
| **L4** | 定量天花板 | 需求产品匹配、会估算规模 |
| **L5** | 全局决策 | 短期规模变化、需求商业匹配、需求增长匹配 |
| **L6** | 动态预测 | 推演使用场景、中期竞争变化、长期市场变化 |

```text
提升路径：
入门（L1-L2）→ 进阶（L3-L4）→ 高阶（L5-L6）
开始有意识拆解 → 开始多工具专业分析 → 开始全局战略思考+动态调整
```

## 九、创业不同阶段的评估策略

| 阶段 | 策略 | 核心动作 |
|------|------|----------|
| **初创期** | 寻找「极高刚性 + 中高频次 + 窄普遍性」的切入点 | 解决一个特定细分市场中"足够足够疼"的问题 |
| **成长期** | 通过产品化抽象提升「普遍性」 | 同时利用客户成功策略维持「频次」 |
| **成熟期** | 将「刚性」从单一功能转化为平台依赖 | 构建竞争力和壁垒 |

## 十、经典案例速查

### 案例一：手机电量 40% 提醒（伪需求经典）

| 维度 | 分析 |
|------|------|
| 用户 | 平时按时上班的上班族 |
| 场景 | 晚上忘记充电，早起床后电量低于40% |
| 需求 | 立即提醒充电 |
| **普遍性** | 中——上班族确实不少 |
| **频次** | 极低——偶尔忘记充电 |
| **刚性** | 没刚性——快充普及、到处可充电，反而制造焦虑 |
| **结论** | **低频 + 非刚需 = 伪需求，直接熔断** |

### 案例二：荷兰鲜奶进入湖南市场

| 维度 | 分析 |
|------|------|
| 投入 | 20人团队整整一年定牧场、工厂、标准、流程 |
| 缺失 | 没有花时间找几个人拿几箱奶去社区测试购买意愿 |
| **刚性** | 不够强——对价格较高的鲜奶，大家不愿意付费 |
| **教训** | 需求刚性不够，花一年建供应链之前，应该先用「评」做一轮定性判断 |

## 十一、三步实操落地指南

### 简单项目（L3 标准方案）

| 步骤 | 动作 | 产出 |
|------|------|------|
| 1 | 用「拆+推」拉出 3-10 个需求选项 | 需求选项清单 |
| 2 | 对每个选项用三角形打「高/中/低」 | 定性对比表 |
| 3 | 横向排序，挑出 Top 1-3 | 高信心选项 |
| 4 | 做几轮用户访谈交叉验证 | 验证后的优先级 |
| 5 | 有信心 → 进入「算」；没信心 → 熔断 | Go/Kill 决策 |

### 困难项目（L4-L5 系统方案）

| 步骤 | 动作 | 产出 |
|------|------|------|
| 1 | JTBD 任务扫描（几十上百个任务候选） | 需求雷达全景 |
| 2 | 第一轮粗筛——用三角形快速过滤 | 候选池缩小到 10-20 |
| 3 | 第二轮深筛——增加客户画像/场景推演 | 候选池缩小到 5-8 |
| 4 | 第三轮精筛——访谈 + 交叉验证 | Top 1-3 |
| 5 | 进入「算」或 MVP 测试 | 科学验证路径 |

## 十二、实操避坑指南

| 常见坑 | 表现 | 正确姿势 |
|--------|------|----------|
| **单选项幻觉** | 只有一个想法，就当它是唯一方向 | 强制拉出至少 3 个备选项再评估 |
| **主观臆测** | "我觉得大家都会需要" | 把每个判断改成可证伪命题，去找事实 |
| **单维度否定** | "这个太窄了，不行" | 看三维度组合：小众+极刚可能是金矿 |
| **忽略事实** | 凭经验和类比下结论，不调研 | 用户行为 > 用户说的话 > 自己的推测 |
| **没有对比** | 只看一个需求的绝对值 | 必须横向对比 3-10 个选项 |
| **不敢熔断** | 明明信心不够，还硬推进 | 80% 的需求就该死在「评」这一关 |

## 十三、L6 级别进阶认知

### 认知一：「评」不是可选项，而是生存项

> 创业者每天面对无数看似精妙的机会。没有「评」的熔断机制，大部分资源会浪费在伪需求上。**「评」不是为了证明某个想法是对的，而是为了在资源有限的情况下，筛选出胜算最高的那一个。**

### 认知二：客观定性本身就是巨大飞跃

> 很多人误以为必须做到精准定量才叫专业。但事实上，从「主观臆测」到「客观定性」，就已经是一次巨大的飞跃。客观定性具有基本的科学可证伪性——每个判断都可以被事实证实或推翻。在真实的商业里，能做到这一步，已经超过了 90% 的创业者。

### 认知三：需求的本质是与你无关的客观事实

> 需求不是你怎么想、打算怎么做、想怎么定价。需求是市场上客观存在的问题——不管你是相信还是不相信，不管你是研究还是不研究，它都客观存在。**把需求从「我认为」里剥离出来，是需求分析真正的第一课。**

### 认知四：单一维度的弱势不等于伪需求

> "太窄了""太低频了""不太刚"——这些单点判断常常杀死真正的好机会。很多伟大的生意起步时都是「小众+极刚」。需求评估要看三维度的组合，而不是某一个维度的绝对值。**被误判为"太小"的机会，可能是被忽略的金矿。**

### 认知五：熔断是需要刻意练习的能力

> 「评」的最终交付不是漂亮的评估表，而是**Go/Kill 决策的勇气**。放弃一个"看起来不错"的方向，往往比推进一个方向更需要判断力。80% 的需求分析在定性评估后就该结束——**学会说「不」，是创业者最高阶的能力之一。**

# 低成本验证实操1：剥离假设篇 — L6 清单体笔记

---

## 一、课程定位与核心金句

> **「没有『关键假设』的精益创业，就很难低成本。」**

> **「精益的高手，都是剥离的高手。关键假设剥离得越好，你给自己争取的试错命数就越多，就有更大的概率把事情做成。」**

> **「一提到精益，立刻开始设计MVP——这中间缺了最最关键的一步：剥离关键风险和假设。」**

> **「把商业模式的可行性，从增长和收入目标里剥离出来。」**

**课程在低成本验证系列中的位置**：

```text
低成本验证系列 · 全景地图：
  全员必修：低成本验证认知篇（认知入门）
    → 低成本验证实操1：剥离假设篇（核心实操·上）← 本节课
      → 低成本验证实操2：MVP设计篇（核心实操·中）
        → 低成本验证实操3：系统测试篇（核心实操·下）
```

**本节核心交付**：**三关模型（心态关→操盘关→本质关）+ 五步法假设拆解框架 + 三层剥离法 + 精益浪费六宗"最" + ABCD四类精益场景。** 帮你从L2（有精益思维）提升到L3（有假设拆解能力）——不再"把业务看成一大坨"，而是能精准剥离出最关键的风险点。

**课程渊源**：Truman在课上坦诚——"这节课我们犹豫再三，决定采用'剥离'这个动词。"因为多年磨课发现，大部分同学一提到精益立刻开始设计MVP，但缺少中间最关键的能力：**把模糊的"业务风险"拆成一个个具体的、可验证的关键假设。**

**推荐谁学**：已经知道要低成本验证，但一到实操就"把业务看成一大坨"，不知道从哪开始测、测什么、怎么拆。如果你总感觉"这个业务太复杂了，没法低成本测"，这节课就是你的必修课。

## 二、预热思考 · 三连问

| # | 问题 | 用意 |
|---|------|------|
| 1 | 你现在的业务，如果必须用一句话说出「最可能让我失败的那个假设是什么」，你能说出来吗？如果说不出来——说明你还不知道自己的关键风险在哪。 | 暴露「没有关键假设意识」这个核心问题 |
| 2 | 你上一次做MVP测试时，是先「拆出关键假设→再设计测试」，还是「想了个大概就直接做了一个简化版产品」？如果是后者，你测完之后真的学到了关键认知吗？ | 区分「临摹MVP」和「假设驱动的科学测试」 |
| 3 | 如果把你的业务按「需求→方案→商业模式→增长→壁垒」拆开，你觉得哪一步的风险最大？哪一步如果没验证就投入，后果最严重？ | 建立「假设分层」的全局意识 |

## 三、核心认知：为什么「剥离假设」是精益的第一性原理

```text
│                                                         │

│    "哦，精益就是小步快跑、低成本试错、做MVP！"              │
│    → 学完觉得很有道理                                      │
│    → 一做业务还是习惯性地把业务看成一大坨                    │
│    → 努力临摹MVP，但效率很低，结果很差                     │
```

### 3.2 「剥离」的真正含义

```text
「剥离」这个动词，是Truman和教研团队反复推敲后选择的。

它的意思不是「删减」，不是「简化」，而是：

把模糊的"这个业务能不能成"的焦虑，
一层一层剥开，
直到露出里面那些具体的、可验证的、

「如果这个假设是错的，整个业务就做不成」的关键假设。
```

### 4.1 第一关：心态关 — 破除四大心态，建立四大心态

**核心原则：不破不立。心态转不过来，再好的方法论也用不出来。**

#### 四种需要破除的心态

| # | 错误心态 | 表现 | 后果 |
|---|----------|------|------|
| 1 | **完美主义** | "等我做得再好一点再拿出去测" | 越憋越大，风险越积越高 |
| 2 | **害怕抄袭** | "我测了被同行看见抄走怎么办" | 把验证拖到产品完整之后，反而更容易被抄 |
| 3 | **担心品牌风险** | "拿个半成品出去测，用户会看不起我" | 为了保护根本不存在的品牌，放弃拿到真实认知的机会 |
| 4 | **害怕MVP失败** | "万一测出来不行，就证明我错了" | 把项目的最终成败交给了运气而非科学验证 |

> 💡 这四种心理惯性的共同后果：**导致系统性风险延后验证，风险越憋越大。把项目成败交给了上天和运气。**

#### 四种需要建立的心态

| # | 正确心态 | 含义 | 为什么重要 |
|---|----------|------|-----------|
| 1 | **默认失败** | "我很可能会搞砸——所以我要先把最容易搞砸的部分测出来" | 不是悲观，是清醒。清醒的人先排雷。 |
| 2 | **相信成功** | "如果一轮轮验证都通过了，我就能越来越笃定" | 信心不是靠打鸡血，是靠证据积累。 |
| 3 | **假设驱动** | "我的每个商业判断，本质上都是一个待验证的假设" | 把「我以为」变成「我要测」，把主观变成客观。 |
| 4 | **螺旋上升** | "每一轮验证后，我对这个业务的认知就深一层" | MVP不是一次性的测试，而是一轮轮的认知升级。 |

> 💡 这四种操盘心态的共同价值：**帮助你直面项目的风险，尽早验证，逐步降低风险，把项目的成败一步步牢牢抓在自己手里。**

### 4.2 第二关：操盘关 — 用五步法做全局商业分析

> **「一堂五步法，在实际指导业务层面，最大的价值是：一个足够稳定、普适、科学的假设拆解框架。而且它是一个循序渐进的里程碑模型。」**

#### 五步法作为假设拆解框架

```text
┌───────────────────────────────────────────────────────────────┐
│         五步法 = 五层关键假设拆解框架                              │
├───────────────────────────────────────────────────────────────┤
│                                                               │
│  一堂五步法：需求 → 解决方案 → 商业模式 → 增长 → 壁垒             │
│                                                               │
│  每一步背后，都隐藏着若干「如果不验证就可能致命」的关键假设：        │
│                                                               │
│  需求层假设：                                                   │
│    「这个需求真的存在吗？够普遍、够频、够刚吗？」                  │
│    「用户愿意为解决这个问题付费吗？」                             │
│                                                               │
│  方案层假设：                                                   │
│    「我的产品内核足够Sharp吗？用户愿意选择我吗？」                 │
│    「关键转化率能支撑商业模式吗？」                               │
│                                                               │
│  商业模式层假设：                                               │
│    「单元模型能跑通吗？毛利能覆盖所有成本吗？」                    │
│    「单客户模型+单销售模型同时成立吗？」                          │
│                                                               │
│  增长层假设：                                                   │
│    「获客渠道可持续吗？CAC和LTV的关系健康吗？」                   │
│    「渠道模型能支撑规模化吗？」                                  │
│                                                               │
│  壁垒层假设：                                                   │
│    「我的护城河是真的吗？规模变大后模型变好还是变差？」             │
│    「我的优势是结构性的还是暂时的？」                             │
│                                                               │
└───────────────────────────────────────────────────────────────┘
```

#### 最重要的剥离动作：价值假设 vs 增长假设

> **「先把商业模式的可行性，从增长和收入目标里剥离出来。」**

```text
很多创业者一上来就想验证"这个生意能不能做大"。
但正确的做法是：

第一步：先验证"价值假设"（前三步）
  → 需求成立吗？方案有效吗？单元模型能跑通吗？
  → 这一步不涉及增长——一个客户能服务好就行

第二步：价值假设验证通过了，再验证"增长假设"（后两步）
  → 能规模化复制吗？壁垒能守住吗？

为什么这个剥离极其重要？
  → 因为很多业务是"价值假设"都没通过，就在讨论"增长"
  → 把验证资源错配到了不该优先验证的假设上
  → 增长是后话，生存是前提
```

### 4.3 第三关：本质关 — 实事求是地面对世界

> **「精益的根源，是科学地认识客观世界。」**

#### 三层本质认知

```text
第一层：剥离风险
  → 实事求是地面对世界，相信概率和风险的存在
  → 不是"我觉得能成"，而是"哪里可能不成"

第二层：多几条命
  → 假设拆得越准，试错成本越低，安全命数越多
  → 每一次精准的剥离，都是在给自己争取额外一次试错机会

第三层：相信客观规律
  → 用MVP探索和不断复现规律
  → 不是"我相信这个业务能成"，而是"经过N轮验证，数据告诉我这个方向走得通"
```

#### 一堂朴素原则

```text
今天课程最后，Truman送了一句话：

「时时刻刻记得，我很可能会失败，会搞砸，会把场面弄很糟，可能会让大家失望。
然后去认真谨慎地测试和验证它。」

拥抱不确定性，直面失败，用最低的成本创业。
就算一直失败，就算血本无归，也不会伤到你的筋骨。
你还能继续爬起来，继续下一轮战斗。

这就是精益创业的精髓所在。
```

## 五、三层剥离法：精益洋葱模型

> **「就像剥洋葱，一层层剥离。有趣的是，每一层都是一个完整的小洋葱（MVP）。减法越多，剥离得越小，成本越低，你可以拥有更多的命数去反复小步快跑。」**

```text
┌───────────────────────────────────────────────────────────────┐
│              三层剥离法 · 洋葱模型                                │
├───────────────────────────────────────────────────────────────┤
│                                                               │
│                     ┌─────────────┐                           │
│                     │  第三层：需求  │                          │
│                     │  够真/够普遍/  │                          │
│                     │  够大吗？     │                          │
│                     └──────┬──────┘                           │
│                            │                                  │
│              ┌─────────────┴─────────────┐                    │
│              │       第二层：解决方案      │                    │
│              │  产品内核够Sharp吗？       │                    │
│              │  关键转化率够支撑吗？       │                    │
│              └─────────────┬─────────────┘                    │
│                            │                                  │
│     ┌──────────────────────┴──────────────────────┐           │
│     │              第一层：商业模式                 │           │
│     │   单元模型能跑通吗？                          │           │
│     │   毛利能覆盖所有成本吗？                      │           │
│     └─────────────────────────────────────────────┘           │
│                                                               │
│  剥离顺序：商业模式 ← 解决方案 ← 需求                           │
│  验证顺序：需求 → 方案 → 商业模式                               │
│                                                               │
│  每一层剥离完成 = 一个有信心的里程碑                             │
│  三层全部剥离并验证 = 可以进入增长假设验证                       │
│                                                               │
└───────────────────────────────────────────────────────────────┘
```

### 三层剥离的里程碑标准

| 层级 | 剥离目标 | 里程碑标准 | 验证通过后可以 |
|------|----------|-----------|-------------|
| **需求层** | 剥离出需求原点（拆推评算） | 有信心支撑解决方案（够真、够普遍、够大） | 进入方案层假设验证 |
| **方案层** | 剥离出产品内核 | 有信心支撑商业模式（关键转化率够好） | 进入单元模型验证 |
| **商业模式层** | 剥离出单元模型 | 有信心支撑增长和扩张（盈利性够强） | 进入增长假设验证 |

## 六、精益浪费六宗"最"

> Truman在课上总结了创业者不剥离假设、习惯"憋大招"导致的六种典型浪费。

```text
┌───────────────────────────────────────────────────────────────┐
│              精益浪费六宗"最"                                    │
├──────────┬──────────────────┬─────────────────────────────────┤
│   类型    │      典型表现      │           一句话                 │
├──────────┼──────────────────┼─────────────────────────────────┤
│ 最悲催   │    需求找错       │ 创业最悲催的浪费——一开头问题就找错了 │
│ 最考验   │    方案做错       │ 需求对了但方案完全走偏              │
│ 最盲区   │    过早细化       │ 还没验证需求就在打磨细节             │
│ 最赔钱   │    过早扩张       │ 单店模型没跑通就开始复制             │
│ 最惋惜   │    闭门造车       │ 从来没有跟真实用户接触过             │
│ 最难调   │    转型太慢       │ 数据已经很差了还在死撑               │
└──────────┴──────────────────┴─────────────────────────────────┘
```

**所有浪费的根源**：Truman总结为五个字——**「热爱憋大招」**。越是害怕失败的人，越容易憋大招。越是憋大招，风险越大。**唯一的破解方法，就是先剥离关键假设，再设计最小成本的验证。**

## 七、ABCD四类精益场景

> 不是所有验证都需要精益。Truman用ABCD四象限帮你判断：**什么时候精益能带来最大杠杆。**

```text
┌───────────────────────────────────────────────────────────────┐
│              ABCD四类精益场景                                    │
├──────────┬──────────────────┬─────────────────────────────────┤
│   场景    │      典型特征      │           精益策略                │
├──────────┼──────────────────┼─────────────────────────────────┤
│   A类    │ 高风险 + 高可测   │ ⭐ 最优先——必须用精益，                 │
│          │                  │ 剥离关键假设，设计MVP验证           │
├──────────┼──────────────────┼─────────────────────────────────┤
│   B类    │ 高风险 + 低可测   │ 想办法把"低可测"变成"高可测"——            │
│          │                  │ 拆解假设、换验证角度、找代理变量    │
├──────────┼──────────────────┼─────────────────────────────────┤
│   C类    │ 低风险 + 高可测   │ 可以做精益，但优先级低于A类              │
│          │                  │ 适合练手、积累验证经验              │
├──────────┼──────────────────┼─────────────────────────────────┤
│   D类    │ 低风险 + 低可测   │ 不用花太多精力在精益上                  │
│          │                  │ 靠常识判断即可                    │
└──────────┴──────────────────┴─────────────────────────────────┘
```

**核心优先级**：**精益优先级：A >> B > C > D。** 把有限的验证资源，优先投向那些"如果不测就可能致命，而且能低成本测出来"的关键假设。

## 十、一层层剥下去：从洋葱到洋葱心

### 10.1 剥离的核心动作链

```text
① 把模糊的「这个业务能不能成」
    ↓ 剥第一层
② 拆成「需求假设 + 方案假设 + 商业模式假设 + 增长假设 + 壁垒假设」
    ↓ 剥第二层
③ 判断当前阶段最该先验证哪一层（价值假设优先于增长假设）
    ↓ 剥第三层
④ 在那一层里，找到「如果不验证就可能致命」的1-3个关键假设
    ↓ 剥第四层
⑤ 为那1-3个关键假设，设计最低成本的验证手段
```

### 10.2 剥离质量的自我检验

```text
问自己三个问题：
  ① 我能说清楚「如果这个假设是错的，我的业务就做不成」吗？
     → 如果说不出来——你还没找到关键假设
  ② 我能说清楚「验证这个假设，最少需要花多少钱、多少时间」吗？
     → 如果说不出来——你剥离得还不够细
  ③ 我现在验证的这个假设，是属于「价值假设」还是「增长假设」？
     → 如果价值假设还没过就开始测增长——你剥离的顺序错了
```

## 十一、一堂内部的精益实操心法

### 11.1 四句核心口诀

```text
① 没有关键假设的精益创业，就很难低成本。
② 把商业模式的可行性，从增长和收入目标里剥离出来。
```

## 十三、L6 级别进阶认知

### 认知一：剥离假设的能力，是精益验证的「元能力」

> 大多数人学精益，把注意力放在「怎么做MVP」上——假Landing Page怎么做、人工替代怎么设计。但Truman这节课的核心洞见是：**MVP只是手段，剥离假设才是前提。** 如果假设没剥离对，MVP做得再漂亮也是「系统性地验证一个不关键的假设」。剥离是精益的第一性原理——没有精准剥离，就没有真正的低成本。

### 认知二：从L2到L3的跨越，本质上是「把恐惧变成假设」

> L1的人觉得「这个业务风险很大，我不敢做」。L2的人觉得「这个业务有风险，我测一下」。但L3的人能把「恐惧」翻译成「假设」——不是「我怕卖不出去」，而是「我的假设是目标用户愿意为这个产品付费超过X元，我需要用Y手段来验证这个假设」。**把模糊的焦虑变成可验证的命题，这是从「感性创业者」到「理性操盘手」的关键质变。**

### 认知三：心态关（第一关）是最被低估的一关

> Truman把心态关放在三关之首，不是随意为之。很多创业者卡在精益验证，表面上是「不会设计MVP」，实际根因是完美主义、害怕失败、害怕品牌受损。这些心态不破，方法论再熟也用不出来。**心态关没过的创业者，学再多精益技巧也只会「知道但做不到」。**

### 认知四：五步法作为假设拆解框架，是全局商业分析的最高效入口

> 没有框架的人剥离假设靠「灵机一动」——今天觉得需求最重要，明天又觉得增长最重要。但有了五步法，你拥有了一个稳定、普适、循序渐进的假设地图。**每一步都对应着一类关键风险，每一步都有对应的验证方法论。** 从需求到壁垒，五步法的框架让你不会漏掉任何可能致命的假设层。

### 认知五：「剥离」不是一个一次性动作，而是一种需要持续刻意练习的习惯

> Truman在课上说：「精益天生就是个实操的学问，光听个热闹没用。所有学习的精华，都在业务执行的一次次实操里。」这节课不只是让你「学会一套框架」，而是希望你**每一次面对新业务、新项目、新想法时，第一反应不是「我该怎么做」，而是「我最该先验证什么假设」。** 把剥离刻进做事习惯里的人，和每次都要重新提醒自己「先别急着做」的人，差距是指数级的。

## 十四、行动建议

| 层级 | 行动 |
|------|------|
| **基础** | 选你当前正在做的一个业务或项目，用五步法框架（需求→方案→商业模式→增长→壁垒），在每一步下列出至少3个关键假设。然后回答：当前阶段，哪一步的哪一个假设，如果没验证就最可能致命？ |
| **进阶** | 把你列出的假设，用ABCD四象限（风险高低×可测高低）排序。找到你的「A类假设」——高风险+高可测的那个。为它设计一个低成本验证方案。记录：这个验证花了多少钱、多少时间？验证结果是证伪还是证实？ |
| **高阶** | 回忆一个你过去因为「憋大招」而交过学费的项目。用这节课的三关模型（心态关→操盘关→本质关）和三层剥离法，重新复盘：当时最关键的假设是什么？如果回到当初，你会怎么剥离？用现在的方法论，当时的成本和认知获取效率能优化多少？把答案写成一份复盘笔记——这可能是你这节课最大的收获。 |

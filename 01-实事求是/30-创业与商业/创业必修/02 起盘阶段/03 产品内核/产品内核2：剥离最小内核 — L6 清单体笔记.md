# 产品内核2：剥离最小内核 — L6 清单体笔记

---

## 一、课程定位与核心金句

> **「产品内核，就是用户愿意选择你的最小解决方案。」**
>
> — Truman，一堂CEO

> **「MVP是帮你拿业务认知的测量工具，产品内核是你盖房子的地基和骨架。」**

> **「拿掉这一条，是不是用户就不买单了？——这就是决定性。」**

**课程在一堂五步法中的位置**：

```text
一堂五步法 = 需求 → 解决方案 → 商业模式 → 增长 → 壁垒
                      ↑
                 产品内核在这里

产品内核修炼四课：
  产品内核1（认知/审美篇）→ 产品内核2（剥离最小内核·L3）→ 产品内核3（找到精准内核·L4）→ 产品内核4（动态迭代内核·L5）
                              ↑
                         本节课在这里
```

**课程段位目标**：帮你提升到 **L3 段位**——有意识地思考和剥离最小内核。

## 二、预热思考 · 三连问

| # | 问题 | 用意 |
|---|------|------|
| 1 | 你现在的业务/产品，如果只能保留 3-5 个核心要素，用户仍然愿意选择你，你留什么？ | 逼你做减法，直面「什么才是不可替代的」|
| 2 | 你现在产品里有哪些功能/特性，拿掉之后用户根本不会在意？ | 识别优化性要素 vs 决定性要素 |
| 3 | 如果现在给你一周时间，只做一件事来验证产品内核，你会做什么？ | 从「建完整产品」切换到「测最小内核」的思维 |

## 三、核心定义深度拆解

### 3.1 一句话定义

```text
产品内核 = 用户愿意选择你的最小解决方案
（「选择」包含两种情况：使用 + 付费）
```

### 3.2 四个关键词完整解读

#### 关键词一：用户 — 脱离用户谈价值是耍流氓

| 对比 | 说明 |
|------|------|
| Photoshop vs 美图秀秀，哪个更好？ | **无从比较**——核心用户和价值完全不同 |
| 一堂 vs 得到，哪个更好？ | **无从比较**——服务的人群和问题完全不同 |

> 💡 产品内核的「用户」必须是**具体到某一类人、某一个场景、某一个待解决的任务**。脱离了用户和需求谈价值高低，就是耍流氓。

**典型案例：婴儿防翻身监测仪**

```text
技术团队在实验室研究了十几个月的算法、红外感应，花了近 1000 万。
把原型机放到真实孩子旁边测试，发现：
→ 孩子长到几个月大后会大量翻身、转身
→ 导致大量不稳定、误判和误报
→ 眼下技术很难解决

❌ 问题：没有提前代入「具体用户的真实场景」去分析
💰 代价：1000 万——如果能提前提出关键假设，至少能省 90%
```

---

#### 关键词二：愿意选择 — 用户真的会用脚投票

**基于「体验更好」能支撑一个创业项目吗？**

```text
案例：有人想做「个人理财师的线上讲课工具」

逻辑：「小鹅通功能太复杂、交互不友好，我想做个简洁版，体验做到 85 分。」
用户调研：「大家都觉得目前工具不够好。」

❌ 问题：用户说「不够好」≠ 用户愿意「切换」。
从 60 分体验 → 85 分体验，在 B 端工具里很难构成换工具的理由。
```

> 💡 「愿意选择」= 用户会因为你提供的东西，**在竞品、替代方案、甚至什么都不做之间，真正选择你**。不是「觉得不错」，而是「用钱或用行为投票」。

---

#### 关键词三：最小 — 做减法，而不是做加法

```text
任何一个产品都会有很多功能/特性/模块。
对于用户来说，这些要素的价值有高有低。

产品内核要回答的问题是：
哪些要素是「拿掉它，用户就不买单」的？
哪些要素是「有它帮助也不大」的？
```

**两个终极判断句**：

| 判断维度 | 问句 | 如果答案为「是」 |
|----------|------|-----------------|
| **决定性** | 拿掉这一条，是不是很多用户就不买单了？ | 这是内核要素 |
| **优化性** | 有了这一条，是不是帮助也不大？ | 这不是内核要素 |

---

#### 关键词四：解决方案 — 不只是产品功能

**洗头机案例的经典教训**：

```text
创业者列举了 9 项功能，还准备开发 8 项新功能。

但当问到：「如果你在公共场合，决定要不要躺下去洗头，你考虑的主要是什么？」

两条共识浮出水面：
❶ 私密：「我可不愿意像按摩椅一样，在大庭广众之下洗头。」
❷ 安全：「头是人最重要的部分，万一出意外怎么办？」

→ 这才是用户真正关心的问题，而不是功能清单上的 17 个条目。
```

> 💡 解决方案 ≠ 功能罗列。用户买的是「解决问题」，不是「功能数量」。分析层级从低到高：**流程层 < 功能层 < 服务层 < 商业层**——不同层级看到的产品是完全不同的。

## 四、产品内核 vs MVP：关键区分

| 对比维度 | 产品内核 | MVP |
|----------|----------|-----|
| 本质 | 盖房子的**地基和骨架** | 盖房子的**测量工具** |
| 确定性 | 对任一产品，是**唯一的、独特的** | 可以做**很多轮** |
| 作用 | 决定产品能不能稳定立起来 | 用来测量高度/温度/湿度等各种指标 |
| 测试范围 | 聚焦在解决方案的核心价值 | 可测试五步法任何一个环节 |
| 关系 | 产品内核是 MVP 要验证的**核心对象** | MVP 是验证产品内核的**手段** |

> 💡 **核心关系**：MVP 可以测很多东西，但产品内核是 MVP 最需要优先验证的。如果内核歪了，后面所有测试都是在「系统性地验证一个错误」。

## 五、产品内核与单元模型的关系（L6 核心认知）

```text
产品内核 → 关键转化率 → 单元模型
   ↓            ↓           ↓
 要强到能      要强到能     决定商业
 支撑转化率    支撑商业     模式信心
              模式信心
```

> **Truman 反复强调**：产品内核是单元模型价值部分的关键转化率。价值足够（转化率过关），通常是单元模型有信心跑通的必要条件。

**洋葱剥离模型**：

```text
如果单元模型不成立，一层层往里剥：

单元模型失败（表面）
  → 客单价/转化率过低
    → 产品内核不够 Sharp（决定性要素缺失）
      → 需求原点就没找对（用户是谁？愿意选择吗？）
```


### 6.2 画布使用的三个关键原则

| 原则 | 含义 |
|------|------|
| **工具原则** | 产品内核只是一个研究产品价值的**工具**，不是目的本身 |
| **分层原则** | 在公司的**各个层级**都可以用产品内核思考（CEO 层、产品层、销售层…） |
| **精准原则** | 努力追求不大不小**刚刚好**的状态——不是越少越好，也不是越多越好 |

## 七、核心方法论：三步走

```text
第一步：明确目标
    ↓
第二步：罗列加法
    ↓
第三步：筛选减法
```

---

### 7.1 第一步：明确目标

**必须回答两个问题**：

| 问题 | 用意 |
|------|------|
| **用户是谁？** | 越具体越好。不是「创业者」，而是「从 0 到 1 阶段、已有一个模糊方向、正在探索商业模式的首次创业者」 |
| **核心指标是什么？** | 决定产品质量的 1-3 个关键转化率指标（如：新客首单转化率、NPS、复购率、付费转化率） |

> ⚠️ 核心指标不是「DAU」「GMV」这种结果指标，而是**直接反映产品内核价值的转化率指标**。

---

### 7.2 第二步：罗列加法

**核心原则：先发散，不评判。**

```text
把所有可能影响用户选择你的要素全部列出来。

来源可以包括：
- 内部头脑风暴
- 用户访谈
- 竞品分析
- 行业专家访谈
- 过往经验复盘
- 关键假设池
```

**Truman 朋友圈案例的加法清单**：

| 备选内核假设 |
|-------------|
| 一堂内部幕后思考（八卦/情报分享） |
| 业务认知/进展/分享 |
| 内容多元（有湿货，非严肃内容） |
| 有情绪的观点和爆炸情绪 |
| 抖机灵/凡尔赛内容 |
| 每天/周持续发，养成习惯 |
| 评论区互动（个性化维护关系） |
| 学员背书和见证（口碑好评） |

---

### 7.3 第三步：筛选减法

**核心原则：用「决定性 vs 优化性」框架做取舍。**

```text
对大多数业务，最简单可靠的减法方式：
一号位按照自己的经验和直觉先拍一个版本 → 再去论证和迭代。
```

**Truman 朋友圈案例的减法结果**：

| 内核假设（减法后保留 5 条） | 非内核假设（被删掉的） |
|----------------------------|------------------------|
| 1. 一堂品牌和使命（研究机构/教育理想/长期主义） | 内部幕后思考 |
| 2. Truman 专业人设（Top 级别的专业度/稀缺性） | 业务认知/分享 |
| 3. 内容足够稀缺性（课程，别的地方没有） | 内容多元 |
| 4. 专属活动报名（特别福利/钩子） | 情绪和观点 |
| 5. 频率超级高，每天 N 条 | 抖机灵/凡尔赛 |

**判断标准**：

| 问题 | 答案「是」→ 是内核 | 答案「否」→ 不是内核 |
|------|-------------------|---------------------|
| 拿掉这一条，用户就不买单了吗？ | ✅ 决定性 | ❌ 优化性 |
| 这一条是用户选择你的核心理由吗？ | ✅ 内核 | ❌ 锦上添花 |

## 八、产品内核修炼地图（L1-L6 六段位）

```text
┌─────────────────────────────────────────────────────────────┐
│              一堂产品内核修炼地图                              │
├──────────┬──────────┬──────────┬──────────┬──────────┬──────────┤
│   L1     │   L2     │   L3     │   L4     │   L5     │   L6     │
│ 缺价值意识│ 有价值意识│ 有最小意识│ 有专业评估│ 有快速迭代│ 有迁移能力│
├──────────┼──────────┼──────────┼──────────┼──────────┼──────────┤
│ 不在乎价值│ 不断做加法│ 缺定性研究│ 缺假设意识│ 缺抽象提炼│           │
│ 只谈产品  │ 追求大   │ 缺定量   │ 缺建模   │ 缺解放   │           │
│ 愿景，价值│ 而全，   │ 方法，缺│ 测试，缺│ 思想，缺│           │
│ 非常模糊  │ 缺思考   │ 评估指标 │ 快速复盘 │ 迁移应用 │           │
│           │ 框架     │          │          │          │           │
└──────────┴──────────┴──────────┴──────────┴──────────┴──────────┘
                              ↑
                         本节课目标
```

### 段位速查表

| 段位 | 能力 | 典型标志 | 常见卡点 |
|------|------|----------|----------|
| **L1** | 缺价值意识 | 只谈产品愿景，价值非常模糊 | 不在乎用户价值，觉得「好产品自然会有人买」 |
| **L2** | 有价值意识 | 开始关注用户价值，但追求大而全 | 不断做加法，缺思考框架，「什么功能都重要」 |
| **L3** | 有最小意识 | 能有意识剥离内核，做减法 | 缺定性/定量研究方法，缺评估指标 |
| **L4** | 有专业评估 | 能定性+定量找到精准内核 | 缺假设意识，缺建模测试 |
| **L5** | 有快速迭代 | 能快速测试、复盘、迭代内核 | 缺快速复盘能力，迭代周期过长 |
| **L6** | 有迁移能力 | 能跨领域抽象内核，自建流程 | 缺抽象提炼，缺解放思想 |

**段位进阶建议**：

| 如果你的情况是… | 建议段位目标 |
|-----------------|-------------|
| 资源有限，希望尽量成功 | L4 |
| 内核风险高，资源少且易错，需要大量迭代 | L5 |
| 想跨领域做事情，学习抽象方法，自建流程 | L6 |

## 九、经典案例速查

### 案例一：Truman 朋友圈的内核剥离

| 维度 | 内容 |
|------|------|
| **用户** | 非会员、会员、MBA 学员 |
| **核心指标** | 朋友圈互动率（阶段）→ 销售转化率（最终） |
| **加法清单** | 8 条备选假设 |
| **减法后内核** | 5 条：品牌使命 + 专业人设 + 内容稀缺 + 活动钩子 + 高频发布 |
| **验证手段** | 持续发布 + 观察互动率和转化率变化 |

---

### 案例二：洗头机 — 功能清单 ≠ 产品内核

| 维度 | 内容 |
|------|------|
| **创业者的思路** | 列举 9 项功能 + 规划 8 项新功能 = 17 条功能 |
| **用户的真实关切** | 私密性（不愿在大庭广众下洗头）+ 安全性（头部安全是第一优先） |
| **教训** | 功能清单不等于产品内核。用户买的是「安全感 + 私密体验」，不是「N 项功能」 |

---

### 案例三：连锁汉堡 — 20 万起盘、三年 100 家店

| 维度 | 内容 |
|------|------|
| **背景** | 20 年连锁餐饮经验，新汉堡品类 |
| **传统做法** | 看研报 → 看竞品数据 → 直接开店 |
| **科学做法** | 用产品内核思维：拆产品要素（口味/设备/定价/品类）→ 排列组合 → MVP 验证 |
| **结果** | 20 万起盘，3 年 100 家店 |

---

### 案例四：通讯模组 — 2B 业务的内核迭代

| 维度 | 内容 |
|------|------|
| **背景** | 移动设备通讯模组，基于 4G 芯片二次开发 |
| **传统做法** | 持续投入研发 → 打磨产品 → 搭建销售铁军 → 获得竞争胜利 |
| **科学做法** | 用产品内核画布三步走：明确目标 → 罗列加法 → 筛选减法 |
| **结果** | 五步法中最受益的一步是「产品内核」，唯一一个这样说且拿到好结果的案主 |

## 十、产品内核系列课全景

```text
产品内核1（认知/审美篇）
  ↳ 定义 + 四个关键词 + 三个原则 + 段位图

产品内核2（剥离最小内核·L3） ← 本节课
  ↳ 产品内核画布 + 三步走（明确目标/罗列加法/筛选减法）

产品内核3（找到精准内核·L4）
  ↳ 定性定量评估 + 三个维度（决定性/优化性/完备性）+ 策略武器库

产品内核4（动态迭代内核·L5）
  ↳ 长期动态迭代 + 内核与规模经济 + 商业化迁移
```

## 十一、常见踩坑清单

| 常见坑 | 表现 | 正确姿势 |
|--------|------|----------|
| **功能堆砌** | 列了十几条功能，觉得「每个都重要」 | 用「拿掉它用户还买不买」逐条筛选 |
| **伪价值意识** | 用户体验 60→85 分就以为能创业 | 体验差异 ≠ 用户愿意切换的理由 |
| **脱离用户谈内核** | 在实验室/会议室里定义内核 | 必须代入具体用户的真实场景 |
| **内核过大** | 「我们的内核是赋能行业数字化转型」 | 内核必须小到可以验证：3-5 条，不超过 7 条 |
| **把 MVP 当内核** | 做一个简化版产品就当找到了内核 | MVP 是测试工具，内核是地基——先有内核假设，再用 MVP 测 |
| **缺少验证** | 一号位拍完内核就全量投入 | 必须用专家访谈/调研/MVP 做一轮验证再投入 |

## 十二、Cheatsheet 速查卡

```text
┌─────────────────────────────────────────────────────────┐
│           剥离最小内核 · 极简清单                          │
├─────────────────────────────────────────────────────────┤
│  □ 用户够具体吗？（不是「创业者」而是「0-1 阶段首次创业者」）│
│  □ 核心指标是转化率吗？（不是 GMV/DAU 这类结果指标）       │
│  □ 加法做够了吗？（至少 8-15 条备选假设）                  │
│  □ 每条都问过了吗：拿掉它，用户还买不买？                  │
│  □ 减法后内核 ≤ 7 条吗？（建议 3-5 条）                   │
│  □ 每一个内核要素都指向「用户愿意选择」吗？                │
│  □ 有验证计划吗？（专家访谈/调研/MVP 测试）                │
├─────────────────────────────────────────────────────────┤
│  一句话：用户愿意选择你的最小解决方案                       │
│  四个词：用户 / 愿意选择 / 最小 / 解决方案                  │
│  三步走：明确目标 → 罗列加法 → 筛选减法                    │
│  两把刀：决定性（拿掉不买）/ 优化性（有它帮助不大）         │
└─────────────────────────────────────────────────────────┘
```

## 十三、L6 级别进阶认知

### 认知一：产品内核不是「总结」，而是「生死判」

> 产品内核不只是一种分析工具，它本质上是一个**资源分配决策**。当你明确地说「这 5 条是内核，其他 20 条不是」时，你其实在决定：把钱和精力投向哪里，从哪里撤出。回避这个判断，就是在回避创业中最重要、最艰难的那个选择。

### 认知二：「最小」不是越少越好，而是「不多不少刚刚好」

> 产品内核追求的不是数学意义上的最小值，而是**商业意义上的 Sharpness**——少一条用户就不选你，多一条是锦上添花但不是决定性。这个「刚刚好」的状态，就是产品内核的精准度。精准原则的本质是：**不大不小刚刚好**。

### 认知三：产品内核是动态的，不是一次性的

> L3 的「剥离最小内核」是起点，不是终点。当你验证了内核、跑通了模型，新的问题会出现：竞争格局变了、用户需求进化了、规模效应需要你做取舍了。这就是为什么还需要 L4（专业评估）、L5（快速迭代）、L6（全面迁移）。**优秀的产品内核是持续迭代出来的，剥离只是第一步。**

### 认知四：产品内核决定了你的单元模型上限

> 很多人花大量时间优化单元模型，但从不回头检查产品内核。单元模型不成立，表面看是客单价低、转化率低，但洋葱剥到最里面，往往是产品内核不够 Sharp。**内核不够强，单元模型的优化只是在系统性地弥补一个先天不足。**

### 认知五：产品内核思维适用于公司的每一层

> 不仅 CEO 需要产品内核思维。销售团队需要思考「客户选择我们的最小理由是什么」；市场团队需要剥离「传播内核」；教研团队需要剥离「训练内核」。**分层原则的价值在于：产品内核不是 CEO 的专属工具，而是组织各级都可以使用的思维框架。**

## 十四、行动建议

| 层级 | 行动 |
|------|------|
| **基础** | 用产品内核画布，把你当前业务/产品的备选内核全部列出来（至少 10 条），然后用「拿掉它用户还买不买」逐条筛选，留下 3-5 条 |
| **进阶** | 把你过去一年内做过的某个失败/停滞的产品拿出来，用产品内核画布重新拆解——问题出在加法不够，还是减法不对？还是根本就是需求原点错了？ |
| **高阶** | 给你的团队做一次「产品内核工作坊」：每个人独立用画布拆解产品内核，然后对比不同人的结果——差异最大的地方，就是团队认知最需要对齐的地方 |

---

> 📌 **最后提醒**：产品内核是五步法里「最容易被忽视、也最难掌握」的一步。如果你正在从 0 到 1 探索一个产品或业务——不确定自己的核心价值是什么、该砍掉什么、该死守什么——**那么产品内核的剥离，就是你绝对不能跳过的生死关口**。与其花几个月做一个「大而全」的东西然后发现没人买单，不如先用一两个小时，在画布上诚实地做一轮加法和减法。

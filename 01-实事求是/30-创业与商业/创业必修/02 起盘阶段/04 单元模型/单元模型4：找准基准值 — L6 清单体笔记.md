# 单元模型4：找准基准值 — L6 清单体笔记

---

## 一、课程定位与核心金句

> **「前几步都是基础：找出单元模型，找出关键项，到了这节课终于要修成正果了——把值带进去，完成商业判断，决定要不要做、要不要转型、要不要扩张。」**
>
> — Truman，一堂CEO

> **「跑通是偶然，迭代才是必然。」**

> **「如果在黑板上都不能成功，在现实里就更不可能成功。」**

> **「别人的数据是假的，行业基准值是假的，关键指标的经验也是假的，要回归到商业的本质：你的一个复制单元到底能不能赚到钱？」**

**课程在单元模型系列中的位置**：

```text
单元模型五课：
  单元模型1（重新理解"商业模式"·L1-L3）
    → 单元模型2（选择核心模型·L3-L4）
      → 单元模型3（构建完整模型·L3→L4）
        → 单元模型4（找准基准值·L4→L5）← 本节课
          → 单元模型5（动态预测模型·L5→L6）
```

**本节段位目标**：帮你从 **L4（有完整账）** 提升到 **L5（有完整账+基准值）**——完成单元模型定量判断，迭代核心指标，做出高质量理性决策。

| 对比 | L4（上节课） | L5（本节目标） |
|------|-------------|---------------|
| 能力 | 有完整账，找全了关键项 | 有完整账+基准值，能定量判断模型通不通 |
| 典型动作 | 列推建查，补齐所有成本收入项 | 建模校对数据 → 判断模型成不成立 → 迭代优化 |
| 解决的核心问题 | 「我漏了什么？」 | 「我的数字准不准？模型通不通？怎么调？」 |

**一句话交付模型**：**「建模→判断→迭代」三环节 + 三大常见错误 + 五项校准策略 + 三点预测法。** 用科学方法填补从「完整账」到「可判断的账」之间的最后空白。

## 二、预热思考 · 三连问

| # | 问题 | 用意 |
|---|------|------|
| 1 | 你现在的单元模型已经找全了关键项。但每个关键项的数值是怎么来的？是行业报告抄来的、凭经验猜的、还是实际测出来的？ | 暴露「数值来源不可靠」这个核心问题 |
| 2 | 如果你的单元模型有5个关键变量，每个变量的预测范围是±30%，整体利润预测范围会是多少？你凭什么相信这个范围？ | 理解不确定性叠加效应，建立「区间定量」意识 |
| 3 | 假设你的模型用最乐观的数据跑一遍，发现仍然亏损。你会继续做这个业务吗？ | 引入「乐观证伪法」——如果乐观都不行，就不用干了 |

## 三、L5的三大典型错误

> 从L4到L5，绝大多数创业者会踩进三种错误。识别它们，本身就是一种能力升维。

```text
┌─────────────────────────────────────────────────────────┐
│           L5 三大典型错误                                  │
├──────────────┬────────────────┬─────────────────────────┤
│   错误类型    │     表现        │         本质             │
├──────────────┼────────────────┼─────────────────────────┤
│  错误类比    │ 简单照搬别人    │ 拿一个"看起来像"的业务    │
│              │ 的数据          │ 数据直接套在自己身上       │
├──────────────┼────────────────┼─────────────────────────┤
│  乐观预期    │ 所有关键项都    │ 用愿望代替计算——         │
│              │ 取最好的值      │ "我们团队牛逼，肯定能做到" │
├──────────────┼────────────────┼─────────────────────────┤
│  缺少统计意义│ 只取一个单点值  │ 用"平均值"掩盖不确定性，  │
│              │ 不做区间预测    │ 没有区间就没有安全边际    │
└──────────────┴────────────────┴─────────────────────────┘
```

### 3.1 错误一：错误类比 — 这是一种非常不科学的简单类比

**表现**：

```text
"我做的是一个编程教育产品，XX公司也是编程教育，他们的获客成本是200-300，我也按这个算。"
"我做的是社区团购，头部公司履约成本8%，我也按8%算。"
```

**为什么错**：

| 变量 | 你的业务 vs 类比对象的差异 |
|------|--------------------------|
| 竞争强度 | 对方垄断流量，你是新入局者，获客成本天然更高 |
| 投放规模 | 对方日耗百万，你日耗一万——规模效应完全不同 |
| 客户群体 | 看起来都是"宝妈"，但一线城市和二线城市的付费意愿差几倍 |
| 品牌溢价 | 对方有品牌信任，你没有——转化率差30-50%是常态 |

> 💡 **别人的数据只能当参照系，不能当答案。外面的一切数据，都只能帮你初步构建一个模糊的认知。一切以你自己的实际为准。**

---

### 3.2 错误二：乐观预期 — 用愿望代替计算

**表现**：

```text
"我们团队执行力强，转化率肯定能做到行业最高的5%以上。"
"我们的产品体验比竞品好，退费率肯定比行业平均水平低。"
"这个渠道我们还没测，但理论上应该能跑通。"
```

**为什么危险**：

```text
如果每个关键项都按乐观值算：
  转化率取上限 + 客单价取上限 + 获客成本取下限 + 退款率取下限 = 看起来很美的模型

但现实是：
  五个乐观假设同时成立的概率 ≈ 3%
```

> 📌 一堂内部案例：三江源公益项目，比较高的数据带进去，整体都是亏损的；孵化器送《最佳实践》获客，比较高的数据都带进去，整体都是不值得的；某XX渠道内容获客，需要Truman持续投入时间，就算做成了，整体ROI都是负的。

---

### 3.3 错误三：缺少统计意义 — 只取单点值

**表现**：

```text
"我们的获客成本大概就是80块。"
"转化率差不多5%。"
"毛利大概40%左右。"
```

**三种取单点值的危险姿势**：

| 取法 | 风险 |
|------|------|
| 取了一个偏乐观的数字 → 将来轻松一点 | 容易主观乐观，承受很大风险 |
| 取了一个偏中间数字 → 这个平均值总安全吧 | 容易忽视变化，忽视后面实验 |
| 取了一个区间定量值 → 未来真实数字在这个范畴抖动 | 我还不知道，持续假设驱动 ← **正确姿势** |

> 💡 **区间定量才是科学的态度。** 你的模型里没有一个数字是100%确定的——每个数字都应该是一个区间。承认不确定性，才是真正理解这个业务。

## 五、环节一：建模 — 校对数据模型

> 解决「准不准」的问题：我的数值是不是真实可信？

### 5.1 关键策略1：用确定性的项，去倒推不确定项

**核心逻辑**：

```text
你永远有一些项是相对确定的（如当地销售人员工资），
有一些项是高度不确定的（如线索成本）。

不要两个都不确定的情况下互相猜。
先锁定确定性高的项，用它反推不确定项的上限。
```

**徐剑·To B SaaS经典案例**：

```text
场景：税控盘托管服务器SaaS，两类关键成本高度不确定：
  - 线索成本（投放获客）= ？
  - 销售成本（人员工资）= ？

策略：
  销售成本确定性更高：
    南京地区一个销售平均月工资 ≈ 8000元
    → 一个销售必须每个月至少贡献8000元毛利才能留下来

  先假定销售成本 = 8000（确定性高）
  → 倒推：线索成本必须控制在 X 元以内，单客户才不会亏

从财务口径（收入=成本）：
  → 倒推出线索成本上限 = 561元
  → 只要一个成交客户的线索成本 < 561，就可以做

从现金流口径（现金流入/现金流出 > 85%）：
  → 倒推出线索成本上限 = 219元
  → 因为硬件采购是一次性支出可用三年，现金流要求更严格
```

> 💡 **当你面对多个不确定变量时，先找到相对确定的那个锚点，用它锁定其他变量的边界。** 这就像在黑暗里找路——先摸到一面确定的墙，再沿墙走。

---

### 5.2 关键策略2：用科学类比+调研，做交叉验证

**核心原则：多角度交叉验证——用不同方法算同一个数字，如果结果接近一个区间，可信度就高。**

#### 5.2.1 方法一：科学类比（三步走）

```text
第一步：找关键要素——找到影响指标高低的3-5个关键要素
第二步：排要素顺序——确定这几个要素的占比或优先级
第三步：做区间定量——找到不同要素组合参考值，综合拿到你的区间定量
```

**实战案例：在线编程教育的获客成本估算**

```text
第一步：找关键要素
  影响获客成本的关键要素：竞争、投放规模、客户群体、付费意愿、品牌

第二步：对不同参照物做排序调整
  头部编程选手（品牌强、规模大）：200-300
    → 我品牌和规模差一些，获客成本应该更高
  初创美术赛道选手（无品牌、小规模）：300-400
    → 我的付费意愿高一些，但竞争强一些，成本可能更高
  K12英语初创公司（少儿群体、无品牌）：300-500
    → 我竞争弱一些，付费意愿弱一些，成本可能更高

第三步：综合拿到区间定量
  → 推测我的基准值大致在 300-600
```

#### 5.2.2 方法二：拆转化漏斗

> **预测一个模糊的大数字很难，就尝试把它拆成一个转化率公式。**

```text
漫展收入 = 人流量(A) × 进店率(B) × 选货率(C) × 选货付费率(D) × 平均数量(E) × 平均单价(F)

拆成转化漏斗后，每个环节的转化率相对更容易估算，
因为你可能有过往经验值、行业常识或类似场景的参考。
```

**徐剑·SaaS案例：拆解线索成本的转化漏斗**

```text
一个客户从看到投流广告到成交付款：

客户留资（获得线索）           ：一个留资费用 60-80元
客户同意加微信                 ：转化率 70%
客户愿意参加线上沙龙会          ：转化率 60%
客户来咨询商务                 ：转化率 80%
签订合同付款                   ：转化率 90%

倒推回去算出一个线索成本数据，和用销售成本倒推出的数值X交叉验证，
基本相差不大 → 得出一个区间范围 → 完成了相对准确的预估。
```

### 5.3 关键策略3：区间定量 + 三点预测

> **借鉴严格财务预测思想，建议做三点预测，而不是一个单点值。**

```text
┌─────────────────────────────────────────────────────┐
│                三点预测法                              │
├──────────┬──────────────────┬───────────────────────┤
│  版本    │      用途         │        含义            │
├──────────┼──────────────────┼───────────────────────┤
│ 乐观值   │ 斧子：用来早期    │ 较好的情况发生——        │
│          │ 证伪，直接砍掉    │ 如果这个版本都跑不通，   │
│          │ 这版模型          │ 那就不用干了             │
├──────────┼──────────────────┼───────────────────────┤
│ 合理值   │ 尺子：用来平时    │ 平均的情况——             │
│          │ 管理业务          │ 用得最多，用来日常管理    │
├──────────┼──────────────────┼───────────────────────┤
│ 悲观值   │ 梯子：用来控      │ 较差的情况——             │
│          │ 下限，管理生存     │ 成本敏感/资源少时尤其    │
│          │ 风险              │ 需要关注                 │
└──────────┴──────────────────┴───────────────────────┘
```

**短视频剪辑教育案例（三点预测实操）**：

| 指标 | 第一版（拍脑袋） | 乐观版 | 悲观版 | 基准参考区间 |
|------|:---:|:---:|:---:|------|
| 首单收入 | 100 | 120 | 85 | 成人教育首单定价1500-2500 |
| 体验课Leads成本 | 55 | 50 | 70 | 短视频成人教育获客成本50-80 |
| 销售成本 | 5 | 4 | 8 | 底薪+提成，1个销售带800-1000学员 |
| 体验课履约成本 | 8.5 | 8.5 | 8.5 | 讲师提成+班级运营 |
| 正价课履约成本 | 8 | 8 | 8 | 1个班主任带200-400学员 |
| 正价课退费 | 10 | 9.6 | 10.2 | 退费率通常在8%-12% |
| **净利** | **13.5** | **39.9** | **-19.7** | 通常>25可以考虑继续做 |

> 📌 三点预测的意义：**不是让你猜得更准，而是让你看见风险的全貌。** 乐观版赚40、悲观版亏20，你才知道自己的安全边际在哪里。

## 六、环节二：判断 — 模型通不通

> 解决「通不通」的问题：有了基准值，如何判断单元模型成不成立？

### 6.1 关键策略1：乐观证伪法

```text
「咱们先按比较理想的情况估算一下试试看？」

策略：所有数据用偏好的版本带入——成本偏低、价值偏高。
如果连这个偏乐观的版本都跑不通，那就不用干了。
```

**核心逻辑**：

```text
乐观证伪法是一个"必要非充分"的条件：
  - 乐观值跑通了 → 没什么，只是必要条件，还需要继续验证
  - 乐观值都跑不通 → 直接砍掉，不用再想了
```

**一堂内部真实案例**：

| 项目 | 乐观值测算结果 | 决策 |
|------|-------------|------|
| 三江源公益项目 | 比较高的数据带进去，整体亏损 | ❌ 砍掉 |
| 孵化器送《最佳实践》获客 | 比较高的数据带进去，不值得 | ❌ 砍掉 |
| 某XX渠道内容获客（需CEO持续投入时间） | 就算做成了，ROI也是负的 | ❌ 砍掉 |

> 💡 **「先在黑板上成功，再在现实里成功。」** — 一堂出现过几十上百次这种快速ROI沟通，用乐观值先筛一轮，大量不靠谱的想法在这一步就被砍掉了。

---

### 6.2 关键策略2：两口径验证

**徐剑·SaaS案例的两种计算口径**：

```text
财务口径（利润表口径）：
  收入 = 成本 → 业务就可以做
  倒推线索成本 ≤ 561元

现金流口径：
  现金流入 / 现金流出 > 85%
  倒推线索成本 ≤ 219元

为什么两个口径差了一倍多？
  → 财务口径允许硬件成本三年摊销
  → 现金流口径要求更快回本，因为硬件采购一次性付清

两种口径都要算，因为：
  财务口径告诉你「最终赚不赚钱」
  现金流口径告诉你「能不能活到赚钱那天」
```

### 6.3 关键策略3：单模型→多模型联算

> **不是算完一个核心模型就结束了。要联算——一个模型跑通了，还要看另一个模型是否同时成立。**

**徐剑案例的联算顺序**：

```text
Step 1：单客户首单模型
  → 交叉验证后，线索成本区间 = 200-300元
  → 取中间值250元
  → 结论：单客户模型跑通

Step 2：单客户LTV模型（三年）
  → 代入线索成本250元
  → 结论：单客户三年盈利3945元
  → 规模化复制客户的疑虑解决了

Step 3：单销售模型
  → 一个销售月薪8000元
  → 倒推：一个月至少成11单客户，销售才能养活自己
  → 设定基准：一个月成交10单 = 模型跑通
  → 按最悲观情况反向验证（每个客户只买1台），仍然成立
  → 结论：可以批量复制销售
```

> 💡 **多个模型同时成立，才能叫「模型跑通」。** 单客户模型赚钱但销售养不活自己 = 无法复制 = 模型没跑通。

## 七、环节三：迭代 — 努力做优化

> 解决「如何调」的问题：模型初步跑通了，但怎么让它更好？

### 7.1 核心原则

```text
跑通是偶然，迭代才是必然。

商业模式不是拍脑袋定出来的，而是调出来的。
一个业务早期犯错误太正常了。
区别在于：有些人一直不看数据，后知后觉，钱烧光了才发现问题；
有些人持续用单元模型测量，快速调整。
```

### 7.2 找到关键指标

> **关键指标 = 在收入成本里占比高、优化空间大、是竞争胜负手的那个变量。**

```text
徐剑案例的关键指标：
  ① 线索成本及转化率（占比高、优化空间大）
  ② 销售月成单量（直接决定单销售模型能否跑通）
```

### 7.3 围绕关键指标做优化

**徐剑团队的优化动作**：

| 优化方向 | 具体动作 |
|----------|----------|
| 内容优化 | 优化线上沙龙内容 |
| 知识建设 | 营销知识库的建设 |
| 技术引入 | AI互动的技术引入 |
| 内容生产 | 提前预录制短视频 |
| 数据驱动 | 数据统计分析建模 |

**结果**：

```text
销售月成单量：提升到12单以上（从10单基准值）
线索转化率：稳定在30%左右（从25%基准值）
```

> 💡 **单元模型不仅仅是一个算账工具，更是确立关键业务动作的指路明灯。** 它告诉你：你的精力应该花在哪里，什么样的优化动作能带来最大的杠杆效应。

### 7.4 迭代中的认知升级：用模型捕捉外部变化

```text
徐剑案例的后续：
  国税总局全面升级"数电票"体系
  → 税控盘硬件加速退出历史舞台
  → 硬件采购成本这一项消失了
  → 收入项不受直接影响
  → 对业务是巨大利好

单元模型理解得透不透、用得好不好，
与能不能深度、快速判断业务变化，密切相关。
如果你把模型算透了，政策一变化，
你能第一时间算出影响并做出反应。
```

## 九、完整实战案例：徐剑·To B SaaS发票托管

### 9.1 业务背景

```text
公司：数族科技
业务：发票托管SaaS
核心客户：代账公司、大集团公司财务部门
痛点：给几十上百户客户管理发票，效率低、易出错、管理成本高
```

### 9.2 从完整模型到找准基准值的全过程

```text
第一步：找全关键项（用列推建查）
  → 发现两个最关键的、占比最大的成本项：
    ① 线索成本（投放获客）
    ② 销售成本（人员工资）
  → 这两个值之前没有经验，行业也没有Benchmark
  → 其他关键项都有可参考的经验或Benchmark（如综合成本占收入5-6%）

第二步：建模（找准基准值）
  → 策略1：销售成本确定性更高（南京8000元/月）
    → 用销售成本倒推线索成本上限
  → 策略2：拆转化漏斗
    → 留资（60-80元）→ 加微信（70%）→ 沙龙（60%）→ 咨询（80%）→ 签约（90%）
    → 倒推线索成本，与策略1交叉验证
  → 确定线索成本区间：200-300元
  → 对应留资线索转化率需做到25%左右

第三步：判断（模型通不通）
  → 单客户首单模型（财务口径）：线索成本≤561元 → ✅
  → 单客户首单模型（现金流口径）：线索成本≤219元 → 以200-300元区间看，可行
  → 单客户LTV模型：三年盈利3945元 → ✅
  → 单销售模型：月成交10单即可养活自己 → ✅

第四步：迭代（持续优化）
  → 关键指标：线索成本及转化率、销售月成单量
  → 一系列优化动作后：月成单量→12单以上，线索转化率→30%
```

## 十三、L6 级别进阶认知

### 认知一：L4到L5的跨越，是从「算账的人」变成「做判断的人」

> 前面三节课（选模型、找全项、建完整模型）都在教你「怎么算」。这节课教你「怎么用算的结果做判断」。很多人卡在L4——账算得很全，但不敢下判断。L5的本质能力不是算得更准，而是**在不确定性中做出有依据的决策。**

### 认知二：乐观证伪法是最被低估的决策工具

> 创业者天然乐观，所以才需要「乐观证伪法」这种反人性的工具。它的价值不在于精确，而在于**用最低成本排除最糟糕的选项。** 一堂内部几十上百次用它砍掉项目——不是因为悲观，而是因为资源有限，必须把精力集中在真正值得做的事上。

### 认知三：区间思维是科学商业判断的分水岭

> 「这个数字大概是80」和「这个数字在50-120之间」，看起来差不多，但代表完全不同的思维模式。前者假装知道答案，后者承认不确定性。**区间定量不是为了更准确——是为了让你看见风险的全貌，并为之做准备。** 悲观值亏20、乐观值赚40，你才知道自己能不能扛住最坏的情况。

### 认知四：单元模型的终极价值不是记账，而是指导行动

> 很多创业者把单元模型当成「给投资人看的账本」。但徐剑的案例告诉我们：单元模型的真正价值在于**确立关键业务动作的指路明灯**——线索成本高就去优化转化漏斗，销售人效低就去优化销售动作。**算账的终点不是数字，而是下一步该做什么。**

### 认知五：基准值不是找来的，是调出来的

> 「别人的数据是假的，行业基准值是假的。」这句话不是让你不信任何外部数据，而是提醒你：**所有外部数据都只是你构建初始假设的素材，真正属于你的基准值，是在你自己的业务里一轮一轮测出来、调出来的。** 这就是为什么迭代比建模更重要——跑通是偶然，迭代才是必然。

## 十四、行动建议

| 层级 | 行动 |
|------|------|
| **基础** | 选你当前最核心的一个单元模型，把每个关键变量都标注当前置信度（高/中/低）。对低置信度的变量，用「确定项倒推不确定项」或「拆转化漏斗」重新估算。做完后，你是否发现某些之前「确定」的数字其实并不确定？ |
| **进阶** | 用三点预测法（乐观/合理/悲观）重做你的核心单元模型。看看乐观值下的利润和悲观值下的亏损差距有多大。问自己：悲观值发生，你能扛多久？ |
| **高阶** | 像徐剑一样，把你的多个核心单元模型联算一遍（单客户→单客户LTV→单销售）。是否有模型A跑通但模型B跑不通的情况？跑不通的那个，就是你下一步最重要的优化方向。同时，把你行业的3-5个关键基准值贡献到一堂基准值共建库，帮助后来的创业者少走弯路。 |

> 📌 **最后提醒**：单元模型系列五节课，这节课是「修成正果」的一步。前面三节教你建模型，这一节教你用模型做判断。如果你的账已经算全了但还不敢拍板——**把乐观值带进去跑一遍，如果连乐观值都跑不通，那就果断砍掉；如果乐观值跑通了，再用合理值和悲观值找到你的安全边际。** 记住：斧子、尺子、梯子。先在黑板上成功，再在现实里成功。

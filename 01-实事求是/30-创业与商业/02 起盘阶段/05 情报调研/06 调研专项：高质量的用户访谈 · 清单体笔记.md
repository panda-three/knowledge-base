# 调研专项：高质量的用户访谈 · 清单体笔记

---

## 一、课程定位与价值

**课程定位**：一堂调研模块实操课，与《高质量的专家访谈》并列调研专项双核心，交付模型为「用户访谈五步法 + 对应步骤技巧清单」。

**一句话内核**：
- 创业早期，洞察用户需求极其重要——它决定了你的产品质量，也决定了你各项业务决策的质量。但**多数公司执行都不够，甚至差到吓人**

**课程背景数据**：
| 维度 | 数据 |
|---|---|
| 讲师 | Truman，一堂 CEO |
| 推荐学习对象 | 访谈工作做得比较少，但希望全面深刻了解用户的人 |
| 学习 Candy | 《提升设计问卷的技能》 |
| 课程姊妹篇 | 《调研专项：高质量的专家访谈》（专家访谈黄金十步法） |

**这节课回答的四个核心问题**：
- **谁**才是你该持续关注的用户？
- 一个**合格的**用户访谈该怎么做？
- 用户画像该如何**设计**？
- 为什么总有人说用户调研**不可信**？

## 二、核心认知：用户访谈的底层原则

### 2.1 用户访谈 vs 专家访谈——定位区分

| 维度 | 用户访谈 | 专家访谈 |
|---|---|---|
| **访谈对象** | 产品的真实/潜在使用者 | 行业专家、资深从业者、投资人 |
| **核心目标** | 理解需求、验证假设、发现问题 | 获取行业认知、判断规律、交叉验证 |
| **交付模型** | 用户访谈五步法 | 专家访谈黄金十步法 |
| **典型误区** | 用户说什么就信什么 | 把专家当神、只访不谈 |
| **能力侧重** | 共情力 + 提问力 + 观察力 | 判断力 + 连接力 + 深挖力 |

### 2.2 五句核心心法（与专家访谈一脉相承）

- 不是交个朋友，而是**价值交换**
- 不是收集观点，而是**收集事实**
- 不是调研问题，而是**验证假设**
- 不是辩论比赛，而是**深入探讨**
- **不是单向采访，而是双向互动**

### 2.3 用户访谈的「一体两面」

- 访谈做得好 = 用最短时间拿到最真实的用户需求
- 访谈做得差 = 被用户带跑偏、拿到虚假需求、浪费资源做错产品
- 核心：**带着假设去验证，而不是带着空白去收集**

## 三、第一关：谁才是你该访谈的用户

### 3.1 用户分层——不是所有用户都值得深访

| 用户类型 | 特征 | 访谈优先级 |
|---|---|---|
| **核心用户** | 高频使用、深度依赖、痛点明确 | ⭐⭐⭐ 最高 |
| **边缘用户** | 偶尔使用、可替代性强 | ⭐⭐ 中 |
| **流失用户** | 曾经用过、已离开 | ⭐⭐⭐ 高（挖原因） |
| **潜在用户** | 尚未使用但属于目标人群 | ⭐⭐ 中（验证假设） |
| **非目标用户** | 不属于目标人群 | ❌ 不访 |

**关键动作**：
- 先定义目标用户画像，再筛选访谈对象——**不要谁有空访谁**
- 早期创业优先访核心用户和流失用户——一个告诉你要做什么，一个告诉你做错了什么

### 3.2 找到用户的四个渠道

| 渠道 | 方法 | 适用场景 |
|---|---|---|
| **自有触达** | 产品内推送、社群邀请、客服列表 | 已有产品/种子用户 |
| **社交搜索** | 朋友圈、微信群、微博、小红书搜索关键词 | 找到在讨论相关问题的真实用户 |
| **线下场景** | 门店蹲点、活动现场、行业展会 | 消费品/本地服务 |
| **用户转介绍** | 让已访谈用户推荐 1-2 个同类用户 | 滚雪球式扩展样本 |

**一堂经验**：早期没用户时，去用户「已经在抱怨问题的地方」蹲着（社交平台评论区、竞品用户群、相关论坛）——这是最低成本的找用户方式。

## 四、第二关：用户访谈五步法（核心交付）

```
Step1 ──→ Step2 ──→ Step3 ──→ Step4 ──→ Step5
明确目标   设计提纲   找到用户   执行访谈   分析验证
（为什么访）（问什么）（访谁）（怎么访）（访完怎么办）
```

### Step 1 · 明确目标：定义「为什么访谈」

**核心问题**：这次访谈，你要验证哪 1-3 个关键假设？

**三种典型访谈目标**：

| 目标类型 | 典型问题 | 适用阶段 |
|---|---|---|
| **探索需求** | 用户到底有什么痛点？痛点有多痛？现在怎么凑合解决的？ | 0→1 需求验证期 |
| **验证方案** | 我做的这个解决方式，用户愿不愿意用？愿不愿意付费？ | 方案验证期 |
| **优化体验** | 用户在哪一步卡住了？为什么流失？哪里体验最差？ | 产品迭代期 |

**常见错误**：
- 目标太散：一次访谈想覆盖 10 个问题 → 结果哪个都没聊透
- 目标太虚：「了解一下用户」不是目标——「验证用户在 XX 场景下的最大痛点是不是 YY」才是

**一堂做法**：每次访谈前写一句话——「这次访谈最主要想验证什么？」写完贴在眼前，全程不跑偏。

### Step 2 · 设计提纲：把「问什么」结构化

**提纲三要素**：

| 层次 | 内容 | 占比 |
|---|---|---|
| **开场·破冰** | 自我介绍、说明目的、建立信任、征得同意 | 10% |
| **主体·追问** | 围绕关键假设，分层递进提问 | 80% |
| **收尾·确认** | 反向总结、确认理解、留钩子、致谢 | 10% |

**提问的四种类型（按深浅递进）**：

| 类型 | 示例 | 何时用 |
|---|---|---|
| **事实型** | 「你上一次用 XX 是什么时候？用了多久？」 | 建立事实基线 |
| **行为型** | 「当时你是怎么做的？先点了哪里？」 | 还原真实场景 |
| **感受型** | 「那个时刻你什么感觉？着急吗？想骂人吗？」 | 挖情绪和痛点 |
| **假设型** | 「如果有个功能能帮你 XX，你会用吗？为什么？」 | 验证方案概念 |

**关键技巧**：
- 多问「上次是什么时候」——把用户从「我觉得」拉回「我做过」
- 少问「你会不会用」——用户嘴上说的和实际做的差距很大
- 追问「然后呢？」——这是最被低估的追问词

**一堂经验—提纲设计 Checklist**：
- 每个假设至少对应 3 个不同角度的提问
- 避免「引导性问题」（"你是不是觉得 XX 很难用？"）
- 留足空白：提纲是地图，不是剧本——跟着用户走，而不是跟着提纲走

### Step 3 · 找到用户：连接 + 说服

**说服用户接受访谈的三个杠杆**：

| 杠杆 | 具体做法 | 效果 |
|---|---|---|
| **价值共鸣** | 「你之前提的反馈我们认真看了，想跟你深聊一下」 | ⭐⭐⭐ 最高 |
| **利益交换** | 红包/优惠券/会员/优先体验权 | ⭐⭐ 中等 |
| **关系借力** | 朋友介绍、社群 KOL 推荐 | ⭐⭐⭐ 高 |

**一堂经验**：
- 用「你的意见对我们很重要」开头 → 转化率极低
- 用「你上次在 XX 提到的问题，我们很重视，想请你展开讲讲」开头 → 转化率翻倍
- 核心是让对方感到：**这不是普查，这是专门为你开的对话**

### Step 4 · 执行访谈：破冰 → 深挖 → 收尾

**① 破冰（前 3 分钟决定访谈质量）**

**核心任务**：快速建立平等对话、让对方放松、明确边界。

**破冰三动作**：

| 动作 | 具体做法 | 话术参考 |
|---|---|---|
| **同步目标** | 一句话说清今天聊什么、多久、给什么回报 | 「今天主要想了解你在 XX 场景下的体验，大约 30 分钟」 |
| **降低压力** | 明确「没有对错、只是想了解你的真实感受」 | 「你说什么都是对的，我们就是想听真实情况」 |
| **建立信任** | 用对方之前的行为/反馈做引子，证明「我了解你」 | 「看到了你在 XX 上的留言，感觉你对这块很有思考」 |

**一堂经验—破冰避坑**：
- 不要说「我们做个用户调研」——太官方，对方会进入「被审问」模式
- 要说「想请你帮我们看看这个方向对不对」——把对方定位成「顾问」而非「被试」

**② 主体深挖（访谈的核心 80%）**

**深挖四原则**：

| 原则 | 说明 | 反面 |
|---|---|---|
| **追事实，不追观点** | 「上次你怎么做的？」＞「你觉得怎么样？」 | 收集了一堆观点，无从验证 |
| **追细节，不追概括** | 「打开 APP 后第一眼看什么？手指先点哪里？」 | 「我一般就是刷刷」——没信息量 |
| **追反例，不追认同** | 「有没有哪次你觉得特别不好用？」 | 用户出于礼貌只说好话 |
| **追沉默，不追热闹** | 用户停顿、犹豫、叹气的地方，追问一句「怎么了」 | 错过真正的情绪信号 |

**五类高频追问词**（一堂提炼）：

| 追问词 | 用途 | 示例 |
|---|---|---|
| 「然后呢？」 | 延续叙述 | 「打开 APP → 然后呢？」 |
| 「举个例子？」 | 从抽象拉回具体 | 「你说'不好用'→ 举个例子？」 |
| 「上次是什么时候？」 | 锁定真实事件 | 「最近一次是上周三…」 |
| 「还有呢？」 | 榨干信息 | 「除了这个，还有别的吗？」 |
| 「为什么？」 | 深挖原因（慎用，容易让对方防御） | 「为什么当时没继续往下走？」 |

**遇到四类难题的应对**：

| 难题 | 应对策略 |
|---|---|
| **对方过于发散** | 「你说的这点很有意思，我们稍微拉回来——刚才你说到 XX，那次具体发生了什么？」 |
| **对方回答太笼统** | 「能不能带我过一次你上次的具体操作？从打开 APP 开始，一步步说」 |
| **自己没听懂** | 不装懂。直接说：「这块我没太理解，能用更简单的方式再说一遍吗？」 |
| **问题太抽象对方接不住** | 先抛一个具体案例或场景：「比如像 XX 这种情况，你遇到过吗？」 |

**③ 收尾（最后 3 分钟，决定对方愿不愿意再来）**

**收尾三动作**：

| 动作 | 目的 | 话术参考 |
|---|---|---|
| **反向确认** | 确保你没理解错 | 「我总结一下，你说的最核心的三个痛点是……对吗？」 |
| **情绪价值** | 让对方觉得这段时间值得 | 「今天聊下来我收获特别大，你对 XX 的理解很深入」 |
| **留钩子** | 为后续联系埋线 | 「后续如果我们针对这个问题做了改进方案，能不能再请你帮我们看一眼？」 |

**一堂经验**：收尾时的反向确认不是走过场——很多关键误解在这一步暴露出来。用户说「不对，我不是那个意思」的瞬间，可能才是访谈中最有价值的信息。

### Step 5 · 分析验证：从单个访谈到规律提炼

**单次访谈后 24 小时内必做**：

| 动作 | 内容 |
|---|---|
| **整理记录** | 趁记忆新鲜，补齐笔记中的省略和速记 |
| **标注关键句** | 把最冲击、最意外、最反常识的 3-5 句话标出来 |
| **更新假设** | 这次访谈验证/推翻了什么？产生了什么新假设？ |

**交叉验证三层法**：

| 层次 | 做法 | 判断标准 |
|---|---|---|
| **层一·单用户一致性** | 同一用户前后说法是否一致 | 不一致 ≠ 用户说谎，可能是用户自己也在探索 |
| **层二·多用户交叉** | 3-5 个同类用户是否呈现相同模式 | 至少 3 个独立来源指向同一结论，才算有了初步判断 |
| **层三·行为验证** | 用户说的和实际做的对不对得上 | 用户说「我会付费」≠ 他真的会付费——看行为而非言语 |

**关键认知**：用户访谈不是统计调研——5 个深度访谈的洞察价值，远超 100 份问卷。但前提是：**每访完一个就迭代一次假设，下一个访谈带着更精准的问题去**。

## 五、第三关：用户画像该如何设计

### 5.1 用户画像的三个层次

| 层次 | 内容 | 获取方式 |
|---|---|---|
| **人口属性** | 年龄、性别、城市、职业、收入 | 问卷 / 产品数据 |
| **行为特征** | 使用频率、使用场景、替代方案、付费意愿 | 访谈 + 数据分析 |
| **心理动机** | 核心痛点、情感需求、身份认同、价值观 | **只能靠深访** |

**关键认知**：前两层靠数据和问卷就能拿到；第三层才是用户访谈不可替代的价值——**理解用户为什么做，而不只是做了什么**。

### 5.2 用户画像输出模板

```
【用户画像ID】: ____
【典型场景】: 什么时候、什么地点、什么状态下使用产品
【核心痛点】: 最让 TA 难受的一件事是什么？痛到多痛？
【现有替代方案】: 不用你的产品时，TA 怎么凑合的？
【关键一句话】: 用用户的原话描述 TA 的需求
【一个反常识】: 这个用户身上什么发现让你意外？
```

**一堂经验**：「关键一句话」必须是用户原话，不是你的翻译——用户说「我每次打开就头疼」，比你写「该用户有使用焦虑」的信息量大 10 倍。

## 六、第四关：为什么用户调研不可信——五大经典陷阱

### 6.1 陷阱全景图

| 陷阱 | 表现 | 破解 |
|---|---|---|
| **礼貌性说谎** | 用户不想让你失望，说「挺好的」「我会用的」 | 看行为不看语言；追问「上次什么时候用的」 |
| **回忆性偏差** | 用户记不清真实行为，自己脑补叙事 | 问最近一次具体事件，不问道理和总结 |
| **霍桑效应** | 被访谈时行为暂时改变，表现得比平时更积极 | 拉长观察周期，结合产品数据对照 |
| **样本偏差** | 愿意接受访谈的本身就是最活跃的用户 | 刻意找沉默用户、流失用户、边缘用户 |
| **访者偏差** | 访谈者无意识引导用户往自己期望的方向答 | 用开放式提问；每三个问题自查一次「我有没有在引导」 |

### 6.2 一堂的判断

- 用户调研不可信，**不是因为用户会说谎**，而是因为多数人把用户访谈做成了「收集用户对未来的承诺」
- 用户不会告诉你他们要什么——**但他们永远不会骗你他们现在怎么做的、上次怎么做的、刚才怎么做的**
- 结论：**信行为，不信承诺；信过去，不信未来；信细节，不信概括**

## 七、85 分用户访谈执行策略

### 7.1 等级标准

| 分数 | 标准 | 典型表现 |
|---|---|---|
| **60 分及格** | 不跑偏、拿回有用信息 | 访谈结构完整，关键假设有初步答案 |
| **75 分良好** | 有深挖、有意外发现 | 用户说了「之前没想过的问题」，访谈者收获了反常识 |
| **85 分优秀** | 双向激发、用户有收获 | 用户说「和你聊完我也想了很多」，访谈成为一次有价值的对话 |
| **95 分顶级** | 一次到位、直接产出 | 访谈结束即形成可落地的用户洞察文档，无需二次补充 |

### 7.2 从 60 分到 85 分的三个关键升级

**① 从「收集信息」升级到「验证假设」**
- 60 分：带着空白去，用户说什么记什么
- 85 分：带着 3 个关键假设去，每个提问都在逼近或推翻假设

**② 从「单向采访」升级到「双向对话」**
- 60 分：像记者一样提问，用户被动回答
- 85 分：营造平等探讨氛围，用户愿意主动说「你等等，我再想想」

**③ 从「访完即结束」升级到「访完即迭代」**
- 60 分：访谈结束 → 记录归档 → 下次重新开始
- 85 分：每访完一个 → 立即更新假设 → 下一个访谈带着更尖锐的问题去

### 7.3 一堂内部用户访谈自检清单

```
□ 访谈前：是否明确了 1-3 个关键假设？
□ 访谈前：提纲是否覆盖了事实型/行为型/感受型/假设型四种提问？
□ 开场3分钟：是否成功让对方放松、建立了平等对话？
□ 访谈中：是否追问了至少 5 次「举个例子？」「然后呢？」
□ 访谈中：是否捕捉到了用户停顿/犹豫/叹气的瞬间并追问？
□ 访谈中：是否避免了引导性提问？（检查「你是不是觉得…」句式）
□ 收尾3分钟：是否做了反向确认？
□ 收尾3分钟：对方是否表达了「今天聊得挺有收获」？
□ 访谈后24小时：是否标注了最冲击的 3-5 句话？
□ 访谈后24小时：假设是否被更新？
```

## 八、总结收口

**六句总结**：

1. **用户访谈的本质是验证假设，不是收集信息**——带着关键假设去，带着更新后的假设回来
2. **五步法闭环**：明确目标 → 设计提纲 → 找到用户 → 执行访谈 → 分析验证，每一步都决定最终质量
3. **追问是区分 60 分和 85 分的分水岭**——「举个例子？」「然后呢？」「上次什么时候？」三句话价值千金
4. **信行为不信承诺，信过去不信未来，信细节不信概括**——这是用户调研可信与不可信的分界线
5. **5 个深度访谈 > 100 份问卷**——前提是每访完一个就迭代一次假设
6. **双向互动才是最高境界**——当用户说「和你聊完我也有很多收获」时，你才真正拿到了深层信息

- 选定一个你正在做的产品/业务，明确一个最需要验证的关键假设

- 访完后对比：你的假设被验证了什么？被推翻了什么？最意外的是什么？

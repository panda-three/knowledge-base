# 低成本验证实操3：系统测试篇 — L6 清单体笔记

---

## 一、课程定位与核心金句

> **「试错和错误才是常态，验证跑通才是偶然。」**

> **「一轮轮漫长的试错学习和建立信心，才是成熟一号位做业务的常态。」**

> **「早期追求糙快猛，避免『过早固化』，留给自己足够多的『试错空间』，然后不断『螺旋上升』。」**

> **「精益创业的本质就两个字：概率。承认九死一生，努力预判风险，用极低成本的失败去无限降低系统性失败的风险。」**

> **「回顾一堂这几年，我应该没有犯过大的错误，没有造成大的创业浪费，背后依赖的就是这节课的能力。」**

> **「敬畏概率，分析概率，征服概率。」**

**课程在低成本验证系列中的位置**：

```text
低成本验证系列 · 全景地图：
  全员必修：低成本验证认知篇（认知入门）
    → 低成本验证实操1：剥离假设篇（核心实操·上）
      → 低成本验证实操2：MVP设计篇（核心实操·中）
        → 低成本验证实操3：系统测试篇（核心实操·下）← 本节课
```

**本节段位目标**：从 **L4（懂聪明MVP）** 提升到 **L5（会系统测试）**——面对大量关键假设时，能设计多轮MVP组合测试方案，真正实现小步快跑、螺旋上升。

**一句话交付模型**：**系统测试三大范式（灰度测试/组合测试/里程碑测试）+ 六种判断方式 + 阶梯螺旋上升曲线。** 帮你从「会设计单一MVP」到「会组织多轮MVP系统测试」。

**推荐谁学**：已经掌握FALSE模型、能独立设计单一MVP，但面对复杂项目的大量假设时，不知道「先测哪个、后测哪个、如何组合、怎么判断可以进入下一轮」。如果你总感觉「测了一堆但不知道整体进度如何」，这节课就是你的必修课。

## 二、预热思考 · 三连问

| # | 问题 | 用意 |
|---|------|------|
| 1 | 假设你是一名创二代，家里有工厂给知名品牌代工电器。你想自立品牌做一款创新空气炸锅，有50万启动资金和工厂资源。这个项目成功的概率有多大？你会如何科学地、系统地设计精益验证计划？一步步怎么测、怎么推进？ | 逼出「系统测试」的全盘推演能力——不是一个MVP，是一组MVP的排列组合 |
| 2 | 做一轮MVP就全部成功，在真实商业世界往往不太现实。面对复杂项目背后的大量假设，想到什么就测什么，和设计一个系统的MVP测试计划，差别到底有多大？ | 检验你对「系统测试」和「随机测试」底层差异的理解 |
| 3 | 你如何评估上一个MVP测试「过了」可以进入下一轮？是看客观数据，还是凭主观感觉？如果早期样本量不够、数据不准，你怎么下这个判断？ | 暴露「上升节点判断标准缺失」这个核心痛点 |

## 三、核心认知：为什么需要系统测试

### 3.1 从「单一MVP」到「系统测试」的认知跃迁

```text
┌─────────────────────────────────────────────────────────┐
│         单一MVP vs 系统测试                                │
├────────────────────┬────────────────────────────────────┤
│     单一MVP         │          系统测试                    │
├────────────────────┼────────────────────────────────────┤
│ 面对1-3个关键假设   │ 面对大量关键假设（10-30个）           │
│ 做一轮测试拿认知    │ 需要多轮测试组合推进                  │
│ 测试后或证伪或继续  │ 每一轮是上一轮的认知基础               │
│ 适合简单项目       │ 适合复杂、高风险、长期项目             │
│ L3-L4的能力        │ L5的核心能力                         │
└────────────────────┴────────────────────────────────────┘
```

### 3.2 Truman的试错曲线升级

```text
第一版认知（《认知篇》的图）：
  「试错和错误才是常态，验证跑通才是偶然」
  → 这张图把Truman从理想拉到了现实

第二版认知（本节升级版）：
  稍微复杂/长期/创新一些的业务，
  把试错曲线从宏观拆解成微观步骤，
  会发现业务是一轮轮试错、阶梯螺旋上升的。

  不是一个简单的「试错→失败→再试错→成功」，
  而是「测试1（拿到认知A）→ 测试2（基于认知A验证B）
  → 测试3（基于A+B验证C）→ 逐步建立信心 → 螺旋上升」。
```

### 3.3 核心原则：阶梯螺旋上升曲线

```text
┌───────────────────────────────────────────────────────────────┐
│              系统测试 · 阶梯螺旋上升曲线                          │
├───────────────────────────────────────────────────────────────┤
│                                                               │
│  解读1：X型曲线偏All-in式——                                    │
│    对于长周期高复杂度业务，一击即中做成的极少                      │
│                                                               │
│  解读2：进展可能不只看客观数据——                                 │
│    早期甚至只是主观的信心值增长                                  │
│                                                               │
│  解读3：随着业务发展，四个维度的显著不同——                        │
│    ①信心 ②认知深度 ③资源投入规模 ④灵活试错空间                  │
│    （早期信心低但试错空间大，后期信心高但试错空间小）               │
│                                                               │
│  解读4：这条曲线可以往下拆解——                                   │
│    业务一号位有自己的曲线，                                    │
│    每个子项目/子假设也各自有一条曲线                              │
│                                                               │
│  一句话核心原则：                                               │
│    早期追求糙快猛，避免「过早固化」，                             │
│    留给自己足够多的「试错空间」，然后不断「螺旋上升」。             │
│                                                               │
└───────────────────────────────────────────────────────────────┘
```

## 四、核心框架：系统测试三大范式

### 4.0 三大范式全景

> Truman和教研组搜集了数百个"取得成绩的MVP案例"，做了合并和爆炸式研究，发现大量案例背后，存在三个典型的MVP系统测试范式。

```text
┌───────────────────────────────────────────────────────────────┐
│              系统测试三大范式 · 全景                              │
├──────────┬──────────────────┬─────────────────────────────────┤
│   范式    │      核心视角      │           一句话定义              │
├──────────┼──────────────────┼─────────────────────────────────┤
│  范式一   │     成本视角       │ 从最小成本开始，一点点加资源，       │
│  灰度测试 │                  │ 逐步扩大测试范围                   │
├──────────┼──────────────────┼─────────────────────────────────┤
│  范式二   │     选项视角       │ 同时跑多个选项，通过对比找到         │
│  组合测试 │                  │ 最优方案——也叫「项目赛马」           │
├──────────┼──────────────────┼─────────────────────────────────┤
│  范式三   │     假设视角       │ 按五步法（需求→方案→商业模式        │
│ 里程碑测试│                  │ →增长→壁垒）顺序，一层层验证         │
└──────────┴──────────────────┴─────────────────────────────────┘
```

### 4.1 三大范式的关系

```text
三种范式不是互斥的——它们是不同视角下的系统测试策略。

同一个项目，可以在不同维度上同时使用不同范式：

整体上 → 用范式三（里程碑测试）：按五步法顺序，层层验证
某一层内 → 用范式二（组合测试）：多个选项赛马，选最优
某一选项内 → 用范式一（灰度测试）：从小到大，逐步放量

举例：某医疗硬件研发公司
  - 整体上是②项目赛马MVP（CEO负责，降低选项错的风险）
  - 单一项目是③里程碑测试（业务一号位负责，按五步法降低全盘推翻风险）
  - 项目内部的技术路线探索又是①灰度测试（技术Leader负责，降低重投入失败风险）

这就构成了一个三层嵌套的系统测试结构。
```

## 五、范式一：灰度测试 — 从成本视角出发

### 5.1 核心逻辑

> **「从最小成本开始，一点点加资源，逐步扩大测试范围。像放水一样，先开一点阀门，水流通了就再开大一点。」**

| 维度 | 内容 |
|------|------|
| **核心视角** | 成本：从低到高，逐步放量 |
| **一句话** | 先跑通最小闭环，再逐步扩大 |
| **适用场景** | 单一方案的风险不确定、需要逐步验证成本和效果 |
| **典型动作** | 小范围→中范围→大范围→全量 |

### 5.2 经典案例

| 案例 | 灰度测试路线 | 关键节点 |
|------|------------|----------|
| **陈先敏·现烤汉堡** | 借用朋友小店→测汉堡胚工艺→测口味→测堂食→测外卖→开简装店→开正式店 | 工艺过关→口味过关→复购过关→才开店 |
| **穆平·卤味连锁** | 手推车→菜鸟驿站试吃→8㎡联营档口（月租800）→标准门店 | 每个环节都有数据支撑才进入下一环节 |
| **何同学·萝卜干** | 天猫每天投放100块→500块→1000块→2000块 | 反复测试投放ROI，确认能回本才加量 |
| **杜同学·棋牌室** | 一家一家测试不同类型门店→测通再复制 | 测通一家再开下一家，不贪多 |
| **一堂早期** | 课程作业率/NPS从模糊到精准→从几百样本到上万样本 | 2020年只有模糊数据，2025年有精准Benchmark |

### 5.3 灰度测试的核心心法

```text
① 永远先跑通最小闭环
   → 不是「做一个简化版」，而是「最小成本验证最核心的假设」

② 每个灰度阶段都有明确的「通关标准」
   → 口味过关 = 内部+朋友+顾客都积极反馈
   → 复购过关 = 外卖平台复购率超过行业基准
   → 不通关，绝不进入下一阶段

③ 灰度不是无限慢——是「每一步都快，但每一步都有依据」
   → 不是拖延决策，而是加速认知获取
```

## 六、范式二：组合测试 — 从选项视角出发

### 6.1 核心逻辑

> **「同时跑多个选项，通过对比找到最优方案——也叫『项目赛马』。当你面对多个可能的方向，不确定哪个最优时，与其一个一个试，不如同时跑。」**

| 维度 | 内容 |
|------|------|
| **核心视角** | 选项：多方案并行，横向对比 |
| **一句话** | 不确定哪个最好？同时跑，比出来 |
| **适用场景** | 多个可选方案、不确定哪个方向最优 |
| **典型动作** | 多选项→并行测试→横向对比→选出最优→集中资源 |

### 6.2 经典案例

| 案例 | 组合测试方案 | 核心收获 |
|------|------------|----------|
| **内衣洗衣液** | 多管线并行：A线测功效（摆摊）→ B线测外包装（超市）→ C线测留香（实验室） | 三条线各自独立验证不同假设，互不干扰 |
| **线上思维课** | 课程大纲→一节课Demo→一个单元→整套课程 | 每个阶段积累认知，下一个阶段基于上一个阶段的验证结果 |
| **线上APP** | 公众号开发核心功能→APP 1.0版本→增加变现功能→完整开发 | 逐步叠加功能，每一层验证通过才加下一层 |
| **大馨·老年潮鞋** | 15种配色同时让200+用户投票→选出最优3种→小批量产测试 | 不是猜用户喜欢什么，是让用户用行为告诉你 |

### 6.3 组合测试的核心心法

```text
① 多选项并行测试的前提：每个选项的测试成本要足够低
   → 如果每个选项都要几十万，并行跑不起
   → 用FALSE模型把每个选项的测试成本压到最低

② 赛马的关键：对比标准要统一
   → 不是「A做得不错B也还行」，而是「A的转化率35%，B的转化率18%」
   → 定量 > 定性排名 > 主观判断

③ 赛马结束后要果断收缩
   → 选出最优方案后，把资源集中过去
   → 不要因为「舍不得」而同时在多个方向上分散资源
```

## 七、范式三：里程碑测试 — 从假设视角出发

### 7.1 核心逻辑

> **「按一堂五步法（需求→解决方案→商业模式→增长→壁垒）的顺序，一层层验证。每一步都是一个里程碑——前一步验证通过了，才进入下一步。这是最系统、最本质的假设验证路径。」**

| 维度 | 内容 |
|------|------|
| **核心视角** | 假设：按五步法顺序，层层递进 |
| **一句话** | 需求通了再测方案，方案通了再测模式，模式通了再测增长 |
| **适用场景** | 需要全局验证的新业务、高风险创新项目 |
| **典型动作** | 需求假设→方案假设→商业模式假设→增长假设→壁垒假设 |

### 7.2 里程碑测试的三层洋葱

```text
┌───────────────────────────────────────────────────────────────┐
│         里程碑测试 · 三层里程碑                                   │
├───────────────────────────────────────────────────────────────┤
│                                                               │
│  里程碑一：商业模式层 — 单元模型能跑通吗？                         │
│    验证内容：毛利覆盖成本？单客户+单销售模型同时成立？               │
│    通关信号：单元模型盈利、有信心支撑增长                         │
│    不通过的后果：整个业务无法持续 → 最优先验证                     │
│                                                               │
│  里程碑二：解决方案层 — 产品内核够Sharp吗？                        │
│    验证内容：关键转化率够好吗？用户愿意选择我吗？                    │
│    通关信号：转化率支撑商业模式、用户行为（非口头）验证通过          │
│    不通过的后果：有需求但方案不被接受 → 第二轮验证                  │
│                                                               │
│  里程碑三：需求层 — 需求够真够普遍够大吗？                          │
│    验证内容：拆推评算全部过关、多源交叉验证一致                     │
│    通关信号：有信心支撑解决方案（够真/够普遍/够大）                  │
│    不通过的后果：一切白费 → 最先验证、最严把关                     │
│                                                               │
│  验证顺序：需求 → 方案 → 商业模式 → 增长 → 壁垒                   │
│  剥离顺序：商业模式 ← 方案 ← 需求（由近及远剥）                    │
│                                                               │
└───────────────────────────────────────────────────────────────┘
```

### 7.3 里程碑测试的核心心法

```text
① 顺序不能乱
   → 需求没验证就做方案 → 大概率在错误的方向上优化
   → 方案没验证就做商业模式 → 拿着不对的产品去算账
   → 商业模式没验证就做增长 → 复制一个亏损模型（最大的悲剧）

② 每一个里程碑都有「不通过就回退」的可能
   → 不是「做到第五步才发现第一步错了」
   → 而是「第一步不过就停下来，避免后面四步的浪费」

③ 里程碑测试可以嵌套
   → 大的里程碑（需求→方案→商业模式）内，可以再拆小里程碑
   → 每个小里程碑内可以用灰度测试或组合测试
```

## 八、核心难题：如何判断「可以进入下一轮了」

> **这是Truman在课上专门停下来回答的核心实操难题。**

### 8.1 问题本质

```text
我怎么评估"口味不错"，可以开始测"定价"了？
我怎么评估"需求很疼"，可以开始测"内核"了？
我怎么评估"卖点够好"，可以开始测"投放"了？
我怎么评估"课程够好"，可以开始测"商业"了？

完美情况当然是严格精准的统计指标。
但早期多数时候，都是在局部的、信息不够的情况下做决策的。
总不能因为「评估不充分」就停下来，无限卡住吧。
```

### 8.2 六种判断方式（从轻到重，从早期到后期）

```text
┌───────────────────────────────────────────────────────────────┐
│         系统测试 · 六种判断方式（由轻到重）                        │
├──────┬──────────────────┬─────────────────────────────────────┤
│ 判断  │       方式        │              适用阶段                │
├──────┼──────────────────┼─────────────────────────────────────┤
│  1   │   主观信心        │ 最早期的方向判断——                     │
│      │  主观感受信心增减   │ 我自己的审美和判断力告诉我这个方向对吗    │
├──────┼──────────────────┼─────────────────────────────────────┤
│  2   │   定性反馈        │ 有了一些用户接触后——                   │
│      │  拿到客观的积极评价 │ 用户给了什么样的定性评价？             │
│      │                  │ "醍醐灌顶""比XX牛逼"这类评价            │
├──────┼──────────────────┼─────────────────────────────────────┤
│  3   │   定性排名        │ 有多个选项在比较时——                   │
│      │  在诸多选项里表现最好│ 不是绝对值高低，而是相对排名            │
│      │                  │ A方案明显比B/C/D好                    │
├──────┼──────────────────┼─────────────────────────────────────┤
│  4   │   订单突破        │ 开始有真实交易时——                     │
│      │  一个或一批订单    │ 不是"用户说好"，而是"用户付钱了"         │
│      │                  │ 哪怕只有一个订单，也是质的飞跃           │
├──────┼──────────────────┼─────────────────────────────────────┤
│  5   │   区间定量        │ 有一定样本量后——                      │
│      │  大概的定量数字范围 │ 不是精准数字，而是可信的区间范围         │
│      │                  │ "转化率大概在12-18%之间"              │
├──────┼──────────────────┼─────────────────────────────────────┤
│  6   │   定量评价        │ 业务成熟后——                          │
│      │  精准定量+Benchmark│ 有大量样本、有行业对标                │
│      │                  │ "作业率85%，续费率60%，NPS 75+"        │
└──────┴──────────────────┴─────────────────────────────────────┘
```

### 8.3 Truman的现身说法：一堂如何度过早期判断

```text
2025年的一堂：可以轻松给你"作业率"、"续费率"这类精准数据，
              有上万个样本，很精准的Benchmark。

但回到2020年：只有模模糊糊的"作业率"、"NPS"让我觉得内核不错。

再往前到2019年（真正测试构建内核的时期）：
  学习样本量只有几百上千，作业率NPS甚至样本都不够。

  那怎么决策呢？当时更多参考三个信息：
    ① 横向课程对比：跟过去交付的A+社分享比，活动/笔记/好评成倍增加
    ② 用户定性评价：一些资深学习型创业者给了大量"醍醐灌顶""比XX牛逼"的评价
    ③ 主观审美信心：Truman对于教育产品的见识和主观信心，觉得自己的课的确不错了

→ 从1（主观信心）→ 2（定性反馈）→ 3（定性排名）
  → 5（区间定量）→ 6（精准定量），业务就是这样一步步演化形成的。

如果5-6在早期无法达成，适当采用1-4也可以评估信心值，
完成业务节点的推进和进步。
```

### 8.4 判断方式的使用原则

```text
① 不要用后期的标准要求早期
   → 早期有几百个样本就不错了，别要求「p<0.05」
   → 用1-4的方式推进，同时积累数据往5-6走

② 但也不要用早期的主观判断替代后期的数据验证
   → 主观信心只是起点，不是终点
   → 随着投入加大，判断标准必须从1-2逐步升级到5-6

③ 判断方式是「叠加」的，不是「替换」的
   → 主观信心+定性反馈+定性排名同时存在
   → 越往后，定量数据的权重越大
```

## 九、汉堡店案例：三条路线的差异

### 9.1 背景

```text
疫情早期，陈先敏要做现烤汉堡。
品类快速增长，但所在城市的具体工艺、定价未知。
有200-500万启动资金（Max下牌桌资金），打算用4-8个季度起盘。

问题：面对多个假设（工艺/口味/SKU/定价/复购），怎么设计MVP测试顺序？
```

### 9.2 三条路线的对比

| 路线 | 具体做法 | 听起来 | 实际效果 |
|:----:|------|:------:|:------:|
| **路线1** | 设计口味→烤给朋友吃→摆摊→档口→小店→大店→连锁 | 聪明、科学、靠谱 | ❌ 过早固化，大量精力被筹备/开店消耗，高风险假设测试不足 |
| **路线2** | 加盟一家→自建品牌→外卖店→堂食店→连锁 | 借资源、省钱 | ❌ 同样过早固化，且加盟店的认知不一定可迁移 |
| **路线3** | 借朋友小店→测工艺→测口味→测堂食→测外卖→简装店→正式店 | 更聪明 | ✅ 没开店就专注产品内核，大量组合测试工艺和口味，70-80%已验证后才开店 |

### 9.3 路线3为什么明显更好

```text
不只是成本低。

而是在没有开店的情况下：
  ① 专注在产品内核（转化/复购）上
  ② 大量组合测试工艺和口味
  ③ 逐步建立业务信心
  ④ 70-80%的核心假设已验证通过后才正式开店

路线1和路线2的核心问题：
  ① 过早固化——很难灵活大量测试
  ② 早期大量精力被耗在筹备/开店上
  ③ 对于真正高风险的假设（真的好吃/好卖/复购好）测试远远不足
```

## 十五、L6 级别进阶认知

### 认知一：系统测试和单一MVP的本质区别——前者是「建系统」，后者是「做动作」

> 单一MVP验证的是「这个假设对不对」。系统测试验证的是「这个业务能不能成」——它不是N个MVP的简单叠加，而是一套有逻辑顺序、有判断标准、有进退机制的完整的认知获取系统。L4的人会设计一个聪明的MVP，L5的人会设计一组有逻辑关系的MVP序列。**从「做动作」到「建系统」，是第三次飞跃（系统飞跃）的核心。**

### 认知二：三大范式不是三选一，而是三维嵌套

> 很多人听完课会问：「我该用灰度测试、组合测试还是里程碑测试？」但真正的高阶用法是三层嵌套——公司CEO用组合测试赛马多个项目，每个项目的一号位用里程碑测试按五步法推进，每个里程碑内部用灰度测试从小到大放量。**这才是真实商业世界中系统测试的完整样貌。**

### 认知三：判断方式的六层递进，是科学精神的实操化

> 很多人卡在「数据不够不敢决策」和「没有数据也敢All-in」两个极端之间。六种判断方式（主观信心→定性反馈→定性排名→订单突破→区间定量→定量评价）的价值在于：**它给你一条从模糊到清晰的连续光谱。** 早期用主观判断推进不丢人——只要你知道这是「第1层判断」，并且随着投入加大会逐步升级到第5-6层。

### 认知四：螺旋上升的核心不是「上升」，而是「螺旋」

> 「上升」是结果——每个测试都会增加认知和信心。「螺旋」才是过程——你会走弯路、会回退、会发现之前以为验证过的假设其实没验证透。**接受螺旋，接受回退，接受「测了三轮又回到了原点但认知和上次完全不同」——这才是成熟的系统测试心态。**

### 认知五：概率三步曲是精益创业的哲学内核

> Truman在课程最后给出的「概率」二字，是整套精益方法论最深层的答案。敬畏概率——承认自己渺小；分析概率——用方法论预判风险；征服概率——用无数次极低成本的失败去换一次系统性的成功。**精益创业不是让你不失败，而是让你失败的代价小到可以承受、频率快到可以学习。** 这就是「命数」的真正含义。

# 《泛产品实操1：需求篇》L6 清单体笔记

> 定位：泛产品设计系列第三课｜实操第一课｜击穿三大自我修养之「永远以用户价值为中心」
> 核心命题：**用户价值，是所有商业、设计与服务的原点。大量的人有「用户思维」的口号，但没有「理解用户」的专业方法和刻意练习。这节课给你一套13张卡牌的专业工具箱，帮你把「理解用户」从玄学变成工程。**

### 1.2 为什么「理解用户」是第一实操课？

```text
在三大自我修养中，Truman 选择先击穿「理解用户」，
因为它是另外两个修养的前提：

没有理解用户 → 最佳实践对标的是「谁的最佳实践」？
没有理解用户 → 无限进步迭代的是「为谁迭代」？

需求错了，后面你再努力做产品、做品牌，都会事倍功半，很难救得回来；
需求歪了，后面你各种决策都会没有"定力"，左右摇摆；
需求泛了，后面你各种决策都可能没有支撑，大而全，效率很低；
需求变了，后面一旦发现重大误判，整个项目逻辑都得推翻重来。
```

### 1.3 与一堂五步法「需求分析」的关系

```text
一堂五步法的第一步是「需求分析」。
泛产品设计的需求篇，可以理解为「五步法需求分析」的泛化版本——
不只用于创业项目判断，而是用于任何产品设计场景的用户理解。

两者的底层逻辑完全一致：理解真实的客观问题。
但泛产品设计的需求篇应用场景更广：
从设计一张海报，到设计一场年会，到设计一个新业务。
```

## 二、底层理念：UCD——不只是一种方法，而是一种价值观

### 2.1 UCD 是什么？

```text
UCD = User-Centered Design（以用户为中心的设计）

Truman 在十几年前接触到这个理念，从此被深刻影响。

但 Truman 强调：
UCD 不只是一个设计思维、设计工具、设计规范，
而是一种做事的价值观。

价值观是一种重大选择，
是一群人的行动准则，
是你遇到重大挑战、分歧时候的评价依据。
```

### 2.2 价值观 vs 方法论

| 维度 | 方法论 | 价值观 |
|---|---|---|
| **本质** | 「做产品的时候要考虑用户」 | 「用户价值是判断一切对错的终极标准」 |
| **使用场景** | 在设计产品的时候想起来用 | 遇到任何分歧、冲突、两难时，第一反应是「用户会怎么想？」 |
| **持续周期** | 这个项目做完就结束了 | 10年、20年、30年不变的底层准则 |
| **典型案例** | 做个用户调研，然后继续按自己的想法做 | 团队争论两个方案时，不是谁官大听谁的，而是「哪个方案对用户价值更大？」 |

### 2.3 一个扎心的评审案例

Truman 在课上分享了一个内部磨课时的小故事：

```text
同学A，做了一个很完整的方案，找到一堂某合伙人B寻求支持。

B看完方案，直接问了一句话：
「你先别说方案，你到底想解决的问题是什么？」

B接着说：
「我有各种手段可以解决这类问题，
我们先别急，我们先把问题探讨清楚。」

结果发现：好好研究需求和问题，
往往只需要花原本方案成本10%的新手段，
就能拿到一个更好的解决方案。
```

> **L6 洞察**：这个案例完美展示了 UCD 价值观和普通工作习惯的区别——普通人拿到任务先想「怎么做」，UCD 价值观的人拿到任务先问「用户真正需要什么」。**这两个问题的答案可能差10倍成本。**

## 三、核心概念：JTBD——用户「雇用」产品来完成的任务

### 3.1 JTBD 是什么？

```text
JTBD = Jobs to be Done（待办任务）

核心定义：
需求不是关于产品本身，而是关于客户在特定环境下想要达成的进步（Progress）。

最经典的表述：
「人们不想买四分之一英寸的钻头，他们想要四分之一英寸的洞。」
```

### 3.2 JTBD 的核心逻辑

| 传统思维 | JTBD 思维 |
|---|---|
| 「用户想要什么功能？」 | 「用户在什么场景下，想要完成什么任务？」 |
| 「我们的产品有什么优点？」 | 「用户为什么『雇用』我们的产品？又为什么『解雇』它？」 |
| 「竞品做了什么功能，我们也做」 | 「用户用竞品完成什么任务？有没有完成得不够好的地方？」 |

### 3.3 一个重要的纠偏

```text
你可能听过一类说法：
"平庸的产品经理满足需求，顶级的产品经理创造需求。"
"乔布斯从来不调研用户，因为如果调研用户，他只会得到一匹更快的马，而不是一辆汽车。"

Truman 的判断：
这类话充满了流量和吸引眼球，
但从实事求是角度讲，存在典型的归因谬误和主观臆测。

以我有限的调研和观察，
乔布斯（Apple）、张小龙（腾讯）对于用户的理解和洞察是极其顶级和优秀的，
他们清楚地知道用户想要什么、以及背后的需求和底层规律。

他们只是不会傻到直接向用户"要现成的解决方案"而已。
```

> **L6 洞察**：「用户要一匹更快的马」——这恰恰说明用户有「更快到达目的地」的 JTBD。真正顶级的产品经理不会直接问用户要什么方案，而是从用户表达的「马」里，听出背后真正的任务：**「我想更快地从A点到B点」**。这个任务可以用马解决，也可以用汽车解决。关键是——你得先理解任务是什么。

## 四、硬剥离需求：商业分析的第一步基本功

### 4.1 为什么必须「剥离」？

```text
很多商业出现重大误判，往往就是「剥离不够」导致的。

需求客观存在，但产品方案是你的主观选择。
如果你把需求分析和方案设计混在一起，你就会——
用自己对方案的感情，来扭曲对需求的判断。
```

### 4.2 需求应该包含什么、不应该包含什么

| 需求应该包含（客观） | 需求不应该包含（主观） |
|---|---|
| 客户类型 | 你的定价 |
| 客户心态 | 你的产品 |
| 客户痛点 | 你的解决方案 |
| 客户已在用的产品 | 你的服务 |
| 客户的付费习惯 | 你的卖点 |
| 客户的决策链条 | 你的品牌 |

```text
关键区分：
需求侧的东西——客观存在在那里，跟你创不创业没什么关系。
方案侧的东西——是你可以选择、可以调整、可以不断推翻和重构的。
```

### 4.3 硬剥离的实操口诀

```text
先问：如果没有我的产品，这个用户/这群人，
在这个场景下，现在是怎么解决这个问题的？

如果现在的解决方案是「忍着」「将就着」「用很笨的方法」——
这就是需求存在的证据。

如果现在的解决方案是「已经有很好的产品在满足了」——
那你就要问：我的差异化在哪里？用户为什么愿意切换？
```

## 五、核心交付：13张「理解用户」官方卡牌全景

Truman 从36张卡牌中，将「理解用户」维度的全部13张牌逐一展开讲解：

### 5.1 卡牌矩阵

```text
                A. 小作品设计          B. 泛产品设计           C. 泛产品创新
               （短平快）            （重资源/多人协作）      （创新/没有对标）

  理解用户     用户视角              项目背景分析            行业模式画布
              用户分层              多视角思考              一堂五步法
              需求挖掘              峰终定律                拆推评算
              场景推演              惊喜公式                产品核心价值要素
              动力阻力
```

| 级别 | 卡牌数量 | 核心逻辑 | 典型场景 |
|---|---|---|---|
| **A. 小作品设计** | 5张 | 快速理解单一用户群的需求 | 一张海报、一封邮件、一个工位 |
| **B. 泛产品设计** | 4张 | 系统理解多用户群、多触点的需求 | 一个直播间、一场年会、一套课程 |
| **C. 泛产品创新** | 4张 | 全局理解市场需求结构和商业机会 | 新业务探索、0到1产品、无人区创新 |

### 5.2 出牌使用指南：三个真实案例推演

Truman 用三个真实同学的案例，带着大家逐一解读每张卡牌的含义和使用方法，完整推演了每个案例的出牌逻辑：

**案例一：小作品级别——设计一张海报**

```text
场景：公司有一个面向潜在客户的产品宣讲活动，老板让你设计一张海报。

无意识的做法：打开Canva/PPT，找一个好看的模板，把信息填进去。

出牌做法：
① 用户视角：拿到这张海报的人是谁？他在什么场景下看到？（刷朋友圈？在电梯里？在群里被转发？）
② 场景推演：他看到海报的第一眼是什么感受？3秒内能抓住什么信息？有没有动力扫码？
③ 需求挖掘：他为什么要来参加这个宣讲？是「想学习」还是「想找合作机会」还是「被老板要求来的」？
④ 动力阻力：什么会让他想来？（嘉宾牛？内容干货？免费？）什么会让他犹豫？（时间？不信任？觉得是广告？）
```

**案例二：泛产品级别——组织一场30人内训**

```text
场景：老板让你组织一场公司30人的内训，有来自各个部门的负责人和员工。

出牌做法：
① 用户分层：高管要什么？（战略对齐）中层要什么？（管理工具）一线要什么？（实操技巧）
② 峰终定律：峰值体验设计在哪？（开场的震撼？某个案例的顿悟时刻？）终值体验设计在哪？（结营仪式？后续行动计划？）
③ 惊喜公式：什么会让参与者觉得「超出预期」？（一个意外的嘉宾？一个定制化的诊断报告？一个后续的跟进机制？）
④ 动力阻力：不同层级的人来参训的动力和阻力分别是什么？如何放大动力、减小阻力？
```

**案例三：泛产品创新级别——探索一个创新的会员产品**

```text
场景：老板让你探索一个创新的面向客户的会员产品。

出牌做法：
L3级出牌（先做全局产品决策）：
① 行业模式画布：这个行业的用户需求分布是怎样的？有没有被忽视的细分市场？
② 一堂五步法：需求-解决方案-商业模式-增长-壁垒，全链条预判
③ 拆推评算：拆解竞品的会员体系→推演它们的逻辑→评估差距和机会→算清ROI

然后拆成独立项目，按L2出牌：
④ 项目背景分析+多视角思考：不同用户群分别需要什么？

最后在具体触点，按L1出牌：
⑤ 场景推演+动力阻力：用户在什么场景下最可能付费？什么在阻碍他们？
```

> **L6 洞察**：注意出牌的逻辑不是「随机选几张牌」，而是**「从高层级逐步细化到低层级」**。不要试图用L1的场景推演去回答L3的行业模式问题，也不要用L3的五步法去设计L1的一个按钮文案。**每个维度，有每个维度的主要矛盾。**

## 六、A级卡牌逐一击穿：小作品设计·理解用户（5张）

### 6.1 用户视角

| 要素 | 内容 |
|---|---|
| **一句话** | 瞬间代入用户角色——「如果我是用户，我看到这个的第一反应是什么？」 |
| **核心操作** | 闭上眼睛，在脑子里把自己完全切换成用户。不是「我作为设计者觉得怎么样」，而是「我作为用户，在这个场景下，看到这个的第一感受」 |
| **常见错误** | 「我觉得挺好的」——这个「我」是设计者的你，还是用户的你？ |
| **训练方法** | 每次使用任何一个产品时，刻意捕捉自己的第一反应：「我刚才是什么感觉？哪个地方让我困惑？哪个地方让我惊喜？」 |

### 6.2 用户分层

| 要素 | 内容 |
|---|---|
| **一句话** | 不同用户，不同需求。把用户按角色/阶段/需求分成2-5层，分别理解 |
| **核心操作** | 问三个问题：谁在用？（角色）什么时候用？（阶段）为什么用/不用？（需求） |
| **常见错误** | 「我们的用户就是创业者」——创业者也分早期、成长期、成熟期；也分互联网、消费、硬科技 |
| **训练方法** | 下一次做任何东西之前，先画一张表：用户分几层？每一层的核心需求是什么？哪一层是最高优先级？ |

### 6.3 需求挖掘

| 要素 | 内容 |
|---|---|
| **一句话** | 理解表面需求背后的真实动机——不停留在用户「说的」，追问「为什么」3-5层 |
| **核心操作** | 用户说「我要A」→ 问「为什么需要A？」→ 用户说「因为B」→ 问「为什么B重要？」→ 循环直到触及真实JTBD |
| **常见错误** | 用户说「我要更快的马」→ 你开始研究怎么养更快的马 |
| **训练方法** | 下次有人说「我想做XX」的时候，练习连续问3-5个「为什么」，直到你听到一个和原话完全不同的、更底层的需求 |

### 6.4 场景推演

| 要素 | 内容 |
|---|---|
| **一句话** | 在具体场景中细颗粒度还原用户行为——什么时间？什么地点？什么情绪？什么前置动作？ |
| **核心操作** | 把用户的使用过程像电影一样在脑子里播一遍：他刚做完什么？现在是什么状态？打开产品的第一秒看到什么？接下来手指/眼睛往哪走？ |
| **常见错误** | 在电脑上设计手机页面——你看到的和用户在手机上看到的完全不一样 |
| **训练方法** | 做任何设计时，强制自己在真实环境里测试——在手机上预览、在纸上打印、在实际场景中走一遍 |

### 6.5 动力阻力

| 要素 | 内容 |
|---|---|
| **一句话** | 分析用户为何行动/为何不行动——画出用户转化链条上的每一环动力和阻力 |
| **核心操作** | 用户从「不知道你」到「完成你期望的动作」，中间有多少步？每一步的动力是什么？阻力是什么？ |
| **常见错误** | 只加动力（「再加一个优惠」「再强调一个卖点」），不减阻力（「注册流程太复杂」「用户不信任」） |
| **训练方法** | 下一次你想提升某个转化率时，先不要想「怎么吸引更多人」，先想「什么在阻止已经感兴趣的人完成动作」 |

## 七、B级卡牌逐一击穿：泛产品设计·理解用户（4张）

### 7.1 项目背景分析

| 要素 | 内容 |
|---|---|
| **一句话** | 从用户/场景/商业三个维度完整分析项目背景 |
| **核心操作** | 不是「我觉得用户需要」，而是「有证据表明用户在这个场景下需要」。收集数据、做访谈、观察行为 |
| **从A到B的升级** | A级的用户视角是「代入一个用户」，B级的项目背景分析是「系统理解一群用户在多个场景下的行为模式」 |

### 7.2 多视角思考

| 要素 | 内容 |
|---|---|
| **一句话** | 从内部/外部/不同角色多个视角审视产品，避免「设计师自嗨」 |
| **核心操作** | 做完一个方案后，强制自己至少从三个视角审视：用户视角（好不好用？）、商业视角（能不能赚钱？）、技术视角（能不能实现？） |
| **常见错误** | 你眼中的完美方案 = 用户眼中的灾难。因为你只从「设计者」视角看过 |

### 7.3 峰终定律

| 要素 | 内容 |
|---|---|
| **一句话** | 找到用户体验的峰值时刻和终值时刻，进行重点设计 |
| **核心原理** | 诺贝尔奖得主丹尼尔·卡尼曼的研究：人们对一段体验的评价，主要取决于两个点——情绪最强烈的时刻（峰值）和体验结束的时刻（终值） |
| **核心操作** | 画出用户的完整体验旅程图，标出每一个触点。问：哪里可以制造一个峰值？终值体验够不够好？ |
| **训练方法** | 下一次你组织任何活动（会议/培训/聚餐），刻意设计一个「峰值时刻」和一个「终值时刻」，事后观察参与者的反应 |

### 7.4 惊喜公式

| 要素 | 内容 |
|---|---|
| **一句话** | 惊喜 = 超出预期 + 恰到好处 |
| **核心操作** | 不是堆功能，而是在关键触点制造「哇」。关键：先管理预期（不要吹太高），再超出预期（在用户最不在意的地方给一个惊喜） |
| **常见错误** | 把惊喜等同于「送更多东西」。错——惊喜是心理感受，不是物理数量 |

## 八、C级卡牌逐一击穿：泛产品创新·理解用户（4张）

### 8.1 行业模式画布

| 要素 | 内容 |
|---|---|
| **一句话** | 从行业机会角度分析用户价值——不只是理解单个用户，而是理解整个行业的需求分布 |
| **核心操作** | 画出行业的用户分层图：不同层级的用户分别有什么JTBD？哪些任务已经被很好地满足了？哪些任务还没有好的解决方案？ |
| **从B到C的升级** | B级的项目背景分析是「理解我当前面对的用户群」，C级的行业模式画布是「理解整个市场上所有用户的需求结构」 |

### 8.2 一堂五步法

| 要素 | 内容 |
|---|---|
| **一句话** | 完整的商业成败假设框架——从需求→解决方案→商业模式→增长→壁垒，全链条验证用户价值 |
| **核心操作** | 第一步需求：用户是谁？场景是什么？JTBD是什么？这个需求足够大/足够痛/足够高频吗？ |
| **在泛产品设计中的用法** | 不只用于创业项目判断，而是任何「创新级别」产品设计的前置分析框架 |

### 8.3 拆推评算

| 要素 | 内容 |
|---|---|
| **一句话** | 拆解竞品→推演逻辑→评估差距→算清ROI。创新前的「知己知彼」 |
| **核心操作** | 拆：把竞品的产品拆成需求假设和方案选择。推：推演他们当时为什么这么选。评：评估他们选得对不对，有没有更好的选择。算：如果选择不同方案，ROI会差多少？ |
| **常见错误** | 只在功能层面「拆」（竞品有这个功能，我们也做），不去需求层面「拆」（竞品在满足用户的哪个JTBD？） |

### 8.4 产品核心价值要素

| 要素 | 内容 |
|---|---|
| **一句话** | 识别你的产品对于用户来说，最核心的价值要素是什么——是价格？品质？便利？身份？安全感？ |
| **核心操作** | 用户选择你而不选择竞品，最核心的1-3个原因是什么？如果只能保留一个，保留哪个？ |
| **常见错误** | 列了一堆卖点，但没有一个能回答「用户为什么非选你不可」 |

## 九、出牌层次：逐步细化，逐步展开

### 9.1 三级出牌模型

这是整节课最重要的方法论总结：

```text
L3（泛产品创新级别）：先用五步法周边的牌，做全局产品决策
    ↓ 拆成独立项目
L2（泛产品设计级别）：按项目背景分析、多视角思考、峰终定律、惊喜公式，分析相关方和体验
    ↓ 拆成具体触点
L1（小作品设计级别）：在每个具体触点，按用户视角、场景推演、需求挖掘、动力阻力，精细化打磨
```

### 9.2 核心原则

```text
每个维度，有每个维度的主要矛盾。
不要试图用低维度的解法，去解决高维度的问题。

用L1的场景推演去回答L3的行业模式问题 → 注定失败
用L3的五步法去设计L1的一个按钮文案 → 杀鸡用牛刀，效率极低
```

### 9.3 以一个AI项目为例的出牌推演

Truman 在课上用AI项目演示了完整的三级出牌逻辑：

```text
L3全局产品决策：
设定一个大概的商业目标→做到什么规模or收入利润。
需求：拆推评算，重点拆解客户类型&广告类型，看细分市场预算空间。
解决方案：品牌方合作内核+消费者认可，分别思考决定性的3-5条要素。
商业模式：单项目模型/单视频模型，测算ROI是否健康、可持续。
增长：预判渠道清单，规模化获客后打磨ROI和业务公式。
壁垒：提升规模经济要素（品牌/规模效应/KnowHow）对抗规模不经济。

→拆成独立项目后，按L2分析：
相关方动力阻力、峰终体验设计

→在每个具体触点，按L1精细化：
场景推演、人群细分、动机分析、阻力排除
```

> **L6 洞察**：大多数人做产品设计的最大问题是「层级错乱」——用做海报的思维做创新业务（低维打高维），或者用做创新业务的框架做一张海报（高维打低维，过度设计）。**泛产品设计高手的标志，是能准确判断当前任务属于哪个级别，然后出对应级别的牌。**

## 十、四个 L6 级洞察

### 洞察一：理解用户的最高境界，不是「听用户的」，而是「听懂用户没说的」

```text
乔布斯和张小龙从来不直接问用户「你想要什么」。
不是因为他们不在乎用户，而是因为他们知道——

用户能说出来的通常是「方案」（我要一匹更快的马），
而不是「需求」（我要更快地从A点到B点）。

真正顶级的用户理解，是：
从用户说出来的「方案」里，反向剥离出他真正的JTBD，
然后给出一个用户表达不出来的、但完美匹配JTBD的解决方案。

这就是「硬剥离需求」的终极价值。
```

### 洞察二：「每个维度有每个维度的主要矛盾」是防止无效努力的最强心法

```text
很多人做产品设计的焦虑来源——
不是没有方法，而是用错了层级的方法。

用L1的场景推演思考行业战略 → 越想越乱，焦虑。
用L3的五步法设计一张海报 → 过度复杂，焦虑。

正确姿势：
先判断你的任务属于L1/L2/L3的哪一级。
然后在那一级里出牌。
上一级的输出是下一级的输入。
下一级的执行验证上一级的假设。

这样做产品设计，每一步都是清晰的、可执行的、不会迷路的。
```

### 洞察三：UCD 作为价值观，比作为方法论威力大 100 倍

```text
当 UCD 只是方法论：你在做产品时会考虑用户。
当 UCD 是价值观：你在做任何决策时都会考虑用户。

区别在哪？
方法论 = 项目结束后就放下了。
价值观 = 跟同事吵架时，不是比谁声音大，
        而是「我们拿几个真实用户来测试一下，谁的效果好用谁的」。

方法论靠记忆，价值观靠信念。
记忆会忘，信念长在骨头里。
```

### 洞察四：需求分析花再多时间都是ROI极高的事

```text
需求错了，后面再努力做产品、做品牌，都会事倍功半。
需求歪了，后面各种决策都会没有"定力"，左右摇摆。
需求泛了，后面各种决策都可能没有支撑，大而全，效率很低。
需求变了，后面一旦发现重大误判，整个项目逻辑都得推翻重来。

Truman的判断：
我们在需求分析上花再多的时间，
去研究用户场景和真正问题背后的客观事实，
都是ROI极高的事情。

这句话的分量——
你在需求上多花1小时，可能省掉后面100小时的返工。
大多数人的问题不是「在需求上花太多时间」，
而是「从来没在需求上花过足够的时间」。
```

## 十一、L6 自检清单：你的「理解用户」能力在什么水平？

### 关于价值观

1. UCD对你来说，是方法论还是价值观？当你和同事/老板/客户意见不一致时，你的第一反应是「听谁的」，还是「我们看看用户怎么想」？
2. 你上一次在工作中说「我觉得用户需要……」的时候，有证据支撑吗？还是只是在说「我觉得」？

### 关于硬剥离

3. 你能不能做到「先别管你的产品/方案，先把用户的问题讲清楚」？
4. 找一个你最近做的方案，把里面关于「我的产品/定价/服务/卖点」的部分全部删掉——剩下的部分，还能不能客观描述用户的需求？

### 关于 JTBD

5. 你的用户「雇用」你的产品，到底是为了完成什么任务？这个任务有没有其他「竞品」（不一定是同行业，而是完成同一任务的其他方式）？
6. 你的用户有没有「解雇」过你的产品？当时是什么情况？替代品是什么？

### 关于卡牌

7. A级的5张牌（用户视角/分层/需求挖掘/场景推演/动力阻力），哪些是你的盲区？
8. B级的4张牌（项目背景分析/多视角思考/峰终定律/惊喜公式），你用过几张？
9. C级的4张牌（行业模式画布/五步法/拆推评算/产品核心价值要素），你目前能熟练出牌吗？
10. 你上一次做产品设计时，有没有犯过「层级错乱」的错——用L1的牌回答L3的问题，或用L3的牌处理L1的问题？

### 关于刻意练习

11. 未来一个月，你有哪些场景可以刻意练习「理解用户」的卡牌？从哪一张开始？
12. 你能不能给自己找一个「用户理解」的教练/同伴——每次你做产品设计的时候，他逼问你「用户的JTBD到底是什么？」「你说的是需求还是方案？」

## 十二、一句话总结

```text
用户价值，是所有商业、设计与服务的原点。
但「以用户为中心」不是一句口号，而是一套可以被拆解、被训练、被打出组合牌的专业方法。

UCD 不只是一个设计工具，而是一种做事的价值观——
它是你遇到重大分歧时的评价依据，
是你「先别管方案，先把问题探讨清楚」的肌肉记忆。

13张卡牌从L1到L3逐级递进：
小作品级别（用户视角/分层/需求挖掘/场景推演/动力阻力）
→ 泛产品级别（项目背景分析/多视角思考/峰终定律/惊喜公式）
→ 泛产品创新级别（行业模式画布/五步法/拆推评算/产品核心价值要素）

核心原则只有一条：
每个维度有每个维度的主要矛盾，
不要试图用低维度的解法，去解决高维度的问题。

Truman 用 JTBD 理论（人们不想买钻头，想要的是洞）
和「硬剥离需求」（把客观需求和主观方案分开），
证明了一件事：
真正理解用户的人，不是擅长问用户要什么，
而是擅长从用户说的「方案」里，反向剥离出那个真正的「任务」。

在需求分析上花再多时间，都是ROI极高的事情。
因为需求对了，后面的每一步都有定力；
需求错了，后面的每一步都在浪费。
```
